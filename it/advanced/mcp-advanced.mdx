Questa pagina è per chi sviluppa e vuole dare a un Agente di Enconvo strumenti propri. Un server MCP personalizzato espone strumenti che un Agente di Enconvo può chiamare. Parti da un piccolo server locale, verifica input e risultato, poi aggiungi il lavoro specifico del servizio che ti serve.

Per installare un server fatto da qualcun altro, vedi [Server MCP](/it/features/mcp). Per distribuire il tuo server in modo che si installi anche in Codex e Claude Code, impacchettalo come plugin con `--template mcp` (vedi [Formati dei plugin](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code)).

## Prima di iniziare

Ti servono Node.js e npm. Questo esempio usa l’**API JavaScript 1.x** dell’SDK TypeScript, fissata alla 1.29.0. Le versioni major dell’SDK possono usare import e configurazioni diverse; consulta la [guida ufficiale ai server MCP](https://modelcontextprotocol.io/docs/develop/build-server) se scegli un’altra versione.

## Scrivi un server locale minimo

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

Salvalo come `server.mjs`:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

Un server stdio attende i messaggi del protocollo; avviarlo in un terminale non mostra un’interfaccia di chat. Tieni la diagnostica su stderr (per esempio `console.error`) perché stdout porta i messaggi del protocollo MCP. La [guida ufficiale](https://modelcontextprotocol.io/docs/develop/build-server) spiega questo requisito del trasporto.

## Collegalo a Enconvo

<Steps>
  <Step title="Aggiungi il server">
    Apri **Impostazioni → Server MCP** e fai clic su **Aggiungi server**. Dagli un **Nome del server**, come `hello-mcp`.
  </Step>
  <Step title="Imposta come si avvia">
    Scegli **STDIO**. In **Comando**, inserisci `node`. In **Argomenti**, inserisci il percorso assoluto di `server.mjs`. Se Enconvo non trova Node, usa il percorso assoluto dell’eseguibile.
  </Step>
  <Step title="Salva e controllalo">
    Fai clic su **Salva**. Conferma che il server si collega ed espone `greet`.
  </Step>
  <Step title="Provalo">
    Rendilo disponibile al tuo Agente e chiedigli di salutare «Ada». Il risultato atteso dello strumento è `Hello, Ada!`.
  </Step>
</Steps>

Configurazione equivalente:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

Sostituisci il percorso di esempio con il percorso reale del file.

## Progetta strumenti utili

- Dai a ogni strumento un’azione e una descrizione precise.
- Valida l’input al confine dello strumento e restituisci messaggi di errore utili.
- Separa la lettura dei dati dalle mutazioni, come inviare o eliminare.
- Restituisci un risultato compatto che l’Agente possa interpretare.
- Tieni le credenziali nella configurazione appropriata del server, fuori dagli esempi di sorgente e dai log.

## Server remoti e autenticazione

Per un server remoto, usa il trasporto HTTP o SSE offerto dalle sue istruzioni di configurazione e il modulo corrispondente di Enconvo (**HTTP** o **SSE** invece di **STDIO**). L’URL del server deve essere l’endpoint MCP, non l’URL di un sito ordinario. Completa ogni flusso di autorizzazione supportato e conferma la connessione prima di abilitare gli strumenti.

Trasporto remoto, scoperta dell’autenticazione e comportamento della sessione dipendono dal server e dalla versione del protocollo. Usa l’SDK ufficiale e la documentazione del protocollo per i dettagli di implementazione, invece di inventare un manifest `auth` che Enconvo non consuma.

## Risoluzione dei problemi

| Problema | Cosa fare |
| --- | --- |
| Il processo esce subito | Controlla il percorso dell’eseguibile, le dipendenze, gli errori di sintassi e stderr |
| Collegato, ma non compare alcuno strumento | Controlla la registrazione dello strumento, che sia abilitato e l’Agente selezionato |
| Risposta del protocollo non valida | Cerca un log accidentale su stdout, o il programma sbagliato in avvio |
| Errore di convalida dello schema | Confronta la forma reale dell’input con la versione dell’SDK che usi |
| Connessione remota fallita | Controlla l’URL dell’endpoint, il trasporto, l’autenticazione e l’accesso alla rete |

Per esporre i documenti di Enconvo a un altro client IA, usa il [server MCP della Base di conoscenza](/it/advanced/knowledge-base-mcp) integrato; un server personalizzato non serve.
