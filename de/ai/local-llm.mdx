---
title: "Lokale Modelle"
description: "Modelle auf eigener Hardware ausführen und eine ganze Aufgabe auf dem Mac behalten."
---

Führe Modelle auf dem Mac oder auf einem anderen Computer aus, der dir gehört, wenn Chats privat bleiben sollen oder du ohne Anbieterkonto arbeiten willst. Enconvo hat eine eingebaute Engine und verbindet sich außerdem mit Ollama und LM Studio.

## Eine Laufzeit wählen

| Laufzeit | Am besten für | Einrichtung |
| --- | --- | --- |
| [Lokales LLM (MLX)](/de/providers/mlx) | Modelle in Enconvo auf einem Apple-Silicon-Mac mit macOS 15 oder neuer | Modell in den Einstellungen wählen und herunterladen |
| [Ollama](/de/providers/ollama) | Modelle, die du schon mit Ollama verwaltest, auf diesem Mac oder einem Server | Ollama starten und die Adresse setzen |
| [LM Studio](/de/providers/lm-studio) | Modelle, die du schon in LM Studio nutzt, auf diesem Mac oder einem Server | Den Server von LM Studio starten und die Adresse setzen |

## Klein anfangen

1. Richte die Laufzeit ein und lade ein Modell herunter oder ein.
2. Sende eine kurze Textnachricht.
3. Wenn das klappt, füge Dokumente oder Werkzeuge hinzu.
4. Beobachte Speicherverbrauch und Tempo, bevor du ein größeres Modell ausprobierst. **Einstellungen → Lokale Modelle** zeigt die Modelle auf diesem Mac und wie viel Speicher sie nutzen.

Modellgröße, Quantisierung, Kontextlänge und andere laufende Aufgaben beeinflussen den Speicher. Nimm die Größe, die die Modellauswahl anzeigt, nicht eine feste Regel.

## Die ganze Aufgabe lokal halten

Ein lokales Chat-Modell allein hält nicht alles auf dem Mac. Spracherkennung, Sprachausgabe, OCR, Dokumentenanalyse, Embeddings, Reranking, Suche und MCP-Werkzeuge nutzen jeweils einen eigenen Anbieter. Enconvo hat lokale Anbieter für mehrere davon; der [Anbieterkatalog](/de/providers/catalog) listet sie.

**Einstellungen → Lokale Modelle** zeigt, welche Funktionen auf diesem Mac laufen und welche in der Cloud. Websuche und andere Online-Dienste brauchen weiterhin das Internet, und ein lokales Modell kann Werkzeuge aufrufen, die Inhalte vom Mac wegschicken.

## Einen Modellserver auf einem anderen Computer nutzen

Stelle den Server so ein, dass er Netzwerkverbindungen annimmt, und setze **BaseUrl** in Enconvo auf die Adresse dieses Computers. `localhost` meint immer den Mac, auf dem Enconvo läuft. Blockiert macOS die Verbindung, schalte Enconvo unter **Systemeinstellungen → Datenschutz & Sicherheit → Lokales Netzwerk** ein.

## Einen anderen Modellserver nutzen

Für einen Server wie llama.cpp, vLLM, KoboldCpp oder text-generation-webui klicke unten unter **Einstellungen → KI-Modell** auf **Neuen Anbieter hinzufügen** und wähle **OpenAI Compatible**. Füge die Adresse des Servers als Basis-URL ein; Enconvo akzeptiert sie mit oder ohne `/v1` und auch mit dem vollständigen Endpunkt. Lass den API-Schlüssel leer, wenn der Server keinen prüft.

## Lange Chats bei kleinem Kontext

Lokale Server führen ein Modell oft mit einem kleineren Kontext aus, als das Modell erlaubt. Enconvo liest den Kontext, mit dem Ollama, llama.cpp, LM Studio, KoboldCpp und text-generation-webui wirklich laufen, und verdichtet den Chat passend. Bei kleinem Kontext fasst es einen langen Chat in Teilen zusammen. Mehr Platz fürs Modell bekommst du, indem du die Kontextlänge in den Einstellungen des Servers erhöhst.

## Fehlerbehebung

| Problem | Was tun |
| --- | --- |
| Das Modell vergisst den Anfang eines langen Chats | Der Server läuft mit kleinem Kontext. Erhöhe die Kontextlänge in den Servereinstellungen oder starte einen neuen Chat. |
| Das Modell ignoriert Werkzeuge oder Bilder | Es nimmt sie nicht an, deshalb antwortet Enconvo ohne sie. Wähle ein Modell, das Tool-Aufrufe oder Bildeingabe unterstützt. |
| Die Verbindung schlägt fehl | Lies den Fehler: Enconvo zeigt die eigene Meldung des Servers und nennt die Ursache. Prüfe, ob der Server läuft und Adresse und Port stimmen. |
