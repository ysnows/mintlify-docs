Workflows ketten Prompts, Agenten und Tools zu einem wiederholbaren Lauf. Dieses Tutorial baut einen von Anfang bis Ende: erstelle ihn aus der Vorlage **Tour durch Schrittarten**, füge einen Schritt von Hand hinzu, lass den Workflow-Assistenten einen weiteren hinzufügen, führe ihn dann aus und lies die Ausgabe jedes Schritts.

<YouTubePlayer videoId="g02LJwso1yk" title="Einen Workflow in Enconvo bauen | Schritt-für-Schritt-Tutorial" />

Das Video ist 2 Minuten und 24 Sekunden lang. Die geschriebenen Schritte unten folgen derselben Reihenfolge, mit dem passenden Zeitstempel für jeden Schritt.

## Was du baust

Die Vorlage **Tour durch Schrittarten** läuft schon von Haus aus. Im Tutorial wächst sie zu einer kleinen Inhaltspipeline:

| Schritt | Typ | Was er tut |
| --- | --- | --- |
| Heutiges Datum holen | Shell | Gibt das heutige Datum aus |
| Gespeicherte Workflows auflisten | Tool | Listet deine vorhandenen Workflows (läuft parallel zum Datum) |
| Das Modell nach einer Idee fragen | Prompt | Schlägt eine neue Automatisierung zum Eingabewert `topic` vor |
| Den Agenten sie ausarbeiten lassen | Agent | Macht aus der Idee einen Plan in drei Schritten |
| Einen Tweet schreiben | Prompt | Von Hand hinzugefügt: macht aus dem Plan einen knackigen Tweet |
| Den Tweet ins Japanische übersetzen | Prompt | Vom Assistenten hinzugefügt: übersetzt den Tweet |

## Mitmachen

<Steps>
  <Step title="Einen Workflow erstellen (0:07)">
    Öffne **Einstellungen → Workflows → Verwalten** und wähle **Neuer Workflow**. Wähle unter **Oder mit einer Vorlage starten** **Tour durch Schrittarten**. Der Workflow wird erstellt und der Editor öffnet sich im Modus **Visuell**. Das Video wurde aufgenommen, bevor der Dialog **Neuer Workflow** existierte, dort heißt der Start also *Starter Workflow*.
  </Step>
  <Step title="Den Graphen lesen (0:18)">
    Lies den Graphen von oben. Der Knoten **Eingaben** erklärt, was ein Lauf braucht; hier ist es ein einzelnes `topic`. Die ersten beiden Schritte sitzen nebeneinander, weil sie zu getrennten Jobs gehören, also laufen sie parallel. Jedes Ergebnis fließt dann in die Schritte darunter, die der Reihe nach laufen.
  </Step>
  <Step title="Einen Schritt bearbeiten (0:28)">
    Wähle einen Schritt, um ihn im Inspektor zu öffnen, wo du seine ID, den Titel und den Prompt ändern kannst. Doppelte geschweifte Klammern holen Werte in einen Schritt: `{{ inputs.topic }}` liest eine Laufeingabe, und `{{ steps.idea.output }}` liest das Ergebnis eines früheren Schritts. So sprechen Schritte miteinander.
  </Step>
  <Step title="Einen Schritt hinzufügen (0:37)">
    Wähle das **+** unter dem letzten Schritt und einen Schritttyp, etwa Prompt, Agent, Shell oder Tool. Gib dem neuen Prompt-Schritt die ID `tweet`, den Titel „Einen Tweet schreiben“ und diesen Prompt:

    ```text wrap
    Turn this plan into one punchy tweet: {{ steps.plan.output }}
    ```

    <Tip>
    Nachdem du eine Schritt-ID umbenannt hast, drücke Return, bevor du zum nächsten Feld gehst.
    </Tip>
  </Step>
  <Step title="Oder den Workflow-Assistenten fragen (0:57)">
    Statt von Hand zu bearbeiten, wähle in der Symbolleiste **Assistent** und beschreibe die Änderung im Panel, das neben der Leinwand aufgeht:

    ```text wrap
    Add a final step that translates the tweet into Japanese
    ```

    Der Assistent bearbeitet den Graphen und listet die Schritte, die er geändert hat. Wähle an seiner Antwort **Zurücksetzen**, wenn dir das Ergebnis nicht gefällt. Im Video fügt er einen Schritt `translate_ja` hinzu, dessen Prompt `{{ steps.tweet.output }}` liest. Prüfe den neuen Schritt, bevor du speicherst: Bearbeitungen des Assistenten bleiben ungespeichert, bis du **Speichern** wählst.
  </Step>
  <Step title="Das YAML sehen (1:16)">
    Wähle in der Symbolleiste **YAML**, um denselben Workflow als Quelle zu sehen. Jeder Workflow ist eine einfache Datei, gespeichert unter `~/.enconvo/workflows/<id>.yaml`, also leicht zu lesen, zu vergleichen und zu teilen. Wähle **Visuell**, um zum Graphen zurückzukehren. Die ganze Datei steht unten unter Der fertige Workflow.
  </Step>
  <Step title="Ausführen und die Ausgabe prüfen (1:28)">
    Wähle **Eingaben**, setze die Laufwerte (das Video nutzt `{"topic": "matcha"}`) und wähle **Ausführen**. Laufende Schritte leuchten blau, fertige werden grün. Der Agent-Schritt dauert länger als die anderen.

    Wenn der Lauf fertig ist, wähle einen beliebigen Schritt und öffne seinen Tab **Ausgabe**, um genau zu sehen, was er erzeugt hat. Der letzte Schritt hat den Tweet aufgenommen und übersetzt, ohne Kopieren und Einfügen.
  </Step>
  <Step title="Frühere Läufe finden (2:05)">
    Jeder Lauf bleibt unter **Läufe** in der Symbolleiste, also kannst du später zu jedem Ergebnis zurück.
  </Step>
</Steps>

<Note>
Einen Workflow auszuführen ruft echte Modelle und Tools auf. Das kann Anbieter-Guthaben verbrauchen, und Shell- oder Tool-Schritte handeln mit den Berechtigungen deines Mac-Kontos. Prüfe die Schritte eines Workflows, bevor du ihn ausführst.
</Note>

## Der fertige Workflow

Hier ist der im Video gebaute Workflow, als YAML ausgeschrieben. Die Ansicht **YAML** kann ihn etwas anders formatieren.

```yaml
version: agent-workflow/v1
title: Starter Workflow
description: "Starter workflow showing parallel jobs and the four executors: command (shell), prompt (LLM), agent, and tool (Local API)."
tags:
  - demo
inputs:
  topic:
    type: string
    description: Topic to brainstorm an automation for
    default: coffee
jobs:
  date:
    steps:
      - id: today
        name: Get today's date
        command: 'date "+%Y-%m-%d"'
  catalog:
    steps:
      - id: my_workflows
        name: List saved workflows (tool)
        tool: workflow/list
        with:
          limit: 5
  ideate:
    needs: [date, catalog]
    steps:
      - id: idea
        name: Ask the model for an idea
        prompt: "Today is {{ jobs.date.today.output.stdout | trim }}. Existing workflows: {{ jobs.catalog.my_workflows.output.summaries | dump }}. Suggest ONE new automation about {{ inputs.topic }} that is not in the list, in one sentence."
      - id: plan
        name: Let the agent expand it
        agent: agent/main
        message: "Expand this automation idea into a three-step execution plan: {{ steps.idea.output }}"
      - id: tweet
        name: Write a tweet
        prompt: "Turn this plan into one punchy tweet: {{ steps.plan.output }}"
      - id: translate_ja
        name: Translate the tweet into Japanese
        prompt: "Translate this tweet into natural, fluent Japanese. Keep hashtags, emojis, and links intact. Reply with only the translated tweet: {{ steps.tweet.output }}"
```

Der Job `ideate` wartet über `needs` auf `date` und `catalog`, also kann er ihre Ergebnisse mit `jobs.<job>.<step>.output` lesen. Innerhalb eines Jobs lesen spätere Schritte frühere mit `steps.<id>.output`.
