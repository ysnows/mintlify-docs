---
title: "Messaging Channels"
description: "Connect an Enconvo Agent to Telegram or Discord and control incoming access."
---

Current built-in IM Channel providers are **Telegram** and **Discord**. Configure them in **Settings → Agents → IM Channels**. Each channel provider binds to at most one Agent; one Agent can serve multiple channel providers.

## Add a channel

1. Open **IM Channels** and add a provider for Telegram or Discord.
2. Give the connection an identifiable name.
3. Enter the platform's **Bot Token** in its password field.
4. Choose **bind agent** to select the Agent that should handle incoming messages.
5. Review access controls, then enable the channel.
6. Confirm that its connection status is **Connected** and send a test message from an allowed account.

Keep Enconvo running and the Mac online while the bot is listening. The Agent's model and tool configuration determine the replies it can produce.

## Telegram

Create a bot with Telegram's **BotFather** and copy its bot token. Open the channel's **Access Control** before enabling it. The default pairing policy requires a new user to share a pairing code for approval; review pending requests and approve only the intended users.

If the bot works in a direct chat but not a group, review Telegram's bot privacy and group permissions as well as the channel's access policy. A token alone does not grant permission to every conversation.

## Discord

Create an application and bot in the Discord Developer Portal, invite it to the intended server, and grant the permissions and intents required for the messages it should receive and send. Paste its bot token into the Discord provider and bind an Agent.

If it connects but does not reply, check the target channel's permissions and whether the bot receives that type of message. Keep access limited to the intended server and channels.

## Sessions and replies

Incoming conversations are routed to chat sessions for the bound Agent. Reply context follows that conversation; it is not one shared transcript for every connected user. Changing the bound Agent reconnects the channel so subsequent messages go to the selected Agent.

Use a dedicated Agent with appropriate instructions and tools for a public or team bot. Review which tools it can invoke before making it available to other people.

## Scheduled delivery

[Scheduled Jobs](/workflows/scheduled-jobs) can deliver results to a configured IM chat. Select the destination explicitly and use the job's run history to distinguish a generation failure from a delivery failure.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Disconnected | Bot token, network, enabled state, and Enconvo running |
| Connected but silent | Agent binding, provider access, platform permissions, and pairing policy |
| Wrong assistant behavior | The bound Agent's instructions, tools, and model |
| Telegram user cannot connect | Pending pairing request and allowed users |
| Replies stop after quitting Enconvo | The local listener needs the app and runtime to remain running |

This built-in channel page does not provide Slack or Feishu setup. If you use those services through another plugin or MCP server, follow that integration's own guide.
