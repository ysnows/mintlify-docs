Use the OpenAI models your organization deploys on Azure. Enconvo talks to your Azure resource directly, so access, quotas, and billing follow your Azure subscription.

## Before you start

You need an Azure OpenAI resource with at least one model deployment. From the Azure portal, copy the resource's **key**, its **endpoint**, and the **deployment name** you gave the model. See [Azure OpenAI](https://learn.microsoft.com/en-us/azure/ai-services/openai/overview) if you haven't set one up.

## Connect

<Steps>
  <Step title="Add the credential">
    Open **Settings → AI Model → Azure OpenAI**. Under **Authentication**, fill in **API Key**, **Endpoint**, and **API Version**, then click **Validate**. The endpoint looks like `https://<resource>.cognitiveservices.azure.com/`.
  </Step>
  <Step title="Set the deployment">
    Enter your deployment name in **Azure OpenAI Api Deployment Name**. Use the name from your Azure resource, which can differ from the model's name.
  </Step>
  <Step title="Test it">
    Send a short message. A reply means the connection works.
  </Step>
</Steps>

## Models and options

| Setting | What it does |
| --- | --- |
| **Azure OpenAI Api Deployment Name** | The deployment this provider calls. |
| **Streaming** | Shows the reply as it's written. On by default; turn it off if your deployment doesn't support streaming. |
| **API Version** | In the credential. The default is `2025-01-01-preview`. |

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **Validate** fails | Check that the key and **Endpoint** come from the same Azure resource. |
| The deployment isn't found | Copy the deployment name exactly from the Azure portal. |
| The reply never appears | Turn off **Streaming** and try again. |
| Rate or quota errors | Raise the deployment's quota in Azure, or switch to another provider for now. |
