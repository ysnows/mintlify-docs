A provider connects an Enconvo feature to a model, voice, search service, or local runtime. Start with the capability you need, then choose its access method.

## Choose access

| Access | Guide |
| --- | --- |
| Enconvo account and Cloud usage | [Enconvo Cloud Plan](/providers/enconvo) |
| Your own provider API key | [Credentials and Provider Profiles](/configuration/credentials) |
| Supported subscription/account sign-in | [ChatGPT](/providers/openai_subscription), [Claude](/providers/anthropic_subscription), [Google Account](/providers/google_subscription) |
| Local inference | [MLX](/providers/mlx), [Ollama](/providers/ollama), [LM Studio](/providers/lm-studio) |
| External Agent gateway | [OpenClaw](/providers/openclaw), [Hermes](/providers/hermes) |

## Configure the feature you use

Open **Settings → Global Providers Settings** for AI Model, Text-to-Speech, Web Search, Image Generation, Video Generation, Web Fetch, and OCR. Speech recognition has separate provider settings for Dictation, Recording, Transcription, and Captioning. Embedding and reranking choices belong to knowledge-base configuration.

The [Provider Capability Catalog](/providers/catalog) lists every declared provider in these categories. Selecting a chat model does not automatically configure your speech, image, or retrieval provider.

## Profiles and defaults

Create additional profiles when you need separate keys or accounts for the same provider. A profile shares credentials across supported feature categories, so changing it can affect more than one feature. Model choices remain specific to the capability and conversation.

See [Model Selection](/ai/model-selection-guide) for Agent, project, and per-chat defaults. Test a short request after setup before moving to a large document or generation task.
