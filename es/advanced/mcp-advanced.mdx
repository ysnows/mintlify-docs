Esta página es para desarrolladores que quieren dar a un Agente de Enconvo herramientas propias. Un servidor MCP personalizado expone herramientas que un Agente de Enconvo puede llamar. Empieza con un servidor local pequeño, comprueba sus entradas y el resultado, y después añade el trabajo específico del servicio que necesites.

Para instalar un servidor hecho por otra persona, consulta [Servidores MCP](/es/features/mcp). Para publicar tu servidor de modo que también se instale en Codex y Claude Code, empaquétalo como plugin con `--template mcp` (consulta [Formatos de plugin](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code)).

## Antes de empezar

Necesitas Node.js y npm. Este ejemplo usa la **API de JavaScript 1.x** del SDK de TypeScript, fijada en 1.29.0. Las versiones mayores del SDK pueden usar importaciones y una configuración distintas; consulta la [guía oficial de servidores MCP](https://modelcontextprotocol.io/docs/develop/build-server) si eliges otra versión.

## Escribir un servidor local mínimo

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

Guárdalo como `server.mjs`:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

Un servidor stdio espera mensajes del protocolo; iniciarlo en un terminal no muestra una interfaz de chat. Deja los diagnósticos en stderr (por ejemplo, `console.error`) porque stdout lleva los mensajes del protocolo MCP. La [guía oficial](https://modelcontextprotocol.io/docs/develop/build-server) explica este requisito del transporte.

## Conectarlo a Enconvo

<Steps>
  <Step title="Añadir el servidor">
    Abre **Ajustes → Servidores MCP** y pulsa **Add server**. Ponle un **Nombre del servidor**, como `hello-mcp`.
  </Step>
  <Step title="Definir cómo se inicia">
    Elige **STDIO**. En **Comando**, escribe `node`. En **Argumentos**, escribe la ruta absoluta de `server.mjs`. Si Enconvo no encuentra Node, usa la ruta absoluta del ejecutable.
  </Step>
  <Step title="Guardar y comprobarlo">
    Pulsa **Guardar**. Confirma que el servidor se conecta y expone `greet`.
  </Step>
  <Step title="Probarlo">
    Ponlo a disposición de tu Agente y pídele que salude a “Ada”. El resultado esperado de la herramienta es `Hello, Ada!`.
  </Step>
</Steps>

Configuración equivalente:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

Sustituye la ruta de ejemplo por la ruta real de tu archivo.

## Diseñar herramientas útiles

- Da a cada herramienta una acción y una descripción concretas.
- Valida la entrada en el límite de la herramienta y devuelve mensajes de error útiles.
- Separa la lectura de datos de las mutaciones, como enviar o eliminar.
- Devuelve un resultado compacto que el Agente pueda interpretar.
- Guarda las credenciales en la configuración adecuada del servidor, fuera de los ejemplos de código y de los registros.

## Servidores remotos y autenticación

Para un servidor remoto, usa el transporte HTTP o SSE que indiquen sus instrucciones de configuración y el formulario correspondiente de Enconvo (**HTTP** o **SSE** en lugar de **STDIO**). La URL del servidor debe ser el extremo MCP, no la URL de un sitio web cualquiera. Completa el flujo de autorización compatible y confirma la conexión antes de activar sus herramientas.

El transporte remoto, el descubrimiento de autenticación y el comportamiento de la sesión dependen del servidor y de la versión del protocolo. Usa el SDK oficial y la documentación del protocolo para los detalles de implementación, en lugar de inventar un manifiesto `auth` que Enconvo no consume.

## Solución de problemas

| Problema | Qué hacer |
| --- | --- |
| El proceso sale de inmediato | Comprueba la ruta del ejecutable, las dependencias, los errores de sintaxis y stderr |
| Conectado, pero no aparece ninguna herramienta | Comprueba el registro de la herramienta, que esté activada y el Agente seleccionado |
| Respuesta de protocolo no válida | Busca registros accidentales en stdout, o que se esté lanzando el programa equivocado |
| Error de validación del esquema | Compara la forma real de la entrada con la versión del SDK que usas |
| Fallo de conexión remota | Comprueba la URL del extremo, el transporte, la autenticación y el acceso a la red |

Para exponer los documentos de Enconvo a otro cliente de IA, usa el [servidor MCP de la base de conocimientos](/es/advanced/knowledge-base-mcp) integrado; no hace falta un servidor personalizado.
