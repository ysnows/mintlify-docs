Code Runner da a un Agente un terminal real en tu Mac. Úsalo para compilaciones, pruebas, scripts, herramientas de paquetes y servidores de desarrollo. Los programas que tienes instalados y los permisos de tu cuenta deciden qué puede ejecutarse.

<Warning>
Los comandos se ejecutan de verdad, con el acceso de tu cuenta a tus archivos y a la red, salvo que actives el **Sandbox** del Agente. Revisa cualquier comando que instale software, cambie archivos o afecte a un servicio en línea antes de que se ejecute.
</Warning>

## Antes de empezar

- Activa Code Runner en el Agente que estés usando.
- El chip **Permissions** del chat decide cuándo el Agente pregunta antes. **Ask for approval** pregunta antes de ejecutar un comando, y **Approve for me** solo pregunta ante acciones que parecen inseguras. Consulta [Aprobar acciones](/es/ai/agents).
- Para limitar los comandos del Agente a la carpeta de trabajo y apartarlos de tus claves y de otras apps, activa **Sandbox** en el mismo chip. Consulta [Sandbox del Agente](/es/configuration/sandbox).

## Ejecutar un comando

Dale al Agente una carpeta y una tarea concreta:

> En mi proyecto de ejemplo, ejecuta el comando de pruebas que ya existe e informa del resultado. No cambies archivos.

El Agente muestra la salida del comando y te dice si terminó o si sigue en ejecución. Para leer, editar y buscar archivos, el Agente usa las [herramientas de archivos](/es/ai/file-tools).

## Cómo se ejecutan los comandos

Cada comando se ejecuta en un seudoterminal, así que un comando que pide una entrada se puede responder sin iniciar un proceso nuevo.

| Modo | Úsalo para |
| --- | --- |
| **oneshot** | Comandos que terminan solos, como pruebas, compilaciones o un script |
| **long_running** | Servidores, observadores y procesos que esperan un evento externo |
| **interactive** | REPL, apps de terminal y sesiones interactivas de línea de comandos |

Un resultado con `status: running` y un `session_id` significa que el proceso sigue. El Agente puede **leer** su salida, **escribir** una entrada o **detenerlo**. Para responder a un aviso, el Agente escribe en esa sesión; iniciar otro comando no lo responde.

## Esperar a que algo termine

Cuando una tarea tiene que esperar, por ejemplo a que una compilación escriba su salida o a que un servidor arranque, el Agente usa la herramienta **Wait For** en lugar de un bucle de shell. Espera una de estas condiciones, sin ningún comando en ejecución:

- Que aparezca un archivo
- Una línea en un archivo de registro
- Que termine un proceso o la sesión de un comando
- Que se abra un puerto, o que una dirección responda

La espera aparece en las tareas en segundo plano del chat. Se avisa al Agente cuando se cumple, falla o se agota el tiempo, y mientras tanto puede hacer otro trabajo.

## Carpeta de trabajo y límites de tiempo

Los comandos se ejecutan en `workDir` cuando el Agente lo define, y si no, en la carpeta de trabajo del chat. Usan tu shell, con tu proyecto y el entorno virtual de Python preparados. Los comandos separados no comparten variables temporales del shell salvo que se ejecuten en la misma sesión.

La primera espera es independiente del límite de tiempo duro del comando. Un comando oneshot espera hasta 30 segundos su resultado; si entonces sigue en ejecución, el Agente recibe la salida hasta ese momento mientras el trabajo continúa. El comando se detiene a los 30 minutos por defecto. Para un servidor o un observador, usa el modo long_running en lugar de tratarlo como un comando oneshot que falló.

## Ajustes

Abre **Ajustes → Plugins → Code Runner**.

| Ajuste | Qué cambia |
| --- | --- |
| **Enable RTK** | Comprime la salida larga de un comando antes de que el Agente la lea, para que use menos tokens. Activado por defecto |

Si falta un detalle que necesitas en la salida comprimida, pide un comando más concreto o la parte relevante del registro. Una salida cortada no demuestra que el comando haya tenido éxito.

## Solución de problemas

| Problema | Qué hacer |
| --- | --- |
| Comando no encontrado | Comprueba que el programa esté instalado y disponible en tu shell |
| El comando espera una entrada | Haz que el Agente responda al aviso en la misma sesión. Un comando que espera una entrada que nadie puede dar termina de inmediato |
| Permiso denegado | Comprueba la ruta de destino y los permisos de macOS. Con el Sandbox activado, pulsa la línea bajo el paso para ver qué detuvo |
| El comando agotó el tiempo | Lee la última salida y elige el modo correcto antes de volver a ejecutarlo |
| Un servidor sigue en ejecución | Haz que el Agente detenga su sesión cuando ya no la necesites |
