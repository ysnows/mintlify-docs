Esta página es para desarrolladores que están a punto de enviar un plugin a la tienda de plugins de Enconvo. Recoge lo que comprueban los revisores, los materiales de revisión que se envían con cada versión, una lista de comprobación para repasar antes de `plugin publish` y lo que ocurre después del envío.

Enconvo revisa cada versión enviada a la tienda de plugins antes de que nadie más pueda instalarla. Estas directrices se aplican a todos los tipos de plugin que acepta la tienda: plugins de Enconvo, de Codex, de Claude Code y portables, incluidos los plugins formados solo por habilidades. Siguen las [directrices de plugins de OpenAI](https://developers.openai.com/apps-sdk/app-submission-guidelines), así que un plugin que las cumple también está casi listo para el portal de plugins de OpenAI.

## Comprueba primero tu plugin

Antes de enviarlo, ejecuta:

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate` detecta lo que se puede comprobar de forma automática, y `scan` revisa las herramientas de un plugin con un servidor MCP; [Validation Codes](/extensions/validation-codes) explica cada problema que informan. Los revisores comprueban el resto a mano, como se describe a continuación.

## Propósito y calidad

- El plugin hace algo útil que Enconvo no puede hacer ya, y lo hace por completo. Las versiones de relleno, solo de demostración o de prueba se rechazan.
- Se comporta de forma predecible. Cuando algo falla, como un error de red, un permiso que falta o una entrada incorrecta, explica lo que ha pasado en lugar de fallar en silencio.
- Usa únicamente código, nombres, iconos y contenido que son tuyos o que tienes licencia para usar. No suplanta a otro producto ni da a entender que Enconvo o cualquier otra persona lo respalda.

## Nombre, descripción y ficha

- **Nombre y título**: claros y concretos. Evita una sola palabra genérica y no añadas "MCP", "MCP Server" ni "Plugin" al nombre de una empresa.
- **Descripción**: dice con exactitud lo que hace el plugin. Sin comparaciones con otros productos, afirmaciones que no puedas respaldar, ni precios, descuentos u ofertas de prueba gratuita.
- **Icono y capturas de pantalla**: el icono es un PNG, JPEG, WebP o GIF de hasta 5 MB. Hasta 8 capturas van en una carpeta `metadata/` y se muestran por orden de nombre de archivo. Muestran el plugin tal como funciona de verdad.
- **Soporte**: da a los usuarios una forma de contactarte: `interface.websiteURL` e `interface.supportURL`, o `homepage` o `repository` para el sitio web. Un plugin de Claude Code puede usar en su lugar `supportUrl` y `documentationUrl`. La página de la tienda muestra estos enlaces antes de que nadie instale el plugin.
- **Versión**: súbela en cada actualización. Mientras una actualización está en revisión, la tienda sigue ofreciendo la versión anterior. `plugin publish` pregunta a la tienda qué versión ha publicado antes de compilar o subir nada, y se detiene indicando la siguiente versión que debes usar cuando la tuya no es superior.

## Herramientas MCP

Cuando el plugin incluye un servidor MCP, los revisores leen sus herramientas como las leerá el modelo de IA.

- **Los nombres** son verbos sencillos que dicen lo que hace la herramienta, como `get_order_status`, y son únicos dentro del servidor. Sin jerga ni abreviaturas sin explicar.
- **Las descripciones** explican qué hace la herramienta, qué cambia y qué no puede hacer, y coinciden con su esquema de entrada y su comportamiento real. No indican al modelo que prefiera este plugin, que llame a otros plugins ni que use la herramienta para todo.
- **Una operación por herramienta**, cada una con su propio esquema de entrada.
- **Las anotaciones** se definen de forma explícita en cada herramienta:

| Anotación | `true` cuando la herramienta | `false` cuando |
|---|---|---|
| `readOnlyHint` | solo lee, calcula o muestra una vista previa | cambia algo: escribe, guarda un archivo, envía, publica, sube, pone trabajo en cola o inicia una tarea |
| `destructiveHint` | elimina, sobrescribe, cancela o envía algo que no se puede deshacer, aunque el usuario pudiera revertirlo | solo añade |
| `openWorldHint` | accede a contenido público o abierto, como una búsqueda web, o envía a cualquier dirección | se queda dentro de una cuenta, un espacio de trabajo o un catálogo acotados, aunque estén alojados en otro lugar |

Enconvo se apoya en estas anotaciones. Una herramienta marcada con `readOnlyHint: true` se ejecuta sin preguntar al usuario y junto con otras lecturas. Una herramienta marcada con `destructiveHint: true` pregunta antes al usuario, salvo que este haya dado acceso total al agente. Una herramienta que cambia algo pero afirma ser de solo lectura se rechaza.

`enconvo plugin scan` inicia el servidor MCP del plugin, enumera sus herramientas con sus anotaciones y nombra cada herramienta que omite alguna ([`annotations_required`](/extensions/validation-codes#mcp-server-scan)).

Una herramienta que muestra su propia interfaz indica su vista, un recurso `ui://`, en `_meta.ui.resourceUri`, y la vista declara los dominios a los que accede en `_meta.ui.csp` (`connectDomains`, `resourceDomains`, `frameDomains`). Son las claves de MCP Apps que lee cualquier host. Enconvo también lee `_meta["openai/outputTemplate"]` y `_meta["openai/widgetCSP"]` de ChatGPT, y ofrece a una vista escrita para ChatGPT (`text/html+skybridge`, o una herramienta nombrada solo por `openai/outputTemplate`) la API `window.openai` que utiliza, de modo que un plugin creado para ChatGPT muestra su interfaz en Enconvo sin cambios. Define también las claves de MCP Apps para que otros hosts la muestren igualmente. `scan` lee cada vista como lo hace Enconvo e indica cuándo una está definida solo al estilo de OpenAI.

## Datos y privacidad

- **Pide solo lo que necesita la tarea.** Las entradas de las herramientas son específicas de la tarea. No pidas toda la conversación, los mensajes anteriores ni datos amplios del perfil "por si acaso".
- **Devuelve solo lo que responde a la petición.** Deja fuera de los resultados de las herramientas los ids internos, los datos de rastreo y la salida de depuración.
- **No recojas nunca** datos de tarjetas de pago, historiales médicos, documentos de identidad oficiales como los números de la seguridad social, ni contraseñas, claves de API o códigos de un solo uso a través de las entradas de las herramientas. Las credenciales van en las preferencias del plugin, donde Enconvo las guarda.
- **Política de privacidad.** Un plugin que envía datos a un servidor necesita una política de privacidad publicada que explique qué recoge, por qué, quién lo recibe, cuánto tiempo se conserva y cómo pueden eliminarlo los usuarios. Pon su dirección en `interface.privacyPolicyURL` y, si las tienes, las condiciones del servicio en `interface.termsOfServiceURL`. La página de la tienda enlaza ambas.
- **Sin seguimiento** de las personas, sus consultas o su uso más allá de lo que el plugin necesita para funcionar y de lo que declara su política de privacidad.
- **Mantén los secretos fuera del paquete.** Cualquiera puede descargarlo. Los archivos `.env` se excluyen automáticamente, pero comprueba que no se cuelen otras claves o archivos privados.

## Inicio de sesión y cuentas de prueba

Si el plugin necesita una cuenta, el inicio de sesión es explícito y solo pide los permisos que necesita. Los revisores necesitan probarlo sin crear una cuenta ni recibir un código de verificación en dos pasos, así que dales una cuenta de demostración con datos de ejemplo:

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

Las notas para los revisores solo llegan a los revisores de Enconvo. No forman parte del paquete ni de la ficha de la tienda.

## Comercio

Un plugin puede funcionar con una cuenta por la que los usuarios ya pagan, y puede indicar cuándo una función requiere otro plan. Si vende algo o cobra pagos, indícalo en los materiales de revisión (`commerce` y `commerce_description`, más abajo): qué se vende y dónde se paga. Los usuarios pagan en tu propio sitio; el plugin no oculta cargos ni cobra más a los usuarios de Enconvo que a los demás.

El portal de OpenAI es más estricto. Solo acepta plugins que venden bienes físicos, y no suscripciones, créditos ni otros productos digitales. Consulta sus [reglas de comercio](https://developers.openai.com/apps-sdk/app-submission-guidelines) antes de enviarlo allí.

## Seguridad

- El plugin es apto para un público general, incluidos los adolescentes, y no se dirige a menores de 13 años.
- Hace lo que el usuario ha pedido y nada más: sin contenido no relacionado, redirecciones ni anuncios.
- Sus descripciones, prompts y habilidades nunca piden secretos, mueven dinero o datos sin el consentimiento del usuario, intentan anular las salvaguardas de Enconvo ni ocultan lo que hace el plugin, tampoco mediante instrucciones codificadas.
- No extrae datos de sitios web ni envuelve otros servicios incumpliendo sus condiciones, ni evita sus límites de frecuencia y controles de acceso.
- No vende ni habilita nada de la lista de [bienes y servicios prohibidos](https://developers.openai.com/apps-sdk/app-submission-guidelines) de OpenAI, como armas, drogas, juegos de azar, contenido para adultos, malware o fraude financiero.

## Materiales de revisión

Los materiales de revisión indican a los revisores qué probar: los prompts que el plugin debe atender, los que debe dejar pasar y un breve vídeo de demostración. Se almacenan con cada versión y solo los ven los revisores.

En un plugin de Codex, de Claude Code o portable, van donde los lee el portal de OpenAI, dentro de `extensions["com.openai"]` de un único `plugin.json`. OpenAI los importa desde `.codex-plugin/plugin.json` cuando el plugin tiene uno, como lo crea `enconvo plugin create`; desde el `plugin.json` de la raíz cuando este tiene su propio `extensions["com.openai"]` o no hay manifiesto de Codex; y desde `.claude-plugin/plugin.json` en un plugin hecho solo para Claude Code. No añadas `extensions["com.openai"]` al `plugin.json` de la raíz solo para ellos: Codex ignoraría entonces la ficha de `.codex-plugin/plugin.json`. `enconvo plugin validate --openai` indica en qué manifiesto deben ir.

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

En un plugin de Enconvo, el mismo objeto `review` va en el nivel superior de `package.json`.

| Campo | Qué contiene |
|---|---|
| `test_cases.positive` | Prompts que el plugin debe atender, cada uno con una `description`, el `prompt`, `expected_behavior` y las `tools_triggered`. Opcionales: `file_attachment_urls` y `expected_output_url`. |
| `test_cases.negative` | Prompts que el plugin debe dejar para otra cosa, cada uno con una `description` y el `prompt`. |
| `demo_recording_url` | Un vídeo con los prompts y herramientas principales. |
| `commerce`, `commerce_description` | Si el plugin vende algo, y qué y dónde. |
| `publication.release_notes` | Qué ha cambiado. `plugin publish` las usa como registro de cambios de la tienda salvo que pases `-m`. |

Cada lista admite hasta 20 casos. Los campos de texto admiten hasta 4000 caracteres, y cada dirección es una dirección `https://` que los revisores pueden abrir. `validate` y `publish` rechazan los materiales que incumplen estos límites.

Los datos de inicio de sesión nunca van en el paquete, porque cualquiera puede descargarlo. `validate` y `publish` rechazan un `review` que tenga `test_credentials` o `reviewer_instructions`; pásalos con `--review-notes`, o en el formulario Review details del panel de OpenAI.

En `plugin.json`, `publication` también puede contener lo que el portal de OpenAI importa para la ficha, y `validate --openai` lo comprueba como lo hace el portal. Enconvo muestra `translations` en el idioma de su interfaz para un plugin instalado y antes de instalar uno desde una fuente; las páginas de la tienda de Enconvo todavía no las usan:

| Campo | Qué contiene |
|---|---|
| `countries` | Dónde está disponible el plugin, como códigos de país en mayúsculas, por ejemplo `["US", "GB"]`. `[]` lo hace disponible en todas partes. |
| `translations` | Texto de la ficha por idioma, como `{"fr-FR": {"subtitle": "…", "description": "…"}}`. Un subtítulo es una línea de hasta 30 caracteres; una descripción, hasta 4000. |

Un campo definido como `null` conserva el valor ya guardado en el panel de OpenAI. Los casos de prueba a nivel de plugin son para un plugin con exactamente un servidor MCP.

El envío final a OpenAI de un plugin con un servidor MCP o una app requiere exactamente 5 casos positivos y 3 negativos, una grabación de demostración y notas de versión; un plugin con solo habilidades necesita únicamente las notas de versión. `validate --openai` enumera lo que falta como avisos, porque la subida al portal acepta un plugin sin ellos y solo los pide en el envío final.

## Lista de comprobación del envío

Antes de ejecutar `plugin publish`:

- `plugin validate` no informa de errores y has leído sus avisos.
- `version` es superior a la última versión que publicaste, y todos los manifiestos del paquete indican el mismo nombre y la misma versión.
- En una actualización, `plugin validate --previous` con el zip de la versión anterior no informa de nada que no esperases: una actualización sustituye todo el plugin, así que una habilidad o un servidor MCP que omita se elimina (`plugin_components_removed`).
- El título, la descripción y el icono dicen lo que hace el plugin, y las capturas lo muestran funcionando.
- Hay una página de inicio o una dirección de soporte definidas, y se enlaza una política de privacidad si el plugin envía datos a algún sitio.
- Cada herramienta MCP tiene un nombre y una descripción claros y define `readOnlyHint`, `destructiveHint` y `openWorldHint`, y `plugin scan` las enumera sin problemas.
- Las habilidades indican en su `description` cuándo usarlas.
- Los ajustes obligatorios, como una clave de API, se declaran como ajustes, no se piden en el chat.
- No hay claves, tokens ni archivos privados en la carpeta.
- Los materiales de revisión enumeran prompts para probar y prompts que dejar pasar, y hay una cuenta de demostración lista para `--review-notes` si hace falta iniciar sesión.
- Has instalado el paquete desde su carpeta (`plugin install .`) y has probado los casos de prueba en Enconvo.

## Qué ocurre después del envío

1. `plugin publish` comprueba el plugin y que su versión sea superior a la que ha publicado la tienda, luego lo sube y envía la versión a revisión. Hasta que un plugin nuevo se aprueba, solo tú puedes verlo.
2. Un revisor lee la ficha, los archivos del paquete (con lo que ha cambiado desde la versión publicada), los materiales de revisión y tus notas, y prueba los casos de prueba.
3. Una versión aprobada aparece en la tienda, y las copias instaladas reciben la oferta de actualización. Si se rechaza una versión, recibes un correo con el motivo. Corrígela, sube la versión y vuelve a publicar.

Enconvo también investiga los informes sobre plugins publicados. Un plugin que incumpla estas directrices, incluso uno aprobado antes, puede retirarse de la tienda, y se envía un correo a su desarrollador con el motivo.

## Enviar también a OpenAI

La misma carpeta puede ir al portal de plugins de OpenAI:

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai` genera el zip que acepta el portal. Las credenciales para los revisores de OpenAI van en el formulario de envío del portal, nunca en el paquete. Mantén también fuera tus propias claves: `pack` y `publish` excluyen los archivos `.env`, y `validate` avisa de un archivo que parece una clave privada o un inicio de sesión (`archive_member_secret`).

### Nombre del plugin

El portal solo acepta letras, dígitos, `-` y `_` en el `name` del plugin, y OpenAI sugiere letras minúsculas, dígitos y guiones sencillos. Codex, Claude Code y Enconvo también instalan un nombre con puntos como `acme.tools`, pero `validate --openai` y `pack --openai` lo rechazan (`plugin_name_format`), así que llama `acme-tools` a un plugin que pienses enviar.

### Servidor MCP y dominio

Tras la subida, el portal se conecta al servidor MCP del plugin y analiza sus herramientas; cuando el servidor cambia, vuelve a analizarlo allí. Solo llega al servidor en una URL `https://` pública, así que un servidor que se ejecuta en el ordenador del usuario debe desplegarse antes; `scan --openai` avisa de uno (`mcp_server_not_remote`). En el envío final, el portal pide las tres anotaciones en cada herramienta. Ya no te pide justificarlas; si su revisión automática marca una, puedes apelar con una explicación. Un plugin cuyas vistas incrustan páginas sigue necesitando una justificación para cada página incrustada: qué hace, por qué la incrusta el plugin y quién controla su dominio. Se permiten las páginas del propio dominio registrable del servidor MCP, y los inquilinos separados de un host compartido cuentan como dominios distintos. `scan --openai` enumera los dominios que incrustan tus vistas (`frame_domain_explanation_required`).

Antes de poder enviar el plugin, el portal verifica que controlas el dominio del servidor MCP: te da un token que debes servir como texto sin formato en `/.well-known/openai-apps-challenge` en el host del servidor o en un dominio superior. `scan --openai` indica qué responden esas URL, y `scan --challenge-token <token>` comprueba que una sirva exactamente el token antes de seleccionar **Verify Domain**; consulta [Domain verification](/extensions/validation-codes#domain-verification).

El portal de OpenAI conecta solo un servidor MCP por plugin para analizarlo y revisarlo, así que `validate --openai` avisa de un plugin con más. El mismo servidor declarado para Codex en `mcp.json` y para Claude Code en `.mcp.json` cuenta una sola vez.

### Actualizar un plugin publicado

Para actualizar un plugin que publicaste allí, sube un ZIP completo con una versión superior y todo lo que quieras conservar. Si no guardaste el zip de la versión publicada, el portal te lo da con **Download release ZIP** en el menú **…** de esa versión; comprueba la versión nueva con él mediante `validate --openai --previous <zip>`. El portal no puede añadir un servidor MCP a un plugin publicado que no tenía ninguno, ni cambiar la URL de un servidor publicado (pídelo al soporte de OpenAI), y `--previous` informa de ambos; consulta [Updates](/extensions/validation-codes#updates).

### Envío final

El envío final de OpenAI exige más a la ficha que su subida, y `validate --openai` avisa de cada carencia:

- `interface.longDescription` y una `interface.category`; sin ella, el directorio lista el plugin en Other.
- Para un plugin con un servidor MCP, `websiteURL`, `supportURL`, `privacyPolicyURL` y `termsOfServiceURL`, cada una una dirección `https://` de hasta 1024 caracteres.
- Una ficha propia. Un plugin de Claude Code con solo `.claude-plugin/plugin.json` recibe una que el portal rellena con valores por defecto (`claude_format_normalized`), así que añade un `.codex-plugin/plugin.json` con una `interface` para escribirla tú.
- Capturas de pantalla solo cuando el servidor MCP tiene su propia interfaz: un PNG o JPEG por cada prompt inicial, de exactamente 706 píxeles de ancho y entre 400 y 860 píxeles de alto. El portal lo decide a partir de su análisis, así que `scan --openai` rechaza las capturas cuando ninguna herramienta muestra una interfaz (`screenshots_not_allowed`). El directorio de OpenAI ya no muestra capturas y presenta un plugin mediante sus prompts iniciales, así que escríbelos con cuidado.

El directorio muestra el nombre de desarrollador de tu identidad verificada de OpenAI, diga lo que diga `interface.developerName`. Consulta [OpenAI's final submission](/extensions/validation-codes#openai’s-final-submission) para los códigos.
