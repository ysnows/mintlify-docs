This page explains what sits behind [Context Awareness](/features/context-awareness): the items Enconvo can read from your Mac, how it reads each one, and how you decide what goes into a message. Read it when you want to control what reaches a model, or when context you expect doesn't appear.

Context Awareness doesn't watch your screen in the background. It reads context when you open SmartBar or when you add an item yourself, from the app you were using just before.

## What Enconvo can read

Each kind of context is an item that can be added to a message.

| Context item | What it holds | How Enconvo reads it |
|---|---|---|
| **Selected Text** | The text selected in the app | Accessibility |
| **Current Application Content** | The window's title and text, the document's address when the app gives one, and a screenshot of the window | Accessibility and a window capture |
| **Browser Current Tab URL** | The front tab's address, its title and the page's text | Apple Events; see [Browsers](#browsers) |
| **Finder Selected Items** | The files and folders selected in Finder, as paths | Apple Events |
| **Finder Current Directory URL** | The folder open in the front Finder window | Apple Events |
| **Clipboard Text** | The text on the clipboard | The clipboard, only when you add it |
| **User Select Area Screenshot** | An area of the screen you select | Screen capture |
| **Current Application Screenshot** | The app you were using | Screen capture |
| **Current Screen Screenshot** | The whole screen | Screen capture |
| **Live Screen Screenshot** | The screen as it is now, without Enconvo's windows | Screen capture |

Enconvo reads paths for Finder items, not the files' contents.

### Browsers

- **Address and title**: read over Apple Events from Safari, Chrome, Edge, Arc and other Chromium browsers. Firefox doesn't give its tab's address, so Enconvo can't read it.
- **Page text**: Safari gives it directly. For other browsers, Enconvo reads the window through Accessibility, which works only while the browser is the frontmost app.

### Other apps

Code editors, text editors and every other app get **Current Application Content**: the window's title, the text Accessibility exposes, the document's address when the app gives one, and a screenshot of the window. How much text that is depends on the app.

## When SmartBar opens

When you open SmartBar, it checks three sources in the app you were using. **Settings → Context Awareness** sets what happens with each one:

| Source | Default | What it picks up |
|---|---|---|
| **Selected Text** | **Attach** | Text selected in the app you were using |
| **Finder Selection** | **Suggest** | Files and folders selected in Finder |
| **Current Browser Page** | **Suggest** | The page open in Safari, Chrome, Arc, Edge or another Chromium browser |

- **Attach** adds the item to the input as soon as SmartBar opens.
- **Suggest** lists it above the commands, so you add it with one click. A suggested page's text is read only when you click it.
- **Off** leaves the source alone.

Only SmartBar uses these settings. Commands you run on a selection always receive the selected text.

## Add context yourself

1. In SmartBar, type `#`.
2. Type a few letters to filter the list of context items.
3. Pick one. Enconvo reads it and adds it to your message.

To use another character, change **Context** in **Settings → SmartBar**, under **Search**. The same group sets `@` for commands, `$` for skills and `>` for recent tasks.

## Permissions

| Permission | Needed for |
|---|---|
| **Accessibility** | Selected text, window content, and page text from browsers other than Safari |
| **Automation** | Finder items and browser pages. macOS asks the first time Enconvo reads each app |
| **Screen Recording** (Screen & System Audio Recording) | Screenshots and the window capture in **Current Application Content** |

Grant them in **System Settings → Privacy & Security**. Enconvo notices a change to Accessibility on its own. See [Permissions](/configuration/permissions) for the full list.

## Context and tokens

Context counts against the model's context window. Page text and screenshots are the largest items, and they can:

- Make replies slower
- Cost more with cloud models
- Leave less room for the conversation's history

<Tip>
In a long chat, add a page or a screenshot only to the message that needs it, instead of attaching it every time.
</Tip>

## Privacy and data flow

Captured context can become part of a saved conversation or knowledge base item. Model requests and selected OCR, embedding, transcription, or other tool providers may receive relevant content. Review [Privacy & Security](/configuration/privacy-security) for the distinction between local storage and provider processing.

A local chat model alone does not make every tool offline. Check the whole flow, including browser access, captures, and provider-based processing. macOS permissions reduce the context available; they are not a promise that every third-party app field can be classified as sensitive.

## Troubleshooting

| Problem | What to do |
|---|---|
| No selected text or window content | Turn on Enconvo in **System Settings → Privacy & Security → Accessibility**. Some apps don't expose their text through Accessibility; copy the text and add **Clipboard Text** with `#` instead. |
| No browser page or Finder items | Turn on Enconvo for that app in **System Settings → Privacy & Security → Automation**. |
| No address from Firefox | Firefox doesn't give its tab's address. Use another browser, or copy the address. |
| A page comes without its text | Outside Safari, page text is read only while the browser is frontmost. Open SmartBar from the browser. |
| Context comes from the wrong app | Context comes from the app you were using when SmartBar opened. Wait until the app you want is in front, then open SmartBar. |
| Screenshots fail | Turn on Enconvo in **System Settings → Privacy & Security → Screen & System Audio Recording**. |
