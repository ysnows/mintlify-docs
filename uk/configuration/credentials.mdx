Кожному провайдеру, яким ви користуєтеся, потрібні облікові дані: ключ API або вхід у тариф, за який ви вже платите. Ви додаєте їх на власній сторінці параметрів провайдера, а Enconvo зберігає їх у профілі провайдера, спільному для кожної функції, що його використовує. **Параметри → Керування обліковими даними** показує всі облікові дані в одному місці.

Це відео завершується керуванням обліковими даними, після аватара й каналів IM.

## Додати провайдера

<Steps>
  <Step title="Відкрити категорію">
    Відкрийте сторінку параметрів того, чим хочете користуватися, наприклад **Параметри → Модель ШІ**, **Параметри → Генерація зображень** або **Параметри → Синтез мовлення**.
  </Step>
  <Step title="Вибрати провайдера">
    Виберіть провайдера. Щоб налаштувати другу копію, для іншого ключа або облікового запису, виберіть **Додати нового провайдера**.
  </Step>
  <Step title="Вибрати спосіб входу">
    У розділі **Автентифікація** виберіть **Ключ API** або **Підписка**, коли провайдер дозволяє користуватися тарифом, за який ви платите.
  </Step>
  <Step title="Додати облікові дані">
    Вставте ключ API або завершіть вхід провайдера.
  </Step>
  <Step title="Перевірити">
    Натисніть **Перевірити**, якщо сторінка це показує, виберіть модель і спробуйте короткий запит.
  </Step>
</Steps>

Ключ API виставляється на рахунок API провайдера. Підписка використовує включене в тариф використання і його ліміти. Текст під **Автентифікація** каже, що саме використовує сторінка.

## Спільні профілі

Профіль провайдера, наприклад **OpenAI 2**, тримає ключ API провайдера і вхід у підписку і з’являється в кожній категорії, яку провайдер підтримує. Перейменування або видалення профілю змінює його в усіх цих категоріях, а не лише на відкритій сторінці.

Кожна категорія зберігає власні параметри моделі, голосу й генерації. Новий ключ API, однак, доходить до кожної функції, що використовує профіль, тож після зміни перевірте ці функції.

Те, що пропонує провайдер, залежить від категорії. Вхід, який працює для чату ШІ, не означає, що входить API голосу в реальному часі. Коли категорія приймає лише ключ API, її сторінка про це каже і називає категорії, де працює підписка.

## Перевірити використання тарифу

Вхід у підписку показує ваш обліковий запис і скільки тарифу лишилося. Значення на кшталт **% залишилося** — це залишок вашого ліміту. Відкрийте меню картки облікового запису і виберіть **Оновити використання**, щоб оновити його, або **Під’єднатися знову**, щоб увійти ще раз.

Коли Claude або Codex надали вам безкоштовні скидання ліміту, картка підписки Claude або ChatGPT показує **Скидання безкоштовного ліміту**: скільки їх є і до коли. Натисніть **Скинути ліміти** і підтвердьте, щоб поповнити ліміти. Якщо їх більше одного, картка їх перелічує, і ви використовуєте те, яке виберете.

Коли використання не показується, це не означає, що воно безлімітне.

## Керувати обліковими даними

Відкрийте **Параметри → Керування обліковими даними**. Список групує облікові дані за профілем провайдера, потім показує **Невикористані ключі**: ключі, яких не використовує жоден провайдер.

- Введіть текст у **Шукати постачальників...**, щоб знайти одного.
- Натисніть **Додати нові облікові дані**, щоб створити ще одні облікові дані для служби, яку виберете.
- Щоб видалити облікові дані, наведіть на них і натисніть іконку смітника. Якщо конектор ключа API використовує цей ключ, підтвердження називає його, а **Видалити й від’єднати** від’єднує його, доки ви не дасте інший ключ.
- Натисніть **Очистити** внизу списку, щоб одразу видалити всі невикористані ключі. Кнопка показує, скільки їх, а підтвердження спочатку їх перелічує. Enconvo ніколи не видаляє невикористані ключі сам.

Натисніть облікові дані, щоб додати або змінити ключ. **Використовується в** перелічує функції, які на них спираються, наприклад **Модель ШІ** або **Синтез мовлення**; натисніть одну, щоб відкрити ту сторінку параметрів.

Власні облікові дані профілю тут не мають кнопки видалення. Вони зникають, коли ви видаляєте провайдера.

Ще дві групи з’являються, коли вони у вас є: **Інші служби** для ключів до служб, для яких у Enconvo немає провайдера, і **Дані входу** для збережених входів на сайти й у програми.

## Коли агенту потрібен ключ

Коли завданню потрібен ключ API служби, агент показує в чаті картку **Під’єднати**, замість того щоб просити вставити ключ. Ключ іде в керування обліковими даними, а не в розмову, і пізніші чати використовують його без повторного запиту.

Для служби, для якої в Enconvo немає провайдера, картка показує хост, на який буде надіслано ключ. Ключ зберігається в **Інші служби**, і агент може використовувати його лише в запитах до цього хоста.

Агент ніколи не тримає ключ сам: він називає збережені облікові дані, а там, де запит або команда показали б ключ, читається `[redacted]`.

У чаті на телефоні картка **Під’єднати** показується на вашому iPhone, а ключ зберігається в керуванні обліковими даними на Mac. У чаті IM агент ніколи не просить ключ; натомість надсилає посилання, яке відкриває чат в Enconvo.

Якщо ви все ж вставите ключ API в повідомлення, Enconvo зберігає його в керуванні обліковими даними і замінює на `[redacted]` у збереженому чаті, тож пізніші запити й інші ваші пристрої його не несуть. Новий ключ, який ви вставляєте для служби, що вже має ключ, замінює збережений.

## Входи на сайти й у програми

Коли завдання в браузері доходить до сторінки входу, картка один раз запитує ім’я користувача й пароль. Enconvo заповнює їх лише на тому сайті, і агент ніколи не бачить пароль. Збережені входи з’являються в **Дані входу**. Зніміть позначку **Запам'ятати ці дані входу**, щоб використати їх лише для цього входу.

Коли вхід у програму Mac потребує пароля, картка називає програму. Enconvo вводить ім’я користувача й пароль лише в ту програму, а пароль — лише в поле, яке приховує те, що ви вводите.

## Власні кінцеві точки

Провайдери **OpenAI Compatible** і **Anthropic Compatible** мають поле базового URL API для вашого сервера. Деякі вбудовані провайдери тримають параметр кінцевої точки в **Керування обліковими даними**. Про сервер моделей на іншому комп’ютері див. [Локальні моделі](/uk/ai/local-llm).

Лише власні вікна Enconvo можуть змінювати, куди надсилається збережений ключ: адреса провайдера або облікових даних, або використання збереженого ключа сервером MCP. Інші програми, що користуються Local API, телефон і агенти отримують відмову.

## Як зберігаються ключі

- Кожен збережений ключ і вхід шифруються ключем, який лишається в Keychain цього Mac, тож копію папки параметрів Enconvo не можна прочитати на іншому комп’ютері. Якщо ви повернетеся до старішої версії Enconvo, ключі треба ввести знову.
- Інша програма, яка запитує параметри через [Local API](/uk/advanced/cli-local-api) Enconvo, отримує `[hidden]` замість кожного ключа. Плагін із магазину може використовувати лише власні ключі й облікові дані, вибрані в його параметрах.
- Відкривати збережені ключі може лише код, який установив Enconvo і який не змінено. Параметри показують і перевіряють ключі, як і раніше.

## Усунення неполадок

| Проблема | Що робити |
| --- | --- |
| Перевірка не вдається | Перевірте вибраний профіль, спосіб автентифікації, кінцеву точку і те, що обліковий запис провайдера має доступ. |
| Одна функція працює, інша ні | Перевірте, що обліковий запис підтримує цю функцію й модель. Сторінка каже, коли категорія приймає лише ключ API. |
| Щось перестало працювати після зміни ключа | Профіль спільний. Перевірте інші категорії, які його використовують. |
| Область використання показує **Під’єднатися знову** | Вхід закінчився. Натисніть **Під’єднатися знову** і ввійдіть ще раз. |
