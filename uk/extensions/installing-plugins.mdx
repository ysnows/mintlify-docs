Більшість людей інсталюють плагіни з магазину плагінів на сторінці **Плагіни** в Enconvo. Enconvo також інсталює плагіни з інших місць, зокрема плагіни Codex і Claude Code, які їхні розробники публікують на GitHub та в маркетплейсах плагінів. Про пакети, які читає Enconvo, дивіться [Формати плагінів](/extensions/plugin-formats).

Щоб інсталювати із застосунку, прочитайте [Зі сторінки Плагіни](#зі-сторінки-плагіни) та [З чату](#з-чату). Решта сторінки призначена для розробників і досвідчених користувачів: інсталяція з Терміналу, додавання маркетплейсів плагінів, оновлення та видалення, а також поширення власного плагіна.

<Warning>
Лише плагіни з магазину Enconvo проходять перевірку в Enconvo. Плагін з будь-якого іншого місця може запускати програми на вашому Mac через свої сервери MCP, тож інсталюйте його лише з джерела, якому довіряєте.
</Warning>

## Зі сторінки Плагіни

Натисніть **Додати** на сторінці **Плагіни**:

| Параметр | Що він робить |
|---|---|
| **Створити плагін** | Починає чат, у якому агент Enconvo створює плагін разом із вами. |
| **Вивантажити архів плагіна…** | Інсталює файл: пакет `.enconvo` або `.zip` плагіна Claude Code чи Codex. |
| **Додати з GitHub…** | Інсталює плагін або плагін із маркетплейсу плагінів з GitHub, git, npm чи папки (дивіться нижче). |
| **Додати сервер MCP…** | Відкриває параметри MCP, щоб підключити один сервер без плагіна навколо нього. |
| **Додати розширення PopBar…** | Інсталює розширення PopBar із посилання, файлу чи фрагмента `#popclip` (дивіться [Розширення PopBar](/uk/features/popbar)). |
| **Нова навичка…** | Відкриває параметри Навичок, щоб написати власну навичку. |
| **Посібник розробника** | Відкриває [Розробка розширень](/uk/extensions/developing). |

Те, що ви додали, міститься в розділі **Інстальовано** вгорі вкладки **Enconvo**: підключені Конектори та плагіни, які ви інсталювали або створили, за назвою. Натисніть **Інстальовано**, щоб побачити їх усі. Плагіни, що постачаються з Enconvo, там не показано. Розширення PopBar мають власну вкладку **PopBar** із перевіреним каталогом Enconvo; дивіться [Розширення PopBar](/uk/features/popbar).

### Додавання з GitHub

Вставте, де міститься плагін, і натисніть **Попередній перегляд**:

- `owner/repo` або посилання GitHub, зокрема на папку (`/tree/<branch>/<folder>`)
- `owner/repo/folder` для плагіна всередині репозиторію, з `@branch` або `@tag`, щоб закріпити версію
- будь-яка адреса git через https
- `npm:<package>`, з `@version`, щоб закріпити версію
- посилання https на `.zip` плагіна
- папка на вашому Mac

Приватний репозиторій GitHub чи git теж підходить. Enconvo використовує обліковий запис GitHub, у який уже виконано вхід на вашому Mac, або ваш ключ SSH, тож пароль вводити не потрібно.

Enconvo показує плагін, перш ніж щось інсталювати: його формат (Codex, Claude Code, переносний або Enconvo), версію, розробника, навички, сервери MCP і хуки, а також застосунки ChatGPT, які він містить і які Enconvo не завантажує. Для кожного сервера MCP зазначено, чи він запускається на вашому Mac, чи підключається через інтернет. Хуки плагіна запускають команди на вашому Mac, тому вони вимкнені, доки ви не позначите **Дозволити запуск хуків**. Натисніть **Інсталювати**, і Enconvo відкриє сторінку плагіна. У рядку **Джерело** вказано, звідки взято плагін (для GitHub і git — з комітом), а також є посилання на репозиторій чи сторінку npm, а примітка внизу називає розробника плагіна: лише власні плагіни Enconvo та плагіни з її магазину вказують, що їх створила Enconvo. Плагіни, інстальовані так, наведено в розділі **Особисте**. Повторна інсталяція з того самого місця оновлює плагін. Якщо плагін з такою самою назвою уже інстальовано з іншого місця, спершу видаліть його.

Якщо адреса веде до маркетплейсу плагінів, діалог показує його плагіни з кнопкою **Інсталювати** біля кожного. Інсталяція одного з них додає маркетплейс, який потім відображається в розділі **Ваші маркетплейси** під час наступного відкриття діалогу.

Початковий код плагіна Enconvo потрібно зібрати, перш ніж він запрацює, тож діалог натомість дає команду `enconvo plugin install`, яку слід виконати в Терміналі.

## З чату

Коли ви просите агента Enconvo про те, чого не вміють ваші плагіни, він може пошукати плагін у маркетплейсах плагінів на вашому Mac: тих, що ви додали в Enconvo, і тих, які є в Codex чи Claude Code, але ще немає в Enconvo, зокрема в маркетплейсі OpenAI Curated, що постачається з Codex (дивіться [Маркетплейси, додані в Codex або Claude Code](#маркетплейси-додані-в-codex-або-claude-code)). Він читає копії їхніх каталогів, що вже є на вашому Mac, і під час пошуку нічого не завантажує. Він пропускає плагіни, які ви вже інсталювали, та плагіни з такою самою назвою, як у тих, що інстальовано з іншого місця.

Коли агент щось знаходить, він показує в чаті картку, і нічого не інсталюється, доки ви не натиснете **Інсталювати**:

- Для маркетплейсу, який ви додали в Enconvo, на картці вказано, які сервери MCP плагін запускає на вашому Mac або до яких підключається, його навички та інші плагіни, яких він потребує.
- Для маркетплейсу, який є лише в Codex чи Claude Code, на картці сказано, що інсталяція додасть цей маркетплейс до Enconvo. Enconvo не може прочитати вміст плагіна до цього, тому картка не може його перелічити.

В обох випадках хуки плагіна залишаються вимкненими, доки ви не ввімкнете їх у **Плагінах**. Коли плагін не можна інсталювати, наприклад тому, що не можна інсталювати потрібний йому плагін, агент повідомляє про це замість показу картки.

### Плагіни з ChatGPT

Плагіни з [каталогу плагінів ChatGPT](https://chatgpt.com/plugins) не можна інсталювати в Enconvo. Більшість із них — це застосунки ChatGPT, які працюють лише всередині ChatGPT, а решту OpenAI надає лише ChatGPT і Codex. Якщо ви виконали вхід у Codex на вашому Mac, агент знає каталог за копією, яку зберігає Codex. Коли ви називаєте один із його плагінів або вставляєте посилання на chatgpt.com, агент пояснює, чому не може його інсталювати, і пропонує щось рівноцінне: Конектор, сервер MCP, навичку або плагін з такою самою назвою в одному з ваших маркетплейсів. Багато плагінів каталогу, що постачаються з файлами, мають також плагін із такою самою назвою в OpenAI Curated, маркетплейсі, що постачається з Codex (публічний репозиторій OpenAI `openai/plugins`). Агент пропонує цей плагін, а його інсталяція додає OpenAI Curated до Enconvo. Enconvo не завантажує застосунки ChatGPT, які містять ці плагіни, а лише їхні навички та сервери MCP.

Посилання chatgpt.com не працює й у **Додати з GitHub**; діалог повідомляє те саме.

## З командного рядка

`plugin install` бере плагін з GitHub, git, npm, zip в інтернеті, папки чи маркетплейсу. Потрібно, щоб працювала Enconvo 2.5.6 або новіша.

```sh
npx -p @enconvo/api enconvo plugin install <source>
```

| Джерело | Приклад |
|---|---|
| Репозиторій GitHub, за потреби з папкою в ньому та гілкою, тегом чи комітом | `acme/notes`, `acme/plugins/notes@v1.2.0` |
| Адреса GitHub | `https://github.com/acme/plugins/tree/main/notes` |
| Будь-який інший репозиторій git через https (потрібен git); адреса ssh працює лише для GitHub | `https://git.example.com/notes.git`, `git@github.com:acme/notes.git` |
| Пакет npm | `npm:@acme/notes-plugin`, `npm:@acme/notes-plugin@1.2.0` |
| Zip плагіна в інтернеті (лише публічний https) | `https://downloads.acme.com/notes-1.2.0.zip` |
| Папка на вашому Mac | `./notes`, `~/code/notes`, `/Users/ada/notes` |
| Плагін у доданому маркетплейсі | `notes@acme-plugins` |

<Note>
`plugin install` і `plugin marketplace` потребують випуску `@enconvo/api` новішого за 0.1.174. Усередині проєкту, що залежить від `@enconvo/api`, достатньо `npx enconvo …`. `marketplace import` також потребує Enconvo 2.5.7 або новішої.
</Note>

Додайте `--preview`, щоб побачити, що буде інстальовано і звідки, без інсталяції.

Коли джерело — це маркетплейс плагінів, а не плагін, `plugin install` перелічує його плагіни. Якщо в маркетплейсі їх понад 200, буде показано перші 200 і сказано, скільки ще є; `plugin marketplace add` перелічує всі. Виберіть один за допомогою `--plugin`, що також додає маркетплейс:

```sh
npx -p @enconvo/api enconvo plugin install acme/plugins --plugin notes
```

### Що відбувається під час інсталяції

- **Параметри**: плагін з обов'язковими параметрами, наприклад ключем API, інсталюється, а потім просить їх. `plugin install` називає їх; заповніть їх на сторінці плагіна.
- **Плагіни Enconvo з початкового коду**: коли репозиторій GitHub або папка містить плагін Enconvo, який ще не зібрано, `plugin install` спершу збирає його. Папку збирають на місці після `npm install`.
- **Знайомство**: коли плагін називає навичку знайомства, Enconvo пропонує запустити її після першої інсталяції.
- **Вхід**: коли сервери MCP плагіна потребують входу, як-от у Notion чи Figma, сторінка Плагіни показує **Увійти** одразу після інсталяції. Enconvo відкриває сторінку входу сервера у вашому браузері й пропонує наступний сервер, щойно цей підключиться. `plugin install` натомість називає сервери. Вхід, який ви пропустили, чекає в **Параметри → Сервери MCP**.
- **Хуки**: [хуки](/extensions/plugin-formats#hooks) плагіна інсталюються вимкненими, бо вони запускають команди. `--preview` перелічує їх; дозвольте їх перемикачем **Дозволити хуки** на сторінці плагіна. Хуки, які ви дозволили, залишаються ввімкненими під час оновлень, що їх не змінюють.
- **Залежності**: коли плагін Claude Code з маркетплейсу потребує інших плагінів, Enconvo інсталює їх разом із ним (дивіться [Маркетплейси плагінів](#маркетплейси-плагінів)). `--preview` перелічує їх і вказує, які вже інстальовано, які буде інстальовано, а які не можна. Залежність, оголошена записом маркетплейсу з маркетплейсу, що не дозволений, зупиняє інсталяцію; залежність, оголошену у власному `plugin.json` плагіна, пропускають, а інсталяція триває. Їхні хуки залишаються вимкненими, а видалення плагіна зберігає їх, доки ви не приберете їх очищенням (дивіться [Видалення](#видалення)).
- **Використання**: як у Codex, введіть `@` у чаті й виберіть плагін або натисніть один із промптів у розділі **Спробуйте запитати** на його сторінці. У будь-якому разі до чату прикріплюється плагін. Кожен інстальований плагін є в меню `@`, зокрема плагін Codex чи Claude Code, що не називає категорії.
- **Однакова назва**: повторна інсталяція з того самого джерела оновлює плагін. Якщо плагін з такою самою назвою уже інстальовано з іншого місця, наприклад з магазину, Enconvo його не чіпає й просить спершу його видалити.

Коли Enconvo не запущено, `plugin install` усе одно може інсталювати плагін Enconvo з GitHub, зібравши його. Для всього іншого відкрийте Enconvo і спробуйте ще раз.

## Маркетплейси плагінів

Маркетплейс — це каталог плагінів у репозиторії чи папці. Enconvo читає обидва види: `.agents/plugins/marketplace.json` від Codex і `.claude-plugin/marketplace.json` від Claude Code.

```sh
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins   # GitHub, a git address or a folder
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins --ref v2   # at a branch, tag or commit
npx -p @enconvo/api enconvo plugin marketplace list               # added marketplaces and their plugins
npx -p @enconvo/api enconvo plugin install notes@acme-plugins     # install one of them
npx -p @enconvo/api enconvo plugin marketplace refresh            # fetch them again for new plugins
npx -p @enconvo/api enconvo plugin marketplace remove acme-plugins
```

`refresh` також відповідає на `upgrade` (назва в Codex) і `update` (назва в Claude Code), а `--ref v2` — те саме, що `acme/plugins@v2`.

На сторінці Плагіни відкрийте **Додати → Додати з GitHub…** і вставте адресу маркетплейсу або виберіть один із доданих у розділі **Ваші маркетплейси**.

Enconvo зберігає копію маркетплейсу з GitHub чи git, а маркетплейс-папку читає там, де вона є. Видалення маркетплейсу зберігає плагіни, які ви з нього інсталювали.

### Маркетплейси, додані в Codex або Claude Code

Якщо ви додавали маркетплейси в Codex чи Claude Code на цьому Mac або Codex отримав свій маркетплейс OpenAI Curated, `marketplace list` показує ті, яких у Enconvo ще немає, а `import` додає їх, щоб не вводити їхні адреси знову:

```sh
npx -p @enconvo/api enconvo plugin marketplace import                            # all of them
npx -p @enconvo/api enconvo plugin marketplace import claude-plugins-official    # only these
```

Enconvo знаходить їх у `~/.codex/config.toml` від Codex, його копії OpenAI Curated та його особистому `~/.agents/plugins/marketplace.json`, а також у списку відомих маркетплейсів Claude Code. Він лише читає ці файли й нічого не змінює в жодному із застосунків. OpenAI Curated додається з `openai/plugins` на GitHub. Він пропускає інші маркетплейси, що постачаються з Codex і містять плагіни для власних інструментів Codex, а також маркетплейси Claude Code, додані за вебадресою файлу `marketplace.json`, які Enconvo не додає. Коли в обох застосунках є маркетплейс з однаковою назвою, пропонується маркетплейс Codex.

Маркетплейси Codex, як-от OpenAI Curated, перелічують лише назву кожного плагіна та джерело, звідки він походить. Для плагіна в папці самого маркетплейсу Enconvo показує заголовок, опис, категорію та розробника з маніфесту плагіна, як і Codex, а агент знаходить його не лише за назвою, а й за призначенням. Те, що запис маркетплейсу каже про себе сам, має пріоритет.

Деякі плагіни OpenAI Curated, як-от Gmail, Google Drive, Outlook і Teams, працюють лише тоді, коли ви входите в Codex через ChatGPT, тож Codex не пропонує їх тим, хто входить за ключем API. Enconvo теж не входить у ChatGPT, тому показує їх як такі, що потребують входу в ChatGPT, не інсталює їх, а агент їх не пропонує. Для цих сервісів натомість додайте власний сервер MCP провайдера або Конектор.

### Звідки беруться плагіни маркетплейсу

Плагіни маркетплейсу можуть походити з папки в маркетплейсі, іншого репозиторію GitHub, адреси git, папки в репозиторії git, npm або zip в інтернеті (джерело `archive` у Claude Code). Плагін, який маркетплейс Codex позначає `NOT_AVAILABLE`, інсталювати не можна.

Джерело-папка, записане як `./plugins/notes`, читається від кореня маркетплейсу. Просту назву, як-от `notes`, читають із папки, яку називає `metadata.pluginRoot`, як у Claude Code, і для цього потрібне це поле.

Завантаження з GitHub, npm чи інтернету може тривати до трьох хвилин; якщо довше, Enconvo зупиняє його й просить перевірити підключення.

Zip, чи то ви вставили його посилання, чи його перелічує маркетплейс, завантажується лише з публічної адреси https, не більш як через п'ять перенаправлень. Коли маркетплейс указує свій `sha256`, завантаження, що не збігається, відхиляється. Плагін може лежати на верхньому рівні zip або всередині однієї папки.

### Записи маркетплейсу Claude Code

Записи маркетплейсу Claude Code працюють із власним `plugin.json` плагіна так, як їх читає Claude Code:

- Запис може додавати `commands`, `agents`, `skills`, `outputStyles` і `themes` до власних у плагіна, а його `hooks` замінюють хуки плагіна для тих самих подій.
- Запис із `"strict": false`, що також перелічує будь-що з цього, поверх плагіна з `plugin.json` відхиляється як конфлікт маніфестів. Тримайте їх в одному місці.
- Коли в плагіна немає `plugin.json`, запис і є його маніфестом.
- Показано назву запису, опис, автора й інші відомості зі списку; версія береться з плагіна.
- `renames` маркетплейсу враховуються. Плагін, інстальований під старою назвою, продовжує оновлюватися під новою, а інсталяція за старою назвою його знаходить. Назва, перейменована на `null`, була вилучена з маркетплейсу, і Enconvo про це повідомляє. Якщо власний маніфест плагіна теж змінив назву, Enconvo просить видалити старий плагін і інсталювати новий, бо Enconvo називає плагін за його маніфестом.
- `dependencies` плагіна, у його записі чи в `plugin.json`, інсталюються разом із ним. Кожна з них — це назва (`"formatter"`), назва та маркетплейс (`"formatter@acme-tools"`), будь-що з цього з діапазоном `^` (`"formatter@acme-tools@^2.1"`) або `{ "name", "marketplace", "version" }` з діапазоном semver. Залежність береться з власного маркетплейсу плагіна, якщо не названо інший, а інший маркетплейс має бути перелічений у `allowCrossMarketplaceDependenciesOn` маркетплейсом, з якого ви інсталювали. Залежність з діапазоном `version` інсталюється за найвищим тегом випуску (`<plugin>--v<version>`) у цьому діапазоні та в діапазонах, які накладають на неї інші інстальовані плагіни, з власного репозиторію плагіна або, для плагіна всередині маркетплейсу, з репозиторію маркетплейсу (папка маркетплейсу враховується, коли вона в репозиторії git). Без такого тегу плагін усередині маркетплейсу інсталюється таким, яким він є в маркетплейсі, а плагін у власному репозиторії відхиляється. Діапазони, яким не відповідає жодна версія, відхиляють інсталяцію, а оновлення залишаються в межах діапазонів. Залежність, яку вже інстальовано, залишається як є, а та, що поза своїм діапазоном `version`, отримує попередження.

### Перевірте маркетплейс, перш ніж ділитися

Перш ніж ділитися маркетплейсом, перевірте його та кожен плагін у ньому. Правила — ті, що застосовує `claude plugin validate`, плюс правила Codex для `.agents/plugins/marketplace.json`; дивіться [Коди перевірки](/extensions/validation-codes#marketplaces). Помилка означає, що Claude Code не може додати маркетплейс або інсталювати плагін, хоча й може його перелічити: поле неправильного типу в записі, `renames`, що не ведуть до плагіна, сигнали `relevance`, які він відхиляє, або назва маркетплейсу, схожа на одну з власних назв Anthropic, наприклад `claude-plugins-hub`. Попередження стосується того, що Claude Code ігнорує, як-от поле з помилкою в написанні, та назв, які відхиляє Claude Desktop.

```sh
npx -p @enconvo/api enconvo plugin validate path/to/marketplace
```

## Оновлення

Перевірка оновлень плагінів Enconvo охоплює також плагіни, інстальовані з GitHub, git, npm, папок і маркетплейсів, і перелічує їхні оновлення разом з оновленнями магазину. Вона читає останній коміт репозиторію без завантаження, питає npm про останню версію, помічає, коли інстальована папка змінилася, а для zip, який маркетплейс закріплює за `sha256`, помічає, коли закріплення змінюється. Оновлення знову інсталює плагін з того самого джерела.

Щоб перевірити один плагін, відкрийте його сторінку й виберіть **Перевірити наявність оновлень** у меню **⋯**. Коли є новіша версія, натисніть **Оновити** у повідомленні, що з'явиться.

Або оновіть один із Терміналу, як це робить `claude plugin update` у Claude Code:

```bash
npx -p @enconvo/api enconvo plugin update notes                # from wherever it came from, or the store
npx -p @enconvo/api enconvo plugin update notes@acme-plugins   # only if it came from that marketplace
```

Спершу вона перевіряє. Коли нічого новішого немає, повідомляє, що плагін уже має останню версію, і нічого не змінює; інакше оновлює плагін так, як це робить список оновлень.

## Видалення

Видаліть плагін з його меню чи сторінки на сторінці Плагіни, де спершу попросять підтвердження, або з Терміналу:

```bash
npx -p @enconvo/api enconvo plugin uninstall notes            # also: remove, rm
npx -p @enconvo/api enconvo plugin uninstall notes --prune    # and the dependencies nothing needs any more
npx -p @enconvo/api enconvo plugin prune --dry-run            # list them without removing anything
npx -p @enconvo/api enconvo plugin prune                      # remove them (also: autoremove)
```

Очищення вилучає лише плагіни, які було інстальовано, бо їх потребував інший плагін, коли жоден інстальований плагін їх уже не потребує, як це робить `claude plugin prune` у Claude Code. Плагін, який ви інсталювали самі, ніколи не вилучається очищенням, а повторна інсталяція залежності вами самими робить її вашою. У Терміналі Enconvo перелічує, що вилучить, і спершу питає; додайте `-y`, щоб пропустити запитання, чого вимагає `--prune`, коли не може спитати. Видалення зі сторінки Плагіни поки не очищує залежності.

## Опублікуйте власний

Щоб розмістити плагін у магазині Enconvo, дивіться [Правила магазину плагінів](/uk/extensions/publishing-guidelines). Щоб надіслати посилання, яке кожен може інсталювати, натисніть **Поділитися…** на сторінці плагіна; дивіться [Поділитися плагіном](/uk/extensions/overview). Щоб поділитися ним без Enconvo, надішліть його на GitHub або в маркетплейс, і люди зможуть інсталювати його через **Додати з GitHub…** чи наведені вище команди.

### Позначте випуск тегом

`plugin tag` позначає коміт, який ви випускаєте, тегом git з назвою `<plugin>--v<version>`, як це робить `claude plugin tag`. Claude Code та Enconvo вибирають із цих тегів, коли залежність іншого плагіна просить діапазон версій, і будь-хто може інсталювати цей випуск через Enconvo, наприклад `acme/plugins/notes@notes--v1.2.0`.

```sh
npx -p @enconvo/api enconvo plugin tag plugins/notes --dry-run   # check, and print the git commands
npx -p @enconvo/api enconvo plugin tag plugins/notes --push      # tag HEAD and push the tag to origin
```

Версія береться з маніфесту плагіна або з запису в його маркетплейсі, коли в маніфесті її немає, і має бути semver (`1.2.0`). Перед тегуванням `plugin tag` перевіряє плагін так, як це робить `plugin validate`, і зупиняється, коли запис маркетплейсу називає іншу версію, коли файли в папці плагіна не закомічено або коли тег уже існує. Підвищте версію для нового випуску; `--force` натомість пересуває наявний тег. Він теґує плагіни Codex, Claude Code, переносні та Enconvo однаково, тому кожен маніфест, який несе пакет, має називати ту саму версію. `-m` задає повідомлення тегу (`%s` — це версія), а `--remote` — віддалений репозиторій, у який надсилає `--push`. Як і `plugin install`, він потребує випуску `@enconvo/api` новішого за 0.1.174.
