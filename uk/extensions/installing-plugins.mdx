Більшість людей установлює плагіни з магазину плагінів на сторінці **Плагіни** Enconvo. Enconvo також установлює плагіни з інших місць, включно з плагінами Codex і Claude Code, які їхні розробники публікують на GitHub і в магазинах плагінів. Які пакети читає Enconvo, див. у [Plugin Formats](/extensions/plugin-formats).

Щоб установити з програми, читайте розділи «Зі сторінки плагінів» і «З чату» нижче. Решта сторінки для розробників і досвідчених користувачів: установлення з Terminal, додавання магазинів плагінів, оновлення й видалення та поширення власного плагіна.

<Warning>
Лише плагіни в магазині Enconvo перевіряє Enconvo. Плагін з будь-якого іншого місця може запускати програми на Mac через свої сервери MCP, тож установлюйте його лише з джерела, якому довіряєте.
</Warning>

## Зі сторінки плагінів

Клацніть **Додати** на сторінці **Плагіни**:

| Варіант | Що робить |
|---|---|
| **Створити плагін** | Починає чат, у якому агент Enconvo будує плагін разом із вами. |
| **Вивантажити архів плагіна…** | Установлює файл: пакет `.enconvo`, розширення робочого столу `.dxt` або `.zip` плагіна Claude Code чи Codex. |
| **Додати з GitHub…** | Установлює плагін або один із магазину плагінів із GitHub, git, npm чи теки (див. нижче). |
| **Додати сервер MCP…** | Відкриває параметри MCP, щоб під’єднати один сервер без плагіна навколо нього. |
| **Додати розширення PopBar…** | Установлює розширення PopBar із посилання, файлу або фрагмента `#popclip` (див. [Розширення PopBar](/uk/features/popbar)). |
| **Нова навичка…** | Відкриває параметри навичок, щоб написати власну навичку. |
| **Посібник розробника** | Відкриває [Розробка розширень](/uk/extensions/developing). |

Те, що ви додали, є в **Установлені**, угорі вкладки **Enconvo**: під’єднані конектори й плагіни, які ви встановили або створили, за назвою. Клацніть **Установлені**, щоб побачити всі. Плагіни, що йдуть з Enconvo, там не перелічені. Розширення PopBar мають власну вкладку **PopBar** з перевіреним каталогом Enconvo; див. [Розширення PopBar](/uk/features/popbar).

### Додайте з GitHub

Вставте, де плагін, і натисніть **Попередній перегляд**:

- `owner/repo` або посилання GitHub, включно з посиланням на теку (`/tree/<branch>/<folder>`)
- `owner/repo/folder` для плагіна всередині репозиторію, з `@branch` або `@tag`, щоб закріпити версію
- будь-яка адреса git https
- `npm:<package>`, з `@version`, щоб закріпити одну
- посилання https на `.zip` плагіна
- тека на Mac

Приватний репозиторій GitHub або git теж працює. Enconvo використовує обліковий запис GitHub, у який уже ввійшли на Mac, або ключ SSH, тож пароль вводити не треба.

Enconvo показує плагін, перш ніж щось установити: формат (Codex, Claude Code, портативний, розширення робочого столу або Enconvo), версію, розробника, навички, сервери MCP і хуки, а також програми ChatGPT, які він містить і які Enconvo не завантажує. Для кожного сервера MCP він каже, чи той запускається на Mac, чи під’єднується через інтернет. Хуки плагіна запускають команди на Mac, тож вони лишаються вимкненими, якщо ви не позначите **Дозволити його хукам виконуватися**. Клацніть **Установити**, і Enconvo відкриває сторінку плагіна. Рядок **Джерело** каже, звідки прийшов плагін (для GitHub і git — з комітом) і посилається на репозиторій або сторінку npm, а примітка внизу називає розробника, якого дає плагін: лише власні плагіни Enconvo і плагіни з його магазину кажуть, що їх створив Enconvo. Плагіни, установлені так, перелічені в **Особисте**. Повторне встановлення з того самого місця оновлює плагін. Якщо плагін із тією самою назвою вже встановлено з іншого місця, спершу видаліть його.

Коли адреса — магазин плагінів, діалог перелічує його плагіни з кнопкою **Установити** на кожному. Установлення одного додає магазин, який потім показується в **Ваші магазини** наступного разу, коли ви відкриєте діалог.

Вихідний код плагіна Enconvo треба зібрати, перш ніж він запрацює, тож діалог дає команду `enconvo plugin install`, яку треба запустити в Terminal натомість.

## З чату

Коли ви просите агента Enconvo про те, чого ваші плагіни не можуть, він може шукати плагін у магазинах плагінів на Mac: тих, які ви додали в Enconvo, і тих, які має Codex або Claude Code, а Enconvo ще ні, включно з магазином OpenAI Curated, що йде з Codex (див. розділ «Магазини, які ви додали в Codex або Claude Code» нижче). Він читає копії їхніх каталогів, уже наявні на Mac, і нічого не завантажує, поки шукає. Він пропускає плагіни, які ви встановили, і плагіни, названі як один, установлений з іншого місця.

Коли він знаходить один, агент показує картку в чаті, і ніщо не встановлюється, доки ви не клацнете **Установити**:

- З магазину, який ви додали в Enconvo, картка каже, які сервери MCP плагін запускає на Mac або до яких під’єднується, його навички й інші потрібні плагіни.
- З магазину, який має лише Codex або Claude Code, картка каже, що встановлення додає цей магазин до Enconvo. Enconvo не може прочитати вміст плагіна до того, тож картка не може його перелічити.

У будь-якому разі хуки плагіна лишаються вимкненими, доки ви не ввімкнете їх у **Плагіни**. Коли плагін не можна встановити, наприклад бо не можна встановити потрібний йому плагін, агент повідомляє про це замість картки.

### Плагіни з ChatGPT

Плагіни з [каталогу плагінів ChatGPT](https://chatgpt.com/plugins) не можна встановити в Enconvo. Більшість із них — програми ChatGPT, які працюють лише всередині ChatGPT, а решту OpenAI дає лише ChatGPT і Codex. Якщо ви ввійшли в Codex на Mac, агент знає каталог із копії, яку тримає Codex. Коли ви називаєте один із його плагінів або вставляєте посилання chatgpt.com, агент пояснює, чому не може його встановити, і пропонує те, що робить те саме: конектор, сервер MCP, навичку або плагін із тією самою назвою в одному з ваших магазинів. Багато плагінів каталогу, що йдуть із файлами, також мають плагін із тією самою назвою в OpenAI Curated, магазині, що йде з Codex (публічний репозиторій OpenAI `openai/plugins`). Агент пропонує цей плагін, і його встановлення додає OpenAI Curated до Enconvo. Enconvo не завантажує програми ChatGPT, які ці плагіни містять, лише їхні навички й сервери MCP.

Посилання chatgpt.com не працює і в **Додати з GitHub**; діалог каже те саме.

## З командного рядка

`plugin install` бере плагін із GitHub, git, npm, zip в інтернеті, теки або магазину. Має працювати Enconvo 2.5.6 або новіший.

```sh
npx -p @enconvo/api enconvo plugin install <source>
```

| Джерело | Приклад |
|---|---|
| Репозиторій GitHub, за бажанням тека в ньому і гілка, тег або коміт | `acme/notes`, `acme/plugins/notes@v1.2.0` |
| Адреса GitHub | `https://github.com/acme/plugins/tree/main/notes` |
| Будь-який інший репозиторій git через https (потрібен git); адреса ssh працює лише для GitHub | `https://git.example.com/notes.git`, `git@github.com:acme/notes.git` |
| Пакет npm | `npm:@acme/notes-plugin`, `npm:@acme/notes-plugin@1.2.0` |
| Zip плагіна в інтернеті (лише публічний https) | `https://downloads.acme.com/notes-1.2.0.zip` |
| Тека на Mac | `./notes`, `~/code/notes`, `/Users/ada/notes` |
| Плагін у доданому магазині | `notes@acme-plugins` |

<Note>
`plugin install` і `plugin marketplace` потребують випуску `@enconvo/api` новішого за 0.1.174. У проєкті, який залежить від `@enconvo/api`, достатньо `npx enconvo …`. `marketplace import` також потребує Enconvo 2.5.7 або новішого.
</Note>

Додайте `--preview`, щоб побачити, що було б установлено і звідки, без установлення.

Коли джерело — магазин плагінів, а не плагін, `plugin install` перелічує його плагіни. Магазин із понад 200 перелічує перші 200 і каже, скільки ще є; `plugin marketplace add` перелічує всі. Оберіть один через `--plugin`, що також додає магазин:

```sh
npx -p @enconvo/api enconvo plugin install acme/plugins --plugin notes
```

### Що відбувається під час установлення

- **Параметри**: плагін із обов’язковими параметрами, наприклад ключем API, установлюється, а потім їх запитує. `plugin install` називає їх; заповніть їх на сторінці плагіна.
- **Плагіни Enconvo з джерела**: коли репозиторій або тека GitHub тримає плагін Enconvo, який ще не зібрано, `plugin install` спершу його збирає. Тека збирається на місці, після `npm install`.
- **Онбординг**: коли плагін називає навичку онбордингу, Enconvo пропонує запустити її після першого встановлення.
- **Вхід**: коли серверам MCP плагіна потрібен ваш вхід, як у Notion чи Figma, сторінка плагінів показує **Увійти**, щойно він установлюється. Enconvo відкриває сторінку входу сервера в браузері й пропонує наступний сервер, щойно цей під’єднається. `plugin install` натомість називає сервери. Вхід, який ви пропускаєте, чекає в **Параметри → Сервери MCP**.
- **Хуки**: [хуки](/extensions/plugin-formats#hooks) плагіна встановлюються вимкненими, бо вони запускають команди. `--preview` їх перелічує; дозвольте їх перемикачем **Дозволити хуки** на сторінці плагіна. Хуки, які ви дозволили, лишаються ввімкненими через оновлення, які їх не змінюють.
- **Залежності**: коли плагіну Claude Code з магазину потрібні інші плагіни, Enconvo встановлює їх разом із ним (див. розділ «Магазини плагінів» нижче). `--preview` їх перелічує і каже, які вже встановлені, які встановилися б і які не можуть. Залежність, яку запис магазину оголошує з магазину, який не дозволено, зупиняє встановлення; ту, яку оголошує власний `plugin.json` плагіна, пропускають, і встановлення триває. Їхні хуки лишаються вимкненими, а видалення плагіна тримає їх, доки ви їх не обріжете (див. розділ «Видалення» нижче).
- **Використання**: як у Codex, введіть `@` у чаті й оберіть плагін або клацніть одну з підказок у розділі **Спробуйте запитати** на його сторінці. У будь-якому разі чат отримує долучений плагін. Кожен установлений плагін є в меню `@`, включно з плагіном Codex або Claude Code, який не називає категорії.
- **Та сама назва**: повторне встановлення з того самого джерела оновлює плагін. Якщо плагін із тією самою назвою вже встановлено з іншого місця, наприклад магазину, Enconvo лишає його і просить спершу видалити.

Коли Enconvo не працює, `plugin install` усе ще може встановити плагін Enconvo з GitHub, зібравши його. Для всього іншого відкрийте Enconvo і спробуйте знову.

## Магазини плагінів

Магазин — каталог плагінів у репозиторії або теці. Enconvo читає обидва види: `.agents/plugins/marketplace.json` Codex і `.claude-plugin/marketplace.json` Claude Code.

```sh
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins   # GitHub, a git address or a folder
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins --ref v2   # at a branch, tag or commit
npx -p @enconvo/api enconvo plugin marketplace list               # added marketplaces and their plugins
npx -p @enconvo/api enconvo plugin install notes@acme-plugins     # install one of them
npx -p @enconvo/api enconvo plugin marketplace refresh            # fetch them again for new plugins
npx -p @enconvo/api enconvo plugin marketplace remove acme-plugins
```

`refresh` також відповідає на `upgrade` (назва Codex) і `update` (назва Claude Code), а `--ref v2` — те саме, що `acme/plugins@v2`.

На сторінці плагінів відкрийте **Додати → Додати з GitHub…** і вставте адресу магазину або оберіть один, який ви додали, в **Ваші магазини**.

Enconvo тримає копію магазину з GitHub або git і читає магазин-теку там, де він є. Вилучення магазину зберігає плагіни, які ви з нього встановили.

### Магазини, які ви додали в Codex або Claude Code

Якщо ви додали магазини в Codex або Claude Code на цьому Mac, або Codex отримав свій магазин OpenAI Curated, `marketplace list` показує ті, яких Enconvo ще не має, а `import` їх додає, тож не треба знову вводити адреси:

```sh
npx -p @enconvo/api enconvo plugin marketplace import                            # all of them
npx -p @enconvo/api enconvo plugin marketplace import claude-plugins-official    # only these
```

Enconvo знаходить їх у `~/.codex/config.toml` Codex, його копії OpenAI Curated і особистому `~/.agents/plugins/marketplace.json`, а також у списку відомих магазинів Claude Code. Він лише читає ці файли й нічого не змінює в жодній програмі. OpenAI Curated додається з `openai/plugins` на GitHub. Він пропускає інші магазини, що йдуть з Codex і тримають плагіни для власних інструментів Codex, і магазини Claude Code, додані з веб-адреси файлу `marketplace.json`, які Enconvo не додає. Коли обидві програми мають магазин із тією самою назвою, він пропонує магазин Codex.

Магазини Codex, такі як OpenAI Curated, перелічують лише назву кожного плагіна і звідки він. Для плагіна у власній теці магазину Enconvo показує назву, опис, категорію й розробника з маніфесту плагіна, як Codex, і агент знаходить його і за тим, що він робить, і за назвою. Те, що каже сам запис магазину, іде першим.

Деякі плагіни OpenAI Curated, наприклад Gmail, Google Drive, Outlook і Teams, працюють лише коли ви входите в Codex через ChatGPT, тож Codex не пропонує їх людям, які входять із ключем API. Enconvo теж не входить у ChatGPT, тож показує їх як такі, що потребують входу ChatGPT, не встановлює їх, і агент їх не пропонує. Для цих сервісів натомість додайте власний сервер MCP провайдера або конектор.

### Звідки беруться плагіни магазину

Плагіни магазину можуть приходити з теки в магазині, іншого репозиторію GitHub, адреси git, теки в репозиторії git, npm або zip в інтернеті (джерело `archive` Claude Code). Плагін, який магазин Codex позначає `NOT_AVAILABLE`, не можна встановити.

Джерело теки, записане як `./plugins/notes`, читається з верху магазину. Голе ім’я, наприклад `notes`, читається з теки, яку називає `metadata.pluginRoot`, як у Claude Code, і потребує цього поля.

Завантаження з GitHub, npm або інтернету може тривати до трьох хвилин; якщо довше, Enconvo зупиняє його і просить перевірити з’єднання.

Zip, чи ви вставляєте його посилання, чи його перелічує магазин, завантажується лише з публічної адреси https, щонайбільше через п’ять переспрямувань. Коли магазин дає його `sha256`, завантаження, яке не збігається, відхиляється. Плагін може лежати на верху zip або всередині однієї теки.

### Записи магазину Claude Code

Записи магазину Claude Code працюють із власним `plugin.json` плагіна так, як їх читає Claude Code:

- Запис може додати `commands`, `agents`, `skills`, `outputStyles` і `themes` до власних плагіна, а його `hooks` замінюють хуки плагіна для тих самих подій.
- Запис із `"strict": false`, який також перелічує будь-що з цього, над плагіном, що має `plugin.json`, відхиляється як конфліктні маніфести. Тримайте їх в одному місці.
- Коли плагін не має `plugin.json`, запис є його маніфестом.
- Показуються назва, опис, автор і інші деталі списку запису; версія — плагіна.
- Дотримуються `renames` магазину. Плагін, установлений під старою назвою, продовжує оновлюватися під новою, і встановлення за старою назвою його знаходить. Назву, перейменовану на `null`, вилучено з магазину, і Enconvo про це каже. Якщо власний маніфест плагіна теж змінив назву, Enconvo просить видалити старий плагін і встановити новий, бо Enconvo називає плагін за його маніфестом.
- `dependencies` плагіна, у його записі або `plugin.json`, установлюються разом із ним. Кожна — ім’я (`"formatter"`), ім’я й магазин (`"formatter@acme-tools"`), будь-яке з діапазоном `^` (`"formatter@acme-tools@^2.1"`) або `{ "name", "marketplace", "version" }` із діапазоном semver. Залежність приходить із власного магазину плагіна, якщо не називає інший, а інший магазин має бути перелічений у `allowCrossMarketplaceDependenciesOn` магазину, з якого ви встановили. Залежність із діапазоном `version` установлюється на найвищому тегу випуску (`<plugin>--v<version>`) у цьому діапазоні й у діапазонах, які на неї ставлять інші встановлені плагіни, з власного репозиторію плагіна або, для плагіна всередині магазину, з магазину (тека магазину зараховується, коли вона в репозиторії git). Без такого тегу плагін усередині магазину встановлюється так, як його має магазин, а той, що у власному репозиторії, відхиляється. Діапазони, яких не задовольняє жодна версія, відхиляють встановлення, і оновлення лишаються всередині діапазонів. Залежність, яка вже встановлена, лишається як є, а та, що поза діапазоном `version`, отримує попередження.

### Перевірте магазин, перш ніж ділитися

Перш ніж ділитися магазином, перевірте його і кожен плагін у ньому. Правила — ті, які застосовує `claude plugin validate`, плюс правила Codex для `.agents/plugins/marketplace.json`; див. [Validation Codes](/extensions/validation-codes#marketplaces). Помилка означає, що Claude Code не може додати магазин або встановити плагін, навіть якщо все ще може його перелічити: поле неправильного типу в записі, `renames`, які не ведуть до плагіна, сигнали `relevance`, які він відхиляє, або назва магазину, схожа на одну з власних Anthropic, наприклад `claude-plugins-hub`. Попередження охоплює те, що Claude Code ігнорує, наприклад поле з помилкою в назві, і назви, які відхиляє Claude Desktop.

```sh
npx -p @enconvo/api enconvo plugin validate path/to/marketplace
```

## Оновлення

Перевірка оновлень плагінів Enconvo також охоплює плагіни, установлені з GitHub, git, npm, тек і магазинів, і перелічує їхні оновлення разом із магазином. Вона читає останній коміт репозиторію, не завантажуючи його, питає npm про останню версію, помічає, коли встановлена тека змінилася, і для zip, який магазин закріплює через `sha256`, помічає, коли закріплення змінюється. Оновлення встановлює плагін знову з того самого джерела.

Щоб перевірити один плагін, відкрийте його сторінку й оберіть **Перевірити наявність оновлень** у меню **⋯**. Коли є новіша версія, клацніть **Оновити** в повідомленні, що з’являється.

Або оновіть один із Terminal, як `claude plugin update` у Claude Code:

```bash
npx -p @enconvo/api enconvo plugin update notes                # from wherever it came from, or the store
npx -p @enconvo/api enconvo plugin update notes@acme-plugins   # only if it came from that marketplace
```

Він спершу перевіряє. Коли нічого новішого немає, він каже, що плагін уже на останній версії, і нічого не змінює; інакше оновлює плагін так, як список оновлень.

## Видалення

Видаліть плагін з його меню або сторінки на сторінці плагінів, яка спершу просить підтвердити, або з Terminal:

```bash
npx -p @enconvo/api enconvo plugin uninstall notes            # also: remove, rm
npx -p @enconvo/api enconvo plugin uninstall notes --prune    # and the dependencies nothing needs any more
npx -p @enconvo/api enconvo plugin prune --dry-run            # list them without removing anything
npx -p @enconvo/api enconvo plugin prune                      # remove them (also: autoremove)
```

Обрізання вилучає лише плагіни, установлені тому, що їх потребував інший плагін, щойно жоден установлений плагін їх не потребує, як `claude plugin prune` у Claude Code. Плагін, який ви встановили самі, ніколи не обрізається, а повторне встановлення залежності самим робить її вашою. У Terminal Enconvo перелічує, що вилучить, і спершу питає; додайте `-y`, щоб пропустити запитання, якого потребує `--prune`, коли не може запитати. Видалення на сторінці плагінів ще не обрізає.

## Опублікуйте власний

Щоб перелічити плагін у магазині Enconvo, див. [Настанови магазину плагінів](/uk/extensions/publishing-guidelines). Щоб надіслати посилання, яке будь-хто може встановити, клацніть **Поділитися…** на сторінці плагіна; див. [Поділіться плагіном](/uk/extensions/overview). Щоб поділитися ним без Enconvo, надішліть його на GitHub або в магазин, і люди можуть установити його через **Додати з GitHub…** або команди вище.

### Позначте випуск

`plugin tag` позначає коміт, який ви випускаєте, тегом git `<plugin>--v<version>`, як `claude plugin tag`. Claude Code і Enconvo обирають серед цих тегів, коли залежність іншого плагіна просить діапазон версій, і будь-хто може встановити цей випуск з Enconvo, наприклад `acme/plugins/notes@notes--v1.2.0`.

```sh
npx -p @enconvo/api enconvo plugin tag plugins/notes --dry-run   # check, and print the git commands
npx -p @enconvo/api enconvo plugin tag plugins/notes --push      # tag HEAD and push the tag to origin
```

Версія береться з маніфесту плагіна або з його запису магазину, коли маніфест її не має, і має бути semver (`1.2.0`). Перед позначенням `plugin tag` перевіряє плагін, як `plugin validate`, і зупиняється, коли запис магазину називає іншу версію, коли файли в теці плагіна не закомічені або коли тег існує. Підніміть версію для нового випуску; `--force` натомість переміщує наявний тег. Він позначає плагіни Codex, Claude Code, портативні й Enconvo однаково, тож кожен маніфест, який несе пакет, має називати ту саму версію. `-m` задає повідомлення тега (`%s` — версія), а `--remote` — віддалений репозиторій, куди надсилає `--push`. Як і `plugin install`, він потребує випуску `@enconvo/api` новішого за 0.1.174.
