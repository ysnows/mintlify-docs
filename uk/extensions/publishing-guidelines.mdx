Ця сторінка для розробників, які збираються подати плагін до магазину плагінів Enconvo. Вона перелічує, що перевіряють рецензенти, матеріали рецензії для кожної версії, контрольний список перед `plugin publish` і що відбувається після подання.

Enconvo рецензує кожну версію, подану до магазину плагінів, перш ніж хтось інший зможе її інсталювати. Ці правила стосуються кожного виду плагіна, який приймає магазин: плагіни Enconvo, Codex, Claude Code і переносні, включно з плагінами лише з навичок. Вони слідують [правилам плагінів OpenAI](https://developers.openai.com/apps-sdk/app-submission-guidelines), тож плагін, який їх задовольняє, також близький до готовності для порталу плагінів OpenAI.

## Спершу перевірте плагін

Перш ніж подавати, запустіть:

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate` ловить те, що можна перевірити автоматично, а `scan` перевіряє інструменти плагіна з сервером MCP; [Коди перевірки](/extensions/validation-codes) пояснюють кожну проблему, про яку вони повідомляють. Решту рецензенти перевіряють вручну, як описано нижче.

## Призначення і якість

- Плагін робить щось корисне, чого Enconvo ще не вміє, і робить це повністю. Заповнювачі, лише демо або пробні версії відхиляють.
- Він поводиться передбачувано. Коли щось не вдається, як-от мережева помилка, відсутній дозвіл або погане введення, він каже, що сталося, замість мовчазної невдачі.
- Він використовує лише код, назви, іконки і вміст, якими ви володієте або на які маєте ліцензію. Він не видає себе за інший продукт і не натякає, що Enconvo чи хтось інший його схвалює.

## Назва, опис і картка

- **Назва і заголовок**: зрозумілі і конкретні. Уникайте загального одного слова і не додавайте «MCP», «MCP Server» або «Plugin» до назви компанії.
- **Опис**: каже, що робить плагін, точно. Без порівнянь з іншими продуктами, тверджень, які не можете підтвердити, або цін, знижок і пропозицій безкоштовної проби.
- **Іконка і знімки екрана**: іконка — PNG, JPEG, WebP або GIF до 5 МБ. До 8 знімків екрана йдуть у папку `metadata/` і показуються в порядку назв файлів. Вони показують плагін таким, як він справді працює.
- **Підтримка**: дайте людям спосіб вас досягти: `interface.websiteURL` і `interface.supportURL` або `homepage` чи `repository` для вебсайту. Плагін Claude Code може натомість використовувати свої `supportUrl` і `documentationUrl`. Сторінка магазину показує ці посилання, перш ніж хтось інсталює плагін.
- **Версія**: підвищуйте її для кожного оновлення. Поки оновлення на рецензії, магазин продовжує пропонувати версію перед ним. `plugin publish` запитує в магазину, яку версію він випустив, перш ніж щось збирати або завантажувати, і зупиняється з наступною версією, коли ваша не вища.

## Інструменти MCP

Коли плагін приносить сервер MCP, рецензенти читають його інструменти так, як їх читатиме модель ШІ.

- **Назви** — прості дієслова, які кажуть, що робить інструмент, як-от `get_order_status`, і унікальні в межах сервера. Без жаргону або непояснених скорочень.
- **Описи** пояснюють, що робить інструмент, що він змінює і чого не може, і відповідають схемі введення і справжній поведінці. Вони не кажуть моделі віддавати перевагу цьому плагіну, викликати інші плагіни або викликати інструмент для всього.
- **Одна операція на інструмент**, кожна з власною схемою введення.
- **Анотації** задано явно на кожному інструменті:

| Анотація | `true`, коли інструмент | `false`, коли він |
|---|---|---|
| `readOnlyHint` | лише читає, обчислює або переглядає | змінює щось: пише, зберігає файл, надсилає, публікує, завантажує, ставить роботу в чергу або починає завдання |
| `destructiveHint` | видаляє, перезаписує, скасовує або надсилає те, що не можна забрати, навіть якщо користувач міг би скасувати | лише додає |
| `openWorldHint` | досягає публічного або відкритого вмісту, як-от пошук в інтернеті, або надсилає на будь-яку адресу | лишається всередині обмеженого облікового запису, робочого простору або каталогу, навіть розміщеного деінде |

Enconvo покладається на ці анотації. Інструмент, позначений `readOnlyHint: true`, працює без запиту користувача і поруч з іншими читаннями. Інструмент, позначений `destructiveHint: true`, спершу запитує користувача, якщо він не дав агенту повний доступ. Інструмент, який щось змінює, але заявляє, що лише для читання, відхиляють.

`enconvo plugin scan` запускає сервер MCP плагіна, перелічує його інструменти з анотаціями і називає кожен інструмент, який одну пропускає ([`annotations_required`](/extensions/validation-codes#mcp-server-scan)).

Інструмент, який показує власний інтерфейс, називає свій вигляд, ресурс `ui://`, у `_meta.ui.resourceUri`, і вигляд оголошує домени, яких досягає, у `_meta.ui.csp` (`connectDomains`, `resourceDomains`, `frameDomains`). Це ключі MCP Apps, які читає кожен хост. Enconvo також читає `_meta["openai/outputTemplate"]` і `_meta["openai/widgetCSP"]` ChatGPT і дає вигляду, написаному для ChatGPT (`text/html+skybridge` або інструмент, названий лише `openai/outputTemplate`), API `window.openai`, який він викликає, тож плагін, збудований для ChatGPT, показує свій інтерфейс в Enconvo без змін. Задайте також ключі MCP Apps, щоб інші хости теж його показували. `scan` читає кожен вигляд так, як Enconvo, і каже, коли один задано лише способом OpenAI.

## Дані і конфіденційність

- **Питайте лише те, що потрібно завданню.** Введення інструментів конкретне для завдання. Не просіть усю розмову, раніші повідомлення або широкі дані профілю «про всяк випадок».
- **Повертайте лише те, що відповідає на запит.** Лишайте внутрішні ідентифікатори, дані трасування і вивід налагодження поза результатами інструментів.
- **Ніколи не збирайте** дані платіжних карток, медичні записи, урядові ідентифікатори на кшталт номерів соціального страхування або паролі, ключі API і одноразові коди через введення інструментів. Облікові дані йдуть у параметри плагіна, де Enconvo їх зберігає.
- **Політика конфіденційності.** Плагіну, який надсилає дані на сервер, потрібна опублікована політика конфіденційності, яка каже, що він збирає, навіщо, хто отримує, як довго зберігається і як люди можуть це видалити. Поставте її адресу в `interface.privacyPolicyURL`, а умови надання послуг, якщо вони є, у `interface.termsOfServiceURL`. Сторінка магазину посилається на обидва.
- **Без відстеження** людей, їхніх запитів або використання понад те, що потрібно плагіну для роботи і що розкриває його політика конфіденційності.
- **Тримайте секрети поза пакетом.** Будь-хто може його завантажити. Файли `.env` лишаються поза автоматично, але перевірте, що інші ключі або приватні файли не потрапляють у нього.

## Вхід і тестові облікові записи

Якщо плагіну потрібен обліковий запис, вхід явний і просить лише дозволи, які йому потрібні. Рецензентам треба спробувати його, не створюючи обліковий запис і не отримуючи код двофакторної автентифікації, тож дайте їм демо-обліковий запис зі зразковими даними:

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

Нотатки рецензента йдуть лише рецензентам Enconvo. Вони не є частиною пакета чи картки магазину.

## Комерція

Плагін може працювати з обліковим записом, за який люди вже платять, і може казати, коли функції потрібен інший план. Якщо він щось продає або приймає платежі, скажіть про це в матеріалах рецензії (`commerce` і `commerce_description` нижче): що продається і де люди платять. Люди платять на вашому власному сайті; плагін не ховає платежі і не стягує з користувачів Enconvo більше, ніж з усіх інших.

Портал OpenAI суворіший. Він приймає плагіни, які продають лише фізичні товари, і жодних підписок, кредитів чи інших цифрових продуктів. Перевірте його [правила комерції](https://developers.openai.com/apps-sdk/app-submission-guidelines), перш ніж подавати туди.

## Безпека

- Плагін підходить для загальної аудиторії, включно з підлітками, і не націлений на дітей до 13 років.
- Він робить те, що попросив користувач, і нічого більше: без непов’язаного вмісту, перенаправлень або реклами.
- Його описи, запити і навички ніколи не просять секрети, не переміщують гроші або дані без згоди користувача, не намагаються обійти запобіжники Enconvo і не ховають, що робить плагін, включно із закодованими інструкціями.
- Він не збирає вебсайти і не обгортає інші служби всупереч їхнім умовам і не обходить їхні ліміти частоти і контроль доступу.
- Він не продає і не уможливлює нічого зі списку OpenAI [заборонених товарів і послуг](https://developers.openai.com/apps-sdk/app-submission-guidelines), як-от зброю, наркотики, азартні ігри, контент для дорослих, шкідливе ПЗ або фінансове шахрайство.

## Матеріали рецензії

Матеріали рецензії кажуть рецензентам, що спробувати: запити, які плагін має обробити, запити, які він має лишити, і коротке демо-відео. Вони зберігаються з кожною версією і показуються лише рецензентам.

У плагіні Codex, Claude Code або переносному вони йдуть туди, де їх читає портал OpenAI, під `extensions["com.openai"]` одного `plugin.json`. OpenAI імпортує їх з `.codex-plugin/plugin.json`, коли плагін його має, як робить `enconvo plugin create`; з кореневого `plugin.json`, коли той має власний `extensions["com.openai"]` або немає маніфесту Codex; і з `.claude-plugin/plugin.json` у плагіні, зробленому лише для Claude Code. Не додавайте `extensions["com.openai"]` до кореневого `plugin.json` лише заради них: Codex тоді ігнорує картку в `.codex-plugin/plugin.json`. `enconvo plugin validate --openai` називає маніфест, якому вони належать.

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

У плагіні Enconvo той самий об’єкт `review` іде на верхньому рівні `package.json`.

| Поле | Що воно тримає |
|---|---|
| `test_cases.positive` | Запити, які плагін має обробити, кожен з `description`, `prompt`, `expected_behavior` і `tools_triggered`. Необов’язково: `file_attachment_urls` і `expected_output_url`. |
| `test_cases.negative` | Запити, які плагін має лишити чомусь іншому, кожен з `description` і `prompt`. |
| `demo_recording_url` | Відео основних запитів і інструментів. |
| `commerce`, `commerce_description` | Чи плагін щось продає, і що і де. |
| `publication.release_notes` | Що змінилося. `plugin publish` використовує їх як журнал змін магазину, якщо ви не передасте `-m`. |

Кожен список тримає до 20 випадків. Текстові поля тримають до 4000 символів, і кожна адреса — адреса `https://`, яку рецензенти можуть відкрити. `validate` і `publish` відхиляють матеріали, які порушують ці межі.

Деталі входу ніколи не йдуть у пакет, бо будь-хто може його завантажити. `validate` і `publish` відхиляють `review`, який має `test_credentials` або `reviewer_instructions`; передайте їх через `--review-notes` натомість або у формі деталей рецензії панелі OpenAI.

У `plugin.json` `publication` також може тримати те, що портал OpenAI імпортує для картки, і `validate --openai` перевіряє їх так, як портал. Enconvo показує `translations` мовою свого інтерфейсу для інстальованого плагіна і перед інсталяцією з джерела; сторінки магазину Enconvo їх ще не використовують:

| Поле | Що воно тримає |
|---|---|
| `countries` | Де плагін доступний, як коди країн великими літерами, як-от `["US", "GB"]`. `[]` робить його доступним скрізь. |
| `translations` | Текст картки за локаллю, як-от `{"fr-FR": {"subtitle": "…", "description": "…"}}`. Підзаголовок — один рядок до 30 символів, опис до 4000. |

Поле, задане як `null`, зберігає значення, уже збережене в панелі OpenAI. Тестові випадки рівня плагіна — для плагіна з рівно одним сервером MCP.

Остаточне подання OpenAI плагіна з сервером MCP або програмою бере рівно 5 позитивних і 3 негативні випадки, демо-запис і нотатки випуску; плагіну лише з навичками потрібні лише нотатки випуску. `validate --openai` перелічує відсутнє як попередження, бо завантаження порталу приймає плагін без них і просить їх лише на остаточному поданні.

## Контрольний список подання

Перш ніж запустити `plugin publish`:

- `plugin validate` не повідомляє помилок, і ви прочитали його попередження.
- `version` вища за останню опубліковану версію, і кожен маніфест у пакеті дає ту саму назву і версію.
- Для оновлення `plugin validate --previous` із zip випуску перед ним не повідомляє нічого, чого ви не мали на увазі: оновлення замінює весь плагін, тож навичку або сервер MCP, який воно лишає поза, видаляють (`plugin_components_removed`).
- Заголовок, опис і іконка кажуть, що робить плагін, і знімки екрана показують його в роботі.
- Задано домашню сторінку або адресу підтримки, і політику конфіденційності пов’язано, якщо плагін надсилає дані кудись.
- Кожен інструмент MCP має зрозумілу назву і опис і задає `readOnlyHint`, `destructiveHint` і `openWorldHint`, і `plugin scan` перелічує їх без проблем.
- Навички кажуть у своєму `description`, коли їх використовувати.
- Обов’язкові параметри, як-от ключ API, оголошено як параметри, а не запитуються в чаті.
- У папці немає ключів, токенів або приватних файлів.
- Матеріали рецензії перелічують запити для спроби і запити, які лишити, і демо-обліковий запис готовий для `--review-notes`, якщо потрібен вхід.
- Ви інсталювали пакет з його папки (`plugin install .`) і спробували тестові випадки в Enconvo.

## Що відбувається після подання

1. `plugin publish` перевіряє плагін і що його версія вища за ту, яку випустив магазин, потім завантажує його і подає версію на рецензію. Доки новий плагін не схвалено, лише ви можете його бачити.
2. Рецензент читає картку, файли пакета (з тим, що змінилося від випущеної версії), матеріали рецензії і ваші нотатки і пробує тестові випадки.
3. Схвалена версія з’являється в магазині, і інстальованим копіям пропонують оновлення. Якщо версію відхилено, ви отримуєте е-пошту з причиною. Виправте, підвищте версію і опублікуйте знову.

Enconvo також розглядає повідомлення про опубліковані плагіни. Плагін, який порушує ці правила, включно зі схваленим раніше, можуть прибрати з магазину, і його розробнику надсилають причину е-поштою.

## Подання також до OpenAI

Та сама папка може піти на портал плагінів OpenAI:

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai` пише zip, який приймає портал. Облікові дані для рецензентів OpenAI йдуть у форму подання порталу, ніколи в пакет. Тримайте власні ключі поза ним теж: `pack` і `publish` лишають поза файли `.env`, і `validate` попереджає про файл, схожий на приватний ключ або вхід (`archive_member_secret`).

### Назва плагіна

Портал приймає лише літери, цифри, `-` і `_` у `name` плагіна, і OpenAI пропонує малі літери, цифри і поодинокі дефіси. Codex, Claude Code і Enconvo також інсталюють назву з крапкою, як-от `acme.tools`, але `validate --openai` і `pack --openai` її відхиляють (`plugin_name_format`), тож назвіть плагін, який збираєтеся подати, `acme-tools`.

### Сервер MCP і домен

Після завантаження портал підключається до сервера MCP плагіна і сканує його інструменти; коли сервер змінюється, перескануйте його там. Він досягає сервера лише за публічною URL `https://`, тож сервер, який працює на комп’ютері користувача, треба спершу розгорнути; `scan --openai` попереджає про такий (`mcp_server_not_remote`). На остаточному поданні портал просить усі три анотації на кожному інструменті. Він більше не просить їх обґрунтувати; якщо автоматична рецензія позначає одну, ви можете оскаржити з поясненням. Плагіну, чиї вигляди вбудовують сторінки, все одно потрібне обґрунтування кожної вбудованої сторінки: що вона робить, чому плагін її вбудовує і хто контролює її домен. Сторінки з власного реєстрованого домену сервера MCP дозволені, і окремі орендарі на спільному хості рахуються як різні домени. `scan --openai` перелічує домени, які вбудовують ваші вигляди (`frame_domain_explanation_required`).

Перш ніж ви зможете подати плагін, портал перевіряє, що ви контролюєте домен сервера MCP: він дає вам токен, який треба віддати як простий текст за `/.well-known/openai-apps-challenge` на хості сервера або батьківському домені. `scan --openai` каже, що відповідають ці URL, і `scan --challenge-token <token>` перевіряє, що одна віддає рівно токен, перш ніж ви оберете **Verify Domain**; див. [Перевірка домену](/extensions/validation-codes#domain-verification).

Портал OpenAI підключає лише один сервер MCP на плагін, щоб сканувати і рецензувати його, тож `validate --openai` попереджає про плагін з кількома. Той самий сервер, оголошений для Codex у `mcp.json` і для Claude Code в `.mcp.json`, рахується раз.

### Оновити опублікований плагін

Щоб оновити плагін, який ви опублікували там, завантажте повний ZIP з вищою версією і всім, що збираєтеся зберегти. Якщо ви не зберегли zip опублікованої версії, портал дає його вам через **Download release ZIP** у меню **…** цієї версії; перевірте нову версію проти нього через `validate --openai --previous <zip>`. Портал не може додати сервер MCP до опублікованого плагіна, який його не мав, або змінити URL опублікованого сервера (попросіть підтримку OpenAI про це), і `--previous` повідомляє про обидва; див. [Оновлення](/extensions/validation-codes#updates).

### Остаточне подання

Остаточне подання OpenAI просить від картки більше, ніж його завантаження, і `validate --openai` попереджає про кожну прогалину:

- `interface.longDescription` і `interface.category`; без однієї каталог перелічує плагін під Other.
- Для плагіна з сервером MCP: `websiteURL`, `supportURL`, `privacyPolicyURL` і `termsOfServiceURL`, кожна адреса `https://` до 1024 символів.
- Власна картка. Плагін Claude Code лише з `.claude-plugin/plugin.json` отримує одну, яку портал заповнює типовими значеннями (`claude_format_normalized`), тож додайте `.codex-plugin/plugin.json` з `interface`, щоб написати її самі.
- Знімки екрана лише коли сервер MCP має власний інтерфейс: один PNG або JPEG для кожного стартового запиту, рівно 706 пікселів завширшки і від 400 до 860 пікселів заввишки. Портал вирішує зі свого сканування, тож `scan --openai` відхиляє знімки екрана, коли жоден інструмент не показує інтерфейс (`screenshots_not_allowed`). Каталог OpenAI більше не показує знімки екрана і представляє плагін його стартовими запитами, тож пишіть їх уважно.

Каталог показує ім’я розробника вашої перевіреної ідентичності OpenAI, що б не казало `interface.developerName`. Див. [Остаточне подання OpenAI](/extensions/validation-codes#openais-final-submission) для кодів.
