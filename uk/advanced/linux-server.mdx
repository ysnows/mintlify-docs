Ця сторінка для вас, якщо ваш Mac додав сервер Linux у розділі **Параметри → З’єднання** і встановив там Enconvo. Сервер запускає Enconvo без екрана, а ваш Mac відкриває його чати, але не параметри. Налаштувати сервер можна трьома способами: у його вебінтерфейсі, з командного рядка або синхронізувавши з ним налаштування вашого Mac.

## Що ваш Mac ділить із сервером

Створення пари дозволяє вашому Mac користуватися чатами, агентами та файлами сервера. Параметри воно не ділить. Сервер тримає власні моделі, агентів, плагіни й ключі API і не копіює їх з вашого Mac.

- Параметри й ключі API не відкриваються з вашого Mac. Ви змінюєте їх на сервері.
- Із коробки агенти сервера використовують типову модель. У новому встановленні це Enconvo Cloud на обліковому записі, з яким увійшов сервер, тож його чати витрачають ваші бали Cloud.
- Щоб швидко змінити модель одного агента, скористайтеся вибором моделі в чаті сервера на вашому Mac. Він задає модель, рівень міркування та швидкість цього агента на сервері. Постачальнику, якому потрібен ключ API, спершу потрібен цей ключ на сервері.

## Відкрийте вебінтерфейс сервера

Сервер може віддавати Вікно чату та Параметри як вебсайт, тож ви можете користуватися Параметрами в браузері вашого Mac. Установлення з вашого Mac його не вмикає. Увімкніть його один раз через SSH.

<Steps>
  <Step title="Увімкніть вебінтерфейс">
    Підключіться до сервера через `ssh` і виконайте:

    ```bash
    enconvo service install --web 127.0.0.1:54580
    ```

    Це перезаписує службу Enconvo з увімкненим вебінтерфейсом і перезапускає її. Вона слухає лише `127.0.0.1`, тож ніщо поза сервером не може до неї дістатися. Коли ви знову виконуєте `enconvo service install`, служба працює лише з параметрами нового запуску.
  </Step>
  <Step title="Відкрийте тунель зі свого Mac">
    У Terminal на вашому Mac використайте ту саму назву хоста, що й з `ssh`:

    ```bash
    ssh -N -L 54580:127.0.0.1:54580 my-server
    ```

    Залиште його працювати, поки користуєтеся вебінтерфейсом. Натисніть Control-C, щоб закрити його.
  </Step>
  <Step title="Відкрийте вебінтерфейс">
    Відкрийте `http://127.0.0.1:54580` у браузері вашого Mac. Параметри працюють так само, як на вашому Mac: вибирайте моделі в розділі **Параметри → Модель ШІ**, додавайте плагіни в розділі **Параметри → Плагіни** і вводьте там же ключі API.
  </Step>
</Steps>

`enconvo service url` на сервері виводить адресу вебінтерфейсу.

### Доступ без тунелю

Щоб відкривати вебінтерфейс з інших комп’ютерів без SSH, прив’яжіть його до мережі:

```bash
enconvo service install --web 0.0.0.0:54580
```

Тоді вебінтерфейсу потрібен токен підключення. Виконайте `enconvo service url`, щоб вивести адресу з ним, що закінчується на `?tkn=`. Відкрийте це посилання один раз, і браузер збереже токен. За зворотним проксі додайте `--web-url https://enconvo.example.com` з адресою, яку віддає проксі, або `--web-host <name>` для іншої назви, за якою звертаються до сервера. Обом також потрібен токен.

<Warning>
  Токен дає тому, хто його має, ваш обліковий запис Enconvo на сервері та кожен файл, який може прочитати його користувач. Тримайте посилання в таємниці, тримайте порт за брандмауером або VPN і віддавайте перевагу тунелю SSH. Щоб замінити токен, видаліть `~/.config/enconvo/.support/windows-shell/web-token` на сервері та виконайте `systemctl --user restart enconvo`.
</Warning>

## Налаштування з командного рядка

Маршрути кожного встановленого плагіна — це команди `enconvo` на сервері: `enconvo <plugin> <route> --flags` або `--input-json` для всього запиту. Додайте `-h` на будь-якому рівні, щоб побачити, що там є:

```bash
enconvo -h
enconvo config -h
enconvo config set -h
```

Беріть у лапки ключі, що містять `|`, як-от `'agent|main'`. Без лапок оболонка читає `|` як канал.

### Моделі

Виведіть список постачальників моделей сервера. `commandKey` кожного, наприклад `llm|enconvo_ai`, — це значення, яке ви задаєте:

```bash
enconvo llm list_providers
```

Задайте типову модель, яку використовує кожен агент, налаштований на типову:

```bash
enconvo config get llm --includes selected
enconvo config set --preferenceKey llm --keys selected --value 'llm|<provider id>'
```

Задайте модель одного агента. Головний агент — це `agent|main`; `enconvo agent list` показує `command_key` інших:

```bash
enconvo config get 'agent|main' --includes llm
enconvo config set --preferenceKey 'agent|main' --keys llm --value 'llm|<provider id>'
```

Задайте значення `default`, щоб знову використовувати типову модель. `enconvo config preferences 'agent|main'` виводить усі параметри агента.

Щоб скасувати один параметр, назвіть його:

```bash
enconvo config reset 'agent|main' --keys llm
```

<Warning>
  `enconvo config reset` без `--keys` скидає всі параметри цього ключа, а для агента чи команди ще й видаляє дані його робочого простору. Це неможливо скасувати.
</Warning>

`config get` показує збережені ключі API й токени як `[hidden]`. Вводьте ключі API в Параметрах вебінтерфейсу, а не через `config set`, щоб вони не потрапили до історії вашої оболонки.

### Плагіни

```bash
enconvo plugin list
enconvo plugin install owner/repo
enconvo plugin uninstall <name>
```

`plugin install` приймає GitHub `owner/repo`, URL git, посилання `https` на `.zip`, `npm:<package>`, теку або `<plugin>@<marketplace>`. Плагіни, яким потрібен екран, на сервері приховані.

### Агенти

```bash
enconvo agent list
enconvo agent create -h
```

`enconvo agent -h` виводить решту, як-от видалення чи призупинення агента.

## Використайте налаштування свого Mac із Синхронізацією

Синхронізація копіює параметри вашого Mac на сервер через ваш обліковий запис Enconvo. Вона входить до планів Enconvo Cloud і безстрокових ліцензій.

1. На вашому Mac відкрийте **Параметри → Синхронізація**, увімкніть **Синхронізація між комп’ютерами** і виберіть **Обліковий запис Enconvo** у розділі **Сховище**. Сервер Linux не може дістатися до iCloud.
2. У вебінтерфейсі сервера відкрийте **Параметри → Синхронізація** і увімкніть **Синхронізація між комп’ютерами**.
3. У розділі **Що синхронізується** виберіть, що перенести, на обох комп’ютерах, наприклад **Параметри**, **Плагіни** та **Навички**.
4. Щоб перенести ще й ключі API, увімкніть **Ключі API** на обох. Це вимкнено типово. Ваш Mac покаже код: перевірте, що сервер показує такий самий, і натисніть **Дозволити**.

Те, що належить одному комп’ютеру, на ньому й залишається: гарячі клавіші, шляхи до тек і робочі теки, входи в облікові записи, Автоматизації та боти для обміну повідомленнями. Що охоплює кожен вибір, дивіться в [Синхронізація ваших Mac](/uk/configuration/account).

## Усунення несправностей

| Проблема | Що робити |
| --- | --- |
| `enconvo: command not found` | Відкрийте новий сеанс SSH. Під час встановлення теку Enconvo додається до `PATH` у профілі вашої оболонки, а сеанс, відкритий до встановлення, його ще не прочитав. |
| `enconvo service url` не виводить адреси | Enconvo не запущено або він працює без вебінтерфейсу. Виконайте `enconvo service install --web 127.0.0.1:54580` ще раз. |
| Браузер не може відкрити `127.0.0.1:54580` | Перевірте, що тунель досі відкритий, потім перевірте службу командою `systemctl --user status enconvo` і її журнал командою `journalctl --user -u enconvo`. |
| Вебінтерфейс просить токен підключення | Відкрийте повне посилання, яке виводить `enconvo service url`, із `?tkn=` наприкінці. |
| `service install` повідомляє, що Enconvo уже запущено для цього користувача | Ваш Mac запустив Enconvo як фоновий процес, що він робить, коли сервер не тримає користувацькі служби запущеними після виходу з системи. Виконайте `sudo loginctl enable-linger $USER`, знову виконайте `enconvo service install --web 127.0.0.1:54580`, потім перезапустіть сервер, щоб служба перебрала керування. |
| `service install` повідомляє, що systemd недоступний | Натомість виконайте `enconvo --headless --web 127.0.0.1:54580` під власним менеджером процесів. |
| Чати використовують іншу модель, ніж на вашому Mac | Сервер має власні моделі. Перевірте `enconvo config get llm --includes selected` або увімкніть Синхронізацію. |
