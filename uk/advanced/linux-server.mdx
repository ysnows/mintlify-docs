---

Ця сторінка для вас, якщо Mac додав сервер Linux у **Параметри → З’єднання** і встановив там Enconvo. Сервер запускає Enconvo без екрана, а Mac відкриває його чати, але не параметри. Налаштувати сервер можна трьома способами: у його вебінтерфейсі, з командного рядка або синхронізувавши налаштування Mac на нього.

## Що Mac ділить із сервером

Пара дає Mac користуватися чатами, агентами й файлами сервера. Параметри вона не ділить. Сервер тримає власні моделі, агентів, плагіни й ключі API і не копіює їх із Mac.

- Параметри й ключі API не відкриваються з Mac. Ви змінюєте їх на сервері.
- З коробки агенти сервера використовують типову модель. На новій інсталяції це Enconvo Cloud, на обліковому записі, у який увійшов сервер, тож його чати використовують ваші бали Cloud.
- Щоб швидко змінити модель одного агента, скористайтеся вибором моделі в чаті сервера на Mac. Він задає модель, рівень міркування й швидкість для цього агента на сервері. Провайдеру, якому потрібен ключ API, цей ключ спершу потрібен на сервері.

## Відкрийте вебінтерфейс сервера

Сервер може віддавати вікно чату й параметри як вебсайт, тож параметрами можна користуватися в браузері Mac. Інсталяція з Mac цього не вмикає. Увімкніть один раз через SSH.

<Steps>
  <Step title="Увімкніть вебінтерфейс">
    Під’єднайтеся до сервера через `ssh` і запустіть:

    ```bash
    enconvo service install --web 127.0.0.1:54580
    ```

    Це переписує службу Enconvo з увімкненим вебінтерфейсом і перезапускає її. Вона слухає лише `127.0.0.1`, тож ніщо поза сервером її не досягне. Коли ви знову запускаєте `enconvo service install`, служба працює лише з параметрами нового запуску.
  </Step>
  <Step title="Відкрийте тунель із Mac">
    У Terminal на Mac використайте те саме ім’я хоста, що й з `ssh`:

    ```bash
    ssh -N -L 54580:127.0.0.1:54580 my-server
    ```

    Залиште його запущеним, поки користуєтеся вебінтерфейсом. Натисніть Control-C, щоб закрити.
  </Step>
  <Step title="Відкрийте вебінтерфейс">
    Відкрийте `http://127.0.0.1:54580` у браузері Mac. Параметри працюють як на Mac: оберіть моделі в **Параметри → Модель ШІ**, додайте плагіни в **Параметри → Плагіни** і введіть ключі API там само.
  </Step>
</Steps>

`enconvo service url` на сервері друкує адресу вебінтерфейсу.

### Досягайте його без тунелю

Щоб відкривати вебінтерфейс з інших комп’ютерів без SSH, прив’яжіть його до мережі:

```bash
enconvo service install --web 0.0.0.0:54580
```

Вебінтерфейсу тоді потрібен токен з’єднання. Запустіть `enconvo service url`, щоб надрукувати адресу з ним, що закінчується на `?tkn=`. Відкрийте це посилання один раз, і браузер збереже токен. За зворотним проксі додайте `--web-url https://enconvo.example.com` з адресою, яку віддає проксі, або `--web-host <name>` для іншого імені, за яким досягають сервера. Обидва теж потребують токена.

<Warning>
  Токен дає тому, хто його має, ваш обліковий запис Enconvo на сервері й кожен файл, який може читати його користувач. Тримайте посилання приватним, тримайте порт за брандмауером або VPN і віддавайте перевагу тунелю SSH. Щоб замінити токен, видаліть `~/.config/enconvo/.support/windows-shell/web-token` на сервері і запустіть `systemctl --user restart enconvo`.
</Warning>

## Налаштуйте з командного рядка

Маршрути кожного встановленого плагіна — це команди `enconvo` на сервері: `enconvo <plugin> <route> --flags` або `--input-json` для всього запиту. Додайте `-h` на будь-якому рівні, щоб побачити, що там є:

```bash
enconvo -h
enconvo config -h
enconvo config set -h
```

Беріть у лапки ключі, що містять `|`, наприклад `'agent|main'`. Без лапок оболонка читає `|` як канал.

### Моделі

Перелічіть провайдерів моделей сервера. `commandKey` кожного, наприклад `llm|enconvo_ai`, — це значення, яке ви задаєте:

```bash
enconvo llm list_providers
```

Задайте типову модель, якою користується кожен агент, установлений на типову:

```bash
enconvo config get llm --includes selected
enconvo config set --preferenceKey llm --keys selected --value 'llm|<provider id>'
```

Задайте модель одного агента. Головний агент — `agent|main`; `enconvo agent list` показує `command_key` інших:

```bash
enconvo config get 'agent|main' --includes llm
enconvo config set --preferenceKey 'agent|main' --keys llm --value 'llm|<provider id>'
```

Встановіть значення `default`, щоб знову слідувати типовій моделі. `enconvo config preferences 'agent|main'` перелічує кожен параметр агента.

Щоб скасувати один параметр, назвіть його:

```bash
enconvo config reset 'agent|main' --keys llm
```

<Warning>
  `enconvo config reset` без `--keys` скидає кожен параметр цього ключа, а для агента чи команди також видаляє дані його робочого простору. Це не можна скасувати.
</Warning>

`config get` показує збережені ключі API й токени як `[hidden]`. Вводьте ключі API в параметрах вебінтерфейсу, а не через `config set`, щоб вони не потрапили в історію оболонки.

### Плагіни

```bash
enconvo plugin list
enconvo plugin install owner/repo
enconvo plugin uninstall <name>
```

`plugin install` приймає GitHub `owner/repo`, URL git, посилання `https` на `.zip`, `npm:<package>`, теку або `<plugin>@<marketplace>`. Плагіни, яким потрібен екран, на сервері приховані.

### Агенти

```bash
enconvo agent list
enconvo agent create -h
```

`enconvo agent -h` перелічує решту, наприклад видалення або призупинення агента.

## Використайте налаштування Mac із синхронізацією

Синхронізація копіює параметри Mac на сервер через обліковий запис Enconvo. Вона входить до планів Enconvo Cloud і довічних ліцензій.

1. На Mac відкрийте **Параметри → Синхронізація**, увімкніть **Синхронізувати між комп’ютерами** і оберіть **Обліковий запис Enconvo** у розділі **Сховище**. Сервер Linux не може досягти iCloud.
2. У вебінтерфейсі сервера відкрийте **Параметри → Синхронізація** і увімкніть **Синхронізувати між комп’ютерами**.
3. У розділі **Що синхронізується** оберіть, що перенести, на обох комп’ютерах, наприклад **Параметри**, **Плагіни** і **Навички**.
4. Щоб перенести й ключі API, увімкніть **Ключі API** на обох. Усталено вимкнено. Mac тоді показує код: перевірте, що сервер показує той самий, потім клацніть **Дозволити**.

Те, що належить одному комп’ютеру, лишається там: гарячі клавіші, шляхи тек і робочі теки, входи, автоматизації й боти повідомлень. Що покриває кожен вибір, див. у [Обліковий запис і синхронізація](/uk/configuration/account).

## Усунення несправностей

| Проблема | Що робити |
| --- | --- |
| `enconvo: command not found` | Відкрийте новий сеанс SSH. Інсталяція додає теку Enconvo до `PATH` у профілі оболонки, якого сеанс, відкритий до інсталяції, не прочитав. |
| `enconvo service url` не друкує адресу | Enconvo не працює або працює без вебінтерфейсу. Знову запустіть `enconvo service install --web 127.0.0.1:54580`. |
| Браузер не може відкрити `127.0.0.1:54580` | Перевірте, що тунель усе ще відкритий, потім перевірте службу через `systemctl --user status enconvo` і її журнал через `journalctl --user -u enconvo`. |
| Вебінтерфейс запитує токен з’єднання | Відкрийте повне посилання, яке друкує `enconvo service url`, з `?tkn=` у кінці. |
| `service install` повідомляє, що Enconvo вже працює для цього користувача | Mac запустив Enconvo як фоновий процес, що він робить, коли сервер не тримає служби користувача після виходу. Запустіть `sudo loginctl enable-linger $USER`, знову запустіть `enconvo service install --web 127.0.0.1:54580`, потім перезапустіть сервер, щоб служба перейняла роботу. |
| `service install` повідомляє, що systemd недоступний | Натомість запустіть `enconvo --headless --web 127.0.0.1:54580` під власним менеджером процесів. |
| Чати використовують іншу модель, ніж на Mac | Сервер має власні моделі. Перевірте `enconvo config get llm --includes selected` або увімкніть синхронізацію. |
