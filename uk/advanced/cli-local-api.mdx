Ця сторінка для розробників і досвідчених користувачів, які хочуть керувати Enconvo з Terminal, зі скрипту чи з іншого застосунку. Команда `enconvo` постачається разом із настільним застосунком Enconvo, окремо встановлювати її не потрібно, а застосунок віддає маршрути кожного встановленого плагіна через локальний HTTP API.

Це відео розповідає про сторінку API, Посібник із CLI та Хуки.

Залиште Enconvo запущеним для команд, які використовують його локальне середовище виконання.

## Знайдіть команди

```bash
enconvo -h
enconvo knowledge_base -h
```

Додайте `-h` до команди, яку досліджуєте, щоб побачити її актуальні підкоманди й параметри.

Відкрийте **Параметри → Посібник із CLI**, щоб побачити встановлені розширення, які надають команди CLI. Натисніть назву, щоб скопіювати її команду `enconvo <name> -h`. Список встановлених розширень — остаточне джерело того, що підтримує ваш застосунок.

Якщо оболонка не знаходить `enconvo`, відкрийте Посібник із CLI в застосунку та перевірте версію встановленого застосунку й налаштування командного рядка.

## Викличте локальний API

Застосунок віддає кожен маршрут за адресою `http://localhost:54535/api/<extension>/<route>`. Надішліть `POST` з тілом JSON:

```bash
curl -X POST http://localhost:54535/api/enconvo/extension/available_list \
  -H "Content-Type: application/json" \
  -d '{}'
```

Відкрийте **Параметри → API** і натисніть **Перевірити API**, щоб переглянути доступні маршрути та схеми запитів із прикладом для кожного. Під час написання інтеграції користуйтеся схемою для встановленої у вас збірки; параметри маршрутів можуть змінюватися з розвитком розширень.

## Запуск Агента чи ШІ-команди ззовні Enconvo

У параметрах кожного Агента і кожної ШІ-команди є рядок **Посилання, CLI та API**. Він показує посилання, команду `enconvo` і виклик локального API, які запускають її з вашим текстом і файлами, — усе готове до копіювання.

| Спосіб | Що він робить |
| --- | --- |
| Посилання | Відкриває новий чат і запускає там Агента чи ШІ-команду |
| CLI | Запускає у фоновому режимі та виводить відповідь |
| Local API | Запускає у фоновому режимі та повертає відповідь |

Посилання має такий вигляд:

```text
enconvo://<extension>/<command>?input_text=<text>&window=<window>&files=<path>
```

- `input_text` — текст, який потрібно надіслати.
- `window` — це `chat_window` або `dynamic_island`. Пропустіть його, щоб запустити в SmartBar.
- `files` прикріплює файл за абсолютним шляхом або шляхом із `~/`. Повторіть його для кількох файлів, наприклад щоб надіслати зображення з іншого застосунку чи скрипту.

З Terminal:

```bash
enconvo agent call "What's on my calendar today?"
enconvo ai-command run 'writing_package|translate' --input-text "Bonjour" --files ~/Desktop/note.png
enconvo writing_package convert_to_list "eggs, milk, bread"
```

Команди письма, як-от «Перекласти», «Підсумувати» та «Перетворити на список», приймають текст як аргумент і відповідають, не додаючи чат до вашої історії. `enconvo agent main` відповідає в новому чаті, коли агент зайнятий в останньому.

Відповідні маршрути локального API — `agent/call` (`agentId`, `message`, `context_files`) і `ai-command/run` (`command_key`, `input_text`, `files`).

### Перевірка запущених чатів

- `agent/session/list` виводить чати, що працюють зараз, у всіх агентів і Проєктах, зокрема чати Claude Code і Codex, із назвою, агентом і Проєктом кожного. Передайте `filter: "waiting"` для чатів, які чекають вашої відповіді, або `"active"` для обох видів.
- `agent/session/status` перевіряє один чат за його `sessionId`.
- `agent/session/steer` додає повідомлення до ходу, який чат виконує зараз, не зупиняючи його. Чат, що не працює, відповідає `not_running`; натомість почніть новий хід через `agent/call`. Запуск нижче за Повний доступ не може керувати ходом Enconvo.

## Користуйтеся безпечно

Для клієнта ШІ, якому потрібне лише отримання з бази знань, замість відкриття загального локального API використовуйте спеціальне підключення [Knowledge Base MCP](/uk/advanced/knowledge-base-mcp).

Ставтеся до локального API та доступу до оболонки як до потужних можливостей: команди можуть читати чи змінювати локальні дані залежно від своєї реалізації. Нехай ваші скрипти чітко вказують команду, вхідні дані та призначення.

Збережені ключі API повертаються як `[hidden]`, коли програма читає параметри через локальний API, а змінити, куди надсилається збережений ключ, можуть лише власні вікна Enconvo. Див. [Облікові дані](/uk/configuration/credentials).

Гаряча клавіша, яку ви задаєте через локальний API, може використовувати короткі назви модифікаторів (`cmd`, `ctrl`, `alt`, `opt`, `fn`) або символи модифікаторів. Гаряча клавіша зі словом, якого Enconvo не знає, не реєструється, а клавіша, що вводить символ, потребує Command, Control, Option або Function.
