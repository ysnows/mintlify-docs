Ця сторінка для розробників, які хочуть дати агенту Enconvo власні інструменти. Власний сервер MCP відкриває інструменти, які агент Enconvo може викликати. Почніть із невеликого локального сервера, перевірте його вхідні дані та результат, потім додайте роботу, специфічну для служби.

Щоб установити сервер, який зробив хтось інший, див. [Сервери MCP](/uk/features/mcp). Щоб поширити свій сервер так, щоб він також установлювався в Codex і Claude Code, запакуйте його як плагін із `--template mcp` (див. [Формати плагінів](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code)).

## Перед початком

Потрібні Node.js і npm. Цей приклад використовує **JavaScript API 1.x** TypeScript SDK, закріплений на 1.29.0. Основні версії SDK можуть використовувати інші імпорти та налаштування; зверніться до [офіційного посібника сервера MCP](https://modelcontextprotocol.io/docs/develop/build-server), коли обираєте іншу версію.

## Написати мінімальний локальний сервер

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

Збережіть це як `server.mjs`:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

Сервер stdio чекає повідомлень протоколу; запуск у терміналі не показує інтерфейс чату. Тримайте діагностику на stderr (наприклад, `console.error`), бо stdout несе повідомлення протоколу MCP. [Офіційний посібник](https://modelcontextprotocol.io/docs/develop/build-server) пояснює цю вимогу транспорту.

## Підключити його до Enconvo

<Steps>
  <Step title="Додати сервер">
    Відкрийте **Параметри → Сервери MCP** і натисніть **Add server**. Дайте йому **Назву сервера**, наприклад `hello-mcp`.
  </Step>
  <Step title="Задати, як він запускається">
    Оберіть **STDIO**. У **Команда** введіть `node`. У **Аргументи** введіть абсолютний шлях `server.mjs`. Якщо Enconvo не знаходить Node, використайте абсолютний шлях до виконуваного файлу.
  </Step>
  <Step title="Зберегти і перевірити">
    Натисніть **Зберегти**. Підтвердьте, що сервер підключається і відкриває `greet`.
  </Step>
  <Step title="Спробувати">
    Зробіть його доступним агенту і попросіть привітати «Ada». Очікуваний результат інструмента — `Hello, Ada!`.
  </Step>
</Steps>

Еквівалентна конфігурація:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

Замініть приклад шляху справжнім шляхом вашого файлу.

## Спроєктувати корисні інструменти

- Дайте кожному інструменту конкретну дію та опис.
- Перевіряйте ввід на межі інструмента і повертайте корисні повідомлення про помилки.
- Відокремте читання даних від змін, таких як надсилання або видалення.
- Повертайте компактний результат, який агент може інтерпретувати.
- Тримайте облікові дані у відповідній конфігурації сервера, поза прикладами коду та журналами.

## Віддалені сервери та автентифікація

Для віддаленого сервера використайте транспорт HTTP або SSE з його інструкцій налаштування та відповідну форму Enconvo (**HTTP** або **SSE** замість **STDIO**). URL сервера має бути кінцевою точкою MCP, а не звичайним URL сайту. Завершіть будь-який підтримуваний потік авторизації і підтвердьте з’єднання, перш ніж вмикати його інструменти.

Віддалений транспорт, виявлення автентифікації та поведінка сеансу залежать від сервера та версії протоколу. Використовуйте офіційний SDK і документацію протоколу для деталей реалізації, а не вигадуйте маніфест `auth`, який Enconvo не споживає.

## Усунення несправностей

| Проблема | Що робити |
| --- | --- |
| Процес одразу завершується | Перевірте шлях до виконуваного файлу, залежності, синтаксичні помилки та stderr |
| Підключено, але інструмент не з’являється | Перевірте реєстрацію інструмента, що інструмент увімкнено, і обраного агента |
| Недійсна відповідь протоколу | Пошукайте випадкове логування в stdout або запуск не тієї програми |
| Помилка перевірки схеми | Порівняйте фактичну форму вводу з версією SDK, яку ви використовуєте |
| Збій віддаленого з’єднання | Перевірте URL кінцевої точки, транспорт, автентифікацію та доступ до мережі |

Щоб відкрити власні документи Enconvo іншому клієнту ШІ, використайте вбудований [сервер MCP бази знань](/uk/advanced/knowledge-base-mcp); власний сервер не потрібен.
