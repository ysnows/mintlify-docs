Ця сторінка для розробників, які хочуть дати Агентові Enconvo власні інструменти. Власний сервер MCP надає інструменти, які може викликати Агент Enconvo. Почніть із невеликого локального сервера, перевірте його вхідні дані та результат, а потім додайте потрібну вам роботу, специфічну для сервісу.

Щоб установити сервер, створений кимось іншим, див. [Сервери MCP](/uk/features/mcp). Щоб випустити свій сервер так, щоб він також установлювався в Codex і Claude Code, запакуйте його як плагін із `--template mcp` (див. [Plugin Formats](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code)).

## Перш ніж почати

Вам потрібні Node.js і npm. У цьому прикладі використано **JavaScript API 1.x** TypeScript SDK, зафіксований на 1.29.0. Основні версії SDK можуть мати різні імпорти й налаштування; обираючи іншу версію, зверніться до [офіційного посібника із сервера MCP](https://modelcontextprotocol.io/docs/develop/build-server).

## Напишіть мінімальний локальний сервер

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

Збережіть це як `server.mjs`:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

Сервер stdio чекає на повідомлення протоколу; запуск його в терміналі не показує інтерфейсу чату. Виводьте діагностику в stderr (наприклад, через `console.error`), бо stdout несе повідомлення протоколу MCP. Цю вимогу до транспорту пояснює [офіційний посібник](https://modelcontextprotocol.io/docs/develop/build-server).

## Підключіть його до Enconvo

<Steps>
  <Step title="Додайте сервер">
    Відкрийте **Параметри → Сервери MCP** і натисніть **Додати сервер**. Дайте йому **Назву сервера**, наприклад `hello-mcp`.
  </Step>
  <Step title="Задайте, як він запускається">
    Виберіть **STDIO**. У полі **Команда** введіть `node`. У полі **Аргументи** введіть абсолютний шлях до `server.mjs`. Якщо Enconvo не знаходить Node, використайте абсолютний шлях до його виконуваного файлу.
  </Step>
  <Step title="Збережіть і перевірте">
    Натисніть **Зберегти**. Переконайтеся, що сервер підключається й надає `greet`.
  </Step>
  <Step title="Спробуйте">
    Зробіть його доступним для свого Агента й попросіть привітати «Ada». Очікуваний результат інструмента — `Hello, Ada!`.
  </Step>
</Steps>

Еквівалентна конфігурація:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

Замініть приклад шляху справжнім шляхом до вашого файлу.

## Проєктуйте корисні інструменти

- Давайте кожному інструментові конкретну дію та опис.
- Перевіряйте вхідні дані на межі інструмента й повертайте корисні повідомлення про помилки.
- Відокремлюйте читання даних від змін, як-от надсилання чи видалення.
- Повертайте компактний результат, який Агент зможе інтерпретувати.
- Тримайте облікові дані у відповідній конфігурації сервера, поза прикладами коду й журналами.

## Віддалені сервери та автентифікація

Для віддаленого сервера використовуйте транспорт HTTP або SSE, який пропонують його інструкції з налаштування, і відповідну форму Enconvo (**HTTP** або **SSE** замість **STDIO**). URL сервера має бути кінцевою точкою MCP, а не звичайною адресою вебсайту. Пройдіть будь-який підтримуваний процес авторизації та переконайтеся в підключенні, перш ніж вмикати його інструменти.

Віддалений транспорт, виявлення автентифікації та поведінка сеансів залежать від сервера й версії протоколу. Щодо подробиць реалізації користуйтеся документацією офіційного SDK і протоколу, а не вигадуйте маніфест `auth`, який Enconvo не використовує.

## Усунення несправностей

| Проблема | Що робити |
| --- | --- |
| Процес одразу завершується | Перевірте шлях до виконуваного файлу, залежності, синтаксичні помилки та stderr |
| Підключено, але жоден інструмент не з’являється | Перевірте реєстрацію інструмента, що інструмент увімкнено, і вибраного Агента |
| Недійсна відповідь протоколу | Пошукайте випадковий вивід у stdout або запуск не тієї програми |
| Помилка перевірки схеми | Порівняйте фактичну форму вхідних даних із версією SDK, яку використовуєте |
| Помилка віддаленого підключення | Перевірте URL кінцевої точки, транспорт, автентифікацію та доступ до мережі |

Щоб надати власні документи Enconvo іншому клієнтові ШІ, використовуйте вбудований [сервер Knowledge Base MCP](/uk/advanced/knowledge-base-mcp); власний сервер не потрібен.
