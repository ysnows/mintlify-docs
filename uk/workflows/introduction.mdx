Робочий процес — це повторюваний процес, збережений як кроки: прочитати інформацію, перетворити її, спитати модель, передати роботу Агентові або викликати встановлений інструмент. Використовуйте його, коли раз у раз виконуєте те саме багатокрокове завдання й хочете бачити, що дав кожен крок. Відкрийте **Параметри → Робочі процеси → Керування**, щоб переглянути свої робочі процеси та історію їхніх запусків.

<Tip>
Вперше чуєте про робочі процеси? Перегляньте 2,5-хвилинний відеоурок [Створіть свій перший робочий процес](/uk/workflows/build-your-first-workflow), щоб створити, змінити й запустити його від початку до кінця.
</Tip>

## Виберіть правильний інструмент

| Ви хочете | Використовуйте |
| --- | --- |
| Повторно використати запит на виділеному тексті | [ШІ-команди](/uk/features/ai-commands) |
| Дозволити помічникові самому вирішувати, які інструменти використовувати | [Агенти](/uk/ai/agents) |
| Визначити повторювану послідовність із вихідними даними, які можна переглянути | Робочий процес |
| Запустити інструкцію Агента, робочий процес чи скрипт у заданий час | [Автоматизації](/uk/workflows/scheduled-jobs) |

## Як організовано робочий процес

Робочий процес складається з трьох частин:

- `inputs`: значення, потрібні запуску, як-от тема чи фрагмент тексту.
- `jobs`: іменовані групи кроків. Завдання починаються паралельно, якщо `needs` не змушує одне завдання чекати на інше.
- `steps`: упорядкований список усередині кожного завдання. Кроки в межах завдання виконуються один за одним.

Поточні робочі процеси використовують `version: agent-workflow/v1` з картою `jobs`, і кожне завдання містить список `steps`:

```yaml
version: agent-workflow/v1
title: Quick Summary
description: Summarize supplied text into three bullets.
inputs:
  text:
    type: string
    default: "A sample paragraph to summarize."
jobs:
  main:
    steps:
      - id: summarize
        prompt: "Summarize in three bullets: {{ inputs.text }}"
```

<Note>
Старий формат `tasks` верхнього рівня більше не приймається. Перенесіть кожну послідовність у `jobs.<name>.steps`, дайте крокам явні ID та використовуйте `steps.<id>.output` у межах завдання або `jobs.<job>.<step>.output` між завданнями.
</Note>

## Що може робити крок

Кожен крок робить рівно одне з цього:

| Крок | Поля | Результат |
| --- | --- | --- |
| Оболонка | `command` або `run` | Вивід команди, зокрема `stdout`, `stderr` і `exitCode` |
| Запит | `prompt` | Відповідь моделі; для структурованих даних використовуйте схему виводу |
| Агент | `agent` і `message` | Відповідь вибраного Агента |
| Інструмент | `tool` і `with` | Результат встановленої кінцевої точки Local API |
| Перетворення | `uses: transform` і `value` | Значення із шаблону |
| Підпроцес | `uses: workflow` із `workflowId` або `workflow` | Результат запуску дочірнього робочого процесу |
| Підтвердження | `uses: approval` і `message` | Ваша відповідь: схвалено або відхилено з необов’язковим відгуком |
| Оцінка | `uses: judge` і `question` | «Так» або «ні» від Jev, швидкої моделі ухвалення рішень Enconvo Cloud, з її ймовірністю |
| Класифікація | `uses: classify`, `question` і `options` | Варіант, який обрав Jev, з його впевненістю |

Крок також може виконуватися лише за умови, повторюватися над списком, повторювати спробу або повертати структуровані дані. Див. [Розширені робочі процеси](/uk/workflows/advanced-workflows).

## Запуск робочого процесу

- Відкрийте його в **Робочих процесах**, задайте **Вхідні дані** та виберіть **Запустити**.
- Знайдіть збережений робочий процес у SmartBar. Текст запуску доступний як `inputs.input_text`.
- Згадайте доступний робочий процес через `@` у чаті, щоб Агент міг його використати.
- Запускайте його за розкладом через [автоматизацію](/uk/workflows/scheduled-jobs).

## Де зберігаються робочі процеси

Кожен робочий процес — це один файл за адресою `~/.enconvo/workflows/<id>.yaml`. Ім’я файлу є ID робочого процесу. Зберігайте цей ID незмінним, щоб не втратити зв’язок з історією запусків.
