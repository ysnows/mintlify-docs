<Note>
Enconvo для Linux перебуває на етапі бета-тестування й виходить у каналі оновлень **Бета**. Він розрахований на щоденне використання, але між збірками ще можуть бути зміни. Якщо щось зламається, повідомте нам на [сайті відгуків](https://feedback.enconvo.com).
</Note>

**Поточна бета-версія: 2.5.13 Beta 3** (`2.5.13-beta-3`). Щоб дізнатися, яка версія у вас, відкрийте **Параметри → Загальні → Оновлення**. На сервері її виводить `enconvo update --check`.

## Оберіть, як ви його запускатимете

| У вас є | Що ви отримуєте | Почніть тут |
| --- | --- | --- |
| Настільний Linux (GNOME, KDE та інші) | Програма Enconvo з вікнами чату та параметрів | [Установлення на робочому столі](#установлення-на-робочому-столі) |
| Сервер або хмарний комп’ютер без робочого столу | Enconvo, що працює у фоні, з яким ви працюєте з браузера на власному комп’ютері | [Установлення на сервері](#установлення-на-сервері) |

## Вимоги

- **64-бітні Intel/AMD (x86-64).** Збірки для ARM поки немає.
- **Ubuntu 22.04, Debian 12, RHEL 9, Amazon Linux 2023 або новіші.** Rocky Linux і AlmaLinux 9 вважаються RHEL 9. На старіших системах Enconvo не запуститься: їхня бібліотека C надто стара.
- **Пам’ять:** радимо мати принаймні 2 ГБ вільних, а 4 ГБ — якщо агент користуватиметься браузером.
- **Звичайний обліковий запис користувача.** Запускайте Enconvo від свого імені, а не від root, оскільки його агент виконує команди з правами цього користувача. На сервері створіть користувача спеціально для Enconvo.

## Завантаження бета-версії

Бета-версія постачається в трьох формах: `.deb` для Debian та Ubuntu, `.rpm` для Fedora, RHEL, Rocky, AlmaLinux і openSUSE та портативний `.tar.gz` для всього іншого. В імені кожного файлу є номер версії бети. Для 2.5.13 Beta 3 це:

- `enconvo_2.5.13~beta~3_amd64.deb`
- `enconvo-2.5.13~beta~3-1.x86_64.rpm`
- `Enconvo-2.5.13-beta-3-linux-x64.tar.gz`

Ці команди знаходять найновішу бета-версію та завантажують її.

<Tabs>
  <Tab title="Debian, Ubuntu">
    ```bash
    FEED=https://file.enconvo.com/linux-x64/beta
    FILE=$(curl -fsSL $FEED/latest.json | grep -o 'enconvo_[^"]*\.deb')
    curl -fLO "$FEED/$FILE"
    ```
  </Tab>
  <Tab title="Fedora, RHEL, Rocky, AlmaLinux, openSUSE">
    ```bash
    FEED=https://file.enconvo.com/linux-x64/beta
    FILE=$(curl -fsSL $FEED/latest.json | grep -o 'enconvo-[^"]*\.rpm')
    curl -fLO "$FEED/$FILE"
    ```
  </Tab>
  <Tab title="Портативний .tar.gz">
    ```bash
    FEED=https://file.enconvo.com/linux-x64/beta
    FILE=$(curl -fsSL $FEED/latest.json | grep -o 'Enconvo-[^"]*\.tar\.gz')
    curl -fLO "$FEED/$FILE"
    tar xzf "$FILE"
    ```

    Це розпаковує теку `Enconvo`. Запускайте програму звідти й використовуйте `./Enconvo/enconvo` скрізь, де на цій сторінці написано `enconvo`.
  </Tab>
</Tabs>

## Установлення на робочому столі

Менеджер пакунків також установлює те, що потрібне вікнам програми, — GTK і WebKitGTK.

<Tabs>
  <Tab title="Debian, Ubuntu">
    ```bash
    sudo apt install ./enconvo_*.deb
    ```
  </Tab>
  <Tab title="Fedora, openSUSE">
    ```bash
    sudo dnf install ./enconvo-*.rpm      # Fedora
    sudo zypper install ./enconvo-*.rpm   # openSUSE
    ```
  </Tab>
  <Tab title="Портативний .tar.gz">
    Установіть GTK 3 і WebKitGTK 4.1 зі свого дистрибутива, потім запустіть Enconvo з його теки:

    ```bash
    ./Enconvo/enconvo
    ```
  </Tab>
</Tabs>

RHEL 9, Rocky Linux 9 і AlmaLinux 9 не постачають WebKitGTK 4.1, потрібний вікнам програми, тож у цих системах [запускайте Enconvo так, як на сервері](#установлення-на-сервері).

Відкрийте **Enconvo** з меню програм, увійдіть і переходьте до [Швидкого старту](/uk/quickstart). Значок Enconvo з’являється в системному треї там, де робочий стіл його показує.

## Установлення на сервері

Серверу не потрібні бібліотеки робочого столу, тож пропустіть їх.

<Steps>
  <Step title="Установіть пакунок">
    <Tabs>
      <Tab title="Debian, Ubuntu">
        ```bash
        sudo apt install --no-install-recommends ./enconvo_*.deb
        ```
      </Tab>
      <Tab title="Fedora, RHEL, Rocky, AlmaLinux">
        ```bash
        sudo dnf install --setopt=install_weak_deps=False ./enconvo-*.rpm
        ```
      </Tab>
      <Tab title="openSUSE">
        ```bash
        sudo zypper install --no-recommends ./enconvo-*.rpm
        ```
      </Tab>
      <Tab title="Портативний .tar.gz">
        Нічого встановлювати: використовуйте розпаковану теку `Enconvo`.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Запустіть Enconvo як службу">
    ```bash
    enconvo service install --web
    ```

    Тепер Enconvo працює у фоні й показує своє вікно чату та параметри як вебсайт лише на цьому комп’ютері, за адресою `127.0.0.1:54580`. Він знову запускається, коли сервер завантажується. Якщо команда повідомляє, що він працює лише поки ви ввійшли в систему, виконайте команду `sudo loginctl enable-linger`, яку вона виводить.
  </Step>
  <Step title="Увійдіть">
    ```bash
    enconvo login
    ```

    Enconvo виводить короткий код. Відкрийте `enconvo.com/device` на телефоні чи комп’ютері, переконайтеся, що сторінка називає ваш обліковий запис, і підтвердьте код протягом 10 хвилин.
  </Step>
  <Step title="Відкрийте Enconvo зі свого комп’ютера">
    Виконайте це на власному комп’ютері, а потім залиште працювати:

    ```bash
    ssh -N -L 54580:127.0.0.1:54580 you@your-server
    ```

    Відкрийте [http://localhost:54580](http://localhost:54580) у браузері. Ви отримаєте те саме вікно чату й ті самі параметри, що й у настільній програмі.
  </Step>
</Steps>

Щоб користуватися цим сервером із програми Enconvo на телефоні, виконайте `enconvo companion pair --phone` і відскануйте код, який вона виводить. Дивіться [Сполучення з телефоном](/uk/integrations/pair-your-phone).

### Доступ без тунелю SSH

Тунель — найбезпечніший спосіб доступу, бо на сервері ніщо не відкрите в мережу. Вебсайт має повні права вашого облікового запису та може діставатися до файлів сервера, тож кожен, хто може його відкрити, може користуватися і тим, і тим.

Щоб відкривати його безпосередньо з інших комп’ютерів, наприклад у приватній мережі чи VPN:

```bash
enconvo service install --web 0.0.0.0:54580
enconvo service url
```

`enconvo service url` виводить адресу з маркером підключення. Зберігайте цю адресу в таємниці й не відкривайте цей порт в інтернет.

Для публічної адреси поставте перед Enconvo зворотний проксі з HTTPS і повідомте Enconvo адресу, за якою він обслуговується:

```bash
enconvo service install --web --web-url https://enconvo.example.com
```

З HTTPS вебсайт також можна встановити як програму на телефон чи комп’ютер.

## Використання браузера на сервері

Агент може переглядати вебсторінки на сервері без екрана: Enconvo запускає власний безголовий браузер, який називається Enconvo Browser, коли агентові вперше він потрібен. Спершу встановіть Chromium.

<Tabs>
  <Tab title="Debian">
    ```bash
    sudo apt install chromium
    ```
  </Tab>
  <Tab title="Ubuntu">
    ```bash
    sudo snap install chromium
    ```
  </Tab>
  <Tab title="Fedora">
    ```bash
    sudo dnf install chromium
    ```
  </Tab>
  <Tab title="RHEL, Rocky, AlmaLinux">
    Chromium надходить з [EPEL](https://docs.fedoraproject.org/en-US/epel/):

    ```bash
    sudo dnf install epel-release
    sudo dnf install chromium
    ```
  </Tab>
</Tabs>

Потім попросіть агента, наприклад: «Відкрий news.ycombinator.com і скажи, яка головна новина».

Enconvo Browser зберігає власні входи. Коли сайт потребує вас, для входу чи перевірки, агент показує вам живий вигляд сторінки у вашому браузері, де ви можете клацати й друкувати самі. Він закривається після 30 хвилин бездіяльності й повертає свої вкладки наступного разу.

Сторінка, до якої може дістатися лише сервер, наприклад сервер розробки, який агент запустив на `localhost`, також відкривається поруч із чатом як живий вигляд, тож це працює крізь тунель SSH.

## Що де працює

| Функція | Настільний Linux | Сервер |
| --- | --- | --- |
| Вікно чату, Параметри | Так | Так, у вашому браузері |
| Агенти, інструменти, файли, документи, артефакти | Так | Так |
| Використання браузера | Так | Так, із Chromium |
| База знань, Пам’ять, Автоматизації, Робочі процеси | Так | Так |
| Моделі Enconvo Cloud, вебпошук, OCR, створення зображень, мовлення | Так | Так |
| Використання комп’ютера | Так | Ні: немає екрана для керування |
| Глобальні скорочення, Диктування, Голосові нотатки, Записи, Малювання на екрані, Appshots, сповіщення | Так | Ні: їм потрібен робочий стіл |

У Wayland глобальним скороченням потрібен робочий стіл, який пропонує їх програмам.

У Linux немає таких функцій: SmartBar, PopBar, Dynamic Island, Голосова команда, Аватар, Улюбленець на робочому столі, Бічна панель програми, Live Talk і Субтитри. SmartBar, PopBar, Dynamic Island, Голосова команда, Аватар і Улюбленець на робочому столі є в [бета-версії для Windows](/uk/getting-started/windows).

Локальні чат-моделі працюють із файлів GGUF у системах із glibc 2.38 або новішою. Моделям MLX потрібен Mac.

## Ваш обліковий запис у Linux

Якщо ваш обліковий запис також використовується в [програмі для iPhone](/uk/integrations/iphone-app), ваш вибір типових моделей чату, мовлення та зображень переходить за обліковим записом на цей комп’ютер. Провайдер, що працює на вашому власному ключі API, не переходить, бо ключі не копіюються. Додайте ключ у **Параметри** на цьому комп’ютері, якщо хочете такого самого провайдера тут.

Якщо годинник вашого сервера в іншому часовому поясі, ніж ваш браузер, Enconvo пропонує використати ваш для часу та [Автоматизацій](/uk/workflows/scheduled-jobs).

## Оновлення

Збірка бети залишається в каналі «Бета». Щоб змінити це, відкрийте **Параметри → Загальні** і виберіть **Канал оновлень**. Дивіться [Оновлення](/uk/configuration/updates).

На робочому столі скористайтеся **Оновити** у вікні чату, коли воно з’явиться. Портативна збірка замінює себе сама. Для `.deb` чи `.rpm` Enconvo завантажує новий пакунок у вашу теку «Завантаження», і ви встановлюєте його, як у розділі [Установлення на робочому столі](#установлення-на-робочому-столі).

На сервері:

```bash
enconvo update --check   # is there a newer version?
enconvo update           # download and check it
```

Якщо ви встановили `.deb` чи `.rpm`, `enconvo update` завантажує новий пакунок і виводить команду для його встановлення від імені root. Виконайте цю команду, потім перезапустіть службу:

```bash
systemctl --user restart enconvo
```

Якщо ви використовуєте портативний `.tar.gz`, `enconvo update` замінює теку й перезапускає її службу за вас. Якщо нова версія не запускається, він повертає стару.

## Усунення несправностей

| Що ви бачите | Що робити |
| --- | --- |
| `enconvo` повідомляє, що настільній програмі потрібні GTK 3 і WebKitGTK 4.1 | На робочому столі встановіть названі пакунки. На сервері чи в RHEL 9 скористайтеся `enconvo service install --web` |
| `GLIBC_2.34 not found` або повідомлення зі списком підтримуваних систем | Система надто стара: скористайтеся однією з розділу [Вимоги](#вимоги) |
| `dnf` повідомляє `nothing provides libwebkit2gtk-4.1.so.0` | У вас старіший пакунок. Установіть поточну бета-версію [командою для сервера](#установлення-на-сервері) |
| Enconvo зупиняється, коли ви виходите із сервера, або не запускається після перезавантаження | Виконайте `sudo loginctl enable-linger "$USER"` |
| `localhost:54580` не відкривається | Перевірте, що команда `ssh -L` досі працює і що `systemctl --user status enconvo` показує active |
| Вебсайт просить маркер | Виконайте `enconvo service url` на сервері й відкрийте адресу, яку вона виводить |
| Агент повідомляє, що не може запустити Enconvo Browser | [Установіть Chromium](#використання-браузера-на-сервері). Google Chrome 137 і новіші не можуть завантажити розширення, потрібне Enconvo Browser |
| Термін дії коду минув | Знову виконайте `enconvo login`, щоб отримати новий |

Щоб прочитати журнал Enconvo на сервері:

```bash
journalctl --user -u enconvo -n 100
```

## Видалення Enconvo

```bash
enconvo service uninstall
sudo apt remove enconvo     # Debian, Ubuntu
sudo dnf remove enconvo     # Fedora, RHEL, Rocky, AlmaLinux
sudo zypper remove enconvo  # openSUSE
```

Ваші параметри та чати залишаються в `~/.config/enconvo`. Видаліть цю теку, щоб прибрати й їх.
