---
title: "Hermes Agent"
description: "Enconvo에서 Hermes Agent를 OpenAI 호환 모델로 사용"
---

Hermes Agent는 Nous Research의 오픈 소스 AI 에이전트입니다. 도구, 메모리, 스킬, 터미널 접근, 메시징 통합이 있는 로컬 또는 서버 호스팅 에이전트 런타임으로 실행됩니다.

Enconvo에서 Hermes Agent는 OpenAI 호환 API 서버를 통해 씁니다. Hermes 게이트웨이가 실행 중이면 Enconvo는 채팅, Enconvo 에이전트, 모델이 움직이는 기능에서 Hermes를 다른 AI 모델처럼 쓸 수 있습니다.

<Tip>
  Hermes가 처음인가요? [Hermes Agent 빠른 시작](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)부터 본 뒤, 여기로 돌아와 Enconvo에 연결하세요.
</Tip>

API 참조: [Hermes Agent API 서버 문서](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server). 소스: [Hermes Agent GitHub 저장소](https://github.com/NousResearch/hermes-agent).

## 시작하기 전에

- Hermes Agent가 이미 설치되고 구성됨
- API 서버가 켜진 Hermes 게이트웨이가 실행 중
- `~/.hermes/.env`의 `API_SERVER_KEY`에서 온 API 서버 토큰
- Hermes Agent AI 모델 제공업체가 켜진 Enconvo

Hermes는 `/v1/models`, `/v1/chat/completions`, `/v1/responses` 같은 OpenAI 호환 엔드포인트를 노출합니다. Enconvo의 Hermes 제공업체는 Chat Completions API(`/v1/chat/completions`)를 씁니다.

Enconvo는 이 제공업체에 Hermes Responses API를 쓰지 않습니다. Hermes를 OpenAI 호환 Chat Completions 제공업체로 구성하세요.

## 자동으로 설정

**설정 → AI 모델 → Hermes Agent**를 여세요. 설정 카드가 로컬 Hermes API 서버를 시작, 중지, 구성할 수 있습니다.

Hermes가 Enconvo와 같은 Mac에 설치되어 있으면 **자동 설정**을 쓰세요. Enconvo는 다음을 합니다.

<Steps>
  <Step title="Hermes 찾기">
    이 Mac에 `hermes` CLI가 있는지 확인합니다.
  </Step>
  <Step title="API 서버 켜기">
    `API_SERVER_ENABLED=true`와, 없으면 `API_SERVER_KEY`로 `~/.hermes/.env`를 업데이트합니다.
  </Step>
  <Step title="게이트웨이 시작">
    Hermes 게이트웨이 서비스를 시작합니다.
  </Step>
  <Step title="API 확인">
    `/v1/health`와 `/v1/models`로 로컬 API 서버를 살핍니다.
  </Step>
  <Step title="자격 증명 저장">
    기본 URL과 API 서버 키를 Enconvo의 Hermes 자격 증명에 저장합니다.
  </Step>
</Steps>

설정 카드는 **실행 중**이나 **중지됨** 같은 런타임 배지를 보여 줍니다. 카드가 보이는 동안 Enconvo는 이 상태를 주기적으로 갱신하고, 카드가 더 이상 보이지 않으면 갱신을 멈춥니다.

## 기본 URL과 API 키 얻기

Enconvo가 Hermes와 같은 Mac에서 실행될 때 이 기본 URL을 쓰세요.

```text
http://127.0.0.1:8642/v1
```

`~/.hermes/.env`에서 API 서버 토큰을 읽으세요.

```bash
awk -F= '/^API_SERVER_KEY=/{print $2}' ~/.hermes/.env
```

Enconvo는 이 값을 이렇게 보냅니다.

```http
Authorization: Bearer <API_SERVER_KEY>
```

OpenAI 호환 엔드포인트를 직접 시험하려면:

```bash
curl http://127.0.0.1:8642/v1/chat/completions \
  -H "Authorization: Bearer <API_SERVER_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "hermes-agent",
    "messages": [
      { "role": "user", "content": "Hello!" }
    ]
  }'
```

`/v1`로 끝나는 기본 URL을 쓰세요. 전체 `/v1/chat/completions` 엔드포인트가 아닙니다.

## Hermes를 직접 연결

**설정 → AI 모델 → Hermes Agent**를 연 뒤 자격 증명 제공업체를 구성하세요.

![Enconvo의 Hermes Agent 자격 증명 설정](/img/hermes-settings.png)

| 설정 | 값 |
|---------|-------|
| **Hermes 기본 URL** | `http://127.0.0.1:8642/v1` |
| **API 서버 키** | `~/.hermes/.env`의 `API_SERVER_KEY` |

기본 URL과 토큰을 입력한 뒤 **검증**을 클릭하세요.

## 요청과 첨부가 작동하는 방식

Enconvo는 OpenAI 호환 Chat Completions로 Hermes 요청을 보냅니다.

```http
POST /v1/chat/completions
```

`hermes-agent` 또는 Hermes `/v1/models` 엔드포인트가 알리는 모델 이름을 쓰세요.

Enconvo는 이미지 첨부를 Hermes로 보내지 않습니다. 상위 Hermes API 서버가 이미지 입력을 광고해도, Enconvo의 Hermes 제공업체는 텍스트/채팅 제공업체로 다루세요. 이미지 워크플로에는 비전을 지원하는 모델 제공업체를 쓰거나, Hermes에 텍스트를 보내기 전에 OCR이나 이미지 분석을 실행하세요.

## Hermes를 AI 모델로 쓰기

구성되면 Hermes가 모델 선택기에 나타납니다. **Hermes Agent**를 고르고, 보통 `hermes-agent`인 광고된 모델을 선택하세요.

![채팅 모델로 선택된 Hermes Agent](/img/hermes-chat-model.png)

Enconvo 대화, 명령, 기능이 일반적인 Enconvo 인터페이스를 유지한 채 Hermes Agent를 거치게 할 때 이 모드를 쓰세요.

<Steps>
  <Step title="모델 선택기 열기">
    채팅이나 모델이 움직이는 다른 Enconvo 기능에서 현재 모델 이름을 클릭하세요.
  </Step>
  <Step title="Hermes Agent 고르기">
    제공업체 목록에서 **Hermes Agent**를 선택하세요.
  </Step>
  <Step title="Hermes 모델 선택">
    `hermes-agent` 또는 Hermes API 서버가 광고하는 모델 이름을 고르세요.
  </Step>
  <Step title="기능을 평소처럼 실행">
    질문하거나 Enconvo 기능을 실행하세요. Hermes가 뒤에서 모델 호출을 처리합니다.
  </Step>
</Steps>

Enconvo는 Hermes `/v1/models` 엔드포인트에서 Hermes 모델을 불러옵니다. Hermes가 실행 중이 아니거나 엔드포인트를 쓸 수 없으면 Enconvo는 `hermes-agent`로 돌아갑니다.

## Hermes용 에이전트 만들기

Hermes Agent를 조율하는 Enconvo 에이전트를 만들 수도 있습니다. Hermes의 에이전트 런타임 주위에 Enconvo 쪽 워크플로, 도구 모음, 프롬프트를 두고 싶을 때 유용합니다.

<Steps>
  <Step title="에이전트 만들기 열기">
    SmartBar를 열고 **에이전트 만들기**를 검색하세요.
  </Step>
  <Step title="에이전트 이름 짓기">
    `Hermes Agent`처럼 분명한 제목을 만드세요.
  </Step>
  <Step title="조율 지침 쓰기">
    Enconvo 에이전트가 Hermes와 어떻게 일해야 하는지 설명하는 지침을 주세요.

    ```markdown
    You coordinate Hermes Agent for the user.

    Use Hermes for agentic work, automation, terminal-backed tasks, and requests that should run through the user's Hermes setup.
    Summarize what Hermes did, surface any blockers, and ask before destructive or irreversible actions.
    ```
  </Step>
  <Step title="Hermes 모델 고르기">
    에이전트의 모델 설정에서 **Hermes Agent**를 선택하고 `hermes-agent`를 고르세요.
  </Step>
  <Step title="저장하고 에이전트 사용">
    새 Enconvo 에이전트와 대화를 시작하세요. 구성한 Enconvo 에이전트 인터페이스와 도구를 유지한 채 Hermes를 씁니다.
  </Step>
</Steps>

## 네트워크로 연결

Hermes가 다른 컴퓨터에서 실행 중이면 Enconvo에 호스트 컴퓨터의 LAN IP를 쓰세요.

```text
http://<hermes-host-lan-ip>:8642/v1
```

<Warning>
  LAN 접근에는 강한 `API_SERVER_KEY`를 쓰세요. 신뢰하는 네트워크에만 Hermes API 서버를 노출하세요.
</Warning>

## 문제 해결

<AccordionGroup>
  <Accordion title="모델 선택기에 Hermes Agent가 나타나지 않음">
    **설정 → AI 모델**에서 Hermes 제공업체가 켜져 있는지 확인하세요. 모델 목록이 비어 있으면 `hermes gateway status`로 게이트웨이가 실행 중인지 확인하세요.
  </Accordion>
  <Accordion title="검증이 권한 없음으로 실패함">
    `~/.hermes/.env`의 `API_SERVER_KEY`를 다시 확인하세요. Enconvo는 이 값을 기대하고 Bearer 토큰으로 보냅니다.
  </Accordion>
  <Accordion title="연결 실패">
    `curl http://127.0.0.1:8642/v1/health`로 API 서버가 정상인지 확인하세요. Enconvo가 다른 기기에서 실행되면 호스트의 LAN IP를 쓰고, Hermes가 네트워크 접근에 바인딩됐는지 확인하세요.
  </Accordion>
  <Accordion title="시작은 성공했는데 상태 갱신이 잠시 걸림">
    서비스 관리자는 API 서버가 준비되기 전에 돌아올 수 있습니다. 몇 초 기다린 뒤 설정 카드의 런타임 배지를 다시 보거나, `hermes gateway status`를 실행하고 `curl http://127.0.0.1:8642/v1/health`를 시험하세요.
  </Accordion>
  <Accordion title="이미지 첨부가 무시됨">
    Enconvo의 Hermes 제공업체는 현재 텍스트 전용입니다. Enconvo는 이미지 첨부를 Hermes로 보내지 않습니다. 직접 이미지 입력에는 비전을 지원하는 제공업체를 고르세요.
  </Accordion>
  <Accordion title="기본 URL이 틀림">
    `http://<gateway-host>:8642/v1`을 입력하세요. Enconvo 기본 URL 필드에 `/chat/completions`를 넣지 마세요.
  </Accordion>
  <Accordion title="게이트웨이 로그가 필요함">
    `tail -f ~/.hermes/logs/gateway.log`로 Hermes 게이트웨이 로그를, `tail -f ~/.hermes/logs/gateway.error.log`로 오류를 읽으세요.
  </Accordion>
</AccordionGroup>
