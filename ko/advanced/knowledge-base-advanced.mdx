---
title: "지식 베이스가 작동하는 방식"
description: "Enconvo가 지식 베이스를 저장, 분할, 색인, 검색하는 방식과 검색 결과를 좋게 유지하는 방법을 알아보세요."
---

이 페이지는 문서가 지식 베이스에 들어간 뒤 어떻게 되는지 알고 싶은 사람을 위한 것입니다. Enconvo가 어디에 두는지, 어떻게 나누고 색인하는지, 검색이 결과를 고르는 방식입니다. 모음을 조정하거나, 나쁜 결과를 고치거나, 자기 코드에서 지식 베이스를 호출할 때 쓰세요. 지식 베이스가 처음이면 [지식 베이스](/ko/ai/knowledge-base)부터 시작하세요.

짧게 말하면, Enconvo는 각 항목의 텍스트를 읽고, 청크로 나누고, 각 청크를 벡터로 바꾼 뒤 로컬 LanceDB 데이터베이스에 저장합니다. 검색은 의미와 정확한 단어를 동시에 찾고, 둘을 섞습니다.

## 데이터가 있는 곳

| 무엇 | 어디 |
|---|---|
| 청크, 벡터, 전문 색인 | `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/`의 LanceDB 데이터베이스 |
| 지식 베이스, 항목, 세부 정보 | `~/.config/enconvo/.support/knowledge_base/db`의 SQLite 데이터베이스(Drizzle ORM) |

모든 지식 베이스가 하나의 LanceDB 데이터베이스를 공유하고, 각 지식 베이스는 그 안의 테이블 하나입니다. Enconvo가 지식 베이스 색인을 다시 만들 때는 옛 테이블 옆에 새 테이블을 쓰고, 새 것이 준비되면 전환하므로 다시 만드는 동안에도 검색이 됩니다.

각 지식 베이스에는 id가 있습니다. API는 이를 `knowledge_base_id`로 받고, Enconvo는 지식 베이스를 명령 `knowledge_base|<id>`로 실행합니다. id를 복사하려면 헤더에서 **지식 베이스 설정**을 열고 **고급**으로 가세요.

저장 용량은 원본 자산, 추출한 텍스트, 청크 수, 임베딩 차원에 따라 다릅니다. 문서 수만으로 추정하지 말고 모음의 실제 디스크 사용을 보세요. 원본 파일과 백업은 검색 색인과 따로 두세요.

## 내용이 들어오는 방식

### 읽기

Enconvo는 항목 종류마다 맞는 도구로 읽습니다.

| 내용 | 읽는 것 |
|---|---|
| **PDF** | Document Parser 플러그인. PDF 텍스트를 쓰고, 스캔된 페이지에만 OCR 제공업체를 실행합니다 |
| **Word, PowerPoint, Excel, EPUB, CSV** | Document Parser 플러그인 |
| **텍스트와 Markdown** | 있는 그대로 읽습니다 |
| **이미지** | OCR 제공업체 |
| **오디오와 동영상** | 음성 텍스트 변환 제공업체 |
| **웹 페이지** | Web Fetch 제공업체 |
| **웹사이트 전체** | 웹사이트 크롤러가 페이지마다 |
| **YouTube** | 동영상의 자막 |

### 청크로 나누기

Enconvo는 쓰인 언어에 맞는 크기로 텍스트를 나눕니다.

| 텍스트 | 청크 크기 | 겹침 |
|---|---|---|
| 영어처럼 대부분 라틴 문자 | 1,500자 | 200자 |
| 대부분 중국어, 일본어, 한국어 | 560자 | 80자 |
| 섞임 | 각 비율에 따라 그 사이 | 그 사이 |

크기를 넘지 않는 가장 자연스러운 경계에서 나누며, 이 순서로 시도합니다.

1. 문단
2. 줄
3. 문장
4. 절
5. 단어
6. 강제 절단(마지막 수단)

스프레드시트는 대략 한 행이 한 청크가 되어, 한 행을 검색하면 그 행이 나옵니다. 이 크기는 내장되어 있으며 설정이 없습니다.

### 임베딩

모든 지식 베이스는 같은 임베딩 모델 EmbeddingGemma 300M을 씁니다. **설정 → 메모리 → 임베딩 모델**에서 어디서 실행할지 고르세요.

- **이 Mac**: 무료이고 아무것도 Mac을 떠나지 않지만, 새 내용을 색인하는 동안 GPU를 씁니다. Apple silicon Mac이 필요합니다.
- **Enconvo Cloud**: Enconvo 계정으로 무료입니다. 색인하거나 검색하는 텍스트가 그곳으로 전송됩니다.

둘 다 같은 모델을 실행하므로, 바꿔도 검색 색인은 그대로입니다. Enconvo는 청크를 묶음으로 임베딩합니다.

### 저장

각 청크는 지식 베이스 테이블의 한 행입니다.

| 필드 | 담는 것 |
|---|---|
| `text` | 청크의 텍스트 |
| `vector` | 임베딩 |
| `id` | 청크 id |
| `attachment_id` | 청크가 나온 항목 |
| `type`, `url`, `title`, `ext`, `loc` | 항목의 유형, 주소, 제목, 파일 확장자, 청크가 항목 안 어디에 있는지 |
| `metadata` | 항목에 대한 그 밖 세부 정보 |

Enconvo는 `text`의 전문 색인도 둡니다. 짧은 문자 연속으로 만들어, 정확한 이름, 숫자, 코드, CJK 단어를 찾습니다.

## 검색이 작동하는 방식

각 검색은 지식 베이스 청크에 대해 최대 세 조회를 동시에 실행합니다.

1. **의미로**: 같은 모델로 질의를 임베딩하고 가장 가까운 벡터를 찾습니다.
2. **단어로**: 흔한 영어 단어를 빼고 질의의 각 단어에 대한 전문(BM25) 검색입니다.
3. **제목으로**: 제목이 질의와 맞는 항목과, 각 항목에서 질의에 가장 가까운 청크입니다.

그다음 Enconvo가 섞습니다. 각 목록의 점수는 0에서 1로 맞추고, 청크 점수는 의미 점수의 0.6에 단어 점수의 0.4를 더합니다. 제목이 맞는 항목이나 질의 전체를 담은 청크는 더 위에 옵니다. 한 항목에서는 청크를 몇 개만 남겨, 긴 문서 하나가 나머지를 밀어내지 않게 하고, 각 청크는 주변 텍스트와 함께 돌아옵니다.

지식 베이스 검색에는 별도의 재순위 단계가 없습니다.

## 색인을 건강하게 유지

Enconvo는 전문 색인을 만들고 테이블을 스스로 정리합니다. 더 오래된 청커나 다른 임베딩 모델로 만들어졌으면, 파일을 다시 읽지 않고 이미 가진 텍스트로 색인을 다시 만듭니다.

직접 다시 만들려면:

- **지식 베이스 전체**: 헤더에서 **지식 베이스 설정**을 열고 **색인 및 검색**으로 가서 **전체 색인 다시 만들기** 옆 **다시 색인…**을 클릭하세요. 실행 중에도 검색은 됩니다.
- **항목 하나**: 오른쪽 클릭하고 **다시 색인**을 고르세요.

**지식 베이스 설정**에는 다섯 섹션이 있습니다. **일반**(이름과 설명), **색인 및 검색**(상태, 주의가 필요한 항목, 검색 모델, 다시 색인), **소스 및 캡처**(연결된 폴더와 캡처 도구), **AI 클라이언트(MCP)**, **고급**(id와 지식 베이스 삭제).

더 이상 필요 없는 지식 베이스를 삭제해 디스크 공간을 되찾으세요.

### 연결된 폴더

없는 항목은 먼저 소스 폴더의 가져오기와 동기화 상태를 보세요. **소스 및 캡처**에서 각 연결된 폴더는 동기화 중인지, 마지막으로 동기화한 시각, 또는 소스 폴더를 찾을 수 없는지를 보여 주고, **지금 동기화**, **다시 연결…**, **자동 동기화**가 있습니다.

그다음 항목의 내용 추출 상태와 임베딩 상태를 따로 보세요. 항목의 **파이프라인**은 **콘텐츠 분석**과 **검색 색인**을 두 단계로 보여 주며, 읽을 수 있는 추출 텍스트가 벡터 색인이 끝났다는 보장은 아닙니다. 제공업체나 파일 접근 오류를 고친 뒤 항목을 다시 색인하세요.

소스 폴더는 연결된 파일의 기준입니다. 오프라인 드라이브 복구와 파일 삭제를 섞지 마세요. 소스 폴더를 찾을 수 없어도 지식 베이스는 항목을 유지합니다. 가져오기를 완료로 보기 전에 건너뛴 파일 수를 검토하세요.

## 여러 지식 베이스 정리

각 지식 베이스에는 자기 문서, 색인, 테이블이 있습니다. 검색하는 방식대로 내용을 나누세요.

| 전략 | 설명 | 예 |
|----------|-------------|---------|
| **프로젝트별** | 프로젝트마다 지식 베이스 하나 | `project-alpha`, `project-beta` |
| **유형별** | 내용 유형으로 나눔 | `code-docs`, `meeting-notes`, `research` |
| **팀별** | 팀 전용 지식 | `engineering`, `marketing`, `support` |
| **범위별** | 개인과 공유 | `personal-notes`, `company-wiki` |

여러 개를 한 번에 검색하려면 컨텍스트 선택기로 첨부하거나, 에이전트에 첨부된 지식 베이스를 설정하세요. 지식 베이스를 지정하지 않은 검색은 메모리를 제외한 모든 지식 베이스를 봅니다.

## 코드에서 지식 베이스 쓰기

지식 베이스 플러그인은 [Local API](/ko/advanced/cli-local-api)에서 경로를 제공하므로, 다른 플러그인, 워크플로, 스크립트가 호출할 수 있습니다. 주요 경로:

| 경로 | 목적 |
|---|---|
| `knowledge_base/create` | 지식 베이스 만들기 |
| `knowledge_base/delete` | 지식 베이스와 모든 데이터 제거 |
| `knowledge_base/add`, `knowledge_base/add_attachments` | 파일, 텍스트, 링크, 미디어 추가 |
| `knowledge_base/search` | 하나 이상의 지식 베이스 검색 |
| `knowledge_base/list` | 지식 베이스 목록 |
| `knowledge_base/get_attachments` | 지식 베이스의 항목 목록 |
| `knowledge_base/delete_attachments` | 지식 베이스에서 항목 제거 |
| `knowledge_base/reindex` | 지식 베이스나 항목의 색인 다시 만들기 |
| `knowledge_base/summarize` | 항목 하나 요약 |

설치된 버전의 각 경로 매개변수는 **설정 → API**를 여세요.

지식 베이스 단계는 워크플로와 예약 작업에 넣을 수 있습니다. 예:

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

다른 AI 클라이언트에는 [지식 베이스 MCP](/ko/advanced/knowledge-base-mcp)를 쓰세요. 고른 지식 베이스를 로컬 읽기 전용 서비스로 노출하며, 에이전트 메모리나 녹음은 내보내지 않습니다.

## 문제 해결

| 문제 | 할 일 |
|---|---|
| 검색이 관련 없는 결과를 돌려줌 | 항목의 **검색 색인** 단계가 끝났는지 확인한 뒤 지식 베이스를 다시 색인하세요. 문서가 쓰는 단어로 검색하세요. 정확한 이름과 숫자는 전문 색인으로 맞습니다 |
| 색인이 느림 | 큰 문서는 더 오래 걸립니다. **이 Mac**이면 색인이 GPU를 씁니다. Mac을 비우려면 **임베딩 모델**을 **Enconvo Cloud**로 바꾸세요 |
| Enconvo Cloud인데 새 항목이 검색되지 않음 | Enconvo 계정에 로그인하세요. 로그인하기 전에는 새 내용이 색인되지 않고, 검색은 맞는 단어만 찾습니다 |
| 파일 유형이 지원되지 않음 | PDF, TXT, MD로 변환한 뒤 다시 추가하세요 |
| id로 지식 베이스를 찾지 못함 | **지식 베이스 설정 → 고급**에서 id를 복사해 `knowledge_base_id`로 전달하세요 |
