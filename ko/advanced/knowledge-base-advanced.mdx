title: "지식 베이스의 작동 방식"
description: "Enconvo가 지식 베이스를 저장하고, 나누고, 색인하고, 검색하는 방식과 검색 결과를 좋게 유지하는 방법을 알아보세요."
---

이 페이지는 문서가 지식 베이스에 들어간 뒤 어떻게 처리되는지 알고 싶은 분을 위한 문서입니다. Enconvo가 문서를 어디에 보관하고, 어떻게 나누고 색인하며, 검색이 결과를 어떻게 고르는지 설명합니다. 컬렉션을 조정하거나, 부정확한 결과를 고치거나, 직접 작성한 코드에서 지식 베이스를 호출할 때 참고하세요. 지식 베이스가 처음이라면 [지식 베이스](/ko/ai/knowledge-base)부터 시작하세요.

요약하면 Enconvo는 각 항목의 텍스트를 읽어 청크로 나누고, 각 청크를 벡터로 변환해 로컬 LanceDB 데이터베이스에 저장합니다. 검색은 의미와 정확한 단어로 동시에 청크를 찾은 다음 두 결과를 합칩니다.

## 데이터가 저장되는 위치

| 항목 | 위치 |
|---|---|
| 청크, 벡터, 전문 검색 인덱스 | `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/`의 LanceDB 데이터베이스 |
| 지식 베이스, 항목과 그 세부 정보 | `~/.config/enconvo/.support/knowledge_base/db`의 SQLite 데이터베이스(Drizzle ORM) |

모든 지식 베이스는 하나의 LanceDB 데이터베이스를 공유하며, 각 지식 베이스는 그 안의 테이블 하나입니다. Enconvo가 지식 베이스의 인덱스를 다시 만들 때는 기존 테이블 옆에 새 테이블을 쓰고 새 테이블이 준비되면 전환하므로, 다시 만드는 동안에도 검색은 계속 동작합니다.

각 지식 베이스에는 ID가 있습니다. API는 이를 `knowledge_base_id`로 받으며, Enconvo는 지식 베이스를 `knowledge_base|<id>` 명령으로 실행합니다. 지식 베이스의 ID를 복사하려면 헤더에서 **지식 베이스 설정**을 열고 **고급**으로 이동하세요.

저장 공간은 원본 자산, 추출된 텍스트, 청크 수, 임베딩 차원에 따라 달라집니다. 문서 수만으로 추정하지 말고 컬렉션의 실제 디스크 사용량을 확인하세요. 원본 파일과 백업은 검색 인덱스와 별도로 보관하세요.

## 콘텐츠가 들어오는 과정

### 읽기

Enconvo는 항목 종류마다 알맞은 도구로 읽습니다.

| 콘텐츠 | 읽는 도구 |
|---|---|
| **PDF** | 문서 파서 플러그인입니다. PDF의 텍스트를 사용하며, 스캔된 페이지에만 OCR 제공업체를 실행합니다 |
| **Word, PowerPoint, Excel, EPUB, CSV** | 문서 파서 플러그인 |
| **텍스트와 Markdown** | 그대로 읽습니다 |
| **이미지** | OCR 제공업체 |
| **오디오 및 동영상** | 전사 제공업체 |
| **웹 페이지** | Web Fetch 제공업체 |
| **웹사이트 전체** | 웹사이트 크롤러가 페이지 단위로 읽습니다 |
| **YouTube** | 동영상의 자막 |

### 청크로 나누기

Enconvo는 텍스트를 작성된 언어에 맞는 크기의 청크로 나눕니다.

| 텍스트 | 청크 크기 | 겹침 |
|---|---|---|
| 영어처럼 주로 라틴 문자 | 1,500자 | 200자 |
| 주로 중국어, 일본어, 한국어 | 560자 | 80자 |
| 혼합 | 각 언어의 비율에 따라 그 중간 | 그 중간 |

청크가 크기를 넘지 않는 가장 자연스러운 경계에서 나누며, 다음 순서로 시도합니다.

1. 문단
2. 줄
3. 문장
4. 절
5. 단어
6. 강제 분할(최후의 수단)

스프레드시트는 행 하나가 대략 청크 하나가 되도록 나누므로, 특정 행을 검색하면 그 행을 찾을 수 있습니다. 이 크기는 내장되어 있으며 설정은 없습니다.

### 임베딩

모든 지식 베이스는 같은 임베딩 모델인 EmbeddingGemma 300M을 사용합니다. 모델이 실행되는 위치는 **설정 → 메모리 → 임베딩 모델**에서 선택하세요.

- **이 Mac**: 무료이며 데이터가 Mac 밖으로 나가지 않지만, 새 콘텐츠를 색인하는 동안 GPU를 사용합니다. Apple 실리콘 Mac이 필요합니다.
- **Enconvo Cloud**: Enconvo 계정으로 무료로 사용합니다. 색인하거나 검색하는 텍스트가 그곳으로 전송됩니다.

둘 다 같은 모델을 실행하므로, 전환해도 검색 인덱스는 그대로 유지됩니다. Enconvo는 청크를 배치 단위로 임베딩합니다.

### 저장

각 청크는 지식 베이스 테이블의 한 행입니다.

| 필드 | 내용 |
|---|---|
| `text` | 청크의 텍스트 |
| `vector` | 청크의 임베딩 |
| `id` | 청크의 ID |
| `attachment_id` | 청크가 속한 항목 |
| `type`, `url`, `title`, `ext`, `loc` | 항목의 유형, 주소, 제목, 파일 확장자와 청크가 항목 안에서 위치한 곳 |
| `metadata` | 항목에 대한 기타 세부 정보 |

Enconvo는 `text`의 전문 검색 인덱스도 짧은 문자열 단위로 만들어 두므로, 정확한 이름, 숫자, 코드, CJK 단어를 찾을 수 있습니다.

## 검색의 작동 방식

검색할 때마다 지식 베이스의 청크를 대상으로 최대 세 가지 조회가 동시에 실행됩니다.

1. **의미로**: 질의를 같은 모델로 임베딩하고 가장 가까운 벡터를 찾습니다.
2. **단어로**: 흔한 영어 단어는 제외하고, 질의의 각 단어에 대해 전문 검색(BM25)을 합니다.
3. **제목으로**: 제목이 질의와 일치하는 항목을 찾고, 각 항목에서 질의에 가장 가까운 청크를 가져옵니다.

그런 다음 Enconvo가 결과를 합칩니다. 각 목록의 점수를 0에서 1 사이로 조정하고, 청크의 점수는 의미 점수의 0.6과 단어 점수의 0.4를 더한 값입니다. 제목이 일치하는 항목이나 질의 전체를 포함하는 청크는 순위가 더 높아집니다. 한 항목에서는 몇 개의 청크만 남기므로 긴 문서 하나가 나머지를 밀어내지 못하며, 각 청크는 주변 텍스트와 함께 반환됩니다.

지식 베이스 검색에는 별도의 재순위 단계가 없습니다.

## 인덱스를 건강하게 유지하기

Enconvo는 전문 검색 인덱스를 만들고 테이블을 정리하는 일을 스스로 처리합니다. 또 이전 청커나 다른 임베딩 모델로 만든 지식 베이스의 인덱스는 파일을 다시 읽지 않고 이미 가진 텍스트로 다시 만듭니다.

직접 다시 만들려면 다음을 사용하세요.

- **지식 베이스 전체**: 헤더에서 **지식 베이스 설정**을 열고 **색인 및 검색**으로 이동한 다음, **전체 색인 다시 만들기** 옆의 **다시 색인…**을 클릭하세요. 실행하는 동안에도 검색은 계속 동작합니다.
- **항목 하나**: 항목을 오른쪽 클릭하고 **다시 색인**을 선택하세요.

**지식 베이스 설정**에는 다섯 개의 섹션이 있습니다. **일반**(이름과 설명), **색인 및 검색**(상태, 주의가 필요한 항목, 검색 모델, 다시 색인), **소스 및 캡처**(연결된 폴더와 캡처 도구), **AI 클라이언트(MCP)**, **고급**(ID와 지식 베이스 삭제)입니다.

더 이상 필요 없는 지식 베이스는 삭제해 디스크 공간을 확보하세요.

### 연결된 폴더

항목이 보이지 않으면 먼저 소스 폴더의 가져오기 및 동기화 상태를 확인하세요. **소스 및 캡처**에서는 연결된 각 폴더가 동기화 중인지, 마지막으로 동기화한 시점이 언제인지, 또는 소스 폴더를 찾을 수 없는지 표시하며, **지금 동기화**, **다시 연결…**, **자동 동기화**를 사용할 수 있습니다.

그다음 항목의 콘텐츠 추출 상태와 임베딩 상태를 따로 확인하세요. 항목의 **파이프라인**은 **콘텐츠 분석**과 **검색 인덱스**를 두 단계로 보여 주며, 추출된 텍스트를 읽을 수 있다고 해서 벡터 색인이 끝났다는 뜻은 아닙니다. 제공업체나 파일 접근 오류를 고친 뒤에는 해당 항목을 다시 색인하세요.

연결된 파일은 소스 폴더가 기준입니다. 오프라인 드라이브 복구와 파일 삭제는 별개로 다루세요. 소스 폴더를 찾을 수 없어도 지식 베이스는 항목을 그대로 유지합니다. 가져오기가 완료되었다고 판단하기 전에 건너뛴 파일 수를 확인하세요.

## 여러 지식 베이스 구성하기

각 지식 베이스에는 자체 문서, 인덱스, 테이블이 있습니다. 검색하는 방식에 맞게 콘텐츠를 나누세요.

| 전략 | 설명 | 예시 |
|----------|-------------|---------|
| **프로젝트별** | 프로젝트마다 지식 베이스 하나 | `project-alpha`, `project-beta` |
| **유형별** | 콘텐츠 유형별로 지식 베이스를 분리 | `code-docs`, `meeting-notes`, `research` |
| **팀별** | 팀 전용 지식 | `engineering`, `marketing`, `support` |
| **범위별** | 개인용과 공유용 | `personal-notes`, `company-wiki` |

여러 개를 한꺼번에 검색하려면 컨텍스트 선택기로 첨부하거나, 에이전트에 첨부된 지식 베이스를 설정하세요. 지식 베이스를 지정하지 않은 검색은 메모리를 제외한 모든 지식 베이스를 대상으로 합니다.

## 코드에서 지식 베이스 사용하기

지식 베이스 플러그인은 [Local API](/ko/advanced/cli-local-api)로 라우트를 제공하므로 다른 플러그인, 워크플로, 스크립트에서 호출할 수 있습니다. 주요 라우트는 다음과 같습니다.

| 라우트 | 용도 |
|---|---|
| `knowledge_base/create` | 지식 베이스 만들기 |
| `knowledge_base/delete` | 지식 베이스와 모든 데이터 삭제 |
| `knowledge_base/add`, `knowledge_base/add_attachments` | 파일, 텍스트, 링크, 미디어 추가 |
| `knowledge_base/search` | 하나 이상의 지식 베이스 검색 |
| `knowledge_base/list` | 지식 베이스 목록 보기 |
| `knowledge_base/get_attachments` | 지식 베이스의 항목 목록 보기 |
| `knowledge_base/delete_attachments` | 지식 베이스에서 항목 삭제 |
| `knowledge_base/reindex` | 지식 베이스 또는 항목의 인덱스 다시 만들기 |
| `knowledge_base/summarize` | 항목 하나 요약 |

설치된 버전에서 각 라우트의 매개변수를 보려면 **설정 → API**를 여세요.

지식 베이스 단계는 워크플로와 자동화에 넣을 수 있습니다. 예를 들면 다음과 같습니다.

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

다른 AI 클라이언트에는 [지식 베이스 MCP](/ko/advanced/knowledge-base-mcp)를 사용하세요. 선택한 지식 베이스를 로컬 읽기 전용 서비스로 제공하며, 에이전트 메모리나 녹음은 내보내지 않습니다.

## 문제 해결

| 문제 | 해결 방법 |
|---|---|
| 검색 결과가 관련 없음 | 항목의 **검색 인덱스** 단계가 끝났는지 확인한 다음 지식 베이스를 다시 색인하세요. 문서에서 쓰는 단어로 검색하세요. 정확한 이름과 숫자는 전문 검색 인덱스로 일치합니다 |
| 색인이 느림 | 큰 문서는 더 오래 걸립니다. **이 Mac**에서는 색인에 GPU를 사용하므로, **임베딩 모델**을 **Enconvo Cloud**로 바꾸면 Mac을 비워 둘 수 있습니다 |
| Enconvo Cloud를 쓰는데 새 항목이 검색되지 않음 | Enconvo 계정에 로그인하세요. 로그인하기 전에는 새 콘텐츠가 색인되지 않고 검색은 일치하는 단어만 찾습니다 |
| 지원하지 않는 파일 형식 | PDF, TXT 또는 MD로 변환한 다음 다시 추가하세요 |
| ID로 지식 베이스를 찾을 수 없음 | **지식 베이스 설정 → 고급**에서 ID를 복사해 `knowledge_base_id`로 전달하세요 |
