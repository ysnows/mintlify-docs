이 페이지는 Enconvo 에이전트에 직접 만든 도구를 제공하려는 개발자를 위한 문서입니다. 사용자 지정 MCP 서버는 Enconvo 에이전트가 호출할 수 있는 도구를 제공합니다. 먼저 작은 로컬 서버로 시작해 입력과 결과를 확인한 다음, 필요한 서비스별 작업을 추가하세요.

다른 사람이 만든 서버를 설치하려면 [MCP 서버](/ko/features/mcp)를 참고하세요. 서버를 Codex와 Claude Code에도 설치할 수 있게 배포하려면 `--template mcp`로 플러그인으로 패키징하세요([플러그인 형식](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code) 참고).

## 시작하기 전에

Node.js와 npm이 필요합니다. 이 예제는 1.29.0으로 고정한 TypeScript SDK의 **1.x JavaScript API**를 사용합니다. SDK 메이저 버전에 따라 import와 설정이 다를 수 있으므로, 다른 버전을 선택할 때는 [공식 MCP 서버 가이드](https://modelcontextprotocol.io/docs/develop/build-server)를 참고하세요.

## 최소한의 로컬 서버 작성하기

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

다음 내용을 `server.mjs`로 저장하세요.

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

stdio 서버는 프로토콜 메시지를 기다리므로, 터미널에서 시작해도 채팅 인터페이스는 표시되지 않습니다. stdout은 MCP 프로토콜 메시지를 전달하므로 진단 출력은 stderr(예: `console.error`)로 보내세요. 이 전송 요건은 [공식 가이드](https://modelcontextprotocol.io/docs/develop/build-server)에서 설명합니다.

## Enconvo에 연결하기

<Steps>
  <Step title="서버 추가">
    **설정 → MCP 서버**를 열고 **서버 추가**를 클릭하세요. `hello-mcp`처럼 **서버 이름**을 지정하세요.
  </Step>
  <Step title="시작 방식 설정">
    **STDIO**를 선택하세요. **명령어**에는 `node`를 입력하고, **인수**에는 `server.mjs`의 절대 경로를 입력하세요. Enconvo가 Node를 찾지 못하면 실행 파일의 절대 경로를 사용하세요.
  </Step>
  <Step title="저장하고 확인">
    **저장**을 클릭하세요. 서버가 연결되고 `greet`가 표시되는지 확인하세요.
  </Step>
  <Step title="사용해 보기">
    에이전트에서 사용할 수 있게 한 뒤 “Ada”에게 인사하라고 요청하세요. 도구 결과는 `Hello, Ada!`여야 합니다.
  </Step>
</Steps>

동일한 설정은 다음과 같습니다.

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

예시 경로를 실제 파일 경로로 바꾸세요.

## 유용한 도구 설계하기

- 각 도구에 구체적인 동작과 설명을 지정하세요.
- 도구 경계에서 입력을 검증하고 유용한 오류 메시지를 반환하세요.
- 데이터 읽기와 전송, 삭제 같은 변경 작업을 분리하세요.
- 에이전트가 해석할 수 있도록 간결한 결과를 반환하세요.
- 자격 증명은 소스 예제나 로그가 아니라 서버의 적절한 설정에 보관하세요.

## 원격 서버와 인증

원격 서버는 설정 안내에서 제공하는 HTTP 또는 SSE 전송과 그에 해당하는 Enconvo 양식(**STDIO** 대신 **HTTP** 또는 **SSE**)을 사용하세요. 서버 URL은 일반 웹사이트 URL이 아니라 MCP 엔드포인트여야 합니다. 지원되는 인증 절차를 완료하고, 도구를 활성화하기 전에 연결을 확인하세요.

원격 전송, 인증 탐색, 세션 동작은 서버와 프로토콜 버전에 따라 다릅니다. 구현 세부 사항은 Enconvo가 사용하지 않는 `auth` 매니페스트를 만들어 내지 말고 공식 SDK와 프로토콜 문서를 참고하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 프로세스가 즉시 종료됨 | 실행 파일 경로, 종속성, 구문 오류, stderr를 확인하세요 |
| 연결되었지만 도구가 나타나지 않음 | 도구 등록 여부, 도구가 활성화되어 있는지, 선택한 에이전트를 확인하세요 |
| 잘못된 프로토콜 응답 | 의도하지 않은 stdout 로그 출력이나 잘못된 프로그램이 실행되고 있는지 확인하세요 |
| 스키마 검증 오류 | 실제 입력 형태를 사용 중인 SDK 버전과 비교하세요 |
| 원격 연결 실패 | 엔드포인트 URL, 전송 방식, 인증, 네트워크 접근을 확인하세요 |

Enconvo 자체 문서를 다른 AI 클라이언트에 제공하려면 사용자 지정 서버 없이 내장된 [지식 베이스 MCP 서버](/ko/advanced/knowledge-base-mcp)를 사용하세요.
