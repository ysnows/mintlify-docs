이 페이지는 Mac의 **설정 → 연결**에서 Linux 서버를 추가하고 그곳에 Enconvo를 설치한 사용자를 위한 안내입니다. 서버는 화면 없이 Enconvo를 실행하므로 Mac에서 채팅은 열 수 있지만 설정 화면은 열 수 없습니다. 서버 설정은 웹 UI, 명령줄, 또는 Mac의 설정을 동기화하는 세 가지 방법 중 하나로 진행할 수 있습니다.

## Mac이 서버와 공유하는 항목

페어링을 하면 Mac에서 서버의 채팅, 에이전트, 파일을 사용할 수 있지만 설정은 공유되지 않습니다. 서버는 자체 모델, 에이전트, 플러그인, API 키를 따로 보관하며 Mac에서 이를 복사해 오지 않습니다.

- 설정과 API 키는 Mac에서 열리지 않으며 서버에서 직접 변경합니다.
- 초기 상태에서 서버의 에이전트는 기본 모델을 사용합니다. 새로 설치한 경우 서버가 로그인한 계정의 Enconvo Cloud가 기본값이므로 해당 채팅은 Cloud 포인트를 사용합니다.
- 특정 에이전트의 모델만 빠르게 바꾸려면 Mac의 서버 채팅에서 모델 선택기를 사용하세요. 서버에 있는 해당 에이전트의 모델, 추론 강도, 속도가 변경됩니다. API 키가 필요한 제공업체는 먼저 서버에 키가 등록되어 있어야 합니다.

## 서버의 웹 UI 열기

서버는 채팅 창과 설정을 웹사이트 형태로 제공할 수 있으므로 Mac 브라우저에서 설정을 다룰 수 있습니다. Mac에서 설치할 때는 이 기능이 기본적으로 켜져 있지 않으므로 SSH를 통해 한 번 켜야 합니다.

<Steps>
  <Step title="웹 UI 켜기">
    `ssh`로 서버에 접속한 뒤 다음 명령을 실행합니다.

    ```bash
    enconvo service install --web 127.0.0.1:54580
    ```

    이 명령은 웹 UI가 켜진 상태로 Enconvo 서비스를 다시 작성하고 재시작합니다. `127.0.0.1`에서만 수신하므로 서버 외부에서는 접근할 수 없습니다. 나중에 `enconvo service install`을 다시 실행하면 새 실행에 지정한 옵션만 적용됩니다.
  </Step>
  <Step title="Mac에서 터널 열기">
    Mac의 터미널에서 `ssh`에 사용하는 것과 동일한 호스트 이름으로 실행합니다.

    ```bash
    ssh -N -L 54580:127.0.0.1:54580 my-server
    ```

    웹 UI를 사용하는 동안 이 터널을 실행 상태로 유지하세요. 닫으려면 Control-C를 누릅니다.
  </Step>
  <Step title="웹 UI 열기">
    Mac의 브라우저에서 `http://127.0.0.1:54580`을 엽니다. 설정은 Mac에서와 동일하게 작동합니다. **설정 → AI 모델**에서 모델을 선택하고, **설정 → 플러그인**에서 플러그인을 추가하며, API 키도 이곳에 입력할 수 있습니다.
  </Step>
</Steps>

서버에서 `enconvo service url`을 실행하면 웹 UI 주소가 출력됩니다.

### 터널 없이 접근하기

SSH 없이 다른 컴퓨터에서도 웹 UI를 열려면 네트워크에 바인딩하세요.

```bash
enconvo service install --web 0.0.0.0:54580
```

이 경우 웹 UI에 연결 토큰이 필요합니다. `enconvo service url`을 실행해 끝에 `?tkn=`이 붙은 주소를 출력하세요. 해당 링크를 한 번 열면 브라우저가 토큰을 보관합니다. 리버스 프록시 뒤에서 사용할 때는 프록시가 제공하는 주소를 `--web-url https://enconvo.example.com`으로 지정하거나, 서버 접속에 쓰는 다른 이름을 `--web-host <name>`으로 지정하세요. 두 경우 모두 토큰이 필요합니다.

<Warning>
  이 토큰을 가진 사람은 서버의 Enconvo 계정과 해당 사용자가 읽을 수 있는 모든 파일에 접근할 수 있습니다. 링크를 비공개로 유지하고 포트를 방화벽이나 VPN 뒤로 제한하며 가급적 SSH 터널을 사용하세요. 토큰을 교체하려면 서버에서 `~/.config/enconvo/.support/windows-shell/web-token`을 삭제한 뒤 `systemctl --user restart enconvo`를 실행하세요.
</Warning>

## 명령줄에서 구성하기

설치된 모든 플러그인의 라우트는 서버에서 `enconvo` 명령으로 실행할 수 있습니다. `enconvo <plugin> <route> --flags` 또는 전체 요청에 `--input-json`을 사용하세요. 어느 단계에서든 `-h`를 붙이면 하위 항목을 확인할 수 있습니다.

```bash
enconvo -h
enconvo config -h
enconvo config set -h
```

`'agent|main'`처럼 `|`가 들어간 키는 따옴표로 감싸세요. 감싸지 않으면 셸이 `|`를 파이프로 해석합니다.

### 모델

서버의 모델 제공업체를 나열합니다. 각 항목의 `commandKey`(예: `llm|enconvo_ai`)가 설정할 값입니다.

```bash
enconvo llm list_providers
```

기본값으로 설정된 모든 에이전트가 사용하는 기본 모델을 지정합니다.

```bash
enconvo config get llm --includes selected
enconvo config set --preferenceKey llm --keys selected --value 'llm|<provider id>'
```

특정 에이전트의 모델을 설정합니다. 메인 에이전트는 `agent|main`이며, 다른 에이전트들의 `command_key`는 `enconvo agent list`로 확인할 수 있습니다.

```bash
enconvo config get 'agent|main' --includes llm
enconvo config set --preferenceKey 'agent|main' --keys llm --value 'llm|<provider id>'
```

값을 `default`로 지정하면 다시 기본 모델을 따릅니다. `enconvo config preferences 'agent|main'`은 에이전트가 가진 모든 설정을 나열합니다.

특정 설정 하나만 되돌리려면 이름을 지정하세요.

```bash
enconvo config reset 'agent|main' --keys llm
```

<Warning>
  `--keys` 없이 `enconvo config reset`을 실행하면 해당 키의 모든 설정이 초기화되며, 에이전트나 명령의 경우 워크스페이스 데이터도 삭제됩니다. 이 작업은 되돌릴 수 없습니다.
</Warning>

`config get`은 저장된 API 키와 토큰을 `[hidden]`으로 표시합니다. API 키가 셸 기록에 남지 않도록 `config set` 대신 웹 UI의 설정에서 입력하세요.

### 플러그인

```bash
enconvo plugin list
enconvo plugin install owner/repo
enconvo plugin uninstall <name>
```

`plugin install`에는 GitHub `owner/repo`, git URL, `.zip`을 가리키는 `https` 링크, `npm:<package>`, 폴더, 또는 `<plugin>@<marketplace>`를 넘길 수 있습니다. 화면이 필요한 플러그인은 서버에서 숨겨집니다.

### 에이전트

```bash
enconvo agent list
enconvo agent create -h
```

삭제나 일시 중지 등 나머지 기능은 `enconvo agent -h`에서 확인할 수 있습니다.

## 동기화로 Mac 설정 그대로 쓰기

동기화는 Enconvo 계정을 통해 Mac의 설정을 서버로 복사합니다. Enconvo Cloud 요금제와 평생 라이선스에 포함되어 있습니다.

1. Mac에서 **설정 → 동기화**를 열고 **컴퓨터 간 동기화**를 켠 다음 **저장 공간** 아래에서 **Enconvo 계정**을 선택합니다. Linux 서버는 iCloud에 접근할 수 없습니다.
2. 서버의 웹 UI에서 **설정 → 동기화**를 열고 **컴퓨터 간 동기화**를 켭니다.
3. 양쪽 컴퓨터 모두에서 **동기화 항목** 아래의 **설정**, **플러그인**, **스킬** 등 가져올 항목을 고릅니다.
4. API 키도 함께 가져오려면 양쪽에서 **API 키**를 켭니다. 기본값은 꺼짐입니다. 이때 Mac에 코드가 표시되면 서버에도 같은 코드가 표시되는지 확인한 뒤 **허용**을 클릭하세요.

한 컴퓨터에 종속된 항목인 단축키, 폴더 경로 및 작업 폴더, 로그인 상태, 자동화, 메시징 봇은 그대로 각 컴퓨터에 남습니다. 각 선택 항목의 범위는 [Mac 간 동기화](/ko/configuration/account)를 참고하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| `enconvo: command not found` | 새 SSH 세션을 여세요. 설치 시 셸 프로필의 `PATH`에 Enconvo 폴더가 추가되므로 설치 전부터 열려 있던 세션에는 아직 반영되지 않았습니다. |
| `enconvo service url`에 주소가 출력되지 않음 | Enconvo가 실행 중이지 않거나 웹 UI 없이 실행되고 있습니다. `enconvo service install --web 127.0.0.1:54580`을 다시 실행하세요. |
| 브라우저에서 `127.0.0.1:54580`을 열 수 없음 | 터널이 여전히 열려 있는지 확인한 뒤, `systemctl --user status enconvo`로 서비스 상태를, `journalctl --user -u enconvo`로 로그를 확인하세요. |
| 웹 UI가 연결 토큰을 요구함 | `enconvo service url`이 출력한 끝에 `?tkn=`이 포함된 전체 링크를 여세요. |
| `service install`이 이 사용자에 대해 Enconvo가 이미 실행 중이라고 표시함 | 로그아웃 후에도 사용자 서비스를 유지하지 않는 서버여서 Mac이 Enconvo를 백그라운드 프로세스로 실행했습니다. `sudo loginctl enable-linger $USER`를 실행하고 `enconvo service install --web 127.0.0.1:54580`을 다시 실행한 뒤, 서비스가 제어권을 갖도록 서버를 재시작하세요. |
| `service install`이 systemd를 사용할 수 없다고 표시함 | 대신 사용 중인 프로세스 관리자 아래에서 `enconvo --headless --web 127.0.0.1:54580`을 실행하세요. |
| 채팅이 Mac과 다른 모델을 사용함 | 서버는 자체 모델을 갖고 있습니다. `enconvo config get llm --includes selected`를 확인하거나 동기화를 켜세요. |
