대부분의 사용자는 Enconvo의 **플러그인** 페이지에 있는 플러그인 스토어에서 플러그인을 설치합니다. Enconvo는 다른 곳에서도 플러그인을 설치할 수 있습니다. 개발자가 GitHub와 플러그인 마켓플레이스에 게시한 Codex 및 Claude Code 플러그인도 포함됩니다. Enconvo가 읽는 패키지는 [플러그인 형식](/extensions/plugin-formats)을 참고하세요.

앱에서 설치하려면 [플러그인 페이지에서](#플러그인-페이지에서)와 [채팅에서](#채팅에서)를 읽어 보세요. 나머지 부분은 개발자와 고급 사용자를 위한 내용입니다. 터미널에서 설치하기, 플러그인 마켓플레이스 추가하기, 업데이트와 제거, 직접 만든 플러그인 공유하기를 다룹니다.

<Warning>
Enconvo 스토어에 있는 플러그인만 Enconvo가 검토합니다. 다른 곳에서 가져온 플러그인은 MCP 서버를 통해 Mac에서 프로그램을 실행할 수 있으므로, 신뢰할 수 있는 출처의 플러그인만 설치하세요.
</Warning>

## 플러그인 페이지에서

**플러그인** 페이지에서 **추가**를 클릭합니다.

| 옵션 | 기능 |
|---|---|
| **플러그인 만들기** | Enconvo의 에이전트와 함께 플러그인을 만드는 채팅을 시작합니다. |
| **플러그인 압축 파일 업로드…** | `.enconvo` 패키지 또는 Claude Code나 Codex 플러그인의 `.zip` 파일을 설치합니다. |
| **GitHub에서 추가…** | GitHub, git, npm 또는 폴더에서 플러그인이나 플러그인 마켓플레이스의 플러그인을 설치합니다(아래 참고). |
| **MCP 서버 추가…** | 플러그인으로 감싸지 않고 서버 하나만 연결할 수 있도록 MCP 설정을 엽니다. |
| **PopBar 확장 프로그램 추가…** | 링크, 파일 또는 `#popclip` 스니펫에서 PopBar 확장 프로그램을 설치합니다([PopBar 확장 프로그램](/ko/features/popbar) 참고). |
| **새 스킬…** | 직접 스킬을 작성할 수 있도록 스킬 설정을 엽니다. |
| **개발자 가이드** | [확장 프로그램 개발](/ko/extensions/developing)을 엽니다. |

추가한 항목은 **Enconvo** 탭 맨 위의 **설치됨**에 있습니다. 연결한 커넥터와 설치했거나 만든 플러그인이 이름별로 표시되며, **설치됨**을 클릭하면 전체를 볼 수 있습니다. Enconvo에 포함된 플러그인은 여기에 표시되지 않습니다. PopBar 확장 프로그램은 Enconvo가 검토한 카탈로그가 있는 별도의 **PopBar** 탭에 있습니다. [PopBar 확장 프로그램](/ko/features/popbar)을 참고하세요.

### GitHub에서 추가

플러그인이 있는 위치를 붙여 넣고 **미리보기**를 누르세요.

- `owner/repo` 또는 GitHub 링크(폴더로 연결되는 링크 `/tree/<branch>/<folder>` 포함)
- 저장소 안의 플러그인은 `owner/repo/folder`이며, 버전을 고정하려면 `@branch` 또는 `@tag`를 붙입니다
- 모든 https git 주소
- `npm:<package>`이며, 버전을 고정하려면 `@version`을 붙입니다
- 플러그인 `.zip`으로 연결되는 https 링크
- Mac의 폴더

비공개 GitHub 또는 git 저장소도 사용할 수 있습니다. Enconvo는 Mac에 이미 로그인된 GitHub 계정이나 SSH 키를 사용하므로 비밀번호를 입력할 필요가 없습니다.

Enconvo는 아무것도 설치하기 전에 플러그인을 보여 줍니다. 형식(Codex, Claude Code, 이식 가능 또는 Enconvo), 버전, 개발자, 스킬, MCP 서버와 훅, 그리고 포함된 ChatGPT 앱이 표시되며, ChatGPT 앱은 Enconvo가 로드하지 않습니다. 각 MCP 서버에 대해서는 Mac에서 시작되는지 인터넷으로 연결되는지 알려 줍니다. 플러그인의 훅은 Mac에서 명령을 실행하므로 **훅 실행 허용**을 체크하지 않으면 꺼진 상태로 유지됩니다. **설치**를 클릭하면 Enconvo가 플러그인 페이지를 엽니다. **소스** 행에는 플러그인이 어디서 왔는지(GitHub와 git은 커밋과 함께)가 표시되고 저장소나 npm 페이지로 연결되며, 아래쪽 메모에는 플러그인의 개발자가 표시됩니다. Enconvo가 만들었다고 표시되는 것은 Enconvo 자체 플러그인과 스토어의 플러그인뿐입니다. 이렇게 설치한 플러그인은 **개인** 아래에 표시됩니다. 같은 위치에서 다시 설치하면 플러그인이 업데이트됩니다. 같은 이름의 플러그인이 이미 다른 곳에서 설치되어 있다면 먼저 제거하세요.

주소가 플러그인 마켓플레이스이면, 대화상자에 마켓플레이스의 플러그인이 각각 **설치** 버튼과 함께 나열됩니다. 하나를 설치하면 마켓플레이스가 추가되며, 다음에 대화상자를 열 때 **내 마켓플레이스** 아래에 표시됩니다.

Enconvo 플러그인의 소스 코드는 빌드해야 작동하므로, 이 경우 대화상자가 터미널에서 실행할 `enconvo plugin install` 명령어를 알려 줍니다.

## 채팅에서

플러그인으로는 할 수 없는 일을 Enconvo의 에이전트에게 요청하면, 에이전트가 Mac에 있는 플러그인 마켓플레이스에서 플러그인을 찾을 수 있습니다. Enconvo에서 추가한 마켓플레이스와, Codex 또는 Claude Code에는 있지만 Enconvo에는 아직 없는 마켓플레이스가 대상이며, Codex에 포함된 OpenAI Curated 마켓플레이스도 포함됩니다([Codex 또는 Claude Code에서 추가한 마켓플레이스](#codex-또는-claude-code에서-추가한-마켓플레이스) 참고). 이미 Mac에 있는 카탈로그 사본을 읽으며, 찾는 동안에는 아무것도 다운로드하지 않습니다. 이미 설치한 플러그인과, 다른 곳에서 설치한 플러그인과 이름이 같은 플러그인은 제외됩니다.

플러그인을 찾으면 에이전트가 채팅에 카드를 보여 주며, **설치**를 클릭하기 전에는 아무것도 설치되지 않습니다.

- Enconvo에서 추가한 마켓플레이스의 플러그인이면, 카드에 플러그인이 Mac에서 시작하거나 연결하는 MCP 서버, 스킬, 필요한 다른 플러그인이 표시됩니다.
- Codex나 Claude Code에만 있는 마켓플레이스의 플러그인이면, 설치하면 해당 마켓플레이스가 Enconvo에 추가된다고 카드에 표시됩니다. 그 전에는 Enconvo가 플러그인 내용을 읽을 수 없으므로 카드에 내용을 나열할 수 없습니다.

어느 경우든 플러그인의 훅은 **플러그인**에서 켜기 전까지 꺼진 상태로 유지됩니다. 필요한 플러그인을 설치할 수 없는 경우처럼 플러그인을 설치할 수 없으면, 에이전트는 카드를 보여 주는 대신 그 사실을 알려 줍니다.

### ChatGPT의 플러그인

[ChatGPT 플러그인 디렉터리](https://chatgpt.com/plugins)에 있는 플러그인은 Enconvo에 설치할 수 없습니다. 대부분은 ChatGPT 안에서만 실행되는 ChatGPT 앱이며, 나머지는 OpenAI가 ChatGPT와 Codex에만 제공합니다. Mac에서 Codex에 로그인했다면 에이전트는 Codex가 보관한 사본으로 디렉터리를 알고 있습니다. 디렉터리의 플러그인 이름을 말하거나 chatgpt.com 링크를 붙여 넣으면, 에이전트가 설치할 수 없는 이유를 알려 주고 같은 일을 하는 대안을 제안합니다. 커넥터, MCP 서버, 스킬, 또는 마켓플레이스 중 하나에 있는 같은 이름의 플러그인입니다. 파일이 포함된 디렉터리의 플러그인 중 상당수는 Codex에 포함된 마켓플레이스인 OpenAI Curated(OpenAI의 공개 `openai/plugins` 저장소)에도 같은 이름의 플러그인이 있습니다. 에이전트가 그 플러그인을 제안하며, 설치하면 OpenAI Curated가 Enconvo에 추가됩니다. Enconvo는 이 플러그인에 포함된 ChatGPT 앱은 로드하지 않고 스킬과 MCP 서버만 로드합니다.

chatgpt.com 링크는 **GitHub에서 추가**에서도 작동하지 않으며, 대화상자에서 같은 안내를 보여 줍니다.

## 명령줄에서

`plugin install`은 GitHub, git, npm, 웹의 zip, 폴더 또는 마켓플레이스에서 플러그인을 가져옵니다. Enconvo 2.5.6 이상이 실행 중이어야 합니다.

```sh
npx -p @enconvo/api enconvo plugin install <source>
```

| 소스 | 예시 |
|---|---|
| GitHub 저장소. 선택적으로 그 안의 폴더와 브랜치, 태그 또는 커밋 | `acme/notes`, `acme/plugins/notes@v1.2.0` |
| GitHub 주소 | `https://github.com/acme/plugins/tree/main/notes` |
| https를 통한 다른 git 저장소(git 필요). ssh 주소는 GitHub에서만 작동합니다 | `https://git.example.com/notes.git`, `git@github.com:acme/notes.git` |
| npm 패키지 | `npm:@acme/notes-plugin`, `npm:@acme/notes-plugin@1.2.0` |
| 웹의 플러그인 zip(공개 https만) | `https://downloads.acme.com/notes-1.2.0.zip` |
| Mac의 폴더 | `./notes`, `~/code/notes`, `/Users/ada/notes` |
| 추가한 마켓플레이스의 플러그인 | `notes@acme-plugins` |

<Note>
`plugin install`과 `plugin marketplace`에는 0.1.174보다 새로운 `@enconvo/api` 릴리스가 필요합니다. `@enconvo/api`에 의존하는 프로젝트 안에서는 `npx enconvo …`만으로 충분합니다. `marketplace import`에는 Enconvo 2.5.7 이상도 필요합니다.
</Note>

`--preview`를 추가하면 설치하지 않고 무엇이 어디서 설치되는지 볼 수 있습니다.

소스가 플러그인이 아니라 플러그인 마켓플레이스이면 `plugin install`이 그 플러그인을 나열합니다. 200개를 넘는 마켓플레이스는 처음 200개를 나열하고 나머지 개수를 알려 주며, `plugin marketplace add`는 모두 나열합니다. `--plugin`으로 하나를 고르면 마켓플레이스도 함께 추가됩니다.

```sh
npx -p @enconvo/api enconvo plugin install acme/plugins --plugin notes
```

### 설치할 때 일어나는 일

- **설정**: API 키처럼 필수 설정이 있는 플러그인은 설치된 뒤 해당 설정을 요청합니다. `plugin install`이 설정 이름을 알려 주며, 플러그인 페이지에서 채우세요.
- **소스에서 가져온 Enconvo 플러그인**: GitHub 저장소나 폴더에 빌드되지 않은 Enconvo 플러그인이 있으면 `plugin install`이 먼저 빌드합니다. 폴더는 `npm install` 후 그 자리에서 빌드됩니다.
- **온보딩**: 플러그인이 온보딩 스킬을 지정하면 Enconvo가 첫 설치 후 실행할지 묻습니다.
- **로그인**: Notion이나 Figma처럼 플러그인의 MCP 서버가 로그인을 요구하면, 설치되는 즉시 플러그인 페이지에 **로그인**이 표시됩니다. Enconvo가 브라우저에서 서버의 로그인 페이지를 열고, 해당 서버가 연결되면 다음 서버를 안내합니다. `plugin install`은 대신 서버 이름을 알려 줍니다. 건너뛴 로그인은 **설정 → MCP 서버**에서 기다립니다.
- **훅**: 플러그인의 [훅](/extensions/plugin-formats#hooks)은 명령을 실행하므로 꺼진 상태로 설치됩니다. `--preview`로 목록을 볼 수 있으며, 플러그인 페이지의 **훅 허용** 스위치로 허용합니다. 허용한 훅은 변경되지 않는 업데이트에서는 계속 켜져 있습니다.
- **의존성**: 마켓플레이스의 Claude Code 플러그인이 다른 플러그인을 필요로 하면 Enconvo가 함께 설치합니다([플러그인 마켓플레이스](#플러그인-마켓플레이스) 참고). `--preview`는 이를 나열하고 이미 설치된 것, 설치될 것, 설치할 수 없는 것을 알려 줍니다. 마켓플레이스 항목이 선언한 의존성이 허용되지 않은 마켓플레이스의 것이면 설치가 중단되고, 플러그인 자체 `plugin.json`이 선언한 의존성은 제외한 채 설치가 계속됩니다. 이들의 훅은 꺼진 상태로 유지되며, 플러그인을 제거해도 정리(prune)하기 전까지는 남아 있습니다([제거하기](#제거하기) 참고).
- **사용하기**: Codex와 마찬가지로 채팅에서 `@`를 입력해 플러그인을 고르거나, 플러그인 페이지의 **이렇게 질문해 보세요** 아래 프롬프트 중 하나를 클릭하세요. 어느 쪽이든 채팅에 플러그인이 첨부됩니다. 설치된 모든 플러그인이 `@` 메뉴에 있으며, 카테고리를 지정하지 않은 Codex 또는 Claude Code 플러그인도 포함됩니다.
- **같은 이름**: 같은 소스에서 다시 설치하면 플러그인이 업데이트됩니다. 같은 이름의 플러그인이 스토어 등 다른 곳에서 이미 설치되어 있으면 Enconvo는 그대로 두고 먼저 제거하라고 안내합니다.

Enconvo가 실행 중이 아니어도 `plugin install`은 GitHub의 Enconvo 플러그인을 빌드하여 설치할 수 있습니다. 다른 경우에는 Enconvo를 열고 다시 시도하세요.

## 플러그인 마켓플레이스

마켓플레이스는 저장소나 폴더에 있는 플러그인 카탈로그입니다. Enconvo는 두 종류를 모두 읽습니다. Codex의 `.agents/plugins/marketplace.json`과 Claude Code의 `.claude-plugin/marketplace.json`입니다.

```sh
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins   # GitHub, a git address or a folder
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins --ref v2   # at a branch, tag or commit
npx -p @enconvo/api enconvo plugin marketplace list               # added marketplaces and their plugins
npx -p @enconvo/api enconvo plugin install notes@acme-plugins     # install one of them
npx -p @enconvo/api enconvo plugin marketplace refresh            # fetch them again for new plugins
npx -p @enconvo/api enconvo plugin marketplace remove acme-plugins
```

`refresh`는 `upgrade`(Codex의 이름)와 `update`(Claude Code의 이름)로도 호출할 수 있으며, `--ref v2`는 `acme/plugins@v2`와 같습니다.

플러그인 페이지에서 **추가 → GitHub에서 추가…**를 열고 마켓플레이스 주소를 붙여 넣거나, **내 마켓플레이스** 아래에서 추가한 마켓플레이스를 고르세요.

Enconvo는 GitHub나 git의 마켓플레이스는 사본을 보관하고, 폴더 마켓플레이스는 있는 그 자리에서 읽습니다. 마켓플레이스를 제거해도 그곳에서 설치한 플러그인은 그대로 남습니다.

### Codex 또는 Claude Code에서 추가한 마켓플레이스

이 Mac의 Codex나 Claude Code에 마켓플레이스를 추가했거나 Codex가 OpenAI Curated 마켓플레이스를 가져왔다면, `marketplace list`가 Enconvo에 아직 없는 마켓플레이스를 보여 주고 `import`가 이를 추가하므로 주소를 다시 입력하지 않아도 됩니다.

```sh
npx -p @enconvo/api enconvo plugin marketplace import                            # all of them
npx -p @enconvo/api enconvo plugin marketplace import claude-plugins-official    # only these
```

Enconvo는 Codex의 `~/.codex/config.toml`, OpenAI Curated 사본, 개인 `~/.agents/plugins/marketplace.json`, 그리고 Claude Code의 알려진 마켓플레이스 목록에서 마켓플레이스를 찾습니다. 이 파일들을 읽기만 하며 어느 앱에서도 아무것도 변경하지 않습니다. OpenAI Curated는 GitHub의 `openai/plugins`에서 추가됩니다. Codex 자체 도구용 플러그인이 있는 Codex에 포함된 다른 마켓플레이스와, Enconvo가 추가하지 않는 `marketplace.json` 파일의 웹 주소로 추가한 Claude Code 마켓플레이스는 제외됩니다. 두 앱에 같은 이름의 마켓플레이스가 있으면 Codex의 것을 제안합니다.

OpenAI Curated 같은 Codex 마켓플레이스는 각 플러그인의 이름과 출처만 나열합니다. 마켓플레이스 자체 폴더에 있는 플러그인은 Codex처럼 플러그인 매니페스트에서 제목, 설명, 카테고리, 개발자를 가져와 보여 주며, 에이전트는 이름뿐 아니라 하는 일로도 플러그인을 찾습니다. 마켓플레이스 항목이 직접 말하는 내용이 우선합니다.

Gmail, Google Drive, Outlook, Teams처럼 OpenAI Curated의 일부 플러그인은 ChatGPT로 Codex에 로그인해야만 작동하므로, API 키로 로그인하는 사용자에게는 Codex도 제공하지 않습니다. Enconvo도 ChatGPT에 로그인하지 않으므로 이들을 ChatGPT 로그인이 필요한 것으로 표시하고 설치하지 않으며, 에이전트도 제안하지 않습니다. 이런 서비스에는 대신 해당 공급자의 MCP 서버나 커넥터를 추가하세요.

### 마켓플레이스의 플러그인이 오는 곳

마켓플레이스의 플러그인은 마켓플레이스 안의 폴더, 다른 GitHub 저장소, git 주소, git 저장소 안의 폴더, npm, 또는 웹의 zip(Claude Code의 `archive` 소스)에서 올 수 있습니다. Codex 마켓플레이스가 `NOT_AVAILABLE`로 표시한 플러그인은 설치할 수 없습니다.

`./plugins/notes`처럼 쓴 폴더 소스는 마켓플레이스의 최상위에서 읽습니다. `notes`처럼 이름만 쓴 경우는 Claude Code와 마찬가지로 `metadata.pluginRoot`가 지정한 폴더에서 읽으며, 해당 필드가 필요합니다.

GitHub, npm 또는 웹에서 다운로드하는 데 최대 3분이 걸릴 수 있습니다. 더 오래 걸리면 Enconvo가 중단하고 연결을 확인하라고 안내합니다.

zip은 링크를 붙여 넣든 마켓플레이스에 나열되어 있든 공개 https 주소에서만, 리디렉션 최대 5회까지 다운로드합니다. 마켓플레이스가 `sha256`을 제공하면 일치하지 않는 다운로드는 거부됩니다. 플러그인은 zip의 최상위 또는 폴더 하나 안에 있을 수 있습니다.

### Claude Code 마켓플레이스 항목

Claude Code 마켓플레이스 항목은 Claude Code가 읽는 방식 그대로 플러그인 자체의 `plugin.json`과 함께 작동합니다.

- 항목은 플러그인 자체에 `commands`, `agents`, `skills`, `outputStyles`, `themes`를 추가할 수 있으며, 항목의 `hooks`는 같은 이벤트에 대한 플러그인의 훅을 대체합니다.
- `plugin.json`이 있는 플러그인에 대해 `"strict": false`인 항목이 이 중 하나라도 나열하면 매니페스트 충돌로 거부됩니다. 한 곳에만 두세요.
- 플러그인에 `plugin.json`이 없으면 항목이 곧 매니페스트입니다.
- 항목의 이름, 설명, 작성자 및 기타 목록 세부 정보가 표시되며, 버전은 플러그인의 것입니다.
- 마켓플레이스의 `renames`를 따릅니다. 이전 이름으로 설치된 플러그인은 새 이름으로 계속 업데이트되고, 이전 이름으로 설치하면 해당 플러그인을 찾습니다. `null`로 이름이 바뀐 항목은 마켓플레이스에서 제거된 것이며 Enconvo가 그렇게 알려 줍니다. 플러그인 자체 매니페스트도 이름을 바꾼 경우, Enconvo는 플러그인 이름을 매니페스트에서 가져오므로 이전 플러그인을 제거하고 새 플러그인을 설치하라고 안내합니다.
- 항목이나 `plugin.json`에 있는 플러그인의 `dependencies`는 함께 설치됩니다. 각 의존성은 이름(`"formatter"`), 이름과 마켓플레이스(`"formatter@acme-tools"`), 둘 중 하나 뒤에 `^` 범위가 붙은 형태(`"formatter@acme-tools@^2.1"`), 또는 semver 범위가 있는 `{ "name", "marketplace", "version" }`입니다. 의존성은 다른 마켓플레이스를 지정하지 않는 한 플러그인 자체의 마켓플레이스에서 가져오며, 다른 마켓플레이스는 설치한 마켓플레이스의 `allowCrossMarketplaceDependenciesOn`에 나열되어 있어야 합니다. `version` 범위가 있는 의존성은 그 범위와 다른 설치된 플러그인이 지정한 범위 안에서 가장 높은 릴리스 태그(`<plugin>--v<version>`)로 설치되며, 플러그인 자체 저장소 또는 마켓플레이스 안의 플러그인이라면 마켓플레이스 저장소에서 가져옵니다(마켓플레이스 폴더가 git 저장소 안에 있으면 해당됩니다). 이런 태그가 없으면 마켓플레이스 안의 플러그인은 마켓플레이스에 있는 그대로 설치되고, 자체 저장소의 플러그인은 거부됩니다. 어떤 단일 버전도 만족하지 못하는 범위는 설치를 거부하며, 업데이트는 범위 안에서만 이루어집니다. 이미 설치된 의존성은 그대로 두고, `version` 범위를 벗어난 의존성은 경고합니다.

### 공유하기 전에 마켓플레이스 확인하기

마켓플레이스를 공유하기 전에 마켓플레이스와 그 안의 모든 플러그인을 확인하세요. 규칙은 `claude plugin validate`가 적용하는 규칙에 `.agents/plugins/marketplace.json`에 대한 Codex의 규칙을 더한 것입니다. [Validation Codes](/extensions/validation-codes#marketplaces)를 참고하세요. 오류는 Claude Code가 항목을 나열하더라도 마켓플레이스를 추가하거나 플러그인을 설치할 수 없다는 뜻입니다. 항목의 잘못된 형식의 필드, 플러그인으로 이어지지 않는 `renames`, 거부되는 `relevance` 신호, `claude-plugins-hub`처럼 Anthropic 자체 이름처럼 보이는 마켓플레이스 이름이 그 예입니다. 경고는 철자가 틀린 필드처럼 Claude Code가 무시하는 항목과 Claude Desktop이 거부하는 이름을 다룹니다.

```sh
npx -p @enconvo/api enconvo plugin validate path/to/marketplace
```

## 업데이트

Enconvo의 플러그인 업데이트 확인은 GitHub, git, npm, 폴더, 마켓플레이스에서 설치한 플러그인도 대상으로 하며, 업데이트를 스토어의 업데이트와 함께 나열합니다. 저장소의 최신 커밋은 다운로드하지 않고 읽고, npm에는 최신 버전을 묻고, 설치된 폴더가 바뀌었는지 확인하며, 마켓플레이스가 `sha256`으로 고정한 zip은 고정 값이 바뀌었는지 확인합니다. 업데이트하면 같은 소스에서 플러그인을 다시 설치합니다.

플러그인 하나만 확인하려면 플러그인 페이지를 열고 **⋯** 메뉴에서 **업데이트 확인**을 선택하세요. 새 버전이 있으면 나타나는 메시지에서 **업데이트**를 클릭합니다.

또는 Claude Code의 `claude plugin update`처럼 터미널에서 하나를 업데이트할 수 있습니다.

```bash
npx -p @enconvo/api enconvo plugin update notes                # from wherever it came from, or the store
npx -p @enconvo/api enconvo plugin update notes@acme-plugins   # only if it came from that marketplace
```

먼저 확인합니다. 더 새로운 버전이 없으면 플러그인이 이미 최신 버전이라고 알려 주고 아무것도 바꾸지 않으며, 있으면 업데이트 목록과 같은 방식으로 플러그인을 업데이트합니다.

## 제거하기

플러그인 페이지에서 플러그인의 메뉴나 해당 페이지에서 제거하면 먼저 확인을 요청하며, 터미널에서도 제거할 수 있습니다.

```bash
npx -p @enconvo/api enconvo plugin uninstall notes            # also: remove, rm
npx -p @enconvo/api enconvo plugin uninstall notes --prune    # and the dependencies nothing needs any more
npx -p @enconvo/api enconvo plugin prune --dry-run            # list them without removing anything
npx -p @enconvo/api enconvo plugin prune                      # remove them (also: autoremove)
```

정리(prune)는 다른 플러그인이 필요로 해서 설치된 플러그인 중 더 이상 어떤 설치된 플러그인도 필요로 하지 않는 것만 제거하며, Claude Code의 `claude plugin prune`과 같습니다. 직접 설치한 플러그인은 정리되지 않으며, 의존성을 직접 다시 설치하면 그 플러그인은 사용자의 것이 됩니다. 터미널에서는 Enconvo가 제거할 대상을 나열하고 먼저 묻습니다. 질문을 건너뛰려면 `-y`를 추가하세요. `--prune`은 질문할 수 없을 때 이 옵션이 필요합니다. 플러그인 페이지의 제거는 아직 정리하지 않습니다.

## 직접 게시하기

Enconvo 스토어에 플러그인을 등록하려면 [플러그인 스토어 가이드라인](/ko/extensions/publishing-guidelines)을 참고하세요. 누구나 설치할 수 있는 링크를 보내려면 플러그인 페이지에서 **공유…**를 클릭하세요. [플러그인 공유하기](/ko/extensions/overview)를 참고하세요. Enconvo 없이 공유하려면 GitHub나 마켓플레이스에 올리면 되며, 사람들은 **GitHub에서 추가…** 또는 위의 명령어로 설치할 수 있습니다.

### 릴리스에 태그 달기

`plugin tag`는 `claude plugin tag`처럼 릴리스하는 커밋에 `<plugin>--v<version>`이라는 이름의 git 태그를 붙입니다. 다른 플러그인의 의존성이 버전 범위를 요청하면 Claude Code와 Enconvo가 이 태그 중에서 고르며, 누구나 Enconvo로 그 릴리스를 설치할 수 있습니다. 예: `acme/plugins/notes@notes--v1.2.0`.

```sh
npx -p @enconvo/api enconvo plugin tag plugins/notes --dry-run   # check, and print the git commands
npx -p @enconvo/api enconvo plugin tag plugins/notes --push      # tag HEAD and push the tag to origin
```

버전은 플러그인의 매니페스트에서 가져오며, 매니페스트에 없으면 마켓플레이스 항목에서 가져옵니다. semver(`1.2.0`)여야 합니다. 태그를 달기 전에 `plugin tag`는 `plugin validate`처럼 플러그인을 확인하고, 마켓플레이스 항목이 다른 버전을 지정했거나, 플러그인 폴더의 파일이 커밋되지 않았거나, 태그가 이미 있으면 중단합니다. 새 릴리스에는 버전을 올리세요. `--force`는 대신 기존 태그를 옮깁니다. Codex, Claude Code, 이식 가능, Enconvo 플러그인에 모두 태그를 달 수 있으므로, 패키지에 있는 모든 매니페스트가 같은 버전을 지정해야 합니다. `-m`은 태그 메시지를 설정하고(`%s`는 버전), `--remote`는 `--push`가 푸시할 원격 저장소를 설정합니다. `plugin install`처럼 0.1.174보다 새로운 `@enconvo/api` 릴리스가 필요합니다.
