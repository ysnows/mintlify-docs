이 페이지는 플러그인을 Enconvo 플러그인 스토어에 제출하려는 개발자용입니다. 검토자가 확인하는 것, 버전마다 보낼 검토 자료, `plugin publish` 전에 실행할 점검 목록, 제출 뒤에 일어나는 일을 나열합니다.

Enconvo는 다른 사람이 설치하기 전에 플러그인 스토어에 제출된 모든 버전을 검토합니다. 이 가이드라인은 스토어가 받는 모든 종류의 플러그인에 적용됩니다. Enconvo, Codex, Claude Code, 휴대용 플러그인, 스킬만으로 된 플러그인을 포함합니다. [OpenAI의 플러그인 가이드라인](https://developers.openai.com/apps-sdk/app-submission-guidelines)을 따르므로, 이를 충족하는 플러그인은 OpenAI 플러그인 포털에도 거의 준비된 상태입니다.

## 먼저 플러그인 확인

제출하기 전에 실행합니다.

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate`는 자동으로 확인할 수 있는 것을 잡고, `scan`은 MCP 서버가 있는 플러그인의 도구를 확인합니다. [검증 코드](/extensions/validation-codes)가 보고하는 각 문제를 설명합니다. 검토자는 나머지를 아래에서 설명하는 대로 손으로 확인합니다.

## 목적과 품질

- 플러그인은 Enconvo가 이미 할 수 없는 유용한 일을 하고, 그것을 완전히 합니다. 자리 표시자, 데모 전용, 체험판은 거절됩니다.
- 예측 가능하게 동작합니다. 네트워크 오류, 없는 권한, 잘못된 입력처럼 실패하면, 조용히 실패하지 않고 무슨 일이 있었는지 말합니다.
- 소유하거나 라이선스가 있는 코드, 이름, 아이콘, 콘텐츠만 씁니다. 다른 제품을 사칭하지 않고, Enconvo나 다른 사람이 보증한다고 암시하지 않습니다.

## 이름, 설명, 목록

- **이름과 제목**: 분명하고 구체적입니다. 일반적인 한 단어는 피하고, 회사 이름에 "MCP", "MCP Server", "Plugin"을 붙이지 않습니다.
- **설명**: 플러그인이 하는 일을 정확히 말합니다. 다른 제품과의 비교, 뒷받침할 수 없는 주장, 가격, 할인, 무료 체험 제안은 없습니다.
- **아이콘과 스크린샷**: 아이콘은 최대 5MB의 PNG, JPEG, WebP, GIF입니다. 스크린샷은 최대 8장을 `metadata/` 폴더에 두고 파일 이름 순으로 표시됩니다. 플러그인이 실제로 동작하는 모습을 보여 줍니다.
- **지원**: 연락할 방법을 줍니다. 웹사이트는 `interface.websiteURL`과 `interface.supportURL`, 또는 `homepage`나 `repository`입니다. Claude Code 플러그인은 `supportUrl`과 `documentationUrl`을 대신 쓸 수 있습니다. 스토어 페이지는 설치 전에 이 링크를 보여 줍니다.
- **버전**: 업데이트마다 올립니다. 업데이트가 검토 중인 동안 스토어는 그 이전 버전을 계속 제공합니다. `plugin publish`는 빌드나 업로드 전에 스토어가 릴리스한 버전을 묻고, 더 높지 않으면 다음에 쓸 버전과 함께 멈춥니다.

## MCP 도구

플러그인이 MCP 서버를 가져오면 검토자는 AI 모델이 읽을 것처럼 도구를 읽습니다.

- **이름**은 도구가 하는 일을 말하는 평범한 동사입니다. `get_order_status` 같은 것이며 서버 안에서 고유합니다. 전문 용어나 설명 없는 약어는 없습니다.
- **설명**은 도구가 하는 일, 바꾸는 것, 할 수 없는 것을 설명하고, 입력 스키마와 실제 동작과 맞습니다. 모델에게 이 플러그인을 선호하라고, 다른 플러그인을 호출하라고, 모든 일에 이 도구를 호출하라고 말하지 않습니다.
- **도구당 하나의 작업**이며, 각각 자체 입력 스키마가 있습니다.
- **주석**은 모든 도구에 명시적으로 설정됩니다.

| 주석 | 도구가 이럴 때 `true` | 이럴 때 `false` |
|---|---|---|
| `readOnlyHint` | 읽기, 계산, 미리보기만 함 | 무엇이든 바꿈: 쓰기, 파일 저장, 보내기, 게시, 업로드, 작업 대기, 작업 시작 |
| `destructiveHint` | 되돌릴 수 없는 것을 삭제, 덮어쓰기, 취소, 보냄. 사용자가 실행 취소할 수 있어도 해당 | 추가만 함 |
| `openWorldHint` | 웹 검색처럼 공개되거나 끝이 열린 콘텐츠에 닿거나, 아무 주소로나 보냄 | 다른 곳에 호스팅되어도 한정된 계정, 작업 공간, 카탈로그 안에 머무름 |

Enconvo는 이 주석에 의존합니다. `readOnlyHint: true`로 표시된 도구는 사용자에게 묻지 않고 다른 읽기와 함께 실행됩니다. `destructiveHint: true`로 표시된 도구는 에이전트에 전체 접근을 주지 않았다면 먼저 사용자에게 묻습니다. 무언가를 바꾸면서 읽기 전용이라고 주장하는 도구는 거절됩니다.

`enconvo plugin scan`은 플러그인의 MCP 서버를 시작하고, 주석과 함께 도구를 나열하며, 하나를 뺀 각 도구의 이름을 짓습니다([`annotations_required`](/extensions/validation-codes#mcp-server-scan)).

자체 인터페이스를 보여 주는 도구는 뷰, `ui://` 리소스를 `_meta.ui.resourceUri`에 이름 짓고, 뷰는 `_meta.ui.csp`(`connectDomains`, `resourceDomains`, `frameDomains`)에 닿는 도메인을 선언합니다. 이것은 모든 호스트가 읽는 MCP Apps 키입니다. Enconvo는 ChatGPT의 `_meta["openai/outputTemplate"]`와 `_meta["openai/widgetCSP"]`도 읽고, ChatGPT용으로 쓴 뷰(`text/html+skybridge`, 또는 `openai/outputTemplate`만으로 이름 지은 도구)에 호출하는 `window.openai` API를 주므로, ChatGPT용으로 만든 플러그인은 Enconvo에서 인터페이스를 바꾸지 않고 보여 줍니다. 다른 호스트도 보여 주도록 MCP Apps 키도 설정하세요. `scan`은 Enconvo가 하듯 각 뷰를 읽고, OpenAI 방식으로만 설정된 경우를 말합니다.

## 데이터와 개인정보

- **작업에 필요한 것만 묻습니다.** 도구 입력은 작업에 구체적입니다. 만약을 위해 대화 전체, 이전 메시지, 넓은 프로필 데이터를 묻지 않습니다.
- **요청에 답하는 것만 반환합니다.** 내부 ID, 추적 데이터, 디버그 출력은 도구 결과에 넣지 않습니다.
- 도구 입력을 통해 결제 카드 데이터, 건강 기록, 사회보장번호 같은 정부 ID, 비밀번호, API 키, 일회용 코드를 **절대 수집하지 않습니다.** 인증 정보는 Enconvo가 보관하는 플러그인 환경설정에 둡니다.
- **개인정보 처리방침.** 서버로 데이터를 보내는 플러그인은 무엇을 수집하는지, 왜, 누가 받는지, 얼마나 보관하는지, 사람들이 어떻게 삭제할 수 있는지를 말하는 공개된 개인정보 처리방침이 필요합니다. 주소를 `interface.privacyPolicyURL`에 넣고, 서비스 약관이 있으면 `interface.termsOfServiceURL`에 넣습니다. 스토어 페이지가 둘 다 연결합니다.
- 플러그인이 동작하는 데 필요하고 개인정보 처리방침이 공개한 것을 넘는 사람, 쿼리, 사용 **추적은 없습니다.**
- **패키지에서 비밀을 빼 둡니다.** 누구나 다운로드할 수 있습니다. `.env` 파일은 자동으로 빠지지만, 다른 키나 비공개 파일이 들어가지 않는지 확인합니다.

## 로그인과 테스트 계정

플러그인에 계정이 필요하면 로그인은 명시적이고 필요한 권한만 묻습니다. 검토자는 계정을 만들거나 2단계 코드를 받지 않고 시험해야 하므로, 샘플 데이터가 있는 데모 계정을 줍니다.

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

검토자 메모는 Enconvo 검토자에게만 갑니다. 패키지나 스토어 목록의 일부가 아닙니다.

## 상거래

플러그인은 사람들이 이미 결제하는 계정과 함께 동작할 수 있고, 기능에 다른 플랜이 필요할 때 말할 수 있습니다. 무언가를 팔거나 결제를 받으면 검토 자료(`commerce`와 `commerce_description`, 아래)에 무엇을 파는지, 어디서 결제하는지를 말합니다. 사람들은 본인 사이트에서 결제합니다. 플러그인은 요금을 숨기거나 Enconvo 사용자에게 다른 사람보다 더 받지 않습니다.

OpenAI 포털은 더 엄격합니다. 실물 상품을 파는 플러그인만 받고, 구독, 크레딧, 다른 디지털 상품은 받지 않습니다. 그곳에 제출하기 전에 [상거래 규칙](https://developers.openai.com/apps-sdk/app-submission-guidelines)을 확인하세요.

## 안전

- 플러그인은 십 대를 포함한 일반 이용자에게 적합하고, 13세 미만 아동을 대상으로 하지 않습니다.
- 사용자가 부탁한 일만 하고 그 외는 하지 않습니다. 관련 없는 콘텐츠, 리디렉션, 광고는 없습니다.
- 설명, 프롬프트, 스킬은 비밀을 묻거나, 사용자의 말 없이 돈이나 데이터를 옮기거나, Enconvo의 보호 장치를 덮어쓰려 하거나, 인코딩된 지시를 포함해 플러그인이 하는 일을 숨기지 않습니다.
- 약관에 반해 웹사이트를 긁거나 다른 서비스를 감싸지 않고, 속도 제한과 접근 제어를 우회하지 않습니다.
- 무기, 약물, 도박, 성인 콘텐츠, 악성코드, 금융 사기처럼 OpenAI의 [금지 상품 및 서비스](https://developers.openai.com/apps-sdk/app-submission-guidelines) 목록에 있는 것을 팔거나 가능하게 하지 않습니다.

## 검토 자료

검토 자료는 검토자에게 무엇을 시험할지 말합니다. 플러그인이 처리해야 하는 프롬프트, 그대로 두어야 하는 프롬프트, 짧은 데모 동영상입니다. 각 버전과 함께 저장되고 검토자에게만 보여집니다.

Codex, Claude Code, 휴대용 플러그인에서는 OpenAI 포털이 읽는 곳, 하나의 `plugin.json`의 `extensions["com.openai"]` 아래에 둡니다. OpenAI는 플러그인에 `.codex-plugin/plugin.json`이 있으면 그곳에서 가져옵니다. `enconvo plugin create`가 그렇게 만듭니다. 루트 `plugin.json`이 자체 `extensions["com.openai"]`를 가지거나 Codex 매니페스트가 없으면 루트에서, Claude Code 전용 플러그인이면 `.claude-plugin/plugin.json`에서 가져옵니다. 그것만을 위해 루트 `plugin.json`에 `extensions["com.openai"]`를 추가하지 마세요. 그러면 Codex가 `.codex-plugin/plugin.json`의 목록을 무시합니다. `enconvo plugin validate --openai`가 속해야 하는 매니페스트의 이름을 짓습니다.

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

Enconvo 플러그인에서는 같은 `review` 객체가 `package.json`의 최상위에 갑니다.

| 필드 | 담는 것 |
|---|---|
| `test_cases.positive` | 플러그인이 처리해야 하는 프롬프트입니다. 각각 `description`, `prompt`, `expected_behavior`, `tools_triggered`가 있습니다. 선택: `file_attachment_urls`와 `expected_output_url`입니다. |
| `test_cases.negative` | 플러그인이 다른 것에 맡겨야 하는 프롬프트입니다. 각각 `description`과 `prompt`가 있습니다. |
| `demo_recording_url` | 주요 프롬프트와 도구의 동영상입니다. |
| `commerce`, `commerce_description` | 플러그인이 무언가를 파는지, 무엇을 어디서 파는지입니다. |
| `publication.release_notes` | 바뀐 것입니다. `plugin publish`는 `-m`을 넘기지 않으면 스토어 변경 기록으로 씁니다. |

각 목록은 최대 20개 사례를 담습니다. 텍스트 필드는 최대 4,000자이고, 모든 주소는 검토자가 열 수 있는 `https://` 주소입니다. `validate`와 `publish`는 이 한도를 깨는 자료를 거부합니다.

로그인 세부 정보는 누구나 다운로드할 수 있으므로 패키지에 넣지 않습니다. `validate`와 `publish`는 `test_credentials`나 `reviewer_instructions`가 있는 `review`를 거부합니다. 대신 `--review-notes`로 넘기거나, OpenAI 대시보드의 검토 세부 정보 양식에 넣습니다.

`plugin.json`에서 `publication`은 OpenAI 포털이 목록을 위해 가져오는 것도 담을 수 있고, `validate --openai`가 포털처럼 확인합니다. Enconvo는 설치된 플러그인과 소스에서 설치하기 전에 인터페이스 언어로 `translations`를 보여 줍니다. Enconvo 스토어 페이지는 아직 쓰지 않습니다.

| 필드 | 담는 것 |
|---|---|
| `countries` | 플러그인을 쓸 수 있는 곳입니다. `["US", "GB"]` 같은 대문자 국가 코드입니다. `[]`는 어디서나 쓸 수 있게 합니다. |
| `translations` | 로케일별 목록 텍스트입니다. `{"fr-FR": {"subtitle": "…", "description": "…"}}` 같은 것입니다. 부제는 최대 30자의 한 줄이고, 설명은 최대 4,000자입니다. |

`null`로 설정된 필드는 OpenAI 대시보드에 이미 저장된 값을 유지합니다. 플러그인 수준 테스트 사례는 MCP 서버가 정확히 하나인 플러그인용입니다.

OpenAI의 최종 제출은 MCP 서버나 앱이 있는 플러그인에 긍정 5개와 부정 3개, 데모 녹화, 릴리스 노트를 정확히 요구합니다. 스킬만 있는 플러그인은 릴리스 노트만 필요합니다. `validate --openai`는 빠진 것을 경고로 나열합니다. 포털 업로드는 그것 없이 플러그인을 받고 최종 제출에서만 묻기 때문입니다.

## 제출 점검 목록

`plugin publish`를 실행하기 전에:

- `plugin validate`가 오류를 보고하지 않고, 경고를 읽었습니다.
- `version`이 마지막으로 게시한 버전보다 높고, 패키지의 모든 매니페스트가 같은 이름과 버전을 줍니다.
- 업데이트의 경우, 그 이전 릴리스 zip으로 `plugin validate --previous`가 의도하지 않은 것을 보고하지 않습니다. 업데이트는 플러그인 전체를 바꾸므로, 빠뜨린 스킬이나 MCP 서버는 제거됩니다(`plugin_components_removed`).
- 제목, 설명, 아이콘이 플러그인이 하는 일을 말하고, 스크린샷이 동작하는 모습을 보여 줍니다.
- 홈페이지나 지원 주소가 설정되어 있고, 플러그인이 어디로든 데이터를 보내면 개인정보 처리방침이 연결되어 있습니다.
- 모든 MCP 도구에 분명한 이름과 설명이 있고 `readOnlyHint`, `destructiveHint`, `openWorldHint`를 설정하며, `plugin scan`이 문제 없이 나열합니다.
- 스킬은 `description`에 언제 쓸지 말합니다.
- API 키 같은 필수 설정은 채팅에서 묻지 않고 설정으로 선언됩니다.
- 폴더에 키, 토큰, 비공개 파일이 없습니다.
- 검토 자료가 시험할 프롬프트와 그대로 둘 프롬프트를 나열하고, 로그인이 필요하면 `--review-notes`용 데모 계정이 준비되어 있습니다.
- 폴더에서 패키지를 설치하고(`plugin install .`) Enconvo에서 테스트 사례를 시험했습니다.

## 제출 뒤에 일어나는 일

1. `plugin publish`는 플러그인과 버전이 스토어가 릴리스한 것보다 높은지 확인한 다음 업로드하고 버전을 검토에 제출합니다. 새 플러그인이 승인될 때까지 본인만 볼 수 있습니다.
2. 검토자가 목록, 패키지 파일(릴리스된 버전 이후 바뀐 것 포함), 검토 자료와 메모를 읽고 테스트 사례를 시험합니다.
3. 승인된 버전은 스토어에 나타나고, 설치된 복사본에 업데이트가 제안됩니다. 버전이 거절되면 이유가 담긴 이메일을 받습니다. 고치고, 버전을 올리고, 다시 게시합니다.

Enconvo는 게시된 플러그인에 대한 신고도 살펴봅니다. 이전에 승인된 것을 포함해 이 가이드라인을 어긴 것으로 밝혀진 플러그인은 스토어에서 제거될 수 있고, 개발자에게 이유가 이메일로 갑니다.

## OpenAI에도 제출

같은 폴더를 OpenAI 플러그인 포털로 보낼 수 있습니다.

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai`는 포털이 받는 zip을 씁니다. OpenAI 검토자용 인증 정보는 패키지가 아니라 포털 제출 양식에 둡니다. 본인 키도 빼 두세요. `pack`과 `publish`는 `.env` 파일을 빼고, `validate`는 개인 키나 로그인처럼 보이는 파일에 경고합니다(`archive_member_secret`).

### 플러그인 이름

포털은 플러그인 `name`에 문자, 숫자, `-`, `_`만 받고, OpenAI는 소문자, 숫자, 단일 하이픈을 제안합니다. Codex, Claude Code, Enconvo는 `acme.tools` 같은 점 있는 이름도 설치하지만, `validate --openai`와 `pack --openai`는 거부합니다(`plugin_name_format`). 제출하려는 플러그인은 `acme-tools`로 이름 지으세요.

### MCP 서버와 도메인

업로드 뒤 포털은 플러그인의 MCP 서버에 연결하고 도구를 스캔합니다. 서버가 바뀌면 그곳에서 다시 스캔합니다. 공개 `https://` URL에서만 서버에 닿으므로, 사용자 컴퓨터에서 실행되는 서버는 먼저 배포해야 합니다. `scan --openai`는 그런 서버에 경고합니다(`mcp_server_not_remote`). 최종 제출에서 포털은 모든 도구에 세 주석을 모두 요구합니다. 더 이상 정당화를 묻지 않습니다. 자동 검토가 하나를 표시하면 설명과 함께 이의 제기할 수 있습니다. 뷰가 페이지를 임베드하는 플러그인은 임베드된 페이지마다 정당화가 여전히 필요합니다. 무엇을 하는지, 왜 플러그인이 임베드하는지, 누가 도메인을 통제하는지입니다. MCP 서버 자체의 등록 가능 도메인에서 온 페이지는 허용되고, 공유 호스트의 별도 테넌트는 다른 도메인으로 셉니다. `scan --openai`는 뷰가 임베드하는 도메인을 나열합니다(`frame_domain_explanation_required`).

플러그인을 제출하기 전에 포털은 MCP 서버 도메인을 통제하는지 확인합니다. 서버 호스트나 상위 도메인의 `/.well-known/openai-apps-challenge`에 일반 텍스트로 제공할 토큰을 줍니다. `scan --openai`는 그 URL이 무엇에 답하는지 말하고, `scan --challenge-token <token>`은 **Verify Domain**을 선택하기 전에 하나가 정확히 그 토큰을 제공하는지 확인합니다. [도메인 확인](/extensions/validation-codes#domain-verification)을 보세요.

OpenAI 포털은 스캔과 검토를 위해 플러그인당 MCP 서버 하나만 연결하므로, `validate --openai`는 더 많은 플러그인에 경고합니다. Codex용 `mcp.json`과 Claude Code용 `.mcp.json`에 선언된 같은 서버는 한 번으로 셉니다.

### 게시한 플러그인 업데이트

그곳에 게시한 플러그인을 업데이트하려면 더 높은 버전과 유지하려는 모든 것이 담긴 완전한 ZIP을 업로드합니다. 게시된 버전의 zip을 보관하지 않았다면, 포털이 그 버전의 **…** 메뉴에서 **Download release ZIP**으로 줍니다. `validate --openai --previous <zip>`으로 새 버전을 그것과 대조합니다. 포털은 없던 MCP 서버를 게시된 플러그인에 추가하거나 게시된 서버의 URL을 바꿀 수 없습니다(그것은 OpenAI 지원에 요청). `--previous`가 둘 다 보고합니다. [업데이트](/extensions/validation-codes#updates)를 보세요.

### 최종 제출

OpenAI의 최종 제출은 업로드보다 목록에 더 많이 요구하고, `validate --openai`가 각 빈틈에 경고합니다.

- `interface.longDescription`과 `interface.category`입니다. 없으면 디렉터리가 플러그인을 Other 아래에 둡니다.
- MCP 서버가 있는 플러그인은 `websiteURL`, `supportURL`, `privacyPolicyURL`, `termsOfServiceURL`이 각각 최대 1,024자의 `https://` 주소여야 합니다.
- 본인 목록입니다. `.claude-plugin/plugin.json`만 있는 Claude Code 플러그인은 포털이 기본값으로 채우는 목록을 받습니다(`claude_format_normalized`). 직접 쓰려면 `interface`가 있는 `.codex-plugin/plugin.json`을 추가합니다.
- 스크린샷은 MCP 서버에 자체 인터페이스가 있을 때만입니다. 각 시작 프롬프트마다 PNG 또는 JPEG 하나, 너비 정확히 706픽셀, 높이 400에서 860픽셀입니다. 포털은 스캔으로 결정하므로, 인터페이스를 보여 주는 도구가 없으면 `scan --openai`가 스크린샷을 거부합니다(`screenshots_not_allowed`). OpenAI 디렉터리는 더 이상 스크린샷을 보여 주지 않고 시작 프롬프트로 플러그인을 소개하므로, 그것을 신중히 쓰세요.

디렉터리는 `interface.developerName`이 무엇이든 검증된 OpenAI 신원의 개발자 이름을 보여 줍니다. 코드는 [OpenAI의 최종 제출](/extensions/validation-codes#openais-final-submission)을 보세요.
