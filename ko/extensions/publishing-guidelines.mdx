이 페이지는 Enconvo 플러그인 스토어에 플러그인을 제출하려는 개발자를 위한 문서입니다. 심사자가 확인하는 항목, 버전마다 함께 보낼 심사 자료, `plugin publish` 전에 확인할 체크리스트, 제출 후 진행 과정을 정리했습니다.

Enconvo는 스토어에 제출된 모든 버전을 심사한 뒤에야 다른 사용자가 설치할 수 있게 합니다. 이 가이드라인은 스토어가 받는 모든 종류의 플러그인에 적용됩니다. Enconvo, Codex, Claude Code, 이식형(portable) 플러그인과 스킬만으로 구성된 플러그인이 모두 해당합니다. 가이드라인은 [OpenAI의 플러그인 가이드라인](https://developers.openai.com/apps-sdk/app-submission-guidelines)을 따르므로, 이를 충족하는 플러그인은 OpenAI 플러그인 포털에 제출할 준비도 거의 끝난 상태입니다.

## 먼저 플러그인 점검하기

제출하기 전에 다음을 실행하세요.

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate`는 자동으로 확인할 수 있는 항목을 잡아내고, `scan`은 MCP 서버가 있는 플러그인의 도구를 확인합니다. 두 명령이 보고하는 각 문제는 [검증 코드](/extensions/validation-codes)에서 설명합니다. 나머지는 아래 설명처럼 심사자가 직접 확인합니다.

## 목적과 품질

- 플러그인은 Enconvo가 아직 하지 못하는 유용한 일을 하고, 그 일을 완전하게 해냅니다. 자리 표시용, 데모 전용, 체험판 버전은 반려됩니다.
- 예측 가능하게 동작합니다. 네트워크 오류, 권한 누락, 잘못된 입력 등으로 실패하면 조용히 실패하지 않고 무슨 일이 일어났는지 알려 줍니다.
- 직접 소유했거나 사용 허가를 받은 코드, 이름, 아이콘, 콘텐츠만 사용합니다. 다른 제품을 사칭하지 않고, Enconvo나 다른 누군가가 보증하는 것처럼 보이게 하지 않습니다.

## 이름, 설명, 등록 정보

- **이름과 제목**: 명확하고 구체적이어야 합니다. 일반적인 한 단어는 피하고, 회사 이름에 "MCP", "MCP Server", "Plugin"을 덧붙이지 마세요.
- **설명**: 플러그인이 하는 일을 정확하게 밝힙니다. 다른 제품과의 비교, 뒷받침할 수 없는 주장, 가격·할인·무료 체험 안내는 넣지 않습니다.
- **아이콘과 스크린샷**: 아이콘은 5MB 이하의 PNG, JPEG, WebP 또는 GIF입니다. 스크린샷은 최대 8장까지 `metadata/` 폴더에 넣으며 파일 이름 순서대로 표시됩니다. 스크린샷에는 플러그인이 실제로 동작하는 모습을 담으세요.
- **지원**: 사용자가 연락할 수 있는 방법을 제공하세요. `interface.websiteURL`과 `interface.supportURL`을 쓰거나, 웹사이트는 `homepage` 또는 `repository`로 대신할 수 있습니다. Claude Code 플러그인은 `supportUrl`과 `documentationUrl`을 대신 쓸 수 있습니다. 스토어 페이지는 설치 전에 이 링크를 보여 줍니다.
- **버전**: 업데이트할 때마다 올리세요. 업데이트를 심사하는 동안 스토어는 이전 버전을 계속 제공합니다. `plugin publish`는 빌드하거나 업로드하기 전에 스토어가 릴리스한 버전을 먼저 확인하고, 내 버전이 더 높지 않으면 다음에 쓸 버전을 알려 주며 멈춥니다.

## MCP 도구

플러그인이 MCP 서버를 포함하면, 심사자는 AI 모델이 읽는 방식 그대로 그 도구를 읽습니다.

- **이름**은 `get_order_status`처럼 도구가 하는 일을 말해 주는 평이한 동사형이어야 하며, 서버 안에서 고유해야 합니다. 전문 용어나 설명 없는 약어는 피하세요.
- **설명**은 도구가 무엇을 하고, 무엇을 변경하며, 무엇을 할 수 없는지 밝히고, 입력 스키마와 실제 동작에 맞아야 합니다. 모델에게 이 플러그인을 우선하라거나, 다른 플러그인을 호출하라거나, 모든 일에 이 도구를 호출하라고 지시하면 안 됩니다.
- **도구 하나에 작업 하나**만 두고, 각 도구에 고유한 입력 스키마를 둡니다.
- **어노테이션**은 모든 도구에 명시적으로 설정합니다.

| 어노테이션 | 도구가 다음에 해당하면 `true` | 다음에 해당하면 `false` |
|---|---|---|
| `readOnlyHint` | 읽기, 계산, 미리보기만 하는 경우 | 쓰기, 파일 저장, 전송, 게시, 업로드, 작업 대기열 추가, 작업 시작 등 무언가를 변경하는 경우 |
| `destructiveHint` | 삭제, 덮어쓰기, 취소를 하거나, 사용자가 되돌릴 수 있더라도 되돌릴 수 없는 것을 전송하는 경우 | 추가만 하는 경우 |
| `openWorldHint` | 웹 검색처럼 공개되었거나 범위가 열려 있는 콘텐츠에 접근하거나, 임의의 주소로 전송하는 경우 | 다른 곳에 호스팅되어 있더라도 한정된 계정, 워크스페이스, 카탈로그 안에서만 동작하는 경우 |

Enconvo는 이 어노테이션에 의존합니다. `readOnlyHint: true`로 표시된 도구는 사용자에게 묻지 않고, 다른 읽기 작업과 함께 실행됩니다. `destructiveHint: true`로 표시된 도구는 사용자가 에이전트에게 전체 접근 권한을 주지 않은 한 먼저 사용자에게 묻습니다. 무언가를 변경하면서 읽기 전용이라고 표시한 도구는 반려됩니다.

`enconvo plugin scan`은 플러그인의 MCP 서버를 시작해 도구와 어노테이션을 나열하고, 어노테이션이 빠진 도구를 각각 알려 줍니다([`annotations_required`](/extensions/validation-codes#mcp-server-scan)).

자체 인터페이스를 보여 주는 도구는 `_meta.ui.resourceUri`에 뷰 이름(`ui://` 리소스)을 지정하고, 뷰는 접근하는 도메인을 `_meta.ui.csp`(`connectDomains`, `resourceDomains`, `frameDomains`)에 선언합니다. 이는 모든 호스트가 읽는 MCP Apps 키입니다. Enconvo는 ChatGPT의 `_meta["openai/outputTemplate"]`과 `_meta["openai/widgetCSP"]`도 읽으며, ChatGPT용으로 작성된 뷰(`text/html+skybridge`, 또는 `openai/outputTemplate`으로만 지정된 도구)에는 그 뷰가 호출하는 `window.openai` API를 제공합니다. 그래서 ChatGPT용으로 만든 플러그인도 Enconvo에서 수정 없이 인터페이스가 표시됩니다. 다른 호스트에서도 표시되도록 MCP Apps 키도 함께 설정하세요. `scan`은 Enconvo와 같은 방식으로 각 뷰를 읽고, OpenAI 방식으로만 설정된 뷰가 있으면 알려 줍니다.

## 데이터와 개인정보

- **작업에 필요한 것만 요청하세요.** 도구 입력은 작업에 맞게 구체적이어야 합니다. 대화 전체, 이전 메시지, 광범위한 프로필 데이터를 "혹시 몰라서" 요구하지 마세요.
- **요청에 답이 되는 것만 반환하세요.** 내부 ID, 추적 데이터, 디버깅 출력은 도구 결과에 넣지 마세요.
- **절대 수집하지 마세요.** 도구 입력으로 결제 카드 정보, 건강 기록, 주민등록번호 같은 정부 발급 ID, 비밀번호, API 키, 일회용 코드를 받지 마세요. 자격 증명은 Enconvo가 보관하는 플러그인 설정에 둡니다.
- **개인정보 처리방침.** 서버로 데이터를 보내는 플러그인에는 무엇을 수집하는지, 왜 수집하는지, 누가 받는지, 얼마나 보관하는지, 사용자가 어떻게 삭제할 수 있는지를 밝힌 공개 개인정보 처리방침이 필요합니다. 그 주소는 `interface.privacyPolicyURL`에, 이용 약관이 있다면 `interface.termsOfServiceURL`에 넣으세요. 스토어 페이지가 두 링크를 모두 보여 줍니다.
- **추적 금지.** 플러그인이 동작하는 데 필요한 범위와 개인정보 처리방침에 공개한 범위를 넘어서 사용자, 질의, 사용 현황을 추적하지 마세요.
- **패키지에 비밀 정보를 넣지 마세요.** 누구나 패키지를 내려받을 수 있습니다. `.env` 파일은 자동으로 제외되지만, 다른 키나 비공개 파일이 포함되지 않았는지 확인하세요.

## 로그인과 테스트 계정

플러그인에 계정이 필요하다면 로그인은 명시적으로 이루어져야 하고 필요한 권한만 요청해야 합니다. 심사자는 계정을 만들거나 2단계 인증 코드를 받지 않고도 써 볼 수 있어야 하므로, 샘플 데이터가 들어 있는 데모 계정을 제공하세요.

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

심사 메모는 Enconvo 심사자에게만 전달됩니다. 패키지나 스토어 등록 정보에는 포함되지 않습니다.

## 결제와 판매

플러그인은 사용자가 이미 결제하고 있는 계정과 연동할 수 있고, 특정 기능에 다른 요금제가 필요하다고 안내할 수도 있습니다. 무언가를 판매하거나 결제를 받는다면 심사 자료(아래의 `commerce`와 `commerce_description`)에 무엇을 판매하고 어디서 결제하는지 밝혀야 합니다. 결제는 개발자의 사이트에서 이루어지며, 플러그인은 요금을 숨기거나 Enconvo 사용자에게 다른 사용자보다 더 많이 청구해서는 안 됩니다.

OpenAI 포털은 더 엄격합니다. 실물 상품을 판매하는 플러그인만 받으며, 구독, 크레딧 같은 디지털 상품은 받지 않습니다. 그곳에 제출하기 전에 [결제 규정](https://developers.openai.com/apps-sdk/app-submission-guidelines)을 확인하세요.

## 안전

- 플러그인은 청소년을 포함한 일반 이용자에게 적합해야 하며, 13세 미만 어린이를 대상으로 하지 않습니다.
- 사용자가 요청한 일만 하고 그 외에는 하지 않습니다. 관련 없는 콘텐츠, 리디렉션, 광고는 안 됩니다.
- 설명, 프롬프트, 스킬은 비밀 정보를 요구하거나, 사용자 동의 없이 돈이나 데이터를 옮기거나, Enconvo의 안전장치를 우회하려 하거나, 인코딩된 지시를 포함해 플러그인이 하는 일을 숨겨서는 안 됩니다.
- 이용 약관을 어기며 웹사이트를 스크래핑하거나 다른 서비스를 래핑하지 않으며, 속도 제한이나 접근 제어를 우회하지 않습니다.
- 무기, 마약, 도박, 성인 콘텐츠, 악성코드, 금융 사기 등 OpenAI의 [금지 상품 및 서비스](https://developers.openai.com/apps-sdk/app-submission-guidelines) 목록에 있는 것을 판매하거나 가능하게 하지 않습니다.

## 심사 자료

심사 자료는 심사자에게 무엇을 시험해 볼지 알려 줍니다. 플러그인이 처리해야 하는 프롬프트, 건드리지 말아야 하는 프롬프트, 짧은 데모 영상이 해당합니다. 심사 자료는 버전마다 저장되며 심사자에게만 보입니다.

Codex, Claude Code 또는 이식형 플러그인에서는 OpenAI 포털이 읽는 위치, 즉 `plugin.json` 하나의 `extensions["com.openai"]` 아래에 둡니다. OpenAI는 플러그인에 `.codex-plugin/plugin.json`이 있으면(`enconvo plugin create`가 만드는 방식) 그 파일에서, 루트 `plugin.json`에 자체 `extensions["com.openai"]`가 있거나 Codex 매니페스트가 없으면 루트 `plugin.json`에서, Claude Code 전용 플러그인이면 `.claude-plugin/plugin.json`에서 가져옵니다. 심사 자료만을 위해 루트 `plugin.json`에 `extensions["com.openai"]`를 추가하지 마세요. 그러면 Codex가 `.codex-plugin/plugin.json`의 등록 정보를 무시합니다. `enconvo plugin validate --openai`가 자료를 넣어야 할 매니페스트를 알려 줍니다.

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

Enconvo 플러그인에서는 같은 `review` 객체를 `package.json`의 최상위에 둡니다.

| 필드 | 담는 내용 |
|---|---|
| `test_cases.positive` | 플러그인이 처리해야 하는 프롬프트입니다. 각 항목에 `description`, `prompt`, `expected_behavior`, `tools_triggered`를 넣습니다. 선택 항목으로 `file_attachment_urls`와 `expected_output_url`이 있습니다. |
| `test_cases.negative` | 플러그인이 다른 것에 맡겨야 하는 프롬프트입니다. 각 항목에 `description`과 `prompt`를 넣습니다. |
| `demo_recording_url` | 주요 프롬프트와 도구를 보여 주는 영상입니다. |
| `commerce`, `commerce_description` | 플러그인이 무언가를 판매하는지, 무엇을 어디서 판매하는지입니다. |
| `publication.release_notes` | 변경된 내용입니다. `-m`을 지정하지 않으면 `plugin publish`가 이를 스토어의 변경 내역으로 사용합니다. |

각 목록에는 최대 20개의 사례를 넣을 수 있습니다. 텍스트 필드는 최대 4,000자이고, 모든 주소는 심사자가 열 수 있는 `https://` 주소여야 합니다. 이 제한을 어기는 자료는 `validate`와 `publish`가 거부합니다.

로그인 정보는 패키지에 절대 넣지 마세요. 누구나 패키지를 내려받을 수 있기 때문입니다. `test_credentials` 또는 `reviewer_instructions`가 들어 있는 `review`는 `validate`와 `publish`가 거부합니다. 대신 `--review-notes`로 전달하거나 OpenAI 대시보드의 Review details 양식에 입력하세요.

`plugin.json`의 `publication`에는 OpenAI 포털이 등록 정보용으로 가져오는 항목도 넣을 수 있으며, `validate --openai`가 포털과 같은 방식으로 확인합니다. Enconvo는 설치된 플러그인과 소스에서 설치하기 전의 플러그인에 대해 `translations`를 인터페이스 언어로 보여 줍니다. Enconvo 스토어 페이지는 아직 이를 사용하지 않습니다.

| 필드 | 담는 내용 |
|---|---|
| `countries` | 플러그인을 사용할 수 있는 국가를 `["US", "GB"]`처럼 대문자 국가 코드로 나타냅니다. `[]`이면 모든 곳에서 사용할 수 있습니다. |
| `translations` | `{"fr-FR": {"subtitle": "…", "description": "…"}}`처럼 로케일별 등록 정보 텍스트입니다. 부제목은 30자 이하의 한 줄, 설명은 4,000자 이하입니다. |

`null`로 설정한 필드는 OpenAI 대시보드에 이미 저장된 값을 유지합니다. 플러그인 수준의 테스트 사례는 MCP 서버가 정확히 하나인 플러그인용입니다.

MCP 서버나 앱이 있는 플러그인을 OpenAI에 최종 제출하려면 긍정 사례 5개와 부정 사례 3개, 데모 영상, 릴리스 노트가 정확히 필요합니다. 스킬만 있는 플러그인은 릴리스 노트만 있으면 됩니다. 포털의 업로드는 이런 자료가 없어도 플러그인을 받고 최종 제출 때에만 요구하므로, `validate --openai`는 빠진 항목을 경고로 나열합니다.

## 제출 체크리스트

`plugin publish`를 실행하기 전에 확인하세요.

- `plugin validate`에 오류가 없고 경고를 모두 읽었습니다.
- `version`이 마지막으로 게시한 버전보다 높고, 패키지의 모든 매니페스트가 같은 이름과 버전을 가리킵니다.
- 업데이트라면 이전 릴리스의 zip과 함께 `plugin validate --previous`를 실행해 의도하지 않은 결과가 없는지 확인했습니다. 업데이트는 플러그인 전체를 교체하므로, 빠뜨린 스킬이나 MCP 서버는 제거됩니다(`plugin_components_removed`).
- 제목, 설명, 아이콘이 플러그인이 하는 일을 나타내고, 스크린샷이 실제 동작을 보여 줍니다.
- 홈페이지 또는 지원 주소가 설정되어 있고, 플러그인이 어디로든 데이터를 보낸다면 개인정보 처리방침이 연결되어 있습니다.
- 모든 MCP 도구에 명확한 이름과 설명이 있고 `readOnlyHint`, `destructiveHint`, `openWorldHint`가 설정되어 있으며, `plugin scan`이 문제 없이 나열합니다.
- 스킬은 `description`에 언제 사용하는지 밝힙니다.
- API 키 같은 필수 설정은 대화에서 요청하지 않고 설정으로 선언합니다.
- 폴더에 키, 토큰, 비공개 파일이 없습니다.
- 심사 자료에 시험할 프롬프트와 건드리지 말아야 할 프롬프트가 나열되어 있고, 로그인이 필요하면 `--review-notes`용 데모 계정이 준비되어 있습니다.
- 폴더에서 패키지를 설치(`plugin install .`)하고 Enconvo에서 테스트 사례를 직접 시험했습니다.

## 제출 후 진행 과정

1. `plugin publish`는 플러그인과, 그 버전이 스토어가 릴리스한 버전보다 높은지를 확인한 다음 업로드하고 심사를 위해 해당 버전을 제출합니다. 새 플러그인이 승인되기 전까지는 본인만 볼 수 있습니다.
2. 심사자는 등록 정보, 패키지의 파일(릴리스된 버전 이후의 변경 사항 포함), 심사 자료, 메모를 읽고 테스트 사례를 시험합니다.
3. 승인된 버전은 스토어에 표시되고, 설치된 사본에는 업데이트가 제공됩니다. 버전이 반려되면 사유가 담긴 이메일을 받습니다. 문제를 고치고 버전을 올린 뒤 다시 게시하세요.

Enconvo는 게시된 플러그인에 대한 신고도 조사합니다. 이전에 승인된 플러그인이라도 이 가이드라인을 어긴 것으로 확인되면 스토어에서 제거될 수 있으며, 개발자에게 사유가 이메일로 전달됩니다.

## OpenAI에도 제출하기

같은 폴더를 OpenAI 플러그인 포털에도 제출할 수 있습니다.

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai`는 포털이 받는 zip을 만듭니다. OpenAI 심사자를 위한 자격 증명은 패키지가 아니라 포털의 제출 양식에 입력하세요. 개인 키도 패키지에 넣지 않도록 주의하세요. `pack`과 `publish`는 `.env` 파일을 제외하며, `validate`는 개인 키나 로그인 정보처럼 보이는 파일을 경고합니다(`archive_member_secret`).

### 플러그인 이름

포털은 플러그인 `name`에 영문자, 숫자, `-`, `_`만 허용하며, OpenAI는 소문자, 숫자, 단일 하이픈을 권장합니다. Codex, Claude Code, Enconvo는 `acme.tools`처럼 점이 들어간 이름도 설치하지만, `validate --openai`와 `pack --openai`는 이를 거부하므로(`plugin_name_format`) 제출할 플러그인은 `acme-tools`처럼 이름을 지으세요.

### MCP 서버와 도메인

업로드 후 포털은 플러그인의 MCP 서버에 연결해 도구를 스캔하며, 서버가 바뀌면 포털에서 다시 스캔하세요. 포털은 공개 `https://` URL의 서버에만 접근할 수 있으므로 사용자 컴퓨터에서 실행되는 서버는 먼저 배포해야 하며, `scan --openai`가 이런 서버를 경고합니다(`mcp_server_not_remote`). 최종 제출 시 포털은 모든 도구에 세 가지 어노테이션을 모두 요구합니다. 더 이상 어노테이션의 근거를 요구하지는 않으며, 자동 심사에서 어노테이션이 지적되면 설명을 달아 이의를 제기할 수 있습니다. 뷰에 페이지를 임베드하는 플러그인은 임베드하는 각 페이지에 대해 그 페이지가 하는 일, 플러그인이 임베드하는 이유, 해당 도메인을 관리하는 주체를 여전히 설명해야 합니다. MCP 서버 자체의 등록 가능 도메인에 속한 페이지는 허용되며, 공유 호스트의 서로 다른 테넌트는 서로 다른 도메인으로 간주됩니다. `scan --openai`는 뷰가 임베드하는 도메인을 나열합니다(`frame_domain_explanation_required`).

플러그인을 제출하려면 먼저 포털이 MCP 서버 도메인을 직접 관리하는지 확인합니다. 포털이 토큰을 주면, 서버 호스트 또는 상위 도메인의 `/.well-known/openai-apps-challenge`에서 일반 텍스트로 제공해야 합니다. `scan --openai`는 해당 URL들이 무엇을 응답하는지 알려 주고, `scan --challenge-token <token>`은 그 URL이 토큰을 정확히 제공하는지 확인합니다. 그런 다음 **Verify Domain**을 선택하세요. [도메인 확인](/extensions/validation-codes#domain-verification)을 참고하세요.

OpenAI 포털은 플러그인당 MCP 서버 하나만 연결해 스캔하고 심사하므로, 서버가 더 많은 플러그인은 `validate --openai`가 경고합니다. Codex용 `mcp.json`과 Claude Code용 `.mcp.json`에 선언된 같은 서버는 하나로 계산됩니다.

### 게시된 플러그인 업데이트

그곳에 게시한 플러그인을 업데이트하려면 더 높은 버전과 유지하려는 모든 것이 담긴 전체 ZIP을 업로드하세요. 게시된 버전의 zip을 보관하지 않았다면, 포털의 해당 버전 **…** 메뉴에 있는 **Download release ZIP**으로 받을 수 있습니다. 새 버전은 `validate --openai --previous <zip>`으로 대조해 확인하세요. 포털은 MCP 서버가 없던 게시된 플러그인에 MCP 서버를 추가하거나 게시된 서버의 URL을 바꿀 수 없으며(OpenAI 지원팀에 문의하세요), `--previous`가 두 경우를 모두 알려 줍니다. [업데이트](/extensions/validation-codes#updates)를 참고하세요.

### 최종 제출

OpenAI의 최종 제출은 업로드보다 등록 정보에 더 많은 것을 요구하며, `validate --openai`가 부족한 부분마다 경고합니다.

- `interface.longDescription`과 `interface.category`가 필요합니다. 카테고리가 없으면 디렉터리는 플러그인을 기타(Other)로 분류합니다.
- MCP 서버가 있는 플러그인은 `websiteURL`, `supportURL`, `privacyPolicyURL`, `termsOfServiceURL`이 필요하며, 각각 1,024자 이하의 `https://` 주소여야 합니다.
- 직접 작성한 등록 정보가 필요합니다. `.claude-plugin/plugin.json`만 있는 Claude Code 플러그인은 포털이 기본값으로 채운 등록 정보를 받으므로(`claude_format_normalized`), 직접 작성하려면 `interface`가 있는 `.codex-plugin/plugin.json`을 추가하세요.
- 스크린샷은 MCP 서버에 자체 인터페이스가 있을 때만 넣습니다. 시작 프롬프트마다 PNG 또는 JPEG 한 장이며, 폭은 정확히 706픽셀, 높이는 400~860픽셀이어야 합니다. 포털은 스캔 결과로 판단하므로, 인터페이스를 보여 주는 도구가 없으면 `scan --openai`가 스크린샷을 거부합니다(`screenshots_not_allowed`). OpenAI 디렉터리는 더 이상 스크린샷을 보여 주지 않고 시작 프롬프트로 플러그인을 소개하므로, 시작 프롬프트를 신경 써서 작성하세요.

디렉터리에는 `interface.developerName`에 무엇을 적었든 인증된 OpenAI 신원의 개발자 이름이 표시됩니다. 코드는 [OpenAI 최종 제출](/extensions/validation-codes#openai’s-final-submission)을 참고하세요.
