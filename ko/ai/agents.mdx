에이전트는 한 종류의 작업을 위한 지침, 모델, 도구를 하나로 묶은 것입니다. 같은 지침을 계속 주고 있거나, 작업에 특정한 도구 모음이 필요할 때 에이전트를 만드세요. 에이전트는 **설정 → 에이전트 목록**에서 관리합니다.

아래 동영상은 2분 이내로 에이전트 목록을 안내합니다. Mavis와 기본 제공 에이전트, 코딩 에이전트, 에이전트의 구성 요소, 나만의 에이전트 만들기를 다룹니다.

## 처음부터 제공되는 에이전트

**Mavis**는 기본 에이전트입니다. 답변할 뿐 아니라 앱을 사용하고, 웹을 탐색하고, 파일을 다룰 수도 있습니다. 기본 제공 에이전트는 각각 하나의 일을 위해 만들어졌습니다. **작가**, **플래너**, **검토자**, **어드바이저**, **리서처**, **디자이너**, **코더**입니다. **Claude Code**, **Codex**, **Grok Build**, **Antigravity**, **Muse Code**는 설치된 코딩 에이전트와 프로젝트 폴더에서 작업하며 채팅하고, **Grok Bot**은 클라우드의 xAI 에이전트와 채팅합니다. [코딩 에이전트](/ko/ai/coding-agents)를 참고하세요.

아무 채팅의 상단에 있는 에이전트 메뉴나 채팅 창 입력란 위의 카드에서 에이전트를 선택합니다. 에이전트 목록에는 가장 최근에 채팅한 에이전트가 맨 위에 표시됩니다.

## 에이전트의 구성 요소

**설정 → 에이전트 목록**에서 에이전트를 클릭하면 해당 페이지가 열립니다. 왼쪽의 섹션을 누르면 각 부분으로 이동합니다.

| 섹션 | 설정하는 내용 |
| --- | --- |
| **지침** | 모든 대화 전에 에이전트에게 전달되는 내용입니다. 변경 사항은 입력하는 대로 저장됩니다. |
| **스타일** | **응답 스타일**과 **인텔리전트 UI** 수준, 즉 차트, 표, 카드로 얼마나 적극적으로 답할지입니다. [스타일 설정](#스타일-설정)을 참고하세요. |
| **모델** | 에이전트가 글을 쓰는 AI 모델입니다. 에이전트마다 다른 모델을 사용할 수 있습니다. |
| **도구 및 스킬** | 사용할 수 있는 것과 나머지를 찾는 방식, 그리고 스킬 폴더와 전문 스킬 및 작업 중인 파일이 있는 **작업 폴더**입니다. [도구와 스킬 선택](#도구와-스킬-선택)을 참고하세요. |
| **지식** | 어떤 지식 베이스를 어떤 순서로 찾아볼지, 그리고 지식 베이스에 답이 없을 때 웹을 검색할지 여부입니다. [지식 베이스 선택](#지식-베이스-선택)을 참고하세요. |
| **메모리** | 어떤 메모리를 읽을지, 새로운 것을 기억할지 여부입니다. |
| **음성** | 답변을 소리 내어 읽어 주는 음성입니다. |
| **동작** | 무엇을 보고, 어떻게 실행하고, 어떻게 답하는지로, **응답 언어**와 **Cloud 포인트 실행 한도** 등이 있습니다. |
| **사용처** | 채팅 외에 이 에이전트를 시작하는 것과 **링크, CLI 및 API** 행입니다. |

## 에이전트 만들기

1. **설정 → 에이전트 목록**에서 **새 에이전트 만들기**를 클릭하거나, SmartBar에서 **에이전트 만들기**를 실행합니다.
2. **제목**을 입력하고, 원하면 **아바타**와 용도를 설명하는 **설명**을 입력합니다.
3. **에이전트 지침**에 무엇을 해야 하는지, 어떤 입력이 필요한지, 결과를 어떻게 보여 줘야 하는지 설명합니다.
4. **무엇을 사용할 수 있나요?**에서 프리셋으로 시작합니다. **일상용**(모든 기본 제공 도구), **코딩**, **리서치**, **글쓰기**입니다. 나중에 **도구 및 스킬**에서 변경할 수 있습니다.
5. 모델을 선택합니다. **추천 모델**에서 Enconvo가 설명을 읽고 Enconvo Cloud 모델을 제안하며, 옆에 더 저렴한 모델과 더 강력한 모델도 함께 보여 줍니다. **이것 사용**을 클릭하거나 다른 모델 중에서 선택하세요. [추천 사용하기](/ko/ai/model-selection-guide)를 참고하세요.
6. **봇 만들기**를 클릭합니다. 그런 다음 에이전트를 열어 스킬과 지식을 선택합니다.
7. 에이전트와 새 채팅을 시작하고 작고 전형적인 작업을 테스트합니다.

아바타를 업로드하는 대신 직접 그리려면, 여기서 또는 나중에 에이전트 설정에서 아바타 선택기의 **생성** 탭을 여세요. 스타일(**플랫**, **3D**, **애니메**, **사진**, **선**, **수채화**)을 선택하고 **생성**을 클릭하면 이미지 모델이 에이전트의 이름과 설명으로 아바타 네 개를 그립니다. 세부 사항을 추가하고 다시 그리거나, 원하는 것을 클릭하세요. **생성**을 클릭하기 전에는 아무것도 그려지지 않습니다.

지침 예시:

```text
Help me turn meeting notes into actionable follow-ups.
Separate decisions, open questions, and action items.
For action items, preserve the owner and due date if stated;
otherwise mark them as unspecified.
```

## 스타일 설정

**스타일**에서 두 가지 설정이 에이전트의 답변이 읽히는 방식을 결정합니다. 채팅에서는 **+** 메뉴의 **스타일 사용**에서 해당 채팅만의 다른 스타일을 선택할 수 있습니다.

**응답 스타일**은 어조, 길이, 형식을 정합니다. **보통**, **간결하게**, **설명형**, **격식체** 또는 직접 만든 스타일입니다. **새 스타일**을 클릭하면 설명이나 직접 쓴 글 샘플로 스타일을 만들 수 있고, **관리**에서 내 스타일을 편집합니다.

**인텔리전트 UI**는 요청하지 않아도 차트, 표, 카드로 얼마나 적극적으로 답할지 정합니다.

| 수준 | 기능 |
| --- | --- |
| **선별** | 데이터, 비교, 계획을 그려서 보여 줍니다. 요약과 설명은 텍스트로 유지합니다. |
| **적극적**(기본값) | 설명 중에도 차트, 표, 카드가 더 읽기 좋을 때마다 추가합니다. |
| **시각 우선** | 시각 자료로 시작하며 한 번의 답변에 여러 개를 사용할 수 있습니다. 답변에 시간이 조금 더 걸립니다. |

시각 자료가 많을수록 시간이 더 걸리고 포인트가 더 많이 사용됩니다. 메신저 채널과 음성 답변은 텍스트로 유지됩니다.

## 도구와 스킬 선택

**도구 및 스킬**에서 에이전트가 사용할 것을 찾는 방식을 선택합니다.

- **자동 검색**(권장)은 필수 항목으로 시작하고, 작업에 필요할 때 설치된 스킬, 플러그인, Connector, MCP 서버를 찾습니다. 의미로 일치시키므로 도구 설명과 표현이 다르거나 다른 언어로 쓴 요청도 찾아냅니다.
- **내가 고른 것만**은 에이전트에게 고정된 세트를 제공합니다. 사용할 수 있는 기본 제공 도구, 스킬, MCP 서버를 선택하세요. 작업에 다른 것이 필요하면 검색하는 대신 무엇이 없는지 알려 줍니다.

**자동 검색**에서도 이 에이전트가 절대 건드리지 말아야 할 **기본 제공 도구**를 끌 수 있고, **고정된 스킬**에서 스킬을 고정하여 모든 채팅에 나열되게 할 수 있으며, **Enconvo Store의 플러그인 제안**을 꺼서 설치할 플러그인을 제안하지 않게 할 수 있습니다. **스킬 폴더**에서는 이 에이전트에 대해 개별 스킬을 끌 수 있습니다.

에이전트에게는 작업에 필요한 도구만 제공하세요.

| 필요한 것 | 기능 |
| --- | --- |
| 문서 읽기 및 편집 | [파일 도구](/ko/ai/file-tools) |
| 최신 정보 찾기 | [웹 검색](/ko/ai/web-search)과 [웹페이지 가져오기](/ko/ai/web-fetch) |
| 웹사이트에서 작업 | [브라우저 사용](/ko/features/browser-control) |
| 데스크톱 앱 조작 | [컴퓨터 사용](/ko/features/computer-use) |
| 내 자료 검색 | [지식 베이스](/ko/ai/knowledge-base) |
| 절차 재사용 | [스킬](/ko/configuration/skills) |
| 외부 서비스 연결 | [MCP 서버](/ko/features/mcp) |
| 코드 실행 | [코드 실행기](/ko/ai/code-runner) |
| 한 번에 여러 도구 호출 | [코드 모드](/ko/configuration/code-mode) |

모델은 선택한 도구와 입력 유형을 지원해야 합니다. 도구에는 각각의 자격 증명, 액세스 권한, 설정도 필요하며, 지침으로 에이전트에게 없는 권한을 부여할 수는 없습니다.

## 지식 베이스 선택

**지식**에서 에이전트가 찾아볼 위치를 선택합니다.

| 옵션 | 기능 |
| --- | --- |
| **모든 지식 베이스** | 질문에 필요할 때 내 지식 베이스 중 어디든 찾아봅니다. |
| **선택한 것 먼저** | 추가한 지식 베이스를 먼저 찾아보고, 거기에 없으면 나머지를 찾아봅니다. |
| **선택한 것만** | 추가한 지식 베이스만 찾아봅니다. 다른 것은 `@`로 언급할 때만 열립니다. |

**지식 베이스 추가**를 클릭하여 선택하고, 찾아볼 순서대로 끌어서 정렬합니다.

## 작업 승인

실행 모드 옆의 **권한** 칩은 에이전트가 행동하기 전에 멈추고 물어볼 시점을 정합니다. 채팅 창, SmartBar, 앱 사이드바, Dynamic Island의 에이전트 모드에 나타납니다. 모두 해당 에이전트의 같은 설정을 변경하므로 한 곳에서 바꾸면 다른 곳에도 반영됩니다.

| 모드 | 묻는 시점 |
| --- | --- |
| **승인 요청** | 명령 실행, 작업 폴더 밖의 파일 편집, 앱, 브라우저, 온라인 서비스에서의 작업 전 |
| **대신 승인**(기본값) | 파일 삭제, 메시지 전송, 게시, 결제처럼 잠재적으로 안전하지 않아 보이는 작업만 |
| **전체 접근** | 묻지 않음. 에이전트가 묻지 않고 행동합니다 |

파일 읽기, 검색, 화면 보기는 묻지 않습니다. **대신 승인**은 자신에게만 `PATH`를 설정하는 명령이나 임시 폴더 아래에 직접 만든 것을 삭제하는 명령도 묻지 않으며, 그 외의 삭제는 계속 묻습니다.

에이전트가 다른 에이전트나 코딩 에이전트에게 작업을 넘기면, 호출된 쪽은 사용자가 채팅하는 에이전트와 같은 모드로 작업합니다. 각 승인 카드에는 어떤 설정 때문에 물었는지 표시됩니다. 예: "이 프로젝트가 대신 승인으로 설정되어 있어 물었습니다." 명령이 실행된 이후 제한되는 내용은 [에이전트 샌드박스](/ko/configuration/sandbox)를 참고하세요.

### 질문이 나타나는 위치

질문은 채팅이 실행되는 창에 나타납니다. 그 창에 채팅이 표시되지 않으면(예: 숨겨져 있거나 인라인 패널인 경우) 질문이 Dynamic Island로 이동합니다. 그곳에서 30초 안에 아무도 답하지 않으면, 채팅 창이 사용 중인 앱 뒤에 여전히 열려 있더라도 페어링된 iPhone에 알림이 전송됩니다.

답하지 않고 아일랜드의 카드를 닫았다면, 아일랜드 채팅에서 대기 중인 단계를 클릭하여 선택지를 다시 확인하세요. 에이전트가 사용자에게 하는 질문도 같은 방식으로 작동합니다.

### 답하기

- **예, 한 번 허용**은 이 작업 하나만 실행하게 합니다.
- **예, 다시 묻지 않기**는 해당 채팅의 나머지 동안 허용하며, Enconvo를 다시 시작해도 기억됩니다.
- 또는 에이전트가 대신 해야 할 일을 직접 입력합니다.

채팅이 대기 중일 때는 채팅 창의 목록, SmartBar의 최근 채팅, Dynamic Island에서 실행 중 대신 **승인 대기 중**이라고 표시됩니다. iPhone 앱의 채팅 목록에는 **승인 필요**로 표시됩니다.

하위 에이전트는 상위 채팅에서 묻고, 질문에는 하위 에이전트가 묻고 있다는 사실과 어떤 작업 중인지 표시됩니다. 예약된 작업, 워크플로, 메신저 채널은 답할 사람이 창 앞에 없으므로 묻지 않고 실행됩니다.

## 하위 에이전트

에이전트 모드에서 에이전트는 작업을 여러 부분으로 나누어 각각 자체 대화에서 동시에 작업하는 하위 에이전트를 최대 여섯 개까지 시작할 수 있습니다. 하위 에이전트가 결과를 보고하면 에이전트가 답합니다. 여러 개의 독립적인 검색처럼 나누는 것이 분명히 도움이 될 때나 사용자가 요청할 때만 이렇게 합니다. 속도 제한 같은 AI 오류로 하위 에이전트가 중간에 멈추더라도, 에이전트는 그때까지 찾은 내용을 받으며 오류가 해소되면 계속하게 할 수 있습니다.

하위 에이전트를 시작할 때 에이전트는 고유한 모델, 추론 강도, 지침, 이름을 지정하거나 현재 대화를 포크하여 넘길 수 있습니다. 에이전트가 직접 모델을 고르는 경우, 빠른 조회, 읽기, 단순 반복 작업은 제공업체의 소형 모델에서 실행되고, 더 어려운 추론에는 더 높은 강도가 적용되며, 나머지는 사용자가 선택한 모델을 유지합니다. 하위 에이전트도 자체 하위 에이전트를 시작할 수 있으며 최대 3단계까지입니다.

- **하위 에이전트로서의 코딩 에이전트.** Claude Code, Codex, Antigravity, Grok Build, Muse Code가 하위 에이전트로 작업할 수 있습니다. 카드에는 코딩 에이전트의 아이콘, 작업 위치, 사용한 도구 호출, 시간, 토큰이 표시됩니다.
- **별도의 워크트리.** 다른 하위 에이전트가 파일을 변경하는 동안 파일을 변경하는 하위 에이전트는 자체 git 워크트리를 받으므로 두 하위 에이전트가 서로의 작업을 덮어쓰지 않습니다. 변경 사항이 없는 워크트리는 하위 에이전트가 끝나면 제거됩니다. 디자인, 문서, 슬라이드, 리서치, 검토만 만드는 하위 에이전트는 워크트리 없이 작업하므로 여러 개를 시작해도 프로젝트가 각각 복사되지 않습니다.
- **다른 컴퓨터.** 에이전트는 페어링된 다른 컴퓨터에서 하위 에이전트를 실행하여, 해당 컴퓨터의 에이전트나 코딩 에이전트에게 작업을 넘길 수 있습니다. [다른 컴퓨터](/ko/integrations/other-computers)를 참고하세요.
- **방향 조정.** 에이전트는 실행 중인 하위 에이전트의 작업에 메시지를 추가하거나, 중단시키거나, 같은 프로젝트에 있는 다른 에이전트의 채팅에 접근할 수 있습니다. 채팅을 중지하면 그 아래의 모든 하위 에이전트가 중지됩니다.
- **파이프라인.** 에이전트는 파일 목록에 대한 동일한 검사처럼 계획된 하위 에이전트 세트를 한 번에 실행할 수 있습니다. 실패한 실행은 이미 끝난 하위 에이전트를 다시 실행하지 않고 이어서 진행됩니다.

### 병렬 채팅

에이전트에게 별도의 작업을 위한 새 채팅을 열어 달라고 요청하면, 요청한 추론 강도로 채팅을 하나 열며, 이 채팅은 사용자가 시작한 채팅처럼 Mac, iPhone, Android의 채팅 목록에 표시됩니다. 상단의 메모에 어떤 채팅이 이 채팅을 시작했는지 표시됩니다. 해당 작업의 검토와 테스트는 계속 하위 에이전트로 실행됩니다. 에이전트가 스스로 시작한 채팅은 카드에서 내 채팅 목록으로 옮길 수 있습니다.

### 하위 에이전트 확인 및 대화

채팅의 카드에는 각 하위 에이전트가 작업별로 나열되며, 실행 중인지, 사용자의 승인을 기다리는지, 완료되었는지, 실패했는지 보여 주는 아이콘이 표시됩니다. 실행 중인 하위 에이전트의 행에는 지금 하고 있는 일과 실행 중인 모델 및 강도도 표시됩니다. 새 하위 에이전트는 카드가 나타나는 즉시 메시지 입력란 위의 백그라운드 트레이에도 표시됩니다.

하위 에이전트가 만드는 디자인이나 문서 같은 결과물은 만들어지는 대로 행 아래에 표시됩니다. 클릭하면 채팅 옆에서 열리며, 에이전트는 답변의 카드로 이를 전달합니다.

- 행을 클릭하면 해당 하위 에이전트의 대화가 열립니다. 작업 공간 패널과 `@` 파일 검색에는 이 하위 에이전트를 시작한 채팅의 작업 폴더가 표시됩니다. SmartBar와 Dynamic Island에서는 작업이 그 자리에서 열립니다.
- 하위 에이전트의 대화에 입력하면 대화할 수 있습니다. 그곳에서 답하고, 질문할 수 있으며, 해당 대화에서 승인을 요청하고, 같은 폴더에서 계속 작업합니다. 이를 시작한 에이전트는 하위 에이전트가 사용자에게 답하는 동안 기다렸다가 가장 최근의 답변을 확인합니다. 이미 끝난 하위 에이전트에게 메시지를 보내면, 같은 폴더에서 다른 하위 에이전트가 파일을 변경하는 중이라도 즉시 다시 시작됩니다.
- 하위 에이전트의 대화에서는 각 메시지에 보낸 에이전트가 표시됩니다. 상위 에이전트의 메시지에는 실행 중인 작업의 방향을 조정했는지, 기다렸는지, 중단시켰는지, 새 턴을 시작했는지가 표시됩니다.
- 채팅의 세부 정보에 있는 **계보**는 3단계 깊이까지 하위 에이전트의 전체 트리를 보여 줍니다. 코딩 에이전트의 채팅에서는 이를 시작한 Enconvo 채팅을 보여 줍니다.
- 채팅 창 사이드바에서는 채팅의 하위 에이전트가 그 아래에 나열되며, 채팅 행의 버튼으로 목록을 접을 수 있습니다.

### 하위 에이전트 역할

모든 하위 에이전트는 역할로 시작합니다.

| 역할 | 기능 |
| --- | --- |
| **기본값** | 이를 시작한 에이전트로서, 같은 지침, 도구, 모델로 작업합니다 |
| **탐색자** | 파일 읽기, 검색, 앱 보기만 합니다. 권한 칩의 설정과 관계없이 편집하거나, 무언가를 변경하는 명령을 실행하거나, 온라인에서 행동할 수 없습니다 |
| **내 에이전트 중 하나** | 해당 에이전트로서 자체 지침, 도구, 모델로 이를 시작한 채팅과 같은 작업 폴더에서 실행됩니다 |
| **프로젝트 도우미** | 작업 폴더 또는 저장소 루트까지의 상위 폴더에 있는 `.claude/agents`, `.codex/agents`, `.enconvo/agents`에서 프로젝트가 정의합니다. 이를 시작한 에이전트로서 도우미 자체의 지침에 따라 작업합니다. 파일에 나열된 도구만 사용하고, 파일에서 지정한 경우 읽기만 하며, 모델 제공업체가 지원하면 도우미의 모델을 사용합니다 |
| **내 도우미** | 홈 폴더의 `~/.enconvo/agents`, `~/.claude/agents`, `~/.codex/agents`에서 정의하며 모든 채팅에서 사용할 수 있습니다. 프로젝트 도우미와 같은 방식으로 작동합니다 |

직접 선택하려면 에이전트 모드 채팅에서 `@`를 입력하고 **하위 에이전트** 그룹에서 선택하세요. 이 그룹에는 도우미, **탐색자**, 일반 **하위 에이전트**가 나열됩니다. 에이전트는 메시지에 대해 해당 하위 에이전트를 시작하고, 작업을 작성해 주며, 결과를 보고받으면 답합니다. 내 에이전트는 메뉴의 에이전트 그룹에 그대로 남습니다.

설정에서 각 에이전트를 명확하게 설명하세요. 작업을 나누는 에이전트는 그 설명을 읽고 어느 쪽이 작업에 맞는지 판단합니다. 작업을 내 에이전트나 코딩 에이전트에게 자체 추론 강도로 팀원처럼 넘기려면 [에이전트 오케스트레이터](/ko/ai/agent-orchestrator)를 참고하세요.

### 프로젝트 도우미

프로젝트 도우미와 내 도우미는 Claude Code 하위 에이전트 및 Codex 에이전트 역할과 같은 파일을 사용하므로, 이미 이를 갖춘 저장소나 홈 폴더에는 추가 설정이 필요 없습니다.

- Claude Code 파일(frontmatter에 `name`과 `description`이 있는 Markdown)은 `permissionMode: plan`을 설정하거나 `Read`, `Grep`, `Glob` 같은 읽기 도구만 나열하면 읽기 전용입니다.
- Codex 파일(`description`과 `developer_instructions`가 있는 TOML)은 `sandbox_mode = "read-only"`일 때 읽기 전용입니다.
- 제공업체가 도우미의 모델을 지원하지 않으면 도우미는 채팅의 모델을 대신 사용합니다.

Claude Code 파일의 `tools`와 `disallowedTools`는 도우미가 에이전트의 도구 중 무엇을 사용할 수 있는지 결정합니다. Enconvo는 각 이름을 자체 도구에 대응시킵니다.

| 도우미 파일에서 | 도우미가 할 수 있는 일 |
|---|---|
| `Read`, `Grep`, `Glob`, `LS` | 파일 읽기 및 검색 |
| `Edit`, `MultiEdit`, `Write` | 파일 편집 및 생성 |
| `Bash` | 모든 셸 명령 실행 |
| `Bash(git diff:*)` | `git diff`로 시작하는 명령만 실행 |
| `WebSearch`, `WebFetch` | 웹 검색 및 웹페이지 읽기 |
| `mcp__github__get_issue`, `mcp__github` | 연결된 MCP 서버의 도구 하나 또는 모든 도구 사용 |

`tools` 줄이 없으면 도우미는 `disallowedTools`에 지정된 것을 제외한 모든 도구를 가집니다. 목록 밖의 호출은 실행되지 않으며 도우미는 어떤 도구를 가지고 있는지 안내받습니다. 모든 도우미는 여전히 스킬을 불러오고 사용자에게 질문할 수 있습니다. `.enconvo/agents` 파일에서는 `browser-use/*`처럼 API 경로로 Enconvo 도구를 나열할 수도 있습니다.

Claude Code 파일의 스킬, MCP 서버, 턴 제한, 백그라운드, 워크트리 설정도 적용됩니다.

## 에이전트에 접근하는 방법

- [채팅 창](/ko/ai/chat), [SmartBar](/ko/features/smartbar), [앱 사이드바](/ko/features/app-sidebar), [Dynamic Island](/ko/features/dynamic-island)에서 채팅합니다.
- **음성 명령**을 설정하여 선택한 에이전트에게 음성 요청을 보냅니다. [받아쓰기](/ko/features/dictation)를 참고하세요.
- [Live Talk](/ko/features/live-voice)로 대화하거나, [아바타](/ko/features/avatar)로 데스크톱 캐릭터를 줍니다.
- [메신저 채널](/ko/integrations/messaging)로 메시징 앱을 연결합니다.
- [예약 작업](/ko/workflows/scheduled-jobs)으로 나중에 실행합니다.
- 링크, 터미널 명령, API 호출로 Enconvo 밖에서 실행합니다. [링크, CLI 및 API](#링크-cli-및-api)를 참고하세요.

### 링크, CLI 및 API

**설정 → 에이전트 목록**에서 에이전트를 엽니다. **사용처**의 **링크, CLI 및 API** 행에 **보기** 버튼이 있습니다. 클릭하면 텍스트와 파일로 이 에이전트를 실행하는 딥링크, 터미널 명령, API 호출을 복사할 수 있는 상태로 얻을 수 있습니다. AI 명령에도 같은 행이 있습니다.

## 기본값과 연속성

여러 채팅이나 채널이 사용하는 에이전트를 변경하기 전에 [모델 기본값](/ko/ai/model-selection-guide)을 확인하세요. 에이전트가 다시 사용해야 하는 사실은 [메모리](/ko/ai/memory)에 설정하고, 모든 것을 지침에 넣는 대신 문서는 지식 베이스에 보관하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 요청이 실패함 | 먼저 도구 오류를 읽거나 누락된 입력이 있는지 확인하세요. |
| 모델과 도구 중 어느 쪽 문제인지 알 수 없음 | 선택적 도구를 끈 상태로 같은 요청을 시도한 다음, 도구를 하나씩 다시 추가하세요. |
| 작업이 파일이나 외부 서비스를 변경함 | 승인하기 전에 대상과 영향을 확인하세요. |
| 에이전트가 도구나 스킬이 없다고 말함 | **도구 및 스킬**에서 **내가 고른 것만**으로 설정되어 있는지, 또는 기본 제공 도구가 꺼져 있는지 확인하세요. |
| 답변에 차트와 카드가 원하는 것보다 많거나 시간이 너무 오래 걸림 | **스타일**에서 **인텔리전트 UI**를 **선별**로 설정하거나, 한 채팅에만 적용하려면 **+** 메뉴의 **스타일 사용**에서 설정하세요. |
