에이전트는 특정 작업에 맞게 지침, 모델, 도구를 결합한 어시스턴트입니다. 매번 같은 지침을 반복해서 입력하거나 작업에 특정 도구 모음이 필요할 때 에이전트를 만들어 보세요. **설정 → 에이전트 목록**에서 에이전트를 관리할 수 있습니다.

아래 영상에서는 2분 내외로 Mavis와 기본 에이전트, 코딩 에이전트, 에이전트의 구성 요소, 그리고 나만의 에이전트를 만드는 방법을 살펴봅니다.

## 기본 제공 에이전트

**Mavis**는 기본 에이전트로, 질문에 답할 뿐만 아니라 앱을 제어하고 웹을 탐색하며 파일을 다룰 수 있습니다. 기본 제공 에이전트는 각기 특화된 역할을 맡고 있습니다: **Writer**, **Planner**, **Reviewer**, **Advisor**, **Researcher**, **Designer**, **Coder**. **Claude Code**, **Codex**, **Grok Build**, **Antigravity**, **Muse Code**는 설치된 코딩 에이전트와 연결되어 프로젝트 폴더 내에서 작업하며, **Grok Bot**은 클라우드에 있는 xAI 에이전트와 대화합니다. 자세한 내용은 [코딩 에이전트](/ko/ai/coding-agents)를 참고하세요.

채팅 상단의 에이전트 메뉴나 채팅 창 입력란 위의 카드에서 에이전트를 선택하세요. 에이전트 목록에는 가장 최근에 대화한 에이전트가 먼저 표시됩니다.

## 에이전트의 구성

**설정 → 에이전트 목록**에서 에이전트를 클릭해 설정 페이지를 여세요. 왼쪽 섹션을 클릭하면 해당 항목으로 바로 이동합니다.

| 섹션 | 설정 내용 |
| --- | --- |
| **지침** | 모든 대화 시작 전 에이전트에게 전달되는 내용입니다. 입력하는 즉시 저장됩니다. |
| **스타일** | **응답 스타일**과, 요청하지 않아도 차트·표·카드로 응답하는 정도를 정하는 **인텔리전트 UI** 수준을 설정합니다. [스타일 설정](#스타일-설정)을 참고하세요. |
| **모델** | 응답 작성에 사용할 AI 모델입니다. 에이전트마다 다른 모델을 지정할 수 있습니다. |
| **도구 및 스킬** | 사용할 수 있는 도구와 나머지 도구를 찾는 방식, 스킬 폴더, 그리고 전용 스킬과 작업 파일을 보관하는 **작업 폴더**를 설정합니다. [도구 및 스킬 선택](#도구-및-스킬-선택)을 참고하세요. |
| **지식** | 검색할 지식 베이스와 순서, 그리고 지식 베이스에 답이 없을 때 웹을 검색할지 여부를 정합니다. [지식 베이스 선택](#지식-베이스-선택)을 참고하세요. |
| **메모리** | 참조할 메모리와 새로운 내용을 기억할지 여부를 설정합니다. |
| **음성** | 응답을 소리 내어 읽을 때 사용할 음성입니다. |
| **동작** | 에이전트가 보는 컨텍스트, 실행 방식, **응답 언어**, **클라우드 포인트 실행 한도** 등 응답 방식을 설정합니다. |
| **사용 위치** | 채팅 외에 이 에이전트를 실행하는 경로와 **링크, CLI 및 API** 항목을 표시합니다. |

## 에이전트 만들기

1. **설정 → 에이전트 목록**에서 **새 에이전트 만들기**를 클릭하거나 SmartBar에서 **Create Agent**를 실행하세요.
2. **이름**을 입력하고, 필요하면 **아바타**와 용도를 설명하는 **설명**을 입력하세요.
3. **에이전트 지침** 아래에 에이전트가 할 일, 필요한 입력, 결과 표시 형식을 적으세요.
4. **무엇을 사용할 수 있나요?** 아래에서 프리셋을 선택해 시작하세요: **일상**(모든 기본 도구), **코딩**, **리서치**, **글쓰기**. 나중에 **도구 및 스킬**에서 변경할 수 있습니다.
5. 모델을 선택하세요. **추천 모델** 아래에서 Enconvo가 설명을 읽고 적합한 Enconvo Cloud 모델을 제안하며, 그 옆에 더 저렴한 모델과 더 강력한 모델도 함께 보여줍니다. **이 모델 사용**을 클릭하거나 다른 모델을 선택하세요. [추천 모델 사용하기](/ko/ai/model-selection-guide)를 참고하세요.
6. **봇 만들기**를 클릭한 뒤 에이전트를 열어 스킬과 지식을 선택하세요.
7. 새 채팅을 시작하고 간단한 대표 작업으로 테스트해 보세요.

이미지를 업로드하는 대신 아바타를 직접 그리려면 여기나 에이전트 설정의 아바타 선택기에서 **생성** 탭을 여세요. 스타일(**Flat**, **3D**, **Anime**, **Photo**, **Line**, **Watercolor**)을 고르고 **생성**을 클릭하면 이미지 모델이 에이전트의 이름과 설명을 바탕으로 아바타 4개를 그려 줍니다. 세부 내용을 추가해 다시 생성하거나 마음에 드는 이미지를 클릭하세요. **생성**을 클릭하기 전까지는 아무것도 그려지지 않습니다.

지침 예시:

```text
Help me turn meeting notes into actionable follow-ups.
Separate decisions, open questions, and action items.
For action items, preserve the owner and due date if stated;
otherwise mark them as unspecified.
```

## 스타일 설정

**스타일** 아래의 두 설정이 에이전트 응답의 형식을 결정합니다. 개별 채팅에서도 **+** 메뉴의 **스타일 사용**에서 다른 스타일을 선택할 수 있습니다.

**응답 스타일**은 어조, 길이, 형식을 정합니다: **일반**, **간결하게**, **설명 위주**, **격식 있게** 중 고르거나 나만의 스타일을 만들 수 있습니다. **새 스타일**을 클릭해 설명이나 직접 작성한 글 샘플로 스타일을 만들고, **관리**를 클릭해 기존 스타일을 편집하세요.

**인텔리전트 UI**는 따로 요청하지 않아도 차트, 표, 카드로 응답할 빈도를 정합니다.

| 수준 | 작동 방식 |
| --- | --- |
| **선별** | 데이터, 비교, 계획을 시각적으로 그립니다. 요약과 설명은 텍스트로 유지합니다. |
| **적극적** (기본값) | 읽기 더 좋다면 설명에도 차트, 표, 카드를 추가합니다. |
| **시각 우선** | 시각 자료를 중심으로 답하며, 한 번의 응답에 여러 개를 사용할 수 있습니다. 응답 시간이 조금 더 걸립니다. |

시각 요소를 많이 사용할수록 응답 시간이 길어지고 포인트를 더 사용합니다. 메신저 채널과 음성 응답은 텍스트로 유지됩니다.

## 도구 및 스킬 선택

**도구 및 스킬** 아래에서 에이전트가 사용할 도구를 찾는 방식을 선택하세요.

- **자동 탐색** (권장)은 필수 도구로 시작해 작업에 필요할 때 설치된 스킬, 플러그인, 커넥터, MCP 서버를 자동으로 찾습니다. 의미 기반으로 매칭하므로 도구 설명과 다르게 표현하거나 다른 언어로 요청해도 잘 찾아냅니다.
- **선택한 항목만**은 에이전트에게 고정된 도구 세트만 허용합니다. 사용할 기본 도구, 스킬, MCP 서버를 직접 고르세요. 작업에 다른 도구가 필요하면 검색하는 대신 무엇이 빠져 있는지 알려줍니다.

**자동 탐색**을 사용하더라도 이 에이전트가 절대 쓰지 않아야 할 **기본 도구**를 끄거나, 모든 채팅 목록에 포함되도록 **고정 스킬**에 등록하거나, **Enconvo Store에서 플러그인 제안**을 꺼서 설치 권장을 막을 수 있습니다. **스킬 폴더**에서는 이 에이전트에 대해 개별 스킬을 끌 수 있습니다.

에이전트에는 작업에 필요한 도구만 부여하세요.

| 필요한 작업 | 기능 |
| --- | --- |
| 문서 읽기 및 편집 | [파일 도구](/ko/ai/file-tools) |
| 최신 정보 검색 | [웹 검색](/ko/ai/web-search) 및 [웹페이지 가져오기](/ko/ai/web-fetch) |
| 웹사이트에서 작업 | [브라우저 사용](/ko/features/browser-control) |
| 데스크톱 앱 제어 | [컴퓨터 사용](/ko/features/computer-use) |
| 보유 자료 검색 | [지식 베이스](/ko/ai/knowledge-base) |
| 반복 절차 재사용 | [스킬](/ko/configuration/skills) |
| 외부 서비스 연동 | [MCP 서버](/ko/features/mcp) |
| 코드 실행 | [코드 실행기](/ko/ai/code-runner) |
| 한 단계에서 여러 도구 호출 | [코드 모드](/ko/configuration/code-mode) |

선택한 모델이 사용하려는 도구와 입력 형식을 지원해야 합니다. 또한 각 도구마다 고유한 인증 정보, 권한, 설정이 필요하며, 지침만으로 에이전트에게 없는 권한을 부여할 수는 없습니다.

## 지식 베이스 선택

**지식** 아래에서 에이전트가 검색할 대상을 고르세요.

| 옵션 | 작동 방식 |
| --- | --- |
| **모든 지식 베이스** | 질문에 필요할 때 보유한 모든 지식 베이스에서 검색합니다. |
| **선택한 것 먼저** | 추가한 지식 베이스를 먼저 찾고, 답이 없으면 나머지에서 찾습니다. |
| **선택한 것만** | 추가한 지식 베이스에서만 검색합니다. 다른 지식 베이스는 `@`로 멘션할 때만 열립니다. |

**지식 베이스 추가**를 클릭해 대상을 고르고, 드래그해 검색 순서를 정하세요.

## 작업 승인

실행 모드 옆의 **권한** 칩은 에이전트가 작업을 실행하기 전에 멈추고 확인을 요청할 시점을 정합니다. 이 칩은 채팅 창, SmartBar, 앱 사이드바, Dynamic Island의 에이전트 모드에 표시됩니다. 어디서 변경하든 해당 에이전트의 동일한 설정이 바뀌므로 다른 창에도 반영됩니다.

| 모드 | 사전 확인 대상 |
| --- | --- |
| **승인 요청** | 명령 실행, 작업 폴더 외부의 파일 편집, 앱·브라우저·온라인 서비스에서의 작업 |
| **대신 승인** (기본값) | 파일 삭제, 메시지 전송, 게시, 결제 등 잠재적으로 위험해 보이는 작업만 확인 |
| **전체 접근** | 없음. 에이전트가 묻지 않고 바로 실행 |

파일 읽기, 검색, 화면 확인은 확인을 요청하지 않습니다. 또한 **대신 승인** 모드에서는 자체적으로 `PATH`만 설정하는 명령이나 임시 폴더 아래에서 직접 만든 항목을 삭제하는 명령은 묻지 않고 실행합니다. 그 외의 삭제 작업은 여전히 확인을 요청합니다.

에이전트가 다른 에이전트나 코딩 에이전트에게 작업을 넘기면 호출된 에이전트도 현재 대화 중인 에이전트와 같은 권한 모드로 동작합니다. 각 승인 카드에는 "이 프로젝트가 대신 승인 모드여서 요청함"처럼 어떤 설정 때문에 확인을 요청했는지 표시됩니다. 실행된 명령을 제한하는 기능은 [에이전트 샌드박스](/ko/configuration/sandbox)를 참고하세요.

### 확인 요청이 표시되는 위치

확인 요청은 채팅이 실행 중인 창에 표시됩니다. 해당 창이 채팅을 보여주고 있지 않다면(예: 숨겨져 있거나 인라인 패널인 경우) 요청이 Dynamic Island로 이동합니다. 30초 내에 응답하지 않으면, 사용 중인 앱 뒤에 채팅 창이 열려 있더라도 페어링된 iPhone으로 알림이 전송됩니다.

응답하지 않고 Dynamic Island의 카드를 닫았다면 Dynamic Island 채팅에서 대기 중인 단계를 클릭해 옵션을 다시 보세요. 에이전트가 사용자에게 묻는 질문도 같은 방식으로 동작합니다.

### 응답하기

- **예, 한 번만 허용**은 이번 작업 한 번만 실행을 허용합니다.
- **예, 다시 묻지 않음**은 해당 채팅이 끝날 때까지 허용하며 Enconvo를 재시작한 뒤에도 기억됩니다.
- 또는 에이전트가 대신 수행할 작업을 직접 입력할 수도 있습니다.

대기 중인 채팅은 채팅 창의 목록, SmartBar의 최근 채팅, Dynamic Island에서 실행 중 대신 **승인 대기 중**으로 표시됩니다. iPhone 앱의 채팅 목록에서는 **승인 필요**로 표시됩니다.

하위 에이전트는 상위 채팅에서 승인을 요청하며, 어떤 하위 에이전트가 어떤 작업을 수행하기 위해 요청하는지 함께 표시합니다. 예약 작업, 워크플로, 메신저 채널은 창 앞에서 응답할 사람이 없으므로 확인 요청 없이 실행됩니다.

## 하위 에이전트

에이전트 모드에서는 에이전트가 작업을 여러 부분으로 나누어 최대 6개의 하위 에이전트를 동시에 실행할 수 있으며, 각 하위 에이전트는 별도의 대화에서 작업합니다. 모든 하위 에이전트가 결과를 보고하면 원래 에이전트가 답변을 종합해 제공합니다. 이 기능은 여러 독립적인 검색을 동시에 수행해야 하는 등 작업을 나누는 것이 분명히 유리하거나 사용자가 직접 요청한 경우에만 사용됩니다. 사용량 제한 같은 AI 오류로 하위 에이전트가 도중에 멈춰도 에이전트는 그때까지 찾은 내용을 받아 두고, 오류가 해소되면 이어서 진행하게 할 수 있습니다.

하위 에이전트를 시작할 때 에이전트는 자체 모델, 추론 강도, 지침, 이름을 지정하거나 현재 대화를 분기해 넘길 수 있습니다. 에이전트가 직접 모델을 고를 때는 빠른 조회, 읽기, 단순 반복 작업에 제공업체의 경량 모델을 쓰고, 고난도 추론에는 더 높은 추론 강도를 적용하며, 나머지는 사용자가 선택한 모델을 그대로 사용합니다. 하위 에이전트도 자체 하위 에이전트를 최대 3단계 깊이까지 생성할 수 있습니다.

- **코딩 에이전트를 하위 에이전트로 사용:** Claude Code, Codex, Antigravity, Grok Build, Muse Code도 하위 에이전트로 작동할 수 있습니다. 카드에는 코딩 에이전트 아이콘, 작업 위치, 사용한 도구 호출 횟수, 소요 시간, 토큰 수가 표시됩니다.
- **분리된 워크트리:** 한 하위 에이전트가 파일을 수정하는 동안 다른 하위 에이전트도 파일을 수정해야 하면 각자 독립된 git 워크트리를 받아 서로의 작업을 덮어쓰지 않습니다. 변경 사항이 없는 워크트리는 하위 에이전트가 완료되면 삭제됩니다. 디자인, 문서, 슬라이드, 리서치, 리뷰만 작성하는 하위 에이전트는 워크트리 없이 작업하므로 여러 개를 시작해도 프로젝트를 복제하지 않습니다.
- **다른 컴퓨터에서 실행:** 에이전트는 페어링된 다른 컴퓨터에서 하위 에이전트를 실행해 그 컴퓨터의 에이전트나 코딩 에이전트에게 작업을 맡길 수 있습니다. [다른 컴퓨터](/ko/integrations/other-computers)를 참고하세요.
- **진행 제어:** 에이전트는 실행 중인 하위 에이전트의 작업에 추가 메시지를 보내거나, 중단하거나, 같은 프로젝트 내 다른 에이전트의 채팅에 연결할 수 있습니다. 채팅을 중지하면 그 아래의 모든 하위 에이전트도 함께 중지됩니다.
- **파이프라인:** 에이전트는 여러 파일 목록에 대해 동일한 검사를 수행하는 것처럼 계획된 하위 에이전트 묶음을 한 단계로 실행할 수 있습니다. 실행에 실패하더라도 이미 완료된 하위 에이전트를 다시 돌리지 않고 이어서 재개합니다.

### 병렬 채팅

에이전트에게 별도의 작업을 위해 새 채팅을 열어 달라고 요청하면 요청한 추론 강도로 새 채팅을 열며, 이 채팅은 사용자가 직접 시작한 채팅처럼 Mac, iPhone, Android의 채팅 목록에 표시됩니다. 상단에는 어떤 채팅에서 시작되었는지 안내가 붙습니다. 해당 작업의 리뷰와 테스트는 여전히 그 채팅의 하위 에이전트로 실행됩니다. 에이전트가 내부용으로 시작한 채팅도 해당 카드에서 내 채팅 목록으로 옮길 수 있습니다.

### 하위 에이전트 추적 및 대화하기

채팅 내 카드에는 각 하위 에이전트가 수행하는 작업과 함께 실행 중, 승인 대기 중, 완료, 실패 상태를 나타내는 아이콘이 표시됩니다. 실행 중인 하위 에이전트 행에는 현재 수행 중인 작업과 사용 중인 모델 및 추론 강도도 표시됩니다. 새 하위 에이전트는 카드가 뜨자마자 메시지 입력창 위 배경 트레이에도 나타납니다.

하위 에이전트가 만든 디자인이나 문서 같은 결과물은 생성되는 즉시 해당 행 아래에 표시됩니다. 클릭하면 채팅 옆에 열리며, 에이전트는 최종 답변에 이 결과물을 카드로 전달합니다.

- 행을 클릭하면 해당 하위 에이전트의 대화가 열립니다. 작업 공간 패널과 `@` 파일 검색에는 이를 시작한 상위 채팅의 작업 폴더가 표시됩니다. SmartBar와 Dynamic Island에서는 현재 창 안에서 바로 열립니다.
- 하위 에이전트의 대화창에 메시지를 입력해 직접 대화할 수 있습니다. 하위 에이전트는 그곳에서 답변하고, 사용자에게 질문하거나 승인을 요청하며, 같은 폴더에서 계속 작업합니다. 상위 에이전트는 하위 에이전트가 응답할 때까지 기다렸다가 최신 답변을 받아갑니다. 이미 완료된 하위 에이전트에게 메시지를 보내면 다른 하위 에이전트가 같은 폴더의 파일을 수정하는 중이라도 즉시 다시 실행됩니다.
- 하위 에이전트의 대화에는 각 메시지를 보낸 에이전트가 표시됩니다. 상위 에이전트가 보낸 메시지에는 실행 중인 작업을 조정했는지, 대기했는지, 중단했는지, 새 턴을 시작했는지가 표시됩니다.
- 채팅 상세 정보의 **계보**에서는 최대 3단계 깊이까지의 전체 하위 에이전트 트리를 볼 수 있습니다. 코딩 에이전트의 채팅에서는 이를 시작한 Enconvo 채팅을 표시합니다.
- 채팅 창 사이드바에서는 채팅 아래에 하위 에이전트가 나열되며, 채팅 행의 버튼으로 목록을 접거나 펼칠 수 있습니다.

### 하위 에이전트 역할

모든 하위 에이전트는 다음 역할 중 하나로 시작합니다.

| 역할 | 작동 방식 |
| --- | --- |
| **기본값** | 시작한 에이전트와 동일한 지침, 도구, 모델로 작업합니다. |
| **탐색기** | 파일 읽기, 검색, 앱 화면 확인만 가능합니다. 권한 칩 설정과 관계없이 파일을 편집하거나 변경 명령을 실행하거나 온라인 작업을 할 수 없습니다. |
| **내 에이전트 중 하나** | 시작한 채팅과 같은 작업 폴더에서 해당 에이전트 고유의 지침, 도구, 모델로 실행됩니다. |
| **프로젝트 헬퍼** | 작업 폴더나 저장소 루트까지의 상위 폴더 내 `.claude/agents`, `.codex/agents`, `.enconvo/agents`에 정의되어 있습니다. 헬퍼 고유의 지침을 따라 시작한 에이전트처럼 작업합니다. 파일에 나열된 도구만 사용하고 읽기 전용으로 지정된 경우 읽기만 수행하며, 모델 제공업체가 지원하는 경우 헬퍼의 모델을 사용합니다. |
| **개인 헬퍼** | 홈 폴더의 `~/.enconvo/agents`, `~/.claude/agents`, `~/.codex/agents`에 정의되어 모든 채팅에서 사용할 수 있습니다. 프로젝트 헬퍼와 동일하게 동작합니다. |

원하는 하위 에이전트를 직접 고르려면 에이전트 모드 채팅에서 `@`를 입력해 **하위 에이전트** 그룹에서 헬퍼, **탐색기**, 일반 **하위 에이전트** 중 선택하세요. 에이전트가 해당 메시지에 맞춰 하위 에이전트를 시작하고 작업을 전달한 뒤 보고가 끝나면 답변합니다. 내가 만든 에이전트들은 메뉴의 에이전트 그룹에 그대로 남아 있습니다.

에이전트 설정에서 각 에이전트의 역할을 명확히 설명해 두세요. 작업을 나누는 에이전트가 그 설명을 읽고 작업에 맞는 에이전트를 고릅니다. 내 에이전트나 코딩 에이전트를 팀원으로 삼아 원하는 추론 강도로 작업을 맡기려면 [에이전트 오케스트레이터](/ko/ai/agent-orchestrator)를 참고하세요.

### 프로젝트 헬퍼

프로젝트 헬퍼와 개인 헬퍼는 Claude Code 하위 에이전트 및 Codex 에이전트 역할과 같은 파일 형식을 사용하므로, 해당 파일이 이미 있는 저장소나 홈 폴더에서는 별도 설정 없이 바로 쓸 수 있습니다.

- Claude Code 파일(frontmatter에 `name`과 `description`이 있는 Markdown)은 `permissionMode: plan`으로 설정되었거나 `Read`, `Grep`, `Glob` 같은 읽기 도구만 나열한 경우 읽기 전용으로 동작합니다.
- Codex 파일(`description`과 `developer_instructions`가 있는 TOML)은 `sandbox_mode = "read-only"`일 때 읽기 전용으로 동작합니다.
- 모델 제공업체가 헬퍼의 모델을 제공하지 않으면 대신 현재 채팅의 모델을 사용합니다.

Claude Code 파일의 `tools`와 `disallowedTools`는 헬퍼가 사용할 수 있는 에이전트 도구를 결정합니다. Enconvo는 각 이름을 자체 도구와 다음과 같이 연결합니다.

| 헬퍼 파일 표기 | 헬퍼가 할 수 있는 작업 |
|---|---|
| `Read`, `Grep`, `Glob`, `LS` | 파일 읽기 및 검색 |
| `Edit`, `MultiEdit`, `Write` | 파일 편집 및 생성 |
| `Bash` | 모든 셸 명령 실행 |
| `Bash(git diff:*)` | `git diff`로 시작하는 명령만 실행 |
| `WebSearch`, `WebFetch` | 웹 검색 및 웹페이지 읽기 |
| `mcp__github__get_issue`, `mcp__github` | 연결된 MCP 서버의 특정 도구 또는 모든 도구 사용 |

`tools` 줄이 없으면 `disallowedTools`에 지정된 도구를 제외한 모든 도구를 사용할 수 있습니다. 목록에 없는 도구 호출은 실행되지 않으며, 헬퍼에게 사용 가능한 도구 목록을 안내합니다. 모든 헬퍼는 여전히 스킬을 불러오고 사용자에게 질문할 수 있습니다. `.enconvo/agents` 파일에서는 `browser-use/*`처럼 API 경로로 Enconvo 도구를 지정할 수도 있습니다.

Claude Code 파일의 스킬, MCP 서버, 턴 제한, 백그라운드, 워크트리 설정도 모두 그대로 적용됩니다.

## 에이전트 실행 방법

- [채팅 창](/ko/ai/chat), [SmartBar](/ko/features/smartbar), [앱 사이드바](/ko/features/app-sidebar), [Dynamic Island](/ko/features/dynamic-island)에서 대화하세요.
- **음성 명령**을 설정해 말로 원하는 에이전트에게 요청을 보낼 수 있습니다. [받아쓰기](/ko/features/dictation)를 참고하세요.
- [Live Talk](/ko/features/live-voice)로 대화하거나 [아바타](/ko/features/avatar)로 데스크톱 캐릭터를 부여해 보세요.
- [메신저 채널](/ko/integrations/messaging)로 메시징 앱과 연결하세요.
- [예약 작업](/ko/workflows/scheduled-jobs)으로 나중에 자동 실행되도록 예약하세요.
- 링크, 터미널 명령, API 호출을 통해 Enconvo 외부에서 실행할 수 있습니다. [링크, CLI 및 API](#링크-cli-및-api)를 참고하세요.

### 링크, CLI 및 API

**설정 → 에이전트 목록**에서 에이전트를 여세요. **사용 위치** 아래 **링크, CLI 및 API** 행에 **보기** 버튼이 있습니다. 클릭하면 이 에이전트를 텍스트와 파일과 함께 바로 실행할 수 있는 딥링크, 터미널 명령, API 호출 구문을 복사할 수 있습니다. AI 명령에도 같은 항목이 있습니다.

## 기본값과 연속성

여러 채팅이나 채널이 함께 사용하는 에이전트를 변경하기 전에 [모델 기본값](/ko/ai/model-selection-guide)을 확인하세요. 에이전트가 계속 재사용할 사실은 [메모리](/ko/ai/memory)에 설정하고, 긴 문서는 지침에 전부 넣기보다 지식 베이스에 보관하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 요청이 실패함 | 먼저 도구 오류 메시지를 읽거나 누락된 입력이 있는지 확인하세요. |
| 모델 문제인지 도구 문제인지 알 수 없음 | 선택적 도구를 끄고 같은 요청을 시도한 뒤 도구를 하나씩 다시 켜며 확인하세요. |
| 작업이 파일이나 외부 서비스를 변경하려 함 | 승인하기 전에 대상 위치와 영향을 확인하세요. |
| 에이전트가 도구나 스킬이 없다고 말함 | **도구 및 스킬**에서 **선택한 항목만**으로 설정되어 있거나 기본 도구가 꺼져 있지 않은지 확인하세요. |
| 차트나 카드가 너무 많거나 응답이 너무 오래 걸림 | **스타일** 아래에서 **인텔리전트 UI**를 **선별**로 설정하거나, 해당 채팅의 **+** 메뉴 → **스타일 사용**에서 변경하세요. |
