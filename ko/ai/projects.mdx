프로젝트는 하나의 폴더에 대한 채팅, 아이디어, 팀을 한곳에 모아 둡니다. 원하는 것을 아이디어로 적어 두면 프로젝트의 리드가 팀과 함께 계획을 세우고, 각 작업은 완료될 때까지 보드를 가로질러 이동합니다. 웹사이트나 앱처럼 계속 이어지는 작업에서 무엇이 실행 중이고 무엇에 내 확인이 필요한지 한눈에 보고 싶다면 프로젝트를 사용하세요.

아래 영상은 프로젝트를 열고, 작업의 일부를 Claude Code에 맡기는 아이디어를 추가하고, 보드에서 진행 상황을 따라간 다음, 프로젝트를 보관하고 복원합니다.

## 시작하기 전에

프로젝트가 필요합니다. 채팅 창 사이드바에서 **프로젝트** 옆의 **+**를 클릭하고 폴더를 선택하세요. [프로젝트 만들기](/ko/ai/agent-orchestrator)를 참고하세요. Claude Code나 Codex 같은 코딩 에이전트에게 작업을 맡기려면 먼저 설치하고 로그인하세요. [코딩 에이전트](/ko/ai/coding-agents)를 참고하세요.

## 프로젝트 열기

사이드바에서 프로젝트를 클릭하세요. 프로젝트 페이지에는 탭이 세 개 있습니다.

| 탭 | 표시되는 내용 |
| --- | --- |
| **채팅** | 프로젝트의 리드와 나누는 채팅, 그리고 [내 확인이 필요한 항목](#확인이-필요한-항목-보기) 패널. |
| **보드** | 프로젝트의 아이디어. **시작 전**에서 **계획 중**, **진행 중**을 거쳐 **완료**까지 표시됩니다. |
| **팀 및 설정** | 팀 구성원, 그리고 팀이 [내게 확인하는 시점](#팀이-확인하는-시점-선택하기). |

팀의 얼굴이 리드부터 순서대로 왼쪽 위에 표시됩니다. 프로젝트 채팅의 작업은 사이드바의 해당 행 아래에도 표시됩니다.

## 아이디어 추가하기

아이디어는 프로젝트가 해 주길 바라는 일입니다.

1. **보드** 탭을 열고 **새 아이디어**를 클릭하세요.
2. 원하는 내용을 말하듯이 적으세요. 스크린샷이나 파일을 첨부하거나, 마이크를 클릭해 말로 입력할 수도 있습니다.
3. 원하면 **우선순위**를 설정하세요. Enconvo는 입력한 내용에서 **종류**를 추측합니다. **기능**, **버그**, **개선**, **문서**, **리서치** 중 하나입니다. 추측이 틀렸다면 바꾸세요.
4. **아이디어 추가**를 클릭하세요.

아이디어는 **시작 전** 아래에 카드로 나타나며, 입력한 내용으로 만든 짧은 제목과 우선순위를 나타내는 빨강, 주황, 파랑 깃발이 표시됩니다. 리드가 바로 계획을 시작하고 아이디어를 **계획 중**으로 옮깁니다. 첨부한 파일은 아이디어가 시작될 때 리드에게 전달됩니다. 한 종류의 아이디어만 보려면 **종류별 필터**를 사용하세요.

아이디어는 저절로 들어오게 할 수도 있습니다. [자동화](/ko/workflows/scheduled-jobs)에 **Ideas에 추가** 동작을 지정하면, 자동화가 받는 GitHub 이슈, Discord나 Telegram 메시지, 이메일, 웹훅이 각각 프로젝트 보드의 아이디어가 됩니다. 리드는 버그를 재현해 수정 계획을 세우거나, 요청을 조사해 이유와 함께 닫거나 계획을 세우며, 무엇이든 바꾸기 전에 먼저 묻습니다.

계획이 준비되면 각 작업과 담당자, 사용할 모델이 표시됩니다. 내용을 확인한 다음 **시작**을 클릭하세요. 아이디어가 **진행 중**으로 이동합니다. 리드는 아이디어의 **목표**와 **완료 기준** 항목을 바탕으로 계획하며, 리드가 그 목표가 달성되었다고 판단해야만 아이디어가 **완료**로 이동합니다.

## 아이디어 따라가기

아이디어를 클릭하면 해당 페이지가 열립니다. 한쪽에는 리드와의 채팅이, 다른 쪽에는 아이디어의 계획, 작업, 설명, 파일, 목표가 있습니다. **진행 상황**에는 **작업 계획**, **작업 수행**, **검토 및 테스트**가 각각 어디까지 진행되었는지와 담당자와 함께 표시됩니다.

완료된 아이디어를 다시 작업하려면 **다시 열기**를 클릭하세요.

작업이 있는 아이디어는 상단에 두 가지 보기가 있습니다. **작업**은 작업만 보드로 보여주고, **채팅 상대**와 리드의 이름(예: **Mavis와 채팅**)은 계획을 세운 채팅을 엽니다.

## 코딩 에이전트에게 작업 맡기기

아이디어나 프로젝트 채팅에서 에이전트의 이름을 지정하세요. 원하면 모델도 지정할 수 있습니다. Opus 5.5처럼 모델만 지정해도 리드가 그 작업을 해당 모델로 수행합니다. 멤버가 없는 프로젝트에서도 사용할 수 있습니다. 예를 들면 다음과 같습니다.

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

리드는 지정한 부분을 해당 에이전트와 모델이 맡는 작업으로 계획하며, 그 에이전트가 프로젝트의 멤버가 아니어도 됩니다. 나머지는 리드가 직접 할 수 있습니다. 계획과 보드에는 작업 담당자 옆에 모델이 표시됩니다. 이름이 여러 모델을 가리킬 수 있거나 어떤 모델도 가리키지 않으면 리드가 물어봅니다.

코딩 에이전트가 작업을 마치면 아이디어의 **작업** 보드에서 **검토 대기** 아래에 내 검토를 기다립니다. 폴더가 git 저장소가 아닌 프로젝트에서는 바로 **완료**로 이동합니다. 각 코딩 작업은 코드의 자체 복사본에서 진행되며, 준비가 되면 계획의 결과 카드에 있는 **병합**을 사용하세요. 멤버는 직접 푸시하거나 병합할 수 없습니다.

채팅 탭이나 아이디어에서 리드에게 맡긴 각 작업은 보드에 아이디어별 또는 채팅별로 그룹화되어 표시됩니다. 하나의 대화를 따라가려면 보드의 채팅 필터에서 채팅을 선택하거나 **그룹 기준**에서 **채팅**을 선택하세요.

프로젝트 채팅에서 직접 한 작업도 보드에 표시됩니다. 채팅이 파일을 변경하거나 명령을 실행하면 카드가 짧은 요약과 변경된 파일과 함께 **완료**까지 따라갑니다. 카드를 클릭하면 채팅이 열립니다. 리드는 이 카드들을 보고, 자신의 작업이 같은 파일을 건드리지 않게 합니다.

## 완료된 작업 병합하기

작업이나 계획의 결과 카드에서 **병합**을 클릭하면 프로젝트의 **기준 브랜치**에 병합됩니다. 같은 파일의 다른 부분에 커밋되지 않은 변경 사항이 있어도 병합이 막히지 않습니다. git이 사용 중이면 병합은 잠시 기다리고, 잠금 파일이 남아 있으면 그 파일 이름을 알려줍니다.

클릭하지 않고 병합하려면 **프로젝트 설정 → 보드**에서 **통과한 작업 병합**을 켜세요. **워크트리**에서 설정하는 **기준 브랜치**가 필요합니다. 그러면 각 작업은 검사와 다른 업체 에이전트의 검토를 통과하는 즉시 저절로 병합됩니다. **통과 조건**에서 **차단 의견 없음**, **검토자 승인**, **검사만** 중 하나를 선택하세요. 충돌이 있는 작업은 담당 멤버에게 돌아갑니다. 검토자가 실행되지 못하면 병합을 건너뛰지 않고 모든 병합이 일시 중지됩니다.

### git이 아닌 프로젝트

폴더가 git 저장소가 아닌 프로젝트에서는 각 리드 채팅이 작업 계획을 자체 채팅 폴더에 저장하므로 두 리드 채팅이 동시에 계획을 실행할 수 있습니다. 계획 카드에 **저장 위치**와 폴더가 표시되고, **함께 변경됨**에는 작업이 그 폴더 밖에서 건드린 파일이 나열됩니다.

## 리드에게 다른 방식으로 요청하기

프로젝트의 리드 채팅에서는 다음을 사용할 수 있습니다.

- **답변 비교**는 두 개에서 여섯 개의 에이전트에게 같은 질문을 하고, 리드가 그 답변을 비교합니다.
- **스타일 사용**은 리드가 답변을 쓰는 방식을 선택합니다.

Codex, Claude Code 또는 다른 에이전트에게 현재 작업을 검토하거나 테스트하게 하려면 그냥 요청하세요. 프로젝트에서는 리드가 해당 에이전트를 하위 에이전트로 시작하고 결과를 같은 채팅으로 가져옵니다. 리드는 프로젝트 멤버에게 주는 작업과 별도로, 자신의 작업을 위해 하위 에이전트를 시작할 수도 있습니다.

프로젝트의 워크플로로 작업을 실행하려면 `@`를 입력하고 워크플로를 선택하거나, **팀 및 설정** 탭에서 워크플로 옆의 **채팅에서 사용**을 클릭하세요. [나만의 워크플로 사용하기](#나만의-워크플로-사용하기)를 참고하세요.

## 확인이 필요한 항목 보기

**채팅** 탭을 여세요. 메시지 상자 위의 패널에는 세 개의 열이 있습니다.

| 열 | 표시되는 내용 |
| --- | --- |
| **확인 필요** | 내 답변, 승인, 검토를 기다리는 작업. |
| **작업 중** | 실행 중인 작업. |
| **새 결과** | 아직 열어 보지 않은 완료된 작업. |

행을 클릭하면 해당 아이디어가 열립니다.

## 모든 것을 보드에서 보기

채팅 창 사이드바 아이콘 레일의 **···** 메뉴에 있는 **보드**에는 모든 채팅, 프로젝트, 팀의 작업이 한곳에 표시됩니다. 레일에 계속 두려면 해당 메뉴에서 **사이드바 사용자화…**를 선택하세요. [채팅 창](/ko/ai/chat)을 참고하세요.

일부 프로젝트만 보려면 왼쪽 위의 필터(**모든 보드**)를 클릭하고 원하는 프로젝트를 선택하세요. 보드의 다른 컨트롤은 [보드 따라가기](/ko/ai/agent-orchestrator)에 있습니다.

## 팀 설정하기

**팀 및 설정** 탭을 여세요. 상단에는 리드와 각 멤버가 표시되며, **멤버 추가**로 다른 에이전트를 불러올 수 있습니다. 왼쪽 위의 팀 얼굴을 클릭하면 전체 팀을 한 번에 볼 수 있습니다. 리드에는 **변경**이 있고, 각 멤버에는 그 자리에서 편집할 수 있는 역할이 있습니다.

리드는 내 에이전트 중 하나이거나 코딩 에이전트(Claude Code, Codex, Grok Build, Antigravity)일 수 있습니다. 코딩 에이전트 리드는 다른 리드와 마찬가지로 작업 계획에서 멤버의 작업을 계획하고 결과를 읽습니다.

멤버는 [페어링된 다른 컴퓨터](/ko/integrations/other-computers)의 에이전트일 수 있습니다. 리드는 그 컴퓨터가 필요한 작업을 맡기고, 답변은 작업의 결과로 돌아옵니다. 그 컴퓨터가 내 계정에서 기기 접근 권한이 없으면 작업에 그렇게 표시되고 **기기 관리**로 안내합니다.

### 팀이 일하는 방식

채팅이나 아이디어에서 리드에게 주는 모든 목표는 **표준**을 거칩니다. **작업 계획**, **작업 수행**, 그리고 **검토 및 테스트**입니다. 각 단계를 누가 맡을지 선택하세요. 계획을 멤버에게 맡기면 요청할 때 그 멤버가 계획을 쓰고, 리드는 그 작업을 내 **시작**을 기다리는 작업 계획으로 제안합니다. 검사를 켜거나 끌 수 있고, 작업이 수정을 위해 돌아가는 횟수인 **수정 횟수**도 설정할 수 있습니다.

### 나만의 워크플로 사용하기

**팀 및 설정** 탭의 **사용자 지정 워크플로**는 켜기 전까지 꺼져 있습니다. 꺼져 있는 동안 모든 목표는 **표준**을 거칩니다. 켜면 목표나 개별 작업을 [워크플로](/ko/workflows/introduction)로 실행할 수 있습니다.

- **또는 각 목표를 워크플로로 실행**에는 팀 워크플로가 나열됩니다. 하나를 가리키고 **모든 목표에 사용**을 클릭하거나, **새 팀 워크플로**를 클릭해 직접 만드세요.
- **작업 워크플로**에는 버그 수정처럼 리드가 개별 작업에 줄 수 있는 워크플로가 나열됩니다. **채팅에서 사용**을 클릭하면 리드 채팅에서 이름을 지정하고, **새 워크플로**를 클릭하면 직접 만들 수 있습니다.

기본 제공 워크플로는 다음과 같습니다.

| 워크플로 | 기능 |
| --- | --- |
| **Ship** | 아이디어를 내가 승인하는 명세, 디자인, 계획으로 바꾸고, 각 작업을 테스트, 검사, 검토, 검증과 함께 구현한 다음 전체 브랜치를 검토합니다. |
| **Planner** | 아이디어를 내가 승인하는 명세, 디자인, 작업으로 바꾸고, 작업을 작업 계획으로 리드에게 넘깁니다. |
| **Sprint** | 계획된 작업 하나를 테스트, 검사, 검토, 검증과 함께 구현합니다. |
| **Compound** | 내가 유지한 교훈을 저장소의 문서와 규칙에 적용합니다. |
| **Verify setup** | 프로젝트를 검사하고 실행하는 방법을 파악하고, 내가 승인하는 검증 런북을 작성한 다음, 실제로 실행해 증명합니다. |

각 행에는 워크플로의 아이콘, 이를 수행하는 멤버의 얼굴, 실행 횟수와 실패 횟수가 표시됩니다. 워크플로에 멤버가 없으면 해당 행에서 **에이전트 선택…**을 클릭하세요. 행을 클릭하면 워크플로가 열리고 단계나 담당자를 바꿀 수 있습니다.

프로젝트에서 워크플로에 저장한 변경 사항은 **초안 작성** 상태로 유지됩니다. **게시**를 클릭하기 전까지 새 계획은 게시된 버전을 계속 사용합니다. **이전 버전으로 되돌리기**는 직전 버전을 복원합니다. 작업의 워크플로에는 각 단계의 토큰과 비용이 표시되며, API 가격 기준의 합계도 함께 표시됩니다.

### 검사 명령 설정하기

검사 명령은 완료된 작업의 코드 복사본에서 검토로 넘어가기 전에 실행됩니다. 검사가 실패하면 작업의 담당 멤버가 고치도록 돌아갑니다.

1. **팀 및 설정** 탭에서 **프로젝트 설정**을 클릭한 다음 **보드**를 클릭하세요.
2. **검사 명령** 옆의 **찾기**를 클릭하세요. Enconvo가 프로젝트 파일에서 명령을 읽고, 통과하는 경우에만 입력합니다.
3. 찾지 못하면 **Mavis에게 설정 요청**(버튼에는 리드의 이름이 표시됩니다)을 클릭하세요. 리드가 채팅에서 명령을 찾거나 추가합니다.

검사 명령이 없는 프로젝트는 검사 단계가 **확인 안 함**으로 표시됩니다.

### 워크트리 정리하기

git 프로젝트의 각 채팅과 작업은 자체 워크트리에서 진행됩니다. 디스크 공간을 확보하기 위해 Enconvo는 끝난 워크트리를 보관하고 해당 폴더를 제거합니다. **프로젝트 설정 → 워크트리**에서 설정하세요.

| 설정 | 기능 |
| --- | --- |
| **병합된 워크트리 보관** | 작업이 기준 브랜치에 반영되고 커밋되지 않았거나 푸시되지 않은 내용이 없으면 워크트리를 보관합니다. |
| **채팅이 없는 워크트리 보관** | 워크트리의 채팅이 채팅 목록에 하나도 남아 있지 않으면 워크트리를 보관합니다. |
| **비활성 워크트리 보관** | **보관하기 전 비활성 기간**에서 선택한 일수(3, 7, 14, 30일) 동안 활동이 없으면 워크트리를 채팅과 함께 보관합니다. |

커밋되지 않은 변경 사항이 있는 워크트리는 항상 남습니다. **복원**은 보관된 워크트리를 되돌립니다.

## 팀이 확인하는 시점 선택하기

**팀 및 설정** 탭을 여세요.

**확인 시점** 아래:

| 설정 | 기능 |
| --- | --- |
| **계획이 준비되었을 때** | 기본값인 **스마트**는 계획이 이미 요청한 내용대로이면 바로 시작하고, 그 이상을 하거나 위험하면 내 **시작**을 기다립니다. **항상 물어보기**는 매번 **시작**을 기다립니다. **항상 시작**은 모든 계획을 준비되는 즉시 시작합니다. |
| **할 일이 추가되면 바로 계획 시작** | 켜면 리드가 새 아이디어를 바로 계획합니다. 끄면 새 아이디어는 직접 시작할 때까지 **시작 전**에서 기다립니다. |

삭제, 전송, 게시, 결제, 푸시를 하는 동작은 어떤 설정이든 항상 먼저 묻습니다. 폴더, 워크트리, 권한, 예산, 경계는 **프로젝트 설정**에 있습니다.

## 자리를 비운 동안 리드가 작업하게 하기

**전체 접근** 프로젝트에서는 작업이 결과를 보고했는데 채팅에 아무도 없을 때 리드가 작업을 계속 진행할 수 있습니다. **프로젝트 설정 → 보드**에서 **자리를 비운 동안 리드가 작업**을 켜세요.

그러면 리드는 시간당 6턴, 하루 100,000포인트 이내에서 직접 수정하고, 재시도하고, 병합합니다. 작업 자체의 코드 복사본 밖에서는 아무것도 전송, 푸시, 게시, 결제, 삭제하지 않습니다.

돌아오면 리드 채팅 상단의 **자리를 비운 동안** 카드에 리드가 한 일과 내게 남겨 둔 단계가 나열됩니다. 연속으로 두 턴이 실패하거나 한도에 도달하면 리드는 일시 중지하고, **확인 필요**가 **이어서 실행**할지 **일시 중지 유지**할지 묻습니다.

## 프로젝트 보관하기

프로젝트가 끝나면 아무것도 삭제하지 않고 사이드바에서 치우도록 보관하세요.

1. 사이드바에서 프로젝트를 가리키고 **⋯**를 클릭하세요.
2. **프로젝트 보관**을 선택하세요.

프로젝트와 채팅이 사이드바에서 사라지고 예약된 작업은 일시 중지됩니다. 보관된 프로젝트의 채팅은 복원하기 전까지 메시지를 받을 수 없습니다.

되돌리려면 다음과 같이 하세요.

1. **설정 → 보관됨**을 여세요.
2. **프로젝트**를 클릭하세요.
3. 프로젝트 옆의 **복원**을 클릭하세요.

프로젝트가 채팅과 함께 사이드바로 돌아오고, 예약된 작업이 다시 켜집니다.

## 휴대폰의 프로젝트

iPhone 앱에서도 프로젝트를 열 수 있습니다. 아이디어, 보드, 프로젝트 설정, **새 프로젝트**, 그리고 작업에 답하고, 병합하고, 시작하고, 다시 시도하는 작업 계획 카드가 있습니다. 그곳의 `@` 메뉴에는 프로젝트의 멤버와 워크플로가 나열됩니다. [iPhone 앱](/ko/integrations/iphone-app)을 참고하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 새 아이디어가 **시작 전**에 머무름 | **팀 및 설정**에서 **할 일이 추가되면 바로 계획 시작**을 켜거나, 아이디어를 열어 직접 시작하세요. |
| **스마트**를 선택했는데도 계획이 기다림 | 계획이 요청한 것보다 범위가 넓거나 위험한 단계를 포함합니다. 내용을 확인하고 **시작**을 클릭하세요. |
| 코딩 에이전트의 작업이 시작되지 않음 | 코딩 에이전트를 설치하고 로그인하세요. |
| 작업이 로그인 경고와 함께 **보류됨**으로 대기함 | 코딩 에이전트가 로그아웃되었거나 로그인이 곧 만료됩니다. **다시 로그인**을 클릭하세요. 보류된 작업은 로그인하면 다시 실행됩니다. |
| 보드 카드에 주황색으로 문제가 표시됨 | 설정 문제입니다. 카드의 해결 방법을 따르세요. 리드는 이를 재시도하지 않습니다. Enconvo 오류는 다시 시도해도 안전하다고 알려줍니다. |
| iCloud에 보관한 프로젝트에서 작업이 실패함 | Mac 저장 공간 최적화가 켜져 있으면 파일이 Mac에 없을 수 있습니다. Finder에서 프로젝트 폴더에 **다운로드된 상태로 유지**를 선택하세요. |
| 작업에서 프로젝트 폴더가 없다고 표시됨 | 폴더가 이동되었거나 삭제되었습니다. 폴더를 되돌려 놓거나 새 위치로 새 프로젝트를 만드세요. |
| 작업이 프로젝트의 **경계**에서 멈춤 | 작업에서 **경계 편집**을 클릭해 필요한 것을 허용하세요. 경계는 사용자만 변경할 수 있습니다. |
| 작업에 병합이나 리베이스가 중간에 멈췄다고 표시됨 | 작업의 에이전트가 도중에 멈췄습니다. 작업을 병합하기 전에 병합이나 리베이스를 마무리하거나 되돌리세요. |
| 모든 계획이 **시작**을 기다림 | Enconvo에서 로그아웃된 동안에는 계획이 기다립니다. **설정 → 계정**에서 로그인하세요. |
| 사이드바에서 프로젝트가 보이지 않음 | 보관되었을 수 있습니다. **설정 → 보관됨**의 **프로젝트**에서 찾아보세요. |
| 워크플로 작업이 실패함 | 작업을 여세요. 명령이 마지막으로 쓴 내용과 어느 멤버의 단계가 실패했는지 알려줍니다. |
| 목표가 선택한 팀 워크플로를 사용하지 않음 | **팀 및 설정** 탭에서 **사용자 지정 워크플로**를 켜세요. 꺼져 있는 동안 모든 목표는 **표준**을 거칩니다. |
