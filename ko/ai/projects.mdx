프로젝트는 하나의 폴더를 중심으로 채팅, 아이디어, 팀을 함께 묶어 관리합니다. 원하는 내용을 아이디어로 적으면 프로젝트 리더가 팀과 함께 계획을 세우고, 각 작업은 완료될 때까지 보드를 따라 이동합니다. 웹사이트나 앱처럼 현재 진행 중인 작업과 내 확인이 필요한 항목을 한눈에 파악하고 싶은 지속적인 작업에 프로젝트를 활용해 보세요.

아래 영상에서는 프로젝트를 열고, 작업 일부를 Claude Code에 맡기는 아이디어를 추가한 뒤, 보드에서 진행 상황을 추적하고 프로젝트를 보관 및 복원하는 과정을 보여줍니다.

## 시작하기 전에

먼저 프로젝트가 필요합니다. 채팅 창 사이드바에서 **프로젝트** 옆의 **+**를 클릭하고 폴더를 선택하세요: [프로젝트 만들기](/ko/ai/agent-orchestrator)를 참고하세요. Claude Code나 Codex 같은 코딩 에이전트에게 작업을 맡기려면 먼저 설치하고 로그인해야 합니다: [코딩 에이전트](/ko/ai/coding-agents)를 참고하세요.

## 프로젝트 열기

사이드바에서 프로젝트를 클릭하세요. 페이지에는 세 개의 탭이 있습니다.

| 탭 | 표시 내용 |
| --- | --- |
| **채팅** | 프로젝트 리더와 나누는 채팅과 [확인이 필요한 항목](#확인이-필요한-항목-보기) 패널을 보여줍니다. |
| **보드** | **시작 전**부터 **계획 중**, **진행 중**을 거쳐 **완료**까지의 프로젝트 아이디어를 보여줍니다. |
| **팀 및 설정** | 팀 구성원과 팀이 [확인 요청을 보내는 시점](#팀의-확인-시점-선택)을 설정합니다. |

왼쪽 상단에는 리더를 시작으로 팀원들의 프로필 아이콘이 표시됩니다. 프로젝트 채팅의 작업 목록은 사이드바의 해당 행 아래에도 표시됩니다.

## 아이디어 추가하기

아이디어는 프로젝트에서 처리하고 싶은 요청입니다.

1. **보드** 탭을 열고 **새 아이디어**를 클릭하세요.
2. 말하듯이 원하는 내용을 적으세요. 스크린샷이나 파일을 첨부하거나 마이크를 클릭해 말로 입력할 수도 있습니다.
3. 필요하면 **우선순위**를 지정하세요. Enconvo가 내용에 따라 **종류**를 **기능**, **버그**, **개선**, **문서**, **리서치** 중 하나로 자동 추측하며, 맞지 않으면 직접 바꿀 수 있습니다.
4. **아이디어 추가**를 클릭하세요.

아이디어는 내용에서 요약된 짧은 제목과 우선순위를 나타내는 빨간색·주황색·파란색 깃발과 함께 **시작 전** 아래에 카드로 추가됩니다. 리더는 즉시 계획을 세우기 시작하며 카드를 **계획 중**으로 옮깁니다. 첨부한 파일은 아이디어가 시작될 때 리더에게 전달됩니다. 특정 종류의 아이디어만 보려면 **종류별 필터**를 사용하세요.

아이디어는 자동으로 들어오게 할 수도 있습니다. [예약 작업](/ko/workflows/scheduled-jobs)에 **아이디어에 추가** 동작을 지정하면 GitHub 이슈, Discord 또는 Telegram 메시지, 이메일, 웹훅이 수신될 때마다 프로젝트 보드의 아이디어가 됩니다. 리더가 버그를 재현해 수정 계획을 세우거나 요청을 조사해 사유와 함께 닫거나 계획을 세운 뒤, 실제 변경이 일어나기 전에 사용자에게 확인을 받습니다.

계획이 준비되면 각 작업, 담당 에이전트, 사용 모델이 표시됩니다. 확인한 뒤 **시작**을 클릭하면 아이디어가 **진행 중**으로 이동합니다. 리더는 아이디어의 **목표**와 **완료 조건**을 기준으로 계획을 세우며, 그 목표가 달성되었다고 리더가 판단한 경우에만 아이디어가 **완료**로 이동합니다.

## 아이디어 진행 추적

아이디어를 클릭해 상세 페이지를 여세요. 한쪽에는 리더와의 채팅이, 다른 쪽에는 아이디어의 계획, 작업, 설명, 파일, 목표가 표시됩니다. **진행 상태**에서는 **작업 계획**, **작업 수행**, **검토 및 테스트** 단계별로 현재 진척도와 담당자가 표시됩니다.

완료된 아이디어를 다시 작업하려면 **다시 열기**를 클릭하세요.

작업이 포함된 아이디어 상단에는 두 가지 보기가 있습니다: **작업**은 해당 작업들만 보드로 보여주며, **Mavis와 채팅**처럼 **리더와 채팅** 항목은 계획이 세워진 채팅을 엽니다.

## 코딩 에이전트에게 작업 맡기기

아이디어나 프로젝트 채팅에서 에이전트 이름과 원하는 모델을 함께 언급하세요. Opus 5.5처럼 모델 이름만 언급하면 리더가 그 모델로 작업을 수행합니다. 이 기능은 팀원이 없는 프로젝트에서도 작동합니다. 예시:

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

리더는 언급된 부분을 해당 모델의 해당 에이전트 작업으로 계획하며(프로젝트 팀원이 아니더라도 가능), 나머지 작업은 직접 처리할 수 있습니다. 계획과 보드에는 담당자 옆에 모델이 함께 표시됩니다. 입력한 이름이 여러 모델을 가리키거나 일치하는 모델이 없으면 리더가 다시 묻습니다.

코딩 에이전트가 작업을 마치면 해당 작업은 아이디어의 **작업** 보드에서 **검토 대기** 상태로 기다립니다. git 저장소가 아닌 폴더의 프로젝트에서는 바로 **완료**로 이동합니다. 각 코딩 작업은 별도의 코드 사본에서 진행되며, 준비가 되면 계획의 결과 카드에 있는 **병합**을 클릭해 합칠 수 있습니다. 팀원은 스스로 푸시하거나 병합할 수 없습니다.

채팅 탭이나 아이디어에서 리더에게 맡긴 모든 작업은 보드에 아이디어별 또는 채팅별로 묶여 표시됩니다. 보드의 채팅 필터에서 채팅을 고르거나 **그룹 기준**을 **채팅**으로 선택해 특정 대화를 따라갈 수 있습니다.

프로젝트 채팅에서 직접 수행한 작업도 보드에 표시됩니다. 채팅에서 파일을 수정하거나 명령을 실행하면 짧은 요약과 변경된 파일 목록을 담은 카드가 **완료**까지 추적됩니다. 카드를 클릭하면 해당 채팅이 열립니다. 리더도 이 카드를 확인하므로 자체 작업이 같은 파일을 건드리지 않게 피합니다.

## 완료된 작업 병합하기

작업 카드나 계획의 결과 카드에서 **병합**을 클릭하면 프로젝트의 **기본 브랜치**로 병합됩니다. 같은 파일의 다른 줄에 커밋되지 않은 변경 사항이 있어도 병합을 막지 않습니다. git이 다른 작업 중이면 병합은 잠시 대기하며, 잠금 파일이 남아 있으면 그 파일 이름을 알려줍니다.

클릭 없이 자동 병합하려면 **프로젝트 설정 → 보드**에서 **통과한 작업 병합**을 켜세요. 이를 위해서는 **워크트리**에서 **기본 브랜치**가 설정되어 있어야 합니다. 그러면 각 작업은 자체 검사와 다른 공급사의 에이전트가 수행한 리뷰를 모두 통과할 때 자동으로 병합됩니다. **통과 기준** 아래에서 **차단 수준의 문제 없음**, **리뷰어 승인**, **검사만** 중 선택할 수 있습니다. 충돌이 발생한 작업은 담당 팀원에게 돌려보냅니다. 리뷰어를 실행할 수 없는 상황에서는 리뷰를 건너뛰지 않고 모든 병합을 일시 중지합니다.

### git 밖의 프로젝트

git 저장소가 아닌 폴더의 프로젝트에서는 각 리더 채팅이 작업 계획을 자체 채팅 폴더에 저장하므로 두 개의 리더 채팅이 동시에 계획을 실행할 수 있습니다. 계획 카드에는 **저장 위치**와 폴더가 표시되며, **함께 변경된 파일**에는 작업이 그 폴더 밖에서 수정한 파일 목록이 표시됩니다.

## 리더에게 다른 방식으로 요청하기

프로젝트의 리더 채팅에서:

- **답변 비교**는 2~6개의 에이전트에게 같은 질문을 던지고 리더가 답변을 비교해 줍니다.
- **스타일 사용**은 리더가 답변을 작성하는 방식을 선택합니다.

Codex, Claude Code 또는 다른 에이전트에게 현재 작업을 리뷰하거나 테스트하도록 요청할 수도 있습니다. 프로젝트에서는 리더가 해당 에이전트를 하위 에이전트로 실행해 결과를 같은 채팅으로 가져옵니다. 또한 리더는 프로젝트 팀원에게 맡긴 작업과 별개로 자체 작업을 위한 하위 에이전트를 시작할 수 있습니다.

프로젝트의 워크플로 중 하나를 실행하려면 `@`를 입력해 워크플로를 선택하거나 **팀 및 설정** 탭에서 워크플로 옆의 **채팅에서 사용**을 클릭하세요. [자체 워크플로 사용](#자체-워크플로-사용)을 참고하세요.

## 확인이 필요한 항목 보기

**채팅** 탭을 여세요. 메시지 입력란 위의 패널에는 세 개의 열이 있습니다.

| 열 | 표시 목록 |
| --- | --- |
| **확인 필요** | 답변, 승인, 리뷰를 기다리는 작업입니다. |
| **작업 중** | 현재 실행 중인 작업입니다. |
| **새 결과** | 아직 열어보지 않은 완료된 작업입니다. |

행을 클릭하면 해당 아이디어가 열립니다.

## 모든 작업을 보드에서 관리하기

채팅 창 사이드바의 아이콘 레일에 있는 **···** 메뉴의 **보드**에서는 모든 채팅, 프로젝트, 팀의 작업을 한곳에서 볼 수 있습니다. 아이콘 레일에 계속 고정해 두려면 해당 메뉴에서 **사이드바 사용자 지정…**을 선택하세요. [채팅 창](/ko/ai/chat)을 참고하세요.

일부 프로젝트만 보려면 왼쪽 상단의 필터(**모든 보드**)를 클릭해 원하는 프로젝트만 선택하세요. 보드의 다른 제어 기능은 [보드 따라가기](/ko/ai/agent-orchestrator)에서 확인할 수 있습니다.

## 팀 구성하기

**팀 및 설정** 탭을 여세요. 상단에 리더와 각 팀원이 표시되며, **팀원 추가**로 다른 에이전트를 데려올 수 있습니다. 왼쪽 상단의 팀 프로필 아이콘들을 클릭하면 팀 전체를 한눈에 볼 수 있습니다: 리더 옆에는 **변경**이, 각 팀원 옆에는 바로 수정할 수 있는 역할 입력란이 있습니다.

리더는 보유한 일반 에이전트나 Claude Code, Codex, Grok Build, Antigravity 같은 코딩 에이전트 중에서 지정할 수 있습니다. 코딩 에이전트 리더도 다른 리더와 마찬가지로 작업 계획에서 팀원들의 작업을 계획하고 결과를 읽습니다.

[페어링된 다른 컴퓨터](/ko/integrations/other-computers)에 있는 에이전트도 팀원이 될 수 있습니다. 리더는 해당 컴퓨터가 필요한 작업을 그 에이전트에게 맡기고, 답변을 작업 결과로 받아옵니다. 해당 컴퓨터에 계정 기기 접근 권한이 없으면 작업에 그 안내가 표시되며 **기기 관리**로 안내합니다.

### 팀의 작업 방식

채팅이나 아이디어에서 리더에게 전달한 모든 목표는 **표준** 흐름을 따릅니다: **작업 계획**, **작업 수행**, **검토 및 테스트**. 각 단계를 누가 맡을지 고르세요. 계획을 팀원에게 맡기면 요청 시 해당 팀원이 계획을 작성하고, 리더가 이를 **시작** 대기 상태의 작업 계획으로 제안합니다. 또한 검사 단계를 켜거나 끌 수 있고, 수정이 필요할 때 되돌려 보내는 최대 횟수인 **수정 라운드**를 설정할 수 있습니다.

### 자체 워크플로 사용

**팀 및 설정** 탭의 **사용자 지정 워크플로**는 켜기 전까지 비활성화되어 있습니다. 꺼져 있는 동안에는 모든 목표가 **표준** 흐름으로 실행됩니다. 목표나 개별 작업을 [워크플로](/ko/workflows/introduction)로 실행하려면 이 옵션을 켜세요.

- **또는 모든 목표를 워크플로로 실행**에는 팀 워크플로 목록이 있습니다. 항목에 마우스를 올리고 **모든 목표에 사용**을 클릭하거나, **새 팀 워크플로**를 클릭해 직접 만드세요.
- **작업 워크플로**에는 버그 수정처럼 리더가 단일 작업에 배정할 수 있는 워크플로가 나열됩니다. 리더 채팅에서 바로 지정하려면 **채팅에서 사용**을 클릭하고, 직접 만들려면 **새 워크플로**를 클릭하세요.

기본 제공 워크플로는 다음과 같습니다.

| 워크플로 | 작동 방식 |
| --- | --- |
| **Ship** | 아이디어를 사용자가 승인하는 명세, 설계, 계획으로 바꾼 뒤 테스트·검사·리뷰·검증을 거쳐 각 작업을 구현하고 마지막으로 브랜치 전체를 리뷰합니다. |
| **Planner** | 아이디어를 사용자가 승인하는 명세, 설계, 작업 목록으로 바꾸어 작업 계획 형태로 리더에게 넘깁니다. |
| **Sprint** | 계획된 단일 작업을 테스트·검사·리뷰·검증과 함께 구현합니다. |
| **Compound** | 축적된 교훈을 저장소의 문서와 규칙에 반영합니다. |
| **검증 설정** | 프로젝트를 확인하고 실행하는 방법을 파악해 사용자가 승인하는 검증 런북을 작성한 뒤 직접 실행해 검증합니다. |

각 행에는 워크플로 아이콘, 이를 수행하는 팀원의 프로필 아이콘, 실행 횟수와 실패 횟수가 표시됩니다. 워크플로에 팀원이 비어 있으면 해당 행에서 **에이전트 선택…**을 클릭하세요. 행을 클릭하면 워크플로가 열려 단계나 담당자를 변경할 수 있습니다.

프로젝트에서 워크플로를 수정해 저장하면 **초안** 상태로 남습니다: **게시**를 클릭하기 전까지 새 계획은 기존에 게시된 버전을 계속 사용합니다. **이전 버전으로 되돌리기**로 직전 버전을 복구할 수 있습니다. 작업의 워크플로에서는 각 단계의 토큰 수와 API 단가 기준 총비용을 확인할 수 있습니다.

### 검사 명령 설정

검사 명령은 완료된 작업이 리뷰로 넘어가기 전에 해당 작업의 코드 사본에서 실행됩니다. 검사에 실패하면 담당 팀원에게 돌아가 수정하게 됩니다.

1. **팀 및 설정** 탭에서 **프로젝트 설정**, **보드**를 차례로 클릭하세요.
2. **검사 명령** 옆의 **찾기**를 클릭하세요. Enconvo가 프로젝트 파일에서 명령을 읽어 오며, 실제로 통과할 때만 입력란에 채웁니다.
3. 찾지 못하면 **Mavis에게 설정 요청**(버튼에는 현재 리더 이름이 표시됨)을 클릭하세요. 리더가 채팅에서 명령을 찾거나 추가해 줍니다.

검사 명령이 없는 프로젝트에서는 검사 단계가 **검사 안 함**으로 표시됩니다.

### 워크트리 정리

git 프로젝트의 각 채팅과 작업은 고유한 워크트리에서 실행됩니다. 디스크 공간을 확보하기 위해 Enconvo는 작업이 끝난 워크트리를 보관 처리하고 폴더를 삭제합니다. **프로젝트 설정 → 워크트리**에서 다음을 설정하세요.

| 설정 | 작동 방식 |
| --- | --- |
| **병합된 워크트리 보관** | 작업이 기본 브랜치에 반영되었고 커밋되지 않았거나 푸시되지 않은 변경 사항이 없으면 워크트리를 보관합니다. |
| **채팅이 없는 워크트리 보관** | 채팅 목록에 해당 워크트리의 채팅이 하나도 남지 않으면 보관합니다. |
| **비활성 워크트리 보관** | **활동 없음 보관 기준**(3, 7, 14, 30일)에 설정한 기간 동안 활동이 없으면 워크트리와 채팅을 함께 보관합니다. |

커밋되지 않은 변경 사항이 있는 워크트리는 항상 유지됩니다. **복원**을 클릭하면 보관된 워크트리를 다시 불러옵니다.

## 팀의 확인 시점 선택

**팀 및 설정** 탭을 여세요.

**확인 요청 시점** 아래 설정:

| 설정 | 작동 방식 |
| --- | --- |
| **계획이 준비되었을 때** | 기본값인 **스마트**는 이미 요청한 범위 내의 작업이면 즉시 계획을 시작하고, 범위를 벗어나거나 위험이 있으면 **시작**을 기다립니다. **항상 묻기**는 매번 **시작**을 기다립니다. **항상 시작**은 계획이 준비되자마자 바로 시작합니다. |
| **할 일이 추가되자마자 계획 시작** | 켜짐: 새 아이디어가 추가되면 리더가 즉시 계획을 세웁니다. 꺼짐: 직접 시작할 때까지 **시작 전** 상태에서 대기합니다. |

어떤 옵션을 선택하든 삭제, 전송, 게시, 결제, 푸시 작업은 항상 확인을 요청합니다. 폴더, 워크트리, 권한, 예산, 경계 설정은 **프로젝트 설정**에 있습니다.

## 자리를 비운 동안 리더가 계속 작업하게 하기

**전체 접근** 권한으로 설정된 프로젝트에서는 채팅에 아무도 없더라도 작업 보고가 들어왔을 때 리더가 작업을 계속 이어갈 수 있습니다. **프로젝트 설정 → 보드**에서 **자리를 비운 동안 리드가 작업**을 켜세요.

그러면 리더가 시간당 최대 6턴, 하루 100,000포인트 한도 내에서 직접 수정, 재시도, 병합을 진행합니다. 작업 자체의 코드 사본 밖에서 전송, 푸시, 게시, 결제, 삭제 작업은 절대 수행하지 않습니다.

돌아오면 리더 채팅 상단의 **자리를 비운 동안** 카드에 리더가 수행한 내용과 사용자에게 남긴 후속 단계가 정리됩니다. 연속으로 2턴 실패하거나 한도에 도달하면 리더가 일시 중지하고 **확인 필요**에서 **재개** 또는 **일시 중지 유지**를 묻습니다.

## 프로젝트 보관하기

프로젝트가 끝나면 데이터를 삭제하지 않고 사이드바에서만 깔끔하게 치워 둘 수 있습니다.

1. 사이드바에서 프로젝트에 마우스를 올리고 **⋯**를 클릭하세요.
2. **프로젝트 보관**을 선택하세요.

프로젝트와 채팅이 사이드바에서 사라지고 예약 작업은 일시 중지됩니다. 보관된 프로젝트의 채팅은 복원하기 전까지 새 메시지를 받을 수 없습니다.

다시 불러오려면:

1. **설정 → 보관됨**을 여세요.
2. **프로젝트**를 클릭하세요.
3. 프로젝트 옆의 **복원**을 클릭하세요.

프로젝트와 채팅이 사이드바에 돌아오고 예약 작업도 다시 켜집니다.

## 휴대폰에서의 프로젝트

iPhone 앱에서도 프로젝트를 열 수 있습니다: 아이디어, 보드, 프로젝트 설정, **새 프로젝트**, 그리고 응답·병합·시작·재시도를 할 수 있는 작업 계획 카드를 모두 지원합니다. 휴대폰의 `@` 메뉴에는 프로젝트 팀원과 워크플로가 표시됩니다. [iPhone 앱](/ko/integrations/iphone-app)을 참고하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 새 아이디어가 **시작 전**에 머물러 있음 | **팀 및 설정**에서 **할 일이 추가되자마자 계획 시작**을 켜거나, 아이디어를 열어 직접 시작하세요. |
| **스마트**를 선택했는데도 계획이 실행되지 않고 대기함 | 요청한 범위를 넘어가거나 위험한 단계가 포함되어 있습니다. 확인 후 **시작**을 클릭하세요. |
| 코딩 에이전트 작업이 시작되지 않음 | 해당 코딩 에이전트를 설치하고 로그인하세요. |
| 작업이 로그인 경고와 함께 **보류됨** 상태로 대기함 | 코딩 에이전트에서 로그아웃되었거나 로그인 만료가 임박했습니다. **다시 로그인**을 클릭하세요. 로그인하면 보류된 작업이 다시 실행됩니다. |
| 보드 카드에 주황색 경고가 표시됨 | 설정 문제입니다. 카드의 해결 안내를 따르세요. 리더가 이를 자동으로 재시도하지는 않습니다. Enconvo 오류인 경우에는 다시 시도해도 안전하다는 안내가 표시됩니다. |
| iCloud에 저장된 프로젝트의 작업이 실패함 | Mac 저장 공간 최적화가 켜져 있으면 파일이 Mac에 내려받아져 있지 않을 수 있습니다. Finder에서 프로젝트 폴더에 대해 **다운로드된 상태로 유지**를 선택하세요. |
| 작업에서 프로젝트 폴더가 없다고 표시됨 | 폴더가 이동되었거나 삭제되었습니다. 원래 위치로 되돌리거나 새 위치로 프로젝트를 다시 만드세요. |
| 작업이 프로젝트의 **경계**에서 멈춤 | 작업 카드에서 **경계 편집**을 클릭해 필요한 범위를 허용하세요. 경계는 사용자만 변경할 수 있습니다. |
| 작업에 병합이나 리베이스가 절반만 진행된 상태로 남았다고 표시됨 | 에이전트가 도중에 중단되었습니다. 작업을 병합하기 전에 해당 병합이나 리베이스를 완료하거나 취소하세요. |
| 모든 계획이 **시작** 대기 상태로 멈춤 | Enconvo에서 로그아웃되어 있으면 계획이 대기합니다. **설정 → 계정**에서 로그인하세요. |
| 사이드바에 프로젝트가 보이지 않음 | 보관되었을 수 있습니다. **설정 → 보관됨**의 **프로젝트** 아래를 확인하세요. |
| 워크플로 작업이 실패함 | 해당 작업을 열어 보세요. 명령이 마지막으로 출력한 내용과 어느 팀원의 단계가 실패했는지 표시됩니다. |
| 목표가 선택한 팀 워크플로를 사용하지 않음 | **팀 및 설정** 탭에서 **사용자 지정 워크플로**를 켜세요. 꺼져 있으면 모든 목표가 **표준**으로 실행됩니다. |
