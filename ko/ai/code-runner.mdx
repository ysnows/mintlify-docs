---

코드 실행기는 에이전트에게 Mac의 실제 터미널을 제공합니다. 빌드, 테스트, 스크립트, 패키지 도구, 개발 서버에 사용하세요. 무엇을 실행할 수 있는지는 설치된 프로그램과 사용자 계정의 권한이 결정합니다.

<Warning>
에이전트의 **샌드박스**를 켜지 않으면 명령은 사용자 계정의 파일 및 네트워크 접근 권한으로 실제로 실행됩니다. 소프트웨어를 설치하거나, 파일을 변경하거나, 온라인 서비스에 영향을 주는 명령은 실행하기 전에 검토하세요.
</Warning>

## 시작하기 전에

- 사용하는 에이전트에 대해 코드 실행기를 켭니다.
- 채팅의 **권한** 칩이 에이전트가 언제 먼저 물어볼지 결정합니다. **승인 요청**은 명령을 실행하기 전에 묻고, **대신 승인**은 안전하지 않아 보이는 작업에 대해서만 묻습니다. [작업 승인](/ko/ai/agents)을 참고하세요.
- 에이전트의 명령을 작업 폴더 안으로 제한하고 키와 다른 앱에 접근하지 못하게 하려면 같은 칩에서 **샌드박스**를 켭니다. [에이전트 샌드박스](/ko/configuration/sandbox)를 참고하세요.

## 명령 실행

에이전트에게 폴더와 구체적인 작업을 알려 주세요.

> 내 샘플 프로젝트에서 기존 테스트 명령을 실행하고 결과를 알려 줘. 파일은 변경하지 마.

에이전트는 명령의 출력을 보여 주고 명령이 끝났는지 아직 실행 중인지 알려 줍니다. 파일을 읽고, 편집하고, 검색할 때는 에이전트가 대신 [파일 도구](/ko/ai/file-tools)를 사용합니다.

## 명령이 실행되는 방식

모든 명령은 의사 터미널에서 실행되므로 입력을 요구하는 명령에는 새 프로세스를 시작하지 않고도 답할 수 있습니다.

| 모드 | 용도 |
| --- | --- |
| **oneshot** | 테스트, 빌드, 스크립트처럼 스스로 끝나는 명령 |
| **long_running** | 서버, 감시자, 외부 이벤트를 기다리는 프로세스 |
| **interactive** | REPL, 터미널 앱, 대화형 명령줄 세션 |

`status: running`과 `session_id`가 포함된 결과는 프로세스가 계속 실행 중이라는 뜻입니다. 에이전트는 해당 프로세스의 출력을 **read**하고, 입력을 **write**하고, **stop**할 수 있습니다. 프롬프트에 답하려면 에이전트가 해당 세션에 write하며, 다른 명령을 시작한다고 해서 프롬프트에 답이 되지는 않습니다.

## 작업이 끝나기를 기다리기

빌드가 출력을 기록하거나 서버가 시작되기를 기다리는 것처럼 작업이 기다려야 할 때, 에이전트는 셸 루프 대신 **Wait For** 도구를 사용합니다. 실행 중인 명령 없이 다음 중 하나를 기다립니다.

- 파일이 나타나기
- 로그 파일에 특정 줄이 기록되기
- 프로세스 또는 명령의 세션이 종료되기
- 포트가 열리거나 주소가 응답하기

대기는 채팅의 백그라운드 작업에 표시됩니다. 에이전트는 조건이 충족되거나, 실패하거나, 시간이 초과되면 알림을 받으며, 그동안 다른 작업을 할 수 있습니다.

## 작업 폴더와 시간 제한

에이전트가 `workDir`을 지정하면 그곳에서, 그렇지 않으면 채팅의 작업 폴더에서 명령이 실행됩니다. 프로젝트와 Python 가상 환경이 설정된 사용자의 셸을 사용합니다. 별도의 명령은 같은 세션에서 실행하지 않는 한 임시 셸 변수를 공유하지 않습니다.

첫 대기는 명령의 강제 시간 제한과 별개입니다. oneshot 명령은 결과를 최대 30초간 기다리며, 그때까지 계속 실행 중이면 작업은 계속되는 상태에서 에이전트가 그때까지의 출력을 받습니다. 명령은 기본적으로 30분 후에 중지됩니다. 서버나 감시자에는 oneshot 명령이 실패한 것으로 취급하지 말고 long_running 모드를 사용하세요.

## 설정

**설정 → 플러그인 → 코드 실행기**를 엽니다.

| 설정 | 변경되는 내용 |
| --- | --- |
| **RTK 활성화** | 에이전트가 읽기 전에 긴 명령 출력을 압축하여 토큰을 덜 사용합니다. 기본값은 켜짐입니다 |

압축된 출력에 필요한 세부 정보가 없다면, 더 구체적인 명령이나 로그의 해당 부분을 요청하세요. 잘린 출력이 명령의 성공을 입증하지는 않습니다.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 명령을 찾을 수 없음 | 프로그램이 설치되어 있고 셸에서 사용할 수 있는지 확인하세요 |
| 명령이 입력을 기다림 | 에이전트가 같은 세션에서 프롬프트에 답하게 하세요. 아무도 줄 수 없는 입력을 기다리는 명령은 즉시 종료됩니다 |
| 권한이 거부됨 | 대상 경로와 macOS 권한을 확인하세요. 샌드박스가 켜져 있다면 단계 아래의 줄을 클릭하여 무엇이 차단되었는지 확인하세요 |
| 명령 시간이 초과됨 | 마지막 출력을 읽고, 다시 실행하기 전에 알맞은 모드를 선택하세요 |
| 서버가 계속 실행됨 | 더 이상 필요하지 않을 때 에이전트가 세션을 중지하게 하세요 |
