채팅을 비공개로 유지하고 싶거나 제공업체 계정 없이 쓰고 싶을 때, Mac이나 본인 소유의 다른 컴퓨터에서 모델을 실행하세요. Enconvo에는 내장 엔진이 있으며 Ollama와 LM Studio에도 연결됩니다.

## 런타임 고르기

| 런타임 | 이런 경우에 적합 | 설정 |
| --- | --- | --- |
| [Local LLM (MLX)](/ko/providers/mlx) | macOS 15 이상의 Apple Silicon Mac에서 Enconvo 안에 모델을 실행할 때 | 설정에서 모델을 고르고 다운로드 |
| [Ollama](/ko/providers/ollama) | 이미 Ollama로 관리하는 모델을 이 Mac이나 서버에서 쓸 때 | Ollama를 시작하고 주소 지정 |
| [LM Studio](/ko/providers/lm-studio) | 이미 LM Studio에서 쓰는 모델을 이 Mac이나 서버에서 쓸 때 | LM Studio 서버를 시작하고 주소 지정 |

## 작게 시작하기

1. 런타임을 설정하고 모델을 다운로드하거나 불러옵니다.
2. 짧은 텍스트 메시지를 보냅니다.
3. 잘 되면 문서나 도구를 추가합니다.
4. 더 큰 모델을 써 보기 전에 메모리 사용량과 속도를 확인하세요. **설정 → 로컬 모델**에서 이 Mac의 모델과 모델별 메모리 사용량을 볼 수 있습니다.

모델 크기, 양자화, 컨텍스트 길이, 실행 중인 다른 작업이 모두 메모리에 영향을 줍니다. 고정된 기준 대신 모델 선택기에 표시되는 크기를 참고하세요.

## 작업 전체를 로컬로 유지하기

로컬 채팅 모델만으로는 모든 것이 Mac 안에 머물지 않습니다. 음성 인식, 텍스트 음성 변환, OCR, 문서 파싱, 임베딩, 리랭킹, 검색, MCP 도구는 각자 별도의 제공업체를 사용합니다. Enconvo에는 이 가운데 여러 기능을 위한 로컬 제공업체가 있으며, [제공업체 카탈로그](/ko/providers/catalog)에서 확인할 수 있습니다.

**설정 → 로컬 모델**에서 어떤 기능이 이 Mac에서 실행되고 어떤 기능이 클라우드에서 실행되는지 볼 수 있습니다. 웹 검색과 기타 온라인 서비스는 여전히 인터넷이 필요하고, 로컬 모델도 내용을 Mac 밖으로 보내는 도구를 호출할 수 있습니다.

## 다른 컴퓨터의 모델 서버 사용하기

서버가 네트워크 연결을 받도록 설정하고, Enconvo의 **BaseUrl**을 그 컴퓨터의 주소로 지정하세요. `localhost`는 언제나 Enconvo가 실행 중인 Mac을 뜻합니다. macOS가 연결을 막으면 **시스템 설정 → 개인정보 보호 및 보안 → 로컬 네트워크**에서 Enconvo를 켜세요.

## 다른 모델 서버 사용하기

llama.cpp, vLLM, KoboldCpp, text-generation-webui 같은 서버는 **설정 → AI 모델** 하단의 **새 제공업체 추가**를 클릭하고 **OpenAI 호환**을 선택하세요. 서버 주소를 기본 URL로 붙여넣으세요. Enconvo는 `/v1`이 있든 없든, 전체 엔드포인트를 붙여넣어도 받아들입니다. 서버가 키를 확인하지 않는다면 API 키는 비워 두세요.

## 작은 컨텍스트에서의 긴 채팅

로컬 서버는 모델이 허용하는 것보다 작은 컨텍스트로 모델을 실행하는 경우가 많습니다. Enconvo는 Ollama, llama.cpp, LM Studio, KoboldCpp, text-generation-webui가 실제로 사용하는 컨텍스트를 읽고 그에 맞게 채팅을 압축합니다. 컨텍스트가 작으면 긴 채팅을 나누어 요약합니다. 모델에 더 많은 공간을 주려면 서버 자체 설정에서 컨텍스트 길이를 늘리세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 모델이 긴 채팅의 앞부분을 잊어버림 | 서버가 작은 컨텍스트로 실행 중입니다. 서버 설정에서 컨텍스트 길이를 늘리거나 새 채팅을 시작하세요. |
| 모델이 도구나 이미지를 무시함 | 모델이 이를 받지 않기 때문에 Enconvo는 그것 없이 답합니다. 도구 호출이나 이미지 입력을 지원하는 모델을 고르세요. |
| 연결에 실패함 | 오류를 읽어 보세요. Enconvo는 서버의 메시지를 그대로 보여 주고 원인을 알려 줍니다. 서버가 실행 중인지, 주소와 포트가 맞는지 확인하세요. |
