사실을 찾는 리서처, 이를 글로 정리하는 작성자, 변경을 맡는 코더와 리뷰어처럼 에이전트 하나로는 부족한 작업이 있습니다. 채팅에서 에이전트의 이름을 지정하면 대화 중인 에이전트가 리드가 됩니다. 리드는 작업 계획을 세우고, 각 멤버에게 작업을 배정하며, 결과가 목표에 맞는지 확인합니다. 계속 이어지는 작업이라면 [프로젝트](#프로젝트)가 한 폴더의 계획, 채팅, 파일을 한곳에 모아 줍니다.

아래 영상은 2분 이내로 전체 흐름을 보여줍니다. @로 에이전트 불러오기, 작업 계획, 보드, 프로젝트를 다룹니다.

## 여러 에이전트에게 작업 맡기기

1. 아무 채팅에서나 `@`와 에이전트 이름의 앞부분을 입력한 다음, Return을 눌러 목록에서 선택하세요. 작업에 필요한 만큼 에이전트를 추가할 수 있습니다.
2. 각 에이전트가 해야 할 일을 설명하고 전송하세요. 예: "@리서처가 교토 대나무 숲에 대한 사실 세 가지를 찾고, @작성자가 이를 짧은 글로 정리해 줘."
3. 리드가 작업 계획으로 답합니다. **목표**, 완료되려면 충족되어야 하는 조건(**완료 기준**), 제외되는 내용, 그리고 멤버별 작업 하나씩이 담깁니다. 각 작업에는 목표와 이 항목들이 문구 그대로 전달됩니다. 다른 작업의 결과가 필요한 작업은 그 작업이 끝나기를 기다렸다가, 해당 작업의 병합되지 않은 결과물을 합친 상태로 시작합니다.
4. 계획이 사용자의 확인을 기다리고 있다면 내용을 검토한 다음 **시작**, **계획 변경**, **취소** 중 하나를 클릭하세요. 멤버는 계획을 시작할 때 작업을 시작합니다.
5. 작업이 끝나면 계획 카드에 각 결과가 표시되고, 리드가 목표가 달성되었는지 알려줍니다.

작업은 프로젝트의 멤버가 아니더라도 사용자의 에이전트나 코딩 에이전트 누구에게나 팀원으로 맡길 수 있습니다. 요청에서 이름을 지정하고, 더 깊이 생각하게 하거나 더 빠르게 답하게 하려면 추론 노력 수준을 선택하세요.

Codex가 포함된 계획이 시작되면 Enconvo가 먼저 폴더 접근 권한을 요청하므로, 자리를 비운 사이에 실행이 멈추지 않습니다.

## 실행 중인 계획 따라가기

계획이 실행되는 동안 채팅 위의 한 줄에 목표, 진행 상황, 비용, 시간이 표시됩니다. 클릭하면 실행 보기가 열립니다. 각 작업의 단계, 찾아낸 내용, 제시한 근거, 멤버별 비용, 작업이 끝나지 못한 이유를 볼 수 있습니다.

일부 결과는 계획이 계속되기 전에 사용자의 확인을 기다립니다. 보류된 결과나 리뷰 지적을 수락하려면 **넘기기**를, 멤버가 고치게 하려면 **되돌려 보내기**를 클릭하세요.

## 결과 확인하기

계획이 끝나면 결과 카드의 맨 위에 최종 결과와 다음 단계가 표시됩니다. 그 아래에는 각 작업의 전체 결과가 있습니다. 코딩 작업에는 **병합** 버튼이 있고, 아직 병합할 작업이 있으면 해당 작업을 한 줄로 알려줍니다.

리드는 각 **완료 기준** 항목을 확인하고, 어떤 작업이 충족을 보여주는지 알려줍니다. 독립적인 검사가 작업에서 분명히 드러나지 않는 주장을 표시합니다. 목표가 아직 달성되지 않았다면 리드는 같은 목표를 위해 하나의 예산 안에서 최대 다섯 번까지 계획을 더 이어갈 수 있습니다.

리드는 이후 실행에서 계획에 반영할 교훈을 최대 세 가지까지 제안할 수도 있습니다. 각각 유지하거나 버릴 수 있으며, 유지한 것만 [메모리](/ko/ai/memory)에 반영됩니다.

## 보드 따라가기

채팅 상단의 **보드**를 클릭하면 채팅의 작업이 카드로 표시됩니다. 각 작업에는 T-1 같은 번호가 있고, **시작 대기**에서 **실행 중**을 거쳐 **완료**로 이동합니다. **확인 필요**에는 사용자의 답변이나 승인을 기다리는 항목이 모입니다.

| 컨트롤 | 기능 |
| --- | --- |
| **전체** / **확인 필요** | 모든 작업을 표시하거나, 사용자를 기다리는 작업만 표시합니다. |
| **그룹 기준** | 아이디어나 **채팅** 등으로 카드를 그룹화합니다. |
| **디스플레이** | 각 카드에 표시되는 내용을 변경합니다. |
| **작업 또는 T-12 검색** | 단어나 번호로 작업을 찾습니다. |

사이드바 아이콘 레일의 **···** 메뉴에 있는 **보드**에는 모든 채팅의 작업이 표시됩니다. 작업이 있는 채팅은 사이드바의 해당 행 아래에도 작업이 나열됩니다.

작업의 검사와 수정 라운드가 같은 문제를 계속 찾아내면 다시 시도하지 않고 라운드가 중단됩니다. 실행할 수 없는 검사는 정상 작동하는 코드를 돌려보내는 대신 그 사실을 알려줍니다.

## 프로젝트

프로젝트는 관련 채팅을 하나의 폴더를 중심으로 묶으며, 폴더의 `AGENTS.md`가 프로젝트의 지침이 됩니다. 사이드바의 **프로젝트** 옆 **+**를 클릭해 **프로젝트 만들기**를 여세요.

- **프로젝트 이름**을 입력하면 문서 폴더에 새 폴더가 만들어집니다. 또는 **기존 폴더 사용**이나 **저장소 복제**를 클릭하세요.
- **시작 템플릿**에서 **비어 있음** 또는 팀(**리서치 데스크**, **콘텐츠 스튜디오**, **앱 빌더**, **여행 플래너**)을 선택하세요.

### 저장소 복제

1. **프로젝트 만들기**에서 **저장소 복제**를 클릭하세요.
2. GitHub URL, `owner/name` 또는 아무 Git 주소를 붙여넣으세요. GitHub에 로그인되어 있다면 목록에서 내 저장소를 선택할 수도 있습니다.
3. **복제**를 클릭하세요. 저장소가 새 폴더로 복사되고 프로젝트로 열립니다.

### 누가 작업하나요

멤버가 있는 프로젝트에서는 리드가 각 목표를 계획하고, 멤버가 이를 구현하며, 리뷰나 테스트가 확인합니다. 멤버에는 Claude Code, Codex 같은 코딩 에이전트도 포함될 수 있습니다. 각 코딩 작업은 코드의 자체 복사본에서 진행되며, 준비가 되면 계획의 결과 카드에 있는 **병합** 버튼을 사용하세요.

Claude Code, Codex, Grok Build, Antigravity는 프로젝트를 이끌 수 있습니다. 멤버가 있으면 코딩 에이전트 리드는 다른 리드와 마찬가지로 작업 계획에서 멤버의 작업을 계획하고 결과를 읽습니다. 멤버가 없는 프로젝트에서는 멤버를 추가하기 전까지 작업 계획이나 보드 작업 없이 채팅에서 직접 작업합니다.

프로젝트의 리드 채팅에서는 요청의 일부를 Opus 5.5처럼 이름으로 모델에 맡길 수 있고, Opus 5.5의 Claude Code처럼 에이전트와 모델을 함께 지정할 수도 있습니다. 리드는 자신의 작업을 위해 하위 에이전트를 시작할 수도 있습니다. 프로젝트는 자체 워크플로로 목표와 작업을 실행할 수 있습니다. [나만의 워크플로 사용하기](/ko/ai/projects)를 참고하세요.

멤버는 계획을 시작하거나, 승인하거나, 설정을 변경하거나, 소프트웨어를 설치하거나, 사용자의 로그인을 사용할 수 없습니다. 코딩 에이전트 멤버는 푸시하거나, 다른 브랜치를 옮기거나, 워크트리를 제거할 수 없으며, 병합과 푸시는 Enconvo만 수행합니다. 프로젝트 리드 채팅과 작업에서의 전체 접근은 다른 채팅과 똑같이 동작합니다. 보드, 아이디어, 프로젝트 설정은 [프로젝트와 보드](/ko/ai/projects)를 참고하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| Return을 눌렀더니 에이전트가 선택되지 않고 메시지가 전송됨 | 입력창 아래에 에이전트 목록이 나타날 때까지 기다린 다음 Return을 누르세요. |
| 작업이 **확인 필요**에서 멈춤 | 작업이나 채팅을 열어 대기 중인 질문이나 승인에 답하세요. |
| 코딩 에이전트를 시작할 수 없음 | 먼저 설치하고 로그인하세요. [코딩 에이전트](/ko/ai/coding-agents)를 참고하세요. |
| Codex 계획이 폴더 접근 권한을 묻느라 멈춤 | 계획이 시작될 때 폴더 접근 질문에 답하면 사용자 없이도 실행이 계속됩니다. |
