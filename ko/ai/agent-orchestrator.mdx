어떤 작업은 여러 에이전트가 함께해야 더 잘 풀립니다. 자료를 찾는 리서처, 이를 글로 다듬는 라이터, 코드를 작성하는 코더와 리뷰어가 필요한 경우입니다. 채팅에서 에이전트들을 호출하면 현재 대화 중인 에이전트가 리더가 됩니다. 리더는 작업 계획을 작성하고 각 팀원에게 작업을 배분하며 목표 달성 여부를 검증합니다. 지속적인 작업이라면 [프로젝트](#프로젝트)를 통해 하나의 폴더를 중심으로 계획, 채팅, 파일을 함께 관리하세요.

아래 영상에서는 2분 내외로 `@`로 에이전트 불러오기, 작업 계획, 보드, 프로젝트의 전체 흐름을 보여줍니다.

## 여러 에이전트에게 작업 맡기기

1. 아무 채팅에서나 `@`와 에이전트 이름의 첫 글자를 입력한 뒤 Return을 눌러 목록에서 선택하세요. 작업에 필요한 만큼 여러 에이전트를 추가할 수 있습니다.
2. 각 에이전트가 할 일을 설명하고 전송하세요. 예시: "@Researcher 교토 대나무 숲에 대한 사실 세 가지를 찾아줘. 그다음 @Writer가 그 내용을 짧은 글로 작성해 줘."
3. 리더가 **목표**, 완료 기준(**완료 조건**), 제외 범위, 그리고 각 팀원의 작업이 담긴 작업 계획으로 응답합니다. 각 작업에는 목표와 이 항목들이 토씨 하나 안 틀리고 그대로 전달됩니다. 다른 작업의 결과가 필요한 작업은 앞선 작업이 끝날 때까지 기다렸다가, 그 작업의 아직 병합되지 않은 변경 사항까지 합쳐진 상태에서 시작합니다.
4. 계획이 승인을 기다리면 내용을 확인한 뒤 **시작**, **계획 변경**, **취소** 중 하나를 클릭하세요. 계획을 시작하면 팀원들이 작업을 개시합니다.
5. 작업이 모두 끝나면 계획 카드에 각 결과가 표시되고, 리더가 목표 달성 여부를 알려줍니다.

프로젝트 팀원이 아니더라도 내가 가진 모든 에이전트나 코딩 에이전트를 팀원으로 지정해 작업을 맡길 수 있습니다. 요청 시 이름을 지정하고, 더 깊이 추론하거나 빠르게 답하게 하려면 추론 강도도 선택하세요.

Codex가 포함된 계획이 시작될 때는 사용자가 자리를 비운 사이 멈추지 않도록 먼저 폴더 접근 권한을 요청합니다.

## 실행 중인 계획 추적하기

계획이 실행되는 동안 채팅 상단의 한 줄에 목표, 진행률, 비용, 소요 시간이 표시됩니다. 클릭하면 실행 보기가 열려 각 작업의 단계, 발견한 내용, 제시한 근거, 팀원별 비용, 작업이 통과하지 못한 이유를 확인할 수 있습니다.

일부 결과는 계획이 다음으로 넘어가기 전에 사용자의 확인을 기다립니다. 보류된 결과나 리뷰 지적 사항을 수락하려면 **통과**, 팀원이 수정하게 하려면 **반려**를 클릭하세요.

## 결과 확인하기

계획이 끝나면 결과 카드 상단에 결론과 다음 단계가 요약됩니다. 아래에는 각 작업의 전체 결과가 나열됩니다. 코딩 작업에는 **병합** 버튼이 제공되며, 아직 병합해야 할 작업이 남아 있으면 한 줄로 안내합니다.

리더는 각 **완료 조건** 항목을 점검하고 어떤 작업이 이를 충족했는지 설명합니다. 또한 독립적인 검증 단계에서 작업 결과가 명확히 입증하지 못한 주장을 짚어 줍니다. 목표가 아직 달성되지 않았다면 리더는 하나의 예산 내에서 최대 다섯 번까지 같은 목표를 위한 후속 계획을 이어갈 수 있습니다.

리더는 이후 실행에서 참고할 수 있도록 최대 세 가지 교훈을 제안하기도 합니다. 각 항목을 유지할지 버릴지 고르세요: 유지한 항목만 [메모리](/ko/ai/memory)에 저장됩니다.

## 보드 따라가기

채팅 상단의 **보드**를 클릭하면 작업들을 카드 형태로 볼 수 있습니다. 각 작업에는 `T-1` 같은 번호가 붙으며 **시작 전**에서 **실행 중**, **완료**로 이동합니다. **확인 필요**에는 사용자의 답변이나 승인을 기다리는 항목이 모입니다.

| 제어 항목 | 기능 |
| --- | --- |
| **전체** / **확인 필요** | 모든 작업을 보거나 내 확인을 기다리는 작업만 봅니다. |
| **그룹 기준** | 아이디어별 또는 **채팅**별 등 카드를 묶어 표시합니다. |
| **표시** | 각 카드에 나타낼 정보를 바꿉니다. |
| **작업 또는 T-12 검색** | 단어나 작업 번호로 작업을 찾습니다. |

사이드바 아이콘 레일의 **···** 메뉴에 있는 **보드**에서는 모든 채팅의 작업을 한 번에 볼 수 있습니다. 작업이 있는 채팅은 사이드바의 채팅 행 아래에도 해당 작업들을 나열합니다.

작업의 검사 및 수정 라운드에서 같은 문제가 반복해서 발견되면 계속 재시도하는 대신 라운드를 중단합니다. 실행 자체가 불가능한 검사도 멀쩡한 코드를 되돌려 보내는 대신 실행할 수 없는 이유를 알려줍니다.

## 프로젝트

프로젝트는 하나의 폴더를 중심으로 관련 채팅을 묶어 관리하며, 해당 폴더의 `AGENTS.md`가 프로젝트 지침이 됩니다. 사이드바에서 **프로젝트** 옆의 **+**를 클릭해 **프로젝트 만들기**를 여세요.

- **프로젝트 이름**을 입력해 문서 폴더에 새 폴더를 만들거나, **기존 폴더 사용** 또는 **저장소 복제**를 클릭하세요.
- **시작 템플릿** 아래에서 **빈 프로젝트** 또는 팀 템플릿(**Research Desk**, **Content Studio**, **App Builders**, **Trip Planner**)을 고르세요.

### 저장소 복제

1. **프로젝트 만들기**에서 **저장소 복제**를 클릭하세요.
2. GitHub URL, `owner/name` 또는 임의의 Git 주소를 붙여넣으세요. GitHub에 로그인되어 있다면 목록에서 내 저장소를 바로 고를 수도 있습니다.
3. **복제**를 클릭하면 새 폴더로 저장소가 복제되고 프로젝트로 열립니다.

### 작업 수행 주체

팀원이 있는 프로젝트에서는 리더가 목표마다 계획을 세우고, 팀원이 구현하며, 리뷰나 테스트 단계가 결과를 검증합니다. Claude Code나 Codex 같은 코딩 에이전트도 팀원이 될 수 있습니다. 각 코딩 작업은 자체 코드 사본에서 실행되며, 준비가 되면 계획의 결과 카드에 있는 **병합** 버튼으로 합칠 수 있습니다.

Claude Code, Codex, Grok Build, Antigravity가 프로젝트 리더가 될 수도 있습니다. 팀원이 있다면 코딩 에이전트 리더 역시 다른 리더처럼 작업 계획으로 팀원들의 작업을 계획하고 결과를 읽습니다. 팀원이 없는 프로젝트에서는 팀원을 추가하기 전까지 작업 계획이나 보드 작업 없이 채팅 안에서 직접 작업을 수행합니다.

프로젝트의 리더 채팅에서는 요청 일부를 Opus 5.5처럼 모델 이름으로 지정해 맡기거나, Claude Code + Opus 5.5처럼 에이전트와 모델을 함께 지정할 수 있습니다. 리더는 자체 작업을 위해 하위 에이전트를 시작할 수도 있습니다. 프로젝트의 목표와 작업을 전용 워크플로로 실행하는 방법은 [자체 워크플로 사용](/ko/ai/projects)을 참고하세요.

팀원은 계획을 임의로 시작하거나, 항목을 승인하거나, 설정을 바꾸거나, 소프트웨어를 설치하거나, 사용자의 로그인 세션을 사용할 수 없습니다. 코딩 에이전트 팀원은 푸시하거나, 다른 브랜치를 옮기거나, 워크트리를 삭제할 수 없으며 오직 Enconvo만 병합과 푸시를 수행합니다. 프로젝트 리더 채팅과 작업에서의 **전체 접근** 권한은 다른 일반 채팅과 동일하게 작동합니다. 보드, 아이디어, 프로젝트 설정에 대한 자세한 내용은 [프로젝트와 보드](/ko/ai/projects)를 참고하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 에이전트를 고르는 대신 Return 키로 메시지가 전송됨 | Return을 누르기 전에 입력창 아래에 에이전트 목록이 뜰 때까지 잠시 기다리세요. |
| 작업이 **확인 필요** 상태에 멈춰 있음 | 해당 작업이나 채팅을 열어 대기 중인 질문이나 승인 요청에 답하세요. |
| 코딩 에이전트가 시작되지 않음 | 먼저 설치하고 로그인해야 합니다. [코딩 에이전트](/ko/ai/coding-agents)를 참고하세요. |
| Codex 계획이 폴더 접근 권한을 묻느라 멈춤 | 자리를 비우기 전에 계획 시작 시 표시되는 폴더 접근 질문에 먼저 답하세요. |
