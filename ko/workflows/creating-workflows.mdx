이 가이드는 워크플로 편집기에서 하는 모든 작업을 다룹니다. 워크플로 시작하기, 캔버스나 YAML로 만들기, 어시스턴트에게 편집 맡기기, 실행하기, 결과 읽기입니다. 마지막 섹션은 파일 형식과 각 단계 유형에 대한 참조입니다.

편집기를 열려면 채팅 창 사이드바에서 **워크플로**를 선택하거나 **설정 → 워크플로 → 관리**를 엽니다. 그런 다음 **새 워크플로**를 선택하거나 **편집**으로 기존 워크플로를 엽니다. 채팅 창에서는 다른 채팅으로 갔다가 돌아와도 편집 중이던 워크플로가 열려 있습니다.

이 페이지는 다음 순서로 구성되어 있습니다.

- 시작하기: [핵심 개념](#핵심-개념), [워크플로 목록](#워크플로-관리하기), [새 워크플로 시작하기](#새-워크플로-시작하기).
- 만들기: [시각화 편집기](#시각화-편집기로-만들기), [단계 동작](#단계-동작), [편집 어시스턴트](#편집-어시스턴트-사용하기).
- 실행하기: [워크플로 실행과 결과 읽기](#실행하고-확인하기).
- 참조: [YAML 파일](#yaml-편집), [이전 결과 참조하기](#이전-결과-참조하기), [모든 단계 유형](#단계-유형).

## 핵심 개념

- 워크플로는 **입력**을 선언한 다음, 순서가 있는 단계 목록을 각각 담은 하나 이상의 작업을 선언합니다. 개요는 [워크플로](/ko/workflows/introduction)를 참고하세요.
- 작업 안의 단계는 위에서 아래로 실행됩니다. 작업은 다른 작업을 기다리지 않는 한 나란히 실행됩니다.
- 단계는 `{{ inputs.topic }}`이나 `{{ steps.fetch.output }}`처럼 `{{ }}` 템플릿으로 실행 입력과 이전 결과를 읽습니다.
- 워크플로 편집과 실행은 별개의 동작입니다. 저장하면 파일이 기록되고, 실행하면 실제 모델과 도구를 호출합니다.

## 워크플로 관리하기

워크플로 목록에서는 워크플로를 열고, 실행하고, 정렬하고, 찾고, 삭제합니다.

### 워크플로 목록

각 행에는 워크플로의 단계 수, 마지막으로 편집한 시기, 마지막 실행 결과가 표시됩니다.

- 마지막 실행을 선택하면 해당 실행의 결과가 캔버스에 표시된 상태로 워크플로가 열립니다.
- 재생 버튼을 선택하면 워크플로를 열고 즉시 실행합니다. 채우지 않은 입력이 필요하면 **입력** 패널이 먼저 열립니다. 워크플로가 실행되는 동안 재생 버튼은 중지 버튼으로 바뀌며, 이를 선택하면 워크플로를 열지 않고도 실행을 중지합니다.
- 일정에 따라 실행되는 워크플로에는 다음 실행 시각이 표시되며, 모든 예약 작업이 꺼져 있으면 **예약 일시 중지됨**이 표시됩니다. 선택하면 실행 기록 패널에서 일정과 함께 워크플로가 열립니다.
- 복사 버튼을 선택하면 새 제목으로 워크플로를 복제하므로 원본을 건드리지 않고 사본을 바꿀 수 있습니다. 목록이 사본으로 스크롤되고 강조 표시됩니다.
- 목록 위의 정렬 메뉴에서 **최근 편집순**, **최근 실행순**, **이름**으로 워크플로를 정렬합니다. 선택한 정렬은 기억됩니다.

목록은 다시 돌아왔을 때와 예약된 실행이 시작될 때 자동으로 업데이트됩니다.

### 워크플로 찾기

**워크플로 검색**에 입력하면 입력하는 동안 목록이 업데이트됩니다. 지우기 버튼이나 Esc를 누르면 모든 워크플로가 다시 표시됩니다.

행의 태그를 선택하면 해당 태그가 있는 워크플로만 표시되며, **워크플로 검색**과 함께 작동합니다. 행에는 태그가 최대 네 개 표시되며, **+N**을 선택하면 나머지를 볼 수 있습니다. 모든 워크플로를 다시 표시하려면 태그를 다시 선택하거나, 목록 위 태그 옆의 ×를 선택하거나, **워크플로 검색**에서 Esc를 누르세요.

| 키 | 워크플로 목록에서 |
| --- | --- |
| **⌘F** 또는 **/** | **워크플로 검색**으로 이동 |
| **워크플로 검색**에서 ↓ | 첫 번째 워크플로로 이동 |
| ↑ 및 ↓ | 워크플로 사이 이동 |
| Return | 선택한 워크플로 열기 |
| Delete | 선택한 워크플로 삭제 |

### 워크플로 이름 바꾸기 또는 삭제하기

워크플로 이름을 바꾸려면 편집기 맨 위의 이름을 선택하고 새 이름을 입력한 뒤 Return을 누르세요. Esc를 누르면 이전 이름이 유지됩니다.

워크플로를 삭제하면 실행 중일 때는 먼저 실행이 중지됩니다. 해당 워크플로를 실행하는 [예약 작업](/ko/workflows/scheduled-jobs)은 일시 중지된 채 보관되므로 다른 워크플로를 지정하거나 삭제할 수 있습니다. 확인 창에서 삭제하기 전에 몇 개인지 알려 줍니다.

## 새 워크플로 시작하기

**새 워크플로**를 선택하면 시작 방법이 있는 대화상자가 열립니다. 먼저 어떤 종류의 워크플로인지 선택하세요.

- **작업 워크플로**: 한 종류의 작업을 처리하는 방법입니다.
- **팀 워크플로**: 여러 멤버가 목표를 계획에서 완료까지 진행하는 방법입니다. 템플릿으로 **계획, 구현, 검토**와 **멤버 한 명**이 있습니다.

아직 워크플로가 없으면 워크플로 목록에 같은 시작 방법이 바로 표시됩니다. **할 일을 설명하기**, **빈 워크플로**, 템플릿입니다.

| 시작 방법 | 사용법 |
| --- | --- |
| 설명하기 | 워크플로가 해야 할 일을 적고(예: "텍스트를 일본어와 스페인어로 동시에 번역해 줘") **만들기**를 선택하거나 **⌘↩**을 누릅니다. 어시스턴트가 이미 워크플로를 만들고 있는 상태로 워크플로가 열립니다. 단계를 검토하고 괜찮아 보이면 **저장**을 선택하세요. |
| 템플릿에서 시작 | **빈 워크플로**, **주제 조사**, **웹 페이지 요약**, **YouTube 동영상 노트**, **작성하고 소리 내어 읽기**, **단계 종류 둘러보기**(셸 명령어, 도구, 프롬프트, 에이전트가 있고 두 작업이 나란히 실행됨) 중에서 고릅니다. 모든 템플릿은 바로 실행할 수 있는 완전한 워크플로입니다. |
| 파일 가져오기 | **파일 선택…**을 선택하거나, 동료가 공유한 파일 같은 `.yaml`, `.yml`, `.json` 워크플로 파일을 대화상자 아무 곳에나 끌어다 놓습니다. 새 워크플로로 저장되므로 이미 있는 워크플로를 대체하지 않습니다. 제목이 목록에 있는 것과 같으면 "News copy"처럼 사본 이름이 붙습니다. 파일이 올바른 워크플로가 아니면 대화상자가 열린 채로 이유를 알려 줍니다. |
| 붙여 넣기 | 채팅에서 공유된 것과 같은 워크플로의 YAML 또는 JSON을 설명 상자에 붙여 넣습니다. **만들기**가 **가져오기**로 바뀌며, 붙여 넣은 그대로 워크플로가 생성됩니다. |

### 기본 제공 워크플로

Enconvo에 포함된 워크플로는 읽기 전용으로 열립니다. 변경하려면 **사본 만들기**를 선택하고 사본을 편집하세요.

### 워크플로 공유하기

워크플로를 공유하거나 사본을 보관하려면 워크플로 목록의 행이나 편집기 도구 모음에서 공유 버튼(다운로드 아이콘)을 선택하세요.

- **YAML 파일로 내보내기…**는 선택한 위치에 `.yaml` 파일을 저장합니다. 아무 Mac에서나 **새 워크플로** > **파일 선택…**으로 가져올 수 있습니다.
- **YAML 복사**는 워크플로를 복사하며, 채팅이나 **새 워크플로** 설명 상자에 붙여 넣으면 가져옵니다.

편집기에서 사용하면 둘 다 아직 저장하지 않은 변경 사항을 포함합니다.

## 시각화 편집기로 만들기

  <img src="/images/guides/workflow-visual.jpg" alt="병렬 작업 두 개와 단계 인스펙터가 있는 실제 Enconvo 워크플로 그래프" />
</Frame>

편집기에는 같은 워크플로를 보는 두 가지 방법이 있습니다.

- **시각화**: 단계를 캔버스의 카드로 보여 주며, 병렬 작업이 나란히 표시됩니다.
- **단계**: 단계를 위에서 아래로 조건, 반복, 병렬 단계와 함께 나열합니다. 두 단계 사이의 **추가** 메뉴로 그 자리에 단계를 삽입하세요.

헤더의 **가이드**를 선택하면 워크플로를 사용자의 언어로 쉽게 설명해 줍니다.

1. 편집기 도구 모음에서 **시각화**를 선택합니다.
2. 노드 사이의 **여기에 단계 추가**로 단계를 삽입하거나, 별도의 분기에는 **병렬 작업 추가**를 사용합니다. 단계 목록은 최근에 고른 단계와 도구인 **최근 사용**으로 열리므로, 자주 추가하는 항목은 한 번의 클릭으로 추가할 수 있습니다. 도구가 많은 플러그인은 처음 여덟 개를 나열하며, **N개 더 보기**를 선택하면 나머지를 볼 수 있고 입력해서 검색할 수도 있습니다.
3. 단계를 선택하면 인스펙터가 열립니다. ID, 제목, 실행기 설정을 편집하고, **동작**을 열어 실행 방식을 바꿉니다.
4. **입력** 노드를 선택하면 워크플로가 선언한 입력을 구성할 수 있습니다. 이름, 유형(텍스트, 숫자, 참/거짓, 목록 또는 객체), 설명, 기본값, 실행에 값이 필요한지 여부입니다. 각 이름 아래에는 단계가 입력을 읽는 방식(`{{ inputs.topic }}` 등)과 읽는 단계 수가 표시됩니다. 입력 이름을 바꾸면 해당 단계가 새 이름으로 업데이트됩니다. 이름에는 문자, 숫자, 밑줄을 사용할 수 있으며 숫자로 시작할 수 없고 다른 입력과 같을 수 없습니다.
5. 그래프를 검토하고 편집하는 동안 **실행 취소** 또는 **다시 실행**을 사용하세요.
6. 변경 사항을 검토한 뒤 **저장**을 선택합니다.

### 단계 카드 읽기

각 단계 카드에는 단계 이름이 표시되고, 그 아래에 단계가 하는 일이 표시됩니다. 도구 또는 단계 종류, 그다음 *웹 검색 · ‹topic› 뉴스*나 프롬프트의 첫 단어처럼 주요 설정의 시작 부분입니다. 입력과 이전 단계에서 읽는 값은 이름과 함께 ‹ ›로 표시됩니다. 이름이 없는 단계는 ID를 말로 풀어서 표시하며, 카드 위에 마우스를 올리면 ID를 볼 수 있습니다.

도구 단계의 카드에는 해당 플러그인의 아이콘이 표시됩니다. 카드의 작은 표시는 단계가 실행되는 방식을 보여 줍니다. 조건이 참일 때만, 목록의 항목마다 한 번씩, 반복, 실패하면 재시도, 이전 단계가 실패해도 실행, 또는 실패해도 워크플로 계속 진행입니다. 표시 위에 마우스를 올리면 의미를 읽을 수 있으며, 단계의 **동작** 섹션에서 변경합니다.

### 단계 고르기

단계 선택기는 기본 제공 단계, 설치된 도구, MCP 도구를 검색합니다. Enconvo 창을 열기만 하거나 공급자의 모델과 음성을 나열하기만 하는 도구는 제외하지만, 워크플로는 YAML에서 이름으로 호출할 수 있습니다.

어떤 것이 필요한지 모르겠다면 "기사를 세 줄로 요약해 줘"처럼 단계가 해야 할 일을 입력하고, 선택기 맨 아래의 **어시스턴트에게 추가 요청**(**⌘↩**)을 선택하세요. 일치하는 항목이 없을 때는 Return을 눌러도 같습니다. 어시스턴트는 선택기를 연 바로 그 위치, 즉 이웃 단계의 앞이나 뒤 또는 새 병렬 작업으로 단계를 추가하며, 다른 어시스턴트 답변처럼 되돌릴 수 있습니다.

### 단계 편집하기

인스펙터에는 **설정**과 **출력** 탭이 있습니다. **단계 실행**은 선택한 단계를 실행하며, 실제 도구 호출이나 셸 명령어를 수행할 수 있습니다. 개별 단계를 실행하기 전에 필요한 상위 값이 있는지 확인하세요.

**설정** 탭은 단계 카드에 표시되는 단계의 **이름**과, 다른 단계가 결과를 읽을 때 사용하는 **단계 id**로 시작합니다. **하는 일**은 단계의 도구나 종류를 나타냅니다.

단계가 다른 일을 하게 하려면 **변경**을 선택하고 다른 도구나 단계 종류를 고르거나, 해야 할 일을 설명하고 **어시스턴트에게 변경 요청**을 선택하세요.

- 단계는 ID를 유지하므로 결과를 읽는 단계는 계속 작동합니다.
- 언제 어떻게 실행되는지, 즉 조건, 반복, 재시도, 기다리는 대상도 유지됩니다.
- 새 도구의 설정은 비어 있는 상태로 시작합니다. 에이전트가 되는 프롬프트나 프롬프트가 되는 에이전트는 텍스트, 모델, 출력 스키마를 유지합니다.
- 편집기가 단계에 붙인 이름은 새 도구를 따라가며, 직접 쓴 이름은 그대로 유지됩니다.

**실행 취소**를 선택하면 되돌립니다.

### 단계 복제, 순서 변경, 끄기

단계를 재사용하려면 인스펙터에서 또는 단계 카드에 마우스를 올렸을 때 **복제**를 선택하세요. 사본은 단계의 모든 설정을 유지하고, 원본 바로 뒤에 나타나며, `fetch_2`처럼 사용 가능한 다음 ID를 받습니다.

작업 안의 단계는 위에서 아래로 실행됩니다. 순서를 바꾸려면 작업 안에서 단계 카드를 위나 아래로 끌어다 놓으세요. 다른 카드가 비켜서 놓일 위치를 보여 줍니다. 단계를 선택하고 인스펙터에서 **위로 이동** 또는 **아래로 이동**을 선택하거나 **⌥↑** 또는 **⌥↓**을 눌러도 됩니다. 이동을 취소하려면 **⌘Z**를 누르세요. 단계가 자신이 결과를 읽는 단계 위로 가면, 아래로 되돌릴 때까지 카드에 경고가 표시됩니다.

단계를 삭제하지 않고 당분간 빼 두려면 단계를 선택하고 **단계 끄기**를 선택하세요. 카드가 흐려지며 **끔**이 표시되고, 실행은 이 단계를 건너뛰며, 뒤따르는 단계는 계속 실행됩니다. **단계 켜기**를 선택하면 되돌립니다.

### 여러 단계 함께 다루기

여러 단계를 한꺼번에 바꾸려면 ⌘ 또는 Shift를 누른 채 카드를 클릭하세요. 캔버스 맨 위의 막대에 선택한 단계 수가 표시되며, 모두에 대한 **끄기**(또는 **켜기**)와 **삭제**가 있습니다. Esc를 누르거나 캔버스의 빈 곳을 클릭하면 선택이 해제되고, **⌘Z**로 실행을 취소합니다.

삭제하면 다른 단계가 망가지거나 작업이 비게 되는 경우 Enconvo가 먼저 묻습니다. 확인 창에는 삭제하려는 단계에 의존하는 각 단계와 **출력을 사용함**이나 **완료될 때까지 기다림** 같은 이유가 나열됩니다. 하나를 선택하면 삭제를 취소하고 그 단계를 열어 먼저 고칠 수 있습니다. 단계 하나를 삭제할 때도 마찬가지입니다.

단계를 복사하려면 하나를 선택하거나(또는 여러 개를 고르고) **⌘C**를 누르거나 막대에서 **복사**를 선택하세요. **⌘X**는 잘라 냅니다. 그런 다음 뒤에 놓을 단계를 선택하고 **⌘V**를 누릅니다.

- 사본은 그 단계 바로 뒤에, 작업이 선택된 경우에는 작업의 맨 끝에 놓이며 설정이 유지됩니다.
- ID가 이미 사용 중인 사본은 `fetch_2`처럼 새 ID를 받으며, 서로를 읽는 붙여 넣은 단계는 새 이름을 따릅니다.
- 단계는 다른 워크플로에도 같은 방식으로 붙여 넣을 수 있으며, **⌘V**는 워크플로 파일에서 복사한 YAML 또는 JSON 단계 목록도 받습니다.

단계를 삭제하거나 붙여 넣으면 무엇이 바뀌었는지 알림이 표시되며, 알림의 실행 취소를 선택하면 그 변경을 되돌립니다.

### 찾기, 확대, 저장, 실행

- 큰 워크플로에서 단계로 이동하려면 **⌘F**를 누르거나 캔버스의 검색 버튼을 선택하고, 단계의 이름, ID, 도구 또는 텍스트의 일부를 입력해 고르세요. 단계가 선택되고 화면에 표시됩니다.
- 캔버스 오른쪽 아래 모서리의 확대/축소 컨트롤을 사용하세요. 확대/축소 수준을 선택하면 100%로 돌아갑니다.
- **단계 찾기**를 선택하거나 캔버스에서 **⌘F**를 누르고 단계 이름의 일부를 입력하면 그 단계가 선택되고 화면에 표시됩니다. 읽기 전용 기본 제공 워크플로에서도 작동합니다.
- 시각화든 YAML이든, 단계 설정에 입력하는 중이더라도 편집기 어디서나 **⌘S**를 눌러 저장합니다.
- **⌘↩**을 누르면 워크플로를 실행합니다. 변경 사항이 있으면 먼저 저장됩니다. YAML 편집기, 어시스턴트, 기타 여러 줄 필드에서는 대신 **실행**을 선택하세요.
- 실행 중에는 **실행**이 **중지**로 바뀝니다. 선택하면 실행이 중지될 때까지 **중지하는 중…**이 표시됩니다.

단계의 프롬프트가 비어 있거나 설명이 없는 것처럼 워크플로에 문제가 있으면 저장과 실행이 중단되고 고칠 내용을 알려 줍니다. **보기**를 선택하면 해당 단계 또는 워크플로의 제목과 설명이 열립니다. 문제가 있는 단계는 카드에 빨간 표시가 있으며, 그 위에 마우스를 올리면 무엇이 잘못되었는지 읽을 수 있습니다. YAML에서는 **검증**을 선택해 전체 문서를 확인하세요.

### 저장되지 않은 변경 사항

워크플로에 저장되지 않은 변경 사항이 있는 동안 편집기 헤더에 **저장되지 않음**이 표시됩니다. 선택하면 마지막 저장 이후 추가되거나 삭제된 YAML 줄을 볼 수 있으며, **변경 사항 삭제**를 선택하면 저장된 버전으로 돌아갑니다. 시각화 편집기에서는 **⌘Z**로 변경 사항을 되살립니다. 저장하지 않은 변경 사항이 있는 채로 워크플로 목록으로 돌아가면 **저장하고 나가기**, **버리기**, **계속 편집** 중에서 고르세요.

저장되지 않은 변경 사항은 편집하는 동안 이 Mac에도 보관됩니다. 저장하기 전에 창이 닫히거나 새로 고쳐지면, 워크플로를 다시 열었을 때 맨 위에 **복원**이 있는 막대가 표시되며, 이를 선택하면 변경 사항이 실행 취소할 수 있는 한 단계로 되돌아오고 **버리기**를 선택할 수도 있습니다. 저장된 워크플로가 그 이후 바뀌지 않은 경우에만 변경 사항이 다시 제공됩니다. 워크플로 목록에서 이런 워크플로에는 **저장되지 않은 변경 사항** 태그가 표시되며, 삭제하면 해당 변경 사항도 함께 삭제됩니다.

### 캔버스 단축키

| 단축키 | 기능 |
| --- | --- |
| **⌘S** | 저장 |
| **⌘↩** | 실행(먼저 저장) |
| **⌘F** | 단계 찾기 |
| **⌘Z** | 실행 취소 |
| **⌘C**, **⌘X**, **⌘V** | 단계 복사, 잘라내기, 붙여넣기 |
| **⌘A** | 모든 단계 고르기 |
| **⌫** | 선택하거나 고른 단계 삭제 |
| **⌥↑**, **⌥↓** | 선택한 단계를 위나 아래로 이동 |
| **⌘=**, **⌘-** | 확대 및 축소 |
| **⌘0** | 워크플로 전체가 보이게 맞춤 |

**병렬 작업 추가** 옆의 키보드 버튼으로도 모든 캔버스 단축키를 볼 수 있습니다.

## 단계 동작

인스펙터의 **동작** 섹션에서는 YAML을 편집하지 않고도 단계가 실행되는 방식을 설정합니다. 헤더에는 *조건부… · 재시도 2회*처럼 바꾼 내용이 나열되거나 **기본값**이 표시됩니다.

| 설정 | 선택지 | 기록되는 YAML |
|---|---|---|
| **실행** | 매번, 조건이 참일 때만, 그 외에는 이전 단계의 조건이 거짓일 때. **이전 단계가 실패하거나 건너뛰어져도 실행**은 상위 단계가 실패한 뒤에도 단계가 계속 실행되게 합니다. | `if`, `else_of`, `run_when` |
| **반복 횟수** | 한 번, 목록의 항목마다 한 번씩, 조건이 충족될 때까지 회차 단위로(최대 회차 수까지) | `foreach`, `loop` |
| **실패한 경우** | 워크플로를 중지하거나, 계속 진행해서 이후 단계가 여전히 실행되게 합니다. **재시도 횟수**는 실패로 처리하기 전에 단계를 다시 실행하며, 시도 사이에 대기 시간을 둘 수 있습니다. | `required: false`, `retries` |
| **대기 시간** | 이전 단계, 아무것도 없음(즉시 시작), 또는 이전 단계와 다른 작업의 단계 목록에서 체크한 단계 | `needs` |

**출력 스키마**는 구조화된 결과를 위한 선택 사항인 JSON Schema를 받습니다. 기본값을 다시 선택하면 YAML에서 해당 설정이 제거됩니다. 각 설정은 [고급 워크플로](/ko/workflows/advanced-workflows)에서 자세히 설명합니다.

## 편집 어시스턴트 사용하기

편집기 도구 모음에서 **어시스턴트**를 선택하면 캔버스 옆에 어시스턴트 패널이 열립니다. 원하는 내용을 설명하세요. 예: "이전 결과를 요약하는 프롬프트 단계를 추가해 줘." 비어 있는 새 워크플로라면 "매일 아침 Hacker News 인기 글을 가져와서 요약해 줘"처럼 전체 과정을 설명해도 됩니다. 보내려면 Return을, 줄을 바꾸려면 **⇧↩**을 누르고, 입력창 아래에서 모델을 선택하세요.

어시스턴트가 작업하는 동안 패널에는 워크플로 읽기, 도구의 매개변수 확인, 편집처럼 하고 있는 일이 표시되며 캔버스도 그에 따라 업데이트됩니다. 답변이 끝날 때까지 캔버스는 읽기 전용이며, **중지**를 선택하면 일찍 끝낼 수 있습니다.

### 작업 중에 더 보내기

답변이 끝나기를 기다렸다가 더 요청하지 않아도 됩니다. 어시스턴트가 작업하는 동안 Return을 누르면 메시지가 입력창 위의 대기열에서 기다립니다. 대기열의 메시지는 각 답변이 끝날 때마다 순서대로 하나씩 전송됩니다.

- 대기 중인 메시지를 끌어서 순서를 바꾸고, **⋯** 메뉴로 편집하고, 휴지통 아이콘을 선택해 삭제합니다.
- **중지**를 선택하거나 답변이 실패하면 대기열이 **보류됨**으로 표시되며 더 이상 자동으로 전송되지 않습니다. 준비가 되면 대기 중인 메시지에서 **보내기**를 선택하세요.
- 어시스턴트가 하는 일에 대한 정정처럼 기다릴 수 없는 메시지는 Return 대신 **⌘↩**을 누르거나 대기 중인 메시지에서 **지금 보내기**를 선택하세요. 현재 답변은 이미 한 편집을 유지한 채 중지되고 **중단됨**으로 표시되며, 메시지가 즉시 전송됩니다. 나머지 대기열은 보류되지 않고 그 뒤에 순서대로 전송됩니다.

### 변경 내용 검토하기

워크플로를 변경하는 각 답변은 추가, 변경, 삭제한 단계를 나열한 카드로 끝납니다. 답변이 끝나면 추가한 단계에는 캔버스에 **추가됨** 태그가, 변경한 단계에는 **수정됨** 태그가 붙으므로 무엇을 검토해야 하는지 알 수 있습니다. 태그는 저장하거나, 실행을 취소하거나, 답변을 되돌릴 때까지 유지됩니다.

- 카드에서 단계를 선택하면 캔버스에서 해당 단계가 선택되고 화면에 표시됩니다. 어시스턴트가 답변에서 언급한 `summarize` 같은 단계 ID도 같은 방식으로 작동합니다.
- 답변 카드에서 **실행**을 선택하면 어시스턴트의 최신 변경을 시험해 볼 수 있습니다. 도구 모음의 **실행**과 같은 방식으로 워크플로를 실행하며, 필요하면 먼저 입력을 요청합니다.
- 최신 카드에서 **되돌리기**를 선택하면 그 답변 이전 상태로 워크플로를 되돌립니다. **실행 취소**(**⌘Z**)도 답변 전체를 한 번에 되돌립니다.

답변이 워크플로를 유효하지 않은 상태로 두면 편집기가 YAML로 전환되어 오류를 표시합니다. 거기서 고치거나 어시스턴트에게 고쳐 달라고 요청하세요. 어시스턴트의 편집은 **저장**을 선택하기 전까지 저장되지 않은 상태로 남습니다.

### 단계나 결과 지정하기

- 한 단계에 대해 질문하려면 캔버스에서 선택하고 인스펙터의 **어시스턴트에게 질문**을 선택하세요. 단계가 다음 메시지에 첨부되므로 "이걸 더 안정적으로 만들어 줘"가 그 단계를 의미합니다.
- 실행 중 단계가 실패하면 실행 요약이나 단계의 **출력** 탭에서 **어시스턴트로 수정**을 선택하세요. 메시지에 단계와 오류가 함께 전달되므로 오류를 직접 복사하지 않아도 됩니다.
- 단계 결과의 일부에 대해 질문하려면 **출력** 탭에서 텍스트를 선택하고 선택 영역 아래의 **어시스턴트에게 질문**을 선택하세요. 텍스트가 메시지 상자 위에 인용으로 나타나 다음 메시지와 함께 전달되므로, 그 의미나 그것을 만든 단계를 어떻게 바꿀지 물을 수 있습니다.

### 채팅과 상시 지침

패널 맨 위의 **새 채팅**을 선택하면 처음부터 다시 시작하며, 이전 채팅은 목록에 남습니다. 패널 맨 위의 채팅 이름을 선택하면 같은 워크플로에 대한 이전 채팅으로 돌아가거나 삭제할 수 있습니다. 저장된 워크플로는 이 브라우저에 마지막 열 개의 채팅을 보관합니다.

어시스턴트가 항상 따라야 할 기본값을 설정하려면 패널 맨 위의 **설정**(슬라이더 아이콘)을 선택하고 **지침** 아래에 적으세요. 예: "파일은 ~/Downloads에 저장해.", "프롬프트 단계에는 anthropic/claude-haiku-4-5를 사용해.", "중국어로 답해." **⌘↩**을 누르거나 **저장**을 선택합니다. 지침은 어시스턴트가 만들거나 편집하는 모든 워크플로에 적용되며, 설정 아이콘의 점이 켜져 있음을 보여 줍니다. 사용을 중단하려면 상자를 비우고 저장하세요.

## 실행하고 확인하기

1. **입력**을 선택하고 이번 실행의 값을 채웁니다.
2. 정의를 검증하고 명령어나 도구 호출을 확인합니다.
3. **실행**을 선택하고 그래프에서 단계 상태를 지켜봅니다.
4. 단계의 **출력** 탭을 선택해 결과나 오류를 확인합니다. 실행 후에는 각 단계 카드에도 설명 대신 단계가 반환한 내용의 첫 줄 또는 실패한 이유가 표시되며, 그 줄을 선택하면 단계의 **출력** 탭이 열립니다. **출력** 탭에서 **복사**를 선택하면 단계의 결과(아무것도 반환하지 않았다면 오류)를 채팅이나 문서에 붙여 넣을 수 있도록 복사합니다.
5. **실행 기록**을 열어 이전 실행을 확인합니다.
6. 정의가 마음에 들면 워크플로를 저장합니다.

<Warning>
실행은 단계에 따라 공급자 크레딧을 소모하거나 외부 데이터를 변경할 수 있습니다. 셸 및 도구 단계는 Mac 계정의 권한으로 동작합니다.
</Warning>

### 실행 입력

도구 모음의 **입력**은 워크플로가 선언한 입력마다 필드가 하나씩 있는 양식을 열며, 유형, 설명, 기본값이 표시됩니다.

- 필드를 비워 두면 기본값을 사용합니다. 목록과 객체는 `["a", "b"]`처럼 JSON을 사용합니다.
- 기본값이 없는 **필수** 입력에는 값이 필요합니다. 비어 있거나 값의 유형이 잘못되면 **실행**이 저장이나 실행 전에 중단되고 고쳐야 할 필드를 가리킵니다.
- 필드에서 **⌘↩**을 누르면 실행합니다.
- 양식은 워크플로가 Enconvo에서 마지막으로 실행된 값으로 시작합니다. **지우기**를 선택하면 모든 필드가 한꺼번에 비워져 다음 실행에서 다시 기본값을 사용합니다. 입력 이름을 바꿔도 입력한 값은 유지됩니다.
- **최근 실행**의 과거 실행이 캔버스에 있는 동안 **그 실행의 값 사용**을 선택하면 해당 실행의 입력으로 양식이 채워지며, 그대로 또는 변경해서 다시 실행할 수 있습니다.
- 빈 필드는 기본값을 회색으로 표시합니다. 긴 기본값을 다시 입력하지 않고 바꾸려면 필드 옆의 **기본값 편집**을 선택해 필드에 기본값을 넣은 뒤 편집하세요.
- 시각화 편집기에서 **입력 내용 편집**을 선택하면 워크플로가 요청하는 내용을 바꿀 수 있습니다. 제거하려는 입력을 아직 읽는 단계가 있으면 Enconvo가 그 단계를 알려 주고 제거 전에 묻습니다. **JSON으로 편집**을 선택하면 워크플로가 선언하지 않은 키를 포함해 입력을 하나의 JSON 객체로 입력할 수 있습니다. **양식 사용**으로 다시 전환합니다.

### 실행이 끝날 때

실행이 끝나면 캔버스 아래쪽에 요약이 나타납니다.

- 단계가 실패하면 요약에 해당 단계의 이름과 종료 코드만이 아니라 `command not found: datex`처럼 무엇이 잘못되었는지 알려 주는 오류의 줄이 표시됩니다. **오류 표시**를 선택하면 해당 단계의 **출력** 탭이 열리고 캔버스에서 단계가 화면에 표시됩니다.
- **어시스턴트로 수정**을 선택하면 실패한 단계와 오류를 어시스턴트에게 넘깁니다. 어시스턴트는 원인으로 답변을 시작한 다음 단계를 고칩니다. API 키 누락, 네트워크 오류, 파일 누락처럼 원인이 워크플로 밖에 있으면 편집하는 대신 무엇을 바꿔야 하는지 알려 줍니다. 실패한 단계의 **출력** 탭에도 같은 **어시스턴트로 수정** 버튼이 있습니다.
- **이어서 실행**을 선택하면 실패했거나 중지된 실행을 계속합니다. 이미 끝난 단계는 결과를 유지하며, 실패한 단계와 그 뒤의 모든 단계가 다시 실행됩니다. 실행 후에 단계를 편집했다면 그 단계와 뒤따르는 단계도 다시 실행됩니다. 실행 입력을 바꾸면 워크플로 전체가 처음부터 실행됩니다. **이어서 실행**은 다른 실행을 시작하기 전까지 도구 모음의 **실행** 옆에도 표시됩니다.
- 문제없이 끝난 실행 후에는 **출력 표시**를 선택하면 마지막 단계의 결과를 볼 수 있습니다. 주의가 필요한 내용이 없으면 요약은 몇 초 후에 사라지며, **×**를 선택하면 더 빨리 닫을 수 있습니다.

### 최근 실행

**최근 실행**에는 워크플로의 이전 실행이 최신순으로 나열됩니다. 각 행에는 다음이 표시됩니다.

- 실행이 성공했는지, 실패했는지, 아직 실행 중인지
- 시작된 시기와 걸린 시간
- 일정(**예약됨**)이나 채팅(**채팅에서**)이 시작했는지
- 실행에 사용된 입력(마우스를 올리면 모두 표시), 실패했다면 오류

캔버스에 표시된 실행에는 **표시 중**이 표시됩니다. 행을 선택하면 해당 실행의 단계 결과가 캔버스에 표시됩니다. 일부 실행은 실패하고 일부는 실패하지 않았다면, 목록 위의 **실패**를 선택해 실패한 실행만 보고 **모든 실행 기록**을 선택해 모든 실행을 다시 볼 수 있습니다.

### 일정에 따라 실행하기

실행 기록 패널 맨 위의 **일정**에는 이 워크플로를 실행하는 예약 작업이 나열되며, 각각 다음 실행 시각과 실행에 사용할 입력이 표시됩니다.

- 예약 작업의 마지막 실행이 실패했다면 **마지막 실행 실패** 위에 마우스를 올려 이유를 보거나, 선택해서 캔버스에서 해당 실행을 열고 어느 단계가 실패했는지 확인하세요.
- 스위치로 예약 작업을 끄거나 켜고, 연필을 선택하면 일정을 바꿀 수 있습니다.
- **예약 추가**를 선택하면 이 워크플로가 이미 선택되고 입력이 **실행 입력**에서 채워진 양식이 바로 열립니다.
- 일정에서 **삭제**를 선택하면 해당 예약 작업이 제거됩니다.

예약된 실행은 저장된 워크플로를 사용하므로, 다음 실행 전에 변경 사항을 저장하세요. 모든 예약 작업은 채팅 창 사이드바의 **예약 작업**에도 나열됩니다. [예약 작업](/ko/workflows/scheduled-jobs)을 참고하세요.

## YAML 편집

저장하면 워크플로가 `~/.enconvo/workflows/<id>.yaml`에 기록됩니다. **YAML**을 선택하면 같은 문서를 소스로 다룰 수 있습니다. 편집기는 입력하는 동안 확인합니다. 오류에는 줄과 열이 표시되고, 경고는 아무 일도 하지 않는 필드를 표시합니다. **유효함** 또는 **유효하지 않음** 배지와 **검증** 동작은 전체 문서를 확인합니다. 작업과 단계 ID에는 문자, 숫자, 밑줄을 사용하고 문자나 밑줄로 시작하세요. **시각화**로 다시 전환하면 **⌘Z**로 YAML 편집을 한 번에 되돌립니다.

```yaml
version: agent-workflow/v1
title: Greeting
description: Produce a greeting and a formatted result without calling a model.
inputs:
  name:
    type: string
    default: world
jobs:
  main:
    steps:
      - id: greeting
        uses: transform
        value: "Hello, {{ inputs.name }}!"
      - id: result
        uses: transform
        value: "Result: {{ steps.greeting.output }}"
```

이 예제는 **입력** 아래 **name** 필드에 `Ada`를 넣고 실행하세요. 마지막 단계는 `Result: Hello, Ada!`를 만들어 냅니다.

## 이전 결과 참조하기

| 표현식 | 값 |
| --- | --- |
| `{{ inputs.name }}` | 입력 값 |
| `{{ steps.greeting.output }}` | 같은 작업의 이전 단계 |
| `{{ jobs.research.search.output }}` | 다른 작업에서 완료된 단계 |
| `{{ item }}` 및 `{{ index }}` | `foreach`의 현재 항목과 인덱스 |
| `{{ round }}` 및 `{{ last }}` | 루프의 회차와 이전 출력 |

다른 작업의 출력을 읽기 전에 작업 수준의 `needs`를 추가하세요. 모든 도구가 같은 필드를 반환한다고 가정하지 말고 **출력**에서 도구 결과를 확인하세요.

### 입력하지 않고 값 삽입하기

시각화 편집기에서는 직접 입력할 필요가 없습니다. 프롬프트, 명령어, 도구 설정, 조건처럼 단계 필드 오른쪽의 `{x}` 버튼인 **값 삽입**을 선택하면 해당 단계가 읽을 수 있는 항목이 나열됩니다. 워크플로의 입력, 같은 작업의 이전 단계 결과, 대기하는 작업의 단계, 반복되는 단계라면 현재 항목이나 회차입니다. 목록을 검색해서 하나를 고르면 커서가 있던 자리에 들어가거나 선택한 텍스트를 대체합니다.

- 셸 단계는 출력된 텍스트를 `{{ steps.<id>.stdout | trim }}`으로 제공합니다.
- 출력 스키마가 있거나 이전 실행이 있는 단계는 결과 필드도 나열합니다.
- 조건, **중지 조건**, 단계가 반복하는 목록은 조건의 `steps.check.output.ok`처럼 해당 필드에 알맞은 형태를 받습니다.

접근할 수 없는 것을 읽는 필드는 아래에 바꿀 내용이 담긴 경고를 표시합니다. 워크플로가 선언하지 않은 입력, 나중에 실행되거나 자기 자신인 단계, 다른 작업에 속한 단계, 이 작업이 기다리지 않는 작업입니다. 캔버스에서는 이런 값이 있는 단계 카드의 제목 옆에 경고 아이콘이 표시되며, 마우스를 올리면 무엇을 고칠지 볼 수 있습니다. 경고가 있어도 저장할 수 있습니다.

## 단계 유형

아래 각 스니펫은 단계 항목입니다. 작업의 `steps` 목록 안에 넣으세요. 시각화 편집기에서는 단계 선택기에서 같은 단계 유형을 고르세요.

### 셸

```yaml
- id: today
  command: 'date "+%Y-%m-%d"'
```

결과는 `steps.today.output.stdout`으로 읽습니다. 선택 설정으로 `cwd`, `shell`, `timeoutMs`, `env`가 있습니다. 명령어는 Mac 계정의 권한을 사용하므로 실행하기 전에 명령어를 검토하세요.

### 프롬프트

```yaml
- id: summarize
  prompt: "Summarize this text: {{ inputs.text }}"
```

모델을 한 번 호출합니다. 이후 단계에 구조화된 필드가 필요하면 [출력 스키마](/ko/workflows/advanced-workflows)를 사용하세요.

### 에이전트

```yaml
- id: plan
  agent: agent/main
  message: "Propose a three-step plan for {{ inputs.topic }}."
```

설치된 에이전트의 명령어 키를 사용하세요. 에이전트가 할 수 있는 일은 활성화된 도구와 공급자 설정에 따라 정해집니다.

### 도구

```yaml
- id: saved
  tool: workflow/list
  with:
    limit: 5
```

`tool`은 슬래시 형식의 Local API 경로입니다. `with`는 매개변수를 제공합니다(`params`는 별칭). 사용 가능한 경로는 **설정 → API**에서 확인하거나 편집 어시스턴트에게 설치된 도구를 살펴보게 하세요.

### 변환

`uses: transform`과 `value`를 사용하면 모델을 호출하지 않고 입력이나 이전 출력을 결합할 수 있습니다. [YAML 편집](#yaml-편집) 예제는 변환 단계 두 개를 사용합니다.

### 하위 워크플로

저장된 `workflowId` 또는 인라인 `workflow` 문서와 함께 `uses: workflow`를 사용하면 재사용할 수 있는 하위 프로세스를 실행합니다. 시각화 편집기에서는 저장된 워크플로를 이름으로 고르고 요청하는 입력을 양식에 채웁니다. 워크플로를 고르지 않은 하위 워크플로 단계는 통과하지 못하며, 실행을 중지하고 무엇이 없는지 알려 줍니다. [고급 워크플로](/ko/workflows/advanced-workflows)를 참고하세요.

### 승인

```yaml
- id: confirm
  uses: approval
  message: "Post this summary to the team? {{ inputs.text }}"
```

Enconvo가 `message`를 **승인**과 **거절** 선택지와 함께 묻고 답을 기다리며, 단계가 `timeoutMs`를 설정하지 않으면 최대 24시간까지 기다립니다. 승인하면 뒤따르는 단계가 실행됩니다. 거절하거나 답이 없으면 거짓 조건처럼 건너뜁니다. 뒤따르는 단계는 건너뛰고, 그 단계의 `else_of` 단계가 실행됩니다. `steps.confirm.output.feedback`에는 거절할 때 입력한 내용이 담깁니다. 보내거나, 게시하거나, 삭제하거나, 결제하는 단계 바로 앞에 두세요. 거절한 뒤 **다시 시도**를 선택하면 새 실행은 무엇을 왜 거절했는지 전달받습니다. 하위 워크플로 안의 승인을 거절하면 하위 워크플로뿐 아니라 전체 실행이 중지됩니다.

### 판단

```yaml
- id: urgent
  uses: judge
  question: Does this message ask for a reply today?
  input: "{{ inputs.text }}"
```

Enconvo Cloud의 빠른 결정 모델인 Jev가 `input`에 대한 `question`에 `yes`와 `probability`로 답합니다. 확률이 `threshold`(직접 설정하지 않으면 0.5)에 도달하면 `yes`는 true입니다. `if: "{{ steps.urgent.output.yes }}"`와 `else_of` 단계로 분기하세요.

### 분류

```yaml
- id: kind
  uses: classify
  question: What kind of request is this?
  input: "{{ inputs.text }}"
  options:
    billing: A question about payments or invoices
    bug: A report that something is broken
    other: Anything else
```

인스펙터에서는 옵션마다 한 행씩 입력하세요. Jev가 `options` 중 하나를 골라 `label`, `confidence`, 각 옵션의 `probabilities`를 반환합니다. `options`는 레이블이 두 개 이상인 목록이거나, 각 레이블과 그 의미를 연결한 맵입니다. `if: "{{ steps.kind.output.label == 'billing' }}"`로 분기하세요.

판단과 분류 단계는 Enconvo Cloud에서 실행되므로 로그인되어 있고 포인트가 남아 있어야 합니다. `output_schema`는 받지 않습니다.
