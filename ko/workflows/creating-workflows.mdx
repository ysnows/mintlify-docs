이 가이드는 워크플로 편집기에서 하는 모든 작업을 다룹니다. 워크플로를 시작하고, 캔버스나 YAML에서 구성하고, 어시스턴트가 편집하도록 맡기고, 실행해 결과를 확인하는 방법을 설명합니다. 뒷부분의 섹션은 파일 형식과 각 단계 유형에 대한 레퍼런스입니다.

편집기를 열려면 채팅 창 사이드바에서 **워크플로**를 선택하거나 **설정 → 워크플로 → 관리**를 여세요. 그런 다음 **새 워크플로**를 선택하거나 기존 워크플로에서 **편집**을 누릅니다. 채팅 창에서는 다른 채팅으로 전환했다가 돌아와도 편집 중이던 워크플로가 그대로 유지됩니다.

이 페이지는 다음 순서로 구성됩니다.

- 시작하기: [핵심 개념](#핵심-개념), [워크플로 목록](#워크플로-관리하기), [새 워크플로 시작하기](#새-워크플로-시작하기).
- 구성하기: [시각화 편집기](#시각화-편집기로-구성하기), [단계 동작](#단계-동작), [편집 어시스턴트](#편집-어시스턴트-사용하기).
- 실행하기: [워크플로 실행 및 결과 읽기](#실행-및-확인).
- 레퍼런스: [YAML 파일](#yaml-편집하기), [이전 결과 참조](#이전-결과-참조하기), [모든 단계 유형](#단계-유형).

## 핵심 개념

- 워크플로는 먼저 **입력**을 선언한 다음, 순서가 있는 단계 목록을 각각 담은 하나 이상의 작업을 정의합니다. 전체 개요는 [워크플로](/ko/workflows/introduction)를 참고하세요.
- 한 작업 안의 단계들은 위에서 아래로 실행됩니다. 작업들은 다른 작업이 기다리도록 설정하지 않는 한 병렬로 실행됩니다.
- 단계는 `{{ inputs.topic }}`이나 `{{ steps.fetch.output }}` 같은 `{{ }}` 템플릿으로 실행 입력과 이전 결과를 읽습니다.
- 워크플로 편집과 실행은 별개의 동작입니다. 저장은 파일에 기록할 뿐이며, 실행해야 실제 모델과 도구를 호출합니다.

## 워크플로 관리하기

워크플로 목록은 워크플로를 열고, 실행하고, 정렬하고, 찾고, 삭제하는 곳입니다.

### 워크플로 목록

각 행에는 워크플로의 단계 수, 마지막으로 편집한 시점, 마지막 실행 결과가 표시됩니다.

- 마지막 실행을 선택하면 해당 실행 결과가 캔버스에 표시된 상태로 워크플로가 열립니다.
- 재생 버튼을 선택하면 워크플로를 열고 즉시 실행합니다. 아직 채우지 않은 입력이 필요하면 **입력** 패널이 먼저 열립니다. 워크플로가 실행되는 동안 재생 버튼은 중지 버튼으로 바뀌며, 이를 선택하면 워크플로를 열지 않고 실행을 멈춥니다.
- 예약 실행되는 워크플로는 다음 실행 시각을 표시하며, 연결된 예약 작업이 모두 꺼져 있으면 **예약 일시 중지됨**을 표시합니다. 이를 선택하면 실행 패널에 예약 목록이 열린 상태로 워크플로가 열립니다.
- 복사 버튼을 선택하면 새 제목으로 워크플로를 복제하므로 원본을 건드리지 않고 사본을 수정할 수 있습니다. 목록이 사본 위치로 스크롤되고 강조 표시됩니다.
- 목록 위의 정렬 메뉴에서 **최근 편집순**, **최근 실행순** 또는 **이름순**으로 정렬할 수 있습니다. 선택한 정렬 기준은 기억됩니다.

목록은 다시 돌아왔을 때와 예약 실행이 시작될 때 자동으로 업데이트됩니다.

### 워크플로 찾기

**워크플로 검색**에 입력하면 입력하는 즉시 목록이 갱신됩니다. 지우기 버튼이나 Esc를 누르면 모든 워크플로가 다시 표시됩니다.

행의 태그를 선택하면 해당 태그가 붙은 워크플로만 표시되며, **워크플로 검색**과 함께 작동합니다. 한 행에는 최대 네 개의 태그가 표시되며 나머지를 보려면 **+N**을 선택하세요. 모든 워크플로를 다시 보려면 태그를 다시 선택하거나 목록 위 태그 옆의 ×를 선택하거나 **워크플로 검색**에서 Esc를 누르세요.

| 키 | 워크플로 목록에서의 동작 |
| --- | --- |
| **⌘F** 또는 **/** | **워크플로 검색**으로 이동 |
| **워크플로 검색**에서 ↓ | 첫 번째 워크플로로 이동 |
| ↑ 및 ↓ | 워크플로 간 이동 |
| Return | 선택한 워크플로 열기 |
| Delete | 선택한 워크플로 삭제 |

### 워크플로 이름 바꾸기 또는 삭제하기

워크플로 이름을 바꾸려면 편집기 상단의 이름을 선택해 새 이름을 입력한 뒤 Return을 누르세요. Esc를 누르면 이전 이름이 유지됩니다.

워크플로를 삭제할 때 실행 중이면 먼저 실행을 중지합니다. 해당 워크플로를 실행하는 [예약 작업](/ko/workflows/scheduled-jobs)은 일시 중지된 채 유지되므로 다른 워크플로를 연결하거나 삭제할 수 있습니다. 삭제하기 전에 몇 개가 영향받는지 확인 창에서 알려 줍니다.

## 새 워크플로 시작하기

**새 워크플로**를 선택하면 아래와 같은 시작 방법을 고를 수 있는 대화 상자가 열립니다. 먼저 워크플로 종류를 선택하세요.

- **작업 워크플로**: 한 종류의 작업을 처리하는 방식입니다.
- **팀 워크플로**: 여러 멤버가 참여해 계획부터 완료까지 목표를 수행하는 방식입니다. 템플릿에는 **계획, 구현, 검토**와 **단일 멤버**가 포함됩니다.

아직 워크플로가 하나도 없을 때는 워크플로 목록 바로 그 자리에 **원하는 작업 설명하기**, **빈 워크플로** 및 템플릿이 표시됩니다.

| 시작 방법 | 사용 방법 |
| --- | --- |
| 설명으로 만들기 | 예를 들어 "텍스트를 일본어와 스페인어로 동시에 번역해 줘"처럼 워크플로가 해야 할 일을 적고 **빌드하기**(또는 **⌘↩**)를 선택합니다. 어시스턴트가 이미 구성을 시작한 상태로 워크플로가 열립니다. 단계를 검토하고 알맞으면 **저장**을 선택하세요. |
| 템플릿에서 시작 | **빈 워크플로**, **주제 리서치**, **웹 페이지 요약**, **YouTube 동영상 노트**, **글 작성 및 소리 내어 읽기**, 또는 **단계 유형 둘러보기**(두 작업이 병렬로 실행되며 셸 명령, 도구, 프롬프트, 에이전트를 포함) 중 하나를 고릅니다. 모든 템플릿은 바로 실행할 수 있는 완성된 워크플로입니다. |
| 파일 가져오기 | **파일 선택…**을 선택하거나 팀원이 공유한 것 같은 `.yaml`, `.yml`, `.json` 워크플로 파일을 대화 상자 아무 곳에나 끌어다 놓습니다. 새 워크플로로 저장되므로 기존 워크플로를 덮어쓰지 않습니다. 제목이 목록의 항목과 같으면 "News copy"처럼 사본 이름이 붙습니다. 올바른 워크플로 파일이 아니면 대화 상자가 닫히지 않고 이유를 알려 줍니다. |
| 붙여넣기 | 채팅에서 공유받은 워크플로의 YAML이나 JSON을 설명 상자에 붙여 넣습니다. **빌드하기**가 **가져오기**로 바뀌며 붙여 넣은 그대로 워크플로가 생성됩니다. |

### 기본 제공 워크플로

Enconvo에 기본 포함된 워크플로는 읽기 전용으로 열립니다. 수정하려면 **사본 만들기**를 선택해 사본을 편집하세요.

### 워크플로 공유하기

워크플로를 공유하거나 백업해 두려면 워크플로 목록의 해당 행이나 편집기 도구 막대에서 공유 버튼(다운로드 아이콘)을 선택하세요.

- **YAML 파일로 내보내기…**는 원하는 위치에 `.yaml` 파일을 저장합니다. 어느 Mac에서든 **새 워크플로** > **파일 선택…**으로 가져올 수 있습니다.
- **YAML 복사**는 채팅이나 가져오기를 지원하는 **새 워크플로** 설명 상자에 바로 붙여 넣을 수 있도록 워크플로를 복사합니다.

편집기에서 사용할 때는 두 방법 모두 아직 저장하지 않은 변경 내용까지 포함합니다.

</Frame>

편집기에서는 같은 워크플로를 두 가지 방식으로 볼 수 있습니다.

- **시각화**: 캔버스 위 카드로 단계를 배치하며 병렬 작업은 나란히 표시됩니다.
- **단계**: 위에서 아래로 단계 목록과 조건, 반복 및 병렬 단계를 보여 줍니다. 두 단계 사이의 **추가** 메뉴를 사용해 그 위치에 단계를 넣을 수 있습니다.

헤더에서 **가이드**를 선택하면 워크플로에 대한 쉬운 설명을 사용 언어로 볼 수 있습니다.

1. 편집기 도구 막대에서 **시각화**를 선택합니다.
2. 노드 사이의 **여기에 단계 추가**로 단계를 삽입하거나 **병렬 작업 추가**로 별도 분기를 만듭니다. 단계 목록은 최근에 고른 몇 개의 단계와 도구를 보여주는 **최근 사용**으로 열리므로 자주 쓰는 항목을 클릭 한 번으로 추가할 수 있습니다. 도구가 많은 플러그인은 처음 여덟 개를 보여 주며 **N개 더 보기**를 선택하거나 입력해 검색할 수 있습니다.
3. 단계를 선택해 검사기를 엽니다. ID, 제목, 실행기 설정을 편집하고 **동작**을 열어 실행 방식을 바꿀 수 있습니다.
4. **입력** 노드를 선택해 워크플로의 선언된 입력(이름, 유형(텍스트, 숫자, 참/거짓, 목록 또는 객체), 설명, 기본값, 실행 시 값 필수 여부)을 설정합니다. 각 이름 아래에는 `{{ inputs.topic }}`처럼 단계가 입력을 어떻게 읽는지와 몇 개의 단계가 읽는지가 표시됩니다. 입력 이름을 바꾸면 해당 단계들도 새 이름으로 함께 업데이트됩니다. 이름은 문자, 숫자, 밑줄을 쓸 수 있고 숫자로 시작할 수 없으며 다른 입력과 겹칠 수 없습니다.
5. 그래프를 검토하고 편집 중에 **실행 취소**나 **다시 실행**을 사용합니다.
6. 변경 사항을 검토한 뒤 **저장**을 선택합니다.

### 단계 카드 읽기

각 단계 카드에는 단계 이름과 그 아래에 단계가 하는 일(도구나 단계 종류, 그리고 *Web Search · ‹topic› news*나 프롬프트 앞부분 같은 주요 설정의 시작 부분)이 표시됩니다. 입력과 이전 단계에서 읽어 오는 값은 ‹ › 안에 이름으로 표시됩니다. 이름이 없는 단계는 ID가 단어로 표시되며, 카드에 마우스를 올리면 ID를 볼 수 있습니다.

도구 단계의 카드에는 해당 플러그인 아이콘이 표시됩니다. 카드의 작은 표시는 단계가 실행되는 방식을 나타냅니다(조건이 참일 때만 실행, 목록의 각 항목마다 한 번씩 실행, 반복 실행, 실패 시 재시도, 이전 단계가 실패해도 실행, 또는 이 단계가 실패해도 워크플로 계속 진행). 표시에 마우스를 올리면 뜻을 읽을 수 있고, 단계의 **동작** 섹션에서 바꿀 수 있습니다.

### 단계 선택하기

단계 선택기는 기본 제공 단계, 설치된 도구 및 MCP 도구를 검색합니다. Enconvo 창을 열기만 하거나 제공업체의 모델·음성 목록을 나열하는 도구는 제외되지만, YAML에서는 이름으로 계속 호출할 수 있습니다.

어떤 도구가 필요한지 확실하지 않다면 "기사를 세 줄로 요약해 줘"처럼 단계가 할 일을 입력한 뒤 선택기 하단의 **어시스턴트에게 추가 요청**(**⌘↩**)을 선택하세요. 일치하는 항목이 없을 때는 Return을 눌러도 똑같이 작동합니다. 어시스턴트는 사용자가 선택기를 연 바로 그 위치(인접 단계 앞뒤 또는 새 병렬 작업)에 단계를 추가하며, 다른 어시스턴트 응답과 마찬가지로 되돌릴 수 있습니다.

### 단계 편집하기

검사기에는 **구성** 및 **출력** 탭이 있습니다. **단계 실행**은 선택한 단계를 실행하며 실제 도구 호출이나 셸 명령을 수행할 수 있습니다. 개별 단계를 실행하기 전에 필요한 앞단계 값이 있는지 확인하세요.

**구성** 탭은 단계 카드에 표시되는 단계의 **이름**과 다른 단계가 결과를 읽을 때 쓰는 **단계 ID**로 시작합니다. **하는 일**에는 단계의 도구나 종류가 표시됩니다.

단계가 다른 일을 하도록 바꾸려면 **변경**을 선택해 다른 도구나 단계 종류를 고르거나, 할 일을 설명한 뒤 **어시스턴트에게 변경 요청**을 선택하세요.

- 단계는 기존 ID를 유지하므로 결과를 참조하던 다른 단계들이 계속 작동합니다.
- 언제, 어떻게 실행되는지(조건, 반복, 재시도 및 대기 대상)도 그대로 유지됩니다.
- 새 도구의 설정은 비워진 상태로 시작합니다. 프롬프트가 에이전트로 바뀌거나 에이전트가 프롬프트로 바뀔 때는 텍스트, 모델 및 출력 스키마가 유지됩니다.
- 편집기가 붙였던 단계 이름은 새 도구를 따르고, 사용자가 직접 쓴 이름은 그대로 남습니다.

이전으로 돌리려면 **실행 취소**를 선택하세요.

### 단계 복제, 순서 변경 또는 끄기

단계를 재사용하려면 검사기에서 **복제**를 선택하거나 단계 카드에 마우스를 올려 복제하세요. 사본은 원래 단계의 모든 설정을 유지한 채 원본 바로 뒤에 추가되며 `fetch_2`처럼 다음 빈 ID를 받습니다.

작업 안의 단계는 위에서 아래로 실행됩니다. 순서를 바꾸려면 작업 안에서 단계 카드를 위아래로 드래그하세요. 다른 카드들이 비켜서며 놓일 위치를 보여 줍니다. 단계를 선택하고 검사기에서 **위로 이동**이나 **아래로 이동**을 선택하거나 **⌥↑** 또는 **⌥↓**를 누를 수도 있습니다. 이동을 되돌리려면 **⌘Z**를 누르세요. 어떤 단계가 자신이 결과를 읽는 단계보다 위로 올라가면 다시 아래로 내릴 때까지 카드에 경고가 표시됩니다.

단계를 삭제하지 않고 잠시 빼 두려면 해당 단계를 선택하고 **단계 끄기**를 선택하세요. 카드가 흐려지며 **꺼짐**으로 표시되고, 실행 시 건너뛰며 그다음 단계들은 계속 실행됩니다. 다시 쓰려면 **단계 켜기**를 선택하세요.

### 여러 단계 함께 다루기

여러 단계를 한꺼번에 바꾸려면 ⌘ 또는 Shift를 누른 채 카드를 클릭하세요. 캔버스 상단 막대에 선택한 단계 수와 함께 모두에 적용되는 **끄기**(또는 **켜기**) 및 **삭제**가 나타납니다. 선택을 해제하려면 Esc를 누르거나 캔버스 빈 곳을 클릭하고, 되돌리려면 **⌘Z**를 누르세요.

삭제 시 다른 단계가 깨지거나 작업이 비게 된다면 Enconvo가 먼저 확인합니다. 확인 창에는 삭제하려는 단계에 의존하는 각 단계와 그 이유(**출력 사용** 또는 **완료 대기** 등)가 나열됩니다. 그중 하나를 선택하면 삭제를 취소하고 해당 단계를 열어 먼저 수정할 수 있습니다. 단계 하나만 삭제할 때도 동일합니다.

단계를 복사하려면 하나를 선택(또는 여러 개 선택)하고 **⌘C**를 누르거나 상단 막대에서 **복사**를 선택하세요. **⌘X**는 잘라냅니다. 그런 다음 붙이고 싶은 앞단계 카드를 선택하고 **⌘V**를 누르세요.

- 사본은 해당 단계 바로 뒤에 놓이거나(작업을 선택한 경우 작업 끝에 놓임) 기존 설정을 그대로 유지합니다.
- ID가 이미 사용 중이면 `fetch_2`처럼 새 ID를 받으며, 붙여 넣은 단계 중 서로를 참조하던 항목은 새 이름을 따릅니다.
- 다른 워크플로에도 같은 방식으로 단계를 붙여 넣을 수 있으며, 워크플로 파일에서 복사한 YAML이나 JSON 단계 목록도 **⌘V**로 붙여 넣을 수 있습니다.

단계를 삭제하거나 붙여 넣으면 무엇이 바뀌었는지 알림이 표시되며, 알림에서 실행 취소를 선택해 되돌릴 수 있습니다.

### 찾기, 확대/축소, 저장 및 실행

- 큰 워크플로에서 특정 단계로 바로 이동하려면 **⌘F**를 누르거나 캔버스의 검색 버튼을 선택하고 단계 이름, ID, 도구 또는 텍스트 일부를 입력해 고르세요. 해당 단계가 선택되고 화면에 보이도록 스크롤됩니다.
- 캔버스 오른쪽 하단의 확대/축소 컨트롤을 사용하세요. 확대/축소 배율을 선택하면 100%로 돌아갑니다.
- **단계 찾기**를 선택하거나 캔버스에서 **⌘F**를 누르고 단계 이름 일부를 입력해 해당 단계를 선택하고 화면에 표시할 수 있습니다. 읽기 전용 기본 제공 워크플로에서도 작동합니다.
- 시각화나 YAML 어디서든, 단계 설정을 입력하는 중에도 **⌘S**를 눌러 저장할 수 있습니다.
- **⌘↩**를 누르면 워크플로를 실행하며, 변경 사항이 있으면 먼저 저장합니다. YAML 편집기, 어시스턴트 및 기타 여러 줄 입력란에서는 대신 **실행**을 선택하세요.
- 실행이 진행되는 동안 **실행**은 **중지**로 바뀝니다. 선택하면 실행이 완전히 멈출 때까지 **중지 중…**이 표시됩니다.

프롬프트가 비어 있거나 설명이 누락된 단계처럼 워크플로에 문제가 있으면 저장과 실행이 멈추며 무엇을 고쳐야 하는지 알려 줍니다. **표시**를 선택하면 해당 단계나 워크플로의 제목 및 설명이 열립니다. 문제가 있는 단계는 카드에 빨간색 표시가 나타나며, 마우스를 올리면 잘못된 내용을 읽을 수 있습니다. YAML에서는 **검증**을 선택해 문서 전체를 검사하세요.

### 저장되지 않은 변경 사항

워크플로에 저장되지 않은 변경 사항이 있으면 편집기 헤더에 **저장되지 않음**이 표시됩니다. 이를 선택하면 마지막 저장 이후 추가되거나 삭제된 YAML 줄을 볼 수 있으며, **변경 사항 버리기**를 선택해 저장된 버전으로 돌아갈 수 있습니다. 시각화 편집기에서는 **⌘Z**로 변경 사항을 되살릴 수 있습니다. 저장하지 않은 변경 사항이 있는 상태에서 워크플로 목록으로 돌아가면 **저장 후 나가기**, **버리기** 또는 **계속 편집** 중 고릅니다.

저장되지 않은 변경 사항은 편집하는 동안 이 Mac에도 보관됩니다. 저장하기 전에 창이 닫히거나 다시 로드되면 워크플로를 다시 열 때 상단 막대에 **복원**(되돌릴 수 있는 한 단계로 변경 사항을 복구) 또는 **버리기**가 나타납니다. 저장된 워크플로가 그사이 바뀌지 않았을 때만 복구를 제안합니다. 워크플로 목록에서 이러한 워크플로에는 **저장되지 않은 변경 사항** 태그가 표시되며, 워크플로를 삭제하면 해당 변경 사항도 함께 버려집니다.

### 캔버스 단축키

| 단축키 | 동작 |
| --- | --- |
| **⌘S** | 저장 |
| **⌘↩** | 실행(먼저 저장) |
| **⌘F** | 단계 찾기 |
| **⌘Z** | 실행 취소 |
| **⌘C**, **⌘X**, **⌘V** | 단계 복사, 잘라내기, 붙여넣기 |
| **⌘A** | 모든 단계 선택 |
| **⌫** | 선택한 단계 삭제 |
| **⌥↑**, **⌥↓** | 선택한 단계 위 또는 아래로 이동 |
| **⌘=**, **⌘-** | 확대 및 축소 |
| **⌘0** | 전체 워크플로를 화면에 맞추기 |
| **?** | 모든 캔버스 단축키 보기 |

**병렬 작업 추가** 옆의 키보드 버튼에서도 모든 캔버스 단축키를 확인할 수 있습니다.

## 단계 동작

검사기의 **동작** 섹션에서는 YAML을 편집하지 않고도 단계가 실행되는 방식을 설정할 수 있습니다. 헤더에는 *조건부 실행… · 재시도 2회*처럼 바꾼 설정이 표시되거나 **기본값**이 표시됩니다.

| 설정 | 선택지 | 생성되는 YAML |
|---|---|---|
| **실행 조건** | 매번 실행, 조건이 참일 때만 실행, 또는 이전 단계의 조건이 거짓일 때 실행. **이전 단계가 실패하거나 건너뛰어져도 실행**을 켜면 앞단계 실패 뒤에도 계속 실행됩니다. | `if`, `else_of`, `run_when` |
| **반복** | 한 번만 실행, 목록의 각 항목마다 실행, 또는 최대 횟수 안에서 조건이 충족될 때까지 라운드 반복 | `foreach`, `loop` |
| **실패 시 동작** | 워크플로를 중지하거나, 이후 단계가 계속 실행되도록 진행합니다. **재시도**는 실패로 처리하기 전에 단계를 다시 실행하며 시도 사이에 대기 시간을 둘 수 있습니다. | `required: false`, `retries` |
| **대기 대상** | 이전 단계, 대기 없음(즉시 시작), 또는 이전 단계와 다른 작업의 단계 목록에서 체크한 단계들 | `needs` |

**출력 스키마**는 구조화된 결과를 위한 선택적 JSON Schema를 받습니다. 다시 기본값을 선택하면 해당 설정이 YAML에서 제거됩니다. 각 설정의 자세한 내용은 [고급 워크플로](/ko/workflows/advanced-workflows)를 참고하세요.

## 편집 어시스턴트 사용하기

편집기 도구 막대에서 **어시스턴트**를 선택하면 캔버스 옆에 어시스턴트 패널이 열립니다. 그런 다음 "이전 결과를 요약하는 프롬프트 단계를 추가해 줘"처럼 원하는 내용을 설명하세요. 새로 만든 빈 워크플로라면 "매일 아침 Hacker News 인기 글을 가져와서 요약해 줘"처럼 전체 과정을 설명할 수도 있습니다. 전송하려면 Return, 줄 바꿈은 **⇧↩**를 누르고, 입력창 아래에서 모델을 선택하세요.

어시스턴트가 작업하는 동안 패널에는 워크플로 읽기, 도구 매개변수 확인, 편집 등 현재 하고 있는 일이 표시되며 캔버스도 진행에 맞춰 업데이트됩니다. 답변이 끝날 때까지 캔버스는 읽기 전용이 되며, 일찍 멈추려면 **중지**를 선택하세요.

### 작업하는 동안 추가 요청 보내기

더 요청하기 전에 답변이 끝날 때까지 기다릴 필요가 없습니다. 어시스턴트가 작업 중일 때 Return을 누르면 메시지가 입력창 위의 대기열에 들어갑니다. 대기 중인 메시지는 각 답변이 끝날 때마다 순서대로 하나씩 전송됩니다.

- 대기 중인 메시지를 드래그해 순서를 바꾸거나, **⋯** 메뉴로 수정하거나, 휴지통 아이콘으로 제거할 수 있습니다.
- **중지**를 선택하거나 답변이 실패하면 대기열이 **보류됨**으로 표시되며 자동으로 더 보내지 않습니다. 준비되면 대기 메시지에서 **전송**을 선택하세요.
- 어시스턴트가 하는 작업에 대한 정정처럼 기다릴 수 없는 메시지라면 Return 대신 **⌘↩**를 누르거나 대기 메시지에서 **지금 전송**을 선택하세요. 현재 답변이 이미 만든 편집 내용은 유지한 채 멈추며 **중단됨**으로 표시되고 새 메시지가 즉시 전송됩니다. 대기열의 나머지 메시지는 보류되지 않고 그 뒤에 순서대로 전송됩니다.

### 변경 내용 검토하기

워크플로를 바꾼 각 답변의 끝에는 추가, 변경 또는 제거한 단계 목록을 보여 주는 카드가 달립니다. 답변이 끝나면 캔버스에서 추가된 단계에는 **추가됨** 태그가, 변경된 단계에는 **편집됨** 태그가 붙어 무엇을 검토해야 하는지 바로 알 수 있습니다. 태그는 저장, 실행 취소 또는 답변 되돌리기를 할 때까지 유지됩니다.

- 카드에서 단계를 선택하면 캔버스에서 그 단계가 선택되고 화면에 표시됩니다. 어시스턴트가 답변 본문에서 언급한 `summarize` 같은 단계 ID도 똑같이 작동합니다.
- 답변 카드에서 **실행**을 선택해 어시스턴트의 최신 변경 사항을 시험해 보세요. 도구 막대의 **실행**과 똑같이 워크플로를 실행하며 입력이 필요하면 먼저 묻습니다.
- 최신 카드에서 **되돌리기**를 선택하면 해당 답변 이전 상태로 워크플로를 되돌립니다. **실행 취소**(**⌘Z**)로도 답변 하나의 변경을 한 번에 되돌릴 수 있습니다.

답변으로 인해 워크플로가 유효하지 않은 상태가 되면 편집기가 YAML로 전환해 오류를 표시합니다. 그 자리에서 고치거나 어시스턴트에게 수정을 요청하세요. 어시스턴트가 편집한 내용은 **저장**을 선택할 때까지 저장되지 않습니다.

### 특정 단계나 결과 가리키기

- 한 단계에 대해 묻고 싶다면 캔버스에서 그 단계를 선택하고 검사기에서 **어시스턴트에게 묻기**를 선택하세요. 다음 메시지에 해당 단계가 첨부되므로 "이걸 더 안정적으로 만들어 줘"라고 말하면 그 단계를 뜻하게 됩니다.
- 실행 중 단계가 실패하면 실행 요약이나 해당 단계의 **출력** 탭에서 **어시스턴트로 수정**을 선택하세요. 단계와 오류가 메시지에 함께 실리므로 오류를 복사해 넣을 필요가 없습니다.
- 단계 결과의 일부에 대해 묻고 싶다면 **출력** 탭에서 텍스트를 선택하고 선택 영역 아래의 **어시스턴트에게 묻기**를 선택하세요. 해당 텍스트가 메시지 상자 위에 인용문으로 들어가 다음 메시지와 함께 전달되므로, 무슨 뜻인지 묻거나 그 결과를 만든 단계를 어떻게 바꿀지 요청할 수 있습니다.

### 채팅과 기본 지침

패널 상단에서 **새 채팅**을 선택해 새로 시작할 수 있으며 이전 채팅은 목록에 남습니다. 패널 상단의 채팅 이름을 선택하면 같은 워크플로에 관한 이전 채팅으로 돌아가거나 삭제할 수 있습니다. 저장된 워크플로는 이 브라우저에 최근 채팅 열 개를 보관합니다.

어시스턴트가 항상 따라야 할 기본 규칙을 정하려면 패널 상단에서 **설정**(슬라이더 아이콘)을 선택하고 **지침** 아래에 적으세요(예: "파일은 ~/Downloads에 저장해 줘.", "프롬프트 단계에는 anthropic/claude-haiku-4-5를 사용해 줘.", "한국어로 답해 줘."). **⌘↩**를 누르거나 **저장**을 선택합니다. 이 지침은 어시스턴트가 만들거나 편집하는 모든 워크플로에 적용되며 설정 아이콘의 점이 켜져 있음을 알려 줍니다. 사용을 멈추려면 상자를 비우고 저장하세요.

## 실행 및 확인

1. **입력**을 선택하고 이번 실행에 쓸 값을 채웁니다.
2. 정의를 검증하고 명령이나 도구 호출을 점검합니다.
3. **실행**을 선택하고 그래프에서 단계 상태를 지켜봅니다.
4. 단계의 **출력** 탭을 선택해 결과나 오류를 확인합니다. 실행 후에는 각 단계 카드에도 설명 대신 반환된 내용의 첫 줄이나 실패 이유가 표시되며, 그 줄을 선택하면 해당 단계의 **출력** 탭이 열립니다. **출력** 탭에서 **복사**를 선택하면 단계 결과(반환값이 없을 때는 오류)를 복사해 채팅이나 문서에 붙여 넣을 수 있습니다.
5. **실행 기록**을 열어 이전 실행을 확인합니다.
6. 정의가 만족스러우면 워크플로를 저장합니다.

<Warning>
실행은 포함된 단계에 따라 제공업체 크레딧을 소모하거나 외부 데이터를 변경할 수 있습니다. Shell 및 Tool 단계는 사용자의 Mac 계정 권한으로 작동합니다.
</Warning>

### 실행 입력

도구 막대의 **입력**을 열면 워크플로가 선언한 각 입력의 유형, 설명 및 기본값을 보여 주는 양식이 나타납니다.

- 기본값을 사용하려면 필드를 비워 두세요. 목록과 객체는 `["a", "b"]`처럼 JSON으로 입력합니다.
- 기본값이 없으면서 **필수**로 표시된 입력에는 값이 있어야 합니다. 비어 있거나 값의 유형이 잘못된 경우 **실행**은 저장하거나 실행하기 전에 멈추고 수정할 필드를 가리킵니다.
- 필드 안에서 **⌘↩**를 누르면 실행됩니다.
- 양식은 Enconvo에서 워크플로가 마지막으로 실행될 때 사용한 값으로 시작합니다. **지우기**를 선택하면 모든 필드를 한꺼번에 비워 다음 실행에서 다시 기본값을 쓰게 됩니다. 입력 이름을 바꾸어도 입력해 둔 값은 유지됩니다.
- **최근 실행**의 이전 실행이 캔버스에 표시된 상태에서는 **해당 실행의 값 사용**을 선택해 그 실행에 쓰였던 입력으로 양식을 채운 뒤 그대로 또는 일부를 바꿔 다시 실행할 수 있습니다.
- 빈 필드에는 기본값이 회색으로 표시됩니다. 긴 기본값을 다시 치는 대신 수정하려면 필드 옆의 **기본값 편집**을 선택해 기본값을 필드에 채운 뒤 편집하세요.
- 시각화 편집기에서는 **입력 편집**을 선택해 워크플로가 요구하는 입력을 바꿀 수 있습니다. 지우려는 입력을 아직 읽는 단계가 있으면 Enconvo가 그 이름을 알려 주고 삭제 전에 확인합니다. **JSON으로 편집**을 선택하면 워크플로가 선언하지 않은 키를 포함해 입력을 하나의 JSON 객체로 입력할 수 있으며, **양식 사용**으로 돌아갈 수 있습니다.

### 실행이 끝날 때

실행이 끝나면 캔버스 하단에 요약이 나타납니다.

- 단계가 실패한 경우 요약에 해당 단계 이름이 표시되며 종료 코드만이 아니라 `command not found: datex`처럼 무엇이 잘못되었는지 알려 주는 오류 줄이 표시됩니다. **오류 표시**를 선택하면 해당 단계의 **출력** 탭이 열리고 캔버스에서 그 단계가 화면에 나타납니다.
- **어시스턴트로 수정**을 선택하면 실패한 단계와 오류를 어시스턴트에게 넘깁니다. 어시스턴트는 원인 설명으로 답변을 시작한 뒤 단계를 수정합니다. 누락된 API 키, 네트워크 오류, 없는 파일처럼 원인이 워크플로 밖에 있는 경우에는 편집하는 대신 무엇을 바꾸어야 하는지 알려 줍니다. 실패한 단계의 **출력** 탭에도 같은 **어시스턴트로 수정** 버튼이 있습니다.
- 실패했거나 중지된 실행을 계속하려면 **이어서 실행**을 선택하세요. 이미 완료된 단계는 결과를 유지하며 실패한 단계와 그 이후 단계만 다시 실행됩니다. 실행 뒤에 어떤 단계를 편집했다면 그 단계와 그 이후 단계도 다시 실행됩니다. 실행 입력을 변경하면 워크플로가 처음부터 다시 실행됩니다. **이어서 실행**은 다른 실행을 시작할 때까지 도구 막대의 **실행** 옆에도 표시됩니다.
- 문제없이 완료된 실행 뒤에는 **출력 표시**를 선택해 마지막 단계의 결과를 볼 수 있습니다. 요약은 확인이 필요한 사항이 없으면 몇 초 뒤에 사라지며, **×**를 선택해 더 빨리 닫을 수도 있습니다.

### 최근 실행

**최근 실행**에는 워크플로의 이전 실행이 최신순으로 나열됩니다. 각 행에는 다음 정보가 표시됩니다.

- 실행 성공, 실패 또는 아직 실행 중인지 여부
- 시작 시각과 소요 시간
- 예약(**예약됨**)으로 시작되었는지 채팅(**채팅에서**)으로 시작되었는지 여부
- 실행에 사용한 입력(마우스를 올리면 전체 표시)과 실패한 경우 오류 내용

캔버스에 표시 중인 실행에는 **표시 중** 표시가 붙습니다. 행을 선택하면 캔버스에 해당 실행의 단계 결과가 나타납니다. 일부 실행은 실패하고 일부는 성공했을 때 목록 위의 **실패**를 선택하면 실패한 실행만 볼 수 있고, **모든 실행**을 선택하면 다시 전체를 볼 수 있습니다.

### 예약 실행

실행 패널 상단의 **예약**에는 이 워크플로를 실행하는 예약 작업들과 다음 실행 시각, 실행 시 사용하는 입력이 나열됩니다.

- 예약 작업의 마지막 실행이 실패했을 때 **마지막 실행 실패** 위에 마우스를 올리면 이유를 볼 수 있고, 선택하면 캔버스에서 해당 실행을 열어 어느 단계가 실패했는지 확인할 수 있습니다.
- 스위치로 예약 작업을 끄거나 켜고, 연필 아이콘을 선택해 일정을 변경하세요.
- **예약 추가**를 선택하면 이 워크플로가 이미 선택되고 **실행 입력**의 입력값이 채워진 상태로 바로 양식이 열립니다.
- 예약에서 **삭제**를 선택하면 해당 예약 작업이 제거됩니다.

예약 실행은 저장된 워크플로를 사용하므로 다음 실행 전에 변경 사항을 저장하세요. 모든 예약 작업은 채팅 창 사이드바의 **예약 작업**에도 나열됩니다. [예약 작업](/ko/workflows/scheduled-jobs)을 참고하세요.

## YAML 편집하기

저장하면 워크플로가 `~/.enconvo/workflows/<id>.yaml`에 기록됩니다. 같은 문서를 소스로 편집하려면 **YAML**을 선택하세요. 편집기는 입력하는 즉시 검사하며 오류는 줄과 열 번호를 알려 주고, 경고는 아무 역할도 하지 않는 필드를 표시합니다. **유효함** 또는 **유효하지 않음** 배지와 **검증** 작업으로 문서 전체를 검사합니다. 작업 ID와 단계 ID에는 문자, 숫자, 밑줄을 사용하고 문자나 밑줄로 시작하세요. **시각화**로 돌아갈 때 **⌘Z**를 누르면 YAML 편집 내용을 한 번에 되돌릴 수 있습니다.

```yaml
version: agent-workflow/v1
title: Greeting
description: Produce a greeting and a formatted result without calling a model.
inputs:
  name:
    type: string
    default: world
jobs:
  main:
    steps:
      - id: greeting
        uses: transform
        value: "Hello, {{ inputs.name }}!"
      - id: result
        uses: transform
        value: "Result: {{ steps.greeting.output }}"
```

**입력** 아래 **name** 필드에 `Ada`를 넣어 이 예제를 실행해 보세요. 마지막 단계는 `Result: Hello, Ada!`를 생성합니다.

## 이전 결과 참조하기

| 표현식 | 값 |
| --- | --- |
| `{{ inputs.name }}` | 입력 값 |
| `{{ steps.greeting.output }}` | 같은 작업 내 이전 단계 |
| `{{ jobs.research.search.output }}` | 다른 작업의 완료된 단계 |
| `{{ item }}` 및 `{{ index }}` | `foreach`의 현재 항목과 인덱스 |
| `{{ round }}` 및 `{{ last }}` | 반복문의 라운드와 이전 출력 |

다른 작업의 출력을 읽기 전에는 작업 수준 `needs`를 추가하세요. 모든 도구가 같은 필드를 반환한다고 가정하지 말고 **출력**에서 도구 결과를 확인하세요.

### 직접 입력하지 않고 값 삽입하기

시각화 편집기에서는 이를 직접 입력할 필요가 없습니다. 프롬프트, 명령, 도구 설정, 조건 같은 단계 필드 오른쪽의 **값 삽입**(`{x}` 버튼)을 선택하면 해당 단계가 읽을 수 있는 항목(워크플로 입력, 같은 작업 내 이전 단계 결과, 대기 중인 작업의 단계, 반복 단계의 경우 현재 항목이나 라운드)이 나열됩니다. 목록을 검색해 하나를 고르면 커서 위치에 들어가거나 선택한 텍스트를 바꿉니다.

- 셸 단계는 출력된 텍스트를 `{{ steps.<id>.stdout | trim }}`으로 제공합니다.
- 출력 스키마나 이전 실행 기록이 있는 단계는 결과 필드도 함께 나열합니다.
- 조건, **중단 조건** 및 단계가 반복할 목록 필드에는 조건 안의 `steps.check.output.ok`처럼 해당 필드에 맞는 형식으로 삽입됩니다.

접근할 수 없는 값을 읽는 필드에는 그 아래에 무엇을 고쳐야 하는지 경고가 표시됩니다(워크플로에 선언되지 않은 입력, 더 뒤에 실행되거나 자기 자신인 단계, 다른 작업에 속한 단계, 또는 이 작업이 기다리지 않는 작업). 캔버스에서 이러한 값이 있는 단계 카드에는 제목 옆에 경고 아이콘이 나타나며, 마우스를 올리면 무엇을 수정해야 하는지 볼 수 있습니다. 경고가 있어도 저장은 할 수 있습니다.

## 단계 유형

아래 각 스니펫은 단계 항목입니다. 작업의 `steps` 목록 안에 넣으세요. 시각화 편집기에서는 단계 선택기에서 같은 단계 유형을 고르면 됩니다.

### Shell

```yaml
- id: today
  command: 'date "+%Y-%m-%d"'
```

결과는 `steps.today.output.stdout`으로 읽습니다. 선택 설정으로 `cwd`, `shell`, `timeoutMs`, `env`가 있습니다. 명령은 사용자의 Mac 계정 권한으로 실행되므로 실행 전에 명령을 검토하세요.

### Prompt

```yaml
- id: summarize
  prompt: "Summarize this text: {{ inputs.text }}"
```

모델을 한 번 호출합니다. 이후 단계에서 구조화된 필드가 필요하면 [출력 스키마](/ko/workflows/advanced-workflows)를 사용하세요.

### Agent

```yaml
- id: plan
  agent: agent/main
  message: "Propose a three-step plan for {{ inputs.topic }}."
```

설치된 에이전트의 명령 키를 사용하세요. 해당 에이전트에 활성화된 도구와 제공업체 설정에 따라 할 수 있는 작업이 결정됩니다.

### Tool

```yaml
- id: saved
  tool: workflow/list
  with:
    limit: 5
```

`tool`은 슬래시 형식의 Local API 라우트입니다. `with`는 매개변수를 전달합니다(`params`는 별칭입니다). 사용 가능한 라우트는 **설정 → API**에서 찾거나 편집 어시스턴트에게 설치된 도구를 확인해 달라고 요청하세요.

### Transform

모델을 호출하지 않고 입력이나 이전 출력을 조합하려면 `value`와 함께 `uses: transform`을 사용하세요. [YAML 편집하기](#yaml-편집하기) 예제에서 두 개의 transform 단계를 사용합니다.

### Subworkflow

재사용 가능한 하위 프로세스를 실행하려면 저장된 `workflowId` 또는 인라인 `workflow` 문서와 함께 `uses: workflow`를 사용하세요. 시각화 편집기에서는 저장된 워크플로를 이름으로 고르고 필요한 입력을 양식에 채워 넣습니다. 워크플로를 선택하지 않은 Subworkflow 단계는 통과하지 못하고 실행을 멈추며 무엇이 빠졌는지 알려 줍니다. [고급 워크플로](/ko/workflows/advanced-workflows)를 참고하세요.

### Approval

```yaml
- id: confirm
  uses: approval
  message: "Post this summary to the team? {{ inputs.text }}"
```

Enconvo는 **승인** 및 **거절** 버튼과 함께 `message`를 묻고, 단계가 `timeoutMs`를 설정하지 않는 한 최대 24시간 동안 응답을 기다립니다. 승인되면 그다음 단계들이 실행됩니다. 거절되거나 응답이 없으면 거짓인 조건처럼 건너뛰어 이후 단계는 건너뛰고 `else_of` 단계가 실행됩니다. 거절할 때 입력한 내용은 `steps.confirm.output.feedback`에 담깁니다. 전송, 게시, 삭제 또는 결제를 수행하는 단계 바로 앞에 두세요. 거절 뒤 **다시 시도**를 선택하면 새 실행에 무엇을 왜 거절했는지 함께 전달됩니다. 하위 워크플로 안에서 승인을 거절하면 하위 워크플로만 멈추는 것이 아니라 전체 실행이 중지됩니다.

### Judge

```yaml
- id: urgent
  uses: judge
  question: Does this message ask for a reply today?
  input: "{{ inputs.text }}"
```

Enconvo Cloud의 빠른 판단 모델인 Jev가 `input`에 대한 `question`에 `yes`와 `probability`로 답합니다. `yes`는 확률이 `threshold`(설정하지 않으면 0.5)에 도달할 때 참이 됩니다. `if: "{{ steps.urgent.output.yes }}"`와 `else_of` 단계로 분기하세요.

### Classify

```yaml
- id: kind
  uses: classify
  question: What kind of request is this?
  input: "{{ inputs.text }}"
  options:
    billing: A question about payments or invoices
    bug: A report that something is broken
    other: Anything else
```

검사기에서 옵션당 한 행씩 입력하세요. Jev는 `options` 중 하나를 골라 `label`, `confidence`, 그리고 각 옵션의 `probabilities`를 반환합니다. `options`는 최소 두 개의 레이블 목록이거나 각 레이블과 그 의미의 맵입니다. `if: "{{ steps.kind.output.label == 'billing' }}"` 형태로 분기하세요.

Judge 및 Classify 단계는 Enconvo Cloud에서 실행되므로 로그인 상태이고 남은 포인트가 있어야 합니다. 이 단계들은 `output_schema`를 받지 않습니다.
