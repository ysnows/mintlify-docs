단순한 순차 단계 목록만으로 부족할 때 다음 기능을 사용하세요. 조건이 참일 때만 단계를 실행하거나, 목록을 따라 반복하거나, 한 단계가 실패해도 실행을 이어 가거나, 구조화된 결과를 받거나, 다른 워크플로를 호출할 수 있습니다. 문서 끝에 바로 복사할 수 있는 전체 예시 워크플로가 있습니다. `agent-workflow/v1` 형식이 처음이라면 [워크플로 만들기](/ko/workflows/creating-workflows)부터 시작하세요.

이 예시들을 실행하기 전에 셸 경로와 도구 또는 제공업체 사용 가능 여부가 사용자의 Mac 환경과 맞는지 확인하세요.

<Tip>
비주얼 편집기에서는 이 설정들을 직접 코드로 작성할 필요가 없습니다. 단계 검사기의 [동작](/ko/workflows/creating-workflows) 섹션에서 `if`, `else_of`, `run_when`, `foreach`, `loop`, `retries`, `required`, `needs`와 출력 스키마를 이해하기 쉬운 선택 항목으로 설정할 수 있습니다.
</Tip>

## 분기

### 조건이 참일 때만 단계 실행하기 (`if`)

`if:`를 붙이면 조건이 참일 때만 해당 단계를 실행합니다. 조건이 거짓이면 해당 단계와 그 뒤를 잇는 하위 단계들은 건너뜁니다.

```yaml
jobs:
  main:
    steps:
    - id: deploy
      if: inputs.ready
      command: ./deploy.sh
```

조건은 참/거짓으로 평가되는 템플릿 표현식입니다. 예를 들어 `inputs.score >= 60`, `steps.check.output.exitCode == 0`, 또는 불리언 입력값을 그대로 쓸 수 있습니다.

### 다른 분기 실행하기 (`else_of`)

`else_of:`는 지정한 단계가 조건 때문에 건너뛰어졌을 때만 실행됩니다. `if`의 "else" 쪽 역할을 합니다.

```yaml
jobs:
  main:
    steps:
    - id: deploy
      if: inputs.ready
      command: ./deploy.sh
    - id: notify_skip
      else_of: deploy
      command: osascript -e 'display notification "deploy skipped"'
```

### 합류 및 정리 (`run_when: always`)

`needs`가 있는 단계는 의존 단계 중 하나라도 건너뛰어지면 보통 함께 건너뛰며, 필수 의존 단계가 실패하면 실행 자체가 중단됩니다. `run_when: always`는 이 둘을 무시하고 의존 단계들이 성공했든 건너뛰어졌든 실패했든 완료만 되면 실행합니다. 분기를 하나로 합치거나 정리 작업을 할 때 사용하세요.

```yaml
jobs:
  main:
    steps:
    - id: build
      command: ./build.sh
    - id: cleanup
      needs:
      - build
      run_when: always
      uses: transform
      value: Build finished; inspect its status in Runs.
```

### 단계 끄기 (`enabled: false`)

`enabled: false`는 워크플로에 단계를 남겨 두되 실행할 때마다 항상 건너뜁니다. 조건에 의해 건너뛴 경우와 달리, 꺼진 단계는 그다음 단계들을 건너뛰게 만들지 않습니다.

- 이후 의존 단계는 계속 실행되며, 꺼진 단계의 출력을 읽으면 빈 값을 받습니다.
- 해당 단계의 `else_of` 단계 역시 건너뜁니다.

단계를 다시 켜려면 해당 키를 지우거나 `true`로 설정하세요. 편집기에서는 검사기의 **단계 끄기**를 사용하면 됩니다.

```yaml
jobs:
  main:
    steps:
    - id: draft
      command: ./draft.sh
    - id: notify
      enabled: false
      command: ./notify.sh
    - id: publish
      command: ./publish.sh
```

## 반복

### 목록의 각 항목마다 반복하기 (`foreach`)

`foreach:`는 목록의 항목마다 단계를 한 번씩 실행합니다. 내부에서 `{{ item }}`은 현재 요소, `{{ index }}`는 위치 번호입니다. 후속 단계는 수집된 출력 배열을 전달받습니다.

```yaml
inputs:
  questions:
    type: array
    default:
    - What is it?
    - Why does it matter?
jobs:
  main:
    steps:
    - id: answer
      foreach: '{{ inputs.questions }}'
      prompt: 'Answer in one sentence: {{ item }}'
    - id: digest
      uses: transform
      value: '{% for a in steps.answer.output %}- {{ a }}

        {% endfor %}'
```

`foreach`에는 인라인 배열도 넣을 수 있으며 `tool:` 호출이나 하위 워크플로 등 모든 종류의 단계에서 작동합니다. 빈 목록은 빈 결과를 내고 후속 단계는 계속 실행됩니다. 한 항목이 실패하면 `required: false`로 표시되지 않은 한 새 항목을 더 이상 시작하지 않습니다.

### 조건이 충족될 때까지 반복하기 (`loop`)

`loop:`는 단계를 반복 실행합니다. 매 라운드가 끝날 때마다 그 라운드의 결과인 `output`에 대해 `until:`을 검사합니다. `{{ round }}`는 현재 라운드 번호, `{{ last }}`는 이전 라운드의 출력입니다. `until`이 충족되기 전에 `maxRounds`를 모두 쓰면 단계가 실패합니다.

```yaml
jobs:
  main:
    steps:
    - id: poll
      run: curl -s -o /dev/null -w '%{http_code}' https://example.com/status
      loop:
        until: output.stdout | trim == '200'
        maxRounds: 10
```

정해진 횟수만큼만 반복하려면 `until`을 생략하세요.

```yaml
jobs:
  main:
    steps:
    - id: retry_build
      command: ./build.sh
      loop:
        maxRounds: 3
```

## 안정성

| 필드 | 기능 |
| --- | --- |
| `retries` | 실패한 단계를 재시도합니다. 횟수(`retries: 2`) 또는 객체(`retries: { maxAttempts: 3, delayMs: 500 }`)로 지정합니다. |
| `required: false` | 이 단계가 실패해도 전체 실행이 중단되지 않고 후속 단계가 계속 진행됩니다. |
| `timeoutMs` | 너무 오래 실행되는 셸 단계를 중지합니다. |

20분 동안 아무 응답이 없는 단계는 중지된 뒤 한 번 더 실행됩니다. 사용자가 직접 중지한 실행은 실패가 아니라 **취소됨**으로 기록됩니다.

```yaml
jobs:
  main:
    steps:
    - id: flaky_fetch
      tool: web_fetch/web_fetch
      params:
        link_url: '{{ inputs.url }}'
      retries:
        maxAttempts: 3
        delayMs: 1000
    - id: optional_enrich
      run: ./enrich.sh || exit 1
      required: false
```

## 출력 계약

`prompt` 또는 `agent` 단계에 `output_schema`(JSON Schema 객체)를 붙이면 응답 형식을 강제할 수 있습니다. 프롬프트 본문에 JSON 형식을 설명할 필요가 없습니다. 요구되는 구조가 모델에 전달되며, 후속 단계가 쓰기 전에 응답을 파싱해 검증합니다. 실패 시 다시 시도하게 하려면 `retries`를 설정하세요. 검증에 끝내 실패한 응답은 단계 실패로 처리됩니다.

```yaml
jobs:
  main:
    steps:
    - id: extract
      prompt: 'Extract the invoice details from: {{ inputs.text }}'
      output_schema:
        type: object
        required:
        - payer
        - amount
        - date
        properties:
          payer:
            type: string
          amount:
            type: number
          date:
            type: string
    - id: record
      uses: transform
      value: '{{ steps.extract.output.payer }} paid {{ steps.extract.output.amount }}'
```

## 단계별 모델 재정의

`prompt` 및 `agent` 단계는 해당 단계에서만 모델을 바꾸기 위해 선택적으로 `provider:`와 `model:`을 지정할 수 있습니다. 이 전환은 해당 실행 동안만 유지되며 저장된 모델 설정은 건드리지 않습니다. 대량 처리 단계에는 저렴한 모델을, 중요한 단계에는 성능이 높은 모델을 쓰세요.

`provider`에는 설치된 제공업체 명령 이름을, `model`에는 현재 빌드에서 해당 제공업체가 표시하는 모델 ID를 지정하세요. 예를 들어 작동 중인 제공업체 설정에서 두 값을 복사해 프롬프트 단계에 넣으면 됩니다. 모델 사용 가능 여부와 권한은 계정마다 다르며, 이 페이지의 예시는 설정된 기본 모델을 사용합니다.

<Note>
`provider`는 제공업체 명령(예: `enconvo_ai`, `open_ai`, `ollama`)이고 `model`은 해당 제공업체의 모델 ID입니다. 두 항목 모두 `prompt` 및 `agent` 단계에서만 유효합니다.
</Note>

## 하위 워크플로

`uses: workflow`를 사용하면 `workflowId:`(저장된 워크플로) 또는 인라인 `workflow:` 블록으로 워크플로를 조합할 수 있습니다. 해당 단계의 출력은 하위 실행 결과가 됩니다. 하위 워크플로의 단계 출력은 `output.outputs['job.step']`으로 참조하세요.

```yaml
jobs:
  main:
    steps:
    - id: build_each
      foreach: '{{ inputs.targets }}'
      uses: workflow
      inputs:
        target: '{{ item }}'
      workflow:
        version: agent-workflow/v1
        title: Build target
        description: Build and package one target.
        jobs:
          main:
            steps:
            - id: compile
              run: make {{ inputs.target }}
            - id: package
              run: tar czf {{ inputs.target }}.tgz build/
    - id: summary
      uses: transform
      value: '{% for r in steps.build_each.output %}{{ r.status }} {% endfor %}'
```

## 템플릿 참조

| 참조 | 사용 위치 |
|---|---|
| `{{ inputs.x }}` | 어디서나: 워크플로 입력 |
| `{{ steps.<id>.output }}` | 어디서나: 같은 작업(job)의 이전 단계 |
| `{{ jobs.<job>.<step>.output }}` | 의존 작업(dependency job)에서 완료된 단계 |
| `{{ item }}` / `{{ index }}` | `foreach` 단계 내부 |
| `{{ round }}` / `{{ last }}` | `loop` 단계 내부 |
| `{{ now }}` | 현재 타임스탬프 |
| `{{ env.HOME }}` | 프로세스 환경 변수 |

템플릿은 Nunjucks 필터(`| trim`, `| int`, `| dump`, `| default(...)`, `{% for %}` 등)를 지원하므로 단계 사이에서 데이터를 원하는 모양으로 가공할 수 있습니다.

## 전체 예시

### 조사, 요약 및 보고서 작성

웹을 검색하고 핵심 내용을 요약한 뒤 Markdown 보고서를 조합합니다. 한 작업(job) 안에서 순서대로 실행되므로 `needs` 연결을 적을 필요가 없습니다.

```yaml
version: agent-workflow/v1
title: Research Brief
description: Search the web on a topic and produce a short Markdown brief.
inputs:
  topic:
    type: string
    default: coffee brewing
jobs:
  main:
    steps:
    - id: search
      tool: web_search/web_search
      params:
        search_query: '{{ inputs.topic }} latest'
        limit: 5
    - id: summarize
      prompt: 'Summarize the key points from these results in 4 bullets.

        Results: {{ steps.search.output }}

        '
    - id: report
      uses: transform
      value: "# {{ inputs.topic }} \u2014 brief ({{ now }})\n{{ steps.summarize.output }}\n"
```

### 조건부 라우팅

점수에 따라 승인 또는 거절로 분기한 뒤, 어느 쪽이든 항상 최종 보고를 작성합니다.

```yaml
version: agent-workflow/v1
title: Lead Router
description: Route a lead by score, reporting the outcome either way.
inputs:
  score:
    type: number
    default: 42
jobs:
  main:
    steps:
    - id: approve
      if: inputs.score >= 60
      uses: transform
      value: approved
    - id: reject
      else_of: approve
      uses: transform
      value: rejected
    - id: report
      needs:
      - approve
      - reject
      run_when: always
      uses: transform
      value: 'outcome: {{ steps.approve.output | default('''') }}{{ steps.reject.output | default('''')
        }}'
```

### 수렴할 때까지 반복

최대 횟수 제한 안에서 자체 점검이 승인할 때까지 초안을 반복 개선합니다.

```yaml
version: agent-workflow/v1
title: Refine Until Good
description: Improve a draft until a self-check approves it.
inputs:
  brief:
    type: string
    default: A tweet announcing our new feature.
jobs:
  main:
    steps:
    - id: refine
      prompt: 'Improve this draft. Return the improved draft and whether it is ready.

        Previous attempt: {{ last | default(inputs.brief) }}

        '
      output_schema:
        type: object
        required:
        - draft
        - approved
        properties:
          draft:
            type: string
          approved:
            type: boolean
      loop:
        until: output.approved == true
        maxRounds: 4
    - id: publish
      uses: transform
      value: '{{ steps.refine.output.draft }}'
```
