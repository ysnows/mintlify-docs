자동화는 매번 직접 시작하지 않아도 일을 해 줍니다. 에이전트에게 무언가를 시키거나, 저장한 워크플로를 실행하거나, 셸 명령을 실행합니다. 일정에(한 번, 또는 반복해서), 새 이메일이나 폴더의 파일처럼 무언가 일어날 때, 또는 직접 시작할 때 실행됩니다. 아침 뉴스 요약, 주간 계획, 가격 확인에 쓰세요.

실행마다 자기 대화가 시작되고, 결과는 자동화에 나타납니다. Mac에서 알림을 받거나, 결과를 IM 채팅으로 보내거나, GitHub에 답글을 달거나, 들은 것을 프로젝트의 Ideas 보드에 추가할 수도 있습니다.

각 자동화는 세 부분으로 읽히며, 그 자리에서 또는 말로 각각 바꿀 수 있습니다.

| 부분 | 담는 것 |
| --- | --- |
| **시점(무엇이 시작하나)** | 일정, 이벤트, 또는 직접 |
| **단계** | 실행하는 에이전트와 지침, 워크플로, 또는 셸 명령 |
| **그러면(실행 후)** | 결과가 가는 곳과 어떻게 듣는지 |

실행은 그 아래 막대로 보여, 무엇이 실행됐고 무엇이 실패했는지 한눈에 보입니다.

이 영상은 자동화를 다룬 뒤 워크플로, 변수, 알림과 방해금지 시간으로 결과를 듣는 방법을 봅니다.

## 채팅으로 자동화 설정

<Steps>
  <Step title="자동화 열기">
    **채팅 창** 사이드바에서 **자동화**를 고른 뒤 **새 자동화**를 선택하세요.
  </Step>
  <Step title="할 일과 시각 말하기">
    작성기에 작업과 시각을 적으세요. 예를 들어 "평일 아침 8시에 가장 중요한 AI 뉴스를 링크와 함께 다섯 항목으로 요약해 줘"입니다. 또는 시작 예시 중 하나를 고르면 작성기가 채워지고, 보내기 전에 고칠 수 있습니다.

    저장한 워크플로가 있으면 **일정에 따라 워크플로 실행** 아래에 몇 개가 나타납니다. 하나를 고르면 매일 9시에 그 워크플로를 실행하는 요청이 채워집니다. 보내기 전에 시각을 바꾸거나 입력 값을 추가하세요.
  </Step>
  <Step title="초안 확인">
    Enconvo가 작업을 설정하고 채팅에 카드로 보여 준 뒤, 언제 실행되는지 쉬운 말과 현지 시간으로 답합니다. 시각을 빼면 합리적인 시각을 고르고 그렇다고 말합니다. 어떤 제품을 볼지처럼 답이 없으면 작업이 될 수 없을 때만 질문합니다.
  </Step>
  <Step title="켜기">
    새 자동화는 꺼진 채로 시작하며, 채팅 옆에 **초안(아직 켜지지 않음)**이라고 표시됩니다. 확인한 뒤 **켜기**를 선택하세요. 그렇게 하기 전에는 아무것도 실행되지 않습니다. 작업은 대화 위의 **이 채팅에서 설정**과 작업 목록에 나타납니다. 계속 대화해 바꾸거나, 일시 중지하거나, 다시 시작하세요.
  </Step>
</Steps>

작업을 완전한 지침으로 쓰세요. 실행마다 설정한 채팅을 보지 못하는 새 대화가 시작되므로, "내일 또 그거 해"보다 "오늘의 주요 AI 뉴스를 링크와 함께 다섯 항목으로 요약해"가 더 잘 됩니다.

## 앞으로 올 것과 실행된 것 보기

자동화 맨 위의 **오늘**은 다음에 실행될 것과 이미 실행된 모든 것을 각 실행의 결과와 함께 보여 줍니다. 실행을 선택해 읽거나, 실패한 실행을 다시 시도하세요.

각 자동화의 최근 실행은 시작되자마자 사이드바의 **채팅** 아래에도 시계 표시와 함께 나타납니다. 그 이전 실행은 그 실행의 채팅에서 한 번 클릭하면 됩니다.

### 예약 채팅으로 돌아가기

예약 채팅은 보관되지만 사이드바의 **채팅** 아래에는 나타나지 않습니다. Enconvo가 답을 기다리는 채팅처럼 돌아가려면, 대화 위의 채팅 이름을 선택하고 **예약 채팅** 아래에서 고르세요. 거기서 채팅을 삭제할 수도 있습니다. 그 안에서 설정한 작업은 계속 실행됩니다.

### 아무 채팅에서나 요청

아무 채팅에서나 요청할 수도 있습니다. "내일 9시에 청구서 보내라고 알려 줘"나 "매주 월요일 아침, 이번 주 마감을 나열해 줘"처럼요. 에이전트가 같은 종류의 작업을 설정하고 카드를 보여 준 뒤, 언제 실행되는지 확인합니다. 카드의 **열기**를 선택하면 **자동화**에서 봅니다. 오래된 채팅의 카드는 그 사이 작업이 일시 중지됐는지, 끝났는지, 삭제됐는지를 보여 줍니다.

## 이벤트로 또는 직접 시작

시각 대신, 무언가 일어날 때 자동화가 시작될 수 있습니다. 자동화 채팅에서 무엇이 시작해야 하는지 설명하면 Enconvo가 트리거를 설정합니다.

| 무엇이 시작하나 | 언제 실행되나 |
| --- | --- |
| 일정 | 정한 시각에 |
| 직접 | **실행**을 선택할 때. 입력한 텍스트가 있으면 그것을 다룹니다. **PopBar에 표시**를 켜면 선택한 텍스트에서 실행하고, **Dynamic Island 홈에 표시**를 켜면 Dynamic Island에 버튼이 생깁니다. |
| 폴더 변경 | 폴더에서 파일이 추가, 변경, 제거될 때마다 |
| 앱 | 앱이 열리거나, 종료되거나, 앞으로 오거나, 한동안 앞에 있을 때 |
| Discord 또는 Telegram 메시지 | 연결된 봇이 읽을 수 있는 메시지마다 |
| 새 이메일 | 에이전트가 읽도록 허용한 [이메일](/ko/integrations/email) 플러그인 메일함의 새 메일마다(1분마다 확인), Mail이 열려 있는 동안 Apple Mail에서(2분마다), 또는 Gmail Connector를 통한 Gmail에서(약 5분마다) |
| GitHub | 연결한 저장소에서 이슈나 pull request가 열리거나, 이슈에 라벨이 붙거나, 댓글이 나를 멘션하거나, CI가 실패하거나, 릴리스가 게시될 때. [GitHub 트리거](/ko/workflows/scheduled-jobs)를 보세요. |
| MCP 이벤트 | 연결된 MCP 서버가 보고하는 이벤트마다 |
| 텍스트로 변환된 녹음 | Enconvo가 텍스트 변환을 끝낸 녹음마다 |
| 웹 페이지와 피드 | 새 피드 항목마다, 또는 페이지 텍스트가 바뀔 때마다 |
| 복사 | 클립보드 기록이 무시하지 않는 앱에서 복사할 때마다 |
| Mac 이벤트 | Mac이 깨어나거나, 잠금 해제되거나, 전원이 연결되거나 분리되거나, 자리를 비우거나 돌아올 때 |
| 캘린더 이벤트 | 캘린더 이벤트가 시작되기 전, 또는 끝날 때 |
| 회의 | Zoom, Teams, FaceTime, WeChat 통화에서 회의가 시작할 때 |
| 로그인 | 로그인한 뒤 Enconvo가 시작될 때마다 한 번 |
| 웹훅 요청 | 요청이 자동화 자신의 주소에 닿을 때마다. 페이지에 복사 버튼과 함께 표시됩니다. |

Enconvo는 실행 중인 동안 Mac에서 이벤트를 감시합니다. 작업의 트리거 행은 Enconvo가 꺼져 있는 동안의 이벤트에 무슨 일이 일어나는지 말합니다.

### GitHub 트리거

<Steps>
  <Step title="GitHub 연결">
    **시점** 아래에서 GitHub를 고르고 **GitHub 연결**을 선택하세요. Enconvo 계정에 로그인해야 합니다.
  </Step>
  <Step title="저장소와 이벤트 고르기">
    **저장소**(또는 직접 입력하려면 **다른 저장소…**)와 **이벤트**를 고르세요. 라벨이 붙은 이슈라면 **라벨** 또는 **모든 라벨**을 고르세요. 저장소를 감시하려면 그 저장소의 관리자 접근이 필요합니다.
  </Step>
  <Step title="누가 시작할지 고르기">
    **나만**, **모든 사람**을 고르거나, 이벤트가 시작해야 하는 사람의 GitHub 사용자 이름을 추가하세요.
  </Step>
</Steps>

GitHub 이벤트는 Enconvo Cloud를 통해 Mac에 도착하고, 여기서 외부 트리거를 허용할 때까지 이 Mac용으로 봉인됩니다. 물으면 **이 Mac에서 허용**을 선택하세요. **이 Mac에서 외부 트리거 중지**는 다시 멈춥니다. 그러면 이벤트는 Enconvo Cloud에서 기다립니다.

이벤트 트리거에는 말로 적은 조건도 둘 수 있습니다. AI가 실행 전에 각 이벤트를 그 조건과 대조합니다. 맞지 않는 이벤트는 건너뛰며, 그래도 **그래도 실행**을 선택할 수 있습니다. 각 확인은 유료 AI 호출입니다. **최근 이벤트에서 시험**을 선택하면 아무것도 실행하지 않고 최근 이벤트 중 무엇을 실행했을지 봅니다.

## 자동화 관리

목록에서 자동화를 선택하면 활성, 일시 중지, 주의 필요 중 무엇인지 본 뒤 **시점**, **단계**, **그러면** 부분과 실행을 봅니다.

마지막 실행이 실패했거나 결과가 전달되지 않았으면, 이름 아래 메모가 이유를 말하고 고치는 방법을 제공합니다.

- **채팅으로 고치기**(에이전트 또는 워크플로 작업)는 오류를 적은 고치기 요청과 함께 작업의 채팅을 엽니다. **다시 실행**은 한 번 더 실행합니다.
- **다시 보내기**는 결과 보내기를 다시 시도하고, **결과 위치 변경**은 결과 선택기를 엽니다. 거기서 **Enconvo만**을 고르면 전달되지 않은 결과에 대한 메모도 지워집니다.
- 스스로 시작하는 작업은 연속 5번 실패하면 일시 중지됩니다. 고친 뒤 **켜기**를 선택하세요.

| 제어 | 하는 일 |
| --- | --- |
| **지금 실행** | 기다리지 않고 한 번 실행합니다. 실제로 실행되므로 에이전트가 도구나 포인트를 쓸 수 있습니다. 직접 시작하는 작업에는 대신 **실행**이 있습니다. |
| **채팅에 따라 변경** | 에이전트 작업에서, 작업을 설정한 채팅을 다시 엽니다(없으면 새 채팅을 시작). "7:30으로 옮겨"나 "날씨 추가"처럼 변경을 말할 수 있습니다. |
| **작업 이름** | 이름을 선택해 작업 이름을 바꿉니다. Return으로 저장하고 Esc로 취소합니다. |
| **일정** | 작업이 언제 실행되는지와 다음 실행을 보여 줍니다. 일정은 **매일 09:00과 18:00**이나 **매년 1월 1일 03:00**처럼 쉬운 말로 읽히며, 목록, 설정, 채팅 카드에서 같습니다. 선택하면 그 자리에서 시각을 바꿉니다. **한 번**, **매일**, **매주**, **매월**, **간격**, **Cron** 중 고르고 다음 실행을 확인한 뒤 **저장**을 선택하세요. 옆 스위치는 작업을 삭제하지 않고 이후 실행을 일시 중지합니다. |
| **지침** → **편집** | 에이전트에게 시키는 일(셸 명령 작업이면 명령)을 그 자리에서 바꿉니다. **⌘↩**를 누르거나 **저장**을 선택하세요. Esc는 취소합니다. |
| **결과** | 각 실행의 결과가 어디로 가는지 보여 줍니다. 선택해 IM 채널로 에이전트와 이야기한 채팅을 고르거나, **Enconvo만**을 골라 각 실행의 대화에 결과를 두세요. 변경은 바로 저장됩니다. **다른 채팅…**은 채팅 ID를 입력하는 편집기를 엽니다. |
| **실행 시 알림** | 실행이 끝나면 결과의 첫 줄과 함께 Mac 알림을 게시합니다. 클릭하면 작업이 열립니다. |
| **…** → **세부 정보 편집** | 에이전트, 설명, 최대 실행 횟수를 포함해 모든 필드의 폼 편집기를 엽니다. |
| **…** → **복제** | 복사본을 만들어 초안으로 열므로, 켜기 전에 바꿀 수 있습니다. |
| **…** → **모든 실행** | 필터가 있는 전체 실행 기록을 엽니다. |
| **…** → **삭제** | 자동화와 실행 기록을 삭제합니다. 실행 중인 것을 삭제하면 그 실행도 멈춥니다. |

실행 막대를 선택하면 그 실행의 결과나 오류를 읽고, 그 대화에서 이어 가고, 복사하거나, 전달되지 않았을 때 결과를 다시 보냅니다.

### 고급 설정

자동화에서 **고급 설정**을 열어 어디까지 갈 수 있는지 정하세요.

| 설정 | 하는 일 |
| --- | --- |
| **실행 한도** | 전부 몇 번 실행하는지입니다. 끝난 자동화는 여기서 실행을 더 줄 수 있습니다. |
| **시간 제한** | 한 실행이 얼마나 걸릴 수 있는지, 15분에서 8시간입니다. 실행이 한도에 닿으면 실행이 더 긴 한도(**허용… 후 다시 실행**)를 제안해, 한 번의 클릭으로 시간을 더 주고 다시 실행합니다. |

### 자동화 찾기

이름, 지침, 명령, 워크플로로 목록을 검색하세요. 목록은 자동화를 **주의 필요**(마지막 실행이 실패했거나 결과가 전달되지 않음), 예정, **일시 중지**, **완료**(실행을 끝낸 한 번 자동화)로 묶습니다. 자동화가 둘 이상의 방식으로 시작하면, 목록 위의 버튼이 무엇이 시작하는지로 거르고, **전체**는 다시 모두 보여 줍니다.

열지 않고 작업에 동작하려면 목록에서 가리킨 뒤 **…**를 선택하거나 Control-클릭한 다음 **지금 실행**, **일시 정지** 또는 **이어서 실행**, **세부 정보 편집**, **삭제**를 고르세요. **작업 검색**에서 ↓를 누르면 첫 작업으로 가고, ↑와 ↓로 작업 사이를 이동합니다.

## 폼 편집기 쓰기

새 작업 화면에서 **대신 양식으로 작업 설정**을 선택하거나, 작업에서 **세부 정보 편집**을 선택하면 모든 필드를 직접 채웁니다.

<Frame caption="The task editor with an Agent instruction and a weekday schedule.">
  <img src="/images/guides/scheduled-task-editor.jpg" alt="에이전트, 지침, 월요일부터 금요일 09:00 주간 일정이 있는 예약 작업 편집 대화상자" />
</Frame>

1. 작업 이름을 짓고 무엇을 할지 고르세요. 에이전트와 지침이 있는 **에이전트에게 요청**, 저장한 [워크플로](/ko/workflows/introduction)를 실행하는 **워크플로 실행**, 또는 Mac의 스크립트를 위한 **셸 명령 실행**입니다. 워크플로라면 받아야 할 입력을 채우세요. 비워 둔 입력은 워크플로의 기본값을 씁니다.
2. **시점** 아래에서 **한 번**, **매일**, **매주**, **매월**, **간격**, **Cron**을 고르고 **다음 실행(현지 시간)** 미리보기를 확인하세요. **Cron**에서는 입력하는 동안 표현식 아래 줄이 뜻을 말합니다. 예를 들어 `0 9-17 * * 1-5`는 **평일 09:00부터 17:00까지 매시간**입니다.
3. **결과 보내기** 아래에서 **각 결과를 채팅으로 보내기**를 켜면 결과를 IM 채팅으로 전달합니다. 선택기에 나타나려면 그 채팅에서 먼저 에이전트와 이야기해야 할 수 있습니다.
4. **추가 옵션**은 설명과 최대 실행 횟수를 추가합니다.
5. **저장**(또는 **작업 만들기**)을 선택하세요. **테스트 실행**은 작업을 저장하고 바로 실행합니다.

셸 명령 작업과, 채팅 ID로 결과를 보내는 것은 이 편집기에서만 설정합니다. 예약 채팅은 에이전트와 워크플로 작업을 다룹니다. 이벤트로 시작하는 작업은 폼이 트리거를 바꾸지 않습니다. 무엇이 시작하는지 자동화 채팅에서 바꾸세요.

셸 명령 작업은 실행이 실패할 때만 알립니다(**실패 시 알림**). 이런 작업은 몇 분마다 실행되는 경우가 많기 때문입니다.

## 워크플로 예약

워크플로 작업은 고른 시각에 저장한 워크플로를 실행하며, 워크플로 편집기에서 **실행**을 선택하는 것과 같습니다. 편집기에서 **워크플로 실행**을 고르거나 예약 채팅에 요청하세요. 예를 들어 "평일 9시에 주제 AI 뉴스로 내 Content Pipeline을 실행해"입니다. 이름으로 워크플로를 찾고, 언급한 입력을 채우고, 나머지는 기본값으로 둡니다.

각 실행의 결과는 워크플로 마지막 단계의 출력이므로, 다른 결과처럼 채팅으로 보내거나 알림에 보여 줄 수 있습니다. 단계가 실패하면 실행은 그 단계의 오류와 함께 실패로 표시됩니다.

- 작업 세부 정보는 워크플로와 입력을 보여 줍니다. **열기**를 선택하면 워크플로를 보고, **변경**을 선택하면 다른 워크플로를 고르거나 입력을 바꿉니다.
- 펼친 실행 아래에서 **실행 열기**를 선택하면 **워크플로**에서 그 실행의 각 단계를 봅니다. 마지막 실행이 실패하면 작업 이름 아래 메모가 **실패한 실행 열기**를 제공합니다.
- 실행은 자동화의 **시간 제한**에서 멈춥니다([고급 설정](/ko/workflows/scheduled-jobs) 참고). 승인 단계의 답을 기다리는 시간은 포함되지 않습니다.
- 워크플로가 삭제되면 작업이 일시 중지되고 그렇다고 말합니다. **워크플로 선택**으로 다른 것을 주거나, **삭제**로 작업을 제거하세요.

## 설정에서 많은 작업 관리

**설정 → 자동화**는 셸 명령 작업을 포함해 모든 작업을 표로 나열합니다. **활성**, **일시 중지**, **주의 필요**로 거르고, 검색하고, 여러 작업을 선택해 함께 일시 중지, 재개, 삭제하세요. 작업의 기록은 각 실행의 상태를 보여 줍니다.

| 상태 | 확인할 것 |
| --- | --- |
| 실패 | 지침, 에이전트의 도구, 셸 종료 상태, 또는 오류 세부 정보 |
| 성공 / 전달되지 않음 | 작업은 실행됐지만 IM 채널이나 채팅에 주의가 필요합니다 |
| 완료 · 더 이상 실행 없음 | 한 번 작업이 끝났습니다 |
| 일시 중지 | 이후 실행을 원하면 다시 켜세요 |

기록에서 **대화 열기**는 에이전트 실행을 열고, **결과 복사**는 출력을 복사하며, **다시 보내기**는 구성한 채팅으로 결과를 실제 메시지로 다시 보냅니다.

## 실행 후

결과를 채팅으로 보내고 알리는 것 외에, **그러면(실행 후)**에는 두 가지 옵션이 더 있습니다.

- **GitHub에 답글**: GitHub 이벤트가 시작한 자동화에서, Enconvo는 실행을 시작한 이슈나 pull request에 댓글로 답글을 게시하기 전에 묻습니다. 하루 안에 아무도 승인하지 않은 답글은 게시되지 않습니다.
- **Ideas에 추가**: 자동화가 들은 각 GitHub 이슈, Discord나 Telegram 메시지, 이메일, 웹훅 요청이 프로젝트의 Ideas 보드에 아이디어가 됩니다. 프로젝트 리드는 버그를 재현하고 수정을 계획하거나, 요청을 조사하고 이유와 함께 닫거나 계획할 수 있으며, 무엇이든 바꾸기 전에 묻습니다. [프로젝트](/ko/ai/projects)를 보세요.

## 결과 듣기

- 워크플로는 단계와 에이전트를 다시 실행할 수 있는 작업으로 잇습니다. [워크플로 예약](/ko/workflows/scheduled-jobs)에서 고르거나, [워크플로](/ko/workflows/introduction)에서 만드세요.
- [변수](/ko/workflows/variables)는 오늘의 날짜나 선택한 텍스트처럼 매번 바뀌는 값을 프롬프트와 지침에 넣습니다.
- **설정 → 알림**은 실행이 끝났다는 것을 어떻게 듣는지 고릅니다. **방해금지 시간**을 켜면 아침까지 에이전트 질문과 끝난 작업을 보관하고, 승인 요청은 여전히 닿게 하려면 **승인 허용**을 켜세요. [알림](/ko/configuration/notifications)을 보세요.

## 알아 두면 좋은 점

- 자동화는 Mac에서 실행되므로 Enconvo가 실행 중이고 Mac이 깨어 있어야 합니다. 잠자거나 오프라인인 Mac은 실행하지 않습니다. 항상 켜진 스케줄러로 의존하지 마세요.
- 시각은 Mac의 현지 시간대입니다. 여행이나 시간대 변경 뒤에는 다음 실행 시각을 확인하세요.
- 한 번 작업은 미래의 시각이 필요하며, 실행한 뒤 **완료**로 이동합니다.
- 에이전트에게 나중에 Apple 메시지를 보내 달라고 하면 한 번 자동화를 설정하므로, 자동화에서 예약된 메시지를 보거나 거기서 취소할 수 있습니다.
- 29일에서 31일의 월간 작업은 그 날짜가 없는 달을 건너뜁니다.
- Mac 알림은 [알림](/ko/configuration/notifications)의 **시스템 알림 보내기**와 macOS 집중 모드도 따릅니다. 이미 그 실행을 보고 있으면 알림은 건너뜁니다.
- 실행 기록은 각 작업의 최근 100개 실행을 유지합니다. 더 오래된 실행과 그 대화는 제거됩니다. 작업을 삭제하기 전에 중요한 것은 복사하세요.
