---
title: "知识库 MCP"
description: "让 Mac 上的 Claude、Cursor、Codex 和其他 MCP 客户端搜索并阅读你共享的知识库。"
---

Enconvo 可以把你的知识库提供给同一台 Mac 上兼容 MCP 的 AI 客户端。客户端只能搜索和阅读你共享的知识库，其他内容一概无法访问；访问权限为只读。这与 **设置 → MCP 服务器** 无关，后者是为 Enconvo 的智能体添加外部工具。

## 连接客户端

1. 打开[知识库](/zh/ai/knowledge-base)，点按齿轮图标（**知识库设置**），然后选择 **AI 客户端（MCP）**。
2. 打开 **启用知识库 MCP**。它默认关闭，关闭期间已连接的客户端会被拒绝。
3. 选择客户端可以看到哪些内容。**与 AI 客户端共享这个知识库** 针对你当前打开的知识库，**共享知识库** 则列出所有知识库。语音输入历史记录和记忆在你打开之前保持隐藏。
4. 在 **连接客户端** 下选择你的客户端（Claude Code、Cursor、Codex 或 Claude Desktop），并复制其配置。
5. 让客户端列出知识库，然后搜索其中一个并阅读一个匹配的条目。

本地端点为：

```text
http://localhost:54535/knowledge_base/mcp
```

它使用 Streamable HTTP 传输方式。客户端使用期间请保持 Enconvo 运行。Claude Desktop 通过一个小型桥接程序 `mcp-remote` 连接，因此其配置需要 Node.js；请按照对话框中显示的对应客户端说明操作。

## 可用工具

| 工具 | 用途 |
| --- | --- |
| `kb_list` | 列出可见的知识库 |
| `kb_search` | 搜索某个可见的知识库 |
| `item_list` | 列出某个可见知识库中的条目 |
| `item_read` | 分页阅读条目已索引的文字 |

这些工具都是只读的。该端点不提供通用的记忆或录音工具。阅读条目时，可能会把其源路径或 URL 作为元数据返回。

## 访问与处理

服务器只接受回环地址连接，不需要令牌。开启后，本机进程都可以阅读你共享的知识库。已连接的 AI 客户端可能会把获取到的内容发送给它自己的模型服务提供商，因此也请检查该客户端的设置。

搜索使用在 **设置 → 记忆** 的 **搜索** 下设置的嵌入模型。它在 Enconvo Cloud 上运行时，搜索文字会发送到 Enconvo Cloud。“本地端点”并不代表检索和回答的每个环节都离线运行。

## 故障排除

| 问题 | 解决方法 |
| --- | --- |
| 连接被拒绝 | 确认 Enconvo 及其 Local API 正在运行。 |
| Forbidden / 403 | 确认 **启用知识库 MCP** 已打开、客户端从这台 Mac 连接，并且其配置与对话框中的一致。 |
| 找不到知识库 | 在 **共享知识库** 下打开该知识库。对客户端来说，隐藏的和不存在的知识库看起来是一样的。 |
| 在浏览器中打开该 URL 显示 405 | 浏览器的 GET 请求不是 MCP 请求。请用 MCP 客户端连接。 |
| 长文档返回不完整 | 让客户端用 `item_read` 请求后续页面。 |

要停止所有访问，关闭 **启用知识库 MCP**。要缩小客户端可以检索的范围，在 **共享知识库** 下关闭单个知识库。
