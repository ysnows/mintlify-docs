自动化会替你完成工作，无需你每次手动启动：它可以让智能体做某件事、运行你保存的某个工作流，或运行一条 Shell 命令。它可以按计划运行（运行一次或反复运行），在某件事发生时运行（例如收到新邮件或文件夹中出现新文件），也可以由你手动启动。可以用它生成早间新闻简报、每周计划，或监控价格。

每次运行都会开启一个独立的对话，结果会显示在该自动化中。你还可以让 Enconvo 在 Mac 上通知你、将结果发送到即时通讯聊天、在 GitHub 上回复，或将收到的内容加入项目的 Ideas 看板。

每个自动化都由三部分组成，你可以直接就地修改每一部分，或用自己的话描述更改：

| 部分 | 包含内容 |
| --- | --- |
| **触发条件（When）** | 定时计划、事件或由你手动启动 |
| **步骤（Steps）** | 要运行的智能体与指令、工作流或 Shell 命令 |
| **后续操作（Then）** | 结果去向以及如何通知你 |

它的运行记录会以条形展示在下方，让你一眼看出哪些已运行、哪些失败了。

## 通过聊天设置自动化

<Steps>
  <Step title="打开自动化">
    在 **聊天窗口** 的侧边栏中选择 **自动化**，然后选择 **新建定时任务**。
  </Step>
  <Step title="说明要做什么、何时做">
    在输入框中描述任务及其时间，例如“每个工作日 8:00，用五条要点为我简报最重要的 AI 新闻，并附上链接。”也可以选择一个起始模板，它会填入输入框，供你在发送前调整。

    如果你保存过工作流，其中几个会出现在 **按计划运行工作流** 下。选择一个，即可填入每天 9:00 运行该工作流的请求，然后在发送前修改时间或添加输入值。
  </Step>
  <Step title="检查草稿">
    Enconvo 会设置好任务，在聊天中以卡片形式显示，并用通俗的语言和你的本地时间告诉你它将何时运行。如果你没有说明时间，它会选择一个合理的时间并告诉你。只有当缺少答案任务就无法运行时（例如要监控哪个产品），它才会提问。
  </Step>
  <Step title="开启任务">
    新建的自动化默认处于关闭状态，在聊天旁边显示为 **草稿（尚未开启）**。检查无误后选择 **开启**；在此之前不会运行任何内容。任务会出现在对话上方的 **在此聊天中设置** 下以及任务列表中。继续聊天即可修改、暂停或恢复它。
  </Step>
</Steps>

<Frame caption="新任务可以从一句话或一个起始模板开始。">
  <img src="/images/guides/scheduled-tasks-new.jpg" alt="设置任务界面，包含一个输入框和六个起始任务" />
</Frame>

请把任务写成一条完整的指令。每次运行都会开启一个新对话，看不到你设置任务时的那段聊天，所以“用五条要点总结今天最重要的 AI 新闻，并附上链接”比“明天再做一次”效果更好。

## 查看即将运行与已运行的任务

自动化顶部的 **今天** 会显示接下来要运行的任务，以及已经运行的全部任务和每次运行的结果。选择一次运行即可阅读其结果，或让失败的运行重试一次。

每个自动化最近的一次运行也会在开始时立即显示在侧边栏的 **聊天** 下，并带有时钟标记。点开该次运行的聊天即可一键查看它更早的运行记录。

### 返回定时任务聊天

定时任务聊天会被保留，但不会出现在侧边栏的 **聊天** 下。要返回其中一个（例如 Enconvo 正在等你回答的聊天），请选择对话上方的聊天名称，然后在 **定时任务聊天** 下选择它。你也可以在那里删除聊天；在其中设置的任务会继续运行。

### 在任意聊天中提出

你也可以在任意聊天中提出，例如“明天 9 点提醒我发送发票”或“每周一早上列出我这周的截止日期”。智能体会设置同样的任务，显示其卡片，并确认它将何时运行。选择卡片上的 **打开**，即可在 **自动化** 中查看它。旧聊天中的卡片会显示任务此后是否已暂停、已完成或已删除。

## 由事件触发或手动启动

除了指定时间，自动化也可以在某件事发生时启动。在自动化聊天中描述由什么启动它，Enconvo 会设置好触发器。

| 启动方式 | 运行时机 |
| --- | --- |
| 计划 | 在你设置的时间 |
| 你手动启动 | 当你选择 **运行** 时；如果你输入了文本，会以该文本为处理对象。开启 **在 PopBar 中显示** 可对你选中的文本运行，开启 **显示在灵动岛主页** 可在灵动岛上添加一个按钮。 |
| 文件夹变化 | 文件夹中每有一个文件被添加、修改或删除时 |
| 应用 | 应用打开、退出、切换到前台，或在前台停留一段时间时 |
| Discord 或 Telegram 消息 | 已连接的机器人能读取的每条消息 |
| 新邮件 | 在 [Email](/zh/integrations/email) 插件允许智能体读取的邮箱中的每封新邮件（每分钟检查一次）、Apple Mail 中的每封新邮件（Mail 打开时每两分钟检查一次），或通过 Gmail 连接器收到的每封 Gmail 新邮件（约每五分钟检查一次） |
| GitHub | 当你连接的仓库中有 Issue 或 Pull Request 被打开、Issue 被贴上标签、评论中提及你、CI 失败或发布新版本时。参见 [GitHub 触发器](#github-触发器)。 |
| MCP 事件 | 已连接的 MCP 服务器报告的每个事件 |
| 已转写的录音 | Enconvo 每完成一段录音的转写时 |
| 网页和订阅源 | 订阅源每出现一个新条目，或网页文字每次发生变化时 |
| 复制 | 你每次复制内容时（剪贴板历史忽略的应用除外） |
| Mac 事件 | Mac 唤醒、解锁、接通或断开电源，或你离开或回到 Mac 时 |
| 日历事件 | 日历事件开始前，或结束时 |
| 会议 | 在 Zoom、Teams、FaceTime 或微信通话中开始会议时 |
| 登录 | 每次登录后 Enconvo 启动时运行一次 |
| Webhook 请求 | 每当有请求到达该自动化专属的地址时；地址显示在其页面上，并带有复制按钮 |

Enconvo 运行期间会监测 Mac 上的事件。Enconvo 关闭期间发生的事件如何处理，请查看任务中该触发器所在行的说明。

### GitHub 触发器

<Steps>
  <Step title="连接 GitHub">
    在 **触发条件（When）** 下选择 GitHub，然后选择 **连接 GitHub**。你需要先登录自己的 Enconvo 账户。
  </Step>
  <Step title="选择仓库和事件">
    选择一个 **仓库**（或选择 **其他仓库…** 手动输入）以及一个 **事件**。如果是 Issue 被贴上标签的事件，请选择具体的 **标签** 或 **任意标签**。监听仓库需要拥有该仓库的管理员权限。
  </Step>
  <Step title="选择谁可以触发">
    选择 **仅我**、**任何人**，或添加其事件可以触发该自动化的 GitHub 用户名。
  </Step>
</Steps>

GitHub 事件会通过 Enconvo Cloud 到达你的 Mac，并在你允许这台 Mac 接收外部触发前保持封存：当系统询问时，选择 **在这台 Mac 上允许**。选择 **在这台 Mac 上停用外部触发** 可再次停用；之后事件会暂存在 Enconvo Cloud 上。

事件触发器还可以设置一个用你自己的话描述的条件。每次运行前，AI 会根据该条件检查事件；不匹配的事件会被跳过，你仍可以对其选择 **仍然运行**。每次检查都是一次付费的 AI 调用。选择 **用最近的事件试一下**，可以查看它会对哪些最近的事件运行，而不会真正运行任何内容。

## 管理自动化

在列表中选择一个自动化即可查看它处于活动、已暂停还是需要处理的状态，接着是它的 **触发条件（When）**、**步骤（Steps）** 和 **后续操作（Then）** 部分以及运行记录。

如果上次运行失败或结果未能发送，名称下方会有一条说明原因的提示，并提供修复方法：

- **通过聊天修复**（适用于智能体或工作流任务）会打开该任务的聊天，并附上一条写明错误的修复请求；**再次运行** 会再运行一次。
- **重新发送** 会重试发送结果，**更改结果保存位置** 会打开结果选择器。在那里选择 **仅 Enconvo** 也会清除结果未发送的提示。
- 自行启动的任务连续 5 次运行失败后会暂停。修复后选择 **开启**。

| 控件 | 作用 |
| --- | --- |
| **立即运行** | 立即运行一次任务。这是真实运行，智能体可能会使用工具或消耗点数。手动启动的任务显示的是 **运行**。 |
| **随聊天更改** | 对于智能体任务，会重新打开设置该任务的聊天（如果没有，则开启一个新聊天），方便你描述修改，例如“改到 7:30”或“加上天气”。 |
| **任务名称** | 选择名称即可重命名任务。按 Return 保存，按 Esc 取消。 |
| **日程安排** | 显示任务何时运行以及下次运行时间。计划以通俗的语言显示，例如 **每天 09:00 和 18:00** 或 **每年 1 月 1 日 03:00**，在列表、设置和聊天卡片中显示一致。选择它即可直接修改时间：选择 **一次**、**每天**、**每周**、**每月**、**间隔** 或 **Cron**，查看接下来的运行时间，然后选择 **保存**。旁边的开关可以暂停之后的运行，而不删除任务。 |
| **指令** → **编辑** | 直接修改要求智能体做的事（Shell 命令任务则修改命令）。按 **⌘↩** 或选择 **保存**；按 Esc 取消。 |
| **结果** | 显示每次运行的结果发送到哪里。选择它，然后选择一个你通过即时通讯渠道与智能体聊过的聊天，或选择 **仅 Enconvo**，将结果保留在每次运行的对话中；更改会立即保存。**另一个聊天…** 会打开编辑器，供你输入聊天 ID。 |
| **运行时通知我** | 每次运行结束时发送一条 Mac 通知，显示结果的第一行。点按通知即可打开任务。 |
| **…** → **编辑详情** | 打开表单编辑器，一次编辑所有字段，包括智能体、描述和最大运行次数。 |
| **…** → **复制** | 创建一个副本并以草稿形式打开，方便你在开启前修改。 |
| **…** → **所有运行记录** | 打开带筛选器的完整运行历史。 |
| **…** → **删除** | 删除该自动化及其运行历史。删除正在运行的自动化也会停止该次运行。 |

选择一条运行记录条，即可阅读该次运行的结果或错误、在其对话中继续追问、复制内容，或在结果未发送时重新发送。

### 高级设置

在自动化上打开 **高级设置**，可设置它最多能运行多少次、运行多久：

| 设置 | 作用 |
| --- | --- |
| **运行次数上限** | 总共运行的次数。可以在这里为已完成的自动化增加更多运行次数。 |
| **时间上限** | 单次运行最长可持续的时间，从 15 分钟到 8 小时不等。当某次运行达到时间上限时，运行界面会提供更长的上限（**放宽到 … 并重新运行**），一键延长时间并重新运行。 |

### 查找自动化

按名称、指令、命令或工作流搜索列表。列表将自动化分为 **需要处理**（上次运行失败或结果未发送）、即将运行、**已暂停** 和 **已完成**（已经运行过的一次性自动化）。当你的自动化有多种启动方式时，列表上方的按钮可按启动方式筛选，选择 **全部** 可重新显示全部项目。

要在不打开任务的情况下操作它，请在列表中将指针移到任务上并选择 **…**，或按住 Control 点按它，然后选择 **立即运行**、**暂停** 或 **继续运行**、**编辑详情** 或 **删除**。在 **搜索任务** 中按 ↓ 可跳到第一个任务，然后用 ↑ 和 ↓ 在任务之间移动。

## 使用表单编辑器

在新建任务界面选择 **改用表单设置任务**，或在任务上选择 **编辑详情**，即可自己填写每个字段。

<Frame caption="任务编辑器，包含一条智能体指令和一个工作日计划。">
  <img src="/images/guides/scheduled-task-editor.jpg" alt="编辑定时任务对话框，包含一个智能体、一条指令，以及每周一至周五 09:00 运行的计划" />
</Frame>

1. 为任务命名并选择它要做什么：**询问智能体**（选择智能体并填写指令）、**运行工作流**（运行你保存的某个[工作流](/zh/workflows/introduction)），或 **运行 Shell 命令**（在 Mac 上运行脚本）。对于工作流，请填写需要传给它的输入；留空的输入会使用工作流的默认值。
2. 在 **时间** 下选择 **一次**、**每天**、**每周**、**每月**、**间隔** 或 **Cron**，并查看 **下次运行时间（本地时间）** 预览。在 **Cron** 中，表达式下方的一行会随着你的输入说明其含义，例如 `0 9-17 * * 1-5` 显示为 **工作日 09:00 至 17:00 每小时一次**。
3. 在 **发送结果** 下开启 **将每个结果发送到聊天**，即可将结果发送到即时通讯聊天。你可能需要先在该聊天中与智能体对话，它才会出现在选择器中。
4. **更多选项** 可添加描述和最大运行次数。
5. 选择 **保存**（或 **创建任务**）。**测试运行** 会保存任务并立即运行。

Shell 命令任务以及按聊天 ID 发送结果，只能在此编辑器中设置；定时任务聊天负责智能体任务和工作流任务。对于由事件启动的任务，表单无法修改触发器：请在自动化聊天中修改启动方式。

Shell 命令任务只在运行失败时通知你（**失败时通知我**），因为这类任务通常每隔几分钟就运行一次。

## 定时运行工作流

工作流任务会在你选择的时间运行一个已保存的工作流，效果与在工作流编辑器中选择 **运行** 相同。在编辑器中选择 **运行工作流**，或询问定时任务聊天，例如“每个工作日 9 点运行我的 Content Pipeline，主题为 AI 新闻”。它会按名称找到工作流，填入你提到的输入，其余保留默认值。

每次运行的结果是工作流最后一个步骤的输出，因此可以像其他结果一样发送到聊天或显示在通知中。如果某个步骤失败，该次运行会被标记为失败，并显示该步骤的错误。

- 任务详情会显示工作流及其输入。选择 **打开** 可查看工作流，选择 **更改** 可换一个工作流或修改输入。
- 在展开的运行下，选择 **打开运行**，即可在 **工作流** 中查看该次运行的每个步骤。上次运行失败时，任务名称下方的提示会提供 **打开失败的运行**。
- 运行会在达到该自动化的 **时间上限**（参见[高级设置](#高级设置)）时停止。等待你回答审批步骤的时间不计入其中。
- 如果工作流被删除，任务会暂停并给出提示。选择 **选择工作流** 可为它指定另一个工作流，选择 **删除** 可移除该任务。

## 在设置中管理大量任务

**设置 → 自动化** 会以表格列出所有任务，包括 Shell 命令任务。你可以按 **已激活**、**已暂停** 或 **需要处理** 筛选、搜索，或选择多个任务一起暂停、恢复或删除。任务的历史记录会显示每次运行的状态：

| 状态 | 要检查的内容 |
| --- | --- |
| 失败 | 指令、智能体的工具、Shell 退出状态或错误详情 |
| 成功 / 未送达 | 任务已运行，但其即时通讯渠道或聊天需要处理 |
| 已完成 · 不再运行 | 一次性任务已经完成 |
| 已暂停 | 如需之后继续运行，请重新开启 |

在历史记录中，**打开对话** 可打开智能体的那次运行，**复制结果** 可复制其输出，**重新发送** 会把结果作为一条真实消息再次发送到配置的聊天。

## 运行之后

除了将结果发送到聊天和通知你之外，**后续操作（Then）** 还有两个选项：

- **在 GitHub 上回复**：对于由 GitHub 事件触发的自动化，Enconvo 会在将回复作为评论发布到触发该次运行的 Issue 或 Pull Request 之前询问你。一天内无人批准的回复不会发布。
- **加入 Ideas**：自动化收到的每条 GitHub Issue、Discord 或 Telegram 消息、邮件或 Webhook 请求，都会成为项目 Ideas 看板上的一条想法。项目的负责人可以复现问题并规划修复方案，或调研需求后附上原因将其关闭或制定方案，并在做出任何改动前询问你。参见[项目与看板](/zh/ai/projects)。

## 获取结果通知

- 工作流将多个步骤和智能体串联成可重复运行的任务。你可以在[定时运行工作流](#定时运行工作流)中选择一个，或在[工作流](/zh/workflows/introduction)中自行构建。
- [变量](/zh/workflows/variables)可以将每次都会变化的值（例如今天的日期或你选中的文本）放进提示词和指令中。
- **设置 → 通知** 用于选择运行完成后如何通知你。开启 **安静时段** 可将智能体的提问和已完成的任务暂缓到早上再通知，如果希望审批请求仍能照常送达，请开启 **批准请求照常提醒**。参见[通知](/zh/configuration/notifications)。

## 须知

- 自动化在你的 Mac 上运行，因此 Enconvo 必须保持运行，Mac 也必须处于唤醒状态。休眠或离线的 Mac 不会运行它们；不要把它当作全天候运行的定时器。
- 时间采用 Mac 的本地时区。旅行或更改时区后，请检查下次运行时间。
- 一次性任务需要设定一个未来的时间，运行后会移到 **已完成**。
- 当你让智能体稍后发送一条 Apple 信息时，它会创建一个一次性自动化，因此你可以在“自动化”中看到这条定时消息，或在那里取消它。
- 设在每月 29 日至 31 日的每月任务，会跳过没有该日期的月份。
- Mac 通知还受[通知](/zh/configuration/notifications)中的 **发送系统通知** 以及 macOS 专注模式影响。如果你正在查看该次运行，则不会发送通知。
- 运行历史会为每个任务保留最近 100 次运行；更早的运行及其对话会被删除。删除任务前，请复制重要内容。
