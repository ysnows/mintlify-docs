有些工作需要不止一个智能体：由研究员查找资料，由作者把资料写成文章，再由程序员和审查员完成代码改动。在聊天中点名这些智能体，你正在对话的智能体就会成为负责人。它会制定一份工作计划，把任务分配给每位成员，并根据目标检查结果。对于持续推进的工作，[项目](#项目)会把同一个文件夹的计划、聊天和文件集中放在一起。

下面的视频在 2 分钟内演示了完整流程：用 `@` 引入智能体、工作计划、看板以及项目。

## 把一项工作交给多个智能体

1. 在任意聊天中输入 `@` 和智能体名称的开头部分，然后按 Return 从列表中选择。按需要添加尽可能多的智能体。
2. 说明每个智能体分别要做什么，然后发送。例如：“@Researcher 查找关于京都竹林的三个事实，然后由 @Writer 将它们写成一篇短文。”
3. 负责人会回复一份工作计划：包括 **目标**、任务完成的判定条件（**完成标准**）、不包含的范围，以及分配给每位成员的任务。每个任务都会原封不动地收到目标和这些标准。需要另一个任务结果的任务会等待它完成，并在启动时并入该任务尚未合并的工作成果。
4. 如果计划需要你确认，检查无误后点按 **开始**、**修改计划** 或 **放弃**。当你启动计划时，成员才会开始工作。
5. 任务全部完成后，计划卡片会展示每项结果，负责人则会说明目标是否已经达成。

任务可以分配给你的任意智能体或编程智能体作为队友，即使它并不是项目的成员也可以。在你的请求中点名它即可；如果你希望它思考得更深入或回答得更快，还可以选择它的推理强度。

当包含 Codex 的计划启动时，Enconvo 会先请求文件夹访问权限，这样任务就不会在你离开后才因为权限问题停下来。

## 跟进正在运行的计划

计划运行期间，聊天上方的一行状态栏会显示它的目标、进度、费用和耗时。点按它可以打开运行视图：查看每个任务的步骤、发现的内容、给出的依据、按成员统计的费用，以及某项任务未能通过的原因。

有些结果需要你确认后计划才会继续。点按 **继续传递** 可接受被保留的结果或审查结论，点按 **退回修改** 则让成员重新修改。

## 查看结果

计划结束时，结果卡片会首先给出结论以及你的下一步操作，下方是每项任务的完整结果。编程任务还会带有一个 **合并** 按钮，并有一行提示列出所有尚未合并的任务。

负责人会逐条核对 **完成标准**，并说明哪些任务证明了标准已满足。独立核查会标出任务结果中未能明确佐证的断言。如果目标尚未达成，负责人可以在同一个预算内针对同一目标继续推进更多计划，最多五轮。

负责人还可能为后续运行提出最多三条经验教训供参考。你可以逐条保留或舍弃：只有你选择保留的经验才会进入[记忆](/zh/ai/memory)。

## 跟进看板

点按聊天顶部的 **看板**，即可将它的任务以卡片形式查看。每项任务都有一个编号（例如 T-1），并按 **待开始** → **正在运行** → **完成** 的状态流转。**等你确认** 集中显示所有等待你回答或批准的任务。

| 控件 | 作用 |
| --- | --- |
| **全部** / **等你确认** | 显示所有任务，或只显示等待你处理的任务。 |
| **分组方式** | 对卡片分组，例如按想法或按 **聊天** 分组。 |
| **显示** | 调整每张卡片显示的信息。 |
| **搜索任务或 T-12** | 按关键词或编号查找任务。 |

侧边栏图标栏的 **···** 菜单中的 **看板** 会显示你所有聊天中的任务。包含任务的聊天还会在侧边栏的对应行下方列出这些任务。

如果某项任务的检查与修复轮次反复发现同一个问题，循环会停下来而不会继续重试。如果某项检查无法运行，它会直接说明，而不会把本来正常的代码退回修改。

## 项目

项目将围绕同一个文件夹的相关聊天组织在一起，该文件夹中的 `AGENTS.md` 会成为项目的指令。点按侧边栏中 **项目** 旁的 **+** 打开 **创建项目**：

- 输入 **项目名称** 以在“文稿”中新建一个文件夹，或者点按 **使用现有文件夹** 或 **克隆仓库**。
- 在 **起点** 下，选择 **空白** 或一个预置团队：**研究台**、**内容工作室**、**应用开发组** 或 **行程规划**。

### 克隆仓库

1. 在 **创建项目** 中，点按 **克隆仓库**。
2. 粘贴 GitHub URL、`owner/name` 或任意 Git 地址。如果你已登录 GitHub，也可以从列表中直接选择你的仓库。
3. 点按 **克隆**。仓库会被复制到新文件夹中，并作为项目打开。

### 由谁完成工作

在配有成员的项目中，负责人规划每个目标，成员负责实现，再由审查或测试环节进行检查。成员中可以包含 Claude Code 和 Codex 等编程智能体。每项编程任务都会在各自的代码副本中工作，当你准备好合并时，计划结果卡片上会提供 **合并** 按钮。

Claude Code、Codex、Grok Build 或 Antigravity 都可以担任项目负责人。当项目中有成员时，担任负责人的编程智能体会像其他负责人一样在工作计划中规划成员的工作并阅读他们的结果。在没有成员的项目中，它会自己在聊天中完成工作，不会生成工作计划或看板任务，直到你添加成员为止。

在项目的主控聊天（Lead chat）中，你可以按名称将请求的一部分交给某个模型（例如 Opus 5.5），也可以同时指定智能体和模型（例如在 Opus 5.5 上运行 Claude Code）。负责人还可以为自己的工作启动子代理。项目也可以通过自己的工作流来运行目标和任务：参见[使用你自己的工作流](/zh/ai/projects)。

成员不能启动计划、批准操作、更改设置、安装软件或使用你的登录状态。编程智能体成员不能推送代码、移动其他分支或删除工作树：只有 Enconvo 负责合并和推送。项目主控聊天及其任务中的完全访问权限与普通聊天中的行为一致。关于看板、想法和项目设置，参见[项目与看板](/zh/ai/projects)。

## 故障排除

| 问题 | 解决方法 |
| --- | --- |
| 按 Return 直接发出了消息，而没有选中智能体 | 请等输入框下方弹出智能体列表后再按 Return。 |
| 某项任务卡在 **等你确认** | 打开该任务或对应聊天，回答它正在等待的问题或批准请求。 |
| 编程智能体无法启动 | 请先安装并登录该编程智能体。参见[编程智能体](/zh/ai/coding-agents)。 |
| Codex 计划停下来请求文件夹访问权限 | 计划启动时先回答文件夹访问提示，之后任务就能在你离开时继续运行。 |
