智能体把指令、模型和工具组合在一起，专门处理一类工作。如果你总是重复给出同样的指令，或者某项工作需要一套特定的工具，就可以创建一个智能体。在 **设置 → 智能体列表** 中管理你的智能体。

## 初始内置智能体

**Mavis** 是默认智能体：它会回答你的问题，还可以操作你的应用、浏览网页并处理你的文件。内置智能体各自专注一项工作：**Writer**、**Planner**、**Reviewer**、**Advisor**、**Researcher**、**Designer** 和 **Coder**。**Claude Code**、**Codex**、**Grok Build**、**Antigravity** 和 **Muse Code** 可以与你已安装的编程智能体在项目文件夹中对话，**Grok Bot** 则与云端的 xAI 智能体对话。参见[编程智能体](/zh/ai/coding-agents)。

在任意聊天顶部的智能体菜单中，或聊天窗口输入框上方的卡片中选择一个智能体。智能体列表会把你最近聊过天的智能体排在最前面。

## 智能体的组成部分

在 **设置 → 智能体列表** 中点击一个智能体，即可打开它的页面。左侧的各个分区可以跳转到对应部分：

| 分区 | 设置内容 |
| --- | --- |
| **指令** | 每次对话前告诉智能体的内容。输入时会自动保存更改。 |
| **风格** | 它的 **回复风格** 以及 **智能 UI** 级别：主动用图表、表格和卡片回答的积极程度。参阅[设置风格](#设置风格)。 |
| **模型** | 它写作时使用的 AI 模型。每个智能体可以使用不同的模型。 |
| **工具与技能** | 它可以使用哪些工具以及如何发现其余工具，还有它的技能文件夹以及存放其专用技能和所处理文件的 **工作文件夹**。参阅[选择工具和技能](#选择工具和技能)。 |
| **知识** | 它在哪些知识库中查找、按什么顺序查找，以及在知识库没有答案时是否搜索网页。参阅[选择知识库](#选择知识库)。 |
| **记忆** | 它读取哪些记忆，以及是否记住新内容。 |
| **语音** | 朗读它回复时使用的声音。 |
| **行为** | 它能看到什么、如何运行以及如何回复，例如 **回复语言** 和 **Cloud 点数运行上限**。 |
| **使用方** | 除聊天外还有哪些入口会启动这个智能体，以及它的 **链接、CLI 与 API** 行。 |

## 创建智能体

1. 在 **设置 → 智能体列表** 中点击 **新建智能体**，或在 SmartBar 中运行 **创建智能体**。
2. 输入 **名称**，还可以选填 **头像** 和用于说明用途的 **描述**。
3. 在 **智能体指令** 下，描述它要做什么、需要什么输入，以及如何呈现结果。
4. 在 **它可以使用什么？** 下，从一个预设开始：**日常**（所有内置工具）、**编程**、**研究** 或 **写作**。你之后可以在 **工具与技能** 中修改。
5. 选择它的模型。在 **推荐模型** 下，Enconvo 会阅读描述并推荐一个 Enconvo Cloud 模型，旁边还会提供一个更便宜的模型和一个更强的模型。点击 **使用此模型**，或选择其他模型。参阅[使用推荐模型](/zh/ai/model-selection-guide)。
6. 点击 **创建机器人**。然后打开这个智能体，为它选择技能和知识库。
7. 用它开始一个新聊天，先用一个小而典型的任务测试。

如果想绘制头像而不是上传图片，可以在这里或之后在智能体设置中打开头像选择器的 **生成** 标签页。选择一种风格（**扁平**、**3D**、**动漫**、**照片**、**线条** 或 **水彩**）并点击 **生成**：你的图像模型会根据智能体的名称和描述绘制四个头像。可以补充细节再重新绘制，或点击你想要的那一个。在点击 **生成** 之前，不会绘制任何内容。

指令示例：

```text
Help me turn meeting notes into actionable follow-ups.
Separate decisions, open questions, and action items.
For action items, preserve the owner and due date if stated;
otherwise mark them as unspecified.
```

## 设置风格

在 **风格** 下，有两项设置决定智能体回复的呈现方式。单个聊天也可以在 **+** 菜单的 **使用风格** 中为自己挑选另一种风格。

**回复风格** 设置语气、篇幅和格式：**普通**、**简洁**、**详尽**、**正式**，或你自己的风格。点击 **新建风格** 可以根据一段描述或你自己的写作样本创建风格，点击 **管理** 可以编辑你的风格。

**智能 UI** 设置它在没有被要求时主动用图表、表格和卡片回答的积极程度：

| 级别 | 作用 |
| --- | --- |
| **选择性** | 绘制数据、对比和计划。摘要和解释保留为纯文字。 |
| **主动**（默认） | 只要图表、表格或卡片更易读，就会加上它们，即便在解释说明中也是如此。 |
| **视觉优先** | 以可视化内容为主，单条回复中可能会用到多个视图。回复耗时会略长一些。 |

视觉内容越多，耗时越长，消耗的点数也越多。即时通讯渠道和语音回复仍保留为纯文字。

## 选择工具和技能

在 **工具与技能** 下，选择智能体如何找到要使用的能力：

- **自动发现**（推荐）从基础能力开始，当任务需要时再查找任何已安装的技能、插件、连接器或 MCP 服务器。它按语义匹配，因此即使用户请求的措辞与工具描述不同，或使用另一种语言提出，也依然能找到它。
- **仅限所选** 为智能体提供固定的一组工具。勾选它可以使用的内置工具、技能和 MCP 服务器。当任务需要其他工具时，它会告诉你需要什么，而不会自己去搜索。

在 **自动发现** 模式下，你仍然可以关闭绝不希望该智能体触碰的 **内置工具**，在 **固定技能** 下固定技能使其在每次聊天中都列出，还可以关闭 **推荐 Enconvo 商店中的插件** 以停止它提供可安装的插件。**技能文件夹** 用于为该智能体关闭单个技能。

只给智能体它的工作真正需要的工具：

| 需求 | 能力 |
| --- | --- |
| 读取和编辑文档 | [文件工具](/zh/ai/file-tools) |
| 查找最新信息 | [网页搜索](/zh/ai/web-search)和[网页抓取](/zh/ai/web-fetch) |
| 在网站中操作 | [使用浏览器](/zh/features/browser-control) |
| 操作桌面 App | [电脑操作](/zh/features/computer-use) |
| 搜索你的资料 | [知识库](/zh/ai/knowledge-base) |
| 复用一套流程 | [技能](/zh/configuration/skills) |
| 连接外部服务 | [MCP 服务器](/zh/features/mcp) |
| 运行代码 | [代码运行器](/zh/ai/code-runner) |
| 在一步中发起多次工具调用 | [代码模式](/zh/configuration/code-mode) |

模型必须支持你选择的工具和输入类型。工具本身也需要各自的凭据、访问权限和配置，指令无法赋予智能体本来没有的权限。

## 选择知识库

在 **知识** 下，选择智能体的查找范围：

| 选项 | 作用 |
| --- | --- |
| **所有知识库** | 当问题需要时，在你的任意知识库中查找。 |
| **优先已选知识库** | 先在你添加的知识库中查找，找不到时再查看其余知识库。 |
| **仅限已选知识库** | 只在你添加的知识库中查找。其他知识库只有当你用 `@` 提及时才会打开。 |

点击 **添加知识库** 进行选择，并拖动它们以调整查找顺序。

## 批准操作

运行模式旁的 **权限** 标签决定智能体在何时停下来先问你。它出现在聊天窗口、SmartBar、应用侧边栏和灵动岛的智能体模式中。它们修改的都是该智能体的同一项设置，所以在一处修改，其他地方也会同步显示。

| 模式 | 何时先问 |
| --- | --- |
| **请求批准** | 运行命令、编辑工作文件夹以外的文件，以及在 App、浏览器或在线服务中操作之前 |
| **替我批准**（默认） | 仅在看起来可能不安全的操作之前，例如删除文件、发送消息、发布或付款 |
| **完全访问** | 从不询问。智能体直接执行 |

读取文件、搜索和查看屏幕始终不会询问。**替我批准** 也不会在只为自身设置 `PATH` 的命令，或删除它在临时文件夹下自行创建的文件的命令前询问；删除其他任何内容仍会询问。

当一个智能体把工作交给另一个智能体或编程智能体时，被调用的智能体会以与你当前聊天相同的权限模式工作。每张批准卡片都会说明是哪项设置触发了询问，例如“由于此项目处于替我批准模式而询问”。关于命令运行后的限制，请参阅[智能体沙盒](/zh/configuration/sandbox)。

### 询问出现在哪里

询问会出现在聊天所在的窗口中。如果该窗口没有显示这个聊天（例如窗口已隐藏，或者它是内联面板），询问会转到灵动岛。如果 30 秒内无人在灵动岛中回应，已配对的 iPhone 会收到提醒通知，即使聊天窗口仍开着、只是被你正在用的 App 挡住了。

如果你没有回应就关闭了灵动岛的卡片，点击灵动岛聊天中正在等待的步骤即可再次看到选项。智能体向你提出的问题也是一样。

### 回应询问

- **是，仅允许一次** 只允许这一次操作。
- **是，且不再询问** 在该聊天的剩余时间内都允许，即使 Enconvo 重启后也会记住。
- 或者输入智能体应该改为怎么做。

聊天在等待时，聊天窗口的列表、SmartBar 的最近聊天和灵动岛中会显示 **等待批准**，而不是运行中。iPhone App 的聊天列表会将其标记为 **需要批准**。

子代理会在其父聊天中询问，并说明是哪个子代理在问、它正在处理什么任务。定时任务、工作流和即时通讯渠道运行时不会询问，因为没有人在窗口前回应。

## 子代理

在智能体模式中，智能体可以把任务拆成几部分，最多启动六个同时工作的子代理，每个子代理都有自己的对话。它们都汇报后，智能体再给出回答。只有在拆分明显有帮助时（例如多个互不相关的搜索），或你要求时，它才会这样做。如果速率限制等 AI 错误让子代理中途停下，智能体仍能拿到它已经找到的内容，并可以在错误消除后让它继续。

启动子代理时，智能体可以为它指定独立的模型、推理强度、指令和名称，或者把当前对话分叉给它。当智能体自己挑选模型时，快速查找、阅读以及简单的重复工作会运行在你的服务提供商的小型模型上，难度更高的推理会使用更高的推理强度，其余工作则保持在你选择的模型上。子代理还可以启动自己的子代理，最多三层深度。

- **将编程智能体用作子代理。** Claude Code、Codex、Antigravity、Grok Build 和 Muse Code 都可以作为子代理工作。卡片会显示编程智能体的图标、它的工作位置，以及它使用的工具调用次数、耗时和 Token 数。
- **独立工作树。** 当一个子代理在另一个子代理修改文件时也修改文件，它会获得一个属于自己的 git worktree，因此两个子代理绝不会互相覆盖工作。没有改动的工作树会在子代理结束时被移除。只制作设计、文档、幻灯片、研究或审查的子代理无需工作树，因此同时启动多个时不会为每个都复制一份项目。
- **其他电脑。** 智能体可以在你配对的另一台电脑上运行子代理，把任务交给那台电脑上的智能体或编程智能体。参阅[其他电脑](/zh/integrations/other-computers)。
- **引导干预。** 智能体可以向正在运行的子代理任务追加消息、中断它，或联系同一个项目中的另一个智能体聊天。停止一个聊天会同时停止它下方的所有子代理。
- **流水线。** 智能体可以在一步中按计划运行一组子代理，例如对一份文件列表执行相同的检查。失败的运行恢复时，不会重新运行已经完成的子代理。

### 并行聊天

当你让智能体为单独的任务打开一个新聊天时，它会以你要求的推理强度打开一个新聊天，并像你自己发起的聊天一样出现在 Mac、iPhone 和 Android 的聊天列表中。顶部的一条说明会标明是由哪个聊天启动了它。针对该任务的审查和测试仍会作为它的子代理运行。智能体为自己启动的聊天也可以从它的卡片中移入你的聊天列表。

### 跟进子代理并与其对话

聊天中的一张卡片按任务列出每个子代理，图标显示它是在运行、等待你批准、已完成还是已失败。正在运行的子代理所在行还会显示它此刻正在做什么，以及它所运行的模型和推理强度。新的子代理在卡片出现的同时，也会显示在消息框上方的后台托盘中。

子代理制作的内容（例如设计或文档）会在生成时显示在其所在行下方。点击即可在聊天旁打开它；智能体也会在回答中以卡片形式将它交给你。

- 点击一行即可打开该子代理的对话。它的工作区面板和 `@` 文件搜索显示的是启动它的那个聊天的工作文件夹。在 SmartBar 和灵动岛中，它的工作会就地展开。
- 在子代理的对话中输入内容即可与它交谈。它会在那里回答你、可以向你提问、在该对话中请求批准，并继续在同一文件夹中工作。启动它的智能体会等它回答你，然后看到它的最新回答。向已经结束的子代理发送消息会立即再次启动它，即使此时另一个子代理正在同一个文件夹中修改文件。
- 在子代理的对话中，每条消息都会标明发送它的智能体。来自父智能体的消息会说明它是引导了正在运行的任务、等待、中断了它，还是开启了新一轮对话。
- 聊天详情中的 **谱系** 会展示完整的子代理树，最多三层深度。在编程智能体的聊天中，它会显示启动它的 Enconvo 聊天。
- 在聊天窗口的侧边栏中，聊天的子代理列在其下方，聊天行上的按钮可以折叠该列表。

### 子代理角色

每个子代理启动时都有一个角色：

| 角色 | 作用 |
| --- | --- |
| **默认** | 以启动它的智能体身份工作，使用相同的指令、工具和模型 |
| **Explorer** | 只读取文件、搜索和查看 App。无论权限标签如何设置，它都不能编辑、运行会修改内容的命令，也不能在线上操作 |
| **你的某个智能体** | 以该智能体的身份运行，使用它自己的指令、工具和模型，工作文件夹与启动它的聊天相同 |
| **项目助手** | 由项目在 `.claude/agents`、`.codex/agents` 或 `.enconvo/agents` 中定义，位于工作文件夹或其上层文件夹（直到仓库根目录）。以启动它的智能体身份工作，但遵循助手自己的指令。它只使用文件中列出的工具，文件指定只读时就只读取，并在你的模型服务提供商支持时使用助手指定的模型 |
| **你自己的助手** | 在你主文件夹中的 `~/.enconvo/agents`、`~/.claude/agents` 或 `~/.codex/agents` 中定义，在每个聊天中都可用。工作方式与项目助手相同 |

如果想自己选择，在智能体模式的聊天中输入 `@`，然后从 **子代理** 分组中选择，该分组列出了各种助手、**Explorer** 和一个通用的 **子代理**。智能体会为你的消息启动该子代理、为它写好任务，并在它汇报后给出回答。你自己的智能体仍在菜单的智能体分组中。

在每个智能体的设置中清楚地描述它：负责拆分工作的智能体会阅读这些描述，判断哪个智能体适合哪项任务。要把任务像队友一样交给你的某个智能体或编程智能体，并为其指定独立的推理强度，请参阅[智能体编排器](/zh/ai/agent-orchestrator)。

### 项目助手

项目助手和你自己的助手使用与 Claude Code 子代理和 Codex 代理角色相同的文件，所以已经配有这些文件的仓库或主文件夹无需额外设置。

- Claude Code 文件（frontmatter 中含 `name` 和 `description` 的 Markdown）在设置了 `permissionMode: plan`，或只列出 `Read`、`Grep`、`Glob` 等读取类工具时为只读。
- Codex 文件（含 `description` 和 `developer_instructions` 的 TOML）在设置 `sandbox_mode = "read-only"` 时为只读。
- 如果服务提供商不提供助手指定的模型，助手会改用聊天的模型。

Claude Code 文件的 `tools` 和 `disallowedTools` 决定助手可以使用智能体的哪些工具。Enconvo 会把每个名称对应到自己的工具：

| 助手文件中的写法 | 助手可以 |
|---|---|
| `Read`、`Grep`、`Glob`、`LS` | 读取和搜索文件 |
| `Edit`、`MultiEdit`、`Write` | 编辑和创建文件 |
| `Bash` | 运行任意 shell 命令 |
| `Bash(git diff:*)` | 只运行以 `git diff` 开头的命令 |
| `WebSearch`、`WebFetch` | 搜索网页并读取网页 |
| `mcp__github__get_issue`、`mcp__github` | 使用已连接 MCP 服务器的某一个工具或全部工具 |

没有 `tools` 行时，助手可以使用除 `disallowedTools` 列出之外的所有工具。列表之外的调用不会执行，并会告诉助手它有哪些工具。每个助手都仍然可以加载技能并向你提问。在 `.enconvo/agents` 文件中，你还可以按 API 路径列出 Enconvo 工具，例如 `browser-use/*`。

Claude Code 文件中的技能、MCP 服务器、轮次上限、后台运行和 worktree 设置同样会生效。

## 使用智能体的方式

- 在[聊天窗口](/zh/ai/chat)、[SmartBar](/zh/features/smartbar)、[应用侧边栏](/zh/features/app-sidebar)或[灵动岛](/zh/features/dynamic-island)中与它聊天。
- 设置 **语音命令**，把口述请求发送给你选择的智能体。参见[听写](/zh/features/dictation)。
- 通过 [Live Talk](/zh/features/live-voice) 与它对话，或用[虚拟形象](/zh/features/avatar)给它一个桌面角色。
- 用[即时通讯渠道](/zh/integrations/messaging)连接聊天 App。
- 用[自动化](/zh/workflows/scheduled-jobs)稍后运行它。
- 通过链接、终端命令或 API 调用从 Enconvo 外部运行它。参见[链接、CLI 与 API](#链接、cli-与-api)。

### 链接、CLI 与 API

在 **设置 → 智能体列表** 中打开一个智能体。在 **使用方** 下，**链接、CLI 与 API** 一行有一个 **显示** 按钮。点击它即可获取用你的文字和文件运行该智能体的 Deeplink、终端命令和 API 调用，全部可直接复制。AI 命令也有这一行。

## 默认设置与延续性

在修改被多个聊天或渠道使用的智能体之前，先查看[模型默认设置](/zh/ai/model-selection-guide)。为智能体需要反复使用的事实设置[记忆](/zh/ai/memory)，把文档放进知识库，而不是全部塞进指令里。

## 故障排除

| 问题 | 解决方法 |
| --- | --- |
| 请求失败 | 先查看工具错误，或检查是否缺少输入。 |
| 分不清是模型还是工具的问题 | 关闭可选工具后重试同一请求，再逐个加回工具。 |
| 某个操作会修改文件或外部服务 | 批准前先检查目标和影响。 |
| 智能体提示缺少工具或技能 | 在 **工具与技能** 下，检查是否设为了 **仅限所选**，或某个内置工具是否被关闭。 |
| 回复里的图表和卡片比你想要的更多，或耗时过长 | 在 **风格** 下将 **智能 UI** 设为 **选择性**，或在 **+** 菜单的 **使用风格** 中为当前聊天单独设置。 |
