项目把同一个文件夹相关的聊天、想法和团队集中在一起。你把想做的事写成一条想法，项目负责人会和团队一起规划，每项任务都会在看板上逐步推进直到完成。对于网站或应用等持续推进的工作，如果希望一眼看清当前进展以及哪些部分需要你介入，就可以使用项目。

下面的视频展示了打开一个项目、添加一条将部分工作交给 Claude Code 的想法、在看板上跟踪进展，以及归档和恢复项目的过程。

## 开始之前

你需要先有一个项目。点击聊天窗口侧边栏中 **项目** 旁边的 **+**，然后选择一个文件夹：参见[创建项目](/zh/ai/agent-orchestrator)。如果要把任务交给 Claude Code 或 Codex 等编程智能体，请先安装并登录：参见[编程智能体](/zh/ai/coding-agents)。

## 打开项目

在侧边栏中点击项目。它的页面包含三个标签页：

| 标签页 | 显示内容 |
| --- | --- |
| **聊天** | 项目与负责人的对话，以及显示[需要你处理的内容](#查看有哪些需要你处理)的面板。 |
| **看板** | 项目的想法，从 **未开始** 到 **规划中**、**进行中**，直至 **完成**。 |
| **团队与设置** | 团队成员列表，以及团队[何时与你确认](#选择团队何时与你确认)。 |

团队成员的头像显示在左上角，负责人排在第一位。项目聊天的任务也会显示在侧边栏对应聊天的下方。

## 添加想法

想法是你希望项目完成的事项。

1. 打开 **看板** 标签页，点击 **新想法**。
2. 用平时的表达方式写下你的需求。你可以附上截图或文件，或者点击麦克风直接口述。
3. 如有需要，设置 **优先级**。Enconvo 会根据你的描述自动判断 **种类**：**功能**、**缺陷**、**改进**、**文档** 或 **调研**。如果判断有误，可以手动修改。
4. 点击 **添加想法**。

想法会以卡片形式出现在 **未开始** 下方，带有根据你的描述生成的简短标题，以及表示优先级的红、黄或蓝色旗标。负责人会立即开始规划，并将它移至 **规划中**。想法启动时，你附加的文件会同步发送给负责人。如果只想查看某一类想法，可以使用 **按种类筛选**。

想法也可以自动进入看板。为[自动化](/zh/workflows/scheduled-jobs)配置 **加入 Ideas** 操作后，监听到的每个 GitHub issue、Discord 或 Telegram 消息、邮件或 webhook 都会变成项目看板上的一条想法。负责人会复现缺陷并规划修复方案，或调研请求后给出原因关闭或进行规划，并在做出任何改动前征求你的意见。

计划就绪后，页面会展示每项任务、执行者以及所使用的模型。确认无误后点击 **开始**，想法就会移至 **进行中**。负责人会根据想法的 **目标** 和 **完成标准** 行来制定计划，并且只有当负责人判定该目标已达成时，想法才会移至 **完成**。

## 跟踪想法

点击一条想法即可打开它的页面。一侧是你与负责人的聊天，另一侧是这条想法的计划、任务、描述、文件和目标。**进展** 会显示 **规划工作**、**完成工作** 和 **审查与测试**，以及每一步的进度和执行者。

如果想重新处理已完成的想法，点击 **重新打开**。

包含任务的想法在顶部有两个视图：**任务** 仅以看板形式展示它的任务；**与 … 聊天**（带有负责人的名字，例如 **与 Mavis 聊天**）会打开规划该想法的对话。

## 把任务交给编程智能体

在想法或项目聊天中直接指定智能体名称，需要的话也可以指定模型。你还可以只指定模型，例如 Opus 5.5，负责人就会用该模型执行这项任务。即使项目没有添加成员，这种方式同样有效。例如：

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

负责人会将指定的部分规划为交给该智能体并使用该模型的任务（即使该智能体不在项目成员中），其余部分则可以由它自己完成。计划和看板都会在执行者旁边标出所使用的模型。如果提到的名称可能对应多个模型，或者没有匹配的模型，负责人会向你确认。

编程智能体完成后，它的任务会在想法的 **任务** 看板中进入 **待审查** 等待你的审查。对于文件夹不是 Git 仓库的项目，任务会直接进入 **完成**。每项编码任务都在各自独立的代码副本中运行，计划结果卡片上会提供 **合并**，供你准备好后操作。成员自己无法执行推送或合并。

你在 **聊天** 标签页或 **想法** 中交给负责人的每项任务都会显示在看板上，可按想法或按聊天分组。在看板的聊天筛选器中选择某个对话，或将 **分组方式** 设为 **聊天**，即可跟踪单个对话的任务。

你在项目聊天中直接完成的工作也会显示在看板上：当某个聊天修改了文件或运行了命令时，看板上会出现一张卡片，并一直跟踪它直到 **完成**，上面附有简短摘要和修改的文件。点击卡片即可打开对应的聊天。负责人看得到这些卡片，并会避免自己的任务去改动同一批文件。

## 合并已完成的工作

点击任务上或计划结果卡片上的 **合并**，即可将改动合并到项目的 **基础分支**。同一文件其他行上的未提交改动不会阻止合并。如果 Git 正忙，**合并** 会稍等片刻；如果残留了锁文件，它会指出具体的文件名。

如果希望通过后自动合并而无需手动点击，请在 **项目设置 → 看板** 中开启 **合并通过的工作**。这需要先在 **工作树** 中设置 **基础分支**。之后，每项任务只要通过自身的检查以及另一家服务提供商的智能体的评审，就会自动合并。在 **通过条件** 下，你可以选择 **没有阻塞问题**、**评审者批准** 或 **仅检查**。出现冲突的任务会退回给对应成员处理。当评审者无法运行时，所有合并都会暂停，而不会跳过评审。

### 非 Git 项目

在文件夹不是 Git 仓库的项目中，每个负责人聊天都会把自己的工作计划保存到各自的聊天文件夹中，因此两个负责人聊天可以同时运行各自的计划。计划卡片会显示 **保存到** 及对应的文件夹，**另外改动了** 则会列出任务在该文件夹之外触及的文件。

## 以其他方式向负责人提问

在项目的负责人聊天中：

- **比较答案** 会向两到六个智能体提出同一个问题，并由负责人对比它们的回答。
- **使用风格** 可选择负责人撰写回复时采用的风格。

如果需要 Codex、Claude Code 或你的其他智能体来评审或测试当前工作，直接提出要求即可。在项目中，负责人会把该智能体作为子代理启动，并将结果带回同一个聊天。除了分派给项目成员的任务外，负责人也可以为自己的工作启动子代理。

要通过项目的某个工作流来运行任务，输入 `@` 并选择该工作流，或在 **团队与设置** 标签页中点击它旁边的 **在聊天中使用**。参见[使用你自己的工作流](#使用你自己的工作流)。

## 查看有哪些需要你处理

打开 **聊天** 标签页。消息框上方的面板分为三栏：

| 栏位 | 列出内容 |
| --- | --- |
| **等你确认** | 等待你回答、批准或审查的任务。 |
| **正在处理** | 正在运行中的任务。 |
| **新结果** | 已完成但你尚未打开查看的任务。 |

点击任意一行即可打开对应的想法。

## 用总看板查看全部任务

在聊天窗口侧边栏的图标栏上打开 **···** 菜单，其中的 **看板** 将所有聊天、项目和团队的任务集中显示在一处。如果想把它留在图标栏上，请在该菜单中选择 **自定义侧栏…**。参见[聊天窗口](/zh/ai/chat)。

如果只想查看部分项目，点击左上角的筛选器（**全部看板**）并勾选你想看的项目。看板的其他控制项参见[使用看板](/zh/ai/agent-orchestrator)。

## 设置团队

打开 **团队与设置** 标签页。顶部显示负责人和每位成员，可通过 **添加成员** 引入其他智能体。点击左上角的团队头像可以一次查看整个团队：负责人旁有 **更换** 按钮，每位成员旁都有可以直接就地编辑的角色说明。

负责人可以是你的任意智能体，也可以是编程智能体：Claude Code、Codex、Grok Build 或 Antigravity。担任负责人的编程智能体同样会在工作计划中安排成员的工作并读取他们的结果，和其他负责人一样。

成员也可以是你[其他已配对电脑](/zh/integrations/other-computers)上的智能体。负责人会把需要那台电脑的任务交给它，答案会作为任务结果返回。如果那台电脑在你的账户下尚未开启设备访问权限，任务会给出提示并引导你前往 **管理设备**。

### 团队如何协作

你通过 **聊天** 或 **想法** 交给负责人的每个目标，都会按 **标准** 流程推进：**规划工作**、**完成工作**，然后 **审查与测试**。你可以指定每一步由谁来执行。把规划交给某位成员后，当你提出需求时，该成员就会编写计划；随后负责人会将其任务整理为一份工作计划，等待你点击 **开始**。你还可以开启或关闭检查步骤，并设置 **修复轮数**，决定任务最多退回修复几次。

### 使用你自己的工作流

**团队与设置** 标签页中的 **自定义工作流** 默认关闭。关闭时，所有目标都按 **标准** 流程运行。开启后，可以让整个目标或单个任务通过[工作流](/zh/workflows/introduction)运行：

- **或者用工作流运行每个目标** 列出了团队工作流。把鼠标移到某个工作流上并点击 **用于所有目标**，或点击 **新建团队工作流** 创建自己的工作流。
- **任务工作流** 列出了负责人可以指派给单个任务的工作流，例如修复缺陷。点击 **在聊天中使用** 可在负责人聊天中引用它，或点击 **新建工作流** 新建一个。

内置工作流包括：

| 工作流 | 作用 |
| --- | --- |
| **Ship** | 将想法转化为由你批准的规格说明、设计与计划，带着测试、检查、评审和验证逐一构建任务，最后审查整个分支。 |
| **Planner** | 将想法转化为由你批准的规格说明、设计与任务列表，并将任务作为工作计划交给负责人。 |
| **Sprint** | 带着测试、检查、评审和验证构建单个已规划的任务。 |
| **Compound** | 将你保留的经验教训应用到仓库的文档和规则中。 |
| **Verify setup** | 弄清楚如何检查和运行项目，编写一份由你批准的验证运行手册，并通过实际运行来验证它。 |

每一行会显示工作流的图标、执行该工作流的成员头像，以及累计运行次数和失败次数。如果某个工作流缺少成员，请点击该行中的 **选择智能体…**。点击某一行即可打开工作流并修改它的步骤或执行成员。

你在项目中保存的工作流修改会先保持为 **草稿**：在你点击 **发布** 之前，新计划会继续使用已发布的版本。**回滚到上一版本** 可以恢复到之前的版本。任务的工作流视图会显示每一步的 token 用量和费用，并按 API 价格给出总计。

### 设置检查命令

检查命令会在任务完成后、进入评审之前，在任务各自的代码副本中运行。检查未通过的任务会退回给负责该任务的成员修复。

1. 在 **团队与设置** 标签页中，点击 **项目设置**，然后选择 **看板**。
2. 在 **检查命令** 旁边，点击 **帮我找**。Enconvo 会从项目文件中读取命令，并且只有在该命令运行通过时才会填入。
3. 如果没有找到，点击 **让 Mavis 来设置**（按钮上会显示你的负责人名字）。负责人会在对话中找出或添加这条命令。

没有配置检查命令的项目，其检查步骤会显示为 **未检查**。

### 清理工作树

Git 项目中的每个聊天和任务都在各自的工作树中运行。为了释放磁盘空间，Enconvo 会归档你已不再需要的工作树并删除它们的文件夹。在 **项目设置 → 工作树** 中：

| 设置 | 作用 |
| --- | --- |
| **归档已合并的工作树** | 当工作树的改动已进入基础分支，且没有未提交或未推送的内容时，将其归档。 |
| **归档没有聊天的工作树** | 当聊天列表中不再有属于该工作树的聊天时，将其归档。 |
| **归档闲置的工作树** | 当工作树及其聊天在 **闲置多久后归档** 所选天数（3、7、14 或 30 天）内没有任何活动时，将它们一并归档。 |

包含未提交改动的工作树始终会保留。点击 **恢复** 可以把已归档的工作树还原。

## 选择团队何时与你确认

打开 **团队与设置** 标签页。

在 **何时与你确认** 下：

| 设置 | 作用 |
| --- | --- |
| **当计划就绪时** | **智能**（默认）会在计划正好只做你已要求的事时立即启动，并在超出范围或包含高风险操作时等待你点击 **开始**。**每次询问** 每次都会等待你点击 **开始**。**总是直接开始** 会在每个计划就绪后立即运行。 |
| **添加待办后立即开始规划** | 开启：负责人会立即规划每个新想法。关闭：新想法会停留在 **未开始**，直到你手动启动它们。 |

无论你如何选择，删除、发送、发布、付款或推送等操作始终会先询问你。文件夹、工作树、权限、预算和边界设置都在 **项目设置** 中。

## 你不在时让负责人继续推进

在处于 **完全访问** 权限的项目中，当某个任务返回结果而聊天中无人值守时，负责人可以继续推进工作。在 **项目设置 → 看板** 中开启 **你不在时 Lead 也能动手**。

随后，负责人会自行修复、重试并合并改动，上限为每小时 6 轮、每天 100,000 点数。除了任务自身的代码副本外，它绝不会对外发送、推送、发布、付款或删除任何内容。

当你回来时，负责人聊天顶部的 **你不在的时候** 卡片会列出负责人做过什么，以及留给你的后续步骤。如果连续两轮失败，或者达到上限，负责人会暂停，并在 **等你确认** 中询问要 **继续运行** 还是 **保持暂停**。

## 归档项目

项目完成后，可以将其归档，以便在不删除任何内容的前提下把它从侧边栏中收起。

1. 将鼠标移到侧边栏中的项目上，点击 **⋯**。
2. 选择 **归档项目**。

项目及其聊天会从侧边栏中移出，它的定时任务也会暂停。在恢复之前，已归档项目中的聊天无法接收新消息。

要恢复项目：

1. 打开 **设置 → 已归档**。
2. 点击 **项目**。
3. 点击项目旁边的 **恢复**。

项目及其聊天会回到侧边栏，它的定时任务也会重新开启。

## 在手机上使用项目

iPhone 应用同样可以打开你的项目：包括想法、看板、项目设置、**新建项目**，以及工作计划卡片——你可以在卡片上回答问题、合并、开始或重试任务。手机端输入 `@` 呼出的菜单会列出项目的成员和工作流。参见 [iPhone 应用](/zh/integrations/iphone-app)。

## 故障排除

| 问题 | 解决方法 |
| --- | --- |
| 新想法一直停留在 **未开始** | 在 **团队与设置** 中开启 **添加待办后立即开始规划**，或打开该想法并手动启动。 |
| 即使选择了 **智能**，计划仍在等待确认 | 该计划超出了你原本要求的范围，或包含高风险步骤。检查后点击 **开始** 即可。 |
| 编程智能体的任务没有启动 | 请先安装该编程智能体并完成登录。 |
| 任务显示 **已挂起** 并提示登录警告 | 编程智能体已退出登录，或登录状态即将过期。点击 **重新登录**。重新登录后，已挂起的任务会继续运行。 |
| 看板卡片以琥珀色显示问题 | 这属于配置问题。请按卡片上的修复提示处理；负责人不会自动重试此类问题。如果提示为 Enconvo 错误，则说明可以安全重试。 |
| 保存在 iCloud 中的项目任务失败 | 开启“优化 Mac 储存空间”后，文件可能并未下载到本地 Mac。请在 Finder 中对项目文件夹选择 **始终保留下载**。 |
| 任务提示项目文件夹不见了 | 该文件夹已被移动或删除。请将它移回原处，或为新位置创建一个新项目。 |
| 任务在项目的 **边界** 处停下 | 在任务上点击 **编辑边界** 以允许其所需访问的目录。只有你可以修改边界。 |
| 任务提示留下了未完成的 merge 或 rebase | 对应智能体在中途停止了。请先完成或撤销该 merge 或 rebase，然后再合并该任务。 |
| 所有计划都在等待 **开始** | 退出登录 Enconvo 时，计划会暂停等待确认。请在 **设置 → 账户** 中登录。 |
| 侧边栏中找不到某个项目 | 它可能已被归档。请在 **设置 → 已归档** 的 **项目** 下查看。 |
| 工作流任务失败 | 打开该任务，其中会显示命令最后输出的内容以及哪位成员的步骤失败。 |
| 目标没有使用你选择的团队工作流 | 在 **团队与设置** 标签页中开启 **自定义工作流**。关闭状态下，所有目标都会按 **标准** 流程运行。 |
