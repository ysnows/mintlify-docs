A workflow describes a repeatable process: read information, transform it, ask a model, call an Agent, or use an installed tool. Open **Settings → Workflows → Manage** to browse workflows and their run history.

## Choose the right automation

| Need | Use |
| --- | --- |
| Reuse a prompt on selected text | [AI Commands](/features/ai-commands) |
| Let an assistant decide which tools to use | [Agents](/ai/agents) |
| Define a repeatable sequence with inspectable outputs | A workflow |
| Run an Agent instruction or script at a set time | [Scheduled Jobs](/workflows/scheduled-jobs) |

## Jobs and steps

Current workflows use `version: agent-workflow/v1` with a **jobs** map. Each job contains an ordered **steps** list. Steps within a job run sequentially. Jobs start in parallel unless `needs` makes one job wait for another.

```yaml
version: agent-workflow/v1
title: Quick Summary
description: Summarize supplied text into three bullets.
inputs:
  text:
    type: string
    default: "A sample paragraph to summarize."
jobs:
  main:
    steps:
      - id: summarize
        prompt: "Summarize in three bullets: {{ inputs.text }}"
```

<Note>
The old top-level `tasks` format is no longer accepted. Move each sequence into `jobs.<name>.steps`, give steps explicit IDs, and use `steps.<id>.output` within a job or `jobs.<job>.<step>.output` across jobs.
</Note>

## What a step can do

| Executor | Fields | Result |
| --- | --- | --- |
| Shell | `command` or `run` | Command output, including `stdout`, `stderr`, and `exitCode` |
| Prompt | `prompt` | A model reply; use an output schema for structured data |
| Agent | `agent` and `message` | The selected Agent's reply |
| Tool | `tool` and `with` | An installed Local API endpoint's result |
| Transform | `uses: transform` and `value` | A templated value |
| Subworkflow | `uses: workflow` with `workflowId` or `workflow` | A child workflow run result |

Each step has exactly one executor. A workflow can add conditions, loops, retries, and output schemas; see [Advanced Workflows](/workflows/advanced-workflows).

## Where to run a workflow

- Open it in **Workflows**, set **Inputs**, and choose **Run**.
- Search for a saved workflow in SmartBar. Launcher text is available as `inputs.input_text`.
- Mention an available workflow with `@` in chat so an Agent can use it.

Saved workflow files live at `~/.enconvo/workflows/<id>.yaml`. The filename is the workflow ID. Keep that ID stable to preserve the link with its run history.

Continue with [Creating Workflows](/workflows/creating-workflows) for the visual editor, YAML, assistant, and a first run.
