A workflow is a repeatable process saved as steps: read information, transform it, ask a model, hand work to an Agent, or call an installed tool. Use one when you do the same multi-step job again and again and want to see what each step produced. Open **Settings → Workflows → Manage** to browse your workflows and their run history.

<Tip>
New to workflows? Watch the 2½-minute video tutorial [Build Your First Workflow](/workflows/build-your-first-workflow) to create, edit, and run one from start to finish.
</Tip>

## Choose the right tool

| You want to | Use |
| --- | --- |
| Reuse a prompt on selected text | [AI Commands](/features/ai-commands) |
| Let an assistant decide which tools to use | [Agents](/ai/agents) |
| Define a repeatable sequence with inspectable outputs | A workflow |
| Run an Agent instruction, a workflow, or a script at a set time | [Automations](/workflows/scheduled-jobs) |

## How a workflow is organized

A workflow has three parts:

- `inputs`: the values a run needs, such as a topic or a piece of text.
- `jobs`: named groups of steps. Jobs start in parallel unless `needs` makes one job wait for another.
- `steps`: the ordered list inside each job. Steps within a job run one after another.

Current workflows use `version: agent-workflow/v1` with a `jobs` map, and each job holds a `steps` list:

```yaml
version: agent-workflow/v1
title: Quick Summary
description: Summarize supplied text into three bullets.
inputs:
  text:
    type: string
    default: "A sample paragraph to summarize."
jobs:
  main:
    steps:
      - id: summarize
        prompt: "Summarize in three bullets: {{ inputs.text }}"
```

<Note>
The old top-level `tasks` format is no longer accepted. Move each sequence into `jobs.<name>.steps`, give steps explicit IDs, and use `steps.<id>.output` within a job or `jobs.<job>.<step>.output` across jobs.
</Note>

## What a step can do

Each step does exactly one of these:

| Step | Fields | Result |
| --- | --- | --- |
| Shell | `command` or `run` | Command output, including `stdout`, `stderr`, and `exitCode` |
| Prompt | `prompt` | A model reply; use an output schema for structured data |
| Agent | `agent` and `message` | The selected Agent's reply |
| Tool | `tool` and `with` | An installed Local API endpoint's result |
| Transform | `uses: transform` and `value` | A templated value |
| Subworkflow | `uses: workflow` with `workflowId` or `workflow` | A child workflow run result |
| Approval | `uses: approval` and `message` | Your answer: approved, or declined with optional feedback |
| Judge | `uses: judge` and `question` | A yes or no from Jev, Enconvo Cloud's fast decision model, with its probability |
| Classify | `uses: classify`, `question`, and `options` | The option Jev picked, with its confidence |

A step can also run only when a condition holds, repeat over a list, retry, or return structured data. See [Advanced Workflows](/workflows/advanced-workflows).

## Run a workflow

- Open it in **Workflows**, set **Inputs**, and choose **Run**.
- Search for a saved workflow in SmartBar. Launcher text is available as `inputs.input_text`.
- Mention an available workflow with `@` in chat so an Agent can use it.
- Run it on a schedule with an [automation](/workflows/scheduled-jobs#schedule-a-workflow).

## Where workflows are saved

Each workflow is one file at `~/.enconvo/workflows/<id>.yaml`. The filename is the workflow ID. Keep that ID stable to preserve the link with its run history.
