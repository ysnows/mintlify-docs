---
title: "Privacy and Security"
description: "Understand which data stays local and which services process your requests."
---

Enconvo combines local storage, macOS capabilities, and optional online services. Where your data is processed depends on the feature, selected provider, enabled tools, and connected integrations.

## Where content is processed

| Action | Data involved |
| --- | --- |
| Cloud AI chat | Prompt, conversation context, and selected attachments sent for model processing |
| Cloud speech recognition | Captured audio sent to the selected speech service |
| Cloud text-to-speech | Text sent to the selected voice service |
| Cloud embeddings or reranking | Document/query content needed for retrieval |
| Web search or fetch | Search query or URL sent to the selected service or website |
| Local model inference | Model processing on the Mac after required resources are downloaded |
| Browser or computer tools | Content and actions available through that tool's granted access |
| IM channel | Messages exchanged with the connected messaging service and Agent |

Using a local chat model alone does not make every tool offline. A web search, remote MCP tool, cloud transcription provider, or cloud embedding model may still send content over the network.

## Control context

Review attachments and context sources before submitting a request. Appshots, screenshots, selected text, clipboard content, and browser pages can contain information beyond the sentence you intend to ask about.

Use [Context Awareness](/features/context-awareness) to choose sources. Grant [macOS permissions](/configuration/permissions) for the features you use and revoke access through System Settings when no longer needed.

## Credentials

API keys and account connections are managed through provider Authentication and [Credential Management](/configuration/credentials). Treat local Enconvo configuration, backups, exported settings, and support logs as sensitive. Do not include keys or account tokens in prompts, screenshots, or shared diagnostic files.

Provider profiles can share credentials across several capabilities. Review all consumers before deleting or replacing a profile. Revoke a compromised key through the provider itself; removing a local profile is not the same as revoking a server-side credential.

## Tools and integrations

An Agent can act through enabled tools. Browser control, computer use, shell execution, file edits, Gmail, and external MCP servers have different effects and access. Review the Agent's tools and the proposed action when working with important data.

Extension worker isolation is not a guarantee that an extension cannot access local files or networks. Install tools from sources you trust and review their configuration.

## Local AI clients

[Knowledge Base MCP](/advanced/knowledge-base-mcp) is opt-in and accepts local connections. Its visibility switches control which knowledge bases are exposed. A local client may send retrieved content to its own AI provider; configure that client too.

## Usage analytics and diagnostics

Enconvo records product usage events. The analytics identity is a device client identifier; analytics events are designed not to include email addresses, conversation text, or media payloads. Diagnostic logs are a separate surface and can include operational details needed to explain failures.

When sharing a report, inspect it first and remove private prompts, paths, keys, account information, and document contents that are not needed to diagnose the problem.

## Keep or remove local data

Use each feature's own history, knowledge-base, recording, and credential controls to manage its data. Read deletion confirmations and keep backups of anything you need. Removing the app does not necessarily remove its configuration and data, and removing local data does not delete copies already processed by an external service.

For provider retention and account policies, consult the provider you selected. This guide describes Enconvo's data flows; it does not replace those providers' policies.
