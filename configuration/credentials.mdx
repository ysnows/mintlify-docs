---
title: "Credentials"
description: "Add an API key or sign in to a provider's plan, share one setup across features, and clean up keys you no longer use."
---

Every provider you use needs a credential: an API key, or a sign-in to a plan you already pay for. You add it on the provider's own Settings page, and Enconvo keeps it in a provider profile that every feature using that provider shares. **Settings → Credential Management** shows all your credentials in one place.

## Add a provider

<Steps>
  <Step title="Open a category">
    Open the Settings page for what you want to use, such as **Settings → AI Model**, **Settings → Image Generation**, or **Settings → Text-to-Speech**.
  </Step>
  <Step title="Pick the provider">
    Select a provider. To set up a second copy of one, for another key or account, choose **Add New Provider**.
  </Step>
  <Step title="Choose how to sign in">
    Under **Authentication**, choose **API Key**, or **Subscription** when the provider lets you use a plan you pay for.
  </Step>
  <Step title="Add the credential">
    Paste your API key, or finish the provider's sign-in.
  </Step>
  <Step title="Test it">
    Click **Validate** if the page shows it, pick a model, and try a short request.
  </Step>
</Steps>

An API key bills the provider's API account. A subscription uses your plan's included usage and its limits. The text under **Authentication** tells you which one the page uses.

## Shared profiles

A provider profile, such as **OpenAI 2**, holds the provider's API key and its subscription sign-in, and appears in every category the provider supports. Renaming or deleting the profile changes it in all of those categories, not just the page you're on.

Each category keeps its own model, voice, and generation settings. A new API key, though, reaches every feature that uses the profile, so test those features after you change it.

What a provider offers varies by category. A sign-in that works for AI chat doesn't mean the provider's realtime voice API is included. When a category only takes an API key, its page says so and names the categories where the subscription works.

## Check a plan's usage

A subscription sign-in shows your account and how much of your plan is left. A value such as **% left** is the allowance you have remaining. Open the account card's menu and choose **Refresh usage** to update it, or **Reconnect** to sign in again.

When no usage shows, that doesn't mean your usage is unlimited.

## Manage your credentials

Open **Settings → Credential Management**. The list groups credentials by provider profile, then shows **Unused keys**: keys that no provider uses.

- Type in **Search providers...** to find one.
- Click **Add New Credential** to create another credential for a service you pick.
- To delete a credential, hover over it and click the trash icon. If an API key Connector uses that key, the confirmation names it, and **Delete and disconnect** disconnects it until you give it another key.
- Click **Clean up** at the bottom of the list to delete every unused key at once. The button shows how many there are, and the confirmation lists them first. Enconvo never deletes unused keys on its own.

A profile's own credentials have no delete button here. They go when you delete the provider.

## Custom endpoints

**OpenAI Compatible** and **Anthropic Compatible** providers have an API base URL field for your own server. Some built-in providers keep their endpoint setting in **Credential Management**. For a model server on another computer, see [Local Models](/ai/local-llm).

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Validation fails | Check the selected profile, the authentication method, the endpoint, and that your provider account has access. |
| One feature works and another fails | Check that the account supports that feature and model. The page says when a category only takes an API key. |
| Something stopped working after you changed a key | The profile is shared. Test the other categories that use it. |
| The usage area shows **Reconnect** | The sign-in has expired. Click **Reconnect** and sign in again. |
