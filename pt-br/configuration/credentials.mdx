Cada fornecedor que você usa precisa de uma credencial: uma chave de API, ou um início de sessão num plano que você já paga. Adiciona-a na própria página de Definições do fornecedor, e o Enconvo guarda-a num perfil de fornecedor que todas as funções que usam esse fornecedor partilham. **Definições → Gestão de credenciais** mostra todas as credenciais num só sítio.

## Adicionar um fornecedor

<Steps>
  <Step title="Abrir uma categoria">
    Abra a página de Definições do que quer usar, como **Definições → Modelo de IA**, **Definições → Geração de imagens** ou **Definições → Texto para voz**.
  </Step>
  <Step title="Escolher o fornecedor">
    Selecione um fornecedor. Para configurar uma segunda cópia, para outra chave ou conta, escolha **Adicionar novo fornecedor**.
  </Step>
  <Step title="Escolher como iniciar sessão">
    Em **Autenticação**, escolha **Chave de API**, ou **Subscrição** quando o fornecedor deixa usar um plano que você paga.
  </Step>
  <Step title="Adicionar a credencial">
    Cole a chave de API, ou termine o início de sessão do fornecedor.
  </Step>
  <Step title="Testar">
    Clique em **Validar** se a página o mostrar, escolha um modelo e experimente um pedido curto.
  </Step>
</Steps>

Uma chave de API fatura a conta de API do fornecedor. Uma subscrição usa o uso incluído no plano e os seus limites. O texto sob **Autenticação** diz qual a página usa.

## Perfis partilhados

Um perfil de fornecedor, como **OpenAI 2**, guarda a chave de API do fornecedor e o início de sessão da subscrição, e aparece em todas as categorias que o fornecedor suporta. Renomear ou eliminar o perfil muda-o em todas essas categorias, não só na página em que você está.

Cada categoria guarda o seu próprio modelo, voz e definições de geração. Uma chave de API nova, porém, chega a todas as funções que usam o perfil, por isso teste essas funções depois de a mudar.

O que um fornecedor oferece varia por categoria. Um início de sessão que funciona para o chat de IA não significa que a API de voz em tempo real do fornecedor esteja incluída. Quando uma categoria só aceita uma chave de API, a página diz isso e nomeia as categorias em que a subscrição funciona.

## Conferir o uso de um plano

Um início de sessão de subscrição mostra a sua conta e quanto do plano resta. Um valor como **% restante** é a margem que ainda tem. Abra o menu do cartão da conta e escolha **Atualizar uso** para o atualizar, ou **Voltar a ligar** para iniciar sessão outra vez.

Quando o Claude ou o Codex lhe concederam reposições de limite grátis, um cartão de subscrição Claude ou ChatGPT mostra **Reposições de limite grátis**: quantas tem e até quando. Clique em **Usar reposição** e confirme para encher os limites. Com mais de uma, o cartão lista-as, e você usa a que escolher.

Quando não aparece uso, isso não significa que o uso seja ilimitado.

## Gerir as suas credenciais

Abra **Definições → Gestão de credenciais**. A lista agrupa credenciais por perfil de fornecedor e depois mostra **Chaves não usadas**: chaves que nenhum fornecedor usa.

- Escreva em **Pesquisar fornecedores...** para encontrar um.
- Clique em **Adicionar nova credencial** para criar outra credencial para um serviço que você escolhe.
- Para eliminar uma credencial, passe o rato sobre ela e clique no ícone do lixo. Se um Connector de chave de API usa essa chave, a confirmação nomeia-o, e **Eliminar e desligar** desliga-o até você lhe dar outra chave.
- Clique em **Limpar** no fundo da lista para eliminar todas as chaves não usadas de uma vez. O botão mostra quantas são, e a confirmação lista-as primeiro. O Enconvo nunca elimina chaves não usadas sozinho.

Clique numa credencial para adicionar ou mudar a chave. **Usado por** lista as funções que dependem dela, como **Modelo de IA** ou **Texto para voz**; clique numa para abrir essa página de Definições.

As credenciais do próprio perfil não têm botão de eliminar aqui. Saem quando você elimina o fornecedor.

Aparecem mais dois grupos quando você os tem: **Outros serviços**, para chaves de serviços para os quais o Enconvo não tem fornecedor, e **Inícios de sessão**, para os inícios de sessão de sites e apps que você guardou.

## Quando um agente precisa de uma chave

Quando uma tarefa precisa da chave de API de um serviço, o agente mostra um cartão **Ligar** no chat em vez de pedir para colar a chave. A chave vai para a Gestão de credenciais, não para a conversa, e os chats seguintes usam-na sem perguntar outra vez.

Para um serviço para o qual o Enconvo não tem fornecedor, o cartão mostra o anfitrião para onde a chave será enviada. A chave fica guardada em **Outros serviços**, e o agente só a pode usar em pedidos a esse anfitrião.

O agente nunca guarda a própria chave: nomeia a credencial guardada, e onde um pedido ou comando mostraria a chave, lê `[redacted]`.

Num chat de telefone, o cartão **Ligar** aparece no iPhone, e a chave fica guardada na Gestão de credenciais no Mac. Num chat de IM, o agente nunca pede uma chave; envia uma ligação que abre o chat no Enconvo.

Se você colar uma chave de API numa mensagem mesmo assim, o Enconvo guarda-a na Gestão de credenciais e substitui-a por `[redacted]` no chat guardado, para pedidos seguintes e os seus outros dispositivos não a levarem. Uma chave nova que você cola para um serviço que já tem uma substitui a chave guardada.

## Inícios de sessão de sites e apps

Quando uma tarefa de navegador chega a uma página de início de sessão, um cartão pede o nome de utilizador e a palavra-passe uma vez. O Enconvo preenche-os só nesse site, e o agente nunca vê a palavra-passe. Os inícios de sessão guardados aparecem em **Inícios de sessão**. Desmarque **Lembrar este início de sessão** para o usar só nessa vez.

Quando o início de sessão de uma app do Mac precisa de uma palavra-passe, o cartão nomeia a app. O Enconvo escreve o nome de utilizador e a palavra-passe só nessa app, e a palavra-passe só num campo que esconde o que você escreve.

## Endpoints personalizados

Os fornecedores **OpenAI Compatible** e **Anthropic Compatible** têm um campo de URL base da API para o seu próprio servidor. Alguns fornecedores incluídos guardam a definição do endpoint na **Gestão de credenciais**. Para um servidor de modelos noutro computador, veja [Modelos locais](/pt-br/ai/local-llm).

Só as próprias janelas do Enconvo podem mudar para onde uma chave guardada é enviada: o endereço de um fornecedor ou de uma credencial, ou o uso de uma chave guardada por um servidor MCP. Outros programas que usam a Local API, o telefone e os agentes são recusados.

## Como as chaves são guardadas

- Cada chave e início de sessão guardados são cifrados com uma chave que fica no Keychain deste Mac, por isso uma cópia da pasta de definições do Enconvo não pode ser lida noutro computador. Se voltar a uma versão mais antiga do Enconvo, introduz as chaves outra vez.
- Outro programa que peça definições à [Local API](/pt-br/advanced/cli-local-api) do Enconvo recebe `[hidden]` no lugar de cada chave. Um plugin da loja só pode usar as suas próprias chaves e a credencial escolhida nas suas definições.
- Só código que o Enconvo instalou e que não foi alterado pode abrir chaves guardadas. As Definições mostram e conferem chaves como antes.

## Solução de problemas

| Problema | O que fazer |
| --- | --- |
| A validação falha | Confira o perfil selecionado, o método de autenticação, o endpoint e se a conta do fornecedor tem acesso. |
| Uma função funciona e outra falha | Confira se a conta suporta essa função e esse modelo. A página diz quando uma categoria só aceita uma chave de API. |
| Algo deixou de funcionar depois de mudar uma chave | O perfil é partilhado. Teste as outras categorias que o usam. |
| A área de uso mostra **Voltar a ligar** | O início de sessão expirou. Clique em **Voltar a ligar** e inicie sessão outra vez. |
