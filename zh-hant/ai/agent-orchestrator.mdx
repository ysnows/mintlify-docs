有些工作需要不止一個代理程式：由研究員找出事實、作者將它們寫成文章，或由程式設計師與審查員負責程式碼修改。在聊天中提及這些代理程式，與你對話的代理程式就會成為主導者。它會撰寫工作計畫、指派任務給每位成員，並依據目標檢查結果。針對持續推進的工作，[專案](#專案)會將同一個資料夾的計畫、聊天與檔案集中在同一處。

## 將工作交給多個代理程式

1. 在任何聊天中輸入 `@` 與代理程式名稱的開頭，然後按 Return 從清單中選取。依工作需求加入所需的代理程式數量。
2. 描述每個代理程式該做的事，然後傳送。例如：「@Researcher 找出關於京都竹林的三個事實，然後由 @Writer 將它們寫成一篇短文。」
3. 主導者會回覆一份工作計畫：**目標**、判定完成的條件（**完成條件**）、不包含的範圍，以及指派給每位成員的一項任務。每項任務都會一字不漏地收到目標與這些條件。需要另一項任務結果的任務會等待它完成，並在啟動時併入該任務尚未合併的工作成果。
4. 若計畫等待你確認，請檢查後點擊 **開始**、**修改計畫** 或 **放棄**。當你啟動計畫時，成員便會開始工作。
5. 任務完成後，計畫卡片會顯示每項結果，主導者也會說明目標是否已達成。

任務可以指派給你的任何代理程式或程式設計代理作為團隊成員，即使它不是專案的成員也一樣。只需在請求中提及它，若希望它思考得更深入或回答得更快，也可以選擇它的推理強度。

包含 Codex 的計畫啟動時，Enconvo 會先請求資料夾存取權限，以免在你離開後才因權限提示而中斷執行。

## 追蹤執行中的計畫

計畫執行期間，聊天上方的一列會顯示它的目標、進度、費用與耗時。點擊它即可開啟執行檢視：查看每項任務的步驟、找到的內容、提供的佐證、依成員統計的費用，以及某項任務未能通過的原因。

部分結果會等你確認後才讓計畫繼續。點擊 **繼續傳遞** 可接受被保留的結果或審查發現，點擊 **退回修改** 則讓成員修正。

## 查看結果

計畫結束時，結果卡片會優先說明它得出的結論與你的下一步，下方則是每項任務的完整結果。程式設計任務附有 **合併** 按鈕，另有一列會列出尚未合併的任務。

主導者會逐條核對 **完成條件**，並說明哪些任務顯示已滿足條件。獨立核查會標出任務結果未明確證明的說法。若目標尚未達成，主導者可在同一預算下針對同一個目標繼續執行更多計畫，最多五輪。

主導者也可能會針對後續執行建議最多三條經驗教訓。你可以選擇保留或捨棄每一條：只有你保留的項目才會進入[記憶](/zh-hant/ai/memory)。

## 追蹤看板

點擊聊天頂部的 **看板**，即可將任務以卡片形式檢視。每項任務都有一個編號（例如 T-1），並從 **待開始**、**執行中** 推進至 **已完成**。**等你確認** 會列出所有等待你回答或核准的項目。

| 控制項 | 作用 |
| --- | --- |
| **全部** / **等你確認** | 顯示所有任務，或僅顯示等待你處理的任務。 |
| **分組方式** | 將卡片分組，例如依想法或依 **聊天**。 |
| **顯示** | 變更每張卡片顯示的內容。 |
| **搜尋任務或 T-12** | 依文字或編號尋找任務。 |

側邊欄圖示列 **···** 選單中的 **看板** 會顯示所有聊天的任務。包含任務的聊天也會在側邊欄對應列下方列出它們。

若某項任務的檢查與修復輪次持續發現相同的問題，輪次將會停止，而不會不斷重試。若某項檢查無法執行，系統會直接說明，而不會將正常運作的程式碼退回。

## 專案

專案將同一個資料夾的相關聊天集中在一起，資料夾中的 `AGENTS.md` 會成為專案的指令。點擊側邊欄中 **專案** 旁的 **+** 即可開啟 **建立專案**：

- 輸入 **專案名稱** 以在「文件」中建立新資料夾，或點擊 **使用現有資料夾** 或 **複製儲存庫**。
- 在 **起點** 下，選擇 **空白** 或預置團隊：**研究台**、**內容工作室**、**應用開發組** 或 **行程規劃**。

### 複製儲存庫

1. 在 **建立專案** 中，點擊 **複製儲存庫**。
2. 貼上 GitHub URL、`owner/name` 或任何 Git 位址。若你已登入 GitHub，也可以從清單中挑選你的儲存庫。
3. 點擊 **複製**。儲存庫會被複製到新資料夾中，並作為專案開啟。

### 由誰執行工作

在配有成員的專案中，主導者規劃每個目標、成員負責建置，再由審查或測試進行檢查。成員可包含 Claude Code 與 Codex 等程式設計代理。每項程式設計任務都會在各自獨立的程式碼副本中執行，計畫的結果卡片上提供 **合併** 按鈕，供你準備好時合併。

Claude Code、Codex、Grok Build 或 Antigravity 皆可擔任專案主導者。當有成員時，擔任主導者的程式設計代理會像其他主導者一樣，在工作計畫中規劃成員的工作並讀取他們的結果。在沒有成員的專案中，它會在聊天中自行完成工作，不會產生工作計畫或看板任務，直到你新增成員為止。

在專案的主導者聊天中，你可以依名稱將請求的一部分交給特定模型（例如 Opus 5.5），或同時指定代理程式與模型（例如讓 Claude Code 使用 Opus 5.5）。主導者也可以為自己的工作啟動子代理。專案還能透過自己的工作流程來執行目標與任務：參閱[使用你自己的工作流程](/zh-hant/ai/projects)。

成員無法啟動計畫、核准操作、變更設定、安裝軟體或使用你的登入狀態。程式設計代理成員無法推送、切換其他分支或移除工作樹：只有 Enconvo 會執行合併與推送。專案主導者聊天與其任務中的完整取用運作方式與其他聊天相同。關於看板、想法與專案設定，請參閱[專案與看板](/zh-hant/ai/projects)。

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 按下 Return 卻直接送出訊息，而非選取代理程式 | 請先等待輸入框下方出現代理程式清單，再按下 Return。 |
| 任務停留在 **等你確認** | 開啟該任務或對應聊天，回答它正在等待的問題或核准請求。 |
| 程式設計代理無法啟動 | 請先安裝並登入該代理。參閱[程式設計代理](/zh-hant/ai/coding-agents)。 |
| Codex 計畫停下來請求資料夾存取權限 | 計畫啟動時請先回應資料夾存取權限詢問，執行就能在你離開後繼續。 |
