有些工作需要不只一個代理程式：由研究員找出事實，由寫手把事實寫成貼文，再由程式設計師和審查者處理一項變更。在聊天中指名這些代理程式，你正在對話的代理程式就會成為主導者。它會撰寫工作計畫，把任務分配給每位成員，並對照目標檢查結果。若是持續進行的工作，[專案](#專案)會把同一個資料夾的計畫、聊天和檔案放在一起。

下方影片在 2 分鐘內介紹完整流程：用 @ 帶入代理程式、工作計畫、看板和專案。

## 把一項工作交給多個代理程式

1. 在任何聊天中，輸入 `@` 和代理程式名稱的開頭，然後按 Return 從列表中選取。工作需要幾個代理程式，就加入幾個。
2. 說明每一個代理程式該做什麼，然後傳送。例如：「@研究員 找出三項關於京都嵐山竹林的事實，然後 @寫手 把它們寫成一篇短貼文。」
3. 主導者會以工作計畫回覆：**目標**、完成時必須成立的條件（**完成標準**）、不包含的內容，以及每位成員各一項任務。每項任務都會逐字收到目標和這幾行內容。需要另一項任務結果的任務會等待它，並在開始時併入該任務尚未合併的成果。
4. 如果計畫在等你，請先檢查，然後點一下 **開始**、**修改計畫** 或 **放棄**。成員會在你開始計畫時啟動。
5. 任務完成後，計畫卡片會顯示每項結果，主導者會說明目標是否達成。

任務可以交給你的任何代理程式或程式設計代理作為隊友，即使它不是專案的成員也可以。在你的需求中指名它，如果希望它想得更深入或回答得更快，也可以選擇它的推理強度。

當包含 Codex 的計畫開始時，Enconvo 會先詢問資料夾取用權限，這樣在你離開之後，執行就不會因此中斷。

## 追蹤執行中的計畫

計畫執行時，聊天上方會有一行顯示它的目標、進度、費用和時間。點一下即可開啟執行檢視：每項任務的步驟、發現的內容、提供的佐證、各成員的費用，以及任務未能完成的原因。

有些結果會等你處理，計畫才會繼續。點一下 **繼續傳遞** 可接受被暫停的結果或審查發現，或點 **退回修改** 讓成員修正。

## 閱讀結果

計畫結束時，結果卡片會先說明最終成果和你的下一步。下方是每項任務的完整結果。程式設計任務有 **合併** 按鈕，並有一行文字指出尚未合併的任務。

主導者會檢查每一條 **完成標準**，並說明哪些任務顯示它已達成。獨立檢查會標出任務未清楚證明的任何說法。如果目標尚未達成，主導者可以在同一預算下，針對同一目標繼續進行更多計畫，最多五個。

主導者也可能建議最多三條教訓，供之後的執行參考。你可以保留或捨棄每一條：只有你保留的才會進入[記憶](/zh-hant/ai/memory)。

## 查看看板

點一下聊天頂端的 **看板**，可以把它的任務以卡片顯示。每項任務都有編號，例如 T-1，並從 **待開始** 移到 **執行中**，再到 **完成**。**等你確認** 收納所有在等你回答或核准的項目。

| 控制項 | 作用 |
| --- | --- |
| **全部** / **等你確認** | 顯示所有任務，或只顯示在等你的任務。 |
| **分組方式** | 為卡片分組，例如依想法或依 **聊天**。 |
| **顯示** | 變更每張卡片顯示的內容。 |
| **搜尋任務或 T-12** | 以文字或編號尋找任務。 |

側邊欄圖示列的 **···** 選單中的 **看板**，會顯示你所有聊天的任務。有任務的聊天，也會在側邊欄中它的那一列下方列出這些任務。

如果任務的檢查與修正回合一直發現同樣的問題，這些回合會停止，而不是再試一次。無法執行的檢查會直接說明，而不是把可運作的程式碼退回。

## 專案

專案會把相關的聊天圍繞著一個資料夾組織起來，該資料夾的 `AGENTS.md` 會成為專案的指示。點一下側邊欄中 **專案** 旁的 **+**，開啟 **建立專案**：

- 輸入 **專案名稱** 即可在「文件」中建立新資料夾，或點一下 **使用現有資料夾** 或 **複製儲存庫**。
- 在 **起點** 下，選擇 **空白** 或一個團隊：**研究台**、**內容工作室**、**應用開發組** 或 **行程規劃**。

### 複製儲存庫

1. 在 **建立專案** 中，點一下 **複製儲存庫**。
2. 貼上 GitHub URL、`owner/name` 或任何 Git 位址。如果你已登入 GitHub，也可以從列表中選擇你的儲存庫。
3. 點一下 **複製**。儲存庫會複製到新資料夾中，並以專案開啟。

### 誰來做事

在有成員的專案中，主導者規劃每個目標，成員負責建置，再由審查或測試進行檢查。成員可以包含 Claude Code 和 Codex 等程式設計代理。每項程式設計任務都在自己的程式碼副本中進行，計畫的結果卡片上有 **合併** 按鈕，等你準備好時使用。

Claude Code、Codex、Grok Build 或 Antigravity 都可以主導專案。有成員時，程式設計代理主導者會像其他主導者一樣，在工作計畫中規劃成員的工作並讀取他們的結果。在沒有成員的專案中，它會直接在聊天中自己完成工作，不使用工作計畫或看板任務，直到你加入成員為止。

在專案的主導者聊天中，你可以指名某個模型來處理部分需求，例如 Opus 5.5，或同時指名代理程式與模型，例如 Opus 5.5 上的 Claude Code。主導者也可以為自己的工作啟動子代理。專案可以透過它自己的工作流程來執行目標和任務：請參閱[使用你自己的工作流程](/zh-hant/ai/projects)。

成員不能啟動計畫、核准事項、變更設定、安裝軟體，也不能使用你的登入狀態。程式設計代理成員不能推送、移動其他分支或移除 worktree：只有 Enconvo 會合併與推送。專案主導者聊天及其任務中的完整取用，運作方式與其他聊天相同。關於看板、想法和專案的設定，請參閱[專案與看板](/zh-hant/ai/projects)。

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 按 Return 時傳送了訊息，而不是選取代理程式 | 等輸入框下方出現代理程式列表後，再按 Return。 |
| 任務卡在 **等你確認** | 開啟該任務或聊天，回答它在等的問題或核准。 |
| 程式設計代理無法啟動 | 請先安裝並登入。請參閱[程式設計代理](/zh-hant/ai/coding-agents)。 |
| Codex 計畫停下來詢問資料夾取用權限 | 在計畫開始時回答資料夾取用的問題，讓執行不需要你也能繼續。 |
