代理程式（Agent）將指令、模型與工具結合在一起，專注處理特定類型的工作。當你經常需要重複給予相同指令，或某項工作需要一組特定工具時，就可以建立一個代理程式。你可以在 **設定 → 代理程式列表** 中管理你的代理程式。

## 初始內建代理程式

**Mavis** 是預設代理程式：它能回答問題，也可以操作你的 App、瀏覽網頁與處理檔案。內建代理程式各自專精於一項工作：**Writer**、**Planner**、**Reviewer**、**Advisor**、**Researcher**、**Designer** 與 **Coder**。**Claude Code**、**Codex**、**Grok Build**、**Antigravity** 與 **Muse Code** 可在專案資料夾中與你已安裝的程式設計代理對話，而 **Grok Bot** 則與雲端的 xAI 代理程式對話。參閱[程式設計代理](/zh-hant/ai/coding-agents)。

你可以從任何聊天頂部的代理程式選單，或從聊天視窗輸入框上方的卡片中選擇代理程式。代理程式列表會將你最近聊過天的代理程式排在最前面。

## 代理程式的組成部分

在 **設定 → 代理程式列表** 中點選一個代理程式，即可開啟它的設定頁面。左側各分區可快速跳轉至對應設定：

| 分區 | 設定內容 |
| --- | --- |
| **指令** | 每次對話開始前給予代理程式的說明。輸入時會自動儲存變更。 |
| **樣式** | 它的 **回覆風格**，以及 **智慧介面** 等級：主動以圖表、表格和卡片回覆的積極程度。參閱[設定風格](#設定風格)。 |
| **模型** | 它撰寫回覆時使用的 AI 模型。每個代理程式可使用不同的模型。 |
| **工具與技能** | 它能使用哪些工具、如何尋找其餘工具，以及它的技能資料夾與存放專用技能和處理檔案的 **工作資料夾**。參閱[選擇工具與技能](#選擇工具與技能)。 |
| **知識** | 它會搜尋哪些知識庫、依什麼順序搜尋，以及知識庫找不到答案時是否搜尋網頁。參閱[選擇知識庫](#選擇知識庫)。 |
| **記憶** | 它會讀取哪些記憶，以及是否記住新內容。 |
| **語音** | 朗讀其回覆時使用的聲音。 |
| **行為** | 它能看到什麼、如何執行以及如何回覆，例如 **回覆語言** 與 **Cloud 點數執行上限**。 |
| **使用方** | 除聊天外還有哪些入口會啟動此代理程式，以及它的 **連結、CLI 與 API** 列。 |

## 建立代理程式

1. 在 **設定 → 代理程式列表** 中點擊 **新增代理程式**，或在 SmartBar 中執行 **建立代理**。
2. 輸入 **標題**，也可選填 **虛擬形象** 與說明其用途的 **描述**。
3. 在 **智慧體指令** 下，描述它應該做什麼、需要什麼輸入，以及如何呈現結果。
4. 在 **它可以使用什麼？** 下，從預設組合開始：**日常**（所有內建工具）、**程式設計**、**研究** 或 **寫作**。之後可在 **工具與技能** 中修改。
5. 選擇它的模型。在 **推薦模型** 下，Enconvo 會讀取描述並推薦一個 Enconvo Cloud 模型，並在旁附上一個較經濟的模型和一個更強大的模型。點擊 **用這個**，或選擇其他模型。參閱[使用推薦模型](/zh-hant/ai/model-selection-guide)。
6. 點擊 **建立機器人**。接著開啟該代理程式，為它選擇技能和知識庫。
7. 用它開始一個新聊天，並用一個小而典型的任務測試。

如果想繪製虛擬形象而非上傳圖片，可在這裡或稍後於代理程式設定中開啟虛擬形象選擇器的 **生成** 分頁。選擇一種風格（**扁平**、**3D**、**動漫**、**照片**、**線條** 或 **水彩**）並點擊 **生成**：你的圖像模型會根據代理程式的名稱和描述繪製四個虛擬形象。你可以補充細節再重新生成，或點擊想要的圖片。在點擊 **生成** 前，不會繪製任何內容。

指令範例：

```text
Help me turn meeting notes into actionable follow-ups.
Separate decisions, open questions, and action items.
For action items, preserve the owner and due date if stated;
otherwise mark them as unspecified.
```

## 設定風格

在 **樣式** 下，有兩項設定決定代理程式回覆的呈現方式。單一聊天也可以從 **+** 選單的 **使用風格** 中挑選其他風格。

**回覆風格** 設定語氣、篇幅與格式：**標準**、**簡潔**、**講解**、**正式**，或你自己的風格。點擊 **新增風格** 可根據一段描述或你自己的寫作範本建立風格，點擊 **管理** 可編輯你的風格。

**智慧介面** 設定在未經要求時，主動以圖表、表格和卡片回覆的積極程度：

| 等級 | 作用 |
| --- | --- |
| **精選** | 繪製資料、比較與計畫。摘要與解釋則保留為純文字。 |
| **主動**（預設） | 只要圖表、表格或卡片更易閱讀，就會加上它們，即使在解釋說明中亦同。 |
| **視覺優先** | 以視覺化內容為主導，單則回覆中可能會使用多個檢視。回覆耗時會略長。 |

視覺內容越多，耗時越長，消耗的點數也越多。即時通訊管道和語音回覆仍保留為純文字。

## 選擇工具與技能

在 **工具與技能** 下，選擇代理程式尋找可用功能的方式：

- **自動發現**（推薦）從基礎工具開始，當任務需要時自動尋找任何已安裝的技能、外掛程式、連接器或 MCP 伺服器。它依語意比對，因此即使用戶請求的措辭與工具描述不同，或以另一種語言提出，依然能找到它。
- **僅限所選** 賦予代理程式固定的一組工具。勾選它可使用的內建工具、技能和 MCP 伺服器。當任務需要其他工具時，它會告訴你缺少什麼，而不會自行搜尋。

使用 **自動發現** 時，你仍可關閉此代理程式絕不應觸碰的 **內建工具**、在 **釘選技能** 下釘選技能使其在每次聊天中都列出，並關閉 **推薦 Enconvo 商店中的外掛程式** 以停止它提供可安裝的外掛程式。**技能資料夾** 可針對此代理程式單獨關閉個別技能。

只給予代理程式完成工作所需的工具：

| 需求 | 能力 |
| --- | --- |
| 讀取與編輯文件 | [檔案工具](/zh-hant/ai/file-tools) |
| 尋找最新資訊 | [網頁搜尋](/zh-hant/ai/web-search)與[網頁擷取](/zh-hant/ai/web-fetch) |
| 在網站中操作 | [使用瀏覽器](/zh-hant/features/browser-control) |
| 操作桌面 App | [電腦操作](/zh-hant/features/computer-use) |
| 搜尋你的資料 | [知識庫](/zh-hant/ai/knowledge-base) |
| 重複使用流程 | [技能](/zh-hant/configuration/skills) |
| 連接外部服務 | [MCP 伺服器](/zh-hant/features/mcp) |
| 執行程式碼 | [程式碼執行器](/zh-hant/ai/code-runner) |
| 在一步中進行多次工具呼叫 | [程式碼模式](/zh-hant/configuration/code-mode) |

模型必須支援你所選的工具和輸入類型。工具本身也需要各自的憑證、存取權限和設定，單靠指令無法授予代理程式原本沒有的權限。

## 選擇知識庫

在 **知識** 下，選擇代理程式查找的範圍：

| 選項 | 作用 |
| --- | --- |
| **全部知識庫** | 當問題需要時，在你的任一知識庫中查找。 |
| **先查選定的** | 先在你加入的知識庫中查找，找不到時再查看其餘知識庫。 |
| **只查選定的** | 只在你加入的知識庫中查找。其他知識庫僅在你以 `@` 提及時才會開啟。 |

點擊 **新增知識庫** 進行選擇，並拖曳它們來調整查找順序。

## 核准操作

執行模式旁的 **權限** 標籤決定代理程式何時停下來先詢問你。它會出現在聊天視窗、SmartBar、App 側邊欄與動態島的代理模式中。它們調整的都是該代理程式的同一項設定，因此在一處修改，其他地方也會同步更新。

| 模式 | 何時先詢問 |
| --- | --- |
| **請求核准** | 執行指令、編輯工作資料夾以外的檔案，以及在 App、瀏覽器或線上服務中操作之前 |
| **替我核准**（預設） | 僅在看起來可能不安全的操作之前，例如刪除檔案、傳送訊息、發佈或付款 |
| **完整取用** | 從不詢問。代理程式直接執行動作 |

讀取檔案、搜尋和查看螢幕畫面永遠不會詢問。**替我核准** 也不會在僅為自身設定 `PATH` 的指令，或刪除它在暫存資料夾下自行建立的檔案的指令前詢問；刪除其他任何檔案仍會詢問。

當一個代理程式將工作交給另一個代理程式或程式設計代理時，被呼叫的一方會以與你目前對話相同的權限模式運作。每張核准卡片都會說明是哪項設定觸發了詢問，例如「因專案設為『替我核准』而詢問」。請參閱[代理沙盒](/zh-hant/configuration/sandbox)，了解指令執行後的限制機制。

### 詢問出現的位置

詢問會出現在聊天執行所在的視窗中。若該視窗目前未顯示該聊天（例如已隱藏，或屬於內嵌面板），詢問會移至動態島。如果 30 秒內沒有人在動態島回應，已配對的 iPhone 會收到提醒通知，即使聊天的視窗仍開在背景中被你正在使用的 App 遮住也是如此。

如果你沒有回應就關閉了動態島卡片，點擊動態島聊天中正在等待的步驟即可再次查看選項。代理程式向你提出的問題也採用相同機制。

### 回應詢問

- **是，僅允許一次** 僅允許執行這一次操作。
- **是，且不再詢問** 在該聊天的剩餘時間內都允許，即使 Enconvo 重新啟動後也會記住。
- 或直接輸入內容告訴代理程式應改為怎麼做。

當聊天在等待時，聊天視窗的列表、SmartBar 的最近聊天以及動態島中會顯示 **等待核准**，而非執行中。iPhone App 的聊天列表則會將其標記為 **需要核准**。

子代理會在它的父聊天中提問，問題中會註明是哪個子代理在詢問以及它正在處理什麼任務。排程任務、工作流程與即時通訊管道執行時不會詢問，因為沒有人在視窗前回應。

## 子代理

在代理模式中，代理程式可以將任務拆分為多個部分，並同時啟動最多六個子代理，每個子代理各自擁有獨立對話。待它們回報後，代理程式再整理回覆。只有在拆分明顯有幫助（例如多項互不相關的搜尋），或你主動要求時，它才會這麼做。若遇到速率限制等 AI 錯誤導致子代理中途停止，代理程式仍會取得它目前已找到的成果，並在錯誤排除後讓它繼續。

啟動子代理時，代理程式可為它指派專屬的模型、推理強度、指令和名稱，或將目前的對話分支給它。當代理程式自行挑選模型時，快速查詢、閱讀和簡單的重複性工作會交由你的服務供應商的小型模型執行，較難的推理會使用較高的推理強度，其餘工作則維持在你選定的模型上。子代理還可以啟動自己的子代理，最多三層深度。

- **將程式設計代理作為子代理。** Claude Code、Codex、Antigravity、Grok Build 與 Muse Code 皆可作為子代理運作。卡片會顯示程式設計代理的圖示、工作位置，以及使用的工具呼叫次數、耗時和 Token 數。
- **獨立工作樹。** 當一個子代理在另一個子代理修改檔案的同時也修改檔案，它會獲得專屬的 git worktree，因此兩個子代理絕不會互相覆蓋工作。沒有變動的工作樹會在子代理結束時自動移除。僅製作設計、文件、簡報、研究或審查的子代理不需要工作樹，因此同時啟動多個時不會為每個都複製一份專案。
- **其他電腦。** 代理程式可以在你另一台已配對的電腦上執行子代理，將任務交給該電腦上的代理程式或程式設計代理。參閱[其他電腦](/zh-hant/integrations/other-computers)。
- **引導干預。** 代理程式可以向執行中的子代理任務追加訊息、中斷它，或聯絡同一個專案中的另一個代理程式對話。停止一個聊天會同時停止其下方的所有子代理。
- **流水線。** 代理程式可以在單一步驟中執行預先規劃的一組子代理，例如對一份檔案列表執行相同檢查。失敗的執行恢復時，不會重新執行已經完成的子代理。

### 平行聊天

當你要求代理程式為另一項任務開啟新聊天時，它會以你指定的推理強度開啟一個新聊天，並在 Mac、iPhone 與 Android 上像你自己發起的聊天一樣顯示在聊天列表中。頂部的一則註記會說明是由哪個聊天啟動了它。針對該任務的審查與測試仍會作為它的子代理執行。代理程式為自己啟動的聊天也可以從其卡片移入你的聊天列表。

### 追蹤並與子代理對話

聊天中的卡片會按任務列出每個子代理，並以圖示顯示它正在執行、等待你的核准、已完成或已失敗。執行中的子代理那一列還會顯示它此刻正在做什麼，以及執行的模型和推理強度。新子代理也會在卡片出現的同時，顯示在訊息框上方的背景工作列中。

子代理產出的內容（例如設計或文件）會在製作時顯示在其所在列下方。點擊即可在聊天旁開啟；代理程式也會在回覆中以卡片形式交給你。

- 點擊任一列即可開啟該子代理的對話。它的工作區面板與 `@` 檔案搜尋會顯示啟動它的那個聊天的工作資料夾。在 SmartBar 與動態島中，它的工作會就地展開。
- 在子代理的對話中輸入內容即可與它交談。它會在那裡回覆你、向你提問、在該對話中請求核准，並繼續在同一個資料夾中工作。啟動它的代理程式會等待它回覆你，然後讀取它的最新回覆。對已經結束的子代理傳送訊息會立即重新啟動它，即使此時另一個子代理正在同一個資料夾中修改檔案。
- 在子代理的對話中，每則訊息都會標示傳送它的代理程式。來自父代理程式的訊息會註明它是引導了執行中的任務、等待、中斷任務，還是開啟了新一輪對話。
- 聊天詳細資料中的 **譜系** 會展示完整的子代理樹，最深三層。在程式設計代理的聊天中，它會顯示啟動它的 Enconvo 聊天。
- 在聊天視窗的側邊欄中，聊天的子代理會列在該聊天下方，聊天列上的按鈕可摺疊該列表。

### 子代理角色

每個子代理啟動時都會擔任一個角色：

| 角色 | 作用 |
| --- | --- |
| **預設** | 以啟動它的代理程式身分運作，使用相同的指令、工具與模型 |
| **Explorer** | 僅讀取檔案、搜尋與查看 App。無論權限標籤如何設定，都無法編輯、執行會更改任何內容的指令或進行線上操作 |
| **你的其中一個代理程式** | 以該代理程式身分執行，使用它自己的指令、工具與模型，並在與啟動它的聊天相同的工作資料夾中運作 |
| **專案助手** | 由專案定義在 `.claude/agents`、`.codex/agents` 或 `.enconvo/agents` 中，位於工作資料夾或其上層資料夾（直到儲存庫根目錄）。以啟動它的代理程式身分運作，但遵循助手自己的指令。它僅使用檔案中列出的工具、當檔案註明時僅執行唯讀操作，並在你的模型服務供應商支援時使用助手指定的模型 |
| **你自己的助手** | 定義在你主資料夾中的 `~/.enconvo/agents`、`~/.claude/agents` 或 `~/.codex/agents` 中，可在每個聊天中使用。運作方式與專案助手相同 |

如果想自行指定，請在代理模式的聊天中輸入 `@`，並從 **子代理** 分組中挑選，該分組列出了各種助手、**Explorer** 以及一個通用的 **子代理**。代理程式會針對你的訊息啟動該子代理、為它撰寫任務，並在它回報後給出回覆。你自己的代理程式仍留在選單的代理程式分組中。

請在每個代理程式的設定中清楚描述其職責：負責拆分工作的代理程式會閱讀這些描述，藉此判斷哪個代理程式適合哪項任務。若要將任務交給你的某個代理程式或程式設計代理作為團隊成員，並為它指定專屬的推理強度，請參閱[代理程式編排器](/zh-hant/ai/agent-orchestrator)。

### 專案助手

專案助手與你自己的助手使用與 Claude Code 子代理和 Codex 代理角色相同的檔案，因此已經配置這些檔案的儲存庫或主資料夾無需額外設定。

- Claude Code 檔案（frontmatter 中含 `name` 與 `description` 的 Markdown）若設定 `permissionMode: plan`，或僅列出 `Read`、`Grep`、`Glob` 等讀取工具，即為唯讀。
- Codex 檔案（含 `description` 與 `developer_instructions` 的 TOML）若設定 `sandbox_mode = "read-only"`，即為唯讀。
- 當服務供應商未提供助手指定的模型時，助手會改用該聊天的模型。

Claude Code 檔案中的 `tools` 與 `disallowedTools` 決定助手可使用代理程式的哪些工具。Enconvo 會將每個名稱對應至自己的工具：

| 助手檔案中的設定 | 助手可以 |
|---|---|
| `Read`、`Grep`、`Glob`、`LS` | 讀取與搜尋檔案 |
| `Edit`、`MultiEdit`、`Write` | 編輯與建立檔案 |
| `Bash` | 執行任何 shell 指令 |
| `Bash(git diff:*)` | 僅執行以 `git diff` 開頭的指令 |
| `WebSearch`、`WebFetch` | 搜尋網頁並讀取網頁內容 |
| `mcp__github__get_issue`、`mcp__github` | 使用已連接 MCP 伺服器的單一工具或所有工具 |

若沒有 `tools` 這一行，助手可使用除 `disallowedTools` 所列之外的所有工具。不在列表內的呼叫不會執行，系統會告知助手它擁有哪幾個工具。每個助手仍可載入技能並向你提問。在 `.enconvo/agents` 檔案中，你也可以依 API 路徑列出 Enconvo 工具，例如 `browser-use/*`。

Claude Code 檔案中的技能、MCP 伺服器、輪次上限、背景執行與 worktree 設定也都會生效。

## 觸發代理程式的方式

- 在[聊天視窗](/zh-hant/ai/chat)、[SmartBar](/zh-hant/features/smartbar)、[App 側邊欄](/zh-hant/features/app-sidebar)或[動態島](/zh-hant/features/dynamic-island)中與它聊天。
- 設定 **語音指令**，將口述請求傳送給你選擇的代理程式。參閱[聽寫](/zh-hant/features/dictation)。
- 透過 [Live Talk](/zh-hant/features/live-voice) 與它通話，或用[虛擬形象](/zh-hant/features/avatar)賦予它桌面角色。
- 使用[即時通訊管道](/zh-hant/integrations/messaging)連接通訊軟體。
- 使用[自動化](/zh-hant/workflows/scheduled-jobs)稍後自動執行。
- 透過連結、終端機指令或 API 呼叫從 Enconvo 外部執行它。參閱[連結、CLI 與 API](#連結、cli-與-api)。

### 連結、CLI 與 API

在 **設定 → 代理程式列表** 中開啟一個代理程式。在 **使用方** 下方，**連結、CLI 與 API** 這一列有一個 **顯示** 按鈕。點擊它即可取得用於以你的文字和檔案執行該代理程式的 Deeplink、終端機指令與 API 呼叫，全部都可直接複製。AI 指令也提供同一列功能。

## 預設設定與延續性

在修改多個聊天或管道共用的代理程式之前，請先查看[模型預設設定](/zh-hant/ai/model-selection-guide)。為代理程式需要重複使用的事實設定[記憶](/zh-hant/ai/memory)，並將文件存放在知識庫中，而非把所有內容都塞進指令裡。

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 請求失敗 | 請先閱讀工具錯誤訊息，或檢查是否缺少輸入內容。 |
| 無法判斷是模型還是工具的問題 | 先關閉選用工具並重試相同請求，再逐一加回工具測試。 |
| 操作將修改檔案或外部服務 | 在核准前先檢查目標位置與影響範圍。 |
| 代理程式表示缺少某項工具或技能 | 在 **工具與技能** 下檢查是否設為 **僅限所選**，或某個內建工具是否被關閉。 |
| 回覆中的圖表與卡片過多，或耗時過長 | 在 **樣式** 下將 **智慧介面** 設為 **精選**，或從 **+** 選單的 **使用風格** 中針對單一聊天調整。 |
