專案會將同一個資料夾的聊天、想法與團隊集中在同一處。你只需把想做的事情寫成想法，專案的主導者就會與團隊共同規劃，每項任務都會在看板上逐步推進，直到完成。針對網站或 App 等持續推進的工作，若希望能一眼掌握進度與需要你處理的事項，就非常適合使用專案。

下方影片示範了開啟專案、新增一條將部分工作交給 Claude Code 的想法、在看板上追蹤進度，以及封存和還原專案的流程。

## 開始之前

你需要先建立一個專案。在聊天視窗側邊欄中點擊 **專案** 旁的 **+** 並選擇一個資料夾：參閱[建立專案](/zh-hant/ai/agent-orchestrator)。若要將任務交給 Claude Code 或 Codex 等程式設計代理，請先完成安裝與登入：參閱[程式設計代理](/zh-hant/ai/coding-agents)。

## 開啟專案

在側邊欄中點擊專案。專案頁面包含三個分頁：

| 分頁 | 顯示內容 |
| --- | --- |
| **聊天** | 專案與主導者的對話，以及列出[需要你處理事項](#查看需要你處理的事項)的面板。 |
| **看板** | 專案的想法，從 **未開始**、**規劃中**、**進行中** 到 **已完成**。 |
| **團隊與設定** | 團隊成員列表，以及團隊[何時向你確認](#選擇團隊何時向你確認)。 |

團隊成員的頭像會顯示在左上角，主導者排在第一位。專案聊天的任務也會顯示在側邊欄對應聊天的下方。

## 新增想法

想法是你希望專案執行的事項。

1. 開啟 **看板** 分頁並點擊 **新想法**。
2. 用平時的說話方式寫下你的需求。你可以附上螢幕截圖或檔案，或點擊麥克風直接口述。
3. 如有需要，可設定 **優先順序**。Enconvo 會根據你的描述自動推測 **種類**：**功能**、**錯誤**、**改進**、**文件** 或 **研究**。若推測有誤，可手動修改。
4. 點擊 **新增想法**。

想法會以卡片形式出現在 **未開始** 下方，並附有根據你描述產生的簡短標題，以及代表優先順序的紅、琥珀或藍色旗標。主導者會立即開始規劃，並將它移至 **規劃中**。想法啟動時，你附上的檔案會一併傳送給主導者。若只想查看特定種類的想法，可使用 **依種類篩選**。

想法也可以自動匯入。為[自動化](/zh-hant/workflows/scheduled-jobs)加入 **加入 Ideas** 動作後，監聽到的每個 GitHub issue、Discord 或 Telegram 訊息、電子郵件或 webhook 都會成為專案看板上的一則想法。主導者會重現問題並規劃修復，或研究需求後附上理由關閉或進行規劃，並在改動任何內容前先徵求你的同意。

計畫準備就緒後，會顯示每項任務、執行者以及使用的模型。確認後點擊 **開始**，想法就會移至 **進行中**。主導者會根據想法的 **目標** 與 **完成條件** 列進行規劃，只有當主導者判斷目標已達成時，想法才會移至 **已完成**。

## 追蹤想法

點擊一則想法即可開啟它的頁面。一側是你與主導者的對話，另一側則是想法的計畫、任務、描述、檔案與目標。**目前進度** 會顯示 **規劃工作**、**執行工作** 與 **審查與測試**，以及各自的進展與執行者。

若想重新處理已完成的想法，點擊 **重新開啟**。

包含任務的想法頂部提供兩種檢視模式：**任務** 只以看板形式顯示其任務；**與 … 聊天**（顯示主導者名稱，例如 **與 Mavis 聊天**）則會開啟規劃該想法的聊天。

## 將任務交給程式設計代理

在想法或專案聊天中直接寫出代理程式名稱，有需要也可加上模型名稱。你也可以只寫出模型名稱，例如 Opus 5.5，主導者就會使用該模型執行該項任務。即使在沒有成員的專案中也適用。例如：

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

主導者會將指定部分規劃為交給該代理程式在該模型上執行的任務（即使該代理程式並非專案成員），其餘部分則可由自己完成。計畫和看板都會在執行者旁顯示所用的模型。若名稱可能對應多個模型或找不到對應模型，主導者會向你詢問。

當程式設計代理完成時，其任務會在想法的 **任務** 看板中移至 **待審查**，等待你的審查。若專案資料夾不是 Git 儲存庫，任務則會直接移至 **已完成**。每項程式設計任務都會在各自獨立的程式碼副本中執行，計畫的結果卡片上會提供 **合併** 按鈕，方便你準備好後合併。成員本身無法執行推送或合併。

你在「聊天」分頁或「想法」中交給主導者的每項任務都會顯示在看板上，並依想法或聊天分組。在看板的聊天篩選器中選擇某個聊天，或將 **分組方式** 設為 **聊天**，即可追蹤單一對話的任務。

你在專案聊天中直接完成的工作也會出現在看板上：當聊天修改了檔案或執行了指令時，看板上的卡片會追蹤它直到 **已完成**，並附上簡短摘要與修改的檔案清單。點擊卡片即可開啟該聊天。主導者看得到這些卡片，並會讓自己的任務避開相同的檔案。

## 合併已完成的工作

點擊任務或計畫結果卡片上的 **合併**，即可將變更合併至專案的 **基礎分支**。同一檔案其他行上尚未提交的變更不會阻擋合併。如果 git 正在忙碌，合併會稍等片刻；若有殘留的鎖定檔案，也會指出該檔案名稱。

若想不經點擊自動合併，請在 **專案設定 → 看板** 中開啟 **合併通過的工作**。這需要先在 **工作樹** 中設定 **基礎分支**。之後每項任務只要通過檢查並由另一家供應商的代理程式審查通過，就會自動合併。在 **通過條件** 下，可選擇 **無阻擋性問題**、**審查者核准** 或 **僅檢查**。發生衝突的任務會退回給其成員處理。當審查者無法執行時，所有合併都會暫停，而不會跳過審查。

### 非 Git 專案

在資料夾不是 Git 儲存庫的專案中，每個主導者聊天都會將其工作計畫儲存到各自的聊天資料夾中，因此兩個主導者聊天可以同時執行各自的計畫。計畫卡片會顯示 **儲存至** 與資料夾路徑，而 **另外變更了** 則會列出任務在該資料夾外觸及的檔案。

## 以其他方式詢問主導者

在專案的主導者聊天中：

- **比較答案** 會向兩到六個代理程式提出相同問題，並由主導者比較它們的回答。
- **使用風格** 可選擇主導者撰寫回覆時採用的風格。

若需要讓 Codex、Claude Code 或你的其他代理程式審查或測試目前的工作，直接開口要求即可。在專案中，主導者會將該代理程式作為子代理啟動，並將結果帶回同一個聊天。除了指派給專案成員的任務外，主導者也可以為自己的工作啟動子代理。

若要透過專案的某個工作流程執行任務，輸入 `@` 並選擇該工作流程，或在 **團隊與設定** 分頁中點擊它旁邊的 **在聊天中使用**。參閱[使用你自己的工作流程](#使用你自己的工作流程)。

## 查看需要你處理的事項

開啟 **聊天** 分頁。訊息框上方的面板包含三個欄位：

| 欄位 | 列出內容 |
| --- | --- |
| **需要你處理** | 等待你回答、核准或審查的任務。 |
| **進行中** | 正在執行的任務。 |
| **新結果** | 已完成但你尚未開啟查看的任務。 |

點擊任一列即可開啟對應的想法。

## 使用總看板管理所有任務

在聊天視窗側邊欄圖示列的 **···** 選單中，**看板** 會將所有聊天、專案和團隊的任務集中在同一處顯示。若想將它常駐在圖示列上，請在該選單中選擇 **自訂側欄…**。參閱[聊天視窗](/zh-hant/ai/chat)。

若只想查看部分專案，點擊左上角的篩選器（**全部看板**）並勾選想查看的專案。看板的其他控制項請參閱[使用看板](/zh-hant/ai/agent-orchestrator)。

## 設定團隊

開啟 **團隊與設定** 分頁。上方顯示主導者與每位成員，點擊 **新增成員** 可加入其他代理程式。點擊左上角的團隊頭像即可一次查看整個團隊：主導者旁有 **更換**，每位成員則有可直接就地編輯的角色說明。

主導者可以是你的任何代理程式，或是程式設計代理：Claude Code、Codex、Grok Build 或 Antigravity。擔任主導者的程式設計代理同樣會在工作計畫中規劃成員的工作並讀取結果，就像其他主導者一樣。

成員也可以是你[其他已配對電腦](/zh-hant/integrations/other-computers)上的代理程式。主導者會將需要該電腦的任務交給它們，並將答案作為任務結果傳回。如果該電腦在你的帳號上尚未具備裝置存取權限，任務會提示並引導至 **管理裝置**。

### 團隊的運作方式

你從聊天或想法交給主導者的每個目標，都會依 **標準** 流程推進：**規劃工作**、**執行工作**，然後 **審查與測試**。你可以選擇由誰負責每個步驟。將規劃交給某位成員後，當你提出需求時，該成員便會撰寫計畫；接著主導者會將任務整理為工作計畫，等待你點擊 **開始**。你還可以開啟或關閉檢查步驟，並設定 **修復輪數**，決定任務最多退回修復幾次。

### 使用你自己的工作流程

**團隊與設定** 分頁中的 **自訂工作流程** 預設為關閉。關閉時，每個目標都會透過 **標準** 流程執行。開啟後，便可透過[工作流程](/zh-hant/workflows/introduction)執行目標或單一任務：

- **或用工作流程執行每個目標** 會列出團隊工作流程。將游標移至其中一個並點擊 **用於所有目標**，或點擊 **新增團隊工作流程** 建立自己的工作流程。
- **任務工作流程** 會列出主導者可指派給單一任務的工作流程，例如修復錯誤。點擊 **在聊天中使用** 可在主導者聊天中指名使用，或點擊 **新增工作流程** 建立新的工作流程。

內建工作流程包括：

| 工作流程 | 作用 |
| --- | --- |
| **Ship** | 將想法化為經你核准的規格、設計與計畫，附帶測試、檢查、審查與驗證逐一建置任務，最後審查整個分支。 |
| **Planner** | 將想法化為經你核准的規格、設計與任務清單，並將任務作為工作計畫交給主導者。 |
| **Sprint** | 附帶測試、檢查、審查與驗證建置單一已規劃的任務。 |
| **Compound** | 將你保留的經驗教訓套用至儲存庫的文件與規則中。 |
| **Verify setup** | 找出檢查與執行專案的方法，撰寫經你核准的驗證操作手冊，並透過實際執行加以證明。 |

每一列會顯示工作流程的圖示、執行成員的頭像，以及執行次數和失敗次數。當某個工作流程缺少成員時，請點擊該列的 **選擇代理程式…**。點擊任一列即可開啟工作流程並修改其步驟或負責人。

在專案中對工作流程儲存的變更會先維持為 **草擬**：在你點擊 **發佈** 之前，新計畫會繼續使用已發佈的版本。**回復至上一版本** 可還原至先前的版本。任務的工作流程會顯示每個步驟的 Token 用量與費用，並以 API 價格計算總計。

### 設定檢查命令

檢查命令會在已完成的任務進入審查前，於其各自的程式碼副本中執行。未通過檢查的任務會退回給該任務的成員修正。

1. 在 **團隊與設定** 分頁中，點擊 **專案設定**，再點擊 **看板**。
2. 在 **檢查命令** 旁，點擊 **幫我找**。Enconvo 會從專案檔案中讀取指令，並僅在測試通過時才填入。
3. 若找不到指令，請點擊 **請 Mavis 設定**（按鈕上會顯示你的主導者名稱）。主導者會在聊天中找出或新增該指令。

未設定檢查命令的專案，其檢查步驟會顯示為 **未檢查**。

### 清理工作樹

Git 專案中的每個聊天與任務都在各自的工作樹中運作。為釋放磁碟空間，Enconvo 會封存已不再需要的工作樹並移除其資料夾。在 **專案設定 → 工作樹** 中：

| 設定 | 作用 |
| --- | --- |
| **封存已合併的工作樹** | 當工作樹的工作已進入基礎分支，且沒有未提交或未推送的內容時，封存該工作樹。 |
| **封存沒有聊天的工作樹** | 當聊天列表中已沒有屬於該工作樹的聊天時，封存該工作樹。 |
| **封存閒置的工作樹** | 當工作樹及其聊天在 **閒置多久後封存** 所選的天數（3、7、14 或 30 天）內無任何活動時，一併封存。 |

包含未提交變更的工作樹一律會保留。**還原** 可將已封存的工作樹恢復。

## 選擇團隊何時向你確認

開啟 **團隊與設定** 分頁。

在 **何時向你確認** 下：

| 設定 | 作用 |
| --- | --- |
| **計畫就緒時** | **智慧**（預設）會在計畫僅執行你已要求的事時立即開始，並在超出範圍或包含高風險步驟時等待你點擊 **開始**。**每次詢問** 每次都會等待你點擊 **開始**。**一律立即開始** 會在每個計畫就緒時立即啟動。 |
| **新增待辦後立即開始規劃** | 開啟：主導者會立即規劃每則新想法。關閉：新想法會停留在 **未開始**，直到你手動啟動。 |

無論你的選擇為何，刪除、傳送、發佈、付款或推送等動作永遠都會先詢問。資料夾、工作樹、權限、預算與邊界設定皆位於 **專案設定** 中。

## 你不在時讓主導者繼續行動

在設為 **完整取用** 的專案中，當任務回報結果而聊天中沒有人時，主導者可以繼續推進工作。在 **專案設定 → 看板** 中開啟 **你不在時 Lead 也能動手**。

主導者隨後會自行修正、重試並合併，上限為每小時 6 輪與每天 100,000 點數。除了任務自身的程式碼副本外，它絕不會傳送、推送、發佈、付款或刪除任何內容。

當你回來時，主導者聊天頂部的 **你不在的時候** 卡片會列出主導者做了什麼，以及留給你的後續步驟。若連續兩輪失敗或達到上限，主導者會暫停，並在 **需要你處理** 中詢問要 **繼續執行** 或 **保持暫停**。

## 封存專案

專案完成後，可以將其封存以從側邊欄中清除，同時不刪除任何資料。

1. 將滑鼠移至側邊欄中的專案上並點擊 **⋯**。
2. 選擇 **封存專案**。

專案及其聊天會從側邊欄移除，其排程任務也會暫停。已封存專案中的聊天在還原前無法接收訊息。

若要恢復專案：

1. 開啟 **設定 → 已封存**。
2. 點擊 **專案**。
3. 點擊專案旁的 **還原**。

專案及其聊天會回到側邊欄，其排程任務也會重新開啟。

## 手機上的專案

iPhone App 也能開啟你的專案：包含想法、看板、專案設定、**新增專案**，以及工作計畫卡片，讓你可以在卡片上回覆、合併、開始或重試任務。該處的 `@` 選單也會列出專案的成員與工作流程。參閱 [iPhone App](/zh-hant/integrations/iphone-app)。

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 新想法一直停留在 **未開始** | 在 **團隊與設定** 中開啟 **新增待辦後立即開始規劃**，或開啟該想法並手動啟動。 |
| 即使選擇了 **智慧**，計畫仍在等待確認 | 計畫超出了你原本要求的範圍，或包含高風險步驟。檢查後點擊 **開始** 即可。 |
| 程式設計代理的任務沒有啟動 | 請先安裝該程式設計代理並登入。 |
| 任務顯示為 **已暫停** 並附有登入警告 | 程式設計代理已登出，或登入即將過期。點擊 **重新登入**。重新登入後，已暫停的任務會繼續執行。 |
| 看板卡片以琥珀色顯示問題 | 這是設定問題。請依卡片上的修復指示處理；主導者不會自動重試此問題。若是 Enconvo 錯誤，則會註明可安全重試。 |
| 保存在 iCloud 中的專案任務失敗 | 開啟「最佳化 Mac 儲存空間」後，檔案可能不在本機 Mac 上。請在 Finder 中對專案資料夾選擇 **保持下載**。 |
| 任務表示專案資料夾已遺失 | 資料夾已被移動或刪除。請移回原處，或為新位置建立新專案。 |
| 任務停在專案的 **邊界** | 在任務上點擊 **編輯邊界** 以允許所需存取的目錄。只有你可以修改邊界。 |
| 任務提示留下了未完成的合併或 rebase | 對應代理程式在中途停止。請先完成或復原該合併或 rebase，再合併此任務。 |
| 所有計畫都在等待 **開始** | 當你登出 Enconvo 時，計畫會等待確認。請在 **設定 → 帳號** 中登入。 |
| 側邊欄中找不到某個專案 | 它可能已被封存。請在 **設定 → 已封存** 的 **專案** 下尋找。 |
| 工作流程任務失敗 | 開啟該任務，它會顯示指令最後輸出的內容與哪位成員的步驟失敗。 |
| 目標未使用你選擇的工作流程 | 在 **團隊與設定** 分頁中開啟 **自訂工作流程**。關閉時，所有目標都會透過 **標準** 流程執行。 |
