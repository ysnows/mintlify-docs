專案會把同一個資料夾的聊天、想法和團隊放在一起。你把想要的內容寫成一個想法，專案的主導者就會與團隊一起規劃，每項任務會在看板上移動，直到完成。專案適合持續進行的工作，例如網站或 App，讓你一眼就能看出什麼正在執行、什麼需要你處理。

下方影片會開啟一個專案，新增一個把部分工作交給 Claude Code 的想法，在看板上追蹤它，並封存及還原該專案。

## 開始之前

你需要一個專案。點一下聊天視窗側邊欄中 **專案** 旁的 **+**，然後選擇一個資料夾：請參閱[建立專案](/zh-hant/ai/agent-orchestrator)。若要把任務交給 Claude Code 或 Codex 等程式設計代理，請先安裝並登入：請參閱[程式設計代理](/zh-hant/ai/coding-agents)。

## 開啟專案

點一下側邊欄中的專案。它的頁面有三個分頁：

| 分頁 | 顯示內容 |
| --- | --- |
| **聊天** | 專案與其主導者的聊天，以及一個顯示[需要你處理的事項](#看看有什麼在等你)的面板。 |
| **看板** | 專案的想法，從 **未開始** 經 **規劃中** 和 **進行中** 到 **完成**。 |
| **團隊與設定** | 團隊中有誰，以及團隊何時[與你確認](#選擇團隊何時與你確認)。 |

團隊成員的頭像會顯示在左上角，主導者排在最前面。專案聊天的任務也會顯示在側邊欄中它那一列的下方。

## 新增想法

想法就是你希望專案去做的事。

1. 開啟 **看板** 分頁，點一下 **新想法**。
2. 用你平常說話的方式寫下你想要的內容。你可以附加螢幕截圖或檔案，也可以點一下麥克風直接說。
3. 如果需要，可以設定 **優先順序**。Enconvo 會根據你的文字猜測 **種類**：**功能**、**錯誤**、**改進**、**文件** 或 **研究**。如果猜錯了，可以自行更改。
4. 點一下 **新增想法**。

想法會以卡片出現在 **未開始** 底下，帶有根據你的文字寫成的簡短標題，以及代表優先順序的紅色、琥珀色或藍色旗標。主導者會立刻開始規劃，並把它移到 **規劃中**。你附加的檔案會在想法開始時送達主導者。若只想查看某一種想法，請使用 **依種類篩選**。

想法也可以自動進來。為[排程工作](/zh-hant/workflows/scheduled-jobs)設定 **加入 Ideas** 動作後，它收到的每個 GitHub issue、Discord 或 Telegram 訊息、電子郵件或 webhook，都會成為專案看板上的一個想法。主導者會重現錯誤並規劃修正，或研究某項請求，然後附上理由將它結案或為它做規劃；在任何內容變更之前，都會先詢問你。

計畫準備好時，會顯示每項任務、由誰執行，以及使用哪個模型。檢查後，點一下 **開始**。想法會移到 **進行中**。主導者依據想法的 **目標** 和 **完成標準** 那一行來規劃，只有在主導者判斷該目標已達成時，想法才會移到 **完成**。

## 追蹤想法

點一下想法即可開啟它的頁面。一側是你與主導者的聊天，另一側是想法的計畫、任務、文字、檔案和目標。**進展** 顯示 **規劃工作**、**完成工作** 和 **審查與測試**，以及每一項進行到哪裡、由誰負責。

若要再次處理已完成的想法，請點一下 **重新開啟**。

有任務的想法在頂端有兩種檢視：**任務** 只以看板顯示它的任務，而 **與** 加上主導者的名稱，例如 **與 Mavis 聊天**，則會開啟當初規劃它的聊天。

## 把任務交給程式設計代理

在想法中或專案的聊天中指名代理程式，若有需要也可指名模型。你也可以只指名模型，例如 Opus 5.5，主導者就會用它來執行該任務。這在沒有成員的專案中同樣適用。例如：

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

主導者會把指名的部分規劃成該代理程式在該模型上的一項任務，即使該代理程式不是專案的成員也一樣，其餘的則可以自己完成。計畫和看板會在負責人旁邊顯示模型。如果名稱可能指向多個模型，或不指向任何模型，主導者會詢問你。

程式設計代理完成後，它的任務會在想法的 **任務** 看板上的 **待審查** 底下等你審查。如果專案的資料夾不是 git 儲存庫，則會直接進入 **完成**。每項程式設計任務都在自己的程式碼副本中進行，計畫的結果卡片上有 **合併**，等你準備好時使用。成員無法自行推送或合併。

你交給主導者的每項任務，無論是在聊天分頁或想法中，都會顯示在看板上，並依想法或聊天分組。在看板的聊天篩選器中選取一個聊天，或選擇 **分組方式** **聊天**，即可追蹤單一對話。

你在專案的聊天中做的工作也會顯示在看板上：當聊天變更檔案或執行指令時，會有一張卡片跟著它移到 **完成**，附上簡短摘要和變更的檔案。點一下卡片即可開啟該聊天。主導者看得到這些卡片，並讓自己的任務避開同樣的檔案。

## 合併完成的工作

在任務上，或在計畫的結果卡片上，點一下 **合併**，即可把它合併到專案的 **基礎分支**。同一個檔案其他行上尚未提交的變更不會阻止合併。如果 git 正忙，合併會稍等一下，若留下了鎖定檔案，則會指出該檔案的名稱。

若想不用點擊就合併，請在 **專案設定 → 看板** 中開啟 **合併通過的工作**。這需要在 **工作樹** 中設定 **基礎分支**。之後每項任務在通過檢查，並由另一家廠商的代理程式審查通過後，就會自行合併。在 **通過條件** 下，選擇 **沒有阻擋問題**、**審查者核准** 或 **僅檢查**。發生衝突的任務會退回給它的成員。當審查者無法執行時，所有合併都會暫停，而不是被略過。

### git 以外的專案

在資料夾不是 git 儲存庫的專案中，每個主導者聊天會把它的工作計畫儲存到自己的聊天資料夾，因此兩個主導者聊天可以同時執行計畫。計畫的卡片會顯示 **儲存到** 和該資料夾，而 **另外變更了** 會列出任務在資料夾之外動到的檔案。

## 用其他方式詢問主導者

在專案的主導者聊天中：

- **比較答案** 會向二到六個代理提出同一個問題，由主導者比較它們的回答。
- **使用風格** 用來選擇主導者撰寫答案的方式。

若想請 Codex、Claude Code 或你的其他代理程式審查或測試目前的工作，直接說就可以了。在專案中，主導者會把該代理程式當作子代理啟動，並把結果帶回同一個聊天。除了交給專案成員的任務之外，主導者也可以為自己的工作啟動子代理。

若要透過專案的某個工作流程來執行任務，請輸入 `@` 並選取該工作流程，或在 **團隊與設定** 分頁中點一下它旁邊的 **在聊天中使用**。請參閱[使用你自己的工作流程](#使用你自己的工作流程)。

## 看看有什麼在等你

開啟 **聊天** 分頁。訊息框上方的面板有三欄：

| 欄 | 列出內容 |
| --- | --- |
| **等你確認** | 等你回答、核准或審查的任務。 |
| **處理中** | 正在執行的任務。 |
| **新結果** | 你還沒開啟過的已完成任務。 |

點一下某一列即可開啟它的想法。

## 用看板掌握一切

聊天視窗側邊欄圖示列的 **···** 選單中的 **看板**，會在同一處顯示每個聊天、專案和團隊的任務。若要讓它留在圖示列上，請在該選單中選擇 **自訂側欄…**。請參閱[聊天視窗](/zh-hant/ai/chat)。

若只想查看部分專案，請點一下左上角的篩選器（**全部看板**），選取你要的專案。看板的其他控制項請見[查看看板](/zh-hant/ai/agent-orchestrator)。

## 設定團隊

開啟 **團隊與設定** 分頁。頂端顯示主導者和每位成員，並有 **新增成員** 可以帶入另一個代理程式。點一下左上角的團隊頭像，即可一次看到整個團隊：主導者旁有 **變更**，每位成員則有可以就地編輯的角色。

主導者可以是你的代理程式之一，也可以是程式設計代理：Claude Code、Codex、Grok Build 或 Antigravity。程式設計代理主導者會像其他主導者一樣，在工作計畫中規劃成員的工作並讀取他們的結果。

成員可以是你[其他已配對電腦](/zh-hant/integrations/other-computers)上的代理程式。主導者會把需要那台電腦的任務交給它們，答案會作為任務的結果送回。如果那台電腦在你的帳號下沒有裝置取用權限，任務會說明這一點，並指向 **管理裝置**。

### 團隊如何運作

你從聊天或想法交給主導者的每個目標，都會經過 **標準** 流程：**規劃工作**、**完成工作**，然後 **審查與測試**。你可以選擇每個步驟由誰負責。把規劃交給某位成員，該成員會在你要求時撰寫計畫；接著主導者會把它的任務提出為一份工作計畫，等待你按 **開始**。你也可以開啟或關閉檢查，並設定 **修復輪數**，也就是任務退回修正的次數。

### 使用你自己的工作流程

團隊與設定分頁上的 **自訂工作流程** 預設為關閉，開啟後才會生效。關閉時，每個目標都會透過 **標準** 流程執行。開啟後，即可透過[工作流程](/zh-hant/workflows/introduction)執行目標或單一任務：

- **或者用工作流程執行每個目標** 會列出團隊工作流程。指向其中一個並點一下 **用於所有目標**，或點一下 **新增團隊工作流程** 來建立你自己的。
- **任務工作流程** 會列出主導者可以交給單一任務的工作流程，例如修正錯誤。點一下 **在聊天中使用** 即可在主導者聊天中指名一個，或點一下 **新增工作流程** 來建立。

內建的工作流程：

| 工作流程 | 作用 |
| --- | --- |
| **Ship** | 把想法轉成你核准的規格、設計和計畫，用測試、檢查、審查和驗證建置每項任務，然後審查整個分支。 |
| **規劃師** | 把想法轉成你核准的規格、設計和任務，並把任務以工作計畫交給主導者。 |
| **Sprint** | 用測試、檢查、審查和驗證建置一項已規劃的任務。 |
| **Compound** | 把你保留的教訓套用到儲存庫的文件和規則上。 |
| **Verify setup** | 找出如何檢查並執行專案，撰寫一份你核准的驗證執行手冊，並透過實際執行來證明它可行。 |

每一列會顯示工作流程的圖示、負責的成員頭像，以及它執行過多少次、失敗了多少次。當工作流程缺少成員時，請點一下該列中的 **選一個 Agent**。點一下某一列即可開啟該工作流程，並更改它的步驟或負責的人。

你在專案中對工作流程儲存的變更會維持為 **草擬**：在你點一下 **發佈** 之前，新計畫會繼續使用已發佈的版本。**回復到上一版本** 會帶回先前的版本。任務的工作流程會顯示每個步驟的 token 和費用，並以 API 價格算出總計。

### 設定檢查命令

檢查命令會在已完成任務的程式碼副本中執行，然後才送去審查。檢查失敗時會退回給任務的成員修正。

1. 在 **團隊與設定** 分頁中，點一下 **專案設定**，然後點 **看板**。
2. 在 **檢查命令** 旁，點一下 **幫我找**。Enconvo 會從專案的檔案中讀取該命令，並且只在它通過時才填入。
3. 如果找不到，請點一下 **請 Mavis 設定**（按鈕會顯示你的主導者名稱）。主導者會在它的聊天中找出或新增該命令。

沒有檢查命令的專案，會把它的檢查步驟顯示為 **未檢查**。

### 清理工作樹

git 專案中的每個聊天和任務都在自己的工作樹中進行。為了釋放磁碟空間，Enconvo 會封存你已處理完的工作樹，並移除它們的資料夾。在 **專案設定 → 工作樹** 中：

| 設定 | 作用 |
| --- | --- |
| **封存已合併的工作樹** | 當工作樹的工作已進入基礎分支，且沒有未提交或未推送的內容時，封存該工作樹。 |
| **封存沒有聊天的工作樹** | 當工作樹的聊天都已不在聊天列表中時，封存該工作樹。 |
| **封存閒置的工作樹** | 在 **閒置多久後封存** 下你選擇的天數（3、7、14 或 30）內沒有任何活動後，封存該工作樹及其聊天。 |

有未提交變更的工作樹一律會保留。**還原** 會帶回已封存的工作樹。

## 選擇團隊何時與你確認

開啟 **團隊與設定** 分頁。

在 **何時與你確認** 下：

| 設定 | 作用 |
| --- | --- |
| **計畫準備好時** | **智慧**（預設）會在計畫就是你已要求的內容時立刻開始，並在它做得更多或有風險時等你按 **開始**。**一律詢問我** 每次都等你按 **開始**。**一律開始** 會在每個計畫準備好時立刻開始。 |
| **新增待辦事項時立刻開始規劃** | 開啟：主導者會立刻規劃每個新想法。關閉：新想法會在 **未開始** 中等待，直到你開始它們。 |

刪除、傳送、發佈、付款或推送的動作，無論你怎麼選擇都一定會詢問。資料夾、工作樹、權限、預算和邊界都在 **專案設定** 中。

## 你不在時讓主導者動手

在 **完整取用** 的專案中，當任務回報而聊天中沒有人時，主導者可以讓工作持續進行。請在 **專案設定 → 看板** 中開啟 **你不在時 Lead 也能動手**。

之後主導者會自行修正、重試和合併，上限為每小時 6 個回合和每天 100,000 點。它絕不會在任務自己的程式碼副本之外傳送、推送、發佈、付款或刪除任何內容。

你回來時，主導者聊天頂端的 **你不在的時候** 卡片會列出主導者做了什麼，以及留給你的步驟。連續兩個回合失敗，或達到上限時，主導者會暫停，**等你確認** 會詢問要 **繼續執行** 還是 **保持暫停**。

## 封存專案

專案完成後，可以封存它，從側邊欄清除而不刪除任何內容。

1. 指向側邊欄中的專案，點一下 **⋯**。
2. 選擇 **封存專案**。

專案及其聊天會從側邊欄消失，它的排程任務也會暫停。已封存專案中的聊天在你還原之前無法接收訊息。

若要帶回它：

1. 開啟 **設定 → 已封存**。
2. 點一下 **專案**。
3. 點一下專案旁的 **還原**。

專案會連同它的聊天回到側邊欄，它的排程任務也會重新開啟。

## 手機上的專案

iPhone App 也可以開啟你的專案：想法、看板、專案設定、**新增專案**，以及工作計畫卡片，你可以在卡片上回答、合併、開始或重試任務。那裡的 `@` 選單會列出專案的成員和工作流程。請參閱 [iPhone App](/zh-hant/integrations/iphone-app)。

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 新想法一直停在 **未開始** | 在 **團隊與設定** 中開啟 **新增待辦事項時立刻開始規劃**，或開啟該想法自行開始。 |
| 即使選了 **智慧**，計畫仍在等待 | 計畫做的超出了你所要求的範圍，或包含有風險的步驟。請檢查後點一下 **開始**。 |
| 程式設計代理的任務沒有開始 | 安裝該程式設計代理並登入。 |
| 任務以 **已暫停** 等待並顯示登入警告 | 程式設計代理已登出，或它的登入即將到期。點一下 **重新登入**。已暫停的任務會在你登入後再次執行。 |
| 看板卡片以琥珀色顯示問題 | 這是設定問題。請依卡片的修正方式處理；主導者不會重試。Enconvo 錯誤則表示可以放心重試。 |
| 保存在 iCloud 的專案中任務失敗 | 開啟「最佳化 Mac 儲存空間」時，檔案可能不在你的 Mac 上。請在 Finder 中對專案資料夾選擇 **保持下載**。 |
| 任務顯示專案的資料夾不見了 | 資料夾被移動或刪除了。請把它移回去，或為它的新位置建立新專案。 |
| 任務停在專案的 **邊界** | 點一下任務上的 **編輯邊界**，允許它需要的項目。只有你能更改邊界。 |
| 任務註明合併或 rebase 做到一半 | 它的代理程式中途停了。請先完成或復原該合併或 rebase，再合併此任務。 |
| 每個計畫都在等 **開始** | 在你登出 Enconvo 時，計畫會一直等待。請在 **設定 → 帳號** 登入。 |
| 側邊欄中找不到某個專案 | 它可能已被封存。請到 **設定 → 已封存** 的 **專案** 底下查看。 |
| 工作流程任務失敗 | 開啟該任務。它會說明它的指令最後寫入了什麼，以及哪位成員的步驟失敗。 |
| 目標沒有使用你選的團隊工作流程 | 在 **團隊與設定** 分頁中開啟 **自訂工作流程**。關閉時，每個目標都會透過 **標準** 流程執行。 |
