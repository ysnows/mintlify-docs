---
title: "知識庫 MCP"
description: "讓你 Mac 上的 Claude、Cursor、Codex 與其他 MCP 用戶端搜尋並讀取你所分享的知識庫。"
---

Enconvo 可以將你的知識庫提供給同一台 Mac 上相容 MCP 的 AI 用戶端。用戶端可以搜尋並讀取你分享的知識庫，除此之外無法存取其他內容；存取權限為唯讀。這與**設定 → MCP 伺服器**是分開的，後者是為 Enconvo 的代理程式加入外部工具。

## 連接用戶端

1. 開啟[知識庫](/zh-hant/ai/knowledge-base)並點按齒輪（**知識庫設定**），然後點按 **AI 用戶端（MCP）**。
2. 開啟**啟用知識庫 MCP**。它預設為關閉，而在關閉期間，已連接的用戶端會被拒絕。
3. 選擇用戶端可以看到的內容。**與 AI 用戶端共享這個知識庫**涵蓋你目前開啟的那一個，而**共用知識庫**則會列出全部。聽寫記錄與記憶在你開啟之前都是隱藏的。
4. 在**連接用戶端**下，選擇你的用戶端（Claude Code、Cursor、Codex 或 Claude Desktop）並複製其設定。
5. 請用戶端列出知識庫，然後搜尋其中一個並讀取相符的項目。

本機端點為：

```text
http://localhost:54535/knowledge_base/mcp
```

它使用 Streamable HTTP 傳輸。用戶端使用期間請保持 Enconvo 執行。Claude Desktop 透過一個小型橋接程式 `mcp-remote` 連接，因此其設定需要 Node.js；請依照對話框中顯示的各用戶端專屬說明操作。

## 可用工具

| 工具 | 用途 |
| --- | --- |
| `kb_list` | 列出可見的知識庫 |
| `kb_search` | 搜尋可見的知識庫 |
| `item_list` | 列出可見知識庫中的項目 |
| `item_read` | 分頁讀取已建立索引的項目文字 |

這些工具皆為唯讀。此端點不會公開一般的記憶或錄音工具。讀取項目時，可能會將其來源路徑或網址作為中繼資料傳回。

## 存取與處理

此伺服器只接受回送連線，也不需要權杖。開啟它之後，本機的處理程序即可讀取你所分享的知識庫。已連接的 AI 用戶端可能會將取得的內容傳送給它自己的模型供應商，因此也請檢視該用戶端的設定。

搜尋會使用在**設定 → 記憶**的**搜尋**下設定的嵌入模型。當它在 Enconvo Cloud 上執行時，搜尋文字會傳送到那裡。「本機端點」並不代表檢索與回答的每個環節都是離線執行的。

## 疑難排解

| 問題 | 處理方式 |
| --- | --- |
| 連線被拒絕 | 確認 Enconvo 及其本機 API 正在執行。 |
| Forbidden / 403 | 確認**啟用知識庫 MCP**已開啟、用戶端是從這台 Mac 連線，且其設定與對話框中的內容一致。 |
| 找不到知識庫 | 在**共用知識庫**下開啟該知識庫。對用戶端而言，被隱藏的知識庫與不存在的知識庫看起來是一樣的。 |
| 在瀏覽器中開啟該網址顯示 405 | 瀏覽器的 GET 不是 MCP 請求。請使用 MCP 用戶端連線。 |
| 較長的文件傳回不完整 | 請用戶端以 `item_read` 要求後續的頁面。 |

若要停止所有存取，請關閉**啟用知識庫 MCP**。若要縮小用戶端可擷取的範圍，請在**共用知識庫**下關閉個別的知識庫。
