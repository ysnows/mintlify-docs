---
title: "知識庫的運作方式"
description: "了解 Enconvo 如何儲存、切分、建立索引與搜尋你的知識庫，以及如何讓搜尋結果保持良好。"
---

本頁寫給想知道文件放進知識庫後會發生什麼事的人：Enconvo 把它存在哪裡、如何切分並建立索引，以及搜尋如何挑出結果。你可以用它來調整資料集、修正不佳的搜尋結果，或從自己的程式碼呼叫知識庫。如果你剛接觸知識庫，請先從[知識庫](/zh-hant/ai/knowledge-base)開始。

簡單來說：Enconvo 會讀取每個項目的文字，切分成區塊，將每個區塊轉換成向量，並把區塊儲存在本機的 LanceDB 資料庫中。搜尋時會同時依語意與精確字詞尋找區塊，再將兩者混合。

## 資料存放位置

| 內容 | 位置 |
|---|---|
| 區塊、向量與全文索引 | 位於 `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/` 的 LanceDB 資料庫 |
| 知識庫、項目與其詳細資料 | 位於 `~/.config/enconvo/.support/knowledge_base/db` 的 SQLite 資料庫（Drizzle ORM） |

所有知識庫共用同一個 LanceDB 資料庫，每個知識庫是其中的一張資料表。Enconvo 重建知識庫的索引時，會在舊資料表旁寫入新的資料表，待新資料表就緒後再切換，所以重建期間搜尋仍可正常運作。

每個知識庫都有一個 ID。API 以 `knowledge_base_id` 接收它，Enconvo 則以 `knowledge_base|<id>` 指令來執行知識庫。若要複製知識庫的 ID，請從其標頭開啟**知識庫設定**，前往**進階**。

儲存空間用量取決於原始資料、擷取出的文字、區塊數量與嵌入維度。請監看你的資料集實際的磁碟用量，而不要只憑文件數量估算。請將來源檔案與備份獨立於搜尋索引之外保存。

## 內容如何進入

### 讀取

Enconvo 會用最適合的工具讀取各類項目：

| 內容 | 讀取方式 |
|---|---|
| **PDF** | 文件解析器外掛。它會使用 PDF 的文字，只在掃描頁面上執行你的 OCR 供應商 |
| **Word、PowerPoint、Excel、EPUB、CSV** | 文件解析器外掛 |
| **文字與 Markdown** | 直接讀取 |
| **圖片** | 你的 OCR 供應商 |
| **音訊和影片** | 你的語音轉寫供應商 |
| **網頁** | 你的網頁擷取供應商 |
| **整個網站** | 網站爬蟲，逐頁處理 |
| **YouTube** | 影片的逐字稿 |

### 切分成區塊

Enconvo 會依文字所用的語言，將文字切分成適當大小的區塊：

| 文字 | 區塊大小 | 重疊 |
|---|---|---|
| 以拉丁文字為主，例如英文 | 1,500 個字元 | 200 個字元 |
| 以中文、日文或韓文為主 | 560 個字元 | 80 個字元 |
| 混合 | 介於兩者之間，依各自所占比例 | 介於兩者之間 |

它會在能讓區塊維持在大小限制內的最自然邊界切分，依下列順序嘗試：

1. 段落
2. 行
3. 句子
4. 子句
5. 字詞
6. 強制切斷（最後手段）

試算表大約每列切成一個區塊，所以搜尋某一列時就能找到該列。這些大小是內建的，沒有對應的設定。

### 嵌入

每個知識庫都使用相同的嵌入模型 EmbeddingGemma 300M。你可以在**設定 → 記憶 → 嵌入模型**中選擇它在哪裡執行：

- **這台 Mac**：免費，且不會有任何資料離開你的 Mac，但在為新內容建立索引時會用到 GPU。需要搭載 Apple 晶片的 Mac。
- **Enconvo Cloud**：免費，使用你的 Enconvo 帳號。要建立索引或搜尋的文字會傳送到雲端。

兩者執行的是同一個模型，所以切換後會保留你現有的搜尋索引。Enconvo 會分批嵌入區塊。

### 儲存

每個區塊是知識庫資料表中的一列：

| 欄位 | 內容 |
|---|---|
| `text` | 區塊的文字 |
| `vector` | 它的嵌入向量 |
| `id` | 區塊的 ID |
| `attachment_id` | 區塊所屬的項目 |
| `type`、`url`、`title`、`ext`、`loc` | 項目的類型、位址、標題與副檔名，以及區塊在其中的位置 |
| `metadata` | 項目的其他詳細資料 |

Enconvo 也會為 `text` 保留一份由短字元片段建立的全文索引，因此能找到精確的名稱、數字、程式碼與 CJK 字詞。

## 搜尋如何運作

每次搜尋會同時對知識庫的區塊執行最多三種查找：

1. **依語意**：以相同的模型嵌入查詢，找出最接近的向量。
2. **依字詞**：對查詢中的每個字詞進行全文（BM25）搜尋，並排除常見的英文單字。
3. **依標題**：標題符合查詢的項目，每個項目附上最接近查詢的區塊。

接著 Enconvo 會將它們混合。每份清單的分數會縮放到 0 至 1，區塊的分數是語意分數的 0.6 加上字詞分數的 0.4。標題相符的項目，或包含完整查詢的區塊，排名會較高。同一個項目只會保留少數幾個區塊，因此單一冗長的文件不會擠掉其他內容，每個區塊回傳時也會附上其前後的文字。

知識庫搜尋中沒有另外的重新排序步驟。

## 維持索引健康

Enconvo 會自行建立全文索引並整理資料表。當知識庫的索引是以較舊的切分器或不同的嵌入模型建立時，它也會以已有的文字重建索引，不需要重新讀取檔案。

若要手動重建：

- **整個知識庫**：從其標頭開啟**知識庫設定**，前往**索引與搜尋**，點按**重建整個索引**旁的**重新索引…**。執行期間搜尋仍可正常運作。
- **單一項目**：在它上面按右鍵，選擇**重新索引**。

**知識庫設定**共有五個部分：**一般**（名稱與描述）、**索引與搜尋**（健康狀態、需要處理的項目、搜尋模型與重新索引）、**來源與擷取**（已連結的資料夾與擷取工具）、**AI 用戶端（MCP）**，以及**進階**（ID 與刪除知識庫）。

刪除不再需要的知識庫，即可回收磁碟空間。

### 已連結的資料夾

若有項目遺失，請先檢查來源資料夾的匯入與同步狀態。在**來源與擷取**中，每個已連結的資料夾都會顯示它是否正在同步、上次同步的時間，或找不到來源資料夾，並提供**立即同步**、**重新連結…**與**自動同步**。

接著分別檢查項目的內容擷取狀態與嵌入狀態：項目的**工作流程**會將**內容解析**與**搜尋索引**顯示為兩個階段，而且能讀取到擷取出的文字，並不代表向量索引已經完成。修正供應商或檔案存取的錯誤後，請重新索引該項目。

對已連結的檔案而言，來源資料夾才是依據。請將離線磁碟的復原與檔案刪除分開處理：找不到來源資料夾時，知識庫會保留其項目。在將匯入視為完成之前，請先檢查略過的檔案數量。

## 整理多個知識庫

每個知識庫都有自己的文件、索引與資料表。請依你搜尋的方式來劃分內容：

| 策略 | 說明 | 範例 |
|----------|-------------|---------|
| **依專案** | 每個專案一個知識庫 | `project-alpha`、`project-beta` |
| **依類型** | 依內容類型分開知識庫 | `code-docs`、`meeting-notes`、`research` |
| **依團隊** | 團隊專屬的知識 | `engineering`、`marketing`、`support` |
| **依範圍** | 個人與共用 | `personal-notes`、`company-wiki` |

若要同時搜尋多個知識庫，請用上下文選擇器附加它們，或設定代理程式所附加的知識庫。未指定任何知識庫的搜尋，會查找你所有的知識庫，但不包括記憶。

## 從程式碼使用知識庫

知識庫外掛會在 [Local API](/zh-hant/advanced/cli-local-api) 上提供它的路由，因此其他外掛、工作流程與腳本都可以呼叫。主要的路由如下：

| 路由 | 用途 |
|---|---|
| `knowledge_base/create` | 建立知識庫 |
| `knowledge_base/delete` | 移除知識庫及其所有資料 |
| `knowledge_base/add`、`knowledge_base/add_attachments` | 加入檔案、文字、連結或媒體 |
| `knowledge_base/search` | 搜尋一個或多個知識庫 |
| `knowledge_base/list` | 列出知識庫 |
| `knowledge_base/get_attachments` | 列出知識庫中的項目 |
| `knowledge_base/delete_attachments` | 從知識庫移除項目 |
| `knowledge_base/reindex` | 重建知識庫或項目的索引 |
| `knowledge_base/summarize` | 摘要單一項目 |

開啟**設定 → API**，可查看你所安裝版本中每個路由的參數。

知識庫的步驟可以放進工作流程與排程工作，例如：

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

若要給其他 AI 用戶端使用，請使用[知識庫 MCP](/zh-hant/advanced/knowledge-base-mcp)。它會透過本機的唯讀服務公開選定的知識庫；不會匯出代理程式的記憶或錄音。

## 疑難排解

| 問題 | 處理方式 |
|---|---|
| 搜尋傳回不相關的結果 | 確認項目的**搜尋索引**階段已完成，然後重新索引知識庫。請使用文件中實際出現的字詞搜尋：精確的名稱與數字會透過全文索引比對到 |
| 建立索引很慢 | 大型文件需要較長的時間。使用**這台 Mac**時，建立索引會用到 GPU；請將**嵌入模型**切換為 **Enconvo Cloud**，讓你的 Mac 保持空閒 |
| 使用 Enconvo Cloud 時，新項目無法搜尋 | 請登入你的 Enconvo 帳號。在登入之前，新內容不會建立索引，搜尋只會找到字詞相符的內容 |
| 不支援某種檔案類型 | 將它轉換為 PDF、TXT 或 MD，再重新加入 |
| 依 ID 找不到知識庫 | 從**知識庫設定 → 進階**複製 ID，並以 `knowledge_base_id` 傳入 |
