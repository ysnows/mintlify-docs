description: "了解 Enconvo 如何儲存、切分、索引和搜尋你的知識庫，以及如何維持良好的搜尋品質。"

本頁適合想了解文件進入知識庫之後會發生什麼事的使用者：Enconvo 把它存放在哪裡、如何切分與建立索引，以及搜尋如何挑選結果。你可以藉此微調文件集合、修正不佳的搜尋結果，或在自己的程式碼中呼叫知識庫。如果你剛開始接觸知識庫，請先閱讀[知識庫](/zh-hant/ai/knowledge-base)。

簡而言之：Enconvo 會讀取每個項目的文字、將其切分為文字區塊、把每個區塊轉換為向量，並將區塊儲存在本機的 LanceDB 資料庫中。搜尋時會同時依語意和精確字詞尋找區塊，然後將兩者結果融合。

## 資料存放的位置

| 內容 | 位置 |
|---|---|
| 區塊、向量與全文索引 | 位於 `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/` 的 LanceDB 資料庫 |
| 知識庫、項目與其詳細資訊 | 位於 `~/.config/enconvo/.support/knowledge_base/db` 的 SQLite 資料庫（Drizzle ORM） |

所有知識庫共用同一個 LanceDB 資料庫，而每個知識庫是其中的一張資料表。當 Enconvo 重建知識庫的索引時，會在舊資料表旁寫入一張新表，待新表就緒後再切換過去，因此重建期間搜尋仍可繼續運作。

每個知識庫都有一個 ID。API 中以 `knowledge_base_id` 傳入該值，而 Enconvo 會將知識庫作為指令 `knowledge_base|<id>` 執行。若要複製知識庫的 ID，請從其標頭開啟 **知識庫設定** 並前往 **進階**。

儲存空間取決於原始素材、擷取出的文字、區塊數量以及嵌入維度。請監控資料集的實際磁碟使用量，而不要僅憑文件數量估算。請獨立於搜尋索引之外妥善保存來源檔案與備份。

## 內容如何匯入

### 讀取

Enconvo 會使用最適合的工具讀取每種項目：

| 內容 | 讀取方式 |
|---|---|
| **PDF** | Document Parser 外掛程式。它會直接使用 PDF 中的文字，僅對掃描頁面執行你的 OCR 服務供應商 |
| **Word、PowerPoint、Excel、EPUB、CSV** | Document Parser 外掛程式 |
| **純文字與 Markdown** | 直接按原文讀取 |
| **圖片** | 你的 OCR 服務供應商 |
| **音訊與影片** | 你的語音轉寫服務供應商 |
| **網頁** | 你的網頁擷取服務供應商 |
| **整個網站** | 網站爬蟲，逐頁擷取 |
| **YouTube** | 影片的字幕逐字稿 |

### 切分為區塊

Enconvo 會依據內容所撰寫的語言，將文字切分為適當大小的區塊：

| 文字 | 區塊大小 | 重疊大小 |
|---|---|---|
| 以拉丁文字為主（如英文） | 1,500 個字元 | 200 個字元 |
| 以中文、日文或韓文為主 | 560 個字元 | 80 個字元 |
| 混合文字 | 介於兩者之間，依各自佔比計算 | 介於兩者之間 |

它會在保持區塊不超過大小限制的前提下，依下列順序選擇最自然的邊界進行切分：

1. 段落
2. 行
3. 句子
4. 子句
5. 單字
6. 硬切分（最後手段）

試算表大約以每列一個區塊的方式切分，因此搜尋某一列資料時能找到該列。這些切分大小為內建設定，無法另行調整。

### 嵌入（Embedding）

所有知識庫都使用同一個嵌入模型：EmbeddingGemma 300M。你可以在 **設定 → 記憶 → 嵌入模型** 中選擇它的執行位置：

- **這台 Mac**：免費，且沒有資料會離開你的 Mac，但在為新內容建立索引時會使用 GPU。需要搭載 Apple 晶片的 Mac。
- **Enconvo Cloud**：使用你的 Enconvo 帳號即可免費使用。正在建立索引或搜尋的文字會傳送至該處。

兩者執行的是完全相同的模型，因此切換時會保留原有的搜尋索引。Enconvo 會以批次方式嵌入區塊。

### 儲存

每個區塊是知識庫資料表中的一列：

| 欄位 | 存放內容 |
|---|---|
| `text` | 區塊的文字內容 |
| `vector` | 對應的嵌入向量 |
| `id` | 區塊的 ID |
| `attachment_id` | 此區塊所屬的項目 |
| `type`、`url`、`title`、`ext`、`loc` | 項目的類型、網址、標題、副檔名，以及區塊在項目中的位置 |
| `metadata` | 關於該項目的其他詳細資訊 |

Enconvo 也會為 `text` 維護一份由短字元片段組成的全文索引，因此能精確找到人名、數字、程式碼與中日韓詞彙。

## 搜尋的運作方式

每次搜尋會同時對知識庫的區塊執行最多三種查詢：

1. **依語意**：使用同一個模型將查詢字詞轉換為向量，並找出最接近的向量。
2. **依字詞**：針對查詢中的每個字詞執行全文（BM25）搜尋，並排除常見英文停用詞。
3. **依標題**：找出標題符合查詢的項目，各自搭配與查詢最接近的區塊。

接著 Enconvo 會融合這些結果。每個清單的分數都會縮放至 0 到 1 之間，區塊的分數為語意分數的 0.6 倍加上字詞分數的 0.4 倍。標題相符的項目或包含完整查詢字詞的區塊排名會更靠前。單一項目只會保留少數區塊，避免一份長文件擠掉其他內容，而且每個區塊都會連同前後文字一起傳回。

知識庫搜尋中沒有單獨的重排序（reranking）步驟。

## 維持索引健康

Enconvo 會自動建立全文索引並整理資料表。若某個知識庫是使用較舊的切分器或不同的嵌入模型建立的，Enconvo 也會從現有的文字直接重建其索引，無需重新讀取原檔案。

若要手動重建：

- **整個知識庫**：從標頭開啟 **知識庫設定**，前往 **索引與搜尋**，並點擊 **重建整個索引** 旁的 **重新索引…**。執行期間搜尋仍可繼續運作。
- **單一項目**：對其點擊右鍵並選擇 **重新索引**。

**知識庫設定** 包含五個部分：**一般**（名稱與描述）、**索引與搜尋**（健康狀況、需要注意的項目、搜尋模型與重新索引）、**來源與擷取**（已連結資料夾與擷取工具）、**AI 用戶端（MCP）**，以及 **進階**（ID 與刪除知識庫）。

刪除不再需要的知識庫可釋放磁碟空間。

### 已連結資料夾

若遺漏某個項目，請先檢查來源資料夾的匯入與同步狀態。在 **來源與擷取** 中，每個已連結資料夾都會顯示目前是否正在同步、上次同步的時間，或提示找不到來源資料夾，並提供 **立即同步**、**重新連結…** 與 **自動同步**。

接著請分別檢查項目的內容擷取狀態與嵌入狀態：項目的 **工作流程** 會將 **內容解析** 與 **搜尋索引** 顯示為兩個階段，能讀取到擷取出的文字並不代表向量索引已經完成。修正服務供應商或檔案存取錯誤後，請重新索引該項目。

來源資料夾始終是已連結檔案的權威來源。請將離線磁碟機復原與檔案刪除區分開來：當找不到來源資料夾時，知識庫會保留現有項目。在將匯入視為完成前，請先檢視被略過的檔案數量。

## 組織多個知識庫

每個知識庫各自擁有獨立的文件、索引與資料表。請依照你的搜尋方式切分內容：

| 策略 | 說明 | 範例 |
|----------|-------------|---------|
| **依專案** | 每個專案一個知識庫 | `project-alpha`、`project-beta` |
| **依類型** | 依內容類型區分知識庫 | `code-docs`、`meeting-notes`、`research` |
| **依團隊** | 團隊專屬知識 | `engineering`、`marketing`、`support` |
| **依範圍** | 個人與共用分開 | `personal-notes`、`company-wiki` |

若要同時搜尋多個知識庫，請透過上下文選擇器將它們附加到對話中，或在代理程式設定中指定關聯的知識庫。未指定知識庫的搜尋會查找除「記憶」以外的所有知識庫。

## 從程式碼中使用知識庫

Knowledge Base 外掛程式在 [Local API](/zh-hant/advanced/cli-local-api) 上提供相關路由，讓其他外掛程式、工作流程與腳本皆可呼叫。主要路由如下：

| 路由 | 用途 |
|---|---|
| `knowledge_base/create` | 建立知識庫 |
| `knowledge_base/delete` | 移除知識庫及其所有資料 |
| `knowledge_base/add`、`knowledge_base/add_attachments` | 新增檔案、文字、連結或媒體 |
| `knowledge_base/search` | 搜尋一個或多個知識庫 |
| `knowledge_base/list` | 列出知識庫 |
| `knowledge_base/get_attachments` | 列出知識庫中的項目 |
| `knowledge_base/delete_attachments` | 從知識庫中移除項目 |
| `knowledge_base/reindex` | 重建知識庫或單一項目的索引 |
| `knowledge_base/summarize` | 摘要單一項目 |

開啟 **設定 → API** 即可檢視你所安裝版本上各路由的參數。

知識庫步驟可整合進工作流程與自動化中，例如：

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

若要搭配其他 AI 用戶端使用，請採用[知識庫 MCP](/zh-hant/advanced/knowledge-base-mcp)。它會透過本機唯讀服務公開選定的知識庫；不會匯出代理記憶或錄音。

## 疑難排解

| 問題 | 解決方法 |
|---|---|
| 搜尋傳回不相關的結果 | 檢查該項目的 **搜尋索引** 階段是否已完成，然後重新索引知識庫。請使用文件中實際使用的詞彙搜尋：精確的人名與數字會透過全文索引進行比對 |
| 索引速度緩慢 | 大型文件需要較長時間。使用 **這台 Mac** 時，索引會佔用 GPU；將 **嵌入模型** 切換為 **Enconvo Cloud** 可保持你的 Mac 流暢 |
| 使用 Enconvo Cloud 時新項目無法搜尋到 | 請登入你的 Enconvo 帳號。在登入前新內容不會被建立索引，搜尋只能找到符合的字詞 |
| 不支援某種檔案類型 | 先將其轉換為 PDF、TXT 或 MD，然後重新加入 |
| 無法透過 ID 找到知識庫 | 從 **知識庫設定 → 進階** 複製 ID，並將其作為 `knowledge_base_id` 傳入 |
