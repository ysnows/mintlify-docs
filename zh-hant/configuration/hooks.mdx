---
title: "掛鉤"
description: "在代理程式啟動、使用工具或完成時，自動執行 shell 指令或傳送 webhook。"
---

掛鉤會在 Enconvo 中發生某些事件時執行 shell 指令或傳送 HTTP 請求，例如代理程式啟動、完成、失敗或使用工具時。掛鉤在一個 JSON 檔案中設定，因此無需建置擴充功能，就能新增通知、日誌、本機自動化或整合。

<Note>
大多數掛鉤都是「射後不理」（fire-and-forget）：它們在背景執行，不會阻塞 Enconvo。代理程式執行期間，`PreToolUse`、`Stop` 和 `SubagentStop` 是例外。代理程式會等待它們完成，因此它們可以阻擋一次工具呼叫，或讓代理程式返回繼續工作。參閱[阻塞式掛鉤](#阻塞式掛鉤)。
</Note>

## 快速開始

<Steps>
  <Step title="建立 hooks 資料夾">
    ```bash
    mkdir -p ~/.enconvo
    ```
  </Step>

  <Step title="建立 ~/.enconvo/hooks.json">
    ```json
    {
      "hooks": {
        "UserPromptSubmit": [
          {
            "hooks": [
              {
                "type": "command",
                "command": "echo 'Agent status changed' >> /tmp/enconvo-hooks.log"
              }
            ]
          }
        ]
      }
    }
    ```
  </Step>

  <Step title="觸發代理程式">
    啟動任意代理程式或聊天指令。當它的狀態變化時，Enconvo 會執行設定的指令，並向 `/tmp/enconvo-hooks.log` 附加一行。
  </Step>
</Steps>

## 設定檔

掛鉤儲存在：

```text
~/.enconvo/hooks.json
```

當新檔案不存在時，Enconvo 也會讀取舊版檔案 `~/.config/enconvo/hooks.json`。如果兩個檔案都存在，以 `~/.enconvo/hooks.json` 為準。

每次觸發事件時都會重新讀取該檔案，所以你可以在 Enconvo 執行時編輯掛鉤，無需重新啟動。

## 在設定中管理掛鉤

開啟 **設定 → 掛鉤**，可以看到 `~/.enconvo/hooks.json` 中依事件分組的掛鉤。用開關開啟或關閉某個項目，或點擊 **開啟 hooks.json** 編輯檔案。開啟或關閉某個項目時，會在該項目上寫入 `enabled: false` 或 `enabled: true`，不會改動它的指令或 webhook。

## 來自外掛程式的掛鉤

Claude Code 和 Codex 外掛程式（例如 context-mode）可以自帶掛鉤。一旦你允許它們，它們會像在 Claude Code 中一樣執行：在聊天開始時、每則訊息前後、工具呼叫前後、上下文壓縮前後，以及回覆失敗或代理程式完成時觸發。

1. 從 **外掛程式** 安裝外掛程式，或在聊天中把外掛程式的 GitHub 儲存庫、Git 位址、zip 或 npm 套件提供給代理程式。它會提供該外掛程式的安裝卡片。
2. 安裝前勾選 **允許執行它的掛鉤**。安裝時未勾選的外掛程式會顯示其掛鉤處於關閉狀態；之後可點擊其頁面上的 **允許掛鉤** 來開啟。

如果外掛程式更新改動了它的掛鉤，這些掛鉤會停止執行，直到你重新檢查並再次允許它們。Enconvo 無法執行的掛鉤會在卡片上列為不在 Enconvo 中執行。

## 掛鉤如何運作

事件觸發時，Enconvo 會：

1. 載入 `~/.enconvo/hooks.json`。
2. 僅當新檔案不存在時，退回使用 `~/.config/enconvo/hooks.json`。
3. 在頂層 `hooks` 物件中尋找鍵名與事件名相符的項目。
4. 套用可選的 `matcher` 正規表示式。
5. 略過 `enabled` 為 `false` 的項目。
6. 並行執行所有已設定的掛鉤。

掛鉤事件名稱沿用 Claude Code 和 Codex 的生命週期事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PermissionRequest`、`PostToolUse`、`Stop` 和 `SubagentStop`。對於既有的安裝，舊的 Enconvo 事件名稱和舊的扁平 JSON 結構仍然有效，但新寫入的內容使用 Codex 風格的巢狀格式。

## 設定參考

```json
{
  "hooks": {
    "event_name": [
      {
        "matcher": "optional_regex_filter",
        "enabled": true,
        "hooks": [
          { "type": "command", "command": "..." },
          { "type": "http", "url": "..." }
        ]
      }
    ]
  }
}
```

| 欄位 | 類型 | 必填 | 說明 |
|-------|------|----------|-------------|
| `hooks` | object | 是 | 以事件名稱為鍵的事件對映表。 |
| `event_name` | string | 是 | 要監聽的事件。用作 `hooks` 中的鍵。 |
| `matcher` | string | 否 | 正規表示式篩選器。對工具事件，它比對 `toolName`、`toolTitle` 或 `path`；對其他事件，它比對掛鉤事件名稱。 |
| `enabled` | boolean | 否 | 設為 `false` 可保留該項目但略過執行。預設為 `true`。 |
| `hooks` | array | 是 | 要執行的指令掛鉤和 HTTP 掛鉤。 |

### 指令掛鉤

指令掛鉤會執行一條 shell 指令。Enconvo 會把事件酬載以 JSON 格式寫入該指令的 stdin。

```json
{
  "type": "command",
  "command": "bash ~/.enconvo/hooks/on-status-change.sh",
  "timeout": 30000
}
```

| 欄位 | 類型 | 預設值 | 說明 |
|-------|------|---------|-------------|
| `type` | `"command"` | - | 必填的掛鉤類型。 |
| `command` | string | - | 要執行的 shell 指令。 |
| `timeout` | number | `30000` | 逾時時間，單位為毫秒。 |

### HTTP 掛鉤

HTTP 掛鉤會把事件酬載作為 JSON 請求主體傳送。

```json
{
  "type": "http",
  "url": "https://example.com/webhook",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer your-token"
  },
  "timeout": 30000
}
```

| 欄位 | 類型 | 預設值 | 說明 |
|-------|------|---------|-------------|
| `type` | `"http"` | - | 必填的掛鉤類型。 |
| `url` | string | - | HTTP 端點 URL。 |
| `method` | string | `"POST"` | HTTP 方法。 |
| `headers` | object | `{}` | 額外的請求標頭。 |
| `timeout` | number | `30000` | 逾時時間，單位為毫秒。 |

## 阻塞式掛鉤

在代理程式或機器人執行期間，有三個事件以阻塞式掛鉤執行。代理程式會等待所有相符的掛鉤（它們並行執行）完成後再繼續，並按照與 Claude Code 和 Codex 相同的方式讀取它們的結果。

| 事件 | 時機 | 掛鉤可以做什麼 |
|-------|------|----------------------|
| `PreToolUse` | 工具呼叫執行之前。`matcher` 會與工具名稱、標題和路由路徑進行比對。 | 阻擋呼叫，或改寫它的輸入。 |
| `Stop` | 代理程式給出回答並結束本輪之前。 | 帶著一條指令讓代理程式返回繼續工作。 |
| `SubagentStop` | 子代理完成之前。 | 帶著一條指令讓子代理返回繼續工作。 |

掛鉤有兩種方式做出決定：

- **結束代碼 2** 表示阻擋。指令寫入 stderr 的文字就是原因。
- **結束代碼 0，並在 stdout 輸出 JSON。** 其他任何輸出、結束代碼、錯誤或逾時都不做決定，執行會像沒有該掛鉤一樣繼續。

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Writing outside the project is not allowed."
  }
}
```

| JSON 輸出 | 效果 |
|-------------|--------|
| `hookSpecificOutput.permissionDecision: "deny"` | `PreToolUse`：呼叫不會執行。模型會把 `permissionDecisionReason` 當作工具結果，並可以改用其他方式。 |
| `hookSpecificOutput.permissionDecision: "ask"` | 依 `deny` 處理。Enconvo 目前還沒有針對掛鉤的確認提示。 |
| `hookSpecificOutput.permissionDecision: "allow"` | `PreToolUse`：呼叫正常執行。 |
| `hookSpecificOutput.updatedInput` | `PreToolUse`：用這個輸入代替模型的輸入來執行呼叫。 |
| `{ "decision": "block", "reason": "..." }` | `Stop` / `SubagentStop`：代理程式繼續工作，並把 `reason` 作為下一條指令。在 `PreToolUse` 上則會阻擋呼叫。 |
| `{ "decision": "approve" }` | 與 `allow` 相同。 |

HTTP 掛鉤透過 2xx 回應做出決定，回應主體為同樣的 JSON。

當多個掛鉤相符時，deny 優先於 ask，ask 優先於 allow。各個原因會合併在一起，並使用最後一個 `updatedInput`。

一個 `Stop` 掛鉤在一輪中最多可以讓代理程式返回 5 次。從第二次檢查開始，`stop_hook_active` 為 `true`，這樣掛鉤可以在其指令已被執行後讓代理程式停下。`Stop` 的阻塞只在代理程式正常結束時生效；失敗或被停止的執行仍會在背景觸發 `Stop`。

<Tip>
代理程式會等待阻塞式掛鉤，所以緩慢的 `PreToolUse` 掛鉤會拖慢每次工具呼叫，緩慢的 `Stop` 掛鉤會延遲本輪的結束。請讓它們保持快速，設定較短的 `timeout`，或把耗時工作放到背景執行（`command &`）。
</Tip>

阻塞式掛鉤會收到常規的[事件酬載](#事件酬載)，並在頂層附帶 Claude Code 的欄位：

```json
{
  "hook_event_name": "PreToolUse",
  "session_id": "Qx2...",
  "cwd": "/Users/you/project",
  "tool_name": "bash",
  "tool_input": { "command": "rm -rf build" },
  "tool_use_id": "call_1",
  "event": "PreToolUse",
  "sourceEvent": "agent_tool_step_changed",
  "params": { "toolName": "bash", "status": "running", "sessionId": "Qx2..." },
  "timestamp": 1742313600000
}
```

`Stop` 和 `SubagentStop` 收到的是 `stop_hook_active` 和 `last_assistant_message`，而不是工具欄位。指令掛鉤在代理程式的工作目錄中執行。

### 阻擋危險指令

```bash
#!/bin/bash
# ~/.enconvo/hooks/guard.sh
COMMAND=$(jq -r '.tool_input.command // empty')
if echo "$COMMAND" | grep -q 'rm -rf /'; then
  echo "Deleting from the filesystem root is not allowed." >&2
  exit 2
fi
```

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "bash",
        "hooks": [{ "type": "command", "command": "bash ~/.enconvo/hooks/guard.sh", "timeout": 5000 }]
      }
    ]
  }
}
```

### 讓代理程式在結束前執行測試

```bash
#!/bin/bash
# ~/.enconvo/hooks/require-tests.sh
[ "$(jq -r '.stop_hook_active')" = "true" ] && exit 0
echo '{"decision":"block","reason":"Run the test suite and fix any failures before you finish."}'
```

## 事件酬載

指令掛鉤從 stdin 收到這段 JSON。HTTP 掛鉤則把同樣的 JSON 作為請求主體收到。

```json
{
  "event": "UserPromptSubmit",
  "fullEvent": "event-UserPromptSubmit",
  "sourceEvent": "run_status_changed",
  "sourceFullEvent": "event-run_status_changed",
  "params": {
    "commandKey": "agent|main",
    "runStatus": "running"
  },
  "timestamp": 1742313600000
}
```

| 欄位 | 說明 |
|-------|-------------|
| `event` | 簡短的事件名稱。 |
| `fullEvent` | 帶 `event-` 前綴的內部事件名稱。 |
| `sourceEvent` | 產生該掛鉤事件的原始 Enconvo 事件（當事件為相容 Codex 而做了對應時）。 |
| `sourceFullEvent` | 帶 `event-` 前綴的原始內部事件名稱。 |
| `params` | 事件專屬的酬載。 |
| `timestamp` | Unix 時間戳記，單位為毫秒。 |

背景掛鉤也會收到 Claude Code 的欄位：`hook_event_name`、事件有工作階段時的 `session_id`，以及工具事件的 `tool_name`、`tool_input` 和 `tool_use_id`。

## 可用事件

| 事件 | 參數 | 觸發時機 |
|-------|--------|------|
| `SessionStart` | `{ command, commandKey }` | 建立了新的聊天工作階段。 |
| `UserPromptSubmit` | `{ commandKey, runStatus, status?, sessionId? }` | 由使用者輸入啟動了一次代理程式、聊天或機器人執行。 |
| `PreToolUse` | `{ toolCallId, toolName, toolTitle?, status, sessionId?, commandKey? }` | 一次工具呼叫開始。在代理程式執行期間為阻塞式。 |
| `PermissionRequest` | `{ toolCallId, toolName, toolTitle?, status, sessionId?, commandKey? }` | 一次工具呼叫進入等待權限或被拒絕狀態。 |
| `PostToolUse` | `{ toolCallId, toolName, toolTitle?, status, sessionId?, commandKey? }` | 一次工具呼叫成功、失敗、完成或被拒絕。 |
| `Stop` | `{ commandKey, runStatus, status?, sessionId? }` | 一次代理程式、聊天或機器人執行進入終止狀態。代理程式正常結束時為阻塞式。 |
| `SubagentStop` | `{ commandKey, runStatus, status?, sessionId? }` | 子代理即將完成。阻塞式。子代理不會觸發 `Stop`。 |

`run_status_changed`、`agent_tool_step_changed` 等舊版 Enconvo 事件名稱仍然有效，因此既有的掛鉤檔案不必立即遷移。

## 實用範例

### 代理程式失敗時傳送 macOS 通知

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "STATUS=$(cat | jq -r '.params.runStatus // .params.status') && [ \"$STATUS\" = \"failed\" ] && osascript -e 'display notification \"An agent failed\" with title \"EnConvo\"'"
          }
        ]
      }
    ]
  }
}
```

### 記錄代理程式狀態變化

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "jq -c '{time: (.timestamp / 1000 | strftime(\"%Y-%m-%d %H:%M:%S\")), agent: .params.commandKey, status: (.params.runStatus // .params.status)}' >> ~/.enconvo/agent-status.log"
          }
        ]
      }
    ]
  }
}
```

### 記錄代理程式的工具呼叫

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.params | \"\\(.status) \\(.toolName) \\(.toolCallId)\"' >> ~/.enconvo/agent-tools.log"
          }
        ]
      }
    ]
  }
}
```

### 傳送到 Slack

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "http",
            "url": "https://hooks.slack.com/services/YOUR/WEBHOOK/URL"
          }
        ]
      }
    ]
  }
}
```

### 自訂指令碼

建立一個從 stdin 讀取事件酬載的指令碼：

```bash
#!/bin/bash
# ~/.enconvo/hooks/on-status-change.sh
INPUT=$(cat)
STATUS=$(echo "$INPUT" | jq -r '.params.runStatus // .params.status')
AGENT=$(echo "$INPUT" | jq -r '.params.commandKey')

echo "[$(date)] $AGENT -> $STATUS" >> /tmp/enconvo-hooks.log

if [ "$STATUS" = "failed" ]; then
  osascript -e "display notification \"$AGENT failed\" with title \"EnConvo\""
fi
```

在 `~/.enconvo/hooks.json` 中引用它：

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.enconvo/hooks/on-status-change.sh"
          }
        ]
      }
    ]
  }
}
```

為指令碼加上執行權限：

```bash
chmod +x ~/.enconvo/hooks/on-status-change.sh
```

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 掛鉤沒有執行 | 檢查 `~/.enconvo/hooks.json` 是否為有效的 JSON、頂層鍵是否與事件名稱一致，以及指令在你手動執行時是否正常。如果你還保留著 `~/.config/enconvo/hooks.json`，在新檔案存在時它會被忽略。 |
| 不確定掛鉤是否會阻塞 Enconvo | 只有 `PreToolUse`、`Stop` 和 `SubagentStop` 在代理程式執行期間會阻塞。其他掛鉤都是射後不理。如果任何掛鉤失敗或逾時，Enconvo 會記錄失敗，並像沒有該掛鉤一樣繼續。 |
| 外掛程式的掛鉤沒有執行 | 開啟該外掛程式並點擊 **允許掛鉤**。如果更新改動了掛鉤，請檢查它們並再次允許。 |
| 指令找不到指令碼或執行檔 | 使用絕對路徑。指令透過 shell 執行時，`~` 展開是有效的，但絕對路徑更容易除錯。 |

### 手動測試指令碼

把一段範例酬載透過管線傳給指令碼：

```bash
echo '{"event":"Stop","params":{"commandKey":"agent|main","runStatus":"failed"},"timestamp":1742313600000}' | bash ~/.enconvo/hooks/on-status-change.sh
```
