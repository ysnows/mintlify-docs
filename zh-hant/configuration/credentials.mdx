你使用的每個服務供應商都需要憑證：一組 API 金鑰，或是登入你已經付費的訂閱方案。你在該供應商的設定頁面加入憑證後，Enconvo 會將它保存在供應商設定檔中，讓所有使用該供應商的功能共用。**設定 → 憑證管理** 則會把所有憑證集中顯示在同一個地方。

這支影片在介紹完虛擬形象與即時通訊管道後，最後會示範憑證管理。

## 新增服務供應商

<Steps>
  <Step title="開啟類別">
    開啟你想使用的功能設定頁面，例如 **設定 → AI 模型**、**設定 → 圖片生成** 或 **設定 → 文字轉語音**。
  </Step>
  <Step title="挑選服務供應商">
    選擇一個服務供應商。如果想為另一組金鑰或帳號建立第二份設定，請選擇 **新增服務供應商**。
  </Step>
  <Step title="選擇登入方式">
    在 **身分驗證** 下方選擇 **API 金鑰**，若該供應商支援使用你已付費的方案，也可以選擇 **訂閱**。
  </Step>
  <Step title="加入憑證">
    貼上你的 API 金鑰，或完成該供應商的登入流程。
  </Step>
  <Step title="測試連線">
    若頁面上有顯示 **驗證**，請點選驗證，挑選一個模型並送出簡短請求測試。
  </Step>
</Steps>

API 金鑰會向服務供應商的 API 帳戶計費。訂閱則會消耗你既有方案包含的額度並受其限制。**身分驗證** 下方的文字會說明該頁面採用的是哪一種方式。

## 共用設定檔

一個服務供應商設定檔（例如 **OpenAI 2**）會同時保存該供應商的 API 金鑰與訂閱登入狀態，並出現在該供應商支援的每一個功能類別中。重新命名或刪除設定檔會套用到所有類別，而不只是你目前所在的頁面。

各個類別仍會保有自己獨立的模型、聲音與生成設定。不過，當你更換新的 API 金鑰時，會影響到所有使用該設定檔的功能，因此修改後請測試相關功能。

供應商在不同類別提供的能力各有差異。能用於 AI 對話的訂閱登入，不代表也包含該供應商的即時語音 API。若某個類別只接受 API 金鑰，該頁面會直接註明，並列出該訂閱方案可使用的類別。

## 查看方案用量

訂閱登入會顯示你的帳號以及方案剩餘額度。像是 **剩餘 %** 這類數值代表你還剩下的可用額度。開啟帳號卡片的選單並選擇 **重新整理用量** 即可更新，或點選 **重新連線** 重新登入。

當 Claude 或 Codex 贈送你免費的額度重設次數時，Claude 或 ChatGPT 訂閱卡片會顯示 **免費額度重設**：包含剩餘次數與有效期限。點選 **使用重置** 並確認即可補滿額度。如果有多筆可用，卡片會全部列出，你可以挑選要用哪一筆。

畫面上沒有顯示用量，並不代表你的用量沒有上限。

## 管理你的憑證

開啟 **設定 → 憑證管理**。列表會依服務供應商設定檔分組顯示憑證，接著顯示 **未使用的金鑰**（目前沒有任何供應商使用的金鑰）。

- 在 **搜尋服務供應商...** 中輸入文字以尋找項目。
- 點選 **新增憑證**，為你選取的服務建立另一組憑證。
- 若要刪除憑證，請將游標移到該項目上並點選垃圾桶圖示。如果有 API 金鑰連接器正在使用該金鑰，確認視窗會列出其名稱，點選 **刪除並中斷連線** 會暫時中斷連線，直到你提供另一組金鑰。
- 點選列表底部的 **清理**，可一次刪除所有未使用的金鑰。按鈕會顯示共有幾組，確認視窗也會先列出清單。Enconvo 絕不會擅自刪除未使用的金鑰。

點選任一憑證即可新增或變更金鑰。**使用於** 會列出依賴該憑證的功能，例如 **AI 模型** 或 **文字轉語音**；點選其中一項即可直接開啟該設定頁面。

設定檔本身的憑證在這裡沒有刪除按鈕，它們會在你刪除該服務供應商時一併移除。

當你有對應資料時，畫面還會出現另外兩個分組：**其他服務**（存放 Enconvo 未內建供應商的服務金鑰）以及 **登入資訊**（存放你儲存的網站與 App 登入資料）。

## 當代理程式需要金鑰時

當任務需要某項服務的 API 金鑰時，代理程式會在對話中顯示一張 **連線** 卡片，而不是要你把金鑰直接貼進聊天裡。金鑰會存進憑證管理，不會留在對話內容中，之後的對話也能直接使用而不必重複詢問。

對於 Enconvo 沒有內建供應商的服務，卡片會顯示金鑰將傳送至的主機位址。該金鑰會儲存在 **其他服務** 下方，而代理程式只能在發往該主機的請求中使用它。

代理程式本身永遠拿不到金鑰明文：它只會指名已儲存的憑證，在任何可能顯示金鑰的請求或指令輸出中，都會顯示為 `[redacted]`。

在手機對話中，**連線** 卡片會顯示在你的 iPhone 上，而金鑰會儲存在你 Mac 的憑證管理裡。在即時通訊管道的對話中，代理程式絕對不會索取金鑰，而是傳送一個連結，讓你改回 Enconvo 開啟對話。

即使你還是把 API 金鑰貼進了訊息裡，Enconvo 也會將它存入憑證管理，並把已儲存對話中的金鑰替換成 `[redacted]`，讓後續請求與你的其他裝置都不會帶有該金鑰。為已有金鑰的服務貼上新金鑰時，會取代原本儲存的金鑰。

## 網站與 App 登入資訊

當瀏覽器任務到達登入頁面時，畫面上會出現一張卡片向你詢問一次使用者名稱與密碼。Enconvo 只會在該網站填入這些資料，代理程式永遠看不到密碼。儲存的登入資訊會顯示在 **登入資訊** 下方。取消勾選 **記住此登入資訊**，即可只在這一次登入使用。

當某個 Mac App 的登入畫面需要密碼時，卡片會顯示該 App 的名稱。Enconvo 只會在該 App 中輸入使用者名稱與密碼，而且只會將密碼輸入到會遮罩輸入字元的欄位裡。

## 自訂端點

**OpenAI 相容** 與 **Anthropic 相容** 服務供應商提供 API 基礎 URL 欄位，讓你連接自己的伺服器。部分內建供應商則將端點設定保存在 **憑證管理** 中。若要連接另一台電腦上的模型伺服器，請參閱[本機模型](/zh-hant/ai/local-llm)。

只有 Enconvo 自己的視窗能變更已儲存金鑰的傳送目標（包含供應商或憑證的位址，或 MCP 伺服器對已儲存金鑰的使用）。其他透過 Local API 存取的程式、手機與代理程式都會被拒絕。

## 金鑰保存方式

- 每組儲存的金鑰與登入資訊都會使用存放在這台 Mac「鑰匙圈」中的金鑰進行加密，因此即使複製 Enconvo 的設定資料夾，也無法在另一台電腦上讀取。如果你降回舊版 Enconvo，則需要重新輸入金鑰。
- 當其他程式透過 Enconvo 的 [Local API](/zh-hant/advanced/cli-local-api) 查詢設定時，所有金鑰都會以 `[hidden]` 代替。從商店安裝的外掛程式也只能存取它自己的金鑰，以及在其設定中指定的憑證。
- 只有經由 Enconvo 安裝且未遭竄改的程式碼才能開啟已儲存的金鑰。設定介面則照常顯示與檢查金鑰。

## 疑難排解

| 問題 | 解決方法 |
| --- | --- |
| 驗證失敗 | 檢查選取的設定檔、身分驗證方式、端點，以及你的供應商帳號是否具備存取權限。 |
| 某個功能正常但另一個功能失敗 | 確認該帳號是否支援該功能與模型。若某類別只接受 API 金鑰，該頁面會特別註明。 |
| 更換金鑰後有其他功能無法運作 | 設定檔是共用的。請測試其他同樣使用該設定檔的功能類別。 |
| 用量區域顯示 **重新連線** | 登入已過期。點選 **重新連線** 並重新登入。 |
