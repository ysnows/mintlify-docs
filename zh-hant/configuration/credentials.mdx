你使用的每個服務供應商都需要一組憑證：API 金鑰，或是登入你已付費的方案。你在該服務供應商自己的設定頁面新增憑證，Enconvo 會將它保存在服務供應商設定檔中，所有使用該服務供應商的功能都會共用。**設定 → 憑證管理** 會在同一處顯示你所有的憑證。

這支影片的最後一段是憑證管理，接在虛擬形象與即時通訊管道之後。

## 新增服務供應商

<Steps>
  <Step title="開啟分類">
    開啟你想使用之功能的設定頁面，例如 **設定 → AI 模型**、**設定 → 圖片生成** 或 **設定 → 文字轉語音**。
  </Step>
  <Step title="選擇服務供應商">
    選取一個服務供應商。若要為另一組金鑰或帳號再設定一份，請選擇 **新增供應商**。
  </Step>
  <Step title="選擇登入方式">
    在 **身分驗證** 下，選擇 **API 金鑰**；若該服務供應商允許使用你付費的方案，則選擇 **訂閱**。
  </Step>
  <Step title="新增憑證">
    貼上你的 API 金鑰，或完成該服務供應商的登入。
  </Step>
  <Step title="測試">
    若頁面有顯示 **驗證**，請點按它，然後選擇一個模型並試著送出一個簡短的請求。
  </Step>
</Steps>

API 金鑰會向該服務供應商的 API 帳號計費；訂閱則使用你方案內含的用量及其限制。**身分驗證** 下的文字會告訴你該頁面使用的是哪一種。

## 共用的設定檔

服務供應商設定檔（例如 **OpenAI 2**）保存該服務供應商的 API 金鑰與訂閱登入，並會出現在該服務供應商支援的每個分類中。重新命名或刪除設定檔，會同時變更所有這些分類，而不只是你目前所在的頁面。

每個分類各自保有自己的模型、語音與生成設定。不過，新的 API 金鑰會影響所有使用該設定檔的功能，因此更換金鑰後請測試這些功能。

服務供應商在各分類提供的內容並不相同。能用於 AI 聊天的登入，不代表也包含該服務供應商的即時語音 API。若某個分類只接受 API 金鑰，其頁面會說明，並指出訂閱可用於哪些分類。

## 查看方案用量

訂閱登入會顯示你的帳號與方案剩餘的額度。**% 剩餘** 這類數值代表你剩下的額度。開啟帳號卡片的選單，選擇 **重新整理用量** 來更新，或選擇 **重新連線** 重新登入。

當 Claude 或 Codex 提供你免費的額度重設時，Claude 或 ChatGPT 訂閱卡片會顯示 **免費額度重設**：你有幾次，以及到何時為止。點按 **使用重置** 並確認，即可補滿你的額度。若有多次，卡片會列出它們，並使用你所選的那一次。

沒有顯示用量，並不表示你的用量沒有上限。

## 管理你的憑證

開啟 **設定 → 憑證管理**。清單會依服務供應商設定檔將憑證分組，然後顯示 **未使用的金鑰**：沒有任何服務供應商在使用的金鑰。

- 在 **搜尋供應商** 中輸入文字即可找到特定項目。
- 點按 **新增憑證**，為你選擇的服務建立另一組憑證。
- 若要刪除憑證，將游標移到它上方並點按垃圾桶圖示。如果某個使用該金鑰的 API 金鑰連接器正在使用它，確認視窗會指出該連接器，**刪除並中斷連線** 會中斷其連線，直到你給它另一組金鑰。
- 點按清單底部的 **清理**，可一次刪除所有未使用的金鑰。按鈕會顯示數量，確認視窗會先列出這些金鑰。Enconvo 不會自行刪除未使用的金鑰。

點按某個憑證即可新增或變更其金鑰。**使用方** 會列出依賴它的功能，例如 **AI 模型** 或 **文字轉語音**；點按其中一項即可開啟該設定頁面。

服務供應商設定檔自己的憑證在這裡沒有刪除按鈕，它們會在你刪除該服務供應商時一併移除。

若你有以下項目，還會出現另外兩個群組：**其他服務**，用於 Enconvo 沒有對應服務供應商之服務的金鑰；以及 **登入資訊**，用於你儲存的網站與 App 登入。

## 當代理程式需要金鑰時

當任務需要某項服務的 API 金鑰時，代理程式會在聊天中顯示 **連接** 卡片，而不是要求你貼上金鑰。金鑰會存入憑證管理，而不是對話中，之後的聊天會直接使用，不必再詢問。

對於 Enconvo 沒有對應服務供應商的服務，卡片會顯示金鑰將被傳送到的主機。金鑰會儲存在 **其他服務** 下，代理程式只能在傳送給該主機的請求中使用它。

代理程式本身從不持有金鑰：它只指名已儲存的憑證，而在請求或指令原本會顯示金鑰的地方，只會顯示 `[redacted]`。

在手機聊天中，**連接** 卡片會顯示在你的 iPhone 上，金鑰則儲存在你 Mac 的憑證管理中。在即時通訊聊天中，代理程式絕不會索取金鑰；它會改為傳送一個連結，在 Enconvo 中開啟該聊天。

如果你還是把 API 金鑰貼進訊息，Enconvo 會將它儲存到憑證管理，並在已儲存的聊天中以 `[redacted]` 取代，因此之後的請求與你的其他裝置都不會帶有它。你為已有金鑰的服務貼上新金鑰時，會取代已儲存的金鑰。

## 網站與 App 登入

當瀏覽器任務遇到登入頁面時，卡片會一次詢問使用者名稱與密碼。Enconvo 只會在該網站填入，代理程式不會看到密碼。已儲存的登入資訊會顯示在 **登入資訊** 下。取消勾選 **記住這組登入資訊**，就只會用於這一次登入。

當 Mac App 的登入需要密碼時，卡片會指出該 App。Enconvo 只會將使用者名稱與密碼輸入到該 App 中，而且密碼只會輸入到會隱藏輸入內容的欄位。

## 自訂端點

**相容 OpenAI** 與 **相容 Anthropic** 服務供應商有一個 API 基礎 URL 欄位，可填入你自己的伺服器。部分內建服務供應商會將其端點設定放在 **憑證管理** 中。若要連接另一台電腦上的模型伺服器，請參閱[本機模型](/zh-hant/ai/local-llm)。

只有 Enconvo 自己的視窗能變更已儲存金鑰的傳送目的地：服務供應商或憑證的位址，或 MCP 伺服器對已儲存金鑰的使用。其他使用 Local API 的程式、手機與代理程式都會被拒絕。

## 金鑰如何保存

- 每個已儲存的金鑰與登入，都以保存在這台 Mac 鑰匙圈中的金鑰加密，因此複製 Enconvo 的設定資料夾後無法在另一台電腦上讀取。如果你退回較舊版本的 Enconvo，需要重新輸入金鑰。
- 其他程式向 Enconvo 的 [Local API](/zh-hant/advanced/cli-local-api) 索取設定時，每個金鑰都會以 `[hidden]` 取代。來自商店的外掛程式只能使用它自己的金鑰，以及在其設定中選取的憑證。
- 只有由 Enconvo 安裝且未被更動的程式碼才能開啟已儲存的金鑰。設定仍會如以往般顯示並檢查金鑰。

## 疑難排解

| 問題 | 處理方式 |
| --- | --- |
| 驗證失敗 | 檢查所選的設定檔、身分驗證方式、端點，以及你的服務供應商帳號是否有存取權限。 |
| 一個功能正常，另一個失敗 | 檢查該帳號是否支援該功能與模型。若某個分類只接受 API 金鑰，頁面會加以說明。 |
| 更換金鑰後某些功能停止運作 | 設定檔是共用的。請測試其他使用它的分類。 |
| 用量區域顯示 **重新連線** | 登入已過期。點按 **重新連線** 並重新登入。 |
