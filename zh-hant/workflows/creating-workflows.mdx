本指南涵蓋你在工作流程編輯器中的所有操作：建立工作流程、在畫布或 YAML 中建置、讓助手編輯、執行並檢視結果。最後幾節提供檔案格式與各步驟類型的參考說明。

要開啟編輯器，請在聊天視窗側邊欄選擇 **工作流程**，或打開 **設定 → 工作流程 → 管理**。接著選擇 **新增工作流程**，或點選 **編輯** 開啟現有的工作流程。在聊天視窗中切換到某個對話再切回來時，你正在編輯的工作流程仍會保持開啟。

本頁依序介紹：

- 入門：[核心概念](#核心概念)、[工作流程列表](#管理你的工作流程)與[建立新工作流程](#建立新工作流程)。
- 建置：[視覺化編輯器](#用視覺化編輯器建置)、[步驟行為](#步驟行為)與[編輯助手](#使用編輯助手)。
- 執行：[執行工作流程並檢視結果](#執行與檢查)。
- 參考：[YAML 檔案](#編輯-yaml)、[讀取先前結果](#引用先前的結果)與[所有步驟類型](#步驟類型)。

## 核心概念

- 工作流程會先宣告它的 **輸入**，接著是一個或多個各自包含有序步驟列表的工作。概覽請參閱[工作流程](/zh-hant/workflows/introduction)。
- 同一工作中的步驟會由上而下依序執行。各個工作會同時平行執行，除非其中一個需要等待另一個完成。
- 步驟使用 `{{ }}` 範本讀取執行輸入與先前結果，例如 `{{ inputs.topic }}` 或 `{{ steps.fetch.output }}`。
- 編輯工作流程與執行工作流程是分開的操作。儲存只會寫入檔案；執行才會實際呼叫模型與工具。

## 管理你的工作流程

你可以在工作流程列表中開啟、執行、排序、搜尋和刪除工作流程。

### 工作流程列表

每一列都會顯示工作流程的步驟數、上次編輯時間，以及上次執行的結果。

- 點選上次執行的結果，即可開啟工作流程並在畫布上顯示該次執行的輸出。
- 點選播放按鈕，即可開啟工作流程並立即執行。如果它需要你尚未填寫的輸入，會先開啟 **輸入** 面板。工作流程執行期間，播放按鈕會變成停止按鈕；點選它即可在不開啟工作流程的情況下停止執行。
- 按排程執行的工作流程會顯示下次執行時間；若其所有自動化排程都已關閉，則顯示 **排程已暫停**。點選它即可開啟工作流程，並在執行記錄面板中檢視其排程。
- 點選複製按鈕，即可用新標題複製一個工作流程，方便你在不動到原始版本的同時修改副本。列表會自動捲動到該副本並將其醒目提示。
- 使用列表上方的排序選單，依 **最近編輯**、**最近執行** 或 **名稱** 排序工作流程。系統會記住你的選擇。

當你回到列表時，以及排程執行開始時，列表都會自動更新。

### 尋找工作流程

在 **搜尋工作流程** 中輸入關鍵字，列表會隨你的輸入即時更新。點選清除按鈕或按 Esc 即可再次顯示所有工作流程。

點選任一列上的標籤，即可只顯示帶有該標籤的工作流程；此功能可與 **搜尋工作流程** 搭配使用。每一列最多顯示四個標籤；點選 **+N** 可查看其餘標籤。若要再次顯示所有工作流程，請再點選一次該標籤、點選列表上方標籤旁的 ×，或在 **搜尋工作流程** 中按 Esc。

| 按鍵 | 在工作流程列表中的操作 |
| --- | --- |
| **⌘F** 或 **/** | 跳至 **搜尋工作流程** |
| 在 **搜尋工作流程** 中按 ↓ | 前往第一個工作流程 |
| ↑ 與 ↓ | 在工作流程之間移動 |
| Return | 開啟選取的工作流程 |
| Delete | 刪除選取的工作流程 |

### 重新命名或刪除工作流程

要重新命名工作流程，請點選編輯器頂端的名稱、輸入新名稱，然後按 Return。按 Esc 則保留原名稱。

如果工作流程正在執行，刪除工作流程會先停止執行。負責執行它的[排程工作](/zh-hant/workflows/scheduled-jobs)會改為暫停並保留下來，讓你可以為它們指定其他工作流程或將其刪除。刪除前，確認視窗會顯示受影響的排程數量。

## 建立新工作流程

點選 **新增工作流程** 會開啟對話方塊，提供以下幾種開始方式。請先選擇工作流程的類型：

- **任務工作流程**：完成單一類型任務的流程。
- **團隊工作流程**：由多位成員協作、將目標從規劃推進到完成的流程。範本包含 **規劃、建置、審查** 與 **單一成員**。

如果你還沒有任何工作流程，工作流程列表會直接在畫面上提供相同的開始方式：**描述它應該做什麼**、**空白工作流程**，以及各種範本。

| 開始方式 | 操作方法 |
| --- | --- |
| 描述需求 | 寫下工作流程應該完成什麼任務，例如「同時將一段文字翻譯成日文和西班牙文」，然後點選 **開始建立**（或按 **⌘↩**）。工作流程會開啟，且助手已著手為你建置。檢查步驟無誤後，點選 **儲存**。 |
| 從範本開始 | 選擇 **空白**、**研究主題**、**摘要網頁內容**、**YouTube 影片筆記**、**撰寫並朗讀** 或 **步驟類型導覽**（包含 Shell 指令、工具、提示詞與代理程式，以及兩個平行執行的工作）。每個範本都是可直接執行的完整工作流程。 |
| 匯入檔案 | 點選 **選擇檔案…**，或將 `.yaml`、`.yml` 或 `.json` 工作流程檔案（例如團隊夥伴分享的檔案）拖放到對話方塊任一處。它會存成新的工作流程，絕不會覆蓋你現有的檔案。若標題與列表中的項目重複，會以副本形式命名，例如「News copy」。如果檔案不是有效的工作流程，對話方塊會保持開啟並說明原因。 |
| 直接貼上 | 將工作流程的 YAML 或 JSON（例如在聊天中分享的內容）貼入描述框。**開始建立** 會變成 **匯入**，並依貼上的內容原樣建立工作流程。 |

### 內建工作流程

Enconvo 隨附的工作流程開啟時為唯讀。若要修改，請點選 **建立副本**，再編輯副本。

### 分享工作流程

若要分享工作流程或留存副本，請點選工作流程列表中該列上的分享按鈕（下載圖示），或在編輯器工具列中選擇：

- **匯出為 YAML 檔案…** 會將 `.yaml` 檔案儲存到你選擇的位置。在任何 Mac 上都可以透過 **新增工作流程** > **選擇檔案…** 匯入。
- **複製 YAML** 會複製工作流程內容，方便直接貼到聊天室，或貼進 **新增工作流程** 的描述框進行匯入。

從編輯器使用這兩個選項時，尚未儲存的變更也會一併包含在內。

## 用視覺化編輯器建置

</Frame>

編輯器提供兩種方式檢視同一個工作流程：

- **視覺化**：將步驟顯示為畫布上的卡片，平行工作會並排呈現。
- **步驟**：由上而下條列所有步驟及其條件、重複與平行步驟。使用兩個步驟之間的 **新增** 選單即可在該處插入步驟。

點選標題列中的 **指南**，即可用你的語言閱讀工作流程的白話說明。

1. 在編輯器工具列選擇 **視覺化**。
2. 使用節點之間的 **在此加入步驟** 插入步驟，或點選 **加入平行工作** 建立獨立分支。步驟列表最上方會顯示 **最近使用**，列出你最近選取過的幾個步驟與工具，讓你一鍵就能加入常用項目。擁有多個工具的外掛程式會先列出前八個；點選 **顯示另外 N 個** 可查看其餘工具，或直接輸入搜尋。
3. 點選任一步驟即可開啟其檢查器。你可以編輯它的 ID、標題與執行器設定，並展開 **行為** 來調整它的執行方式。
4. 點選 **輸入** 節點可設定工作流程宣告的輸入：名稱、類型（文字、數字、真/假、列表或物件）、說明、預設值，以及執行時是否必填。在每個名稱下方，面板會顯示步驟如何讀取該輸入（例如 `{{ inputs.topic }}`）以及有多少個步驟使用它。重新命名輸入時，這些步驟也會自動更新為新名稱。名稱可使用字母、數字與底線，不能以數字開頭，也不能與其他輸入重複。
5. 編輯時可隨時檢視流程圖並使用 **復原** 或 **重做**。
6. 檢查修改無誤後，點選 **儲存**。

### 閱讀步驟卡片

每張步驟卡片都會顯示步驟名稱，其下方則顯示該步驟的動作：工具或步驟類型，接著是主要設定的開頭，例如 *網頁搜尋 · ‹topic› news* 或提示詞的前幾個字。從輸入與先前步驟讀取的值會以 ‹ › 依名稱標示。未命名的步驟會以文字顯示其 ID；將滑鼠游標移到卡片上即可查看其 ID。

工具步驟的卡片會顯示所屬外掛程式的圖示。卡片上的小標記代表該步驟的執行方式：僅在條件為真時執行、針對列表中的每個項目各執行一次、重複執行、失敗時重試、即使前面步驟失敗仍繼續執行，或允許工作流程在該步驟失敗後繼續。將游標移到標記上可查看說明；你可在步驟的 **行為** 區塊更改這些設定。

### 選擇步驟

步驟選擇器會搜尋內建步驟、已安裝的工具以及 MCP 工具。它會排除僅用於開啟 Enconvo 視窗或列出服務供應商模型與聲音的工具；不過工作流程仍可在 YAML 中依名稱呼叫這些工具。

如果不確定該選哪一個，請輸入該步驟應該完成的任務（例如「將文章摘要為三個重點」），然後點選選擇器底部的 **請助手加入**（**⌘↩**）。當沒有符合的結果時，按 Return 也會執行相同操作。助手會將步驟精準加在你開啟選擇器的位置（相鄰步驟之前、之後，或作為新的平行工作），而且你可以像復原其他助手回覆一樣還原這次變更。

### 編輯步驟

檢查器有 **設定** 與 **輸出** 兩個分頁。點選 **執行步驟** 會執行所選的步驟，這可能會實際呼叫工具或執行 Shell 指令。單獨執行某個步驟前，請先確認所需的上游數值都已備妥。

**設定** 分頁的開頭是步驟卡片上顯示的 **名稱**，以及供其他步驟讀取其結果的 **步驟 ID**。**執行內容** 則標明該步驟的工具或類型。

若要讓該步驟改做其他事，請點選 **變更** 並選擇另一個工具或步驟類型，或描述希望它執行的任務並點選 **請助手修改**：

- 步驟會保留原本的 ID，因此讀取其結果的後續步驟依然能正常運作。
- 它會保留原本的執行時機與方式：包含條件、重複、重試與等待對象。
- 新工具的設定會以空白開始。由提示詞轉換為代理程式，或由代理程式轉換為提示詞時，會保留文字內容、模型與輸出結構描述。
- 若步驟原本使用編輯器自動產生的名稱，名稱會隨新工具更新；若為你自行填寫的名稱，則會保留。

點選 **復原** 即可回到上一步。

### 複製、重新排序或關閉步驟

若要重複使用某個步驟，請在檢查器中點選 **複製**，或將滑鼠移到步驟卡片上點選複製圖示。副本會保留原步驟的所有設定、出現在原步驟正後方，並自動取得下一個可用的 ID，例如 `fetch_2`。

工作中的步驟會由上而下執行。若要調整順序，可在所屬工作內上下拖曳步驟卡片，其他卡片會自動讓開以顯示放置位置。你也可以選取步驟後在檢查器選擇 **上移** 或 **下移**，或按 **⌥↑**、**⌥↓**。按 **⌘Z** 可復原移動。如果某個步驟被移到它所讀取結果的步驟上方，卡片上會顯示警告，直到你將它移回下方為止。

若想暫時略過某個步驟而不刪除它，請選取該步驟並選擇 **關閉步驟**。卡片會變淡並顯示 **關閉**，執行時會跳過它，而後續步驟仍會照常執行。選擇 **開啟步驟** 即可恢復。

### 同時處理多個步驟

若要一次變更多個步驟，請按住 ⌘ 或 Shift 並點選它們的卡片。畫布上方會出現一條工具列，顯示已選取的步驟數量，並提供針對這些步驟全部套用的 **關閉**（或 **開啟**）與 **刪除** 按鈕。按 Esc 或點選畫布空白處可取消選取，按 **⌘Z** 可復原操作。

如果刪除操作會破壞其他步驟，或讓某個工作變成空白，Enconvo 會先詢問確認。確認視窗會列出所有依賴被刪除步驟的其他步驟及其原因，例如 **使用其輸出** 或 **等待其完成**。點選其中一項即可取消刪除並開啟該步驟，方便你先進行修正。刪除單一步驟時也是如此。

要複製步驟，請選取一個（或多個）步驟並按 **⌘C**，或點選工具列中的 **複製**；**⌘X** 則會剪下它們。接著選取要接續的步驟並按 **⌘V**：

- 副本會落在該步驟正後方（若選取的是工作，則落在該工作末端），並保留所有設定。
- 若副本的 ID 已被使用，系統會自動產生新 ID（例如 `fetch_2`），而貼上且彼此相依的步驟也會自動跟隨新名稱。
- 步驟也能以相同方式貼到另一個工作流程中；此外，**⌘V** 也支援直接貼上從工作流程檔案複製的 YAML 或 JSON 步驟列表。

刪除或貼上步驟時，畫面上會出現一則通知說明變更內容；點選通知中的「復原」即可還原該次操作。

### 尋找、縮放、儲存與執行

- 要在大型工作流程中快速跳至某個步驟，請按 **⌘F** 或點選畫布上的搜尋按鈕，輸入步驟名稱、ID、工具或文字的一部分後選取即可。該步驟會被選取並捲動到畫面中。
- 使用畫布右下角的縮放控制項。點選縮放比例即可回到 100%。
- 點選 **尋找步驟**，或在畫布上按 **⌘F**，輸入步驟名稱的一部分即可選取該步驟並捲動至視野內。此功能在唯讀的內建工作流程中同樣有效。
- 在編輯器任何位置（無論在視覺化或 YAML 檢視中，甚至是在步驟設定欄位輸入文字時），按 **⌘S** 都能儲存。
- 按 **⌘↩** 即可執行工作流程；若有未儲存的變更，會先自動儲存。在 YAML 編輯器、助手以及其他多行輸入欄位中，請改為點選 **執行**。
- 執行期間，**執行** 會變成 **停止**。點選後會顯示 **正在停止…**，直到執行完全中止。

如果工作流程有問題（例如某個步驟的提示詞為空或缺少說明），「儲存」與「執行」會停下來並指出需要修正的地方。點選 **顯示** 即可開啟該步驟，或開啟工作流程的標題與說明。有問題的步驟卡片上會出現紅色標記；將游標移上去即可查看錯誤原因。在 YAML 中，點選 **驗證** 可檢查整份文件。

### 未儲存的變更

當工作流程有尚未儲存的變更時，編輯器標題列會顯示 **未儲存**。點選它可檢視自上次儲存以來新增與移除的 YAML 行數，點選 **捨棄修改** 則會回到已儲存的版本；在視覺化編輯器中，按 **⌘Z** 可恢復你的修改。如果帶著未儲存的變更返回工作流程列表，請選擇 **儲存並離開**、**捨棄** 或 **繼續編輯**。

編輯期間，未儲存的變更也會暫存在這台 Mac 上。如果你在儲存前關閉或重新載入視窗，重新開啟該工作流程時，頂端會出現橫幅提供 **還原**（以單一步驟還原你的變更，且支援復原）或 **捨棄**。只有當已儲存的工作流程自那之後未曾變動過，系統才會提供還原選項。在工作流程列表中，這類工作流程會顯示 **有未儲存的變更** 標籤，刪除該工作流程時也會一併捨棄這些變更。

| 快速鍵 | 功能 |

| **⌘S** | 儲存 |
| **⌘↩** | 執行（會先儲存） |
| **⌘F** | 尋找步驟 |
| **⌘Z** | 復原 |
| **⌘C**、**⌘X**、**⌘V** | 複製、剪下與貼上步驟 |
| **⌘A** | 選取所有步驟 |
| **⌫** | 刪除所選步驟 |
| **⌥↑**、**⌥↓** | 上移或下移選取的步驟 |
| **⌘=**、**⌘-** | 放大與縮小 |
| **⌘0** | 縮放至檢視整個工作流程 |
| **?** | 顯示所有畫布快速鍵 |

你也可以點選 **加入平行工作** 旁的鍵盤按鈕查看所有畫布快速鍵。

## 步驟行為

檢查器中的 **行為** 區塊讓你在不編輯 YAML 的情況下設定步驟的執行方式。區塊標題會列出已變更的項目，例如 *僅當… · 重試 2×*，未修改時則顯示 **預設**。

| 設定 | 選項 | 寫入的 YAML |
|---|---|---|
| **執行條件** | 每次都執行；僅在條件為真時執行；否則（當前面步驟的條件為假時執行）。**即使先前步驟失敗或被跳過仍執行** 可讓步驟在上游失敗後依然執行。 | `if`、`else_of`、`run_when` |
| **重複方式** | 執行一次；針對列表中的每個項目執行一次；依輪次迴圈執行直到達成條件，最多不超過指定輪數 | `foreach`、`loop` |
| **失敗處理** | 停止工作流程，或繼續執行讓後續步驟照常運作。**重試** 會在判定失敗前重新執行該步驟，可選擇在兩次嘗試之間加上等待時間。 | `required: false`、`retries` |
| **等待對象** | 上一個步驟；不等待，立即開始；或從先前步驟及其他工作的步驟列表中勾選要等待的步驟 | `needs` |

**輸出結構描述** 可選擇填寫 JSON Schema 以取得結構化結果。若重新選回預設值，該設定就會從 YAML 中移除。[進階工作流程](/zh-hant/workflows/advanced-workflows)有各項設定的詳細說明。

## 使用編輯助手

點選編輯器工具列中的 **助手**，在畫布旁開啟助手面板，接著描述你的需求，例如：「新增一個提示詞步驟，摘要上一個步驟的結果。」對於全新的空白工作流程，你也可以直接描述整個流程，例如：「每天早上擷取 Hacker News 熱門文章並進行摘要。」按 Return 傳送、**⇧↩** 換行，並可在輸入框下方選擇模型。

助手作業期間，面板會顯示它正在執行的動作（例如讀取工作流程、檢查工具參數或編輯），畫布也會即時更新。在回覆完成前，畫布會維持唯讀；點選 **停止** 可提前結束。

### 作業期間繼續發送指令

你不必等到助手回覆完畢才提出下一步要求。當助手仍在作業時按 Return，你的訊息會進入輸入框上方的佇列等待。每則回覆結束後，佇列中的訊息會依序逐一送出。

- 拖曳佇列中的訊息可調整順序，使用 **⋯** 選單可編輯訊息，點選垃圾桶圖示則可移除。
- 如果你點選 **停止** 或回覆失敗，佇列會標記為 **已暫停**，不會自動繼續送出。準備好時，請在佇列訊息上點選 **傳送**。
- 當有急著處理的訊息（例如修正助手目前正在做的事），請改按 **⌘↩**（取代 Return），或在佇列訊息上點選 **立即傳送**。目前的回覆會立即停止、保留已完成的編輯並標記為 **已中斷**，而你的訊息會立刻送出。佇列中的其餘訊息不會暫停，會接著依序送出。

### 檢視變更內容

每次修改工作流程的回覆結尾都會附上一張卡片，列出新增、變更或移除的步驟。回覆完成後，畫布上新增的步驟會標記為 **已新增**，修改的步驟會標記為 **已編輯**，方便你一眼看出需要審查的項目。這些標籤會保留到你儲存、復原或還原該回覆為止。

- 點選卡片上的步驟，即可在畫布上選取它並捲動到畫面中。助手在回覆中提到的步驟 ID（例如 `summarize`）也支援同樣操作。
- 點選回覆卡片上的 **執行**，即可測試助手剛做好的變更。它的執行方式與工具列上的 **執行** 相同，需要輸入時會先詢問。
- 點選最新卡片上的 **還原**，即可將工作流程恢復到該次回覆前的狀態。**復原**（**⌘Z**）也能一步還原整則回覆的變更。

如果回覆導致工作流程無效，編輯器會切換至 YAML 檢視並顯示錯誤。你可以直接在 YAML 中修正，或請助手幫忙修復。在你點選 **儲存** 之前，助手的編輯都不會儲存。

### 指定特定步驟或結果

- 若要針對單一步驟提問，請在畫布上選取該步驟，並在檢查器中選擇 **詢問助手**。該步驟會附加到你的下一則訊息中，因此說「讓這一步更可靠」就是指這個步驟。
- 當某個步驟在執行時失敗，請在執行摘要或該步驟的 **輸出** 分頁選擇 **使用助手修復**。你的訊息會自動帶上該步驟與錯誤內容，不必手動複製貼上。
- 若要詢問步驟結果中的某一段內容，請在 **輸出** 分頁選取文字，並點選選取範圍下方的 **詢問助手**。該段文字會以引文形式出現在輸入框上方，並隨你的下一則訊息一起送出，方便你詢問它的含義或該如何調整產生它的步驟。

### 對話紀錄與常駐指示

點選面板頂端的 **新對話** 即可重新開始；先前的對話仍會保留在列表中。點選面板頂端的對話名稱，即可切回同一個工作流程的舊對話，或刪除不需要的對話。已儲存的工作流程會在此瀏覽器中保留最近十筆對話。

若要設定助手每次都應遵守的預設規範，請點選面板頂端的 **設定**（滑桿圖示），在 **指示** 下方填寫內容，例如「將檔案儲存至 ~/Downloads。」、「提示詞步驟使用 anthropic/claude-haiku-4-5。」或「使用繁體中文回覆。」。按 **⌘↩** 或點選 **儲存**。這些指示會套用到助手建置或編輯的每個工作流程，設定圖示上會出現一個小圓點代表指示啟用中。若要停用，清除內容並儲存即可。

## 執行與檢查

1. 點選 **輸入** 並填寫本次執行的數值。
2. 驗證工作流程定義並檢查所有指令或工具呼叫。
3. 點選 **執行** 並在流程圖中觀察各步驟狀態。
4. 點選任一步驟的 **輸出** 分頁來檢查其結果或錯誤。執行結束後，每張步驟卡片原本顯示說明的位置，也會改為顯示該步驟回傳結果的第一行或失敗原因；點選該行即可開啟該步驟的 **輸出** 分頁。在 **輸出** 分頁點選 **複製** 可複製步驟結果（若無回傳結果，則複製其錯誤訊息），方便貼到聊天或文件中。
5. 開啟 **執行記錄** 查看先前的執行紀錄。
6. 確認工作流程定義無誤後，儲存工作流程。

<Warning>
視步驟內容而定，執行工作流程可能會消耗服務供應商額度或修改外部資料。Shell 與工具步驟會以你 Mac 帳號的權限運作，請務必留意。
</Warning>

### 執行輸入

工具列上的 **輸入** 會開啟一張表單，為工作流程宣告的每個輸入提供一個欄位，並顯示其類型、說明與預設值：

- 欄位留空即會使用預設值。列表與物件類型請輸入 JSON，例如 `["a", "b"]`。
- 標記為 **必填** 且沒有預設值的輸入必須填寫數值。如果為空或數值類型不符，**執行** 會在儲存或執行任何步驟前先行停止，並指出需要修正的欄位。
- 在欄位中按 **⌘↩** 即可執行。
- 表單會帶入該工作流程上次在 Enconvo 執行時使用的數值。點選 **清除** 可一次清空所有欄位，讓下次執行重新使用預設值。重新命名輸入時，會保留你原先為它填寫的值。
- 當畫布上正顯示來自 **最近執行** 的舊紀錄時，點選 **使用該次執行的數值** 即可將表單填入那次執行的輸入，接著原樣重跑或微調後再執行。
- 空白欄位會以灰色顯示預設值。如果想修改較長的預設值而不是重打一遍，請點選欄位旁的 **編輯預設值** 將預設值填入欄位，然後再編輯。
- 在視覺化編輯器中，點選 **編輯輸入** 可更改工作流程要求的輸入項目。若仍有步驟讀取你準備移除的輸入，Enconvo 會列出這些步驟名稱並在移除前詢問確認。點選 **以 JSON 編輯** 可將所有輸入當成單一 JSON 物件填寫，包含工作流程未宣告的鍵值。點選 **使用表單** 可切回表單模式。

### 執行結束時

執行結束後，畫布底部會出現執行摘要：

- 如果有步驟失敗，摘要會指出該步驟，並顯示說明出錯原因的那一行錯誤訊息（例如 `command not found: datex`，而不只是結束代碼）。點選 **顯示錯誤** 即可開啟該步驟的 **輸出** 分頁，並將該步驟捲動到畫面中。
- 點選 **使用助手修復** 可將失敗步驟與錯誤交給助手處理。助手會先說明原因，接著修復該步驟。如果問題出在工作流程之外（例如缺少 API 金鑰、網路錯誤或找不到檔案），助手會告訴你該調整什麼，而不會亂改流程。失敗步驟的 **輸出** 分頁中也有相同的 **使用助手修復** 按鈕。
- 點選 **繼續** 可接續執行失敗或中止的執行紀錄。已完成的步驟會保留其結果；失敗步驟與其後的步驟會重新執行。如果你在執行後修改了某個步驟，該步驟與其後的步驟也會重新執行。如果你更改了執行輸入，整個工作流程會從頭開始執行。在下次執行開始前，工具列上的 **執行** 旁也會顯示 **繼續**。
- 成功執行結束後，點選 **顯示輸出** 可查看最後一個步驟的結果。除非有項目需要你處理，否則摘要會在幾秒後自動淡出；點選 **×** 可提早關閉。

### 最近執行

**最近執行** 會列出工作流程先前的執行紀錄，最新的排在最前面。每一列顯示：

- 該次執行成功、失敗或仍在執行中；
- 開始時間與花費時間；
- 是否由排程（**排程**）或對話（**來自對話**）啟動；
- 執行時使用的輸入（滑鼠移上去可查看完整內容），以及失敗時的錯誤訊息。

目前顯示在畫布上的紀錄會標記為 **顯示中**。點選任一列即可在畫布上顯示該次執行的步驟結果。當部分紀錄成功、部分失敗時，點選列表上方的 **失敗** 可只看失敗的紀錄，點選 **所有執行** 則顯示全部紀錄。

### 排程執行

執行記錄面板頂端的 **排程** 會列出執行此工作流程的排程工作，並顯示各排程的下次執行時間與使用的輸入。

- 當某個排程的上次執行失敗時，將滑鼠移到 **上次執行失敗** 上可查看原因，或點選它直接在畫布上開啟該次執行以查看是哪個步驟出錯。
- 使用開關來開啟或關閉排程工作，或點選鉛筆圖示修改排程時間。
- 選擇 **新增定時** 可直接在該處開啟表單，系統會自動選好這個工作流程，並從 **執行輸入** 帶入輸入值。
- 在排程上點選 **刪除** 可移除該排程工作。

排程執行會使用已儲存的工作流程，因此請在下次排程開始前先儲存你的變更。所有排程工作也會列在聊天視窗側邊欄的 **排程工作** 中；請參閱[排程工作](/zh-hant/workflows/scheduled-jobs)。

## 編輯 YAML

儲存時，工作流程會寫入 `~/.enconvo/workflows/<id>.yaml`。點選 **YAML** 即可用原始碼方式編輯同一份文件。編輯器會邊打字邊檢查：錯誤會標明行號與欄號，警告則會標出沒有作用的欄位。**有效** 或 **無效** 徽章與 **驗證** 操作可檢查整份文件。工作與步驟 ID 請使用字母、數字與底線，並以字母或底線開頭。切回 **視覺化** 時，按 **⌘Z** 可一次復原你在 YAML 中做的修改。

```yaml
version: agent-workflow/v1
title: Greeting
description: Produce a greeting and a formatted result without calling a model.
inputs:
  name:
    type: string
    default: world
jobs:
  main:
    steps:
      - id: greeting
        uses: transform
        value: "Hello, {{ inputs.name }}!"
      - id: result
        uses: transform
        value: "Result: {{ steps.greeting.output }}"
```

在 **輸入** 下的 **name** 欄位填入 `Ada` 並執行此範例，最後一個步驟會輸出 `Result: Hello, Ada!`。

## 引用先前的結果

| 運算式 | 值 |
| --- | --- |
| `{{ inputs.name }}` | 輸入值 |
| `{{ steps.greeting.output }}` | 同一工作中先前步驟的輸出 |
| `{{ jobs.research.search.output }}` | 另一個工作中已完成步驟的輸出 |
| `{{ item }}` 與 `{{ index }}` | `foreach` 迴圈中目前的項目與索引 |
| `{{ round }}` 與 `{{ last }}` | 迴圈中的目前輪次與上一輪輸出 |

讀取另一個工作的輸出前，請先在工作層級加上 `needs`。請在 **輸出** 分頁實際檢查工具結果，不要假設每個工具都回傳相同的欄位。

### 不必手動輸入即可插入值

在視覺化編輯器中，你不需要自己手打這些運算式。在步驟欄位右側（例如提示詞、指令、工具設定或條件）點選 **插入值**（`{x}` 按鈕），即可列出該步驟可讀取的項目：工作流程的輸入、所屬工作中先前步驟的結果、它所等待之工作的步驟，以及針對重複執行步驟的目前項目或輪次。搜尋列表並選取項目後，運算式會插入游標所在位置，或取代你選取的文字。

- Shell 步驟會提供 `{{ steps.<id>.stdout | trim }}` 作為列印出的文字。
- 設有輸出結構描述或已有執行紀錄的步驟，還會列出其結果欄位。
- 條件、**停止條件** 以及步驟重複執行的列表欄位會自動帶入適合該欄位的格式，例如條件欄位中的純 `steps.check.output.ok`。

如果欄位讀取了無法存取的項目，下方會顯示警告說明需要修正之處：例如工作流程未宣告的輸入、執行順序在後面的步驟或步驟本身、屬於其他工作的步驟，或是此工作並未等待的工作。在畫布上，含有這類數值的步驟卡片標題旁會出現警告圖示；將游標移上去即可查看要修正什麼。警告不會阻擋儲存。

## 步驟類型

下方每個片段都是一個步驟項目：請放在工作的 `steps` 列表中。在視覺化編輯器中，可從步驟選擇器挑選相同的步驟類型。

### Shell

```yaml
- id: today
  command: 'date "+%Y-%m-%d"'
```

透過 `steps.today.output.stdout` 讀取結果。選用設定包含 `cwd`、`shell`、`timeoutMs` 與 `env`。指令會以你 Mac 帳號的權限執行；執行前請先檢查指令內容。

### Prompt

```yaml
- id: summarize
  prompt: "Summarize this text: {{ inputs.text }}"
```

這會呼叫一次模型。當後續步驟需要結構化欄位時，請使用[輸出結構描述](/zh-hant/workflows/advanced-workflows)。

### Agent

```yaml
- id: plan
  agent: agent/main
  message: "Propose a three-step plan for {{ inputs.topic }}."
```

使用已安裝代理程式的指令金鑰（command key）。代理程式啟用的工具與服務供應商設定決定它能執行哪些操作。

### Tool

```yaml
- id: saved
  tool: workflow/list
  with:
    limit: 5
```

`tool` 是斜線格式的 Local API 路由。`with` 提供參數（`params` 為別名）。可在 **設定 → API** 中探索可用的路由，或請編輯助手檢查已安裝的工具。

### Transform

使用 `uses: transform` 搭配 `value`，即可在不呼叫模型的情況下組合輸入或先前步驟的輸出。[編輯 YAML](#編輯-yaml) 中的範例就使用了兩個 transform 步驟。

### Subworkflow

使用 `uses: workflow` 搭配已儲存的 `workflowId` 或內嵌的 `workflow` 文件，即可執行可重複使用的子流程。在視覺化編輯器中，依名稱選取已儲存的工作流程，並在表單中填入它要求的輸入。未選取工作流程的 Subworkflow 步驟不會通過驗證，且會停止執行並提示缺少什麼。請參閱[進階工作流程](/zh-hant/workflows/advanced-workflows)。

### Approval

```yaml
- id: confirm
  uses: approval
  message: "Post this summary to the team? {{ inputs.text }}"
```

Enconvo 會向你顯示 `message` 與 **核准**、**拒絕** 按鈕並等待你的回覆，除非步驟另有設定 `timeoutMs`，否則最長等待 24 小時。核准後，後續步驟就會繼續執行。若拒絕或逾時未回覆，該步驟會像條件為假一樣被略過：其後的步驟不會執行，而對應的 `else_of` 步驟會執行。`steps.confirm.output.feedback` 會保存你在拒絕時輸入的說明。建議將它放在傳送、發佈、刪除或付款等步驟之前。當你在拒絕後點選 **重試** 時，新一次執行會知道你先前拒絕了什麼以及原因。在子工作流程中拒絕核准會停止整個執行，而不只是停止子工作流程。

### Judge

```yaml
- id: urgent
  uses: judge
  question: Does this message ask for a reply today?
  input: "{{ inputs.text }}"
```

Jev（Enconvo Cloud 的快速決策模型）會針對 `input` 回答 `question`，並回傳 `yes` 與 `probability`。當機率達到 `threshold`（預設為 0.5，除非自行設定）時，`yes` 為真。可搭配 `if: "{{ steps.urgent.output.yes }}"` 與 `else_of` 步驟進行分支。

### Classify

```yaml
- id: kind
  uses: classify
  question: What kind of request is this?
  input: "{{ inputs.text }}"
  options:
    billing: A question about payments or invoices
    bug: A report that something is broken
    other: Anything else
```

在檢查器中為每個選項輸入一列。Jev 會從 `options` 中選出最符合的一項，並回傳其 `label`、`confidence`（信心度）以及每個選項的 `probabilities`。`options` 可以是至少兩個標籤的列表，或是每個標籤對應其含義的映射表。可透過 `if: "{{ steps.kind.output.label == 'billing' }}"` 進行分支。

Judge 與 Classify 步驟會在 Enconvo Cloud 上執行，因此需要登入帳號且剩餘足夠點數。這兩類步驟不接受 `output_schema`。
