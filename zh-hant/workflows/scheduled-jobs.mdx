排程工作會替你完成一項工作，而不必每次都由你啟動：它可以請 Agent 去做某件事、執行你儲存的某個工作流程，或執行 Shell 命令。它可以依排程執行（一次，或反覆執行）、在發生某件事時執行（例如收到新郵件或資料夾中出現檔案），也可以在你手動啟動時執行。可用於早晨新聞摘要、每週計畫或價格查詢。

每次執行都會開啟自己的對話，結果會顯示在排程工作中。你也可以讓 Enconvo 在 Mac 上通知你、將結果傳送到即時通訊聊天、在 GitHub 上回覆，或將聽到的內容加入專案的 Ideas 看板。

每個排程工作都由三個部分組成，你可以就地修改每一部分，也可以用自己的話來修改：

| 部分 | 內容 |
| --- | --- |
| **何時** | 排程、事件，或由你手動啟動 |
| **步驟** | 它要執行的 Agent 和指令、工作流程或 Shell 命令 |
| **然後** | 結果送到哪裡，以及你如何得知 |

它的執行記錄會以長條顯示在下方，讓你一眼就能看出哪些已執行、哪些失敗。

這部影片介紹排程工作，接著是工作流程、變數，以及如何透過通知和安靜時段得知結果。

## 透過聊天設定排程工作

<Steps>
  <Step title="開啟排程工作">
    在 **聊天視窗** 側邊欄中，選擇 **排程工作**，然後選擇 **新增排程工作**。
  </Step>
  <Step title="說明要做什麼以及何時做">
    在輸入框中描述任務及其時間，例如「每個工作日 8:00，用五個要點加連結向我簡報最重要的 AI 新聞。」或選擇其中一個範例，它會填入輸入框，讓你在傳送前調整。

    如果你有已儲存的工作流程，其中幾個會顯示在 **按排程執行工作流程** 之下。選擇一個，就會填入一個每天 9:00 執行該工作流程的請求，然後可在傳送前變更時間或加入輸入值。
  </Step>
  <Step title="檢查草稿">
    Enconvo 會設定好任務，在聊天中以卡片顯示，並用白話和你的當地時間回覆它何時執行。如果你沒有指定時間，它會挑選合理的時間並告訴你。只有在沒有答案任務就無法進行時，它才會提問，例如要監看哪項產品。
  </Step>
  <Step title="開啟">
    新的排程工作一開始是關閉的，並在聊天旁標示為 **草稿**。檢查後選擇 **開啟**；在此之前不會執行任何東西。任務會顯示在對話上方的 **在此聊天中設定** 之下，以及任務清單中。繼續聊天即可變更、暫停或繼續它。
  </Step>
</Steps>

<Frame caption="新任務從一句話或一個範例開始。">
  <img src="/images/guides/scheduled-tasks-new.jpg" alt="排程任務畫面，有輸入框和六個範例任務" />
</Frame>

請把任務寫成一則完整的指令。每次執行都會開啟全新的對話，看不到你設定它的那個聊天，因此「摘要今天最重要的 AI 新聞，用五個要點並附上連結」比「明天再做一次」更有效。

## 查看即將執行和已執行的內容

排程工作頂端的 **今天** 會顯示接下來要執行的內容，以及所有已經執行的內容，並附上每次執行的結果。選擇一次執行即可閱讀它，或讓失敗的執行再試一次。

每個排程工作的最新一次執行，也會在開始的那一刻以時鐘圖示顯示在側邊欄的 **聊天** 之下。它先前的執行只要點按一下，就能在該次執行的聊天中查看。

### 回到排程聊天

排程聊天會被保留，但不會顯示在側邊欄的 **聊天** 之下。若要回到其中一個，例如 Enconvo 正在等待你回答的聊天，請選擇對話上方的聊天名稱，並在 **排程聊天** 之下選擇它。你也可以在那裡刪除聊天；在其中設定的任務會繼續執行。

### 在任何聊天中詢問

你也可以在任何聊天中詢問，例如「明天 9 點提醒我寄發票」或「每週一早上，列出我這週的截止日期。」Agent 會設定同類型的任務、顯示它的卡片，並確認它何時執行。選擇卡片上的 **開啟**，即可在 **排程工作** 中查看。較舊聊天中的卡片會顯示該任務之後是否已被暫停、完成或刪除。

## 由事件或手動啟動

排程工作不一定要依時間啟動，也可以在某件事發生時啟動。在排程工作聊天中描述什麼應該啟動它，Enconvo 就會設定觸發條件。

| 什麼會啟動它 | 何時執行 |
| --- | --- |
| 排程 | 在你設定的時間 |
| 你，手動 | 當你選擇 **執行** 時，若你輸入了文字，就以該文字處理。開啟 **在 PopBar 中顯示**，即可對你選取的文字執行；或開啟 **顯示在動態島主頁**，在動態島上放一個按鈕。 |
| 資料夾變更 | 資料夾中每新增、變更或移除一個檔案 |
| App | 當 App 開啟、結束、移到前景，或在前景停留一段時間 |
| Discord 或 Telegram 訊息 | 已連接的機器人可讀取的每一則訊息 |
| 新郵件 | [電子郵件](/zh-hant/integrations/email)外掛程式中允許 Agent 讀取的信箱裡的每封新郵件（每分鐘檢查一次）、Apple 郵件（郵件開啟時每兩分鐘檢查一次），或透過 Gmail 連接器收到的 Gmail 新郵件（約每五分鐘一次） |
| GitHub | 當你連接的儲存庫中有 issue 或 pull request 被開啟、issue 被加上標籤、留言提到你、CI 失敗，或發布新版本時。請參閱 [GitHub 觸發條件](#github-觸發條件)。 |
| MCP 事件 | 已連接的 MCP 伺服器回報的每個事件 |
| 已轉錄的錄音 | Enconvo 完成轉錄的每一則錄音 |
| 網頁和摘要來源 | 每個新的摘要項目，或每次頁面文字變更時 |
| 複製 | 你每次複製的內容，在剪貼簿記錄沒有忽略的 App 中 |
| Mac 事件 | 當 Mac 喚醒、解鎖、接上或拔除電源，或當你離開或回到 Mac 時 |
| 行事曆事件 | 行事曆事件開始前，或結束時 |
| 會議 | 當 Zoom、Teams、FaceTime 或微信通話中的會議開始時 |
| 登入 | 每次登入後 Enconvo 啟動時一次 |
| Webhook 請求 | 每次有請求送到該排程工作專屬的位址時，位址會顯示在它的頁面上，並附有複製按鈕 |

Enconvo 在執行期間會監看你 Mac 上的事件。任務上觸發條件的那一列，會說明 Enconvo 關閉期間發生的事件如何處理。

### GitHub 觸發條件

<Steps>
  <Step title="連接 GitHub">
    在 **時間** 之下，選擇 GitHub，然後選擇 **連接 GitHub**。你需要登入你的 Enconvo 帳號。
  </Step>
  <Step title="選擇儲存庫和事件">
    選擇 **儲存庫**（或 **其他儲存庫…** 以自行輸入）和 **事件**。若是被加上標籤的 issue，請選擇 **標籤** 或 **任何標籤**。監看儲存庫需要它的管理員權限。
  </Step>
  <Step title="選擇誰可以啟動它">
    選擇 **僅我**、**任何人**，或加入 GitHub 使用者名稱，讓這些人的事件可以啟動它。
  </Step>
</Steps>

GitHub 事件會透過 Enconvo Cloud 送達你的 Mac，並在你於此允許外部觸發之前，一直對這台 Mac 保持封鎖：在它詢問時選擇 **在這台 Mac 上允許**。**在這台 Mac 上停用外部觸發** 會再次停止它們；事件接著會在 Enconvo Cloud 等候。

事件觸發也可以附上一個用你自己的話寫的條件。AI 會在執行前，依據該條件檢查每個事件；不符合的事件會被略過，你仍可對其選擇 **仍然執行**。每次檢查都是一次付費的 AI 呼叫。選擇 **用最近的事件試一下**，即可看到它對哪些最近的事件會執行，而不會真的執行任何東西。

## 管理排程工作

在清單中選擇一個排程工作，即可看到它是已啟用、已暫停還是需要處理，接著是它的 **時間**、**步驟** 和 **此時** 三個部分，以及它的執行記錄。

當最後一次執行失敗，或其結果未送出時，名稱下方會有一則說明原因的備註，並提供修復方式：

- **透過聊天修復**（Agent 或工作流程任務）會開啟該任務的聊天，並附上一則指出錯誤的修復請求，**再次執行** 則會再執行一次。
- **重新傳送** 會重試傳送結果，**變更結果儲存位置** 會開啟結果選擇器。在那裡選擇 **僅 Enconvo**，也會清除關於結果未送出的備註。
- 自行啟動的任務在連續失敗 5 次後會暫停。修好之後請選擇 **開啟**。

| 控制項 | 作用 |
| --- | --- |
| **立即執行** | 立刻執行一次任務。它是真的會執行，因此 Agent 可能會使用工具或點數。由你手動啟動的任務則是 **執行**。 |
| **隨聊天變更** | 對 Agent 任務，重新開啟設定該任務時所用的聊天（如果沒有，則開啟新的），讓你描述變更，例如「改到 7:30」或「加入天氣」。 |
| **任務名稱** | 選擇名稱即可重新命名任務。按 Return 儲存，或按 Esc 取消。 |
| **排程** | 顯示任務何時執行以及下次執行的時間。排程以白話顯示，例如 **每天 09:00 和 18:00** 或 **每年 1 月 1 日 03:00**，在清單、設定和聊天卡片中都相同。選擇它即可就地變更時間：選擇 **一次**、**每天**、**每週**、**每月**、**間隔** 或 **Cron**，檢查下次執行時間，然後選擇 **儲存**。旁邊的開關可以暫停之後的執行，而不會刪除任務。 |
| **指令** → **編輯** | 就地變更要求 Agent 做的事（Shell 命令任務則是命令）。按 **⌘↩** 或選擇 **儲存**；Esc 取消。 |
| **結果** | 顯示每次執行的結果送到哪裡。選擇它，然後挑選你曾透過即時通訊管道與 Agent 交談的聊天，或選擇 **僅 Enconvo** 讓結果保留在每次執行的對話中；變更會立即儲存。**另一個聊天…** 會開啟編輯器，讓你輸入聊天 ID。 |
| **執行時通知我** | 在執行完成時發出 Mac 通知，內容為結果的第一行。點按它即可開啟該任務。 |
| **…** → **編輯詳細資料** | 開啟表單編輯器，一次顯示所有欄位，包括 Agent、說明和最大執行次數。 |
| **…** → **複製** | 建立副本並以草稿開啟，讓你在開啟前先修改。 |
| **…** → **所有執行記錄** | 開啟完整的執行記錄，並提供篩選。 |
| **…** → **刪除** | 刪除排程工作及其執行記錄。刪除正在執行的排程工作，也會停止它的執行。 |

選擇一個執行長條，即可閱讀該次執行的結果或錯誤、在它的對話中從該處繼續、複製它，或在結果未送出時再次傳送結果。

### 進階設定

開啟排程工作的 **進階設定**，設定它可以做到什麼程度：

| 設定 | 作用 |
| --- | --- |
| **執行次數上限** | 它總共執行幾次。已完成的排程工作可以在這裡增加執行次數。 |
| **時間上限** | 單次執行可以花多久，從 15 分鐘到 8 小時。當執行達到上限時，該次執行會提供較長的上限（**允許 … 並再次執行**），讓你一鍵給它更多時間並再執行一次。 |

### 尋找排程工作

可依名稱、指令、命令或工作流程搜尋清單。清單將排程工作分為 **需要處理**（最後一次執行失敗，或結果未送出）、即將執行、**已暫停** 和 **已完成**（已執行過的一次性排程工作）。當你的排程工作有多種啟動方式時，清單上方的按鈕可依啟動方式篩選，並用 **全部** 再次顯示所有項目。

若要不開啟任務就對它操作，請將指標移到清單中的它並選擇 **…**，或按住 Control 點按它，然後選擇 **立即執行**、**暫停** 或 **繼續執行**、**編輯詳細資料**，或 **刪除**。在 **搜尋任務** 中按 ↓ 即可前往第一個任務，再按 ↑ 和 ↓ 在任務之間移動。

## 使用表單編輯器

在新增任務畫面選擇 **改用表單設定任務**，或在任務上選擇 **編輯詳細資料**，即可自行填寫每個欄位。

<Frame caption="任務編輯器，含 Agent 指令和平日排程。">
  <img src="/images/guides/scheduled-task-editor.jpg" alt="編輯排程任務的對話框，含 Agent、指令，以及週一到週五 09:00 的每週排程" />
</Frame>

1. 為任務命名並選擇它要做什麼：**詢問代理程式** 搭配 Agent 和指令、**執行工作流程** 以執行你儲存的某個[工作流程](/zh-hant/workflows/introduction)，或 **執行 Shell 命令** 以執行你 Mac 上的腳本。若是工作流程，請填入它應該收到的任何輸入；留空的輸入會使用工作流程的預設值。
2. 在 **時間** 之下，選擇 **一次**、**每天**、**每週**、**每月**、**間隔** 或 **Cron**，並檢查 **下次執行時間（當地時間）** 預覽。在 **Cron** 中，運算式下方的那一行會在你輸入時說明它的意思，例如 `0 9-17 * * 1-5` 會顯示為 **平日每小時，從 09:00 到 17:00**。
3. 在 **傳送結果** 之下，開啟 **將每個結果傳送到聊天**，即可將結果傳送到即時通訊聊天。你可能需要先在該聊天中與 Agent 交談，它才會顯示在選擇器中。
4. **更多選項** 可加入說明和最大執行次數。
5. 選擇 **儲存**（或 **建立任務**）。**測試執行** 會儲存任務並立即執行。

Shell 命令任務，以及依 ID 將結果傳送到聊天，只能在這個編輯器中設定；排程聊天處理的是 Agent 和工作流程任務。對於由事件啟動的任務，表單不會變更觸發條件：請在排程工作聊天中變更什麼會啟動它。

Shell 命令任務只會在執行失敗時通知你（**失敗時通知我**），因為這類任務常常每隔幾分鐘就執行一次。

## 排程工作流程

工作流程任務會在你選擇的時間執行已儲存的工作流程，與在工作流程編輯器中選擇 **執行** 相同。在編輯器中選擇 **執行工作流程**，或詢問排程聊天，例如「每個工作日 9 點執行我的 Content Pipeline，主題是 AI 新聞」。它會依名稱找到工作流程，填入你提到的輸入，其餘保留預設值。

每次執行的結果是工作流程最後一個步驟的輸出，因此可以像其他任何結果一樣傳送到聊天或顯示在通知中。如果某個步驟失敗，該次執行會被標示為失敗，並附上該步驟的錯誤。

- 任務的詳細資料會顯示工作流程及其輸入。選擇 **開啟** 即可查看工作流程，或選擇 **變更** 以挑選其他工作流程或變更輸入。
- 在展開的執行下，選擇 **打開執行**，即可在 **工作流程** 中查看該次執行的每個步驟。當最後一次執行失敗時，任務名稱下方的備註會提供 **開啟失敗的執行**。
- 執行會在排程工作的 **時間上限** 停止（請參閱[進階設定](#進階設定)）。等待你回應核准步驟的時間不計入。
- 如果工作流程被刪除，任務會暫停並說明原因。選擇 **選擇工作流程** 可為它指定另一個，或選擇 **刪除** 移除該任務。

## 在設定中管理多個任務

**設定 → 排程工作** 會在表格中列出每個任務，包括 Shell 命令任務。可依 **已啟用**、**已暫停** 或 **需要處理** 篩選、搜尋，並選取多個任務一起暫停、繼續或刪除。任務的記錄會顯示每次執行的狀態：

| 狀態 | 要檢查什麼 |
| --- | --- |
| 失敗 | 指令、Agent 的工具、shell 結束狀態，或錯誤詳細資料 |
| 成功 / 未送達 | 任務已執行，但它的即時通訊管道或聊天需要處理 |
| 完成 · 不再執行 | 一次性任務已完成 |
| 已暫停 | 如果你想要之後繼續執行，請重新開啟 |

在記錄中，**開啟對話** 會開啟 Agent 的執行，**複製結果** 會複製它的輸出，**重新傳送** 會把結果再次傳送到設定的聊天，成為一則真正的訊息。

## 執行之後

除了將結果傳送到聊天並通知你，**然後** 還有兩個選項：

- **在 GitHub 上回覆**：對於由 GitHub 事件啟動的排程工作，Enconvo 在將它的回覆以留言形式發布到啟動該次執行的 issue 或 pull request 之前，會先詢問你。一天內沒有人核准的回覆就不會發布。
- **加入 Ideas**：排程工作聽到的每個 GitHub issue、Discord 或 Telegram 訊息、電子郵件或 webhook 請求，都會成為專案 Ideas 看板上的一個想法。專案的負責人可以重現錯誤並規劃修復，或研究一項請求並附上理由將它結案或排入計畫，並且在任何變更之前都會先詢問你。請參閱[專案](/zh-hant/ai/projects)。

## 得知結果

- 工作流程把步驟和 Agent 串成一項可重複執行的工作。在[排程工作流程](#排程工作流程)中選擇一個，或在[工作流程](/zh-hant/workflows/introduction)中建立一個。
- [變數](/zh-hant/workflows/variables)會把每次都不同的值，例如今天的日期或你選取的文字，放入提示詞和指令中。
- **設定 → 通知** 可選擇你如何得知某次執行已完成。開啟 **安靜時段**，可將 Agent 的問題和已完成的任務保留到早上，並開啟 **核准請求照常提醒**，讓核准請求仍能送達你。請參閱[通知](/zh-hant/configuration/notifications)。

## 注意事項

- 排程工作在你的 Mac 上執行，因此 Enconvo 必須正在執行，且你的 Mac 必須處於喚醒狀態。睡眠中或離線的 Mac 不會執行它們；請不要把它當成永遠開著的排程器。
- 時間以你 Mac 的當地時區為準。旅行或時區變更後，請檢查下次執行的時間。
- 一次性任務需要未來的時間，並在執行後移到 **已完成**。
- 當你請 Agent 稍後傳送 Apple 訊息時，它會設定一個一次性排程工作，因此你可以在排程工作中看到已排程的訊息，或在那裡取消。
- 每月 29 日到 31 日的任務，會略過沒有該日期的月份。
- Mac 通知也會遵循[通知](/zh-hant/configuration/notifications)中的 **傳送系統通知** 以及 macOS 專注模式。當你正在查看該次執行時，通知會被略過。
- 執行記錄會保留每個任務最近 100 次的執行；更舊的執行及其對話會被移除。刪除任務前，請先複製任何重要的內容。
