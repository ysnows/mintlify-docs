排程工作會自動替你完成任務，無需你每次手動啟動：它可以要求代理程式執行任務、執行你儲存的工作流程，或執行 Shell 命令。它支援按排程執行（一次或重複執行）、在特定事件發生時執行（例如收到新郵件或資料夾中出現新檔案），或由你手動啟動。你可以用它來產生每日早晨新聞摘要、每週計畫或價格監控。

每次執行都會開啟一個獨立的對話，結果會顯示在該排程工作中。你也可以讓 Enconvo 在你的 Mac 上通知你、將結果傳送到即時通訊聊天、在 GitHub 上回覆，或將接收到的內容加入專案的 Ideas 看板。

每個排程工作由三個部分組成，你可以直接在原地修改每個部分，或用自己的話描述變更：

| 部分 | 包含內容 |
| --- | --- |
| **何時（觸發條件）** | 排程、事件或由你手動啟動 |
| **步驟** | 要執行的代理程式與指令、工作流程或 Shell 命令 |
| **後續（執行後）** | 結果的去向與通知方式 |

執行記錄會以長條圖顯示在下方，讓你一目了然哪些已執行、哪些執行失敗。

這部影片先介紹排程工作，接著說明工作流程、變數，以及如何透過通知和安靜時段接收結果。

## 透過聊天設定排程工作

<Steps>
  <Step title="開啟排程工作">
    在**聊天視窗**側邊欄中選取**排程工作**，然後選取**新增排程工作**。
  </Step>
  <Step title="說明要做的事與時間">
    在輸入框中描述任務和時間，例如「每個平日 8:00，用五個重點和連結向我摘要最重要的 AI 新聞」。你也可以選取其中一個範本，它會自動填入輸入框供你在傳送前調整。

    如果你有已儲存的工作流程，其中幾個會顯示在**按排程執行工作流程**下方。選取其中一個即可填入每天 9:00 執行該工作流程的請求，接著在傳送前修改時間或加入輸入值。
  </Step>
  <Step title="檢查草稿">
    Enconvo 會設定好任務，在聊天中以卡片顯示，並用通俗的文字和你的當地時間回覆何時執行。如果你沒有指定時間，它會選擇一個合理的時間並告知你。只有在缺乏答案就無法執行任務時（例如要追蹤哪個產品），它才會向你提問。
  </Step>
  <Step title="開啟任務">
    新的排程工作預設為關閉，在聊天旁標記為**草稿（尚未開啟）**。確認無誤後選取**開啟**；在此之前不會執行任何任務。任務會出現在對話上方的**在此聊天中設定**底下及任務列表中。繼續聊天即可修改、暫停或繼續執行它。
  </Step>
</Steps>

<Frame caption="新任務可從一句話或範本開始。">
  <img src="/images/guides/scheduled-tasks-new.jpg" alt="排程任務畫面，包含一個輸入框與六個起始任務" />
</Frame>

請將任務寫成完整的指令。每次執行都會開啟全新的對話，無法看到你設定任務時的聊天內容，因此「用五個重點和連結摘要今天最重要的 AI 新聞」會比「明天再做一次」效果更好。

## 查看即將執行與已執行的任務

排程工作頂部的**今天**會顯示接下來要執行的任務，以及所有已執行的任務和每次執行的結果。選取任一次執行即可閱讀結果，或讓失敗的執行再試一次。

每個排程工作最近一次的執行，在開始時也會立即出現在側邊欄的**聊天**底下並附有時鐘標記。在該次執行的聊天中，按一下即可查看更早的執行記錄。

### 返回排程聊天

排程聊天會保留下來，但不會顯示在側邊欄的**聊天**底下。若要返回某個排程聊天（例如 Enconvo 正在等待你回覆的聊天），請選取對話上方的聊天名稱，並在**排程聊天**下選擇它。你也可以在那裡刪除聊天；在其中設定好的任務仍會繼續執行。

### 從任何聊天提出請求

你也可以在任何聊天中提出請求，例如「提醒我明天 9 點寄出發票」或「每週一早上列出我這週的截止日期」。代理程式會建立相同類型的任務、顯示其卡片並確認執行時間。選取卡片上的**開啟**即可在**排程工作**中查看。舊聊天中的卡片會顯示該任務之後是否已暫停、完成或刪除。

## 依事件或手動啟動

除了指定時間之外，排程工作也可以在某件事發生時啟動。在排程工作聊天中描述觸發條件，Enconvo 就會為你設定好觸發器。

| 啟動方式 | 執行時機 |
| --- | --- |
| 排程 | 在你設定的時間執行 |
| 由你手動 | 當你選取**執行**時（若有輸入文字則會對該文字進行處理）。開啟**在 PopBar 中顯示**可對選取文字執行，或開啟**顯示在動態島主頁**以在動態島上顯示按鈕。 |
| 資料夾變更 | 每當資料夾中有檔案新增、變更或移除時 |
| 應用程式 | 當 App 開啟、結束、切換到前景，或停留在前景一段時間時 |
| Discord 或 Telegram 訊息 | 每當已連接的機器人收到可讀取的訊息時 |
| 新郵件 | 每當代理程式可讀取的 [Email](/zh-hant/integrations/email) 外掛程式信箱（每分鐘檢查一次）、Apple 郵件（郵件 App 開啟時每兩分鐘檢查一次），或透過 Gmail 連接器的 Gmail（約每五分鐘檢查一次）收到新郵件時 |
| GitHub | 當你連接的儲存庫中有 Issue 或 Pull Request 被開啟、Issue 被加上標籤、留言提及你、CI 失敗或發布新版本時。請參閱 [GitHub 觸發條件](#github-觸發條件)。 |
| MCP 事件 | 每當已連接的 MCP 伺服器回報事件時 |
| 已轉寫的錄音 | 每當 Enconvo 完成錄音轉寫時 |
| 網頁與訂閱源 | 每當訂閱源有新項目，或網頁文字發生變更時 |
| 複製內容 | 每當你在剪貼簿歷史記錄未忽略的 App 中複製內容時 |
| Mac 事件 | 當 Mac 喚醒、解鎖、插上或拔除電源，或當你離開或回到電腦前時 |
| 行事曆事件 | 在行事曆事件開始前或結束時 |
| 會議 | 當 Zoom、Teams、FaceTime 或微信通話中的會議開始時 |
| 登入 | 每次你登入系統後 Enconvo 啟動時執行一次 |
| Webhook 請求 | 每當請求送達該排程工作專屬的位址時（頁面會顯示該位址與複製按鈕） |

Enconvo 會在執行期間於你的 Mac 上監聽事件。任務上的觸發器欄位會說明 Enconvo 關閉期間發生的事件將如何處理。

### GitHub 觸發條件

<Steps>
  <Step title="連接 GitHub">
    在**何時**底下選擇 GitHub，並選取**連接 GitHub**。你需要登入你的 Enconvo 帳號。
  </Step>
  <Step title="選擇儲存庫與事件">
    選擇一個**儲存庫**（或選取**其他儲存庫…**自行輸入）與一個**事件**。對於加上標籤的 Issue，請選擇特定**標籤**或**任何標籤**。監看儲存庫需要擁有該儲存庫的管理員權限。
  </Step>
  <Step title="選擇誰能觸發">
    選擇**僅我**、**任何人**，或新增應觸發該工作的成員 GitHub 使用者名稱。
  </Step>
</Steps>

GitHub 事件會透過 Enconvo Cloud 傳送到你的 Mac，並在你允許此 Mac 接收外部觸發前保持封存狀態：系統詢問時請選取**在這台 Mac 上允許**。選取**在這台 Mac 上停用外部觸發**可再次停止接收；之後事件會暫存在 Enconvo Cloud。

事件觸發器也可以加上用自然語言寫的條件。AI 會在執行前依據該條件檢查每個事件；不符合的事件會被略過，但你仍可對單一事件選取**仍然執行**。每次檢查都是一次付費 AI 呼叫。選取**用最近的事件試一下**，即可在不實際執行的情況下查看哪些近期事件會符合條件。

## 管理排程工作

在列表中選取一個排程工作，即可查看它是已啟用、已暫停還是需要處理，接著可查看其**何時**、**步驟**、**後續**部分及執行記錄。

當最近一次執行失敗或結果未能傳送時，名稱下方的提示會說明原因並提供修復選項：

- **透過聊天修復**（代理程式或工作流程任務）會開啟該任務的聊天並附上包含錯誤資訊的修復請求；**再次執行**則會再執行一次。
- **重新傳送**會重試傳送結果，**變更結果儲存位置**則會開啟結果選擇器。在該處選擇**僅 Enconvo** 也會清除結果未傳送的提示。
- 自動啟動的任務若連續失敗 5 次將會自動暫停。修復後請選取**開啟**。

| 控制項 | 作用 |
| --- | --- |
| **立即執行** | 立即執行一次該任務。這會真實執行，因此代理程式可能會使用工具或點數。手動啟動的任務顯示的是**執行**。 |
| **隨聊天變更** | 對於代理程式任務，重新開啟建立該任務的聊天（若沒有則開啟新聊天），讓你描述修改內容，例如「改到 7:30」或「加上天氣」。 |
| **任務名稱** | 點選名稱即可重新命名任務。按 Return 儲存或 Esc 取消。 |
| **排程** | 顯示任務的執行時間和下次執行時間。排程會以通俗文字顯示，例如**每天 09:00 與 18:00** 或**每年 1 月 1 日 03:00**，在列表、設定和聊天卡片中皆相同。點選它即可原地修改時間：選擇**一次**、**每天**、**每週**、**每月**、**間隔**或 **Cron**，確認下次執行時間後選取**儲存**。旁邊的開關可暫停後續執行而不刪除任務。 |
| **指令** → **編輯** | 原地修改要求代理程式執行的內容（或 Shell 命令任務的命令）。按 **⌘↩** 或選取**儲存**；Esc 取消。 |
| **結果** | 顯示每次執行的結果去向。點選它並選擇你透過即時通訊管道與代理程式對話過的聊天，或選擇**僅 Enconvo** 以將結果保留在每次執行的對話中；變更會立即儲存。**另一個聊天…** 會開啟編輯器讓你輸入聊天 ID。 |
| **執行時通知我** | 每次執行完成時發送 Mac 通知，附帶結果的第一行文字。點擊通知即可開啟該任務。 |
| **…** → **編輯詳細資料** | 開啟表單編輯器一次編輯所有欄位，包含代理程式、描述和執行次數上限。 |
| **…** → **複製** | 建立副本並以草稿開啟，方便你在開啟前修改。 |
| **…** → **所有執行記錄** | 開啟附帶篩選器的完整執行歷史記錄。 |
| **…** → **刪除** | 刪除排程工作及其執行歷史記錄。刪除正在執行的工作也會同時中止該次執行。 |

選取任一執行長條即可閱讀該次執行的結果或錯誤、在該對話中繼續交談、複製結果，或在結果未送出時重新傳送。

### 進階設定

開啟排程工作的**進階設定**，以設定其執行的限制範圍：

| 設定 | 作用 |
| --- | --- |
| **執行次數上限** | 總共執行的次數。已完成的排程工作可以在此增加執行次數。 |
| **時間上限** | 單次執行的最長時間，範圍從 15 分鐘到 8 小時。當執行達到上限時，該次執行會提供更長的上限選項（**允許 … 並再次執行**），讓你一鍵延長時間並重試。 |

### 尋找排程工作

可依名稱、指令、命令或工作流程搜尋列表。列表會將排程工作分組為**需要處理**（上次執行失敗或結果未送出）、即將執行、**已暫停**和**已完成**（已執行完畢的一次性排程工作）。當你的排程工作有多種啟動方式時，列表上方的按鈕可依啟動方式篩選，點擊**全部**即可重新顯示所有任務。

若要在不開啟任務的情況下操作，請將指標移至列表中的任務上並選取 **…**，或按住 Control 鍵點擊它，然後選擇**立即執行**、**暫停**或**繼續執行**、**編輯詳細資料**或**刪除**。在**搜尋任務**中按 ↓ 可移至第一個任務，再用 ↑ 和 ↓ 在任務間移動。

## 使用表單編輯器

在新任務畫面上選取**改用表單設定任務**，或在任務上選取**編輯詳細資料**，即可自行填寫每個欄位。

<Frame caption="包含代理程式指令與平日排程的任務編輯器。">
  <img src="/images/guides/scheduled-task-editor.jpg" alt="編輯排程任務對話框，包含代理程式、指令及每週一至週五 09:00 的排程" />
</Frame>

1. 為任務命名並選擇執行內容：**詢問代理程式**並指定代理程式與指令、**執行工作流程**以執行已儲存的[工作流程](/zh-hant/workflows/introduction)，或**執行 Shell 命令**以在 Mac 上執行腳本。對於工作流程，請填寫要傳入的任何輸入值；留空的輸入會使用工作流程的預設值。
2. 在**何時**底下選擇**一次**、**每天**、**每週**、**每月**、**間隔**或 **Cron**，並檢查**下次執行時間（當地時間）**預覽。在 **Cron** 中，運算式下方的說明文字會在你輸入時即時解讀，例如 `0 9-17 * * 1-5` 會顯示為**平日 09:00 至 17:00 每小時執行**。
3. 在**傳送結果**底下開啟**將每個結果傳送到聊天**，即可將結果傳送到即時通訊聊天。你可能需要先在該聊天中與代理程式對話一次，它才會出現在選擇器中。
4. **更多選項**可新增描述與執行次數上限。
5. 選取**儲存**（或**建立任務**）。**測試執行**會儲存任務並立即執行一次。

Shell 命令任務以及依聊天 ID 傳送結果，只能在此編輯器中設定；排程聊天僅處理代理程式與工作流程任務。對於依事件啟動的任務，表單不會修改觸發器：請在排程工作聊天中修改其啟動條件。

Shell 命令任務僅在執行失敗時通知你（**失敗時通知我**），因為這類任務通常每幾分鐘就會執行一次。

## 排程工作流程

工作流程任務會在你選擇的時間執行已儲存的工作流程，效果與在工作流程編輯器中選取**執行**相同。在編輯器中選擇**執行工作流程**，或在排程聊天中提出要求，例如「每個平日 9 點以 AI 新聞為主題執行我的 Content Pipeline」。它會依名稱找到該工作流程、填入你提及的輸入值，其餘則保留預設值。

每次執行的結果即為工作流程最後一個步驟的輸出，因此可以像其他結果一樣傳送到聊天或顯示在通知中。若某個步驟失敗，該次執行會標記為失敗並顯示該步驟的錯誤。

- 任務詳細資料會顯示工作流程及其輸入值。選取**開啟**可檢視該工作流程，或選取**變更**以選擇其他工作流程或修改輸入值。
- 在展開的執行記錄底下，選取**打開執行**即可在**工作流程**中查看該次執行的每個步驟。當最近一次執行失敗時，任務名稱下方的提示會提供**開啟失敗的執行**。
- 執行時間受限於排程工作的**時間上限**（請參閱[進階設定](#進階設定)）。等待你回覆核准步驟的時間不計入其中。
- 如果工作流程被刪除，任務會暫停並顯示提示。選取**選擇工作流程**為它指定另一個工作流程，或選取**刪除**移除該任務。

## 在設定中管理大量任務

**設定 → 排程工作**以表格列出所有任務，包含 Shell 命令任務。可依**已啟用**、**已暫停**或**需要處理**篩選、搜尋，並一次選取多個任務進行暫停、繼續執行或刪除。任務的歷史記錄會顯示每次執行的狀態：

| 狀態 | 應檢查項目 |
| --- | --- |
| 失敗 | 指令、代理程式的工具、Shell 結束狀態碼或錯誤詳細資料 |
| 成功 / 未送達 | 任務已執行，但其即時通訊管道或聊天需要處理 |
| 已完成 · 無更多執行 | 一次性任務已執行完畢 |
| 已暫停 | 若希望繼續執行後續排程，請重新開啟 |

在歷史記錄中，**開啟對話**會開啟代理程式的執行對話、**複製結果**會複製輸出內容，而**重新傳送**則會將結果作為真實訊息再次傳送到設定的聊天中。

## 執行之後

除了將結果傳送到聊天和通知你之外，**後續（執行後）**還有兩個選項：

- **在 GitHub 上回覆**：對於由 GitHub 事件啟動的排程工作，Enconvo 會在將回覆張貼為該 Issue 或 Pull Request 留言前向你確認。超過一天未核准的回覆將不會張貼。
- **加入 Ideas**：排程工作接收到的每個 GitHub Issue、Discord 或 Telegram 訊息、電子郵件或 Webhook 請求，都會成為專案 Ideas 看板上的一個想法。專案負責人可以重現錯誤並規劃修復方案，或研究請求後附上原因關閉或進行規劃，並在進行任何變更前詢問你。請參閱[專案](/zh-hant/ai/projects)。

## 接收結果通知

- 工作流程將多個步驟與代理程式串聯成可重複執行的工作。你可以在[排程工作流程](#排程工作流程)中選取一個工作流程，或在[工作流程](/zh-hant/workflows/introduction)中建立。
- [變數](/zh-hant/workflows/variables)可將每次都會變動的值（例如今天日期或你選取的文字）放入提示詞與指令中。
- **設定 → 通知**決定執行完成後如何通知你。開啟**安靜時段**可將代理程式提問和已完成的任務暫緩至隔天早上通知，若仍希望核准請求立即通知你，請開啟**核准請求照常提醒**。請參閱[通知](/zh-hant/configuration/notifications)。

## 注意事項

- 排程工作在你的 Mac 上執行，因此 Enconvo 必須保持開啟且 Mac 處於喚醒狀態。睡眠或離線的 Mac 不會執行任務；請勿將其視為全天候常駐的排程伺服器。
- 時間採用你 Mac 的當地時區。旅行或變更時區後請檢查下次執行時間。
- 一次性任務必須設定未來的時間，並在執行後移至**已完成**。
- 當你要求代理程式稍後傳送 Apple 訊息時，它會建立一個一次性排程工作，因此你可以在排程工作中查看該預約訊息或在該處取消。
- 設定在每月 29 日至 31 日執行的每月任務，在沒有該日期的月份會自動略過。
- Mac 通知同時遵循[通知](/zh-hant/configuration/notifications)中的**傳送系統通知**設定與 macOS 專注模式。如果你當下正在查看該次執行，系統會略過該通知。
- 執行歷史記錄會為每個任務保留最近 100 次執行；更早的執行及其對話會被移除。刪除任務前請先複製任何重要內容。
