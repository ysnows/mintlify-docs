Every Agent and AI Command can be started from outside Enconvo in three ways:

| Way | Where it runs | What you get back |
|---|---|---|
| [Deeplink](#deeplink) | In an Enconvo window: SmartBar, the Chat Window, or the Dynamic Island | The answer on screen, as if you had typed the message yourself |
| [CLI](#cli) | In the background, from Terminal or a script | The answer printed in Terminal |
| [Local API](#local-api) | In the background, from any app that can send an HTTP request | The answer as JSON |

Use a deeplink when you want to see the answer and keep chatting, for example from a launcher, a Shortcut, a note, or a bookmark. Use the CLI or the local API when a script needs the answer.

Keep Enconvo running. All three ways go through the app on your Mac and use the same models and settings as when you run the Agent or AI Command yourself.

## Find the command key

Each way names the Agent or AI Command by its command key, `<extension>|<command>`:

| Agent or AI Command | Command key |
|---|---|
| Mavis | `agent|main` |
| Translate | `writing_package|translate` |
| Summarize | `writing_package|summarize` |
| Fix Spelling and Grammar | `writing_package|fix_spelling_and_grammar` |

An Agent or AI Command you made yourself has its own key. `enconvo agent list` lists the agents with their keys.

## Deeplink

A deeplink opens the Agent or AI Command in an Enconvo window and sends your text right away:

```text
enconvo://<extension>/<command>?input_text=<text>
```

For example, this link asks Mavis to plan your day in SmartBar:

```text
enconvo://agent/main?input_text=Plan%20my%20day
```

You can add these to the link:

| Parameter | What it does |
|---|---|
| `input_text` | The message to send. Leave it out to open the Agent or AI Command with an empty input. |
| `window` | Where it opens: `smart_bar` (the default), `chat_window`, or `dynamic_island`. |
| `files` | The absolute path of a file to attach. Repeat it for more files. Images are sent as images, so the model can read them. A path with no file behind it is skipped. |

Encode the text and paths in the link (spaces as `%20`, `/` in a path as `%2F`, `&` as `%26`), or the link breaks at the first special character. This link opens Translate in the Chat Window with a screenshot attached:

```text
enconvo://writing_package/translate?window=chat_window&input_text=Translate%20the%20text%20in%20this%20image&files=%2FUsers%2Fme%2FDesktop%2Fmenu.png
```

To open a link from Terminal or a script, use `open`:

```bash
open "enconvo://agent/main?input_text=$(python3 -c 'import urllib.parse,sys; print(urllib.parse.quote(sys.argv[1]))' 'Plan my day')"
```

A link always opens in the window it names, or in SmartBar when it names none, even if you last used another window.

## CLI

The `enconvo` command ships with the app. It runs the Agent or AI Command in the background, waits for the answer, and prints it. Nothing opens on screen.

Ask an Agent:

```bash
enconvo agent call index --agent-id "agent|main" "Plan my day"
```

The answer comes back as JSON with the agent's `answer` and the `sessionId` of its chat, which you can open in Enconvo or continue with `--session-id`. Attach files with `--context-files`:

```bash
enconvo agent call index --agent-id "agent|main" "What does this chart show?" --context-files ~/Desktop/chart.png
```

Run an AI Command:

```bash
enconvo ai-command run "writing_package|translate" --input-text "今天天气很好"
enconvo ai-command run "writing_package|explain" --input-text "Explain this" --files ~/Desktop/chart.png
```

It prints `{ "result": "<the answer>" }`. An AI Command run this way isn't saved as a chat, and nothing is pasted or read aloud. Add `-h` to any command to see all its options. The exit code is 1 when the run fails, with the reason on stderr.

## Local API

The app serves the same runs over HTTP at `http://localhost:54535`, for apps and scripts that don't use the CLI. Send a `POST` with a JSON body.

Ask an Agent:

```bash
curl -X POST http://localhost:54535/api/agent/call \
  -H "Content-Type: application/json" \
  -d '{"agentId": "agent|main", "message": "Plan my day", "context_files": ["/Users/me/Desktop/chart.png"]}'
```

```json
{ "sessionId": "U6gjftDuA0ZLF2h_EFFA", "agent": "agent|main", "agentName": "Mavis", "status": "done", "answer": "…" }
```

Run an AI Command:

```bash
curl -X POST http://localhost:54535/api/ai-command/run \
  -H "Content-Type: application/json" \
  -d '{"command_key": "writing_package|translate", "input_text": "今天天气很好", "files": []}'
```

```json
{ "result": "The weather is really nice today." }
```

File paths must be absolute. A failed run answers with an HTTP error and `{ "error": "<why>" }`. The local API only listens on this Mac.
