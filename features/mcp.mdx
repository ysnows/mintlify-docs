[Model Context Protocol (MCP)](https://modelcontextprotocol.io) is an open standard that lets AI models use outside tools and data. Each MCP server offers tools an agent can call, such as reading files, querying a database, or sending a message. Add a server to Enconvo, and agents use its tools on their own when a task needs them.

## Add a server in Settings

<Steps>
  <Step title="Open MCP Servers">
    Open **Settings** from the Enconvo icon in the menu bar (**Settings...**), or press **⌘,**. Then open **Settings → MCP Servers**.
  </Step>
  <Step title="Add the server">
    Click **Add server** and enter a **Server name**. Choose a transport: **STDIO** for a command that runs on your Mac, or **HTTP** or **SSE** for a server at a URL. Fill in its fields and click **Save**.
  </Step>
  <Step title="Check that it connects">
    The dot beside the server turns green, and its row shows how many tools it has. Click the tool count to see them.
  </Step>
  <Step title="Choose where its tools apply">
    Use the switch on the server's row. On: Enconvo includes the server's tools whenever the assistant prepares a reply, everywhere. Off: they aren't loaded everywhere, but you can still add the server from SmartBar or turn it on for one app in App Sidebar.
  </Step>
</Steps>

Servers that use OAuth open a sign-in page the first time you connect. If a server shows **Authenticate**, click it and finish signing in. **Grant access** appears when a connected server asks for more access than your sign-in gave it.

Servers that come with a plugin are listed under **From plugins**.

<Tip>
The Settings sidebar is long. Press **⌘F** in Settings and type "MCP" to jump to the pane, or open it with the deeplink `enconvo://preference?pane=mcp_management`.
</Tip>

## Add a server from the CLI

```bash
# Add a stdio server
enconvo mcp add github --command npx --args "-y @modelcontextprotocol/server-github"

# Add an HTTP server
enconvo mcp add notion --transport http --url "https://mcp.notion.com/mcp"

# List servers
enconvo mcp servers list

# List tools
enconvo mcp tools list
```

## Import servers from another app

Bring in the MCP configs you already use in Claude Desktop, Cursor, or another tool.

1. In **Settings → MCP Servers**, click **Import**.
2. Under **Config Format**, choose **Claude Desktop** or **Codex CLI**.
3. Paste the configuration into **JSON Config**.
4. Click **Import**. Every server in it is added.

## Install an MCP bundle

An MCP bundle is an `.mcpb` file that packs a server to run on your Mac. In **Settings → MCP Servers**, click **Install bundle** and choose the file. Opening an `.mcpb` file in Finder brings you to the same place.

A bundle's server runs on your Mac with your permissions, so install bundles only from people you trust. To update one, install a newer `.mcpb` file.

## Share an install link

An install link adds an MCP server to Enconvo in one click. It uses the same format as `mcp.json`: a name and the transport configuration.

```
https://enconvo.com/mcp/install?name=$NAME&config=$BASE64_ENCODED_CONFIG
```

| Component | Description |
|-----------|-------------|
| `https://enconvo.com` | Web install page |
| `/mcp/install` | Path |
| `name` | Query parameter for server name |
| `config` | Query parameter for base64 encoded JSON configuration |

The web page opens the `enconvo://` deeplink, and shows the server configuration in case the app doesn't open.

### Make a link

1. Get the server's name and JSON configuration.
2. `JSON.stringify` the configuration, then base64 encode it.
3. Replace `$NAME` and `$BASE64_ENCODED_CONFIG` with the name and the encoded config.

For example, this configuration:

```json Single MCP server config
{
  "exa": {
    "url": "https://mcp.exa.ai/mcp"
  }
}
```

gives these results:

| Format | Example |
|--------|---------|
| Text link | `https://enconvo.com/mcp/install?name=exa&config=eyJ1cmwiOiJodHRwczovL21jcC5leGEuYWkvbWNwIn0=` |

### What happens when someone opens it

1. They click the link or paste it into a browser.
2. Enconvo asks **Add the MCP server "name"?** and shows what the server runs or connects to. They click **Add**.
3. **Settings → MCP Servers** opens, and the server is added and starts connecting.
4. Once it's connected, agents can use its tools.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The server fails to start | Check the command and arguments. For a STDIO server, make sure the program is installed and on your `PATH`. For a Node.js server, make sure `npx` or `node` is available. |
| Its tools don't appear | Check that the server's dot is green. Some servers need an API key before they offer tools. Turn the server off and on again. |
| The server shows **Authenticate** | Click it and finish signing in on the page that opens. |
| Authentication errors | Check that the API keys are correct and haven't expired, and that the environment variables the server needs are set. |

For the full MCP specification, see [modelcontextprotocol.io](https://modelcontextprotocol.io).
