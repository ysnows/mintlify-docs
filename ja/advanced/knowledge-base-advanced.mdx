このページは、ドキュメントがナレッジベースに入った後に何が起きるのかを知りたい方向けです。Enconvo がどこに保存し、どのように分割してインデックス化し、検索がどのように結果を選ぶのかを説明します。コレクションの調整、精度の低い結果の改善、自分のコードからのナレッジベースの呼び出しにお役立てください。ナレッジベースを初めて使う場合は、まず[ナレッジベース](/ja/ai/knowledge-base)をご覧ください。

要点は次のとおりです。Enconvo は各アイテムのテキストを読み取り、チャンクに分割し、各チャンクをベクトルに変換して、ローカルの LanceDB データベースに保存します。検索では、意味による検索と正確な語による検索を同時に行い、両者を組み合わせます。

## データの保存場所

| 内容 | 保存場所 |
|---|---|
| チャンク、ベクトル、全文インデックス | `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/` にある LanceDB データベース |
| ナレッジベース、アイテム、その詳細 | `~/.config/enconvo/.support/knowledge_base/db` にある SQLite データベース(Drizzle ORM) |

すべてのナレッジベースが 1 つの LanceDB データベースを共有し、各ナレッジベースはその中の 1 つのテーブルです。Enconvo はナレッジベースのインデックスを再構築するとき、古いテーブルの横に新しいテーブルを書き込み、準備が整ったら切り替えます。そのため、再構築中も検索は使えます。

各ナレッジベースには ID があります。API では `knowledge_base_id` として受け取り、Enconvo はそのナレッジベースを `knowledge_base|<id>` というコマンドとして実行します。ナレッジベースの ID をコピーするには、ヘッダーから**ナレッジベースの設定**を開き、**詳細設定**に移動します。

ストレージの使用量は、元のアセット、抽出されたテキスト、チャンク数、埋め込みの次元数によって決まります。ドキュメントの数だけから見積もらず、お使いのコレクションの実際のディスク使用量を確認してください。元のファイルとバックアップは、検索インデックスとは別に保管してください。

## コンテンツが取り込まれる流れ

### 読み取り

Enconvo は、アイテムの種類ごとに適したツールで読み取ります。

| コンテンツ | 読み取り方法 |
|---|---|
| **PDF** | Document Parser プラグイン。PDF のテキストを使い、スキャンされたページにだけ OCR プロバイダーを実行します |
| **Word、PowerPoint、Excel、EPUB、CSV** | Document Parser プラグイン |
| **テキストと Markdown** | そのまま読み取ります |
| **画像** | OCR プロバイダー |
| **音声と動画** | 文字起こしプロバイダー |
| **Web ページ** | Web Fetch プロバイダー |
| **Web サイト全体** | ウェブサイトのクローラーがページごとに処理します |
| **YouTube** | 動画のトランスクリプト |

### チャンクへの分割

Enconvo は、テキストを、書かれている言語に合わせたサイズのチャンクに分割します。

| テキスト | チャンクサイズ | オーバーラップ |
|---|---|---|
| 英語などラテン文字が中心 | 1,500 文字 | 200 文字 |
| 中国語、日本語、韓国語が中心 | 560 文字 | 80 文字 |
| 混在 | それぞれの割合に応じてその中間 | その中間 |

チャンクをサイズ内に収められる、最も自然な区切りで分割します。次の順に試します。

1. 段落
2. 行
3. 文
4. 節
5. 単語
6. 強制的な分割(最後の手段)

スプレッドシートは 1 行がおおよそ 1 チャンクになるように分割されるため、1 行を探す検索でその行が見つかります。これらのサイズは組み込み済みで、設定はありません。

### 埋め込み

すべてのナレッジベースが同じ埋め込みモデル、EmbeddingGemma 300M を使います。実行する場所は **設定 → メモリ → 埋め込みモデル**で選びます。

- **このMac**: 無料で、データが Mac の外に出ることはありませんが、新しいコンテンツのインデックス化中は GPU を使います。Apple シリコンの Mac が必要です。
- **Enconvo Cloud**: Enconvo アカウントで無料です。インデックス化または検索するテキストはクラウドに送信されます。

どちらも同じモデルを実行するため、切り替えても検索インデックスはそのまま使えます。Enconvo はチャンクをバッチで埋め込みます。

### 保存

各チャンクは、ナレッジベースのテーブルの 1 行になります。

| フィールド | 内容 |
|---|---|
| `text` | チャンクのテキスト |
| `vector` | その埋め込み |
| `id` | チャンクの ID |
| `attachment_id` | チャンクの元になったアイテム |
| `type`, `url`, `title`, `ext`, `loc` | アイテムの種類、アドレス、タイトル、ファイル拡張子、およびチャンクがアイテム内のどこにあるか |
| `metadata` | アイテムに関するその他の詳細 |

Enconvo は、`text` の全文インデックスも保持しています。短い文字の並びから作られるため、正確な名前、数字、コード、CJK の語を見つけられます。

## 検索の仕組み

検索のたびに、ナレッジベースのチャンクに対して最大 3 つの検索が同時に実行されます。

1. **意味による検索**: クエリを同じモデルで埋め込み、最も近いベクトルを探します。
2. **語による検索**: クエリの各語について全文(BM25)検索を行います。一般的な英単語は除外されます。
3. **タイトルによる検索**: タイトルがクエリに一致するアイテムを、クエリに最も近いチャンクとともに返します。

その後、Enconvo はこれらを組み合わせます。各リストのスコアは 0 から 1 に正規化され、チャンクのスコアは、意味のスコアの 0.6 と語のスコアの 0.4 の合計です。タイトルが一致するアイテムや、クエリ全体を含むチャンクは、より上位になります。1 つのアイテムから残るチャンクはわずかなので、長い 1 つのドキュメントがほかを押しのけることはなく、各チャンクは前後のテキストとともに返されます。

ナレッジベース検索には、独立した再ランキングの手順はありません。

## インデックスを健全に保つ

Enconvo は、全文インデックスの作成とテーブルの整理を自動で行います。また、古いチャンカーや別の埋め込みモデルで作られたナレッジベースのインデックスを、すでに保持しているテキストから、ファイルを読み直さずに再構築します。

手動で再構築するには次のようにします。

- **ナレッジベース全体**: ヘッダーから**ナレッジベースの設定**を開き、**インデックスと検索**に移動して、**インデックス全体を再構築**の横にある**再インデックス化…**をクリックします。実行中も検索は使えます。
- **1 つのアイテム**: アイテムを右クリックして**再インデックス化**を選びます。

**ナレッジベースの設定**には 5 つのセクションがあります。**一般**(名前と説明)、**インデックスと検索**(健全性、対応が必要なアイテム、検索モデル、再インデックス化)、**ソースとキャプチャ**(リンクされたフォルダーとキャプチャツール)、**AI クライアント（MCP）**、**詳細設定**(ID とナレッジベースの削除)です。

不要になったナレッジベースは、ディスク容量を回復するために削除してください。

### リンクされたフォルダー

アイテムが見つからない場合は、まずソースフォルダーのインポートと同期の状況を確認してください。**ソースとキャプチャ**では、リンクされた各フォルダーについて、同期中か、最後に同期した時刻、またはソースフォルダーが見つからないことが表示され、**今すぐ同期**、**再リンク…**、**自動同期**を使えます。

次に、アイテムのコンテンツ抽出の状況と埋め込みの状況を別々に確認します。アイテムの**パイプライン**には、**コンテンツの解析**と**検索インデックス**が 2 つの段階として表示されます。抽出されたテキストが読めても、ベクトルのインデックス化が完了しているとは限りません。プロバイダーやファイルアクセスのエラーを解消したら、そのアイテムを再インデックス化してください。

リンクされたファイルについては、ソースフォルダーが正となります。オフラインのドライブの復旧とファイルの削除は別のものとして扱ってください。ソースフォルダーが見つからないときも、ナレッジベースはアイテムを保持します。インポートが完了したと判断する前に、スキップされたファイルの数を確認してください。

## 複数のナレッジベースを整理する

各ナレッジベースは、それぞれ独自のドキュメント、インデックス、テーブルを持ちます。検索するときの切り口に合わせて、コンテンツを分けてください。

| 方針 | 説明 | 例 |
|----------|-------------|---------|
| **プロジェクト別** | プロジェクトごとに 1 つのナレッジベース | `project-alpha`, `project-beta` |
| **種類別** | コンテンツの種類ごとにナレッジベースを分ける | `code-docs`, `meeting-notes`, `research` |
| **チーム別** | チーム専用のナレッジ | `engineering`, `marketing`, `support` |
| **範囲別** | 個人用と共有用 | `personal-notes`, `company-wiki` |

複数を同時に検索するには、コンテキストピッカーで添付するか、エージェントに添付するナレッジベースを設定します。ナレッジベースを指定しない検索は、メモリを除く、すべてのナレッジベースを対象にします。

## コードからナレッジベースを使う

ナレッジベースプラグインは、そのルートを [Local API](/ja/advanced/cli-local-api) で提供しているため、ほかのプラグイン、ワークフロー、スクリプトから呼び出せます。主なものは次のとおりです。

| ルート | 用途 |
|---|---|
| `knowledge_base/create` | ナレッジベースを作成する |
| `knowledge_base/delete` | ナレッジベースとそのすべてのデータを削除する |
| `knowledge_base/add`, `knowledge_base/add_attachments` | ファイル、テキスト、リンク、メディアを追加する |
| `knowledge_base/search` | 1 つまたは複数のナレッジベースを検索する |
| `knowledge_base/list` | ナレッジベースを一覧表示する |
| `knowledge_base/get_attachments` | ナレッジベース内のアイテムを一覧表示する |
| `knowledge_base/delete_attachments` | ナレッジベースからアイテムを削除する |
| `knowledge_base/reindex` | ナレッジベースまたはアイテムのインデックスを再構築する |
| `knowledge_base/summarize` | 1 つのアイテムを要約する |

各ルートのパラメータは、お使いのバージョンの **設定 → API** で確認できます。

ナレッジベースの操作は、ワークフローや自動化に組み込めます。たとえば次のようになります。

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

ほかの AI クライアントには、[ナレッジベース MCP](/ja/advanced/knowledge-base-mcp) を使ってください。選択したナレッジベースを、ローカルの読み取り専用サービスとして公開します。エージェントのメモリや録音はエクスポートしません。

## トラブルシューティング

| 問題 | 対処 |
|---|---|
| 検索結果が関係のないものになる | アイテムの**検索インデックス**の段階が完了していることを確認し、ナレッジベースを再インデックス化してください。ドキュメントで使われている語で検索してください。正確な名前や数字は、全文インデックスで一致します |
| インデックス化が遅い | 大きなドキュメントは時間がかかります。**このMac**ではインデックス化に GPU を使うため、**埋め込みモデル**を **Enconvo Cloud** に切り替えると Mac の負荷を避けられます |
| Enconvo Cloud を使用中、新しいアイテムが検索できない | Enconvo アカウントにサインインしてください。サインインするまで、新しいコンテンツはインデックス化されず、検索では一致する語しか見つかりません |
| ファイルの種類がサポートされていない | PDF、TXT、MD に変換してから、もう一度追加してください |
| ID でナレッジベースが見つからない | **ナレッジベースの設定 → 詳細設定**から ID をコピーし、`knowledge_base_id` として渡してください |
