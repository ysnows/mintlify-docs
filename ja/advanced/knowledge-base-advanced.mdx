このページは、ナレッジベースに入れたドキュメントが内部でどう処理されるか（保存場所、分割・インデックス作成の仕組み、検索結果の選ばれ方）を知りたい方向けの解説です。コレクションの調整、検索精度の改善、またはコードからのナレッジベース呼び出しにお役立てください。初めてナレッジベースを使う場合は、[ナレッジベース](/ja/ai/knowledge-base) からご覧ください。

概要は次のとおりです。Enconvo は各項目のテキストを読み取ってチャンクに分割し、各チャンクをベクトルに変換してローカルの LanceDB データベースに保存します。検索時には、意味による検索と完全一致の単語検索を同時に実行し、両方の結果を統合します。

## データの保存場所

| データ | 保存場所 |
|---|---|
| チャンク、ベクトル、全文検索インデックス | `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/` にある LanceDB データベース |
| ナレッジベース、項目、およびその詳細情報 | `~/.config/enconvo/.support/knowledge_base/db` にある SQLite データベース（Drizzle ORM） |

すべてのナレッジベースは 1 つの LanceDB データベースを共有し、各ナレッジベースがその中の 1 テーブルになります。インデックスを再構築する際、Enconvo は古いテーブルの横に新しいテーブルを書き出し、準備が整ってから切り替えるため、再構築中も検索は止まらずに動作します。

各ナレッジベースには ID があります。API では `knowledge_base_id` として渡し、Enconvo 内部では `knowledge_base|<id>` というコマンドとして実行されます。ナレッジベースの ID をコピーするには、ヘッダーから **ナレッジベース設定** を開き、**詳細設定** へ進みます。

必要なストレージ容量は、元のアセット、抽出されたテキスト、チャンク数、埋め込みの次元数によって変わります。ドキュメント数だけで見積もるのではなく、実際のディスク使用量を確認してください。元のファイルとバックアップは、検索インデックスとは別に保管しておくことをおすすめします。

## コンテンツの取り込み方法

### 読み込み

Enconvo は各項目の種類に応じたツールで内容を読み取ります。

| コンテンツ | 読み取り方法 |
|---|---|
| **PDF** | ドキュメントパーサープラグイン。PDF のテキストデータを使用し、スキャンされたページにのみ OCR プロバイダーを実行します |
| **Word、PowerPoint、Excel、EPUB、CSV** | ドキュメントパーサープラグイン |
| **テキストおよび Markdown** | そのまま読み込みます |
| **画像** | ご使用の OCR プロバイダー |
| **音声および動画** | ご使用の文字起こしプロバイダー |
| **ウェブページ** | ご使用の Web ページを取得プロバイダー |
| **ウェブサイト全体** | ウェブサイトクローラーで 1 ページずつ取得します |
| **YouTube** | 動画の字幕テキスト |

### チャンクへの分割

Enconvo は記述されている言語に合わせて適切なサイズにテキストを分割します。

| テキスト | チャンクサイズ | オーバーラップ |
|---|---|---|
| 主にラテン文字（英語など） | 1,500 文字 | 200 文字 |
| 主に中国語・日本語・韓国語 | 560 文字 | 80 文字 |
| 混在テキスト | 割合に応じた中間値 | 割合に応じた中間値 |

チャンクサイズ内に収まる最も自然な区切りで分割され、次の優先順位で境界を探します。

1. 段落
2. 行
3. 文
4. 節
5. 単語
6. 強制分割（最終手段）

スプレッドシートはおおむね 1 行を 1 チャンクとして分割されるため、特定の行を検索するとその行がヒットします。これらのサイズは組み込み仕様であり、設定変更項目はありません。

### 埋め込み

すべてのナレッジベースで同じ埋め込みモデル（EmbeddingGemma 300M）を使用します。実行場所は **設定 → メモリ → 埋め込みモデル** で選択できます。

- **この Mac**: 無料で利用でき、Mac の外部にデータは一切送信されませんが、新しいコンテンツのインデックス作成中に GPU を使用します。Apple Silicon 搭載 Mac が必要です。
- **Enconvo Cloud**: Enconvo アカウントで無料利用できます。インデックス作成や検索対象のテキストが送信されます。

どちらも同じモデルを実行しているため、切り替えても検索インデックスはそのまま維持されます。Enconvo はチャンクをバッチ単位で埋め込み処理します。

### 保存

各チャンクはナレッジベースのテーブルに 1 行として保存されます。

| フィールド | 保持する内容 |
|---|---|
| `text` | チャンクのテキスト |
| `vector` | 埋め込みベクトル |
| `id` | チャンクの ID |
| `attachment_id` | チャンク元の項目 ID |
| `type`, `url`, `title`, `ext`, `loc` | 項目の種類、アドレス、タイトル、拡張子、および項目内でのチャンク位置 |
| `metadata` | 項目に関するその他のメタデータ |

また、Enconvo は短い文字列単位から構成した `text` の全文検索インデックスも保持しているため、固有名詞、数値、コード、CJK の単語を正確に検索できます。

## 検索の仕組み

検索を実行すると、ナレッジベースのチャンクに対して最大 3 種類の検索が同時に走ります。

1. **意味検索**: クエリを同じモデルで埋め込み、最も近いベクトルを探します。
2. **単語検索**: 英語の一般的なストップワードを除き、クエリの各単語に対して全文検索（BM25）を実行します。
3. **タイトル検索**: タイトルがクエリに一致する項目を、それぞれクエリに最も近いチャンクとあわせて抽出します。

その後、これらを統合します。各リストのスコアは 0〜1 にスケーリングされ、チャンクのスコアは「意味スコア × 0.6 + 単語スコア × 0.4」で計算されます。タイトルが一致する項目や、クエリ全体を含むチャンクはより上位にランク付けされます。1 つの長いドキュメントが結果を独占しないよう、1 項目あたり数チャンクのみが保持され、各チャンクには前後のテキストも含めて返されます。

ナレッジベース検索には、別途のリランキング（reranking）ステップはありません。

## インデックスを健全に保つ

Enconvo は全文検索インデックスの生成とテーブルの整理を自動で行います。また、古いチャンカーや異なる埋め込みモデルで作られたナレッジベースも、ファイルを読み直すことなく既存のテキストからインデックスを再構築します。

手動で再構築するには次のようにします。

- **ナレッジベース全体**: ヘッダーから **ナレッジベース設定** を開き、**インデックスと検索** に進んで **インデックス全体を再構築** の横にある **再インデックス…** をクリックします。処理中も検索はそのまま利用できます。
- **特定の 1 項目**: 項目を右クリックして **再インデックス** を選択します。

**ナレッジベース設定** には 5 つのセクションがあります。**一般**（名前と説明）、**インデックスと検索**（健全性、確認が必要な項目、検索モデル、再インデックス）、**ソースとキャプチャ**（リンクされたフォルダとキャプチャツール）、**AI クライアント（MCP）**、および **詳細設定**（ID とナレッジベースの削除）です。

ディスク容量を解放するには、不要になったナレッジベースを削除してください。

### リンクされたフォルダ

見つからない項目がある場合は、まず元のフォルダのインポートおよび同期ステータスを確認してください。**ソースとキャプチャ** では、リンクされた各フォルダについて、同期中かどうか、最終同期日時、または元フォルダが見つからない状態かどうかが表示され、**今すぐ同期**、**再リンク…**、**自動同期** を利用できます。

次に、項目のコンテンツ抽出ステータスと埋め込みステータスを別々に確認します。項目の **パイプライン** には **コンテンツ解析** と **検索インデックス** が 2 つの段階として表示されるため、抽出済みテキストが読める状態であっても、ベクトルインデックス作成が完了しているとは限りません。プロバイダーやファイルアクセスのエラーを修正したら、その項目を再インデックスしてください。

リンクされたファイルの元の権限・実体はソースフォルダ側にあります。オフラインドライブの復旧とファイル削除は区別されます。ソースフォルダが見つからなくても、ナレッジベースは既存の項目を保持します。インポート完了と判断する前に、スキップされたファイル数も確認してください。

## 複数のナレッジベースを整理する

ナレッジベースごとに独自のドキュメント、インデックス、テーブルを持ちます。検索する単位に合わせてコンテンツを分割してください。

| 整理方法 | 説明 | 例 |
|----------|-------------|---------|
| **プロジェクト別** | プロジェクトごとに 1 つの KB | `project-alpha`, `project-beta` |
| **種類別** | コンテンツの種類ごとに KB を分ける | `code-docs`, `meeting-notes`, `research` |
| **チーム別** | チーム固有のナレッジ | `engineering`, `marketing`, `support` |
| **公開範囲別** | 個人用と共有用 | `personal-notes`, `company-wiki` |

複数をまとめて検索するには、コンテキストピッカーで添付するか、エージェントの添付ナレッジベースを設定します。ナレッジベースを指定しない検索は、メモリを除くすべてのナレッジベースを対象に検索します。

## コードからナレッジベースを利用する

ナレッジベースプラグインは [ローカル API](/ja/advanced/cli-local-api) 上でルートを提供しているため、他のプラグイン、ワークフロー、スクリプトから呼び出せます。主なルートは次のとおりです。

| ルート | 用途 |
|---|---|
| `knowledge_base/create` | ナレッジベースを作成する |
| `knowledge_base/delete` | ナレッジベースとすべてのデータを削除する |
| `knowledge_base/add`, `knowledge_base/add_attachments` | ファイル、テキスト、リンク、メディアを追加する |
| `knowledge_base/search` | 1 つ以上のナレッジベースを検索する |
| `knowledge_base/list` | ナレッジベース一覧を取得する |
| `knowledge_base/get_attachments` | ナレッジベース内の項目一覧を取得する |
| `knowledge_base/delete_attachments` | ナレッジベースから項目を削除する |
| `knowledge_base/reindex` | ナレッジベースまたは項目のインデックスを再構築する |
| `knowledge_base/summarize` | 1 つの項目を要約する |

インストール中のバージョンにおける各ルートのパラメータは **設定 → API** で確認できます。

ナレッジベースの各ステップはワークフローや自動化に組み込めます。例：

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

別の AI クライアントから利用する場合は、[Knowledge Base MCP](/ja/advanced/knowledge-base-mcp) を使用してください。選択したナレッジベースをローカルの読み取り専用サービスとして公開します（エージェントのメモリや録音データは公開しません）。

## トラブルシューティング

| 問題 | 対処方法 |
|---|---|
| 検索結果に関連性の低い項目が出る | 項目の **検索インデックス** 段階が完了しているか確認し、ナレッジベースを再インデックスしてください。また、ドキュメント内で使われている単語で検索すると、全文検索インデックスによって正確な名称や数値がヒットします |
| インデックス作成が遅い | 大きなドキュメントは時間がかかります。**この Mac** では GPU を使用するため、Mac の負荷を抑えたい場合は **埋め込みモデル** を **Enconvo Cloud** に切り替えてください |
| Enconvo Cloud 使用中に新しい項目が検索に出てこない | Enconvo アカウントにサインインしてください。サインインするまで新しいコンテンツはインデックスされず、単語一致のみで検索されます |
| ファイル形式がサポートされていない | PDF、TXT、MD に変換してから再度追加してください |
| ID でナレッジベースが見つからない | **ナレッジベース設定 → 詳細設定** から ID をコピーし、`knowledge_base_id` として渡してください |
