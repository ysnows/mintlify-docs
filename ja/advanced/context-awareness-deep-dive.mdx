このページでは、[コンテキスト認識](/ja/features/context-awareness)の裏側を説明します。Enconvo が Mac から読み取れる項目、それぞれの読み取り方、メッセージに何を含めるかを決める方法です。モデルに届く内容を制御したいときや、期待したコンテキストが表示されないときにお読みください。

コンテキスト認識は、バックグラウンドで画面を監視することはありません。SmartBar を開いたとき、または自分で項目を追加したときに、直前まで使っていたアプリからコンテキストを読み取ります。

## Enconvo が読み取れるもの

各種類のコンテキストは、メッセージに追加できる項目です。

| コンテキスト項目 | 内容 | Enconvo の読み取り方法 |
|---|---|---|
| **選択したテキスト** | アプリで選択されているテキスト | アクセシビリティ |
| **Current Application Content** | ウィンドウのタイトルとテキスト、アプリが提供する場合はドキュメントのアドレス、ウィンドウのスクリーンショット | アクセシビリティとウィンドウのキャプチャ |
| **Browser Current Tab URL** | 最前面のタブのアドレス、タイトル、ページのテキスト | Apple Events。[ブラウザ](#ブラウザ)を参照 |
| **Finder Selected Items** | Finder で選択されているファイルとフォルダーのパス | Apple Events |
| **Finder Current Directory URL** | 最前面の Finder ウィンドウで開いているフォルダー | Apple Events |
| **Clipboard Text** | クリップボードにあるテキスト | クリップボード。追加したときのみ |
| **User Select Area Screenshot** | 自分で選択した画面の範囲 | 画面キャプチャ |
| **Current Application Screenshot** | 使用中のアプリ | 画面キャプチャ |
| **Current Screen Screenshot** | 画面全体 | 画面キャプチャ |
| **Live Screen Screenshot** | Enconvo のウィンドウを除いた、現在の画面 | 画面キャプチャ |

Finder の項目について Enconvo が読み取るのはパスであり、ファイルの内容ではありません。

### ブラウザ

- **アドレスとタイトル**: Safari、Chrome、Edge、Arc、およびほかの Chromium ブラウザから、Apple Events 経由で読み取ります。Firefox はタブのアドレスを提供しないため、Enconvo は読み取れません。
- **ページのテキスト**: Safari はそのまま提供します。ほかのブラウザでは、Enconvo がアクセシビリティ経由でウィンドウを読み取ります。これは、そのブラウザが最前面のアプリである間のみ機能します。

### そのほかのアプリ

コードエディタ、テキストエディタ、そのほかすべてのアプリでは、**Current Application Content** が使われます。ウィンドウのタイトル、アクセシビリティが公開するテキスト、アプリが提供する場合はドキュメントのアドレス、ウィンドウのスクリーンショットです。テキストの量はアプリによって異なります。

## SmartBar を開くとき

SmartBar を開くと、直前まで使っていたアプリの 3 つのソースを確認します。それぞれの扱いは **設定 → コンテキスト認識**で設定します。

| ソース | デフォルト | 取得するもの |
|---|---|---|
| **選択したテキスト** | **自動追加** | 使用していたアプリで選択されているテキスト |
| **Finder の選択項目** | **提案** | Finder で選択されているファイルとフォルダー |
| **ブラウザの現在のページ** | **提案** | Safari、Chrome、Arc、Edge、またはほかの Chromium ブラウザで開いているページ |

- **自動追加**は、SmartBar が開いた時点で、その項目を入力に追加します。
- **提案**は、コマンドの上に項目を表示し、1 クリックで追加できるようにします。提案されたページのテキストは、クリックしたときにだけ読み取られます。
- **オフ**は、そのソースを対象にしません。

これらの設定を使うのは SmartBar だけです。選択範囲に対して実行するコマンドは、常に選択したテキストを受け取ります。

## 自分でコンテキストを追加する

1. SmartBar で `#` を入力します。
2. 数文字入力して、コンテキスト項目の一覧を絞り込みます。
3. 1 つを選びます。Enconvo がそれを読み取り、メッセージに追加します。

別の文字を使うには、**設定 → SmartBar** の**検索**にある**コンテキスト**を変更します。同じグループで、コマンドの `@`、スキルの `$`、最近のタスクの `>` も設定できます。

## 権限

| 権限 | 必要な用途 |
|---|---|
| **アクセシビリティ** | 選択したテキスト、ウィンドウの内容、Safari 以外のブラウザのページのテキスト |
| **オートメーション** | Finder の項目とブラウザのページ。Enconvo が各アプリを初めて読み取るときに、macOS が確認します |
| **画面収録**(画面とシステムオーディオの収録) | スクリーンショットと、**Current Application Content** でのウィンドウのキャプチャ |

これらは **システム設定 → プライバシーとセキュリティ**で許可します。Enconvo はアクセシビリティの変更を自動的に検知します。一覧の全体は[権限](/ja/configuration/permissions)を参照してください。

## コンテキストとトークン

コンテキストは、モデルのコンテキストウィンドウを消費します。ページのテキストとスクリーンショットは最も大きな項目で、次のような影響があります。

- 返信が遅くなる
- クラウドモデルでは費用が増える
- 会話の履歴に使える余地が減る

<Tip>
長いチャットでは、ページやスクリーンショットを毎回添付するのではなく、必要なメッセージにだけ追加してください。
</Tip>

## プライバシーとデータの流れ

取り込んだコンテキストは、保存された会話やナレッジベースのアイテムの一部になることがあります。モデルへのリクエストや、選択した OCR、埋め込み、文字起こし、そのほかのツールのプロバイダーが、関連するコンテンツを受け取る場合があります。ローカルでの保存とプロバイダーによる処理の違いについては、[プライバシーとセキュリティ](/ja/configuration/privacy-security)を確認してください。

ローカルのチャットモデルを使うだけで、すべてのツールがオフラインになるわけではありません。ブラウザのアクセス、キャプチャ、プロバイダーによる処理を含め、全体の流れを確認してください。macOS の権限は、利用できるコンテキストを減らしますが、サードパーティのアプリのすべてのフィールドを機密として分類できることを保証するものではありません。

## トラブルシューティング

| 問題 | 対処 |
|---|---|
| 選択したテキストやウィンドウの内容が取得できない | **システム設定 → プライバシーとセキュリティ → アクセシビリティ**で Enconvo をオンにしてください。アクセシビリティ経由でテキストを公開しないアプリもあります。その場合は、テキストをコピーして、`#` で **Clipboard Text** を追加してください。 |
| ブラウザのページや Finder の項目が取得できない | **システム設定 → プライバシーとセキュリティ → オートメーション**で、そのアプリに対して Enconvo をオンにしてください。 |
| Firefox からアドレスが取得できない | Firefox はタブのアドレスを提供しません。別のブラウザを使うか、アドレスをコピーしてください。 |
| ページがテキストなしで届く | Safari 以外では、ページのテキストはそのブラウザが最前面にある間のみ読み取られます。ブラウザから SmartBar を開いてください。 |
| コンテキストが別のアプリから取得される | コンテキストは、SmartBar を開いたときに使っていたアプリから取得されます。目的のアプリが最前面になるのを待ってから、SmartBar を開いてください。 |
| スクリーンショットが失敗する | **システム設定 → プライバシーとセキュリティ → 画面収録とシステムオーディオ収録**で Enconvo をオンにしてください。 |
