このページでは[コンテキスト認識](/ja/features/context-awareness)の裏側の仕組みを解説します。Enconvo が Mac から読み取れる項目、それぞれの読み取り方法、そしてメッセージに含める内容をどのように決められるかを説明します。モデルへ渡る情報を細かく管理したいときや、想定したコンテキストが表示されないときに参照してください。

コンテキスト認識はバックグラウンドで画面を監視し続けるものではありません。SmartBar を開いたとき、または自分で項目を追加したときに、その直前まで使っていたアプリからコンテキストを読み取ります。

## Enconvo が読み取れる内容

コンテキストの種類ごとに、メッセージへ追加できる 1 つの項目として扱われます。

| コンテキスト項目 | 含まれる情報 | Enconvo の読み取り方法 |
|---|---|---|
| **選択したテキスト** | アプリ内で選択されているテキスト | アクセシビリティ |
| **現在のアプリケーションのコンテンツ** | ウィンドウのタイトルとテキスト、アプリが提供する場合はドキュメントのアドレス、ウィンドウのスクリーンショット | アクセシビリティとウィンドウキャプチャ |
| **ブラウザの現在のタブの URL** | 最前面タブのアドレス、タイトル、ページテキスト | Apple Events（[ブラウザ](#ブラウザ)を参照） |
| **Finder で選択した項目** | Finder で選択中のファイルやフォルダのパス | Apple Events |
| **Finder の現在のディレクトリ URL** | 最前面の Finder ウィンドウで開いているフォルダ | Apple Events |
| **クリップボードのテキスト** | クリップボードにあるテキスト | クリップボード（追加したときのみ） |
| **選択範囲のスクリーンショット** | ドラッグして選んだ画面領域 | 画面キャプチャ |
| **現在のアプリケーションのスクリーンショット** | 使っていたアプリのウィンドウ | 画面キャプチャ |
| **現在の画面のスクリーンショット** | 画面全体 | 画面キャプチャ |
| **ライブ画面のスクリーンショット** | Enconvo のウィンドウを除いた現在の画面そのまま | 画面キャプチャ |

Finder 項目について Enconvo が読み取るのはパスであり、ファイルの中身そのものではありません。

### ブラウザ

- **アドレスとタイトル**：Safari、Chrome、Edge、Arc、その他の Chromium 系ブラウザから Apple Events 経由で読み取ります。Firefox はタブのアドレスを提供しないため、Enconvo は読み取れません。
- **ページテキスト**：Safari は直接テキストを渡します。その他のブラウザではアクセシビリティ経由でウィンドウを読み取るため、ブラウザが最前面にあるときだけ動作します。

### その他のアプリ

コードエディタ、テキストエディタ、その他すべてのアプリでは **現在のアプリケーションのコンテンツ** として、ウィンドウのタイトル、アクセシビリティが公開しているテキスト、アプリが提供する場合はドキュメントのアドレス、ウィンドウのスクリーンショットを取得します。どれだけテキストを取得できるかはアプリ側の対応に依存します。

## SmartBar を開いたとき

SmartBar を開くと、直前に使っていたアプリ内の 3 つのソースを確認します。それぞれの扱いは **設定 → コンテキスト認識** で決められます。

| ソース | デフォルト | 取得する内容 |
|---|---|---|
| **選択したテキスト** | **自動追加** | 使っていたアプリで選択中のテキスト |
| **Finder の選択項目** | **提案** | Finder で選択中のファイルやフォルダ |
| **ブラウザの現在のページ** | **提案** | Safari、Chrome、Arc、Edge、その他の Chromium 系ブラウザで開いているページ |

- **自動追加** は SmartBar を開いた瞬間に項目を入力欄へ追加します。
- **提案** はコマンドの上部に候補として表示し、ワンクリックで追加できるようにします。提案されたページのテキストは、クリックしたときにだけ読み取られます。
- **オフ** はそのソースを取得しません。

これらの設定を使うのは SmartBar だけです。選択テキストに対して直接実行したコマンドには、常に選択テキストが渡されます。

## 手動でコンテキストを追加する

1. SmartBar で `#` を入力します。
2. 数文字入力してコンテキスト項目のリストを絞り込みます。
3. 項目を選びます。Enconvo がそれを読み取り、メッセージへ追加します。

別の文字を使いたい場合は、**設定 → SmartBar** の **検索** にある **コンテキスト** を変更してください。同じグループで、コマンド用の `@`、スキル用の `$`、最近のタスク用の `>` も設定できます。

## 権限

| 権限 | 必要な対象 |
|---|---|
| **アクセシビリティ** | 選択テキスト、ウィンドウのコンテンツ、Safari 以外のブラウザのページテキスト |
| **オートメーション** | Finder の項目とブラウザのページ。各アプリを初めて読み取るときに macOS が確認します |
| **画面収録**（画面収録とシステムオーディオ録音） | スクリーンショットと **現在のアプリケーションのコンテンツ** に含まれるウィンドウキャプチャ |

**システム設定 → プライバシーとセキュリティ** で許可してください。アクセシビリティの変更は Enconvo が自動で検知します。一覧は[権限](/ja/configuration/permissions)を参照してください。

## コンテキストとトークン

コンテキストはモデルのコンテキストウィンドウを消費します。中でもページテキストとスクリーンショットはサイズが大きく、次のような影響があります。

- 応答が遅くなる
- クラウドモデルでのコストが増える
- 会話の履歴に使える容量が減る

<Tip>
長いチャットでは、毎回添付し続けるのではなく、ページやスクリーンショットが必要なメッセージにだけ追加してください。
</Tip>

## プライバシーとデータの流れ

取得されたコンテキストは、保存された会話やナレッジベースの一部になることがあります。モデルへのリクエストや、選択した OCR・埋め込み・文字起こし・その他のツールプロバイダーが関連データを受け取る場合もあります。ローカル保存とプロバイダーでの処理の違いについては[プライバシーとセキュリティ](/ja/configuration/privacy-security)を確認してください。

ローカルチャットモデルを使うだけでは、すべてのツールがオフラインになるわけではありません。ブラウザアクセス、画面キャプチャ、プロバイダー経由の処理を含め、全体の流れを確認してください。macOS の権限によって取得できるコンテキストを減らすことはできますが、他社製アプリ内のすべての入力欄を機密情報として自動判別・除外できるわけではありません。

## トラブルシューティング

| 問題 | 対処方法 |
|---|---|
| 選択テキストやウィンドウ内容が取得できない | **システム設定 → プライバシーとセキュリティ → アクセシビリティ** で Enconvo をオンにしてください。アクセシビリティ経由でテキストを公開しないアプリもあるため、その場合はテキストをコピーして `#` から **クリップボードのテキスト** を追加してください。 |
| ブラウザのページや Finder 項目が取得できない | **システム設定 → プライバシーとセキュリティ → オートメーション** で対象アプリに対する Enconvo の許可をオンにしてください。 |
| Firefox からアドレスを取得できない | Firefox はタブのアドレスを公開していません。別のブラウザを使うか、アドレスをコピーしてください。 |
| ページのテキストが含まれない | Safari 以外では、ブラウザが最前面にあるときだけページテキストを読み取ります。ブラウザを開いた状態で SmartBar を開いてください。 |
| 別のアプリからコンテキストが取得される | コンテキストは SmartBar を開いた直前に使っていたアプリから取得されます。目的のアプリを最前面にしてから SmartBar を開いてください。 |
| スクリーンショットが失敗する | **システム設定 → プライバシーとセキュリティ → 画面収録とシステムオーディオ録音** で Enconvo をオンにしてください。 |
