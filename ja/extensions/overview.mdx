---
title: "プラグイン"
description: "Enconvo に新しいコマンド、ツール、連携機能を追加するプラグインを検索・インストール・管理する方法を説明します。"
---

プラグインを使うと、Enconvo にコマンド、プロバイダー、ツール、API ルートを追加できます。**設定 → プラグイン** を開くと、カタログの検索、必要なもののインストール、インストール済みプラグインの管理を行えます。

## プラグインを見つけてインストールする

<Steps>
  <Step title="プラグインを開く">
    **設定 → プラグイン** を開きます。**⌘K** を押すと検索ボックスにジャンプします。
  </Step>
  <Step title="検索する">
    実行したいタスクやプラグイン名で検索します。現在のタブに一致するものがない場合は、他のタブの結果が表示されます。
  </Step>
  <Step title="プラグインページを開く">
    プラグインをクリックして、説明、含まれる機能、必要な設定を確認します。
  </Step>
  <Step title="インストールして設定する">
    まだインストールされていない場合は **インストール** をクリックします。その後、求められたプロバイダーの認証情報やコマンド設定を追加します。
  </Step>
  <Step title="使ってみる">
    **今すぐ試す** をクリックするか、SmartBar からコマンドを実行するか、使用する Agent でそのツールを有効にします。
  </Step>
</Steps>

プラグインのページには、そのプラグインに含まれるコマンドと設定が一覧表示されます。Enconvo 内の別の場所からコマンドの設定を開くと、そのプラグイン内の該当コマンドに移動します。

[メール](/ja/integrations/email) のようにチャットウィンドウ内に専用ビューを持つプラグインでは、ページ上に **開く** ボタンが表示され、メールボックスの追加などの操作を 1 クリックで開けます。複数のビューを持つプラグインでは **開く** メニューが表示されます。

## プラグイン画面の構成

| タブ | 表示内容 |
| --- | --- |
| **Enconvo** | カテゴリ別のカタログです。上部の **インストール済み** には接続済みのコネクタやインストール・作成したプラグインが表示され、**最近の追加** には新しく追加された項目が表示されます。 |
| **Built-in** | Enconvo に最初から含まれているプラグインです。**Search** には SmartBar から検索できるリストが、**Control** にはコンピュータ操作とブラウザ操作が含まれます。 |
| **Mac Apps** | Calendar、Mail、Notes など、Agent が利用できるこの Mac 上のアプリです。接続時はアカウントではなく macOS の権限が求められます。詳しくは [Apple アプリ](/ja/integrations/apple-ecosystem) を参照してください。 |
| **PopBar** | [PopBar](/ja/features/popbar) にボタンを追加する PopClip 互換の拡張機能です。 |
| **Personal** | 自分で作成またはインポートしたプラグイン、および Enconvo ストアに公開したプラグインです。 |

カタログ外のプラグインを追加するには、**プラグインを作成** または **追加** メニューを使用します:

| オプション | 機能 |
| --- | --- |
| **プラグインを作成** | 必要な内容を説明すると、Agent がプラグインを作成・テスト・インストールします。 |
| **プラグインのアーカイブをアップロード…** | `.enconvo` ファイル、または Claude Code や Codex プラグインの `.zip` をインストールします。 |
| **GitHub から追加…** | プラグインリポジトリ、または Claude Code / Codex マーケットプレイスからインストールします。 |
| **MCP サーバーを追加…** | [MCP サーバー](/ja/features/mcp) の設定画面を開きます。 |
| **PopBar 拡張機能を追加…** / **PopClip からインポート…** | PopClip 拡張機能を PopBar に追加します。 |
| **新規スキル…** | [スキル](/ja/configuration/skills) を開きます。 |

## 目的に合った機能を探す

| タスク | ガイド |
| --- | --- |
| 文章の改善や翻訳 | [ライティングツールキット](/ja/features/writing-tools)、[翻訳](/ja/ai/translate) |
| ウェブ検索やページ閲覧 | [ウェブ検索](/ja/ai/web-search)、[ウェブページを読む](/ja/ai/web-fetch) |
| ファイル操作やターミナル実行 | [ファイルツール](/ja/ai/file-tools)、[コードランナー](/ja/ai/code-runner) |
| 画像・動画・音声の生成 | [プロバイダーカタログ](/ja/providers/catalog) |
| Mail・Calendar・Notes・Reminders の操作 | [Apple アプリ](/ja/integrations/apple-ecosystem) |
| 外部ツールとの接続 | [MCP サーバー](/ja/features/mcp) |
| 再利用可能な Agent 手順の追加 | [スキル](/ja/configuration/skills) |

ストアの一部プラグインは、サービス全体のツールとガイドをまとめて提供します:

- **Shopify** を使うと、Agent が Shopify 公式 CLI を通じて Shopify ストアを管理でき、変更を適用する前に内容を提示して確認を求めます。複数ストアに対応しており、ストア名が指定されていない場合は確認し、すべての変更にストア名を明記し、複数ストア対象の変更はストアごとに実行します。
- **Expo** は従来の読み取り専用 Expo コネクタに代わり、Expo チーム公式のスキルと Expo MCP サーバーを提供します。Agent が Expo / React Native アプリのビルド・アップグレード・出荷、EAS ビルド・ログ・クラッシュ・レビューの読み取りを行い、ビルドと提出はユーザーが承認した場合にのみ実行します。既存の Expo サインイン状態はそのまま引き継がれます。

**Obsidian**、**Tailscale**、**Cloudflare** もプラグインストアのプラグインとして提供されており、プラグイン画面からインストールできます。すでにインストール済みのものは引き続き動作し、自動更新されます。Agent は、Obsidian・Tailscale・Cloudflare・Shopify のうちどれがインストール済みかを最初から認識しています。

ドキュメント化されているコマンド群の一覧は [ビルトインコマンドカタログ](/ja/extensions/built-in-extensions) を参照してください。ストアの掲載内容やビルドに含まれるプラグインは異なる場合があります。

## コマンド・プロバイダー・ツール

- **コマンド** はユーザーが実行するアクションです。
- **プロバイダー** はモデルや音声などの機能を提供します。
- **ツール** は Agent が呼び出せるアクションです。

プラグインをインストールしても、そのプロバイダーが自動的にデフォルトになったり、すべての Agent でツールが有効になったりするとは限りません。

SmartBar では、コマンドピッカー（デフォルトは `@`）を使うか、コマンドのタイトルを検索してください。`/` アクションメニューは別の機能であり、プラグイン名を指定するプレフィックスではありません。

## コネクタで複数アカウントを使う

Notion、Webflow、Linear など、Mac 上でサインインするコネクタでは、複数のアカウントを保持できます。

- コネクタのページで **別のアカウントを接続** を選択してアカウントを追加します。すべてのアカウントが **接続済みアカウント** に一覧表示されます。
- Agent が送信や作成に使用するアカウントで **デフォルトにする** を選択します。読み取りはすべてのアカウントから行われます。
- リクエスト内で「仕事用のアドレスから送信して」のようにアカウントを指定すると、Agent はそのアカウントを使用します。
- **接続解除** で 1 つのアカウントを削除でき、**すべてのアカウントの接続を解除** ですべて削除できます。

クライアントのワークスペースでは、各コネクタがそのワークスペース専用のデフォルトアカウントを保持でき、**次のデフォルト** としてワークスペース名が表示されます。別のアカウントを指定しない限り、Agent はそのクライアントのアカウントを使用します。

## 無効化・更新・アンインストール

プラグインのページでは次の操作ができます:

- スイッチでプラグインのオン / オフを切り替えます。オフの間は Agent が見つけたり使ったりできず、SmartBar にも表示されず `@` で呼び出せません。設定は保持されます。
- **⋯** メニューには **設定**、**アップデートを確認**、**アンインストール** があります。Enconvo に最初から含まれているプラグインはアンインストールできません。

プラグインをアンインストールする前に、それを使用している Agent、ワークフロー、カスタムコマンドを確認してください。コマンドをリセットすると設定が初期状態に戻ります。共有プロバイダーをリセットすると、他の機能が使っている認証情報も変更される場合があるため、[認証情報](/ja/configuration/credentials) を参照してください。

## プラグインを共有する

自分で作成したプラグインや、この Mac 上にフォルダがあるプラグインは、リンクを共有して他の人がインストールできるようにできます。

1. プラグインのページで **共有…** をクリックします。求められた場合は Enconvo アカウントにサインインします。
2. **インストール可能なユーザー** で **リンクを知っている全員** または **プラグインストア** を選択します。
3. **公開** をクリックし、**リンクをコピー** して共有相手に送ります。

Enconvo はリンクからインストールされる前に各バージョンを検証・レビューし、リンクを開くと enconvo.com 上のプラグインページが表示されます。インストールした人はそれぞれ独自のコピーを受け取り、あなたのデータ、API キー、サインイン情報はこの Mac に残ります。

共有したプラグインを更新するには、もう一度 **共有…** をクリックして新しいバージョンを送信するか、**インストール可能なユーザー** を変更するか、**共有を停止** をクリックします。共有を停止するとリンクは無効になりますが、すでにインストールした人のコピーは残ります。レビューでバージョンが却下された場合、**共有…** に理由が表示され、**チャットで修正** が提示されます。[Space](/ja/features/spaces) を共有する場合は [Space のガイド](/ja/features/spaces) を参照してください。

## 独自のプラグインを作る

TypeScript SDK と CLI の使い方は [拡張機能の開発](/ja/extensions/developing) を参照してください。CLI ではビルド・インストール・スキーマ生成・公開が `enconvo plugin` サブコマンドにまとめられています。公開すると、自分の開発環境以外からもプラグインを利用できるようになります。

Enconvo は Codex、Claude Code、およびポータブルプラグインのインストールにも対応しています。詳しくは [Plugin Formats](/extensions/plugin-formats) と [プラグインのインストール](/ja/extensions/installing-plugins) を参照してください。
