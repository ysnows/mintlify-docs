ほとんどのユーザーは、Enconvo の**プラグイン**ページにあるプラグインストアからプラグインをインストールしています。Enconvo はそれ以外にも、開発者が GitHub やプラグインマーケットプレイスで公開している Codex や Claude Code のプラグインを含め、さまざまな場所からプラグインをインストールできます。Enconvo が読み込めるパッケージについては、[プラグイン形式](/extensions/plugin-formats)をご覧ください。

アプリからインストールする場合は、[プラグインページから](#プラグインページから)と[チャットから](#チャットから)をお読みください。それ以降のセクションは開発者やパワーユーザー向けで、ターミナルからのインストール、プラグインマーケットプレイスの追加、更新とアンインストール、自作プラグインの共有について説明します。

<Warning>
Enconvo によってレビューされているのは、Enconvo ストア内のプラグインのみです。それ以外の場所にあるプラグインは MCP サーバーを通じて Mac 上のプログラムを実行できるため、信頼できる提供元からのみインストールしてください。
</Warning>

## プラグインページから

**プラグイン**ページで**追加**をクリックします：

| オプション | 内容 |
|---|---|
| **プラグインを作成** | Enconvo のエージェントと一緒にプラグインを作成するチャットを開始します。 |
| **プラグインのアーカイブをアップロード…** | `.enconvo` パッケージ、`.dxt` デスクトップ拡張機能、または Claude Code / Codex プラグインの `.zip` ファイルをインストールします。 |
| **GitHub から追加…** | GitHub、git、npm、またはフォルダから、プラグインやプラグインマーケットプレイス内のプラグインをインストールします（下記参照）。 |
| **MCPサーバーを追加…** | プラグインでラップせずに単一のサーバーを接続するため、MCP 設定を開きます。 |
| **PopBar 拡張機能を追加…** | リンク、ファイル、または `#popclip` スニペットから PopBar 拡張機能をインストールします（[PopBar 拡張機能](/ja/features/popbar)を参照）。 |
| **新規スキル…** | 独自のスキルを作成するため、スキル設定を開きます。 |
| **開発者ガイド** | [拡張機能の開発](/ja/extensions/developing)を開きます。 |

追加したものは **Enconvo** タブの上部にある**インストール済み**に一覧表示されます（接続したコネクタと、インストールまたは作成したプラグインが名前順に表示されます）。すべてを見るには**インストール済み**をクリックします。Enconvo に最初から含まれるプラグインはここには表示されません。PopBar 拡張機能には独自の **PopBar** タブがあり、Enconvo のレビュー済みカタログが用意されています。詳しくは [PopBar 拡張機能](/ja/features/popbar)をご覧ください。

### GitHub から追加

プラグインの場所を貼り付けて**プレビュー**を押します：

- `owner/repo`、または GitHub リンク（フォルダへのリンク `/tree/<branch>/<folder>` を含む）
- リポジトリ内のプラグインの場合は `owner/repo/folder`（バージョンを固定するには `@branch` または `@tag` を付与）
- 任意の https git アドレス
- `npm:<package>`（バージョン固定には `@version` を付与）
- プラグインの `.zip` への https リンク
- Mac 上のフォルダ

プライベートの GitHub リポジトリや git リポジトリも利用できます。Enconvo は Mac 上ですでにサインイン済みの GitHub アカウントまたは SSH キーを使用するため、パスワードを入力する必要はありません。

インストール前にはプラグインの詳細が表示されます：形式（Codex、Claude Code、ポータブル、デスクトップ拡張機能、または Enconvo）、バージョン、開発者、スキル、MCP サーバーとフック、そして含まれている ChatGPT アプリ（Enconvo はこれを読み込みません）です。各 MCP サーバーについては、Mac 上で起動するかインターネット経由で接続するかが表示されます。プラグインのフックは Mac 上でコマンドを実行するため、**フックの実行を許可**にチェックを入れない限りオフのままになります。**インストール**をクリックすると、そのプラグインのページが開きます。**提供元**行にはプラグインの入手元（GitHub や git の場合はコミットを含む）とリポジトリまたは npm ページへのリンクが表示され、下部の注記にはプラグインが申告している開発者名が表示されます。Enconvo 自身のプラグインおよびストア掲載プラグインのみが Enconvo 製と表示されます。この方法でインストールしたプラグインは**個人**の下に表示されます。同じ提供元から再インストールするとプラグインが更新されます。同じ名前のプラグインが別の場所からすでにインストールされている場合は、先にアンインストールしてください。

アドレスがプラグインマーケットプレイスの場合、ダイアログにはそのマーケットプレイスのプラグイン一覧とそれぞれの**インストール**ボタンが表示されます。いずれか 1 つをインストールするとそのマーケットプレイスが追加され、次回ダイアログを開いたときに**追加したマーケットプレイス**に表示されます。

Enconvo プラグインのソースコードは動作前にビルドする必要があるため、ダイアログには代わりにターミナルで実行する `enconvo plugin install` コマンドが表示されます。

## チャットから

お手持ちのプラグインで対応できないことを Enconvo のエージェントに頼むと、エージェントは Mac 上のプラグインマーケットプレイスからプラグインを探せます。対象となるのは Enconvo に追加済みのマーケットプレイスと、Codex または Claude Code が持っていて Enconvo にはまだないマーケットプレイス（Codex に付属する OpenAI Curated マーケットプレイスを含む、[Codex や Claude Code で追加したマーケットプレイス](#codex-や-claude-code-で追加したマーケットプレイス)を参照）です。検索時は Mac 上にすでにあるカタログのコピーのみを読み取り、ダウンロードは行いません。すでにインストール済みのプラグインと、別の場所からインストール済みのプラグインと同名のものは除外されます。

見つかった場合、エージェントはチャット内にカードを表示し、**インストール**をクリックするまで何もインストールされません：

- Enconvo に追加済みのマーケットプレイスの場合、カードにはプラグインが Mac 上で起動する、または接続する MCP サーバー、スキル、および依存する他のプラグインが表示されます。
- Codex または Claude Code にのみあるマーケットプレイスの場合、インストールするとそのマーケットプレイスが Enconvo に追加される旨がカードに表示されます。それ以前には Enconvo がプラグインの中身を読み取れないため、カードに一覧表示はできません。

いずれの場合も、プラグインのフックは**プラグイン**でオンにするまでオフのままです。依存プラグインをインストールできないなどの理由でインストールできない場合は、カードの代わりにエージェントがその旨を伝えます。

### ChatGPT のプラグイン

[ChatGPT プラグインディレクトリ](https://chatgpt.com/plugins)のプラグインは Enconvo にはインストールできません。その多くは ChatGPT 内でしか動作しない ChatGPT アプリであり、残りのプラグインも OpenAI が ChatGPT と Codex のみに提供しているためです。Mac 上で Codex にサインインしている場合、エージェントは Codex が保持するコピーからそのディレクトリを把握しています。ディレクトリのプラグイン名を挙げたり chatgpt.com のリンクを貼り付けたりすると、エージェントはインストールできない理由を説明し、同等の働きをするコネクタ、MCP サーバー、スキル、またはお使いのマーケットプレイス内にある同名プラグインを提案します。ファイルを含むディレクトリ内のプラグインの多くは、Codex に付属するマーケットプレイスである OpenAI Curated（OpenAI の公開リポジトリ `openai/plugins`）にも同名プラグインがあります。エージェントはそのプラグインを提案し、インストールすると OpenAI Curated が Enconvo に追加されます。Enconvo はそれらのプラグインに含まれる ChatGPT アプリは読み込まず、スキルと MCP サーバーのみを読み込みます。

**GitHub から追加**でも chatgpt.com のリンクは利用できず、ダイアログに同じ説明が表示されます。

## コマンドラインから

`plugin install` は GitHub、git、npm、ウェブ上の zip、フォルダ、またはマーケットプレイスからプラグインをインストールします。Enconvo 2.5.6 以降が起動している必要があります。

```sh
npx -p @enconvo/api enconvo plugin install <source>
```

| 提供元 | 例 |
|---|---|
| GitHub リポジトリ（任意で中のフォルダとブランチ・タグ・コミットを指定） | `acme/notes`, `acme/plugins/notes@v1.2.0` |
| GitHub アドレス | `https://github.com/acme/plugins/tree/main/notes` |
| その他の https 経由 git リポジトリ（git が必要。ssh アドレスは GitHub のみ対応） | `https://git.example.com/notes.git`, `git@github.com:acme/notes.git` |
| npm パッケージ | `npm:@acme/notes-plugin`, `npm:@acme/notes-plugin@1.2.0` |
| ウェブ上のプラグイン zip（公開 https のみ） | `https://downloads.acme.com/notes-1.2.0.zip` |
| Mac 上のフォルダ | `./notes`, `~/code/notes`, `/Users/ada/notes` |
| 追加済みマーケットプレイス内のプラグイン | `notes@acme-plugins` |

<Note>
`plugin install` と `plugin marketplace` には 0.1.174 より新しい `@enconvo/api` リリースが必要です。`@enconvo/api` に依存するプロジェクト内では `npx enconvo …` だけで実行できます。`marketplace import` には Enconvo 2.5.7 以降も必要です。
</Note>

`--preview` を付けると、インストールせずに何がどこからインストールされるかを確認できます。

指定元がプラグインではなくプラグインマーケットプレイスの場合、`plugin install` はその中のプラグイン一覧を表示します。200 件を超えるマーケットプレイスでは最初の 200 件と残りの件数が表示され、`plugin marketplace add` を使うと全件を確認できます。`--plugin` で 1 つ選ぶと、マーケットプレイスの追加も同時に行われます：

```sh
npx -p @enconvo/api enconvo plugin install acme/plugins --plugin notes
```

### インストール時の動作

- **設定**：API キーなどの必須設定があるプラグインは、インストール後に設定の入力を求めます。`plugin install` は該当項目を表示しますので、プラグインのページで入力してください。
- **ソースからの Enconvo プラグイン**：GitHub リポジトリまたはフォルダに未ビルドの Enconvo プラグインが含まれる場合、`plugin install` が先にビルドを行います。フォルダの場合は `npm install` のあとその場でビルドされます。
- **オンボーディング**：プラグインにオンボーディングスキルが指定されている場合、初回インストール後に Enconvo がその実行を提案します。
- **サインイン**：Notion や Figma のようにプラグインの MCP サーバーがサインインを必要とする場合、インストール直後にプラグインページに**サインイン**が表示されます。Enconvo がブラウザでサーバーのサインインページを開き、接続が完了すると次のサーバーを案内します。`plugin install` の場合は代わりにサーバー名が表示されます。スキップしたサインインは**設定 → MCP サーバー**に保留されます。
- **フック**：プラグインの[フック](/extensions/plugin-formats#hooks)はコマンドを実行するため、オフの状態でインストールされます。`--preview` で一覧を確認でき、プラグインページの**フックを許可**スイッチで有効にできます。許可したフックは、フック自体が変更されないアップデートであればオンのまま維持されます。
- **依存関係**：マーケットプレイスの Claude Code プラグインが他のプラグインを必要とする場合、Enconvo はそれらも一緒にインストールします（[プラグインマーケットプレイス](#プラグインマーケットプレイス)を参照）。`--preview` は依存プラグインの一覧と、インストール済み・新規インストール予定・インストール不可の別を表示します。マーケットプレイスエントリで宣言された依存関係が許可されていないマーケットプレイスのものだった場合、インストールは停止します。プラグイン自身の `plugin.json` で宣言された依存関係がそうだった場合は除外してインストールを続行します。依存プラグインのフックはオフのままとなり、本体をアンインストールしても整理（prune）するまで残ります（[アンインストール](#アンインストール)を参照）。
- **使い方**：Codex と同様に、チャットで `@` を入力してプラグインを選ぶか、プラグインページの**試してみる**にあるプロンプトをクリックします。どちらの方法でもチャットにプラグインが添付されます。カテゴリを指定していない Codex や Claude Code のプラグインも含め、インストール済みのすべてのプラグインが `@` メニューに表示されます。
- **同名のプラグイン**：同じ提供元から再インストールするとプラグインが更新されます。ストアなど別の場所から同名のプラグインがすでにインストールされている場合、Enconvo は上書きせず、先にアンインストールするよう求めます。

Enconvo が起動していない場合でも、`plugin install` は GitHub から Enconvo プラグインをビルドしてインストールできます。それ以外の場合は、Enconvo を開いてからもう一度お試しください。

## プラグインマーケットプレイス

マーケットプレイスとは、リポジトリやフォルダ内にあるプラグインのカタログです。Enconvo は Codex の `.agents/plugins/marketplace.json` と Claude Code の `.claude-plugin/marketplace.json` の両方に対応しています。

```sh
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins   # GitHub、git アドレス、またはフォルダ
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins --ref v2   # ブランチ、タグ、またはコミットを指定
npx -p @enconvo/api enconvo plugin marketplace list               # 追加済みマーケットプレイスとそのプラグイン一覧
npx -p @enconvo/api enconvo plugin install notes@acme-plugins     # その中の 1 つをインストール
npx -p @enconvo/api enconvo plugin marketplace refresh            # 新しいプラグインがないか再取得
npx -p @enconvo/api enconvo plugin marketplace remove acme-plugins
```

`refresh` は `upgrade`（Codex のコマンド名）や `update`（Claude Code のコマンド名）でも動作し、`--ref v2` は `acme/plugins@v2` と同じ意味です。

プラグインページでは、**追加 → GitHub から追加…** を開いてマーケットプレイスのアドレスを貼り付けるか、**追加したマーケットプレイス**から追加済みのものを選べます。

Enconvo は GitHub または git からのマーケットプレイスのコピーを保持し、フォルダマーケットプレイスはその場所から直接読み取ります。マーケットプレイスを削除しても、そこからインストールしたプラグインは残ります。

### Codex や Claude Code で追加したマーケットプレイス

この Mac で Codex や Claude Code にマーケットプレイスを追加済みの場合、または Codex が OpenAI Curated マーケットプレイスを取得済みの場合、`marketplace list` に Enconvo 未登録のものが表示され、`import` を使ってアドレスを再入力せずに追加できます：

```sh
npx -p @enconvo/api enconvo plugin marketplace import                            # すべて取り込む
npx -p @enconvo/api enconvo plugin marketplace import claude-plugins-official    # 指定したものだけ取り込む
```

Enconvo は Codex の `~/.codex/config.toml`、OpenAI Curated のコピー、個人用の `~/.agents/plugins/marketplace.json`、および Claude Code の既知のマーケットプレイス一覧からそれらを検出します。ファイルを読み取るだけで、どちらのアプリの設定も変更しません。OpenAI Curated は GitHub の `openai/plugins` から追加されます。Codex 独自ツール用のプラグインが入ったその他の付属マーケットプレイスと、`marketplace.json` ファイルのウェブアドレスから追加された Claude Code マーケットプレイスは対象外です。両方のアプリに同名のマーケットプレイスがある場合は Codex のものが提案されます。

OpenAI Curated などの Codex マーケットプレイスには、各プラグインの名前と入手元のみが記載されています。マーケットプレイス自身のフォルダ内にあるプラグインについて、Enconvo は Codex と同様にプラグインのマニフェストからタイトル、説明、カテゴリ、開発者を表示し、エージェントは名前だけでなく機能内容からも見つけられるようになります。マーケットプレイスエントリ自体の記述がある場合はそちらが優先されます。

Gmail、Google Drive、Outlook、Teams など OpenAI Curated の一部のプラグインは ChatGPT で Codex にサインインしている場合のみ動作するため、Codex は API キーでサインインしているユーザーにはそれらを表示しません。Enconvo も ChatGPT にはサインインしないため、ChatGPT サインインが必要として表示し、インストールは行わず、エージェントも提案しません。これらのサービスには、各提供元自身の MCP サーバーまたはコネクタを追加してください。

### マーケットプレイスのプラグインの入手元

マーケットプレイスのプラグインは、マーケットプレイス内のフォルダ、別の GitHub リポジトリ、git アドレス、git リポジトリ内のフォルダ、npm、またはウェブ上の zip（Claude Code の `archive` ソース）から取得できます。Codex マーケットプレイスで `NOT_AVAILABLE` と記されたプラグインはインストールできません。

`./plugins/notes` のように書かれたフォルダソースは、マーケットプレイスのルートから読み取られます。`notes` のような名前のみの指定は、Claude Code と同様に `metadata.pluginRoot` で指定されたフォルダから読み取られるため、そのフィールドが必要です。

GitHub、npm、またはウェブからのダウンロードには最大 3 分かかることがあります。それ以上かかる場合、Enconvo は処理を中止し、接続を確認するよう求めます。

zip ファイルは、リンクを直接貼り付けた場合でもマーケットプレイスに記載されている場合でも、公開 https アドレスからのみダウンロードされ、リダイレクトは最大 5 回までたどります。マーケットプレイスに `sha256` が記載されている場合、一致しないダウンロードは拒否されます。プラグインは zip の直下にあっても、1 つのフォルダの中に入っていても構いません。

### Claude Code マーケットプレイスのエントリ

Claude Code マーケットプレイスのエントリは、Claude Code と同じ方法でプラグイン自身の `plugin.json` と連携します：

- エントリはプラグイン自身の項目に加えて `commands`、`agents`、`skills`、`outputStyles`、`themes` を追加でき、同じイベントに対するプラグインの `hooks` はエントリの `hooks` で置き換えられます。
- `"strict": false` のエントリがこれらのいずれかを列挙しており、かつプラグイン側に `plugin.json` がある場合は、マニフェストの競合として拒否されます。定義はどちらか一方にまとめてください。
- プラグインに `plugin.json` がない場合は、エントリ自体がそのマニフェストになります。
- エントリの名前、説明、作者、その他の掲載情報が表示され、バージョンにはプラグインのものが使われます。
- マーケットプレイスの `renames` は追跡されます。旧名でインストールされたプラグインは新しい名前で更新を続け、旧名でインストールしても新しい名前が見つかります。`null` にリネームされた名前はマーケットプレイスから削除されたことを意味し、Enconvo はその旨を伝えます。プラグイン自身のマニフェストでも名前が変わった場合は、Enconvo がマニフェストの名前をプラグイン名として扱うため、古いプラグインをアンインストールしてから新しいものをインストールするよう求めます。
- エントリまたは `plugin.json` にあるプラグインの `dependencies` も一緒にインストールされます。それぞれ名前（`"formatter"`）、名前とマーケットプレイス（`"formatter@acme-tools"`）、その後に `^` 範囲を付けたもの（`"formatter@acme-tools@^2.1"`）、または semver 範囲を含む `{ "name", "marketplace", "version" }` の形式で指定します。別のマーケットプレイスを指定しない限り、依存関係はプラグイン自身のマーケットプレイスから取得されます。別のマーケットプレイスを指定するには、インストール元のマーケットプレイスの `allowCrossMarketplaceDependenciesOn` にそのマーケットプレイスが記載されている必要があります。`version` 範囲を持つ依存関係は、その範囲および他のインストール済みプラグインが課す範囲内で最も高いリリースタグ（`<plugin>--v<version>`）からインストールされます（プラグイン自身のリポジトリ、またはマーケットプレイス内のプラグインの場合はマーケットプレイスのリポジトリから取得。git リポジトリ内であればマーケットプレイスフォルダも対象になります）。該当するタグがない場合、マーケットプレイス内のプラグインはマーケットプレイスにある状態でインストールされ、独自リポジトリのプラグインは拒否されます。どの単一バージョンも満たせない範囲がある場合はインストールが拒否され、更新も範囲内に留まります。すでにインストール済みの依存関係はそのまま残され、`version` 範囲外のものは警告が表示されます。

### 共有前にマーケットプレイスを検証する

マーケットプレイスを共有する前に、マーケットプレイスとそこに含まれるすべてのプラグインを検証してください。ルールは `claude plugin validate` が適用するものに加え、`.agents/plugins/marketplace.json` に対する Codex のルールに基づきます（[検証コード](/extensions/validation-codes#marketplaces)を参照）。エラーがあると、一覧に表示されたとしても Claude Code がマーケットプレイスを追加したりプラグインをインストールしたりできなくなります（エントリ内のフィールドの型違い、プラグインにつながらない `renames`、拒否される `relevance` シグナル、`claude-plugins-hub` のように Anthropic 公式のものに見えるマーケットプレイス名など）。警告は、スペルミスのフィールドなど Claude Code が無視する点や、Claude Desktop が拒否する名前を対象とします。

```sh
npx -p @enconvo/api enconvo plugin validate path/to/marketplace
```

## アップデート

Enconvo のプラグインアップデート確認は、GitHub、git、npm、フォルダ、マーケットプレイスからインストールしたプラグインも対象としており、ストアのものと一緒に更新一覧に表示します。リポジトリはダウンロードせずに最新コミットを確認し、npm には最新バージョンを問い合わせ、インストール済みフォルダに変更がないかを検出し、マーケットプレイスが `sha256` で固定している zip についてはハッシュ値の変更を検知します。更新を実行すると、同じ提供元からプラグインを再インストールします。

1 つのプラグインを確認するには、そのプラグインのページを開き、**⋯** メニューから**アップデートを確認**を選びます。新しいバージョンがある場合は、表示されるメッセージで**アップデート**をクリックします。

または Claude Code の `claude plugin update` と同様に、ターミナルから更新することもできます：

```bash
npx -p @enconvo/api enconvo plugin update notes                # 入手元やストアから更新
npx -p @enconvo/api enconvo plugin update notes@acme-plugins   # そのマーケットプレイスから入れた場合のみ更新
```

最初に確認を行い、新しいバージョンがなければすでに最新である旨を表示して何も変更しません。更新がある場合は、アップデート一覧と同じ方法でプラグインを更新します。

## アンインストール

プラグインページのメニューまたはプラグインページからアンインストールできます（最初に確認が表示されます）。ターミナルからも実行できます：

```bash
npx -p @enconvo/api enconvo plugin uninstall notes            # 別名: remove, rm
npx -p @enconvo/api enconvo plugin uninstall notes --prune    # 不要になった依存プラグインも削除
npx -p @enconvo/api enconvo plugin prune --dry-run            # 削除せずに一覧表示
npx -p @enconvo/api enconvo plugin prune                      # 削除を実行（別名: autoremove）
```

プルーニング（prune）は、Claude Code の `claude plugin prune` と同様に、他のプラグインが必要としたためにインストールされたプラグインのうち、現在どのプラグインからも必要とされなくなったものだけを削除します。ユーザー自身がインストールしたプラグインが削除されることはなく、依存プラグインを自分で再インストールすると自身のプラグイン扱いになります。ターミナルでは、Enconvo は削除対象を一覧表示して先に確認を求めます。質問をスキップするには `-y` を追加してください（対話確認できない場合の `--prune` には必須です）。プラグインページからのアンインストールはまだプルーニングに対応していません。

## 自作プラグインを公開する

Enconvo ストアにプラグインを掲載するには、[プラグインストアガイドライン](/ja/extensions/publishing-guidelines)をご覧ください。誰でもインストールできるリンクを送るには、プラグインページの**共有…**をクリックします（[プラグインを共有する](/ja/extensions/overview)を参照）。Enconvo を通さずに共有するには、GitHub またはマーケットプレイスにプッシュしてください。受け取った側は**GitHub から追加…**や上記のコマンドでインストールできます。

### リリースにタグを付ける

`plugin tag` は、Claude Code の `claude plugin tag` と同様に、リリースするコミットに `<plugin>--v<version>` という名前の git タグを付けます。別のプラグインの依存関係がバージョン範囲を指定するとき、Claude Code と Enconvo はこれらのタグから選択し、誰でも `acme/plugins/notes@notes--v1.2.0` のように指定してそのリリースをインストールできるようになります。

```sh
npx -p @enconvo/api enconvo plugin tag plugins/notes --dry-run   # 検証し、git コマンドを表示
npx -p @enconvo/api enconvo plugin tag plugins/notes --push      # HEAD にタグを付けて origin にプッシュ
```

バージョンはプラグインのマニフェスト（マニフェストにない場合はマーケットプレイスエントリ）から取得され、semver（`1.2.0`）である必要があります。タグ付けの前に `plugin tag` は `plugin validate` と同じチェックを実行し、マーケットプレイスエントリとバージョンが異なる場合、プラグインフォルダ内に未コミットのファイルがある場合、またはそのタグがすでに存在する場合は停止します。新しいリリースではバージョンを上げてください。既存のタグを移動したい場合は代わりに `--force` を使います。Codex、Claude Code、ポータブル、Enconvo のどのプラグインも同じようにタグ付けするため、パッケージに含まれるすべてのマニフェストが同じバージョンを記載している必要があります。`-m` でタグメッセージを設定でき（`%s` がバージョンになります）、`--remote` で `--push` 先のリモートを指定できます。`plugin install` と同様に、0.1.174 より新しい `@enconvo/api` リリースが必要です。
