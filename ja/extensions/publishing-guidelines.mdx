このページは、Enconvo のプラグインストアにプラグインを提出しようとしている開発者向けです。審査担当者が確認する点、バージョンごとに送る審査資料、`plugin publish` の前に実行するチェックリスト、提出後の流れをまとめています。

Enconvo は、プラグインストアに提出されたすべてのバージョンを、ほかのユーザーがインストールできるようになる前に審査します。このガイドラインは、ストアが受け付けるすべての種類のプラグインに適用されます。Enconvo、Codex、Claude Code、ポータブルプラグイン、そしてスキルのみで構成されたプラグインも対象です。内容は [OpenAI のプラグインガイドライン](https://developers.openai.com/apps-sdk/app-submission-guidelines)に沿っているため、これを満たしたプラグインは OpenAI のプラグインポータルへの提出にもほぼ対応できます。

## まずプラグインを確認する

提出する前に、次を実行してください。

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate` は自動で確認できる項目を検出し、`scan` は MCP サーバーを持つプラグインのツールを確認します。報告される各問題の意味は [Validation Codes](/extensions/validation-codes) で説明しています。それ以外は、以下のとおり審査担当者が手作業で確認します。

## 目的と品質

- プラグインは、Enconvo にまだない便利な機能を、最後まで完成した形で提供します。プレースホルダー、デモ専用、お試し版のプラグインは却下されます。
- 動作が予測可能です。ネットワークエラー、権限の不足、不正な入力などで失敗したときは、何も表示せずに失敗するのではなく、何が起きたかを伝えます。
- 自分が所有している、または使用許諾を受けているコード、名前、アイコン、コンテンツだけを使います。ほかの製品になりすましたり、Enconvo やほかの誰かが推奨していると思わせたりしません。

## 名前、説明、掲載内容

- **名前とタイトル**: わかりやすく、具体的にします。一般的すぎる単語 1 語は避け、会社名に「MCP」「MCP Server」「Plugin」を付け足さないでください。
- **説明**: プラグインの機能を正確に述べます。ほかの製品との比較、裏付けのない主張、価格、割引、無料トライアルの案内は書かないでください。
- **アイコンとスクリーンショット**: アイコンは 5 MB までの PNG、JPEG、WebP、GIF です。スクリーンショットは最大 8 枚まで `metadata/` フォルダーに入れ、ファイル名の順に表示されます。実際に動作している様子を写してください。
- **サポート**: 連絡手段を用意してください。`interface.websiteURL` と `interface.supportURL` を設定するか、ウェブサイトには `homepage` または `repository` を使います。Claude Code プラグインでは、代わりに `supportUrl` と `documentationUrl` を使えます。ストアのページには、インストールする前にこれらのリンクが表示されます。
- **バージョン**: 更新のたびに上げてください。更新が審査中のあいだ、ストアは直前のバージョンを提供し続けます。`plugin publish` はビルドやアップロードを行う前に、ストアが公開済みのバージョンを問い合わせ、指定したバージョンがそれより高くない場合は、次に使うべきバージョンを示して停止します。

## MCP ツール

プラグインが MCP サーバーを含む場合、審査担当者は AI モデルが読むのと同じようにそのツールを読みます。

- **名前**は、`get_order_status` のように、ツールの動作を表すわかりやすい動詞にし、サーバー内で重複させないでください。専門用語や説明のない略語は使いません。
- **説明**には、ツールが何をするか、何を変更するか、何ができないかを書き、入力スキーマと実際の動作に一致させます。このプラグインを優先するようモデルに指示したり、ほかのプラグインを呼び出させたり、あらゆる場面でそのツールを呼び出させたりする内容は書かないでください。
- **1 つのツールにつき 1 つの操作**とし、それぞれに専用の入力スキーマを持たせます。
- **アノテーション**は、すべてのツールで明示的に設定します。

| アノテーション | `true` にするツール | `false` にするツール |
|---|---|---|
| `readOnlyHint` | 読み取り、計算、プレビューのみを行う | 書き込み、ファイルの保存、送信、投稿、アップロード、作業のキュー登録、ジョブの開始など、何かを変更する |
| `destructiveHint` | ユーザーが元に戻せる場合でも、削除、上書き、キャンセル、または取り消せない送信を行う | 追加のみを行う |
| `openWorldHint` | ウェブ検索のように公開された、または範囲の定まらないコンテンツにアクセスする、あるいは任意のアドレスに送信する | 別の場所でホストされていても、範囲の決まったアカウント、ワークスペース、カタログの内部にとどまる |

Enconvo はこれらのアノテーションを前提に動作します。`readOnlyHint: true` のツールは、ユーザーに確認せず、ほかの読み取りと並行して実行されます。`destructiveHint: true` のツールは、ユーザーがエージェントにフルアクセスを与えていない限り、先にユーザーに確認します。何かを変更するのに読み取り専用と宣言しているツールは却下されます。

`enconvo plugin scan` はプラグインの MCP サーバーを起動し、ツールをアノテーションとともに一覧表示して、アノテーションが抜けているツールを指摘します([`annotations_required`](/extensions/validation-codes#mcp-server-scan))。

独自のインターフェースを表示するツールは、`_meta.ui.resourceUri` にそのビュー(`ui://` リソース)を指定し、ビューは接続先のドメインを `_meta.ui.csp`(`connectDomains`、`resourceDomains`、`frameDomains`)で宣言します。これらはすべてのホストが読む MCP Apps のキーです。Enconvo は ChatGPT の `_meta["openai/outputTemplate"]` と `_meta["openai/widgetCSP"]` も読み取り、ChatGPT 向けに書かれたビュー(`text/html+skybridge`、または `openai/outputTemplate` のみで指定されたツール)には、そのビューが呼び出す `window.openai` API を提供します。そのため、ChatGPT 向けに作られたプラグインは、そのまま Enconvo でもインターフェースが表示されます。ほかのホストでも表示されるように、MCP Apps のキーも設定してください。`scan` は Enconvo と同じ方法で各ビューを読み取り、OpenAI 方式でのみ設定されているものがあれば知らせます。

## データとプライバシー

- **タスクに必要なものだけを求める。** ツールの入力はタスクに合わせて具体的にします。念のためといって、会話全体、過去のメッセージ、広範なプロフィールデータを求めないでください。
- **リクエストに答えるものだけを返す。** 内部 ID、トレースデータ、デバッグ出力はツールの結果に含めないでください。
- **収集しないもの**: 決済カード情報、健康記録、社会保障番号などの公的 ID、パスワード、API キー、ワンタイムコードをツールの入力から収集してはいけません。認証情報は、Enconvo が保管するプラグインの設定に入れます。
- **プライバシーポリシー。** サーバーにデータを送信するプラグインには、何を収集し、なぜ収集し、誰が受け取り、どのくらいの期間保持し、どうすれば削除できるかを記した、公開済みのプライバシーポリシーが必要です。そのアドレスを `interface.privacyPolicyURL` に、利用規約があれば `interface.termsOfServiceURL` に記載してください。ストアのページはどちらもリンクします。
- **トラッキングの禁止**: プラグインの動作に必要な範囲と、プライバシーポリシーで開示した範囲を超えて、ユーザー、そのクエリ、利用状況を追跡しないでください。
- **シークレットをパッケージに含めない。** パッケージは誰でもダウンロードできます。`.env` ファイルは自動的に除外されますが、ほかのキーや非公開ファイルが含まれていないか確認してください。

## サインインとテストアカウント

プラグインにアカウントが必要な場合、サインインは明示的に行い、必要な権限だけを求めます。審査担当者がアカウントを作成したり 2 要素認証コードを受け取ったりしなくても試せるよう、サンプルデータの入ったデモアカウントを用意してください。

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

審査メモは Enconvo の審査担当者にのみ届きます。パッケージやストアの掲載内容には含まれません。

## 商取引

プラグインは、ユーザーがすでに支払っているアカウントと連携でき、機能に別のプランが必要な場合はそのことを示せます。何かを販売する、または支払いを受け付ける場合は、審査資料(後述の `commerce` と `commerce_description`)で、何を販売し、どこで支払うのかを明記してください。支払いは自社のサイトで行い、プラグインが料金を隠したり、Enconvo のユーザーだけに高い料金を請求したりしてはいけません。

OpenAI のポータルはさらに厳格です。受け付けるのは物理的な商品を販売するプラグインのみで、サブスクリプション、クレジットなどのデジタル商品は対象外です。そちらに提出する前に、[商取引のルール](https://developers.openai.com/apps-sdk/app-submission-guidelines)を確認してください。

## 安全性

- プラグインは 10 代を含む一般の利用者に適しており、13 歳未満の子どもを対象にしていません。
- ユーザーが求めたことだけを行い、無関係なコンテンツ、リダイレクト、広告は含めません。
- 説明、プロンプト、スキルは、シークレットを求めたり、ユーザーの了承なしに金銭やデータを移動させたり、Enconvo の保護機能を回避しようとしたり、エンコードされた指示などによってプラグインの動作を隠したりしてはいけません。
- ウェブサイトをスクレイピングしたり、ほかのサービスを利用規約に反してラップしたり、そのレート制限やアクセス制御を回避したりしません。
- OpenAI の[禁止されている商品およびサービス](https://developers.openai.com/apps-sdk/app-submission-guidelines)の一覧にあるもの(武器、薬物、ギャンブル、アダルトコンテンツ、マルウェア、金融詐欺など)を販売したり、可能にしたりしません。

## 審査資料

審査資料は、審査担当者が何を試すべきかを伝えるものです。プラグインが処理すべきプロンプト、処理すべきでないプロンプト、短いデモ動画からなります。バージョンごとに保存され、審査担当者にのみ表示されます。

Codex、Claude Code、ポータブルプラグインでは、OpenAI のポータルが読み取る場所、つまり 1 つの `plugin.json` の `extensions["com.openai"]` に記述します。OpenAI は、プラグインに `.codex-plugin/plugin.json` がある場合(`enconvo plugin create` が作成するもの)はそこから、ルートの `plugin.json` が独自の `extensions["com.openai"]` を持つ場合や Codex のマニフェストがない場合はルートの `plugin.json` から、Claude Code 専用のプラグインでは `.claude-plugin/plugin.json` から取り込みます。審査資料のためだけにルートの `plugin.json` に `extensions["com.openai"]` を追加しないでください。Codex が `.codex-plugin/plugin.json` の掲載内容を無視するようになります。どのマニフェストに記述すべきかは `enconvo plugin validate --openai` が示します。

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

Enconvo プラグインでは、同じ `review` オブジェクトを `package.json` の最上位に置きます。

| フィールド | 内容 |
|---|---|
| `test_cases.positive` | プラグインが処理すべきプロンプト。それぞれに `description`、`prompt`、`expected_behavior`、`tools_triggered` を付けます。任意で `file_attachment_urls` と `expected_output_url` も指定できます。 |
| `test_cases.negative` | プラグインが別のものに任せるべきプロンプト。それぞれに `description` と `prompt` を付けます。 |
| `demo_recording_url` | 主なプロンプトとツールを示す動画。 |
| `commerce`, `commerce_description` | プラグインが何かを販売しているかどうか、また何をどこで販売しているか。 |
| `publication.release_notes` | 変更内容。`-m` を指定しない場合、`plugin publish` はこれをストアの変更履歴として使います。 |

各リストには最大 20 件のケースを入れられます。テキストフィールドは最大 4,000 文字で、すべてのアドレスは審査担当者が開ける `https://` のアドレスにしてください。`validate` と `publish` は、これらの上限を超える資料を受け付けません。

サインインの情報は、パッケージを誰でもダウンロードできるため、パッケージに含めてはいけません。`validate` と `publish` は、`test_credentials` または `reviewer_instructions` を含む `review` を受け付けません。代わりに `--review-notes` で渡すか、OpenAI のダッシュボードの Review details フォームに入力してください。

`plugin.json` の `publication` には、OpenAI のポータルが掲載用に取り込む内容も含められ、`validate --openai` はポータルと同じ基準でそれらを確認します。Enconvo は、インストール済みのプラグイン、およびソースからインストールする前のプラグインについて、`translations` を Enconvo のインターフェース言語で表示します。Enconvo ストアのページでは、まだこれらを使っていません。

| フィールド | 内容 |
|---|---|
| `countries` | プラグインを提供する国を、`["US", "GB"]` のような大文字の国コードで指定します。`[]` にするとすべての国で利用できます。 |
| `translations` | ロケールごとの掲載テキスト。たとえば `{"fr-FR": {"subtitle": "…", "description": "…"}}` のように指定します。サブタイトルは 30 文字以内の 1 行、説明は 4,000 文字以内です。 |

`null` に設定したフィールドは、OpenAI のダッシュボードにすでに保存されている値を維持します。プラグインレベルのテストケースは、MCP サーバーがちょうど 1 つあるプラグイン向けです。

OpenAI の最終提出では、MCP サーバーまたはアプリを持つプラグインに、ポジティブ 5 件とネガティブ 3 件のケース、デモ動画、リリースノートがちょうどそのとおり必要です。スキルのみのプラグインに必要なのはリリースノートだけです。ポータルのアップロードはこれらがなくても受け付け、最終提出のときにのみ求めるため、`validate --openai` は不足している項目を警告として一覧表示します。

## 提出前チェックリスト

`plugin publish` を実行する前に、次を確認してください。

- `plugin validate` がエラーを報告せず、警告にも目を通した。
- `version` が前回公開したバージョンより高く、パッケージ内のすべてのマニフェストで名前とバージョンが一致している。
- 更新の場合は、1 つ前のリリースの zip を指定した `plugin validate --previous` で、意図しない報告がない。更新はプラグイン全体を置き換えるため、含めなかったスキルや MCP サーバーは削除されます(`plugin_components_removed`)。
- タイトル、説明、アイコンがプラグインの機能を伝えており、スクリーンショットが動作している様子を示している。
- ホームページまたはサポートのアドレスが設定されており、プラグインがどこかにデータを送信する場合はプライバシーポリシーがリンクされている。
- すべての MCP ツールにわかりやすい名前と説明があり、`readOnlyHint`、`destructiveHint`、`openWorldHint` が設定され、`plugin scan` で問題なく一覧表示される。
- スキルの `description` に、どんなときに使うかが書かれている。
- API キーなど必須の設定は、チャットで求めるのではなく、設定として宣言されている。
- キー、トークン、非公開ファイルがフォルダーに含まれていない。
- 審査資料に、試すべきプロンプトと処理すべきでないプロンプトが挙げられており、サインインが必要な場合は `--review-notes` 用のデモアカウントが用意されている。
- パッケージをそのフォルダーからインストール(`plugin install .`)し、Enconvo でテストケースを試した。

## 提出後の流れ

1. `plugin publish` は、プラグインと、そのバージョンがストアが公開済みのものより高いことを確認したうえで、アップロードし、バージョンを審査に提出します。新しいプラグインが承認されるまでは、あなただけが見られます。
2. 審査担当者は、掲載内容、パッケージのファイル(公開済みバージョンからの変更点を含む)、審査資料、あなたのメモを読み、テストケースを試します。
3. 承認されたバージョンはストアに表示され、インストール済みのコピーに更新が提供されます。バージョンが却下された場合は、理由がメールで届きます。修正し、バージョンを上げて、もう一度公開してください。

Enconvo は、公開済みプラグインに関する報告も調査します。以前に承認されたものを含め、このガイドラインに違反していると判明したプラグインはストアから削除されることがあり、開発者には理由がメールで届きます。

## OpenAI にも提出する

同じフォルダーを OpenAI のプラグインポータルに提出できます。

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai` は、ポータルが受け付ける zip を書き出します。OpenAI の審査担当者向けの認証情報は、パッケージではなく、ポータルの提出フォームに入力します。ご自身のキーも含めないでください。`pack` と `publish` は `.env` ファイルを除外し、`validate` は秘密鍵やログイン情報のように見えるファイルを警告します(`archive_member_secret`)。

### プラグイン名

ポータルがプラグインの `name` に使えるのは英字、数字、`-`、`_` のみで、OpenAI は小文字の英字、数字、単一のハイフンを推奨しています。Codex、Claude Code、Enconvo は `acme.tools` のようにドットを含む名前もインストールしますが、`validate --openai` と `pack --openai` はそれを受け付けません(`plugin_name_format`)。提出するつもりのプラグインには `acme-tools` のような名前を付けてください。

### MCP サーバーとドメイン

アップロード後、ポータルはプラグインの MCP サーバーに接続してそのツールをスキャンします。サーバーを変更したときは、ポータルで再スキャンしてください。ポータルがサーバーに接続できるのは公開された `https://` の URL だけなので、ユーザーのコンピューターで動作するサーバーは、先にデプロイする必要があります。`scan --openai` はそのようなサーバーを警告します(`mcp_server_not_remote`)。最終提出では、ポータルはすべてのツールについて 3 つのアノテーションすべてを求めます。その正当性の説明はもう求められません。自動審査で指摘された場合は、説明を添えて異議を申し立てられます。ビューにページを埋め込むプラグインでは、埋め込む各ページについて、何をするものか、なぜプラグインが埋め込むのか、そのドメインを誰が管理しているのかという説明が引き続き必要です。MCP サーバー自身の登録可能ドメインのページは許可され、共有ホスト上の別々のテナントは別のドメインとして扱われます。`scan --openai` は、ビューが埋め込むドメインを一覧表示します(`frame_domain_explanation_required`)。

プラグインを提出する前に、ポータルはあなたが MCP サーバーのドメインを管理していることを確認します。ポータルがトークンを発行するので、それをサーバーのホストまたは親ドメインの `/.well-known/openai-apps-challenge` でプレーンテキストとして配信します。`scan --openai` はそれらの URL の応答を示し、`scan --challenge-token <token>` は、**Verify Domain** を選択する前に、そのトークンがそのまま配信されているかを確認します。[Domain verification](/extensions/validation-codes#domain-verification) も参照してください。

OpenAI のポータルがスキャンと審査のために接続するのはプラグインあたり 1 つの MCP サーバーだけなので、`validate --openai` は、それ以上のサーバーを持つプラグインを警告します。Codex 用に `mcp.json` で、Claude Code 用に `.mcp.json` で宣言された同じサーバーは 1 つと数えます。

### 公開済みのプラグインを更新する

そこで公開したプラグインを更新するには、より高いバージョンと、残したいものをすべて含む完全な ZIP をアップロードします。公開済みバージョンの zip を保管していない場合は、そのバージョンの **…** メニューにある **Download release ZIP** でポータルから入手できます。新しいバージョンは `validate --openai --previous <zip>` でその zip と照らして確認してください。ポータルは、MCP サーバーのなかった公開済みプラグインに MCP サーバーを追加することも、公開済みサーバーの URL を変更することもできません(これは OpenAI のサポートに依頼してください)。`--previous` はどちらも報告します。[Updates](/extensions/validation-codes#updates) も参照してください。

### 最終提出

OpenAI の最終提出では、アップロードよりも多くの掲載内容が求められ、`validate --openai` は不足している項目ごとに警告します。

- `interface.longDescription` と `interface.category`。カテゴリがない場合、ディレクトリはそのプラグインを Other に掲載します。
- MCP サーバーを持つプラグインでは、`websiteURL`、`supportURL`、`privacyPolicyURL`、`termsOfServiceURL`。それぞれ 1,024 文字以内の `https://` のアドレスにします。
- 自分で用意した掲載内容。`.claude-plugin/plugin.json` のみを持つ Claude Code プラグインには、ポータルが既定値で埋めた掲載内容が使われます(`claude_format_normalized`)。自分で書くには、`interface` を含む `.codex-plugin/plugin.json` を追加してください。
- スクリーンショットは、MCP サーバーが独自のインターフェースを持つ場合のみです。スタータープロンプトごとに PNG または JPEG を 1 枚、幅はちょうど 706 ピクセル、高さは 400 から 860 ピクセルにします。ポータルはスキャンの結果から判断するため、インターフェースを表示するツールがない場合、`scan --openai` はスクリーンショットを受け付けません(`screenshots_not_allowed`)。OpenAI のディレクトリはスクリーンショットを表示しなくなり、プラグインをスタータープロンプトで紹介するので、それらは丁寧に書いてください。

ディレクトリには、`interface.developerName` の内容にかかわらず、認証済みの OpenAI ID の開発者名が表示されます。コードについては [OpenAI's final submission](/extensions/validation-codes#openai’s-final-submission) を参照してください。
