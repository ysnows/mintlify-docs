このページは、Enconvo プラグインストアにプラグインを提出する開発者向けのガイドです。審査担当者が確認する項目、バージョンごとに提出する審査資料、`plugin publish` 実行前のチェックリスト、提出後の流れをまとめています。

Enconvo は、他のユーザーがインストールできるようになる前に、プラグインストアへ提出されたすべてのバージョンを審査します。このガイドラインは、Enconvo、Codex、Claude Code、およびスキルのみで構成されたプラグインを含むポータブルプラグインなど、ストアが受け付けるあらゆる種類のプラグインに適用されます。また、[OpenAI のプラグインガイドライン](https://developers.openai.com/apps-sdk/app-submission-guidelines)に準拠しているため、この基準を満たしたプラグインは OpenAI のプラグインポータルへの提出準備もほぼ整った状態になります。

## まずプラグインをチェックする

提出する前に、次のコマンドを実行してください。

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate` は自動検証できる項目をチェックし、`scan` は MCP サーバーを持つプラグインのツールを検査します。報告される各問題の意味については [Validation Codes](/extensions/validation-codes) を参照してください。残りの項目は、以下に沿って審査担当者が手動で確認します。

## 目的と品質

- Enconvo 単体ではできない有用な機能を提供し、かつ完結して動作すること。プレースホルダー、デモ専用、試用版の提出は却下されます。
- 予測どおりに動作すること。ネットワークエラー、権限不足、不正な入力などが発生した場合、黙って失敗するのではなく何が起きたかをユーザーに伝える必要があります。
- ご自身が所有しているかライセンス許諾を得ているコード、名称、アイコン、コンテンツのみを使用すること。他製品のなりすましや、Enconvo や第三者による推奨を示唆する表現は認められません。

## 名称、説明、ストア掲載情報

- **名称とタイトル**：明確かつ具体的であること。一般的な 1 語のみの名称は避け、企業名に「MCP」「MCP Server」「Plugin」などを付け足さないでください。
- **説明**：プラグインの機能を正確に記述すること。他製品との比較、裏付けのない主張、価格・割引・無料トライアルの案内は含めないでください。
- **アイコンとスクリーンショット**：アイコンは最大 5 MB の PNG、JPEG、WebP、または GIF を使用します。最大 8 枚のスクリーンショットを `metadata/` フォルダに配置するとファイル名順に表示されます。スクリーンショットは実際の動作画面を示す必要があります。
- **サポート窓口**：`interface.websiteURL` と `interface.supportURL`（またはウェブサイト用に `homepage` か `repository`）を設定し、ユーザーが連絡できる手段を用意してください。Claude Code プラグインでは代わりに `supportUrl` と `documentationUrl` を使用できます。これらのリンクはインストール前にストアページへ表示されます。
- **バージョン**：更新のたびにバージョンを上げてください。更新が審査中の間、ストアでは引き続き 1 つ前のバージョンが公開されます。`plugin publish` はビルドやアップロードの前にストアへ公開済みバージョンを問い合わせ、指定したバージョンがそれより高くない場合は次に使うべきバージョンを案内して停止します。

## MCP ツール

プラグインが MCP サーバーを含む場合、審査担当者は AI モデルが参照するのと同じ視点でツールを確認します。

- **ツール名**：`get_order_status` のように、何をするツールかがわかる平易な動詞を使い、サーバー内で一意にします。専門用語や説明のない略語は避けてください。
- **説明**：ツールが何を行い、何を変更し、何ができないかを明確にし、入力スキーマや実際の動作と一致させます。「このプラグインを優先して使う」「他のプラグインを呼び出す」「あらゆる場面でこのツールを使う」といった指示をモデル向けに書かないでください。
- **1 ツール 1 操作**：それぞれに専用の入力スキーマを持たせます。
- **アノテーション**：すべてのツールに明示的に設定します。

| アノテーション | `true` にする場合 | `false` にする場合 |
|---|---|---|
| `readOnlyHint` | 読み取り、計算、プレビューのみを行う場合 | ファイルの書き込み・保存、送信、投稿、アップロード、ジョブのキュー追加や開始など、何らかの変更を行う場合 |
| `destructiveHint` | 削除、上書き、キャンセル、または取り消せない送信を行う場合（ユーザーが後から元に戻せる場合も含む） | 追加のみを行う場合 |
| `openWorldHint` | ウェブ検索などの公開情報やオープンエンドな対象にアクセスする場合、または任意のアドレスへ送信する場合 | 外部ホスト上であっても、特定のアカウント、ワークスペース、カタログの範囲内に留まる場合 |

Enconvo はこれらのアノテーションに依存して動作します。`readOnlyHint: true` のツールはユーザーに確認せず他の読み取りと並行して実行されます。`destructiveHint: true` のツールは、エージェントにフルアクセスが付与されていない限り事前にユーザーへ確認を求めます。何かを変更するにもかかわらず読み取り専用と宣言されているツールは却下されます。

`enconvo plugin scan` はプラグインの MCP サーバーを起動し、各ツールとそのアノテーションを一覧表示して、設定が抜けているツールを指摘します（[`annotations_required`](/extensions/validation-codes#mcp-server-scan)）。

独自の画面を表示するツールでは、`_meta.ui.resourceUri` にビュー（`ui://` リソース）を指定し、そのビューの `_meta.ui.csp`（`connectDomains`、`resourceDomains`、`frameDomains`）でアクセス先ドメインを宣言します。これらはすべてのホストが読み取る MCP Apps のキーです。Enconvo は ChatGPT 用の `_meta["openai/outputTemplate"]` および `_meta["openai/widgetCSP"]` も読み取り、ChatGPT 向けに書かれたビュー（`text/html+skybridge`、または `openai/outputTemplate` のみで指定されたツール）には呼び出し先となる `window.openai` API を提供するため、ChatGPT 用に作られたプラグインの UI もそのまま Enconvo 上で表示できます。ただし、他のホストでも表示できるよう MCP Apps のキーもあわせて設定してください。`scan` は Enconvo と同様に各ビューを読み取り、OpenAI 形式しか設定されていない場合は警告を出します。

## データとプライバシー

- **タスクに必要な情報のみを求める**：ツールの入力はタスクに特化したものにしてください。「念のため」として会話全体、過去のメッセージ、広範なプロフィール情報を要求しないでください。
- **リクエストへの回答に必要な内容だけを返す**：内部 ID、トレース情報、デバッグ出力はツールの結果に含めないでください。
- **収集を禁止する情報**：クレジットカード情報、医療記録、マイナンバーや社会保障番号などの公的個人番号、パスワード、API キー、ワンタイムコードをツール入力で収集しないでください。認証情報はプラグインの設定項目に定義し、Enconvo に管理させます。
- **プライバシーポリシー**：外部サーバーへデータを送信するプラグインには、何を収集し、なぜ収集し、誰が受け取り、どれくらい保持し、ユーザーがどう削除できるかを明記した公開プライバシーポリシーが必要です。その URL を `interface.privacyPolicyURL` に、利用規約がある場合はその URL を `interface.termsOfServiceURL` に記載してください。ストアページに両方のリンクが表示されます。
- **無断トラッキングの禁止**：プラグインの動作に必要な範囲およびプライバシーポリシーで開示した範囲を超えて、ユーザー、クエリ、利用状況を追跡しないでください。
- **パッケージに秘密情報を含めない**：パッケージは誰でもダウンロードできます。`.env` ファイルは自動的に除外されますが、他のキーや非公開ファイルが含まれていないか確認してください。

## サインインとテスト用アカウント

アカウントが必要なプラグインでは、サインインを明示的に行い、必要な権限のみを要求してください。審査担当者がアカウントの新規作成や二要素認証コードなしで試せるよう、サンプルデータ入りのデモ用アカウントを用意してください。

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

審査メモは Enconvo の審査担当者にのみ共有され、パッケージやストア掲載情報には含まれません。

## 課金・決済

すでにユーザーが契約しているアカウントと連携したり、特定の機能に別のプランが必要である旨を案内したりすることは可能です。プラグインが商品を販売したり決済を受け付けたりする場合は、何をどこで支払うのかを審査資料（後述の `commerce` および `commerce_description`）に明記してください。決済は開発者自身のサイト上で行い、隠れた料金を請求したり、Enconvo ユーザーに他より高い価格を設定したりしないでください。

OpenAI のポータルはさらに厳格で、物理的な商品の販売のみを受け付け、サブスクリプション、クレジット、その他のデジタル商品は認められません。OpenAI に提出する場合は事前に[コマース規定](https://developers.openai.com/apps-sdk/app-submission-guidelines)を確認してください。

## 安全性

- 10 代を含む一般利用者向けとして適切であり、13 歳未満の子どもを対象としていないこと。
- ユーザーが依頼したことだけを実行し、無関係なコンテンツ、リダイレクト、広告を含めないこと。
- 説明文、プロンプト、スキルにおいて、秘密情報を求めたり、ユーザーの指示なしに資金やデータを移動したり、Enconvo の安全策を回避しようとしたり、エンコードされた指示などによって実際の動作を隠したりしないこと。
- 利用規約に反するスクレイピングや他サービスのラップを行わず、レート制限やアクセス制御を回避しないこと。
- 武器、違法薬物、ギャンブル、アダルトコンテンツ、マルウェア、金融詐欺など、OpenAI の[禁止されている商品およびサービス](https://developers.openai.com/apps-sdk/app-submission-guidelines)に該当するものを販売または助長しないこと。

## 審査資料

審査資料では、プラグインが処理すべきプロンプト、処理せずに見送るべきプロンプト、および短いデモ動画を審査担当者へ伝えます。これらはバージョンごとに保存され、審査担当者にのみ表示されます。

Codex、Claude Code、またはポータブルプラグインでは、OpenAI ポータルが読み取る場所（いずれか 1 つの `plugin.json` の `extensions["com.openai"]` 配下）に記述します。OpenAI は、`enconvo plugin create` で作成されるような `.codex-plugin/plugin.json` がある場合はそこから、ルートの `plugin.json` 独自の `extensions["com.openai"]` がある場合や Codex マニフェストがない場合はルートの `plugin.json` から、Claude Code 専用プラグインの場合は `.claude-plugin/plugin.json` から読み込みます。審査資料のためだけにルートの `plugin.json` へ `extensions["com.openai"]` を追加しないでください。追加すると Codex が `.codex-plugin/plugin.json` 内の掲載情報を無視してしまいます。`enconvo plugin validate --openai` を実行すると、どのマニフェストに記述すべきかが表示されます。

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

Enconvo プラグインでは、同じ `review` オブジェクトを `package.json` のトップレベルに配置します。

| フィールド | 内容 |
|---|---|
| `test_cases.positive` | プラグインが処理すべきプロンプト。各項目に `description`、`prompt`、`expected_behavior`、`tools_triggered` を指定します。任意で `file_attachment_urls` と `expected_output_url` を追加できます。 |
| `test_cases.negative` | 他の機能に任せてプラグインが反応すべきでないプロンプト。各項目に `description` と `prompt` を指定します。 |
| `demo_recording_url` | 主なプロンプトとツールの動作を示す動画。 |
| `commerce`, `commerce_description` | プラグインが何かを販売するかどうか、およびその内容と決済場所。 |
| `publication.release_notes` | 変更内容。`-m` を指定しない限り、`plugin publish` はこれをストアの変更履歴として使用します。 |

各リストには最大 20 件まで登録できます。テキストフィールドは最大 4,000 文字で、すべての URL は審査担当者が開ける `https://` アドレスである必要があります。これらの制限に違反する資料があると、`validate` と `publish` は処理を拒否します。

パッケージは誰でもダウンロードできるため、サインイン情報をパッケージ内に記述してはいけません。`review` に `test_credentials` または `reviewer_instructions` が含まれている場合、`validate` と `publish` はエラーを出します。代わりに `--review-notes` で渡すか、OpenAI ダッシュボードの審査詳細フォームに入力してください。

`plugin.json` の `publication` には、OpenAI ポータルがストア掲載情報として読み込む項目も指定でき、`validate --openai` はポータルと同じ基準で検証します。Enconvo はインストール済みプラグインやインストール前の確認画面で現在の表示言語に合わせた `translations` を表示しますが、Enconvo ストアのウェブページではまだ使用されません。

| フィールド | 内容 |
|---|---|
| `countries` | プラグインを提供する地域を `["US", "GB"]` のような大文字の国コードで指定します。`[]` にすると全世界で利用可能になります。 |
| `translations` | `{"fr-FR": {"subtitle": "…", "description": "…"}}` のようなロケールごとの掲載テキスト。サブタイトルは 30 文字以内の 1 行、説明は最大 4,000 文字です。 |

フィールドに `null` を指定すると、OpenAI ダッシュボードにすでに保存されている値が維持されます。プラグインレベルのテストケースは、MCP サーバーをちょうど 1 つ持つプラグイン向けです。

OpenAI で MCP サーバーまたはアプリを含むプラグインを最終提出するには、ポジティブケース 5 件、ネガティブケース 3 件、デモ録画、リリースノートが必須です（スキルのみのプラグインはリリースノートのみで構いません）。ポータルへのアップロード自体はこれらがなくても受け付けられ、最終提出時にのみ求められるため、`validate --openai` は不足項目を警告として一覧表示します。

## 提出前チェックリスト

`plugin publish` を実行する前に次を確認してください。

- `plugin validate` でエラーが出ないこと、および表示された警告を確認したこと。
- `version` が前回公開したバージョンより高く、パッケージ内のすべてのマニフェストで同じ名称とバージョンが指定されていること。
- アップデートの場合、前回リリースの zip を指定して `plugin validate --previous` を実行し、意図しない変更がないこと（アップデートはプラグイン全体を置き換えるため、含まれないスキルや MCP サーバーは削除されます：`plugin_components_removed`）。
- タイトル、説明、アイコンがプラグインの機能を正確に表しており、スクリーンショットが実際の動作を示していること。
- ホームページまたはサポート URL が設定されており、データを外部送信する場合はプライバシーポリシーへのリンクが設定されていること。
- すべての MCP ツールにわかりやすい名称と説明があり、`readOnlyHint`、`destructiveHint`、`openWorldHint` が設定されていて、`plugin scan` で問題が検出されないこと。
- スキルの `description` に、いつそのスキルを使うべきかが明記されていること。
- API キーなどの必須設定がチャットで尋ねるのではなく、設定項目として宣言されていること。
- フォルダ内にキー、トークン、非公開ファイルが含まれていないこと。
- 審査資料に試すべきプロンプトと処理しないプロンプトが記載されており、サインインが必要な場合は `--review-notes` に渡すデモ用アカウントが準備できていること。
- 自身のフォルダからパッケージをインストールし（`plugin install .`）、Enconvo 上でテストケースを試したこと。

## 提出後の流れ

1. `plugin publish` はプラグインとストア公開版より新しいバージョンであることを検証したうえでアップロードし、バージョンを審査へ提出します。新しいプラグインが承認されるまで、表示されるのはあなた自身だけです。
2. 審査担当者が掲載情報、パッケージ内のファイル（公開済みバージョンからの変更点を含む）、審査資料、審査メモを確認し、テストケースを試します。
3. 承認されるとストアに公開され、すでにインストールしているユーザーにはアップデートが案内されます。却下された場合は理由を記載したメールが届きます。修正し、バージョンを上げて再度公開してください。

Enconvo は公開済みプラグインに関する報告も調査します。すでに承認されたものを含め、本ガイドラインに違反していることが判明したプラグインはストアから削除され、開発者へメールで理由が通知されます。

## OpenAI にも提出する

同じフォルダからそのまま OpenAI のプラグインポータルにも提出できます。

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai` はポータルが受け付ける zip ファイルを作成します。OpenAI 審査担当者向けの認証情報はパッケージに入れず、ポータルの提出フォームに入力してください。ご自身のキーも含めないよう注意してください。`pack` と `publish` は `.env` ファイルを除外し、`validate` は秘密鍵やログイン情報に見えるファイルがあると警告します（`archive_member_secret`）。

### プラグイン名

OpenAI ポータルではプラグインの `name` に英字、数字、`-`、`_` のみが許可されており、OpenAI は小文字の英字、数字、単一のハイフンを推奨しています。Codex、Claude Code、Enconvo は `acme.tools` のようなドット区切りの名前もインストールできますが、`validate --openai` と `pack --openai` はこれを拒否するため（`plugin_name_format`）、提出予定のプラグインには `acme-tools` のような名前を付けてください。

### MCP サーバーとドメイン

アップロード後、ポータルはプラグインの MCP サーバーに接続してツールをスキャンします。サーバーを変更した場合はポータル側で再スキャンしてください。ポータルは公開されている `https://` URL のみに接続するため、ユーザーのコンピュータ上でローカル実行されるサーバーは事前にデプロイしておく必要があります（`scan --openai` はローカルサーバーに対して `mcp_server_not_remote` の警告を出します）。最終提出時にはすべてのツールに 3 つのアノテーションすべてが必須となります。以前のような正当性の説明は不要になりましたが、自動審査でフラグが立った場合は説明を添えて異議申し立てを行えます。ビュー内に他ページを埋め込むプラグインでは、埋め込むページごとに「何をするか」「なぜ埋め込むのか」「誰がそのドメインを管理しているか」の説明が必要です。MCP サーバー自身の登録ドメイン配下のページは許可されますが、共有ホスト上の別テナントは別ドメインとして扱われます。ビューが埋め込むドメインは `scan --openai` で一覧表示されます（`frame_domain_explanation_required`）。

プラグインを提出する前に、ポータルはあなたが MCP サーバーのドメインを管理しているかを検証します。サーバーのホストまたは親ドメインの `/.well-known/openai-apps-challenge` にプレーンテキストとして配信するためのトークンが発行されます。`scan --openai` でそれらの URL の応答を確認でき、**Verify Domain** を選択する前に `scan --challenge-token <token>` でトークンが正確に返されているかをチェックできます。[ドメイン認証](/extensions/validation-codes#domain-verification)を参照してください。

OpenAI ポータルはスキャンおよび審査のためにプラグインあたり 1 つの MCP サーバーにしか接続しないため、複数ある場合は `validate --openai` が警告を出します。Codex 用の `mcp.json` と Claude Code 用の `.mcp.json` に宣言された同一のサーバーは 1 つとして数えられます。

### 公開済みプラグインの更新

OpenAI 側で公開済みのプラグインを更新するには、バージョンを上げ、維持したい要素をすべて含めた完全な ZIP をアップロードします。公開済みバージョンの zip を手元に残していない場合は、ポータル上の該当バージョンの **…** メニューにある **Download release ZIP** から取得し、`validate --openai --previous <zip>` で新しいバージョンと比較検証できます。なお、ポータルでは MCP サーバーを持たなかった公開済みプラグインに後からサーバーを追加したり、公開済みサーバーの URL を変更したりすることはできません（URL の変更は OpenAI サポートへ依頼してください）。`--previous` を付けると両方の変更が報告されます。[アップデート](/extensions/validation-codes#updates)を参照してください。

### 最終提出

OpenAI の最終提出ではアップロード時よりも多くの掲載情報が求められ、`validate --openai` は不足している項目ごとに警告を出します。

- `interface.longDescription` と `interface.category`（カテゴリがない場合、ディレクトリ上では Other に分類されます）。
- MCP サーバーを持つプラグインの場合、`websiteURL`、`supportURL`、`privacyPolicyURL`、`termsOfServiceURL`（それぞれ 1,024 文字以内の `https://` URL）。
- 独自の掲載情報。`.claude-plugin/plugin.json` のみを持つ Claude Code プラグインにはポータルがデフォルト値で掲載情報を補完するため（`claude_format_normalized`）、自分で記述したい場合は `interface` を含む `.codex-plugin/plugin.json` を追加してください。
- スクリーンショットは、MCP サーバーが独自の画面を持つ場合にのみ添付します。スタータープロンプトごとに 1 枚の PNG または JPEG で、幅はちょうど 706 ピクセル、高さは 400〜860 ピクセルである必要があります。ポータルはスキャン結果から画面の有無を判定するため、画面を表示するツールがない場合は `scan --openai` がスクリーンショットを拒否します（`screenshots_not_allowed`）。現在 OpenAI のディレクトリではスクリーンショットは表示されず、スタータープロンプトによってプラグインが紹介されるため、プロンプトは丁寧に作成してください。

`interface.developerName` に何を書いたかにかかわらず、ディレクトリには認証済みの OpenAI ID の開発者名が表示されます。各コードの詳細は [OpenAI の最終提出](/extensions/validation-codes#openais-final-submission)を参照してください。
