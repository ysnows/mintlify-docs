このガイドでは、ワークフローエディタで行うすべての操作（ワークフローの作成、キャンバスや YAML での構築、アシスタントによる編集、実行、結果の確認）を解説します。後半では、ファイル形式と各ステップの種類の仕様をリファレンスとしてまとめています。

エディタを開くには、チャットウィンドウのサイドバーで **ワークフロー** を選択するか、**設定 → ワークフロー → 管理** を開きます。その後 **新規ワークフロー** を選択するか、既存のワークフローで **編集** をクリックします。チャットウィンドウでは、チャット画面と行き来しても編集中のワークフローは開いたまま保たれます。

## 基本概念

- ワークフローでは、まず **入力** を宣言し、その下に順序付きのステップ列を含む 1 つ以上のジョブを定義します。全体の概要は [ワークフロー](/ja/workflows/introduction) を参照してください。
- ジョブ内のステップは上から順に実行されます。ジョブ同士は、他のジョブの完了を待つ指定がない限り並列で実行されます。
- ステップは `{{ inputs.topic }}` や `{{ steps.fetch.output }}` のような `{{ }}` テンプレートを使って、実行時の入力や前のステップの結果を参照します。
- ワークフローの編集と実行は別の操作です。保存するとファイルが書き出され、実行すると実際のモデルやツールが呼び出されます。

## ワークフローを管理する

ワークフロー一覧画面では、ワークフローの開く・実行・並び替え・検索・削除を行えます。

### ワークフロー一覧

各行にはステップ数、最終編集日時、前回の実行結果が表示されます。

- 前回の実行結果を選択すると、その結果がキャンバスに読み込まれた状態でワークフローが開きます。
- 再生ボタンを選択すると、ワークフローを開いてすぐ実行します。未入力の必須入力がある場合は先に **入力** パネルが開きます。実行中は再生ボタンが停止ボタンに変わり、クリックするとワークフローを開かずに実行を停止できます。
- スケジュール実行されるワークフローには、次回の実行時刻、またはすべての予約タスクがオフのときに **スケジュール一時停止中** と表示されます。ここを選択すると、実行パネルにスケジュール一覧を開いた状態でワークフローが開きます。
- コピーボタンを選択すると、ワークフローを別のタイトルで複製できるため、元のワークフローに触れずに編集を試せます。一覧はコピー先へスクロールし、ハイライト表示します。
- 一覧の上にある並び替えメニューで、**最近の編集順**、**最近の実行順**、**名前順** に並び替えられます。選んだ順序は記憶されます。

一覧は、この画面に戻ったときやスケジュール実行が開始されたときに自動で更新されます。

### ワークフローを探す

**ワークフローを検索** に文字を入力すると、入力に合わせて一覧が絞り込まれます。クリアボタンまたは Esc キーで全件表示に戻ります。

行上のタグを選択すると、そのタグが付いたワークフローだけを表示します（**ワークフローを検索** と併用可能）。1 行には最大 4 つのタグが表示され、**+N** を選択すると残りを表示できます。全件表示に戻すには、そのタグをもう一度選択するか、一覧の上にあるタグ横の × を選択するか、**ワークフローを検索** 内で Esc キーを押します。

| キー | ワークフロー一覧での動作 |
| --- | --- |
| **⌘F** または **/** | **ワークフローを検索** にフォーカス |
| **ワークフローを検索** 内で ↓ | 先頭のワークフローへ移動 |
| ↑ と ↓ | ワークフロー間を移動 |
| Return | 選択中のワークフローを開く |
| Delete | 選択中のワークフローを削除 |

### ワークフローの名前変更と削除

名前を変更するには、エディタ上部のワークフロー名を選択して新しい名前を入力し、Return を押します。Esc を押すと元の名前が保たれます。

ワークフローを削除するとき、実行中の場合は先に実行を停止します。そのワークフローを実行している [予約タスク](/ja/workflows/scheduled-jobs) は削除されずに一時停止状態になるため、別のワークフローを割り当てたり削除したりできます。削除前の確認ダイアログには、影響を受ける予約タスクの数が表示されます。

## 新しいワークフローを作成する

**新規ワークフロー** を選択するとダイアログが開き、次の方法から作成を始められます。最初にワークフローの種類を選びます:

- **タスクワークフロー**: 1 つの種類のタスクを完了までの手順として定義します。
- **チームワークフロー**: 複数のメンバーで計画から完了まで進めるワークフローです。**計画・構築・レビュー** や **1 人のメンバー** などのテンプレートがあります。

まだワークフローが 1 つもない場合は、ワークフロー一覧画面に同じ開始方法（**やりたいことを説明**、**空白のワークフロー**、各種テンプレート）が直接表示されます。

| 開始方法 | 手順 |
| --- | --- |
| 言葉で説明する | たとえば「テキストを日本語とスペイン語に同時に翻訳する」のようにやりたいことを入力し、**作成** を選択（または **⌘↩** を押す）します。アシスタントがすでにワークフローを組み立て始めた状態でエディタが開きます。ステップを確認し、問題なければ **保存** を選択してください。 |
| テンプレートから始める | **空白**、**トピックを調査**、**ウェブページを要約**、**YouTube 動画からメモを作成**、**書いて読み上げる**、**ステップ種類のツアー**（シェルコマンド、ツール、プロンプト、Agent を使い、2 つのジョブを並列実行する例）から選びます。どのテンプレートもそのまま即実行できる完成済みワークフローです。 |
| ファイルをインポートする | **ファイルを選択…** を選択するか、チームメイトから共有された `.yaml`、`.yml`、`.json` ワークフローファイルをダイアログ上の任意の場所にドロップします。既存のワークフローを上書きすることはなく、新しいワークフローとして保存されます。同じタイトルがすでにある場合は「News copy」のようにコピー名が付きます。ファイルが有効なワークフローでない場合はダイアログが開いたまま理由が表示されます。 |
| 貼り付ける | チャットなどで共有されたワークフローの YAML や JSON を説明欄に貼り付けます。**作成** ボタンが **インポート** に変わり、貼り付けた内容のままワークフローが作成されます。 |

### ビルトインワークフロー

Enconvo に最初から含まれているワークフローは読み取り専用で開きます。変更したい場合は **コピーを作成** を選択し、コピーした方を編集してください。

### ワークフローを共有する

ワークフローを共有したり手元に控えを残したりするには、ワークフロー一覧の行にある共有ボタン（ダウンロードアイコン）、またはエディタツールバーの共有ボタンを選択します:

- **YAML ファイルとして書き出す…**: 任意の場所に `.yaml` ファイルを保存します。どの Mac でも **新規ワークフロー** > **ファイルを選択…** からインポートできます。
- **YAML をコピー**: ワークフローをクリップボードにコピーします。チャットに貼ったり、**新規ワークフロー** の説明欄に貼り付けてインポートしたりできます。

エディタから実行した場合は、未保存の変更も含めて書き出し・コピーされます。

## Visual エディタで構築する

  <img src="/images/guides/workflow-visual.jpg" alt="2 つの並列ジョブとステップインスペクタを表示した実際の Enconvo ワークフローグラフ" />
</Frame>

エディタでは、同じワークフローを 2 つの表示形式で編集できます:

- **Visual**: ステップをキャンバス上のカードとして表示し、並列ジョブを横に並べて表示します。
- **Steps**: 条件、繰り返し、並列ステップを含めて上から順にステップを一覧表示します。2 つのステップの間の **追加** メニューから新しいステップを挿入できます。

ヘッダーの **ガイド** を選択すると、そのワークフローの仕組みを日本語（お使いの言語）の平易な言葉で説明します。

1. エディタツールバーで **Visual** を選択します。
2. ノード間の **ここにステップを追加** でステップを挿入するか、**並列ジョブを追加** で別のブランチを作ります。ステップ一覧の上部には **最近使用した項目** として直近で選んだステップやツールが表示されるため、よく使うものを 1 クリックで追加できます。ツール数が多いプラグインは最初の 8 件を表示するので、**さらに N 件表示** を選択するか入力して検索してください。
3. ステップを選択してインスペクタを開きます。ID、タイトル、実行設定を編集し、**動作** セクションで実行条件などを変更します。
4. **入力** ノードを選択して、ワークフローが受け取る入力（名前、型〔テキスト、数値、真偽値、リスト、オブジェクト〕、説明、デフォルト値、実行時に必須かどうか）を設定します。各名前の下には、`{{ inputs.topic }}` のようにステップからどう参照されているかと、参照しているステップ数が表示されます。入力名を変更すると、それらステップの参照も新しい名前に自動更新されます。名前には英字・数字・アンダースコアが使えますが、数字で始めることや他の入力と重複させることはできません。
5. グラフを確認し、編集中は必要に応じて **元に戻す** や **やり直す** を使用します。
6. 変更を確認したら **保存** を選択します。

### ステップカードの見方

各ステップカードにはステップ名が表示され、その下にステップが行う処理（ツールやステップの種類、および「*Web Search · ‹topic› news*」やプロンプトの冒頭などの主要設定）が表示されます。入力や前のステップから読み取る値は ‹ › 内に名前で表示されます。名前を付けていないステップは ID を言葉で表した表示になり、カーソルを合わせると実際の ID を確認できます。

ツールステップのカードには、そのプラグインのアイコンが表示されます。カード上の小さなマークはステップの実行条件（条件が真のときだけ実行、リストの各要素ごとに実行、繰り返し、失敗時のリトライ、前のステップが失敗しても実行、失敗してもワークフローを続行）を表します。マークにカーソルを合わせると意味が表示され、設定はステップの **動作** セクションで変更できます。

### ステップを選ぶ

ステップピッカーでは、ビルトインステップ、インストール済みツール、および MCP ツールを検索できます。Enconvo のウィンドウを開くだけのツールやプロバイダーのモデル・音声一覧を取得するだけのツールは省かれていますが、YAML で名前を指定すれば呼び出すことは可能です。

どのステップを使えばよいか分からない場合は、「記事を 3 つの箇条書きに要約する」のようにステップにさせたいことを入力し、ピッカー下部の **アシスタントに追加を依頼**（**⌘↩**）を選択します。一致する項目がない場合は Return キーでも同じ操作になります。アシスタントはピッカーを開いた位置（隣接ステップの前後、または新しい並列ジョブ）に正確にステップを追加します。他のアシスタントの編集と同様に元に戻すこともできます。

### ステップを編集する

インスペクタには **設定** と **出力** の 2 つのタブがあります。**ステップを実行** を使うと選択中のステップだけを単体実行できます（実際のツール呼び出しやシェルコマンドが実行されます）。単体実行の前に、上流の必要な値が揃っているか確認してください。

**設定** タブの先頭には、ステップカードに表示される **名前** と、他のステップがその出力を参照するときに使う **ステップ ID** があります。**処理内容** にはステップのツールまたは種類が表示されます。

ステップの処理を別のものに変えるには、**変更** を選択して別のツールやステップの種類を選ぶか、やってほしいことを入力して **アシスタントに変更を依頼** を選択します:

- ステップの ID は維持されるため、その結果を参照している後続ステップはそのまま動作します。
- 条件、繰り返し、リトライ回数、待機対象など、いつ・どのように実行するかの設定も維持されます。
- 新しいツールの設定は空の状態から始まります。プロンプトから Agent への変更、または Agent からプロンプトへの変更では、テキスト・モデル・出力スキーマが引き継がれます。
- エディタが自動付与した名前は新しいツールに合わせて更新されますが、自分で入力した名前はそのまま残ります。

元の状態に戻すには **元に戻す** を選択します。

### ステップの複製・並び替え・無効化

ステップを再利用するには、インスペクタ内またはステップカードにカーソルを合わせたときに表示される **複製** を選択します。コピーは元のステップのすべての設定を保持したまま直後に配置され、`fetch_2` のような未使用の ID が自動で割り当てられます。

ジョブ内のステップは上から順に実行されます。順番を変えるには、ステップカードを同じジョブ内で上下にドラッグしてください。他のカードが自動で避けて移動先が示されます。ステップを選択してインスペクタの **上へ移動** / **下へ移動** を選ぶか、**⌥↑** / **⌥↓** を押すこともできます。移動を取り消すには **⌘Z** を押します。あるステップが、自分の参照元ステップよりも上に移動してしまった場合は、下に移動し直すまでカードに警告が表示されます。

ステップを削除せずに一時的に除外するには、ステップを選択して **ステップをオフにする** を選びます。カードが半透明になって **オフ** と表示され、実行時にはスキップされて後続のステップがそのまま実行されます。元に戻すには **ステップをオンにする** を選択します。

### 複数のステップをまとめて操作する

複数のステップを一度に変更するには、⌘ キーまたは Shift キーを押しながらカードをクリックします。キャンバス上部のバーに選択中のステップ数が表示され、まとめて **オフにする**（または **オンにする**）と **削除** を行えます。選択を解除するには Esc を押すかキャンバスの空白部分をクリックし、取り消すには **⌘Z** を押します。

削除によって他のステップが壊れたりジョブが空になったりする場合は、事前に確認が表示されます。確認画面には削除対象に依存しているステップと、その理由（**出力を使用** や **完了を待機** など）が一覧表示されます。いずれかを選択すると削除を中止してそのステップを開くため、先に依存関係を修正できます。単一ステップを削除するときも同様です。

ステップをコピーするには、1 つ（または複数）選択して **⌘C** を押すか、上部バーの **コピー** を選択します（切り取りは **⌘X**）。その後、貼り付け先の直前となるステップを選択して **⌘V** を押します:

- コピーされたステップは設定を保ったまま、選択したステップの直後（ジョブを選択していた場合はジョブの末尾）に挿入されます。
- すでに使われている ID と重複する場合は `fetch_2` のような新しい ID が付与され、貼り付けたステップ同士の参照関係も新しい名前に合わせて更新されます。
- 別のワークフローへの貼り付けも同じように動作し、ワークフローファイルからコピーした YAML または JSON のステップリストも **⌘V** でそのまま貼り付けられます。

ステップの削除や貼り付けを行うと変更内容を知らせる通知が表示され、その中の「元に戻す」を選択して取り消すこともできます。

### 検索・ズーム・保存・実行

- 大きなワークフローで特定のステップへ移動するには、**⌘F** を押すかキャンバス上の検索ボタンを選択し、ステップの名前・ID・ツール・テキストの一部を入力して選択します。該当ステップが選択され、画面内にスクロールされます。
- キャンバス右下のズームコントロールで拡大・縮小でき、倍率表示をクリックすると 100% に戻ります。
- **ステップを検索**（またはキャンバス上で **⌘F**）を選択してステップ名の一部を入力すると、そのステップを選択して表示領域に収めます。読み取り専用のビルトインワークフローでも使えます。
- Visual と YAML のどちらでも、ステップ設定の入力中であっても、**⌘S** を押せばいつでも保存できます。
- **⌘↩** を押すとワークフローを実行します（未保存の変更がある場合は先に保存されます）。YAML エディタやアシスタント欄など複数行入力欄の中にいるときは、ツールバーの **実行** を選択してください。
- 実行中は **実行** ボタンが **停止** に変わります。クリックすると、完全に停止するまで **停止中…** と表示されます。

プロンプトが空のステップや説明の欠落など問題がある場合、保存や実行は停止して修正箇所を案内します。**表示** を選択すると問題のステップやワークフローのタイトル・説明欄が開きます。問題のあるステップはカードに赤いマークが付き、カーソルを合わせると内容を確認できます。YAML 表示では **検証** を選択してドキュメント全体をチェックできます。

### 未保存の変更

未保存の変更がある間は、エディタのヘッダーに **未保存** と表示されます。クリックすると前回の保存から追加・削除された YAML の行を確認でき、**変更を破棄** で保存済みの状態に戻せます（Visual エディタでは **⌘Z** で変更を戻すこともできます）。未保存の変更がある状態でワークフロー一覧に戻ろうとすると、**保存して移動**、**破棄**、**編集を続ける** の選択肢が表示されます。

未保存の変更は編集中この Mac 上にも保持されます。保存前にウィンドウを閉じたり再読み込みしたりした場合でも、もう一度そのワークフローを開くと上部にバーが表示され、1 ステップの「元に戻す」操作として変更を戻せる **復元**、または **破棄** を選べます（前回以降に保存済みファイル側が変更されていない場合のみ復元が提案されます）。ワークフロー一覧ではこのようなワークフローに **未保存の変更** タグが表示され、ワークフローを削除するとそれらの未保存変更も破棄されます。

### キャンバスのショートカット

| ショートカット | 動作 |
| --- | --- |
| **⌘S** | 保存 |
| **⌘↩** | 実行（先に保存） |
| **⌘F** | ステップを検索 |
| **⌘Z** | 元に戻す |
| **⌘C**、**⌘X**、**⌘V** | ステップのコピー、切り取り、貼り付け |

| **⌫** | 選択中のステップを削除 |
| **⌥↑**、**⌥↓** | 選択中のステップを上下に移動 |
| **⌘=**、**⌘-** | 拡大・縮小 |
| **⌘0** | ワークフロー全体を画面に収める |

**並列ジョブを追加** の横にあるキーボードアイコンからもすべてのショートカットを確認できます。

## ステップの動作

インスペクタの **動作** セクションでは、YAML を書かずにステップの実行方法を設定できます。ヘッダーには変更した内容（*条件付き… · リトライ 2 回* など）が表示され、未変更のときは **デフォルト** と表示されます。

| 設定 | 選択肢 | 書き出される YAML |
|---|---|---|
| **実行条件** | 毎回実行、条件が真のときのみ実行、あるいは前のステップの条件が偽だったときのみ実行。**前のステップが失敗またはスキップされても実行** をオンにすると上流で失敗しても実行されます。 | `if`、`else_of`、`run_when` |
| **繰り返し** | 1 回のみ、リストの各項目ごとに 1 回、または条件を満たすまで最大回数内でラウンドを繰り返す | `foreach`、`loop` |
| **失敗時の処理** | ワークフローを停止する、または続行して後続ステップを実行する。**リトライ** では失敗とみなす前に再試行する回数と、再試行間の待機時間を指定できます。 | `required: false`、`retries` |
| **待機対象** | 直前のステップ、何も待たずにすぐ開始、または前のステップおよび別ジョブのステップからチェックして指定 | `needs` |

**出力スキーマ** では、構造化された結果を得るための任意の JSON Schema を指定できます。再びデフォルトを選べば YAML からその設定が削除されます。各設定の詳細は [高度なワークフロー](/ja/workflows/advanced-workflows) で説明しています。

## 編集アシスタントを使う

エディタツールバーの **アシスタント** を選択するとキャンバスの横にアシスタントパネルが開きます。ここに「前の結果を要約するプロンプトステップを追加して」のように希望を入力します。空の新しいワークフローでは、「毎朝 Hacker News のトップ記事を取得して要約する」のようにプロセス全体を説明することもできます。Return で送信、**⇧↩** で改行でき、入力欄の下でモデルを選択できます。

アシスタントが作業している間は、ワークフローの読み込みやツールパラメータの確認、編集中といった状況がパネルに表示され、キャンバスもリアルタイムで更新されます。応答が終わるまでキャンバスは読み取り専用になります。途中で止めるには **停止** を選択してください。

### 作業中に続けて指示を送る

応答が終わるのを待たずに次の指示を送ることもできます。アシスタントの作業中に Return を押すと、メッセージが入力欄の上のキューに入り、各応答が終わり次第 1 件ずつ順番に送信されます。

- キューに入ったメッセージはドラッグで並び替えたり、**⋯** メニューで編集したり、ゴミ箱アイコンで削除したりできます。
- **停止** を選択するか応答が失敗した場合、キューは **保留中** になり自動送信されなくなります。再開する準備ができたらキュー内のメッセージで **送信** を選択してください。
- アシスタントの作業に対する修正など待てない指示を送るときは、Return の代わりに **⌘↩** を押すか、キュー内のメッセージで **今すぐ送信** を選択します。現在の応答はそれまでに行った編集を保ったまま **中断** として停止し、新しいメッセージが即座に送信されます。残りのキューは保留にならず、そのあと順番に送信されます。

### 変更箇所をレビューする

ワークフローを変更した応答の末尾には、追加・変更・削除されたステップを一覧表示するカードが付きます。応答が完了すると、追加されたステップにはキャンバス上で **Added**、変更されたステップには **Edited** のタグが付き、確認すべき箇所が一目で分かります。これらのタグは保存、元に戻す、または応答の復元を行うまで残ります。

- カード上のステップを選択すると、キャンバス上でそのステップが選択されて表示位置にスクロールされます。アシスタントが返信本文中で `summarize` のようにステップ ID を挙げた場合も同様にクリックで移動できます。
- 返信カード上の **実行** を選択すると、アシスタントによる最新の変更を試せます。ツールバーの **実行** と同じように動作し、必要な場合は入力を求めてから実行します。
- 最新のカードにある **元に戻す** を選択すると、その応答の前の状態にワークフローを戻せます。**元に戻す**（**⌘Z**）でも応答 1 回分の変更をまとめて取り消せます。

応答の結果ワークフローが無効な状態になった場合は、エディタが YAML 表示に切り替わりエラー箇所を示します。そこで手動修正するか、アシスタントに修正を依頼してください。**保存** を選択するまで、アシスタントによる編集は未保存の状態にとどまります。

### 特定のステップや結果を指定して聞く

- 1 つのステップについて尋ねたいときは、キャンバス上でそのステップを選択し、インスペクタで **アシスタントに聞く** を選択します。次のメッセージにそのステップが添付されるため、「これをもう少し安定させて」と言うだけでそのステップを指せます。
- 実行時にステップが失敗した場合は、実行サマリーまたはステップの **出力** タブにある **アシスタントで修正** を選択します。ステップとエラー内容がそのままメッセージに添付されるため、エラーをコピーし直す必要はありません。
- ステップ結果の一部について尋ねるには、**出力** タブで該当テキストを選択し、選択範囲の下に表示される **アシスタントに聞く** を選択します。そのテキストが引用として入力欄の上に表示され、次のメッセージと一緒に送信されるため、意味を尋ねたり生成元ステップの修正を頼んだりできます。

### チャット履歴と常時指示

パネル上部の **新しいチャット** を選択すると新しい会話からやり直せます（前のチャットも一覧に残ります）。パネル上部のチャット名を選択すると、同じワークフローに関する過去のチャットに切り替えたり、不要なチャットを削除したりできます。保存されたワークフローは、このブラウザ内に直近 10 件のチャットを保持します。

アシスタントに常に守らせたい基本ルールを設定するには、パネル上部の **設定**（スライダーアイコン）を選択し、**指示** に「ファイルは ~/Downloads に保存する」「prompt ステップには anthropic/claude-haiku-4-5 を使う」「日本語で返信する」などを記入して **⌘↩** を押すか **保存** を選択します。この指示はアシスタントが作成・編集するすべてのワークフローに適用され、設定アイコン上のドットで有効になっていることが分かります。使わなくするときは欄を空にして保存してください。

## 実行して結果を確認する

1. **入力** を選択し、今回の実行に使う値を入力します。
2. 定義を検証し、実行されるコマンドやツール呼び出しを確認します。
3. **実行** を選択し、グラフ上の各ステップのステータスを確認します。
4. ステップの **出力** タブを選択して結果またはエラーを確認します。実行後、各ステップカードにも説明文の代わりに「ステップが返した内容の最初の 1 行」または「失敗した理由」が表示されます。その行をクリックしてもステップの **出力** タブが開きます。チャットやドキュメントに貼り付けるときなどは、**出力** タブの **コピー** でステップの結果（何も返さなかった場合はエラー内容）をコピーできます。
5. **実行履歴** を開いて過去の実行を確認します。
6. 問題がなければワークフローを **保存** します。

<Warning>
ステップの内容によっては、実行時にプロバイダーのクレジットを消費したり外部データを変更したりすることがあります。Shell ステップや Tool ステップは、この Mac アカウントの権限で実行されます。
</Warning>

### 実行時の入力

ツールバーの **入力** を開くと、ワークフローが宣言している入力ごとに型・説明・デフォルト値を表示したフォームが開きます:

- 空欄のままにするとデフォルト値が使われます。リストやオブジェクトは `["a", "b"]` のような JSON 形式で入力します。
- **必須** と表示されていてデフォルト値がない項目は入力が必要です。空欄のままだったり型が合っていなかったりすると、保存や実行を始める前に **実行** が停止し、修正すべき項目を示します。
- 入力欄の中で **⌘↩** を押すとそのまま実行します。
- フォームには、Enconvo でこのワークフローを前回実行したときの値が初期表示されます。**クリア** を選択するとすべての項目を一度に空にでき、次回は再びデフォルト値が使われます。入力名を変更しても、そこに入力した値は引き継がれます。
- **最近の実行** から過去の実行をキャンバスに表示している間は、**その実行の値を使用** を選択して当時の入力値をフォームに読み込み、同じ条件または一部を変えた条件で再実行できます。
- 空の欄にはデフォルト値がグレーで表示されます。長いデフォルト値を打ち直さずに一部だけ変えたいときは、横の **デフォルトを編集** を選択して欄に値を展開してから編集します。
- Visual エディタで **入力を編集** を選択すると、ワークフローが求める入力項目を変更できます。まだステップから参照されている入力を削除しようとすると、該当ステップ名を挙げて確認を求めます。**JSON として編集** を選択すると、未宣言のキーも含めて 1 つの JSON オブジェクトとして入力を書けます。**フォームを使う** で元の表示に戻ります。

### 実行が終了したとき

実行が終わると、キャンバスの下部にサマリーが表示されます:

- ステップが失敗した場合、サマリーはそのステップ名と、終了コードだけでなく何が問題だったかを示すエラー行（例: `command not found: datex`）を表示します。**エラーを表示** を選択すると、そのステップの **出力** タブが開き、キャンバス上で該当ステップが画面内に表示されます。
- **アシスタントで修正** を選択すると、失敗したステップとエラーをアシスタントに渡します。アシスタントはまず原因を説明したうえでステップを修正します。API キー不足、ネットワークエラー、ファイル欠如などワークフロー外の原因である場合は、編集する代わりに何を変更すべきかを案内します。失敗したステップの **出力** タブにも同じ **アシスタントで修正** ボタンがあります。
- 失敗または停止した実行を途中から続けるには **再開** を選択します。すでに完了しているステップの結果はそのまま保持され、失敗したステップとそれ以降のステップだけが再実行されます。実行後にステップを編集した場合は、その編集したステップとそれ以降が再実行されます。実行入力を変更した場合はワークフロー全体が最初から実行されます。**再開** は、別の実行を始めるまでツールバーの **実行** の横にも表示されます。
- 正常に完了した後は、**出力を表示** を選択して最後のステップの結果を確認できます。特に確認が必要な点がない限りサマリーは数秒後に自動で消えますが、**×** をクリックしてすぐ閉じることもできます。

### 最近の実行

**最近の実行** には、このワークフローの過去の実行が新しい順に表示されます。各行には次の情報が表示されます:

- 成功・失敗・実行中のいずれか
- 開始時刻と所要時間
- スケジュール実行（**Scheduled**）かチャットからの実行（**From chat**）か
- 実行時に使った入力（カーソルを合わせるとすべて表示）と、失敗時はエラー内容

現在キャンバスに表示中の実行には **表示中** とマークが付きます。別の行を選択するとその実行の各ステップ結果がキャンバスに切り替わります。成功と失敗が混在しているときは、一覧上部の **失敗のみ** で失敗した実行だけに絞り込み、**すべての実行** で元に戻せます。

### スケジュール実行

実行履歴パネルの上部にある **スケジュール** には、このワークフローを実行する予約タスクが、次回実行時刻と実行時入力とともに一覧表示されます。

- 予約タスクの前回実行が失敗している場合は、**前回の実行が失敗** にカーソルを合わせて理由を確認するか、クリックしてその実行をキャンバスに開き、どのステップが失敗したか確認できます。
- スイッチで予約タスクのオン / オフを切り替えたり、鉛筆アイコンでスケジュールを変更したりできます。
- **スケジュールを追加** を選択すると、このワークフローが選択済みで、**実行入力** の値が引き継がれた状態のフォームがその場で開きます。
- スケジュールの **削除** を選択すると、その予約タスクが削除されます。

スケジュール実行では保存済みのワークフローが使われるため、次の実行までに変更を保存してください。すべての予約タスクはチャットウィンドウのサイドバーの **予約タスク** にも一覧表示されます。詳しくは [予約タスク](/ja/workflows/scheduled-jobs) を参照してください。

## YAML を編集する

保存すると、ワークフローは `~/.enconvo/workflows/<id>.yaml` に書き込まれます。**YAML** を選択すると、同じドキュメントをソースコードとして直接編集できます。エディタは入力と同時に検証を行い、エラーがあれば行と列を示し、意味を持たないフィールドには警告を表示します。**Valid** / **Invalid** バッジと **検証** アクションでドキュメント全体をチェックできます。ジョブ ID とステップ ID には英字・数字・アンダースコアを使い、先頭は英字またはアンダースコアにしてください。**Visual** に切り替えた後でも、**⌘Z** で YAML での編集をまとめて 1 ステップで取り消せます。

```yaml
version: agent-workflow/v1
title: Greeting
description: Produce a greeting and a formatted result without calling a model.
inputs:
  name:
    type: string
    default: world
jobs:
  main:
    steps:
      - id: greeting
        uses: transform
        value: "Hello, {{ inputs.name }}!"
      - id: result
        uses: transform
        value: "Result: {{ steps.greeting.output }}"
```

**入力** の **name** 欄に `Ada` と入力してこの例を実行すると、最後のステップで `Result: Hello, Ada!` が出力されます。

## 前の結果を参照する

| 式 | 値 |
| --- | --- |
| `{{ inputs.name }}` | 入力値 |
| `{{ steps.greeting.output }}` | 同じジョブ内の前のステップの出力 |
| `{{ jobs.research.search.output }}` | 別のジョブの完了済みステップの出力 |
| `{{ item }}` と `{{ index }}` | `foreach` 内の現在の要素とインデックス |
| `{{ round }}` と `{{ last }}` | ループ内の現在のラウンド番号と前回の出力 |

別ジョブの出力を参照する前に、ジョブレベルの `needs` を追加してください。すべてのツールが同じフィールドを返すとは限らないため、**出力** タブで実際のツール結果を確認してください。

### 手入力せずに値を挿入する

Visual エディタではこれらを手で入力する必要はありません。プロンプト、コマンド、ツール設定、条件などのステップ入力欄の右端にある **値を挿入**（`{x}` ボタン）を選択すると、そのステップから参照できる値の一覧（ワークフローの入力、同じジョブの前のステップの結果、待機対象ジョブのステップ、繰り返しステップなら現在の要素やラウンド）が表示されます。一覧を検索して 1 つ選ぶと、カーソル位置に挿入されるか選択中のテキストを置き換えます。

- シェルステップでは出力された標準出力テキストを `{{ steps.<id>.stdout | trim }}` として挿入できます。
- 出力スキーマが設定されたステップや一度実行したステップでは、結果内の各フィールドも一覧に並びます。
- 条件、**停止条件**、および繰り返す対象のリストには、条件欄での裸の `steps.check.output.ok` のようにその欄に適した形式が挿入されます。

参照できない項目を指定している欄には、その下に修正内容を案内する警告が表示されます（ワークフローが宣言していない入力、後で実行されるステップまたは自分自身、別ジョブのステップ、待機していないジョブなど）。キャンバス上でも、そのような値を含むステップカードにはタイトル横に警告アイコンが表示され、カーソルを合わせると修正点を確認できます。なお、警告があっても保存は可能です。

## ステップの種類

以下のスニペットはいずれも 1 つのステップ項目であり、ジョブの `steps` リスト内に配置します。Visual エディタでは、ステップピッカーから同じステップ種類を選択できます。

### Shell

```yaml
- id: today
  command: 'date "+%Y-%m-%d"'
```

結果は `steps.today.output.stdout` で参照できます。オプション設定として `cwd`、`shell`、`timeoutMs`、`env` があります。コマンドはお使いの Mac アカウントの権限で実行されるため、実行前に内容を確認してください。

### Prompt

```yaml
- id: summarize
  prompt: "Summarize this text: {{ inputs.text }}"
```

モデルを 1 回呼び出します。後続のステップで構造化フィールドが必要な場合は [出力スキーマ](/ja/workflows/advanced-workflows) を使用してください。

### Agent

```yaml
- id: plan
  agent: agent/main
  message: "Propose a three-step plan for {{ inputs.topic }}."
```

インストール済み Agent のコマンドキーを指定します。実行できる内容は、その Agent で有効なツールとプロバイダー設定によって決まります。

### Tool

```yaml
- id: saved
  tool: workflow/list
  with:
    limit: 5
```

`tool` にはスラッシュ形式のローカル API ルートを指定します。`with` でパラメータを渡します（`params` もエイリアスとして使えます）。利用可能なルートは **設定 → API** で確認するか、編集アシスタントにインストール済みツールを調べてもらってください。

### Transform

`uses: transform` と `value` を指定すると、モデルを呼び出さずに複数の入力や前の出力を組み合わせられます。[YAML ファイルの編集](#yaml-を編集する) の例では 2 つの transform ステップを使っています。

### Subworkflow

`uses: workflow` と保存済みの `workflowId`（またはインラインの `workflow` ドキュメント）を指定して、再利用可能な子プロセスを実行します。Visual エディタでは保存済みワークフローを名前で選び、求められる入力をフォームに入力します。ワークフローが選ばれていない Subworkflow ステップは実行できず、不足箇所を示して停止します。詳しくは [高度なワークフロー](/ja/workflows/advanced-workflows) を参照してください。

### Approval

```yaml
- id: confirm
  uses: approval
  message: "Post this summary to the team? {{ inputs.text }}"
```

Enconvo が `message` とともに **承認** と **却下** ボタンを表示して回答を待ちます（`timeoutMs` を設定しない限り最大 24 時間）。承認されると後続のステップが実行されます。却下された場合またはタイムアウトした場合は、偽の条件と同様にスキップされ、後続ステップはスキップされてその `else_of` ステップが実行されます。却下時に入力したテキストは `steps.confirm.output.feedback` に格納されます。送信・投稿・削除・決済などを行うステップの直前に配置してください。却下後に **再試行** を選択すると、新しい実行には何をなぜ却下したかが伝えられます。Subworkflow 内で承認を却下すると、Subworkflow だけでなくワークフロー全体の実行が停止します。

### Judge

```yaml
- id: urgent
  uses: judge
  question: Does this message ask for a reply today?
  input: "{{ inputs.text }}"
```

Enconvo Cloud の高速判定モデルである Jev が、`input` に関する `question` に `yes` と `probability` で回答します。確率が `threshold`（未指定時は 0.5）以上に達すると `yes` が true になります。`if: "{{ steps.urgent.output.yes }}"` と `else_of` ステップで分岐できます。

### Classify

```yaml
- id: kind
  uses: classify
  question: What kind of request is this?
  input: "{{ inputs.text }}"
  options:
    billing: A question about payments or invoices
    bug: A report that something is broken
    other: Anything else
```

インスペクタでは選択肢ごとに 1 行ずつ入力します。Jev が `options` の中から 1 つを選び、その `label`、`confidence`、および各選択肢の `probabilities` を返します。`options` は 2 つ以上のラベルのリスト、または各ラベルとその意味のマップです。分岐には `if: "{{ steps.kind.output.label == 'billing' }}"` を使用します。

Judge ステップと Classify ステップは Enconvo Cloud 上で実行されるため、サインイン済みで残りポイントが必要です。また、`output_schema` は指定できません。
