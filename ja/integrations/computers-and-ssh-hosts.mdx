Agent が作業できるのはこの Mac だけではありません。SSH でサインインできるサーバーを追加してチャット内でメンションすれば、手元の Mac について尋ねるのと同じ感覚で依頼できます。Agent がサーバー上でコマンドを実行し、その結果をこのチャットに返します。サーバー側へのインストールは不要です。Enconvo が動作している別のコンピュータも同じようにペアリングできます。

以下の動画では、SSH 設定から SSH ホストを追加し、Agent にログを読ませ、この Mac に接続できる端末を確認する流れを紹介しています。

## 始める前に

- この Mac から `ssh` でサインインできるサーバーが必要です（`~/.ssh/config` に定義されたホスト、または `user@host` 形式で指定できるアドレス）。Enconvo はこの Mac 自身の `ssh` と鍵を使用します。サーバーがパスワードやパスフレーズを求めた場合は Enconvo を通じて入力を求めますが、Enconvo がその情報を保存することはありません。
- ローカルネットワーク上のサーバーに接続する場合は、**システム設定 → プライバシーとセキュリティ → ローカルネットワーク** で Enconvo を許可してください。

## 「接続」に表示される一覧

**設定 → 接続** を開くと、3 つの一覧が表示されます:

| 一覧 | 表示内容 |
| --- | --- |
| **スマートフォン** | この Mac とペアリングされている iPhone および Android アプリ。詳しくは [iPhone アプリ](/ja/integrations/iphone-app) を参照してください。 |
| **コンピュータ** | この Mac とペアリングされている、Enconvo が動作する他のコンピュータ。各端末は制御方法とともに 1 行ずつ表示されます。追加するには **コンピュータをペアリング** をクリックします。詳しくは [他のコンピュータを使う](/ja/integrations/other-computers) を参照してください。 |
| **SSH ホスト** | 何もインストールせずに Agent が SSH 経由で接続できるサーバー。 |

スマートフォンやコンピュータをクリックすると、この Mac 上でその端末に許可されている操作を確認できる専用ページが開きます。

チャットウィンドウからホストの追加やコンピュータ・スマートフォンのペアリングを行うこともできます。サイドバー下部にあるデバイススイッチャーをクリックし、**デバイスを追加** を選択してください。

## SSH ホストを追加する

1. **設定 → 接続** を開き、**SSH ホスト** の下にある **ホストを追加** をクリックします。
2. `~/.ssh/config` にあるホストの一覧が表示されます。`build-server` などを選ぶか、`user@host`（または `user@host:port`）を入力します。
3. **接続** をクリックします。Enconvo がホストへの到達、ホストキーの確認、サインイン、テストコマンドの実行を行って接続を検証します。
4. **各コマンドの実行前** で、そこでコマンドを実行する前に Agent がどのように確認を求めるかを選びます:
   - **チャットに従う**: そのチャットの権限モードに従って確認します。詳しくは [Agent](/ja/ai/agents) を参照してください。
   - **毎回確認する**: すべてのコマンド実行前に必ず確認を求めます。
5. **ホストを追加** をクリックします。

これで **SSH ホスト** の一覧と、すべてのチャットの `@` メニューにそのホストが表示されるようになります。

初めて接続するサーバーのホストキーが表示されたら、サーバー管理者に鍵が正しいか確認したうえで **信頼して接続** をクリックしてください。Linux サーバーの場合は、そのサーバーをコンピュータとしてペアリングする **そこにも Enconvo をインストールする** というオプションも表示されます。何もインストールしない場合はオフのままにしてください。

## ホスト上で Agent に作業を依頼する

1. チャットで `@` に続けてホスト名の先頭を入力します。登録済みのコンピュータと SSH ホストは **コンピュータ** の下に表示されます。
2. ホストを選択すると、メッセージ内にチップとして挿入されます。
3. そこで実行したい内容を書いて送信します。例:

   ```text
   @build-server What errors are in ~/app/logs/app.log? Just read it, don't change anything.
   ```

Agent はホストに対して設定した確認ルールに従って確認を挟みつつ、SSH 経由でコマンドを実行します。各コマンドステップには実行されたホスト名が表示され、結果がチャットに返ります。

実際に実行された内容を確認するには、回答の上にある **作業時間** をクリックします。展開すると各コマンドが表示されます。

ペアリング済みのコンピュータも同じようにメンションできます。Agent はそのコンピュータ自身の Agent にタスクを引き渡すか、そのコンピュータがこの Mac からのターミナル操作を許可している場合はコマンドを実行します。

チャット上では、ホストや別のコンピュータ上で実行されたコマンドは **コマンドを実行しました** と表示され、各ステップに対象のマシン名が記載されます。

## ペアリング済みコンピュータ上で Agent を動かす

**設定 → 接続** で **コンピュータ** の下にあるコンピュータをクリックすると、その端末のページが開きます。2 つのスイッチにより、こちらのチャットにいる Agent がその端末で何を行えるかが決まります:

| スイッチ | 機能 |
| --- | --- |
| **Agent** | その端末の Agent をプロジェクトに追加したり、チャットを引き渡したりできます。タスクはそのコンピュータ上で実行され、その Agent が操作を行おうとするときはまずユーザーに確認を求めます。 |
| **コマンド** | こちらのチャットの Agent がそのコンピュータ上でコマンドを実行できるようになり、チャットの権限モードに従って確認を求めます。 |

スイッチが淡色表示になっている場合は、相手のコンピュータ側で許可されていません。相手のコンピュータ上でこの Mac 向けに **Agent** または **ターミナル** をオンにしてください。**コマンド** をオフにすると、同じコンピュータを指す SSH ホスト経由のコマンド実行も停止します。

別のコンピュータの Agent にこの Mac の画面やブラウザを直接操作させるには、この Mac 上の該当コンピュータページで **Agent による操作** をオンにします。詳しくは [他のコンピュータを使う](/ja/integrations/other-computers) を参照してください。

## ホストの設定を変更する

**SSH ホスト** の下にあるホストをクリックすると設定ページが開きます:

| 設定 | 機能 |
| --- | --- |
| **Agent が使用可能** | オフにすると、一覧には残りますがすべてのチャットから選択できなくなります。 |
| **各コマンドの実行前** | **チャットに従う** または **毎回確認する** を選択します。 |
| **ファイルをコピー** | Agent が `scp` を使ってホストとの間でファイルをコピーできるようにします。 |
| **開始フォルダ** | コマンドが最初に開くフォルダです。空欄にするとログイン時のホームフォルダになります。 |

ページの **⋯** メニューには **接続テスト** と **ホストを削除…** があります。ホストを削除しても Enconvo の登録が消えるだけで、`~/.ssh/config` やサーバー本体は変更されません。

## この Mac に接続できる端末を確認する

**設定 → 接続** の **この Mac に接続できる端末** には、この Mac にアクセスできるスマートフォンとコンピュータの台数が表示されます。

すべての接続を一括で遮断するには **すべてのアクセスを停止** をクリックして確定します。スマートフォンや他のコンピュータはどの Mac にも到達できなくなり、そこで実行中の処理も停止します。再度利用できるようにするには **アクセスを再度オンにする** をクリックしてください。

## トラブルシューティング

| 問題 | 対処法 |
| --- | --- |
| ローカルネットワーク上のサーバーに接続テストが届かない | macOS がローカルネットワーク権限の確認のため接続を保留しています。**Enconvo にローカルネットワークを許可** をクリックするか、**システム設定 → プライバシーとセキュリティ → ローカルネットワーク** で Enconvo をオンにしてから再試行してください。 |
| サーバーに鍵が拒否されたと表示される | `~/.ssh/config` にある該当ホストの `IdentityFile` を確認するか、`ssh-add` で鍵を追加してください。 |
| サーバーが以前と異なるホストキーを返した | サーバーが再構築されたか、通信経路上に別の機器が介在している可能性があります。再構築されたことが確実な場合は、ターミナルで `ssh-keygen -R` に続けてサーバーアドレスを実行して古い鍵を削除し、再試行してください。 |
| `@` メニューにホストが表示されない | ホストの設定ページを開き、**Agent が使用可能** をオンにしてください。 |
| パスワードまたはパスフレーズを間違えた | 入力に失敗した旨が表示されて入力ボックスが再度開くので、もう一度入力してください。 |
| 1 台のコンピュータに 2 つの SSH ホストがある | 最初のホストがそのコンピュータに紐づけられ、設定ページにもそちらが表示されます。最初のホストを削除すると、もう一方のホストが紐づきます。 |
| `~/.ssh/config` にホストが登録されていない | **ホストを追加** の欄に `user@host` 形式でアドレスを直接入力してください。 |
