---
title: "エージェントサンドボックス"
description: "エージェントのコマンド実行を作業フォルダ内に制限し、鍵情報や他アプリから隔離するとともに、実行前に Enconvo が確認を求める理由を把握します。"
---

サンドボックスは、エージェントが実行するシェルコマンドからアクセスできる範囲を制限します。オンにすると、コマンドはチャットの作業フォルダと一時フォルダのみを変更できるようになり、macOS によって鍵情報の読み取り、他アプリの操作、Enconvo への接続が遮断されます。コマンドを 1 つずつ見守りたくないエージェントで有効にしてください。

サンドボックスはエージェントの権限モードと併用されます。権限モードは操作前に Enconvo が確認を求めるタイミングを決め、サンドボックスはコマンドが実際に実行されたあとにできることを制限します。

## サンドボックスをオンにする

1. チャットウィンドウ、SmartBar、Dynamic Island、アプリのサイドバー、またはプロジェクトのリードチャットで、そのエージェントとのチャットを開きます。
2. 実行モードの横にある **権限** チップをクリックします。
3. **サンドボックス** をオンにします。

このスイッチはエージェントごとに保存されるため、そのエージェントを使うすべてのウィンドウに適用されます。呼び出された先のエージェントのコマンドもサンドボックス内で実行されます。

サンドボックスがエージェントのコマンドに許可しているアクセス範囲を見るには、スイッチの下の **サンドボックスの仕組み** をクリックします。作業フォルダ、権限モード、およびコマンドがアクセスできる場所・できない場所が図解されます。

## サンドボックス内のコマンドがアクセスできる範囲

| 対象 | サンドボックス内での扱い |
| --- | --- |
| 作業フォルダと一時フォルダ | 読み取り・変更が可能 |
| その他のファイル | 読み取りは可能、変更は不可 |
| インターネット | 接続可能 |
| SSH 鍵、キーチェーン、Cookie などの鍵・パスワード | 読み取り不可 |
| 保存済み認証情報と Enconvo の設定 | 読み取り不可 |
| 他のアプリ | 起動・操作ともに不可 |
| Enconvo 本体 | 接続不可 |

コマンドが起動するすべてのプログラムも同じくサンドボックス内で動作します。Enconvo は App Store アプリと同じ macOS 純正のサンドボックス機構を使用しています。

## サンドボックスがコマンドを止めたとき

サンドボックスで禁止されている対象にコマンドがアクセスしようとすると macOS が拒否し、ステップの下に「どのフォルダへの書き込み」や「どの鍵ファイルの読み取り」など、何が止められたかを示す行が表示されます。

1. その行をクリックすると、止められた内容と理由を確認できます。
2. そのコマンドに操作を許可したい場合は、**サンドボックス外で実行** をクリックします。コマンドがあなたのフルアクセス権限で 1 回だけ実行され、通常どおりチャットに表示されます。この許可は記憶されません。

**サンドボックス外で実行** は、実行中であなたが画面を見ているときにのみ表示されます。予約タスクなど誰も見ていない実行では、サンドボックス外でコマンドが実行されることはありません。

## コマンド実行前に Enconvo が確認を求める理由

どの操作で確認を求めるかは、サンドボックスのオン・オフにかかわらずエージェントの権限モードによって決まります。詳しくは [操作を承認する](/ja/ai/agents) を参照してください。

| モード | サンドボックスオン時の動作 |
| --- | --- |
| **承認を求める** | すべてのコマンドは実行前に確認を求めます。許可したコマンドが実行できる範囲はサンドボックスで制限されます。 |
| **自動で承認** | ファイル削除や公開などリスクのあるものを除き、コマンドは確認なしで実行されます。 |
| **フルアクセス** | コマンドは確認なしで実行されます。コンピュータに損害を与えうる変更のみ確認します。 |

Enconvo はコマンドを部分ごとに解析して読み取るため、引用符・ネスト・連結・パイプの中に隠された危険な処理であっても確認を求め、一方で `echo` やフォルダ一覧表示のような無害な処理では確認しません。

**フルアクセス** であっても、重要なフォルダの削除、シェル起動ファイルや SSH 鍵の編集、保存済みパスワードの読み取りなど、コンピュータに害を及ぼすおそれのある変更の前には、コマンド内でパスがどのように書かれていても **一度だけ許可** と **拒否** で確認を求めます。

**自動で承認** では、ルールだけで判断できないコマンドがあなたの依頼内容と照合されます。依頼からして自律実行が想定外であると判断される場合、Enconvo は理由を添えて確認を求めます。

各承認カードには、「このプロジェクトが自動で承認になっているため確認しています」のように、確認を求めた設定名が明記されます。

## その他の確認が入る操作

- [コンピューター操作](/ja/features/computer-use) は、クリックと同様に、削除・送信・支払い・アプリ終了・サインアウトを行うキーボードショートカットの前にも確認を求めます。
- プラグインページ独自のルートを呼び出すコマンドは先に確認を求めます。
- プラグインのツールを承認する際は、そのツールが送信しようとしている内容が表示されます。
- エージェントは [友だち](/ja/features/friends) やチームメイトに通話やメッセージを送る前に確認を求めます（**フルアクセス** 時のみ確認しません）。
- エージェント自身が承認カードに応答したり、自分の権限を引き上げたり、プラグインのインストールやポイント上限などユーザー向けのカードに応答したりすることはできません。

## トラブルシューティング

| 問題 | 対処方法 |
| --- | --- |
| コマンドが権限エラーで失敗する | サンドボックスが止めた可能性があります。ステップ下の行をクリックし、信頼できるコマンドであれば **サンドボックス外で実行** をクリックしてください。 |
| コマンドから他アプリを起動・操作できない | サンドボックス内のコマンドは他アプリを操作できません。[コンピューター操作](/ja/features/computer-use) を使うか、このエージェントのサンドボックスをオフにしてください。 |
| 確認されるはずの操作で確認が出なかった | **権限** チップでエージェントの権限モードを確認してください。**フルアクセス** はコンピュータに損害を与えうる変更の前にのみ確認します。 |
| **サンドボックス** スイッチが見つからない | チャットがエージェントモードになっているか確認し、Enconvo をアップデートしてください。詳しくは [アップデート](/ja/configuration/updates) を参照してください。 |
