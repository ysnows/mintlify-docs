使うプロバイダーにはそれぞれ認証情報が必要です。API キー、または契約中のプランへのサインインのどちらかです。認証情報はプロバイダー自身の設定ページで追加します。Enconvo はそれをプロバイダープロファイルに保存し、そのプロバイダーを使うすべての機能で共有します。**設定 → 認証情報の管理** では、すべての認証情報を 1 か所で確認できます。

この動画は、アバターとメッセージングチャネルに続いて、認証情報の管理で終わります。

## プロバイダーを追加する

<Steps>
  <Step title="カテゴリを開く">
    使いたいものの設定ページを開きます。たとえば **設定 → AI モデル**、**設定 → 画像生成**、**設定 → テキスト読み上げ** です。
  </Step>
  <Step title="プロバイダーを選ぶ">
    プロバイダーを選びます。別のキーやアカウントのために同じプロバイダーをもう 1 つ設定するには、**新しいプロバイダーを追加** を選びます。
  </Step>
  <Step title="サインイン方法を選ぶ">
    **認証** で **API キー** を選びます。プロバイダーが契約中のプランの利用に対応している場合は、**サブスクリプション** も選べます。
  </Step>
  <Step title="認証情報を追加する">
    API キーを貼り付けるか、プロバイダーのサインインを完了します。
  </Step>
  <Step title="テストする">
    ページに **検証** が表示されている場合はクリックし、モデルを選んで短いリクエストを試します。
  </Step>
</Steps>

API キーでは、プロバイダーの API アカウントに課金されます。サブスクリプションでは、プランに含まれる使用量とその上限が使われます。そのページがどちらを使うかは、**認証** の下の説明で確認できます。

## 共有プロファイル

**OpenAI 2** のようなプロバイダープロファイルには、そのプロバイダーの API キーとサブスクリプションのサインインが保存され、プロバイダーが対応するすべてのカテゴリに表示されます。プロファイルの名前を変更したり削除したりすると、いま開いているページだけでなく、それらすべてのカテゴリに反映されます。

モデル、音声、生成の設定は、カテゴリごとに別々に保持されます。ただし、新しい API キーはそのプロファイルを使うすべての機能に反映されるため、キーを変更したら、それらの機能をテストしてください。

プロバイダーが提供する内容はカテゴリによって異なります。AI チャットで使えるサインインが、そのプロバイダーのリアルタイム音声 API を含むとは限りません。カテゴリが API キーしか受け付けない場合は、そのページにその旨が表示され、サブスクリプションが使えるカテゴリも示されます。

## プランの使用状況を確認する

サブスクリプションのサインインでは、アカウントとプランの残り使用量が表示されます。**残り %** のような値は、残っている使用可能量です。アカウントカードのメニューを開き、**使用量を更新** を選ぶと更新され、**再接続** を選ぶと再度サインインできます。

Claude や Codex から無料の上限リセットが付与されている場合、Claude または ChatGPT のサブスクリプションカードに **無料の上限リセット** が表示され、その数と有効期限が分かります。**リセットを使う** をクリックして確認すると、上限が回復します。複数ある場合はカードに一覧が表示され、選んだものが使われます。

使用状況が表示されていなくても、使用量が無制限という意味ではありません。

## 認証情報を管理する

**設定 → 認証情報の管理** を開きます。一覧では、認証情報がプロバイダープロファイルごとにまとめられ、その後に、どのプロバイダーも使っていないキーが **未使用のキー** として表示されます。

- **プロバイダーを検索** に入力して、目的のものを探せます。
- **新しい認証情報を追加** をクリックすると、選んだサービス用に別の認証情報を作成できます。
- 認証情報を削除するには、その上にカーソルを置いてゴミ箱アイコンをクリックします。API キーを使うコネクタがそのキーを使っている場合は、確認画面にそのコネクタ名が表示されます。**削除して接続を解除** を選ぶと、別のキーを指定するまでそのコネクタの接続が解除されます。
- 一覧の下部にある **クリーンアップ** をクリックすると、未使用のキーをまとめて削除できます。ボタンにはその数が表示され、確認画面では先に一覧が表示されます。Enconvo が未使用のキーを自動で削除することはありません。

認証情報をクリックすると、そのキーを追加または変更できます。**利用元** には、その認証情報を使っている **AI モデル** や **テキスト読み上げ** などの機能が表示されます。クリックすると、その設定ページが開きます。

プロファイル自体の認証情報には、ここでは削除ボタンがありません。プロバイダーを削除すると一緒に削除されます。

該当するものがある場合は、さらに 2 つのグループが表示されます。Enconvo にプロバイダーがないサービスのキー用の **その他のサービス** と、保存した Web サイトやアプリのサインイン用の **ログイン情報** です。

## エージェントがキーを必要とするとき

タスクにサービスの API キーが必要になると、エージェントはキーの貼り付けを求める代わりに、チャットに **接続** カードを表示します。キーは会話ではなく認証情報の管理に保存され、以後のチャットでは改めて尋ねられることなく使われます。

Enconvo にプロバイダーがないサービスの場合、カードにはキーの送信先ホストが表示されます。キーは **その他のサービス** に保存され、エージェントはそのホストへのリクエストにだけ使えます。

エージェント自身がキーを保持することはありません。エージェントは保存済みの認証情報を名前で指定するだけで、リクエストやコマンドにキーが表示される箇所は `[redacted]` と読み取られます。

電話チャットでは、**接続** カードは iPhone に表示され、キーは Mac の認証情報の管理に保存されます。IM チャットでは、エージェントがキーを求めることはなく、代わりに Enconvo でそのチャットを開くリンクを送ります。

それでもメッセージに API キーを貼り付けた場合、Enconvo はそれを認証情報の管理に保存し、保存されるチャットでは `[redacted]` に置き換えます。そのため、以後のリクエストや他のデバイスにキーが渡ることはありません。すでにキーがあるサービスに新しいキーを貼り付けた場合は、保存済みのキーが置き換えられます。

## Web サイトとアプリのログイン

ブラウザのタスクがサインインページに到達すると、カードがユーザー名とパスワードを一度だけ尋ねます。Enconvo はそのサイトでのみ入力し、エージェントがパスワードを見ることはありません。保存したログイン情報は **ログイン情報** に表示されます。**このログイン情報を保存する** のチェックを外すと、そのサインインにだけ使われます。

Mac アプリのサインインにパスワードが必要なときは、カードにアプリ名が表示されます。Enconvo はそのアプリにのみユーザー名とパスワードを入力し、パスワードは入力内容が隠れるフィールドにのみ入力します。

## カスタムエンドポイント

**OpenAI 互換** と **Anthropic 互換** のプロバイダーには、自分のサーバー用の API ベース URL フィールドがあります。一部の組み込みプロバイダーでは、エンドポイントの設定を **認証情報の管理** に置いています。別のコンピューター上のモデルサーバーについては、[ローカルモデル](/ja/ai/local-llm) を参照してください。

保存済みのキーの送信先を変更できるのは、Enconvo 自身のウィンドウだけです。対象は、プロバイダーや認証情報のアドレス、および MCP サーバーによる保存済みキーの利用です。ローカル API を使う他のプログラム、電話、エージェントからの変更は拒否されます。

## キーの保管方法

- 保存されたキーとサインインは、この Mac のキーチェーンに残る鍵で暗号化されます。そのため、Enconvo の設定フォルダーをコピーしても、別のコンピューターでは読み取れません。Enconvo の古いバージョンに戻した場合は、キーをもう一度入力します。
- Enconvo の[ローカル API](/ja/advanced/cli-local-api) に設定を問い合わせた他のプログラムには、各キーの代わりに `[hidden]` が返されます。ストアのプラグインが使えるのは、そのプラグイン自身のキーと、その設定で選ばれた認証情報だけです。
- 保存されたキーを開けるのは、Enconvo がインストールし、変更されていないコードだけです。設定画面では、これまでどおりキーを表示して確認できます。

## トラブルシューティング

| 問題 | 対処 |
| --- | --- |
| 検証に失敗する | 選択したプロファイル、認証方法、エンドポイントを確認し、プロバイダーのアカウントにアクセス権があることを確かめてください。 |
| ある機能は動くが、別の機能は失敗する | その機能とモデルにアカウントが対応しているか確認してください。カテゴリが API キーしか受け付けない場合は、ページにその旨が表示されます。 |
| キーを変更したあと、動かなくなったものがある | プロファイルは共有されています。そのプロファイルを使う他のカテゴリもテストしてください。 |
| 使用状況の欄に **再接続** が表示される | サインインの有効期限が切れています。**再接続** をクリックして、もう一度サインインしてください。 |
