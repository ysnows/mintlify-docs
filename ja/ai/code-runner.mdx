title: "コードランナー"

---

コードランナーは、エージェントに Mac 上の実際のターミナルを与えます。ビルド、テスト、スクリプト、パッケージツール、開発サーバーに使ってください。何が実行できるかは、インストール済みのプログラムと、アカウントの権限で決まります。

<Warning>
エージェントの **サンドボックス** をオンにしない限り、コマンドは、あなたのアカウントによるファイルとネットワークへのアクセスで、実際に実行されます。ソフトウェアをインストールする、ファイルを変更する、オンラインサービスに影響を与えるコマンドは、実行前に確認してください。
</Warning>

## 始める前に

- 使用するエージェントで、コードランナーをオンにします。
- チャットの **権限** チップが、エージェントが先に確認を求めるタイミングを決めます。**承認を求める** は、コマンドを実行する前に確認を求め、**自動で承認** は、安全でなさそうな操作についてのみ確認を求めます。[アクションを承認する](/ja/ai/agents)を参照してください。
- エージェントのコマンドを作業フォルダに限定し、キーや他のアプリから遠ざけるには、同じチップで **サンドボックス** をオンにします。[エージェントのサンドボックス](/ja/configuration/sandbox)を参照してください。

## コマンドを実行する

エージェントにフォルダと具体的なタスクを伝えます。

> サンプルプロジェクトで、既存のテストコマンドを実行して結果を報告してください。ファイルは変更しないでください。

エージェントは、コマンドの出力を表示し、完了したか、まだ実行中かを伝えます。ファイルの読み取り、編集、検索には、代わりに[ファイルツール](/ja/ai/file-tools)を使います。

## コマンドが実行されるしくみ

すべてのコマンドは擬似端末で実行されるため、入力を求めるコマンドには、新しいプロセスを起動せずに答えられます。

| モード | 用途 |
| --- | --- |
| **oneshot** | テスト、ビルド、スクリプトなど、自力で終了するコマンド |
| **long_running** | サーバー、ウォッチャー、外部のイベントを待つプロセス |
| **interactive** | REPL、ターミナルアプリ、対話式のコマンドラインセッション |

結果に `status: running` と `session_id` がある場合、プロセスは動き続けています。エージェントは、その出力を **read**、入力を **write**、または **stop** できます。プロンプトに答えるには、エージェントがそのセッションに書き込みます。別のコマンドを開始しても、答えたことにはなりません。

## 完了を待つ

ビルドが出力を書き込むのを待つ、サーバーが起動するのを待つなど、タスクが待機する必要がある場合、エージェントは、シェルのループの代わりに **Wait For** ツールを使います。コマンドを実行せずに、次のいずれかを待ちます。

- ファイルが現れる
- ログファイルに特定の行が出る
- プロセスまたはコマンドのセッションが終了する
- ポートが開く、またはアドレスが応答する

待機は、チャットのバックグラウンドタスクに表示されます。条件が満たされたとき、失敗したとき、タイムアウトしたときに、エージェントに通知され、その間、他の作業を進められます。

## 作業フォルダと時間制限

コマンドは、エージェントが `workDir` を設定した場合はそこで、設定しない場合はチャットの作業フォルダで実行されます。プロジェクトと Python の仮想環境が設定された、あなたのシェルが使われます。別々のコマンドは、同じセッションで実行されない限り、一時的なシェル変数を共有しません。

最初の待機は、コマンドの厳密な時間制限とは別です。oneshot コマンドは、結果を最大 30 秒待ちます。その時点でまだ実行中の場合、エージェントはそこまでの出力を受け取り、作業は続きます。コマンドは、デフォルトで 30 分後に停止されます。サーバーやウォッチャーには、失敗した oneshot コマンドとして扱うのではなく、long_running モードを使ってください。

## 設定

**設定 → プラグイン → コードランナー** を開きます。

| 設定 | 変更される内容 |
| --- | --- |
| **RTK を有効にする** | エージェントが読み取る前に、長いコマンド出力を圧縮して、トークンの使用量を減らします。デフォルトでオンです |

圧縮された出力に必要な詳細がない場合は、より絞り込んだコマンドや、ログの該当部分を頼んでください。出力が途中で切れていても、コマンドが成功した証拠にはなりません。

## トラブルシューティング

| 問題 | 対処 |
| --- | --- |
| コマンドが見つからない | プログラムがインストールされ、シェルで使えることを確認してください |
| コマンドが入力を待っている | 同じセッションで、エージェントにプロンプトへ答えさせてください。誰も入力できない入力を待つコマンドは、すぐに終了します |
| 権限が拒否された | 対象のパスと macOS の権限を確認してください。サンドボックスがオンの場合は、ステップの下の行をクリックして、何が止められたかを確認してください |
| コマンドがタイムアウトした | 最後の出力を読み、もう一度実行する前に、適切なモードを選んでください |
| サーバーが動き続けている | 不要になったら、エージェントにそのセッションを停止させてください |
