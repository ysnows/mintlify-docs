作業によっては、情報を集めるリサーチャー、記事にまとめるライター、実装者とレビュアーなど、複数のエージェントが必要になることがあります。チャット内でエージェント名を指定すると、会話しているエージェントがリードとなり、作業プランを作成して各メンバーにタスクを割り当て、ゴールに対して結果を確認します。継続的な作業には、[プロジェクト](#プロジェクト) を使うと 1 つのフォルダのプラン、チャット、ファイルをまとめて管理できます。

## 複数のエージェントに仕事を任せる

1. 任意のチャットで `@` とエージェント名の先頭を入力し、リストから選んで Return キーを押します。作業に必要なだけエージェントを追加してください。
2. 各エージェントに担当してほしい内容を書いて送信します。例: 「@Researcher 京都の竹林について 3 つ事実を調べて、その後 @Writer が短い投稿にまとめて。」
3. リードが作業プランを返します。プランには **ゴール**、完了の判断基準となる **完了条件**、対象外事項、そして各メンバーのタスクが含まれます。各タスクにはゴールとこれらの条件がそのまま渡されます。別のタスクの結果を必要とするタスクは完了を待機し、そのタスクの未マージの変更を取り込んだ状態で開始します。
4. プランがあなたの確認待ちになっている場合は、内容を確認して **開始**、**プランを変更**、または **取り下げ** をクリックします。開始するとメンバーが動き出します。
5. タスクが完了すると、プランカードにそれぞれの結果が表示され、リードがゴールを達成できたかどうかを報告します。

プロジェクトのメンバーではないエージェントやコーディングエージェントであっても、チームメイトとしてタスクを割り当てられます。リクエスト内で名前を指定し、じっくり考えさせたい場合や素早く答えたい場合は推論の強さも指定してください。

Codex を含むプランを開始する際、Enconvo は最初にフォルダへのアクセス許可を求めます。これにより、あなたが席を離れたあとにアクセス確認で処理が止まるのを防ぎます。

## 実行中のプランを追う

プランの実行中、チャット上部にゴール、進捗、コスト、経過時間が表示されます。ここをクリックすると実行ビューが開き、各タスクのステップ、調査結果、提示された根拠、メンバーごとのコスト、そしてタスクが完了できなかった理由を確認できます。

一部の結果は、プランを進める前にあなたの判断を待ちます。保留された結果やレビュー指摘を受け入れる場合は **引き継ぐ** を、メンバーに修正させる場合は **差し戻す** をクリックします。

## 結果を読む

プランが完了すると、結果カードの先頭に結論と次のステップが表示され、その下に各タスクの詳細な結果が並びます。コーディングタスクには **マージ** ボタンがあり、まだマージされていないタスクがある場合はその一覧も表示されます。

リードは各 **完了条件** を確認し、どのタスクによって達成が示されているかを伝えます。タスク側で明確に裏付けられていない主張がある場合は、独立したチェックがフラグを立てます。ゴールがまだ満たされていない場合、リードは同じ予算内で最大 5 回まで追加のプランを継続できます。

また、リードは今後の実行時の計画に活かせる教訓を最大 3 つ提案することがあります。残すかどうかを個別に選択でき、採用したものだけが [メモリ](/ja/ai/memory) に保存されます。

## ボードで進捗を追う

チャット上部の **ボード** をクリックすると、タスクがカード形式で表示されます。各タスクには `T-1` のような番号が付き、**開始待ち** → **実行中** → **完了** と移動します。回答や承認を待っている項目は **確認待ち** に入ります。

| コントロール | 動作 |
| --- | --- |
| **すべて** / **確認待ち** | すべてのタスクを表示するか、あなたの確認待ちだけを表示します。 |
| **グループ化** | アイデア別や **チャット** 別などでカードをグループ化します。 |
| **表示** | 各カードに表示する情報を切り替えます。 |
| **Search tasks or T-12** | キーワードや番号でタスクを検索します。 |

サイドバーのアイコンレールにある **···** メニューの **ボード** では、すべてのチャットのタスクをまとめて確認できます。タスクを持つチャットは、サイドバーの該当行の下にもタスク一覧を表示します。

タスクのチェックと修正ラウンドで同じ問題が繰り返し見つかる場合、再試行を続けるのではなくラウンドを停止します。また、チェック自体を実行できない場合は、動作するコードを差し戻すのではなく、実行できない理由を伝えます。

## プロジェクト

プロジェクトは関連するチャットを 1 つのフォルダ単位でまとめ、そのフォルダの `AGENTS.md` がプロジェクトの指示になります。サイドバーで **プロジェクト** の横にある **+** をクリックすると **プロジェクトを作成** が開きます。

- **プロジェクト名** を入力して「書類」フォルダ内に新しいフォルダを作るか、**既存のフォルダを使用** または **リポジトリをクローン** をクリックします。
- **テンプレート** で **空白** またはチーム（**リサーチデスク**、**コンテンツスタジオ**、**アプリ開発チーム**、**旅行プランナー**）を選びます。

### リポジトリをクローンする

1. **プロジェクトを作成** で **リポジトリをクローン** をクリックします。
2. GitHub の URL、`owner/name`、または任意の Git アドレスを貼り付けます。GitHub にサインイン済みの場合は、一覧から自分のリポジトリを選ぶこともできます。
3. **クローン** をクリックします。リポジトリが新しいフォルダにコピーされ、プロジェクトとして開きます。

### 誰が作業を行うか

メンバーがいるプロジェクトでは、リードが各ゴールを計画し、メンバーが実装して、レビューまたはテストで検証します。メンバーには Claude Code や Codex などのコーディングエージェントを含められます。各コーディングタスクはコードの独立したコピー上で作業し、準備ができたらプランの結果カードにある **マージ** ボタンで取り込めます。

Claude Code、Codex、Grok Build、または Antigravity をプロジェクトのリードにすることもできます。メンバーがいる場合、コーディングエージェントのリードも他のリードと同様にメンバーの作業をワークプランとして計画し、結果を読み取ります。メンバーがいないプロジェクトでは、メンバーを追加するまでワークプランやボードのタスクを作らず、チャット内で直接作業を行います。

プロジェクトのリードチャットでは、Opus 5.5 のようにモデル名を指定して一部の作業を任せたり、Claude Code で Opus 5.5 を使うようにエージェントとモデルを組み合わせて指定したりできます。リードは自分自身の作業用にサブエージェントを起動することもできます。プロジェクトのゴールやタスクを独自のワークフローで実行する方法は、[独自のワークフローを使う](/ja/ai/projects) を参照してください。

メンバーはプランの開始、承認、設定変更、ソフトウェアのインストール、あなたのサインイン情報の使用を行えません。また、コーディングエージェントのメンバーはプッシュ、他ブランチへの移動、ワークツリーの削除を行えず、マージとプッシュを実行できるのは Enconvo だけです。プロジェクトのリードチャットやタスクにおける「フルアクセス」は、他のチャットと同じように機能します。ボード、アイデア、プロジェクトの設定については [プロジェクトとボード](/ja/ai/projects) を参照してください。

## トラブルシューティング

| 問題 | 対処方法 |
| --- | --- |
| エージェントを選ぶつもりが Return キーで送信されてしまった | 入力欄の下にエージェント候補一覧が表示されてから Return キーを押してください。 |
| タスクが **確認待ち** のまま止まっている | そのタスクまたはチャットを開き、待機している質問や承認に応答してください。 |
| コーディングエージェントが起動しない | 先にインストールとサインインを行ってください。詳しくは [コーディングエージェント](/ja/ai/coding-agents) を参照してください。 |
| Codex のプランがフォルダアクセスの確認で止まる | プラン開始時のフォルダアクセス確認に回答すると、その後は自動で進められます。 |
