1 人のエージェントでは足りない仕事もあります。事実を調べるリサーチャー、それを投稿にまとめるライター、変更を担当するコーダーとレビュアーなどです。チャットでエージェントを指名すると、話しかけているエージェントがリードになります。リードはワークプランを作り、各メンバーにタスクを割り当て、結果をゴールに照らして確認します。継続的な作業には、1 つのフォルダのプラン、チャット、ファイルをまとめて管理する[プロジェクト](#プロジェクト)が便利です。

下の動画では、@ でエージェントを呼び出す方法、ワークプラン、ボード、プロジェクトまでの一連の流れを 2 分足らずで紹介しています。

## 複数のエージェントに仕事を任せる

1. 任意のチャットで `@` とエージェント名の最初の部分を入力し、Return キーを押して一覧から選びます。仕事に必要なだけエージェントを追加できます。
2. それぞれにしてほしいことを説明して送信します。たとえば「@Researcher が京都の竹林について 3 つの事実を調べて、そのあと @Writer が短い投稿にまとめて」のように入力します。
3. リードは、ワークプランを返します。内容は、**ゴール**、達成とみなす条件（**完了条件**）、対象外にすること、メンバーごとに 1 つのタスクです。各タスクには、ゴールとこれらの行がそのまま渡されます。別のタスクの結果が必要なタスクはその完了を待ち、そのタスクの未マージの作業をマージした状態で始まります。
4. プランがあなたの確認を待っている場合は、内容を確認してから**開始**、**プランを変更**、**取り下げ**のいずれかをクリックします。メンバーは、プランを開始したときに動き出します。
5. タスクが終わると、プランカードに各結果が表示され、リードがゴールを達成したかどうかを伝えます。

タスクは、あなたのどのエージェントやコーディングエージェントにもチームメイトとして割り当てられます。プロジェクトのメンバーでなくても構いません。リクエストの中で名前を挙げ、より深く考えさせたい場合や素早く答えさせたい場合は、推論エフォートも選んでください。

Codex を含むプランを開始すると、Enconvo は最初にフォルダへのアクセスを確認します。席を離れたあとで実行が止まらないようにするためです。

## 実行中のプランを追う

プランの実行中は、チャットの上にゴール、進捗、コスト、時間を示す行が表示されます。クリックすると実行ビューが開き、各タスクのステップ、見つかったこと、示された根拠、メンバーごとのコスト、タスクが完了しなかった理由を確認できます。

一部の結果は、プランが先に進む前にあなたの判断を待ちます。保留中の結果やレビューの指摘を受け入れるには**引き継ぐ**を、メンバーに修正させるには**差し戻す**をクリックします。

## 結果を確認する

プランが終わると、結果カードの先頭に結果の要点と次にすることが表示されます。その下に各タスクの詳しい結果が並びます。コーディングタスクには**マージ**ボタンがあり、まだマージしていないタスクがあれば、その名前が 1 行で表示されます。

リードは各**完了条件**を確認し、どのタスクで達成が確認できたかを伝えます。独立した確認では、タスクの結果から明確に確認できない主張に印が付きます。ゴールがまだ達成されていない場合、リードは同じゴールのために、1 つの予算の範囲で最大 5 つまで追加のプランを続けられます。

リードは、以降の実行で計画に役立てる教訓を最大 3 つ提案することもあります。それぞれを残すか破棄するか選べます。残したものだけが[メモリ](/ja/ai/memory)に反映されます。

## ボードで追う

チャットの上部にある**ボード**をクリックすると、そのチャットのタスクがカードとして表示されます。各タスクには T-1 のような番号が付き、**開始待ち**から**実行中**、**完了**へ進みます。**確認待ち**には、あなたの回答や承認を待っているものが入ります。

| 操作 | 内容 |
| --- | --- |
| **すべて** / **確認待ち** | すべてのタスク、またはあなたを待っているタスクだけを表示します。 |
| **グループ化** | カードをグループ化します（たとえばアイデア別や**チャット**別）。 |
| **表示** | 各カードに表示する内容を変更します。 |
| **タスクまたは T-12 を検索** | 言葉または番号でタスクを探します。 |

サイドバーのアイコンレールにある **···** メニューの**ボード**には、すべてのチャットのタスクが表示されます。タスクのあるチャットは、サイドバーのその行の下にも一覧されます。

あるタスクのチェックと修正のラウンドで同じ問題が見つかり続ける場合は、再試行せずにラウンドを止めます。実行できないチェックは、動作するコードを差し戻すのではなく、その旨を伝えます。

## プロジェクト

プロジェクトは、関連するチャットを 1 つのフォルダを中心にまとめるもので、そのフォルダの `AGENTS.md` がプロジェクトの指示になります。サイドバーの**プロジェクト**の横にある **+** をクリックすると、**プロジェクトを作成**が開きます。

- **プロジェクト名**を入力すると「書類」に新しいフォルダが作られます。または、**既存のフォルダを使用**や**リポジトリをクローン**をクリックします。
- **テンプレート**で、**空白**またはチームを選びます。チームは、**リサーチデスク**、**コンテンツスタジオ**、**アプリ開発チーム**、**旅行プランナー**です。

### リポジトリをクローンする

1. **プロジェクトを作成**で、**リポジトリをクローン**をクリックします。
2. GitHub の URL、`owner/name`、または任意の Git アドレスを貼り付けます。GitHub にログインしている場合は、一覧から自分のリポジトリを選ぶこともできます。
3. **クローン**をクリックします。リポジトリが新しいフォルダにコピーされ、プロジェクトとして開きます。

### 誰が作業するか

メンバーのいるプロジェクトでは、リードが各ゴールを計画し、メンバーがそれを作り、レビューまたはテストが確認します。メンバーには、Claude Code や Codex などのコーディングエージェントも含められます。各コーディングタスクは、コードの専用コピーで作業し、プランの結果カードには、準備ができたときのための**マージ**ボタンがあります。

Claude Code、Codex、Grok Build、Antigravity は、プロジェクトのリードになれます。メンバーがいる場合、コーディングエージェントのリードも、ほかのリードと同じように、メンバーの作業をワークプランで計画し、結果を読み取ります。メンバーのいないプロジェクトでは、メンバーを追加するまで、ワークプランもボードのタスクもなく、チャットの中で自分で作業します。

プロジェクトのリードのチャットでは、リクエストの一部を Opus 5.5 のようにモデル名を挙げて任せたり、「Opus 5.5 上の Claude Code」のようにエージェントとモデルを一緒に指定したりできます。リードは、自分の作業のためにサブエージェントを起動することもできます。プロジェクトは、独自のワークフローでゴールとタスクを実行できます。[独自のワークフローを使う](/ja/ai/projects)をご覧ください。

メンバーは、プランの開始、承認、設定の変更、ソフトウェアのインストール、あなたのログインの利用はできません。コーディングエージェントのメンバーは、プッシュ、ほかのブランチの移動、ワークツリーの削除ができません。マージとプッシュを行えるのは Enconvo だけです。プロジェクトのリードのチャットとそのタスクでのフルアクセスは、ほかのチャットと同じように動作します。ボード、アイデア、プロジェクトの設定については、[プロジェクトとボード](/ja/ai/projects)をご覧ください。

## トラブルシューティング

| 問題 | 対処 |
| --- | --- |
| Return キーを押したら、エージェントが選ばれずにメッセージが送信された | 入力欄の下にエージェントの一覧が表示されてから Return キーを押してください。 |
| タスクが**確認待ち**のまま止まっている | タスクまたはチャットを開き、待っている質問や承認に答えてください。 |
| コーディングエージェントが起動できない | 先にインストールしてログインしてください。[コーディングエージェント](/ja/ai/coding-agents)をご覧ください。 |
| Codex のプランがフォルダへのアクセスを確認するために止まる | プランの開始時にフォルダアクセスの確認に答えると、あなたがいなくても実行を続けられます。 |
