プロジェクトは、1 つのフォルダに関するチャット、アイデア、チームをまとめて管理します。やりたいことをアイデアとして書き留めると、プロジェクトのリードがチームと一緒に計画し、各タスクは完了までボード上を進みます。Web サイトやアプリのような継続的な作業で、何が実行中で何があなたの対応待ちかをひと目で把握したいときに、プロジェクトを使ってください。

下の動画では、プロジェクトを開き、作業の一部を Claude Code に任せるアイデアを追加して、ボードで進み具合を追い、プロジェクトをアーカイブして復元するまでを紹介しています。

## はじめる前に

プロジェクトが必要です。チャットウィンドウのサイドバーで**プロジェクト**の横にある **+** をクリックし、フォルダを選びます。[プロジェクトを作成する](/ja/ai/agent-orchestrator)をご覧ください。Claude Code や Codex などのコーディングエージェントにタスクを任せるには、先にインストールしてログインしてください。[コーディングエージェント](/ja/ai/coding-agents)をご覧ください。

## プロジェクトを開く

サイドバーでプロジェクトをクリックします。ページには 3 つのタブがあります。

| タブ | 表示される内容 |
| --- | --- |
| **チャット** | プロジェクトのリードとのチャットと、[あなたの対応待ち](#確認が必要なものを見る)のパネル。 |
| **ボード** | プロジェクトのアイデア。**未開始**から**計画中**、**進行中**を経て**完了**へ進みます。 |
| **チームと設定** | チームのメンバーと、チームが[あなたに確認するタイミング](#チームが確認するタイミングを選ぶ)。 |

チームの顔が、リードを先頭に左上に表示されます。プロジェクトのチャットのタスクは、サイドバーのその行の下にも表示されます。

## アイデアを追加する

アイデアとは、プロジェクトにやってほしいことです。

1. **ボード**タブを開き、**新しいアイデア**をクリックします。
2. 話しかけるように、やりたいことを書きます。スクリーンショットやファイルを添付したり、マイクをクリックして話したりすることもできます。
3. 必要に応じて**優先度**を設定します。**種類**は、書いた内容から Enconvo が推測します。**機能**、**バグ**、**改善**、**ドキュメント**、**リサーチ**のいずれかです。推測が違う場合は変更してください。
4. **アイデアを追加**をクリックします。

アイデアは、**未開始**の下にカードとして表示されます。カードには、書いた内容から付けた短いタイトルと、優先度を示す赤、黄、青の旗が付きます。リードはすぐに計画を始め、アイデアを**計画中**に移します。添付したファイルは、アイデアの開始時にリードへ渡されます。1 種類のアイデアだけを表示するには、**種類で絞り込む**を使います。

アイデアが自動で届くこともあります。[予約タスク](/ja/workflows/scheduled-jobs)に **Ideas に追加**アクションを設定すると、受け取った GitHub の issue、Discord や Telegram のメッセージ、メール、Webhook が、それぞれプロジェクトのボードのアイデアになります。リードはバグを再現して修正を計画し、リクエストの場合は調べたうえで、理由を付けて閉じるか計画し、何かを変更する前にあなたに確認します。

計画ができあがると、各タスク、担当者、使用するモデルが表示されます。内容を確認して、**開始**をクリックします。アイデアは**進行中**に移ります。リードはアイデアの**ゴール**と**完了条件**の行をもとに計画し、リードがそのゴールを達成したと判断して初めて、アイデアは**完了**に移ります。

## アイデアを追う

アイデアをクリックすると、そのページが開きます。片側にリードとのチャット、もう片側にアイデアの計画、タスク、本文、ファイル、ゴールが表示されます。**進み具合**には、**作業を計画**、**作業を実行**、**レビューとテスト**のそれぞれの進捗と担当者が表示されます。

完了したアイデアの作業をもう一度行うには、**再開**をクリックします。

タスクのあるアイデアには、上部に 2 つのビューがあります。**タスク**はそのタスクだけをボードとして表示し、**チャット**にリードの名前を続けたもの（たとえば **Mavis とチャット**）は、計画したチャットを開きます。

## コーディングエージェントにタスクを任せる

アイデアまたはプロジェクトのチャットで、エージェントを指名します。モデルを指定したい場合は、それも書きます。Opus 5.5 のようにモデルだけを指名することもでき、その場合リードはそのタスクをそのモデルで行います。メンバーのいないプロジェクトでも使えます。たとえば次のように入力します。

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

リードは、指名された部分を、そのエージェントとそのモデルによるタスクとして計画します。そのエージェントがプロジェクトのメンバーでなくても同様で、残りはリード自身が行うこともできます。計画とボードには、担当者の横にモデルが表示されます。名前が複数のモデルを指す場合や、どのモデルにも当てはまらない場合は、リードが確認します。

コーディングエージェントが終わると、そのタスクは、アイデアの**タスク**ボードの**レビュー待ち**であなたのレビューを待ちます。フォルダが git リポジトリでないプロジェクトでは、そのまま**完了**になります。各コーディングタスクはコードの専用コピーで作業し、プランの結果カードには、準備ができたときのための**マージ**があります。メンバー自身はプッシュもマージもできません。

チャットタブやアイデアからリードに渡した各タスクは、アイデア別またはチャット別にグループ化されて、ボードに表示されます。1 つの会話を追うには、ボードのチャットフィルタでチャットを選ぶか、**グループ化**で**チャット**を選びます。

プロジェクトのチャットで行った作業もボードに表示されます。チャットがファイルを変更したりコマンドを実行したりすると、カードが**完了**まで追従し、短い要約と変更したファイルが表示されます。カードをクリックすると、そのチャットが開きます。リードはこれらのカードを見て、自分のタスクが同じファイルを触らないようにします。

## 完成した作業をマージする

タスクまたはプランの結果カードの**マージ**をクリックすると、プロジェクトの**ベースブランチ**にマージされます。同じファイルの別の箇所にコミットされていない変更があっても、マージは止まりません。git が使用中の場合、マージは少しの間待ち、ロックファイルが残っているときはそのファイル名を表示します。

クリックせずにマージするには、**プロジェクトの設定 → ボード**で**通過した作業をマージ**をオンにします。**ワークツリー**で設定する**ベースブランチ**が必要です。以後、各タスクは、チェックと、別ベンダーのエージェントによるレビューに通ると、自動でマージされます。**通過条件**で、**ブロッキング指摘なし**、**レビュアーが承認**、**チェックのみ**から選べます。競合のあるタスクはメンバーに戻されます。レビュアーが実行できないときは、マージをスキップせずにすべて一時停止します。

### git を使わないプロジェクト

フォルダが git リポジトリでないプロジェクトでは、各リードのチャットがワークプランを自分のチャットフォルダに保存するため、2 つのリードのチャットが同時にプランを実行できます。プランのカードには**保存先**とそのフォルダが表示され、**ほかに変更されたファイル**には、タスクがその外で触れたファイルが一覧されます。

## そのほかの方法でリードに頼む

プロジェクトのリードのチャットでは、次のことができます。

- **回答を比較**は、2 〜 6 のエージェントに同じ質問をし、リードが回答を比較します。
- **スタイルを使用**は、リードの回答の書き方を選びます。

Codex、Claude Code、またはほかのエージェントに現在の作業をレビューやテストしてもらうには、頼むだけで構いません。プロジェクトでは、リードがそのエージェントをサブエージェントとして起動し、結果を同じチャットに戻します。リードは、プロジェクトのメンバーに渡すタスクとは別に、自分の作業のためにサブエージェントを起動することもできます。

プロジェクトのワークフローでタスクを実行するには、`@` を入力してワークフローを選ぶか、**チームと設定**タブでそのワークフローの横にある**チャットで使う**をクリックします。[独自のワークフローを使う](#独自のワークフローを使う)をご覧ください。

## 確認が必要なものを見る

**チャット**タブを開きます。メッセージ欄の上のパネルには 3 つの列があります。

| 列 | 一覧されるもの |
| --- | --- |
| **確認待ち** | あなたの回答、承認、レビューを待っているタスク。 |
| **作業中** | 実行中のタスク。 |
| **新しい結果** | まだ開いていない完了済みのタスク。 |

行をクリックすると、そのアイデアが開きます。

## すべてをボードで確認する

チャットウィンドウのサイドバーのアイコンレールにある **···** メニューの**ボード**には、すべてのチャット、プロジェクト、チームのタスクが 1 か所に表示されます。ボードをレールに残すには、そのメニューで**サイドバーをカスタマイズ…**を選びます。[チャットウィンドウ](/ja/ai/chat)をご覧ください。

一部のプロジェクトだけを表示するには、左上のフィルタ（**すべてのボード**）をクリックして、表示したいものを選びます。ボードのそのほかの操作は、[ボードで追う](/ja/ai/agent-orchestrator)をご覧ください。

## チームを設定する

**チームと設定**タブを開きます。上部にリードと各メンバーが表示され、**メンバーを追加**で別のエージェントを加えられます。左上のチームの顔をクリックすると、チーム全体が一度に表示されます。リードには**変更**があり、各メンバーにはその場で編集できるロールがあります。

リードには、あなたのエージェントか、コーディングエージェント（Claude Code、Codex、Grok Build、Antigravity）を選べます。コーディングエージェントのリードは、ほかのリードと同じように、メンバーの作業をワークプランで計画し、結果を読み取ります。

メンバーには、[ペアリングしたほかのコンピューター](/ja/integrations/other-computers)上のエージェントも選べます。リードは、そのコンピューターが必要なタスクをメンバーに任せ、答えはタスクの結果として戻ります。お使いのアカウントで、そのコンピューターにデバイスへのアクセスがない場合は、タスクにその旨が表示され、**デバイスを管理**が案内されます。

### チームの動き方

チャットやアイデアからリードに渡すすべてのゴールは、**標準**の流れで進みます。**作業を計画**、**作業を実行**、**レビューとテスト**の順です。各ステップを誰が担当するかを選べます。計画をメンバーに任せると、依頼したときにそのメンバーが計画を作り、リードはそのタスクをワークプランとして提案して、あなたの**開始**を待ちます。チェックのオンとオフ、タスクが修正のために戻される回数である**修正回数**も設定できます。

### 独自のワークフローを使う

**チームと設定**タブの**カスタムワークフロー**は、オンにするまでオフです。オフの間は、すべてのゴールが**標準**で進みます。オンにすると、ゴールや個別のタスクを[ワークフロー](/ja/workflows/introduction)で実行できます。

- **または、ワークフローで各ゴールを進める**には、チームのワークフローが一覧されます。1 つにポインタを合わせて**すべてのゴールで使う**をクリックするか、**新規チームワークフロー**をクリックして自分で作ります。
- **タスクワークフロー**には、バグの修正など、リードが 1 つのタスクに割り当てられるワークフローが一覧されます。**チャットで使う**をクリックするとリードのチャットでそれを指名でき、**新規ワークフロー**をクリックすると自分で作れます。

組み込みのワークフローは次のとおりです。

| ワークフロー | 内容 |
| --- | --- |
| **Ship** | アイデアを、あなたが承認する仕様、デザイン、プランにし、各タスクをテスト、チェック、レビュー、検証付きで作り、最後にブランチ全体をレビューします。 |
| **Planner** | アイデアを、あなたが承認する仕様、デザイン、タスクにし、そのタスクをワークプランとしてリードに渡します。 |
| **Sprint** | 計画された 1 つのタスクを、テスト、チェック、レビュー、検証付きで作ります。 |
| **Compound** | 残した教訓をリポジトリのドキュメントとルールに反映します。 |
| **Verify setup** | プロジェクトを確認して実行する方法を割り出し、あなたが承認する検証手順書を作り、実際に実行して確かめます。 |

各行には、ワークフローのアイコン、担当するメンバーの顔、実行回数と失敗回数が表示されます。ワークフローにメンバーが足りない場合は、その行の**エージェントを選択…**をクリックします。行をクリックするとワークフローが開き、ステップや担当者を変更できます。

プロジェクト内のワークフローに加えた変更は**下書き**のままで、**公開**をクリックするまで、新しいプランは公開済みの版を使い続けます。**以前の版に戻す**で、1 つ前の版に戻せます。タスクのワークフローには、各ステップのトークン数とコストが表示され、API 価格での合計も表示されます。

### チェックコマンドを設定する

チェックコマンドは、完了したタスクのコードのコピーに対して、レビューに進む前に実行されます。チェックに失敗すると、タスクのメンバーに戻され、修正されます。

1. **チームと設定**タブで**プロジェクトの設定**をクリックし、**ボード**をクリックします。
2. **チェックコマンド**の横にある**探す**をクリックします。Enconvo はプロジェクトのファイルからコマンドを読み取り、それが通る場合にだけ入力します。
3. 見つからない場合は、**Mavis に設定を依頼**（ボタンにはリードの名前が表示されます）をクリックします。リードがチャット内でコマンドを探すか、追加します。

チェックコマンドのないプロジェクトでは、チェックのステップが**未チェック**と表示されます。

### ワークツリーを整理する

git プロジェクトでは、各チャットとタスクが専用のワークツリーで作業します。ディスク容量を空けるため、Enconvo は不要になったワークツリーをアーカイブし、そのフォルダを削除します。**プロジェクトの設定 → ワークツリー**で設定します。

| 設定 | 内容 |
| --- | --- |
| **マージ済みのワークツリーをアーカイブ** | 作業がベースブランチに入り、コミットもプッシュもされていない変更がなくなったワークツリーをアーカイブします。 |
| **チャットのないワークツリーをアーカイブ** | チャット一覧にそのチャットが 1 つも残っていないワークツリーをアーカイブします。 |
| **非アクティブなワークツリーをアーカイブ** | **アーカイブするまでの非アクティブ期間**で選んだ日数（3、7、14、30 日）の間、動きがなかったワークツリーを、そのチャットと一緒にアーカイブします。 |

コミットされていない変更があるワークツリーは、常に残ります。**復元**で、アーカイブしたワークツリーを元に戻せます。

## チームが確認するタイミングを選ぶ

**チームと設定**タブを開きます。

**確認するタイミング**では、次の設定ができます。

| 設定 | 内容 |
| --- | --- |
| **プランの準備ができたとき** | 初期設定の**スマート**は、プランがあなたの依頼どおりの内容ならすぐに開始し、それ以上のことをする場合やリスクがある場合は、あなたの**開始**を待ちます。**常に確認する**は、毎回**開始**を待ちます。**常に開始する**は、準備ができたプランをすべてすぐに開始します。 |
| **ToDo が追加されたらすぐに計画を開始する** | オン：リードは新しいアイデアをすぐに計画します。オフ：新しいアイデアは、あなたが開始するまで**未開始**で待ちます。 |

削除、送信、公開、支払い、プッシュを行う操作は、どの設定でも必ず確認します。フォルダ、ワークツリー、権限、予算、境界は**プロジェクトの設定**にあります。

## 不在中もリードに作業させる

**フルアクセス**のプロジェクトでは、タスクが報告してきたときにチャットに誰もいなくても、リードが作業を進められます。**プロジェクトの設定 → ボード**で**不在中もリードが作業**をオンにします。

リードはその場合、1 時間に 6 ターン、1 日に 100,000 ポイントの範囲内で、自分で修正、再試行、マージを行います。タスク専用のコードのコピーの外では、送信、プッシュ、公開、支払い、削除は一切行いません。

戻ってくると、リードのチャットの上部にある**不在中の出来事**カードに、リードが行ったことと、あなたに残したステップが一覧されます。ターンが 2 回続けて失敗した場合や上限に達した場合、リードは一時停止し、**確認待ち**に、**再開**するか**一時停止のまま**にするかが表示されます。

## プロジェクトをアーカイブする

プロジェクトが完了したら、何も削除せずにサイドバーから消すため、アーカイブします。

1. サイドバーでプロジェクトにポインタを合わせ、**⋯** をクリックします。
2. **プロジェクトをアーカイブ**を選びます。

プロジェクトとそのチャットがサイドバーから消え、スケジュールされたタスクは一時停止します。アーカイブされたプロジェクトのチャットは、復元するまでメッセージを受け付けません。

元に戻すには、次の操作を行います。

1. **設定 → アーカイブ済み**を開きます。
2. **プロジェクト**をクリックします。
3. プロジェクトの横にある**復元**をクリックします。

プロジェクトはチャットと一緒にサイドバーに戻り、スケジュールされたタスクも再びオンになります。

## iPhone でプロジェクトを使う

iPhone アプリでもプロジェクトを開けます。アイデア、ボード、プロジェクトの設定、**新規プロジェクト**、そしてタスクに答えたり、マージ、開始、再試行したりできるワークプランカードがあります。そこでの `@` メニューには、プロジェクトのメンバーとワークフローが一覧されます。[iPhone アプリ](/ja/integrations/iphone-app)をご覧ください。

## トラブルシューティング

| 問題 | 対処 |
| --- | --- |
| 新しいアイデアが**未開始**のまま | **チームと設定**で**ToDo が追加されたらすぐに計画を開始する**をオンにするか、アイデアを開いて自分で開始します。 |
| **スマート**を選んでいるのにプランが待っている | プランが依頼した内容を超えているか、リスクのあるステップを含んでいます。内容を確認して**開始**をクリックします。 |
| コーディングエージェントのタスクが開始しない | コーディングエージェントをインストールしてログインしてください。 |
| タスクがログインの警告付きで**保留中**になる | コーディングエージェントがログアウトしているか、ログインがまもなく期限切れになります。**再度ログイン**をクリックします。保留中のタスクは、ログインすると再び実行されます。 |
| ボードのカードに黄色で問題が表示される | 設定上の問題です。カードの案内に従って対処してください。リードは再試行しません。Enconvo のエラーの場合は、再試行しても安全と表示されます。 |
| iCloud に置いたプロジェクトでタスクが失敗する | 「Mac のストレージを最適化」がオンの場合、ファイルが Mac にないことがあります。Finder でプロジェクトのフォルダに**ダウンロードしたままにする**を選んでください。 |
| タスクにプロジェクトのフォルダがないと表示される | フォルダが移動または削除されています。元に戻すか、新しい場所で新しいプロジェクトを作成してください。 |
| タスクがプロジェクトの**境界**で止まる | タスクの**境界を編集**をクリックして、必要なことを許可します。境界を変更できるのはあなただけです。 |
| タスクにマージまたはリベースが途中のままと表示される | エージェントが途中で止まりました。タスクをマージする前に、そのマージまたはリベースを完了するか、取り消してください。 |
| すべてのプランが**開始**を待っている | Enconvo からログアウトしている間、プランは待機します。**設定 → アカウント**でログインしてください。 |
| プロジェクトがサイドバーにない | アーカイブされている可能性があります。**設定 → アーカイブ済み**の**プロジェクト**を確認してください。 |
| ワークフローのタスクが失敗した | タスクを開きます。コマンドが最後に書き込んだ内容と、どのメンバーのステップが失敗したかが表示されます。 |
| ゴールが選んだチームのワークフローを使わない | **チームと設定**タブで**カスタムワークフロー**をオンにしてください。オフの間は、すべてのゴールが**標準**で進みます。 |
