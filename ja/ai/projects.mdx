プロジェクトは、1 つのフォルダに関するチャット、アイデア、チームをまとめて管理します。やりたいことをアイデアとして書き出すと、プロジェクトのリードがチームと計画を立て、各タスクは完了するまでボード上を移動していきます。ウェブサイトやアプリ開発など、動いているタスクや自分の確認が必要な項目を一目で把握したい継続的な作業に最適です。

下の動画では、プロジェクトを開き、作業の一部を Claude Code に渡すアイデアを追加してボードで追跡し、プロジェクトをアーカイブして復元する流れを紹介しています。

## はじめる前に

プロジェクトが必要です。チャットウィンドウのサイドバーで **プロジェクト** の横にある **+** をクリックし、フォルダを選択してください。詳しくは [プロジェクトを作成する](/ja/ai/agent-orchestrator) を参照してください。Claude Code や Codex などのコーディングエージェントにタスクを渡す場合は、あらかじめインストールとサインインを済ませておいてください。詳しくは [コーディングエージェント](/ja/ai/coding-agents) をご覧ください。

## プロジェクトを開く

サイドバーでプロジェクトをクリックします。ページには 3 つのタブがあります。

| タブ | 表示内容 |
| --- | --- |
| **チャット** | プロジェクトのリードとのチャット、および [確認待ちタスク](#確認待ちタスクを確認する) のパネル。 |
| **ボード** | **未開始** から **計画中**、**進行中** を経て **完了** に至るプロジェクトのアイデア一覧。 |
| **チームと設定** | チームメンバーの一覧と、チームが [確認を求めるタイミング](#チームが確認を求めるタイミングを選ぶ) の設定。 |

左上にはリードを先頭にチームの顔アイコンが表示されます。プロジェクトチャットのタスクは、サイドバーの該当行の下にも表示されます。

## アイデアを追加する

アイデアとは、そのプロジェクトで実現したいことです。

1. **ボード** タブを開き、**新しいアイデア** をクリックします。
2. 普段話すようにやりたいことを書きます。スクリーンショットやファイルを添付したり、マイクをクリックして話したりもできます。
3. 必要であれば **優先度** を設定します。Enconvo が文章から **種類**（**機能**、**バグ**、**改善**、**ドキュメント**、**調査**）を推測します。違っていれば変更してください。
4. **アイデアを追加** をクリックします。

アイデアは **未開始** 列にカードとして追加され、内容から生成された短いタイトルと、優先度を示す赤・琥珀・青のフラグが付きます。リードはすぐに計画を開始し、カードを **計画中** へ移動します。添付したファイルはアイデア開始時にリードへ渡されます。特定の種類だけを表示したい場合は **種類で絞り込む** を使ってください。

アイデアは自動で取り込むこともできます。[予約タスク](/ja/workflows/scheduled-jobs) に **Ideas に追加** アクションを設定すると、受け取った GitHub Issue、Discord や Telegram のメッセージ、メール、Webhook がそれぞれプロジェクトのボード上のアイデアになります。リードはバグを再現して修正計画を立てたり、要望を調査して理由付きでクローズまたは計画したりし、何かを変更する前に必ず確認を求めます。

プランが整うと、各タスク、担当者、使用モデルが表示されます。内容を確認して **開始** をクリックすると、アイデアは **進行中** へ移動します。リードはアイデアの **ゴール** と **完了条件** 行をもとに計画を立て、ゴールを満たしたと判断したときにのみ **完了** へ移します。

## アイデアの進捗を追う

アイデアをクリックすると詳細ページが開きます。片側にリードとのチャット、もう片側にアイデアのプラン、タスク、説明文、ファイル、ゴールが表示されます。**進み具合** では **作業を計画**、**作業を実行**、**レビューとテスト** の進捗と担当者が確認できます。

完了したアイデアをもう一度作業したい場合は、**再開** をクリックします。

タスクを持つアイデアの上部には 2 つのビュー切り替えがあります。**タスク** はそのアイデアのタスクだけをボード表示し、**○○とチャット**（たとえば **Mavis とチャット**）は計画が作られたチャットを開きます。

## コーディングエージェントにタスクを渡す

アイデアまたはプロジェクトチャットで、エージェント名と必要に応じてモデル名を指定します。たとえば Opus 5.5 のようにモデル名だけを指定することもでき、その場合はリードがそのモデルで該当タスクを実行します。これはメンバーがいないプロジェクトでも使えます。例：

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

そのエージェントがプロジェクトのメンバーでなくても、リードは指定された部分をそのエージェントとモデルのタスクとして計画し、残りを自分で担当できます。プランとボードには担当者の横にモデル名も表示されます。指定した名前が複数のモデルに該当する、または該当なしの場合はリードが確認します。

コーディングエージェントが作業を終えると、そのタスクはアイデアの **タスク** ボード上の **レビュー待ち** であなたの確認を待ちます。フォルダが git リポジトリではないプロジェクトでは、そのまま **完了** へ進みます。各コーディングタスクはコードの独立したコピー上で作業し、準備ができたらプランの結果カードにある **マージ** で取り込めます。メンバー自身がプッシュやマージを行うことはできません。

チャットタブやアイデアでリードに依頼したタスクはすべてボードに表示され、アイデア別またはチャット別にグループ化されます。1 つの会話だけを追いたい場合は、ボードのチャットフィルターでチャットを選ぶか、**グループ化** で **チャット** を選択してください。

プロジェクトのチャット内で行った作業もボードに反映されます。チャットがファイルを変更したりコマンドを実行したりすると、カードが **完了** まで進み、短い要約と変更したファイルが表示されます。カードをクリックするとそのチャットが開きます。リードもこれらのカードを参照し、自分のタスクが同じファイルを触らないように避けます。

## 完了した作業をマージする

タスクまたはプランの結果カードにある **マージ** をクリックすると、プロジェクトの **ベースブランチ** へマージされます。同じファイルの別行にある未コミットの変更があってもマージは止まりません。git が使用中の場合は少し待機し、ロックファイルが残っている場合はそのファイル名を表示します。

クリックせずに自動マージしたい場合は、**プロジェクトの設定 → ボード** で **通過した作業をマージ** をオンにします。これには **ワークツリー** で **ベースブランチ** を設定しておく必要があります。オンにすると、チェックと他ベンダーのエージェントによるレビューの両方を通過したタスクが自動でマージされます。**通過条件** では **ブロッキング指摘なし**、**レビュアーが承認**、**チェックのみ** のいずれかを選べます。コンフリクトが起きたタスクは担当メンバーに差し戻されます。レビュアーが実行できない場合、マージはスキップされるのではなく一時停止します。

### git 管理外のプロジェクト

フォルダが git リポジトリではないプロジェクトでは、各リードチャットが自分のワークプランを専用のチャットフォルダへ保存するため、複数のリードチャットで同時にプランを実行できます。プランのカードには保存先のフォルダが **保存先** として表示され、その外でタスクが変更したファイルは **ほかに変更されたファイル** に一覧表示されます。

## リードへのその他の依頼方法

プロジェクトのリードチャットでは次の機能も使えます。

- **回答を比較** は 2〜6 個のエージェントに同じ質問を投げ、リードがそれぞれの回答を比較します。
- **スタイルを使用** はリードの回答の文体を選びます。

Codex や Claude Code、あるいは別の自分のエージェントに現在の作業をレビュー・テストさせたいときは、そのままチャットで頼むだけです。プロジェクト内ではリードがそのエージェントをサブエージェントとして起動し、同じチャットに結果を持ち帰ります。リードはメンバーに割り当てるタスクとは別に、自分自身の作業用にもサブエージェントを起動できます。

プロジェクトのワークフローの 1 つを通してタスクを実行するには、`@` を入力してワークフローを選ぶか、**チームと設定** タブでワークフローの横にある **チャットで使う** をクリックします。詳しくは [独自のワークフローを使う](#独自のワークフローを使う) を参照してください。

## 確認待ちタスクを確認する

**チャット** タブを開くと、メッセージボックスの上に 3 列のパネルがあります。

| 列 | 一覧の内容 |
| --- | --- |
| **確認待ち** | あなたの回答、承認、またはレビューを待っているタスク。 |
| **実行中** | 現在実行中のタスク。 |
| **新しい結果** | まだ開いていない完了済みタスク。 |

行をクリックするとそのアイデアが開きます。

## すべての作業をボードでまとめて見る

チャットウィンドウのサイドバーのアイコンレールにある **···** メニューの **ボード** では、すべてのチャット、プロジェクト、チームのタスクを 1 か所で確認できます。アイコンレールに常時表示したい場合は、同じメニューの **サイドバーをカスタマイズ…** を選んでください。詳しくは [チャットウィンドウ](/ja/ai/chat) を参照してください。

特定のプロジェクトだけを表示するには、左上のフィルター（**すべてのボード**）をクリックして表示したいプロジェクトを選択します。ボードのその他の操作は [ボードで進捗を追う](/ja/ai/agent-orchestrator) を参照してください。

## チームを設定する

**チームと設定** タブを開きます。上部にリードと各メンバーが表示され、**メンバーを追加** で別のエージェントを追加できます。左上のチームの顔アイコンをクリックするとチーム全体を一度に表示でき、リードは **変更** で交代でき、各メンバーの役割はその場で編集できます。

リードには自分のエージェントのほか、コーディングエージェント（Claude Code、Codex、Grok Build、Antigravity）も選べます。コーディングエージェントのリードも他のリードと同様に、メンバーの作業をワークプランにまとめ、結果を読み取ります。

メンバーには [ペアリング済みのほかのコンピュータ](/ja/integrations/other-computers) にあるエージェントも追加できます。そのコンピュータが必要なタスクをリードが割り当てると、結果がタスクの成果として返ってきます。そのコンピュータにアカウントのデバイスアクセス権がない場合はその旨が表示され、**デバイスを管理** への案内が出ます。

### チームの動作フロー

チャットやアイデアからリードに渡したゴールはすべて **標準** フロー（**作業を計画** → **作業を実行** → **レビューとテスト**）で進みます。各ステップの担当者を選べます。計画をメンバーに任せると、依頼時にそのメンバーがプランを作成し、リードがあなたの **開始** を待つワークプランとして提案します。チェックのオン・オフや **修正回数**（タスクを修正のために差し戻す最大回数）も設定できます。

### 独自のワークフローを使う

**チームと設定** タブの **カスタムワークフロー** は、オンにするまでオフになっています。オフの間はすべてのゴールが **標準** で実行されます。オンにすると、ゴール全体や単体タスクを [ワークフロー](/ja/workflows/introduction) で実行できます。

- **または、ワークフローで各ゴールを進める** にはチームワークフローが並びます。項目にポインターを合わせて **すべてのゴールで使う** をクリックするか、**新規チームワークフロー** で独自に作成します。
- **タスクワークフロー** には、バグ修正など単一タスクにリードが割り当てられるワークフローが並びます。リードチャットで指定するには **チャットで使う** をクリックし、新しく作るには **新規ワークフロー** をクリックします。

組み込みワークフローは次のとおりです。

| ワークフロー | 内容 |
| --- | --- |
| **Ship** | アイデアから承認用の仕様・設計・計画を作成し、各タスクをテスト・チェック・レビュー・検証付きで実装したあと、ブランチ全体をレビューします。 |
| **Planner** | アイデアから承認用の仕様・設計・タスクを作成し、ワークプランとしてリードに渡します。 |
| **Sprint** | 計画済みの 1 タスクをテスト・チェック・レビュー・検証付きで実装します。 |
| **Compound** | 保持した教訓をリポジトリのドキュメントとルールに反映します。 |
| **Verify setup** | プロジェクトのチェック方法と実行方法を調べ、承認用の検証手順書を作成して実際に実行・証明します。 |

各行にはワークフローのアイコン、担当メンバーの顔アイコン、実行回数と失敗回数が表示されます。メンバーが不足しているワークフローでは、行内の **エージェントを選択…** をクリックします。行をクリックするとワークフローが開き、ステップや担当者を変更できます。

プロジェクト内でワークフローに変更を加えて保存しても、**公開** をクリックするまでは **下書き** 状態にとどまり、新しいプランでは引き続き公開済みバージョンが使われます。**以前の版に戻す** をクリックすると 1 つ前のバージョンに戻せます。タスクのワークフローでは各ステップのトークン数とコストが表示され、API 価格ベースの合計も確認できます。

### チェックコマンドを設定する

チェックコマンドは、完了したタスクのコードのコピー上で、レビューへ回る前に実行されます。チェックに失敗すると、修正のために担当メンバーへ差し戻されます。

1. **チームと設定** タブで **プロジェクトの設定** → **ボード** をクリックします。
2. **チェックコマンド** の横にある **探す** をクリックします。Enconvo がプロジェクトファイルからコマンドを読み取り、実際に成功した場合にのみ自動入力します。
3. 見つからなかった場合は、**Mavis に設定してもらう**（ボタン名は現在のリード名になります）をクリックします。リードがチャット上でコマンドを探すか追加します。

チェックコマンドが設定されていないプロジェクトでは、チェックステップが **未チェック** と表示されます。

### ワークツリーを整理する

git プロジェクト内の各チャットやタスクは、それぞれ独立したワークツリーで作業します。ディスク容量を空けるため、Enconvo は完了したワークツリーをアーカイブしてフォルダを削除できます。**プロジェクトの設定 → ワークツリー** で設定します。

| 設定 | 動作 |
| --- | --- |
| **マージ済みのワークツリーをアーカイブ** | 作業がベースブランチに取り込まれ、未コミットや未プッシュの変更が残っていないワークツリーをアーカイブします。 |
| **チャットのないワークツリーをアーカイブ** | チャット一覧に紐づくチャットが 1 つも残っていないワークツリーをアーカイブします。 |
| **非アクティブなワークツリーをアーカイブ** | **アーカイブするまでの非アクティブ期間**（3・7・14・30 日）にわたり動きがないワークツリーをチャットごとアーカイブします。 |

未コミットの変更が残っているワークツリーは常に保持されます。アーカイブしたワークツリーは **再開**（復元）で元に戻せます。

## チームが確認を求めるタイミングを選ぶ

**チームと設定** タブを開きます。

**確認を求めるタイミング** の設定：

| 設定 | 動作 |
| --- | --- |
| **プランの準備ができたとき** | デフォルトの **スマート** は、すでに頼んだ範囲内であれば即座にプランを開始し、範囲を超える場合やリスクがある場合は **開始** 待ちになります。**毎回確認する** は毎回 **開始** を待ちます。**常に開始する** は準備ができ次第すべてのプランを開始します。 |
| **To-do が追加されたらすぐ計画を開始する** | オン：新しいアイデアはリードがすぐに計画を始めます。オフ：手動で開始するまで **未開始** にとどまります。 |

削除、送信、公開、支払い、プッシュを伴う操作は、設定にかかわらず常に確認を求めます。フォルダ、ワークツリー、権限、予算、境界は **プロジェクトの設定** にあります。

## 不在中もリードが作業を進められるようにする

**フルアクセス** のプロジェクトでは、誰もチャットを見ていないときにタスクから報告が返ってきても、リードが作業を先へ進められるようにできます。**プロジェクトの設定 → ボード** で **不在中もリードが作業** をオンにしてください。

これによりリードは 1 時間あたり最大 6 ターン、1 日あたり 100,000 ポイントの範囲内で、自律的に修正・再試行・マージを行います。タスク自身のコードコピーの外にあるものを送信、プッシュ、公開、支払い、削除することは決してありません。

戻ってくると、リードチャットの上部に **不在中の出来事** カードが表示され、リードが行った処理とあなたに残された確認事項が一覧になります。2 ターン連続で失敗した場合、または上限に達した場合はリードが一時停止し、**確認待ち** で **再開** か **一時停止のまま** かを尋ねます。

## プロジェクトをアーカイブする

プロジェクトが完了したら、何も削除せずにサイドバーから整理して非表示にできます。

1. サイドバーでプロジェクトにポインターを合わせ、**⋯** をクリックします。
2. **プロジェクトをアーカイブ** を選択します。

プロジェクトとそのチャットがサイドバーから消え、予約タスクは一時停止します。アーカイブされたプロジェクトのチャットは、復元するまでメッセージを受け付けません。

元に戻すには：

1. **設定 → アーカイブ済み** を開きます。
2. **プロジェクト** をクリックします。
3. 対象プロジェクトの横にある **復元** をクリックします。

プロジェクトがチャットとともにサイドバーへ戻り、予約タスクも再び有効になります。

## スマートフォンでプロジェクトを使う

iPhone アプリでもプロジェクトを開けます。アイデア、ボード、プロジェクトの設定、**新規プロジェクト**、さらに作業プランカードからタスクへの回答、マージ、開始、再試行が行えます。そこでの `@` メニューにはプロジェクトのメンバーとワークフローが表示されます。詳しくは [iPhone アプリ](/ja/integrations/iphone-app) を参照してください。

## トラブルシューティング

| 問題 | 対処方法 |
| --- | --- |
| 新しいアイデアが **未開始** のまま変わらない | **チームと設定** で **To-do が追加されたらすぐ計画を開始する** をオンにするか、アイデアを開いて手動で開始してください。 |
| **スマート** を選んでいるのにプランが待機する | 依頼した範囲を超えているか、リスクのあるステップが含まれています。内容を確認して **開始** をクリックしてください。 |
| コーディングエージェントのタスクが開始しない | コーディングエージェントをインストールしてサインインしてください。 |
| タスクがサインイン警告とともに **保留中** で止まっている | コーディングエージェントからサインアウトしているか、サインイン期限が近づいています。**再度ログイン** をクリックしてください。サインインすると保留中のタスクは再開されます。 |
| ボードカードに琥珀色の問題が表示される | セットアップ上の問題です。カード内の修正手順に従ってください（リードによる自動再試行は行われません）。Enconvo 側のエラーであれば再試行可能と表示されます。 |
| iCloud に保存されたプロジェクトでタスクが失敗する | 「Mac ストレージを最適化」がオンだとファイルが Mac 上にない場合があります。Finder でプロジェクトフォルダに対して **ダウンロードしたままにする** を選択してください。 |
| プロジェクトのフォルダが見つからないというエラーが出る | フォルダが移動または削除されています。元の場所に戻すか、新しい場所用にプロジェクトを作成してください。 |
| タスクがプロジェクトの **境界** で止まる | タスク上の **境界を編集** をクリックして必要なアクセスを許可してください。境界を変更できるのはあなただけです。 |
| マージやリベースが途中で残っているという注記が出る | 担当エージェントが途中で停止しました。タスクをマージする前に、そのマージまたはリベースを完了させるか取り消してください。 |
| すべてのプランが **開始** 待ちになる | Enconvo からサインアウトしている間はすべてのプランが待機状態になります。**設定 → アカウント** でサインインしてください。 |
| サイドバーにプロジェクトが見当たらない | アーカイブされている可能性があります。**設定 → アーカイブ済み** の **プロジェクト** を確認してください。 |
| ワークフロータスクが失敗した | タスクを開いてください。コマンドが最後に出力した内容と、どのメンバーのステップで失敗したかが表示されます。 |
| 選択したチームワークフローがゴールで使われない | **チームと設定** タブで **カスタムワークフロー** をオンにしてください。オフの間はすべてのゴールが **標準** で実行されます。 |
