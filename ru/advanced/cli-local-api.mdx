Эта страница для разработчиков и опытных пользователей, которые хотят управлять Enconvo из Терминала, скрипта или другого приложения. Команда `enconvo` поставляется вместе с настольным приложением Enconvo, отдельной установки не требуется, а приложение отдаёт маршруты каждого установленного плагина через локальный HTTP API.

В этом видео рассказано о странице API, Руководстве по CLI и Хуках.

Для команд, использующих локальную среду выполнения, держите Enconvo запущенным.

## Поиск команд

```bash
enconvo -h
enconvo knowledge_base -h
```

Добавьте `-h` к интересующей команде, чтобы увидеть её текущие подкоманды и параметры.

Откройте **Настройки → Руководство по CLI**, чтобы увидеть установленные расширения, которые предоставляют команды CLI. Нажмите на имя, чтобы скопировать его команду `enconvo <name> -h`. Список установленных расширений — главный источник сведений о том, что поддерживает ваше приложение.

Если оболочка не находит `enconvo`, откройте Руководство по CLI в приложении и проверьте установленную версию приложения и настройку командной строки.

## Вызов локального API

Приложение отдаёт каждый маршрут по адресу `http://localhost:54535/api/<extension>/<route>`. Отправьте `POST` с телом JSON:

```bash
curl -X POST http://localhost:54535/api/enconvo/extension/available_list \
  -H "Content-Type: application/json" \
  -d '{}'
```

Откройте **Настройки → API** и нажмите **Проверить API**, чтобы посмотреть доступные маршруты и схемы запросов с примером для каждого. При написании интеграции пользуйтесь схемой для вашей установленной сборки: параметры маршрутов могут меняться по мере развития расширений.

## Запуск агента или AI-команды вне Enconvo

В настройках каждого агента и каждой AI-команды есть строка **Ссылка, CLI и API**. В ней показаны ссылка, команда `enconvo` и вызов локального API, которые запускают его с вашим текстом и файлами, — всё готово к копированию.

| Способ | Что делает |
| --- | --- |
| Ссылка | Открывает новый чат и запускает там агента или AI-команду |
| CLI | Запускает в фоне и выводит ответ |
| Local API | Запускает в фоне и возвращает ответ |

Ссылка выглядит так:

```text
enconvo://<extension>/<command>?input_text=<text>&window=<window>&files=<path>
```

- `input_text` — текст для отправки.
- `window` — `chat_window` или `dynamic_island`. Опустите параметр, чтобы запустить в SmartBar.
- `files` прикрепляет файл по абсолютному пути или пути, начинающемуся с `~/`. Повторите параметр для нескольких файлов, например чтобы отправить изображения из другого приложения или скрипта.

Из Терминала:

```bash
enconvo agent call "What's on my calendar today?"
enconvo ai-command run 'writing_package|translate' --input-text "Bonjour" --files ~/Desktop/note.png
enconvo writing_package convert_to_list "eggs, milk, bread"
```

Команды письма, такие как «Перевести», «Кратко пересказать» и «Преобразовать в список», принимают текст как аргумент и отвечают, не добавляя чат в вашу историю. `enconvo agent main` отвечает в новом чате, если агент занят в последнем.

Соответствующие маршруты локального API — `agent/call` (`agentId`, `message`, `context_files`) и `ai-command/run` (`command_key`, `input_text`, `files`).

### Проверка запущенных чатов

- `agent/session/list` перечисляет чаты, которые сейчас выполняются, у всех агентов и во всех Проектах, включая чаты Claude Code и Codex, с названием, агентом и Проектом каждого. Передайте `filter: "waiting"`, чтобы увидеть чаты, ожидающие вашего ответа, или `"active"` для обоих случаев.
- `agent/session/status` проверяет один чат по его `sessionId`.
- `agent/session/steer` добавляет сообщение в ход, который чат выполняет сейчас, не останавливая его. Чат, который не выполняется, отвечает `not_running`; вместо этого начните новый ход через `agent/call`. Запуск с правами ниже «Полного доступа» не может направлять ход Enconvo.

## Безопасное использование

Если ИИ-клиенту нужен только поиск по базе знаний, используйте специальное подключение [MCP базы знаний](/ru/advanced/knowledge-base-mcp), а не открывайте общий локальный API.

Относитесь к локальному API и доступу к оболочке как к мощным возможностям: команды могут читать или изменять локальные данные в соответствии со своей реализацией. Указывайте в скриптах явно команду, входные данные и место назначения.

Сохранённые ключи API возвращаются как `[hidden]`, когда программа читает настройки через локальный API, а изменить, куда отправляется сохранённый ключ, могут только собственные окна Enconvo. См. [Учётные данные](/ru/configuration/credentials).

Для горячей клавиши, заданной через локальный API, можно использовать короткие названия модификаторов (`cmd`, `ctrl`, `alt`, `opt`, `fn`) или символы модификаторов. Горячая клавиша с неизвестным Enconvo словом не регистрируется, а клавише, которая вводит символ, нужен Command, Control, Option или Function.

## Развивайте на этой основе

- [Разработка расширений](/ru/extensions/developing): добавляйте собственные команды и маршруты. Файл в `src/api/` плагина становится здесь маршрутом.
- [Справочник по API расширений](/extensions/extension-api-reference): точки входа SDK.
- [Хуки](/ru/configuration/hooks): запускайте собственные команды в заданные моменты работы агента. Они берутся из вашей конфигурации JSON, а **Настройки → Хуки** показывает загруженные.
- [Автоматизации](/ru/workflows/scheduled-jobs): запускайте работу в выбранное время.
- [Настройка Enconvo на сервере Linux](/ru/advanced/linux-server): задайте модели, агентов и плагины сервера, который добавил ваш Mac, той же командой `enconvo`.
