Эта страница для тех, кто хочет понять, что происходит с документом после того, как он попал в базу знаний: где Enconvo его хранит, как разбивает и индексирует и как поиск выбирает результаты. Используйте её, чтобы настроить коллекцию, исправить плохие результаты или обращаться к базам знаний из собственного кода. Если базы знаний для вас в новинку, начните с раздела [База знаний](/ru/ai/knowledge-base).

Коротко: Enconvo читает текст каждого элемента, разбивает его на фрагменты, превращает каждый фрагмент в вектор и сохраняет фрагменты в локальной базе данных LanceDB. Поиск ищет фрагменты и по смыслу, и по точным словам одновременно, а затем смешивает результаты.

## Где хранятся данные

| Что | Где |
|---|---|
| Фрагменты, векторы и полнотекстовый индекс | База данных LanceDB в `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/` |
| Базы знаний, элементы и их сведения | База данных SQLite (Drizzle ORM) в `~/.config/enconvo/.support/knowledge_base/db` |

Все базы знаний используют одну базу данных LanceDB, и каждая база знаний — это одна таблица в ней. Когда Enconvo перестраивает индекс базы знаний, он записывает новую таблицу рядом со старой и переключается на неё, когда она готова, поэтому поиск продолжает работать во время перестроения.

У каждой базы знаний есть идентификатор. API принимают его как `knowledge_base_id`, а Enconvo запускает базу знаний как команду `knowledge_base|<id>`. Чтобы скопировать идентификатор базы знаний, откройте **Настройки базы знаний** из её заголовка и перейдите в **Дополнительно**.

Объём хранилища зависит от исходных материалов, извлечённого текста, числа фрагментов и размерности эмбеддингов. Следите за реальным использованием диска для вашей коллекции, а не оценивайте его только по числу документов. Храните исходные файлы и резервные копии независимо от поискового индекса.

## Как содержимое попадает в базу

### Чтение

Enconvo читает каждый вид элементов подходящим для него инструментом:

| Содержимое | Чем читается |
|---|---|
| **PDF** | Плагин Document Parser. Он использует текст PDF и запускает вашего провайдера OCR только для отсканированных страниц |
| **Word, PowerPoint, Excel, EPUB, CSV** | Плагин Document Parser |
| **Текст и Markdown** | Читаются как есть |
| **Изображения** | Ваш провайдер OCR |
| **Аудио и видео** | Ваш провайдер транскрибации |
| **Веб-страницы** | Ваш провайдер Web Fetch |
| **Сайты целиком** | Обходчик сайтов, страница за страницей |
| **YouTube** | Транскрипт видео |

### Разбиение на фрагменты

Enconvo разбивает текст на фрагменты, размер которых подобран под язык, на котором он написан:

| Текст | Размер фрагмента | Перекрытие |
|---|---|---|
| В основном латиница, например английский | 1500 символов | 200 символов |
| В основном китайский, японский или корейский | 560 символов | 80 символов |
| Смесь | Между этими значениями, в зависимости от доли каждого | Между этими значениями |

Текст разбивается по самой естественной границе, которая позволяет уложить фрагмент в его размер, в таком порядке:

1. Абзацы
2. Строки
3. Предложения
4. Части предложения
5. Слова
6. Жёсткий разрез (крайняя мера)

Электронные таблицы разбиваются примерно по одной строке на фрагмент, поэтому поиск одной строки находит именно её. Эти размеры встроены; настройки для них нет.

### Эмбеддинг

Все базы знаний используют одну и ту же модель эмбеддингов, EmbeddingGemma 300M. Где она запускается, выберите в **Настройки → Память → Модель эмбеддингов**:

- **Этот Mac**: бесплатно, и ничто не покидает ваш Mac, но во время индексации нового содержимого используется GPU. Требуется Mac с Apple silicon.
- **Enconvo Cloud**: бесплатно с вашей учетной записью Enconvo. Индексируемый или искомый текст отправляется туда.

Обе модели одинаковы, поэтому при переключении ваш поисковый индекс остаётся прежним. Enconvo создаёт эмбеддинги фрагментов пакетами.

### Хранение

Каждый фрагмент — это одна строка в таблице базы знаний:

| Поле | Что содержит |
|---|---|
| `text` | Текст фрагмента |
| `vector` | Его эмбеддинг |
| `id` | Идентификатор фрагмента |
| `attachment_id` | Элемент, из которого взят фрагмент |
| `type`, `url`, `title`, `ext`, `loc` | Тип, адрес, заголовок и расширение файла элемента и место, где в нём находится фрагмент |
| `metadata` | Прочие сведения об элементе |

Enconvo также хранит полнотекстовый индекс по `text`, построенный из коротких последовательностей символов, поэтому он находит точные имена, числа, код и слова CJK.

## Как работает поиск

Каждый поиск выполняет до трёх запросов одновременно по фрагментам базы знаний:

1. **По смыслу**: для запроса создаётся эмбеддинг той же моделью и находятся ближайшие векторы.
2. **По словам**: полнотекстовый поиск (BM25) по каждому слову запроса, без распространённых английских слов.
3. **По заголовку**: элементы, заголовок которых соответствует запросу, у каждого — фрагмент, ближайший к запросу.

Затем Enconvo смешивает результаты. Оценки каждого списка приводятся к шкале от 0 до 1, а оценка фрагмента — это 0,6 его оценки по смыслу плюс 0,4 его оценки по словам. Элемент, заголовок которого совпал, или фрагмент, содержащий запрос целиком, ранжируется выше. От одного элемента сохраняется лишь несколько фрагментов, чтобы один длинный документ не вытеснил остальные, и каждый фрагмент возвращается вместе с окружающим текстом.

В поиске по базе знаний нет отдельного шага повторного ранжирования.

## Поддерживайте индекс в порядке

Enconvo сам создаёт полнотекстовый индекс и приводит таблицы в порядок. Он также перестраивает индекс базы знаний, если тот был создан более старым разбивщиком или другой моделью эмбеддингов, из уже имеющегося текста, не читая файлы заново.

Чтобы перестроить вручную:

- **Всю базу знаний**: откройте **Настройки базы знаний** из её заголовка, перейдите в **Индексация и поиск** и нажмите **Переиндексировать…** рядом с **Перестроить весь индекс**. Поиск продолжает работать, пока идёт перестроение.
- **Один элемент**: щёлкните его правой кнопкой мыши и выберите **Переиндексировать**.

В **Настройки базы знаний** пять разделов: **Основные** (название и описание), **Индексация и поиск** (состояние, элементы, требующие внимания, модель поиска и переиндексация), **Источники и захват** (привязанные папки и инструменты захвата), **AI-клиенты (MCP)** и **Дополнительно** (идентификатор и удаление базы знаний).

Удаляйте ненужные базы знаний, чтобы освободить место на диске.

### Привязанные папки

Если элемент отсутствует, сначала проверьте состояние импорта и синхронизации папки-источника. В **Источники и захват** у каждой привязанной папки показано, синхронизируется ли она, когда была последняя синхронизация или что папка-источник не найдена, а также доступны **Синхронизировать сейчас**, **Привязать заново…** и **Автосинхронизация**.

Затем отдельно проверьте состояние извлечения содержимого и состояние эмбеддинга элемента: **Конвейер** элемента показывает **Разбор контента** и **Поисковый индекс** как два этапа, и читаемый извлечённый текст не гарантирует, что векторная индексация завершена. Переиндексируйте элемент после устранения ошибки провайдера или доступа к файлу.

Папка-источник остаётся главным источником для привязанных файлов. Не смешивайте восстановление офлайн-диска с удалением файлов: когда папка-источник не найдена, база знаний сохраняет свои элементы. Прежде чем считать импорт завершённым, проверьте число пропущенных файлов.

## Организуйте несколько баз знаний

У каждой базы знаний свои документы, индекс и таблица. Разделяйте содержимое так, как вы его ищете:

| Стратегия | Описание | Пример |
|----------|-------------|---------|
| **По проекту** | Одна база знаний на проект | `project-alpha`, `project-beta` |
| **По типу** | Отдельные базы знаний по типу содержимого | `code-docs`, `meeting-notes`, `research` |
| **По команде** | Знания конкретной команды | `engineering`, `marketing`, `support` |
| **По области** | Личные и общие | `personal-notes`, `company-wiki` |

Чтобы искать сразу в нескольких, прикрепите их через выбор контекста или задайте прикреплённые базы знаний агента. Поиск, в котором не названа ни одна база знаний, просматривает все ваши, кроме Памяти.

## Использование баз знаний из кода

Плагин «База знаний» отдаёт свои маршруты через [Local API](/ru/advanced/cli-local-api), поэтому их могут вызывать другие плагины, рабочие процессы и скрипты. Основные из них:

| Маршрут | Назначение |
|---|---|
| `knowledge_base/create` | Создать базу знаний |
| `knowledge_base/delete` | Удалить базу знаний и все её данные |
| `knowledge_base/add`, `knowledge_base/add_attachments` | Добавить файлы, текст, ссылки или медиа |
| `knowledge_base/search` | Искать в одной или нескольких базах знаний |
| `knowledge_base/list` | Перечислить базы знаний |
| `knowledge_base/get_attachments` | Перечислить элементы базы знаний |
| `knowledge_base/delete_attachments` | Удалить элементы из базы знаний |
| `knowledge_base/reindex` | Перестроить индекс базы знаний или элемента |
| `knowledge_base/summarize` | Кратко пересказать один элемент |

Откройте **Настройки → API**, чтобы увидеть параметры каждого маршрута для вашей установленной версии.

Шаги с базами знаний встраиваются в рабочие процессы и автоматизации, например:

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

Для другого ИИ-клиента используйте [MCP базы знаний](/ru/advanced/knowledge-base-mcp). Он открывает выбранные базы знаний через локальную службу только для чтения; Память агента и записи он не экспортирует.

## Устранение неполадок

| Проблема | Что делать |
|---|---|
| Поиск возвращает нерелевантные результаты | Проверьте, что этап **Поисковый индекс** элемента завершён, затем переиндексируйте базу знаний. Ищите теми словами, которые использует документ: точные имена и числа находятся через полнотекстовый индекс |
| Индексация идёт медленно | Большие документы обрабатываются дольше. При **Этот Mac** индексация использует GPU; переключите **Модель эмбеддингов** на **Enconvo Cloud**, чтобы не нагружать ваш Mac |
| Новые элементы не находятся поиском при использовании Enconvo Cloud | Войдите в учетную запись Enconvo. Пока вы этого не сделаете, новое содержимое не индексируется, а поиск находит только совпадающие слова |
| Тип файла не поддерживается | Преобразуйте его в PDF, TXT или MD и добавьте снова |
| База знаний не находится по идентификатору | Скопируйте идентификатор из **Настройки базы знаний → Дополнительно** и передайте его как `knowledge_base_id` |
