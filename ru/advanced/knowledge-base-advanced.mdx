Эта страница для тех, кто хочет понять, что происходит с документом после добавления в базу знаний: где Enconvo его хранит, как разбивает и индексирует и как поиск выбирает результаты. Ей пользуются, чтобы настроить коллекцию, исправить слабые результаты или вызывать базы знаний из своего кода. Если вы только начинаете, сначала прочитайте [База знаний](/ru/ai/knowledge-base).

Коротко: Enconvo читает текст каждого элемента, режет его на фрагменты, превращает каждый фрагмент в вектор и сохраняет фрагменты в локальной базе LanceDB. Поиск ищет фрагменты одновременно по смыслу и по точным словам, а затем смешивает оба списка.

## Где лежат данные

| Что | Где |
|---|---|
| Фрагменты, векторы и полнотекстовый индекс | База LanceDB в `~/.config/enconvo/.support/knowledge_base/vector/knowledge_base/` |
| Базы знаний, элементы и их сведения | База SQLite (Drizzle ORM) в `~/.config/enconvo/.support/knowledge_base/db` |

Все базы знаний делят одну базу LanceDB, и каждая база знаний — отдельная таблица в ней. Когда Enconvo перестраивает индекс базы знаний, он записывает новую таблицу рядом со старой и переключается, когда новая готова, поэтому поиск продолжает работать во время перестройки.

У каждой базы знаний есть идентификатор. API принимают его как `knowledge_base_id`, а Enconvo запускает базу знаний как команду `knowledge_base|<id>`. Чтобы скопировать идентификатор, откройте **Настройки базы знаний** в заголовке и перейдите в **Дополнительно**.

Объём зависит от исходных файлов, извлечённого текста, числа фрагментов и размерности эмбеддингов. Смотрите реальное место на диске для своей коллекции, а не оценивайте его только по числу документов. Исходные файлы и резервные копии храните отдельно от поискового индекса.

## Как попадает содержимое

### Чтение

Enconvo читает каждый тип элемента подходящим инструментом:

| Содержимое | Чем читается |
|---|---|
| **PDF** | Плагином Document Parser. Он берёт текст PDF и запускает ваш провайдер OCR только на сканированных страницах |
| **Word, PowerPoint, Excel, EPUB, CSV** | Плагином Document Parser |
| **Текст и Markdown** | Читаются как есть |
| **Изображения** | Вашим провайдером OCR |
| **Аудио и видео** | Вашим провайдером транскрибирования |
| **Веб-страницы** | Вашим провайдером Web Fetch |
| **Целые сайты** | Обходчиком сайтов, страница за страницей |
| **YouTube** | Субтитрами видео |

### Разбиение на фрагменты

Enconvo режет текст на фрагменты по размеру, подходящему языку:

| Текст | Размер фрагмента | Перекрытие |
|---|---|---|
| В основном латиница, например английский | 1 500 символов | 200 символов |
| В основном китайский, японский или корейский | 560 символов | 80 символов |
| Смешанный | Промежуточный, по доле каждого | Промежуточный |

Рез идёт по самой естественной границе, которая удерживает фрагмент в пределах размера, в таком порядке:

1. Абзацы
2. Строки
3. Предложения
4. Части предложения
5. Слова
6. Жёсткий рез (крайний случай)

Таблицы режутся примерно по одной строке на фрагмент, чтобы поиск одной строки находил именно её. Эти размеры заданы в коде; отдельной настройки нет.

### Эмбеддинг

Все базы знаний используют одну модель эмбеддинга, EmbeddingGemma 300M. Где она работает, выбирается в **Настройки → Память → Модель эмбеддингов**:

- **Этот Mac**: бесплатно, и ничего не уходит с Mac, но пока индексируется новое содержимое, занят GPU. Нужен Mac с Apple silicon.
- **Enconvo Cloud**: бесплатно с учётной записью Enconvo. Текст, который индексируется или ищется, отправляется туда.

Оба варианта запускают одну модель, поэтому смена не ломает поисковый индекс. Enconvo считает эмбеддинги фрагментов пакетами.

### Хранение

Каждый фрагмент — одна строка в таблице базы знаний:

| Поле | Что хранит |
|---|---|
| `text` | Текст фрагмента |
| `vector` | Его эмбеддинг |
| `id` | Идентификатор фрагмента |
| `attachment_id` | Элемент, из которого фрагмент |
| `type`, `url`, `title`, `ext`, `loc` | Тип, адрес, название и расширение файла элемента и место фрагмента в нём |
| `metadata` | Прочие сведения об элементе |

Enconvo также ведёт полнотекстовый индекс по `text` из коротких последовательностей символов, поэтому находит точные имена, числа, код и слова на CJK.

## Как работает поиск

Каждый поиск запускает до трёх просмотров сразу по фрагментам базы знаний:

1. **По смыслу**: запрос превращается в эмбеддинг той же моделью, и ищутся ближайшие векторы.
2. **По словам**: полнотекстовый поиск (BM25) по каждому слову запроса, без частых английских слов.
3. **По названию**: элементы, чьё название совпадает с запросом, каждый со своим фрагментом, ближе всего к запросу.

Затем Enconvo смешивает списки. Оценки каждого списка приводятся к диапазону от 0 до 1, а оценка фрагмента — это 0,6 оценки по смыслу плюс 0,4 оценки по словам. Элемент с совпавшим названием или фрагмент, в котором есть весь запрос, стоит выше. От одного элемента остаётся лишь несколько фрагментов, чтобы один длинный документ не вытеснил остальное, и каждый фрагмент возвращается вместе с соседним текстом.

Отдельного шага переранжирования в поиске по базе знаний нет.

## Держать индекс в порядке

Enconvo сам создаёт полнотекстовый индекс и приводит таблицы в порядок. Он также перестраивает индекс базы знаний, если он сделан старым разбивщиком или другой моделью эмбеддинга, по уже имеющемуся тексту, без повторного чтения файлов.

Чтобы перестроить вручную:

- **Всю базу знаний**: откройте **Настройки базы знаний** в заголовке, перейдите в **Индексация и поиск** и нажмите **Переиндексировать…** рядом с **Перестроить весь индекс**. Поиск продолжает работать, пока это идёт.
- **Один элемент**: щёлкните по нему правой кнопкой и выберите **Переиндексировать**.

В **Настройках базы знаний** пять разделов: **Основные** (название и описание), **Индексация и поиск** (состояние, элементы, которым нужно внимание, модель поиска и переиндексация), **Источники и захват** (связанные папки и инструменты захвата), **AI-клиенты (MCP)** и **Дополнительно** (идентификатор и удаление базы знаний).

Удаляйте ненужные базы знаний, чтобы вернуть место на диске.

### Связанные папки

Если элемент пропал, сначала проверьте импорт и синхронизацию исходной папки. В **Источниках и захвате** у каждой связанной папки видно, идёт ли синхронизация, когда она была в последний раз или что исходная папка не найдена, а также **Синхронизировать сейчас**, **Привязать заново…** и **Автосинхронизация**.

Затем отдельно проверьте извлечение содержимого и эмбеддинг: в **Конвейере** элемента **Разбор контента** и **Поисковый индекс** — два разных этапа, и читаемый извлечённый текст не значит, что векторная индексация закончена. Переиндексируйте элемент после исправления ошибки провайдера или доступа к файлу.

Исходная папка остаётся главной для связанных файлов. Восстановление отключённого диска не путайте с удалением файлов: если исходная папка не найдена, база знаний сохраняет свои элементы. Прежде чем считать импорт завершённым, проверьте число пропущенных файлов.

## Несколько баз знаний

У каждой базы знаний свои документы, индекс и таблица. Делите содержимое так, как вы его ищете:

| Стратегия | Описание | Пример |
|----------|-------------|---------| 
| **По проекту** | Одна база на проект | `project-alpha`, `project-beta` |
| **По типу** | Отдельные базы по типу содержимого | `code-docs`, `meeting-notes`, `research` |
| **По команде** | Знания конкретной команды | `engineering`, `marketing`, `support` |
| **По охвату** | Личное и общее | `personal-notes`, `company-wiki` |

Чтобы искать сразу в нескольких, прикрепите их в выборе контекста или задайте базы знаний агента. Поиск без указанной базы знаний проходит по всем вашим, кроме Памяти.

## Базы знаний из кода

Плагин Базы знаний отдаёт свои маршруты через [Local API](/ru/advanced/cli-local-api), поэтому их могут вызывать другие плагины, рабочие процессы и скрипты. Основные:

| Маршрут | Назначение |
|---|---|
| `knowledge_base/create` | Создать базу знаний |
| `knowledge_base/delete` | Удалить базу знаний и все её данные |
| `knowledge_base/add`, `knowledge_base/add_attachments` | Добавить файлы, текст, ссылки или медиа |
| `knowledge_base/search` | Искать в одной или нескольких базах знаний |
| `knowledge_base/list` | Список баз знаний |
| `knowledge_base/get_attachments` | Список элементов базы знаний |
| `knowledge_base/delete_attachments` | Удалить элементы из базы знаний |
| `knowledge_base/reindex` | Перестроить индекс базы знаний или элемента |
| `knowledge_base/summarize` | Кратко пересказать один элемент |

Параметры каждого маршрута для установленной версии смотрите в **Настройки → APIs**.

Шаги с базой знаний встраиваются в рабочие процессы и автоматизации, например:

```
Trigger: New file in ~/Documents/research/
  → Add to Knowledge Base "research"
  → Search for related content
  → Generate summary
  → Save summary to notes
```

Для другого AI-клиента используйте [MCP базы знаний](/ru/advanced/knowledge-base-mcp). Он отдаёт выбранные базы знаний через локальную службу только для чтения и не экспортирует память агента и записи.

## Устранение неполадок

| Проблема | Что делать |
|---|---|
| Поиск возвращает не то | Проверьте, что этап **Поисковый индекс** элемента завершён, затем переиндексируйте базу знаний. Ищите словами из документа: точные имена и числа находятся через полнотекстовый индекс |
| Индексация идёт медленно | Большие документы занимают больше времени. С **Этот Mac** индексация занимает GPU; переключите **Модель эмбеддингов** на **Enconvo Cloud**, чтобы освободить Mac |
| Новые элементы не ищутся на Enconvo Cloud | Войдите в учётную запись Enconvo. Пока этого нет, новое содержимое не индексируется, а поиск находит только совпадающие слова |
| Тип файла не поддерживается | Преобразуйте его в PDF, TXT или MD и добавьте снова |
| База знаний не находится по идентификатору | Скопируйте идентификатор из **Настройки базы знаний → Дополнительно** и передайте его как `knowledge_base_id` |
