Эта страница для разработчиков, которые хотят дать агенту Enconvo свои инструменты. Свой сервер MCP открывает инструменты, которые агент Enconvo может вызывать. Начните с небольшого локального сервера, проверьте вход и результат, затем добавьте работу, нужную вашему сервису.

Чтобы установить чужой сервер, смотрите [Серверы MCP](/ru/features/mcp). Чтобы сервер ставился также в Codex и Claude Code, упакуйте его как плагин с `--template mcp` (см. [Форматы плагинов](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code)).

## Перед началом

Нужны Node.js и npm. В примере используется **JavaScript API 1.x** TypeScript SDK, зафиксированный на 1.29.0. Крупные версии SDK могут требовать другие импорты и настройку; при выборе другой версии смотрите [официальное руководство по серверу MCP](https://modelcontextprotocol.io/docs/develop/build-server).

## Минимальный локальный сервер

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

Сохраните это как `server.mjs`:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

Сервер stdio ждёт сообщения протокола; запуск в терминале не показывает интерфейс чата. Диагностику пишите в stderr (например, `console.error`), потому что stdout несёт сообщения протокола MCP. [Официальное руководство](https://modelcontextprotocol.io/docs/develop/build-server) объясняет это требование транспорта.

## Подключение к Enconvo

<Steps>
  <Step title="Добавьте сервер">
    Откройте **Настройки → Серверы MCP** и нажмите **Добавить сервер**. Задайте **Имя сервера**, например `hello-mcp`.
  </Step>
  <Step title="Укажите, как он запускается">
    Выберите **STDIO**. В **Команде** введите `node`. В **Аргументах** укажите абсолютный путь к `server.mjs`. Если Enconvo не находит Node, укажите абсолютный путь к исполняемому файлу.
  </Step>
  <Step title="Сохраните и проверьте">
    Нажмите **Сохранить**. Убедитесь, что сервер подключился и отдаёт `greet`.
  </Step>
  <Step title="Попробуйте">
    Сделайте его доступным агенту и попросите поздороваться с «Ada». Ожидаемый результат инструмента — `Hello, Ada!`.
  </Step>
</Steps>

Эквивалентная конфигурация:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

Замените пример пути на настоящий путь к файлу.

## Полезные инструменты

- У каждого инструмента — конкретное действие и описание.
- Проверяйте вход на границе инструмента и возвращайте понятные сообщения об ошибках.
- Отделяйте чтение данных от изменений вроде отправки или удаления.
- Возвращайте короткий результат, который агент может понять.
- Храните учётные данные в подходящей конфигурации сервера, вне примеров кода и журналов.

## Удалённые серверы и аутентификация

Для удалённого сервера используйте транспорт HTTP или SSE из его инструкции и соответствующую форму Enconvo (**HTTP** или **SSE** вместо **STDIO**). URL сервера должен быть конечной точкой MCP, а не адресом обычного сайта. Пройдите поддерживаемый вход и подтвердите соединение, прежде чем включать инструменты.

Удалённый транспорт, обнаружение аутентификации и поведение сессии зависят от сервера и версии протокола. Для деталей реализации смотрите официальный SDK и документацию протокола, а не придумывайте манифест `auth`, который Enconvo не читает.

## Устранение неполадок

| Проблема | Что делать |
| --- | --- |
| Процесс сразу завершается | Проверьте путь к исполняемому файлу, зависимости, синтаксические ошибки и stderr |
| Подключён, но инструмент не появляется | Проверьте регистрацию инструмента, что он включён, и выбранного агента |
| Неверный ответ протокола | Ищите случайный вывод в stdout или запуск не той программы |
| Ошибка проверки схемы | Сравните фактическую форму входа с используемой версией SDK |
| Удалённое соединение не устанавливается | Проверьте URL конечной точки, транспорт, аутентификацию и доступ к сети |

Чтобы отдать документы Enconvo другому AI-клиенту, используйте встроенный [сервер MCP базы знаний](/ru/advanced/knowledge-base-mcp); свой сервер для этого не нужен.
