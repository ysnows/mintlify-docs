Эта страница для разработчиков, которые хотят дать агенту Enconvo собственные инструменты. Собственный сервер MCP предоставляет инструменты, которые может вызывать агент Enconvo. Начните с небольшого локального сервера, проверьте его входные данные и результат, а затем добавьте нужную работу с конкретным сервисом.

Чтобы установить сервер, созданный кем-то другим, см. [Серверы MCP](/ru/features/mcp). Чтобы поставлять свой сервер так, чтобы он устанавливался и в Codex, и в Claude Code, упакуйте его как плагин с `--template mcp` (см. [Форматы плагинов](/extensions/plugin-formats#one-package-for-enconvo-codex-and-claude-code)).

## Прежде чем начать

Вам нужны Node.js и npm. В этом примере используется **JavaScript API 1.x** TypeScript SDK, закреплённый на версии 1.29.0. В разных основных версиях SDK могут быть разные импорты и настройка; при выборе другой версии обратитесь к [официальному руководству по серверам MCP](https://modelcontextprotocol.io/docs/develop/build-server).

## Напишите минимальный локальный сервер

```sh
mkdir hello-mcp
cd hello-mcp
npm init -y
npm install @modelcontextprotocol/sdk@1.29.0 zod@3
```

Сохраните это как `server.mjs`:

```javascript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "hello-enconvo", version: "1.0.0" });

server.registerTool("greet", {
  description: "Return a greeting for the supplied name.",
  inputSchema: { name: z.string().min(1).describe("Name to greet") },
}, async ({ name }) => ({
  content: [{ type: "text", text: `Hello, ${name}!` }],
}));

await server.connect(new StdioServerTransport());
```

Сервер stdio ожидает сообщений протокола; при запуске в терминале интерфейс чата не отображается. Выводите диагностику в stderr (например, через `console.error`), потому что stdout несёт сообщения протокола MCP. Это требование к транспорту объясняется в [официальном руководстве](https://modelcontextprotocol.io/docs/develop/build-server).

## Подключите его к Enconvo

<Steps>
  <Step title="Добавьте сервер">
    Откройте **Настройки → Серверы MCP** и нажмите **Добавить сервер**. Задайте **Имя сервера**, например `hello-mcp`.
  </Step>
  <Step title="Задайте способ запуска">
    Выберите **STDIO**. В поле **Команда** введите `node`. В поле **Аргументы** введите абсолютный путь к `server.mjs`. Если Enconvo не находит Node, используйте абсолютный путь к его исполняемому файлу.
  </Step>
  <Step title="Сохраните и проверьте">
    Нажмите **Сохранить**. Убедитесь, что сервер подключился и предоставляет `greet`.
  </Step>
  <Step title="Попробуйте">
    Сделайте его доступным для вашего агента и попросите поприветствовать «Аду». Ожидаемый результат инструмента — `Hello, Ada!`.
  </Step>
</Steps>

Эквивалентная конфигурация:

```json
{
  "command": "node",
  "args": ["/absolute/path/to/hello-mcp/server.mjs"]
}
```

Замените путь из примера фактическим путём к вашему файлу.

## Проектируйте полезные инструменты

- Давайте каждому инструменту конкретное действие и описание.
- Проверяйте входные данные на границе инструмента и возвращайте понятные сообщения об ошибках.
- Отделяйте чтение данных от изменений, например отправки или удаления.
- Возвращайте компактный результат, который агент сможет истолковать.
- Храните учётные данные в подходящей конфигурации сервера, вне примеров исходного кода и журналов.

## Удалённые серверы и аутентификация

Для удалённого сервера используйте транспорт HTTP или SSE, указанный в инструкции по его настройке, и соответствующую форму Enconvo (**HTTP** или **SSE** вместо **STDIO**). URL сервера должен быть конечной точкой MCP, а не обычным адресом веб-сайта. Пройдите любой поддерживаемый процесс авторизации и убедитесь в подключении, прежде чем включать его инструменты.

Удалённый транспорт, обнаружение аутентификации и поведение сеанса зависят от сервера и версии протокола. За подробностями реализации обращайтесь к официальной документации SDK и протокола, а не придумывайте манифест `auth`, который Enconvo не использует.

## Устранение неполадок

| Проблема | Что делать |
| --- | --- |
| Процесс сразу завершается | Проверьте путь к исполняемому файлу, зависимости, синтаксические ошибки и stderr |
| Подключение есть, но инструменты не появляются | Проверьте регистрацию инструмента, включён ли он и выбранного агента |
| Недопустимый ответ протокола | Поищите случайный вывод в stdout или запуск не той программы |
| Ошибка проверки схемы | Сравните фактическую форму входных данных с используемой версией SDK |
| Сбой удалённого подключения | Проверьте URL конечной точки, транспорт, аутентификацию и доступ к сети |

Чтобы открыть собственные документы Enconvo другому ИИ-клиенту, используйте встроенный [сервер MCP базы знаний](/ru/advanced/knowledge-base-mcp); собственный сервер не требуется.
