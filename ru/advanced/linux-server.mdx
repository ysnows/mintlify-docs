Эта страница для вас, если ваш Mac добавил сервер Linux в разделе **Настройки → Подключения** и установил на него Enconvo. Сервер запускает Enconvo без экрана, и ваш Mac открывает его чаты, но не его настройки. Настроить сервер можно тремя способами: в его веб-интерфейсе, из его командной строки или синхронизировав с ним настройки вашего Mac.

## Чем ваш Mac делится с сервером

Сопряжение позволяет вашему Mac использовать чаты, агентов и файлы сервера. Настройки оно не передаёт. Сервер хранит собственные модели, агентов, плагины и ключи API и не копирует их с вашего Mac.

- Настройки и ключи API нельзя открыть с вашего Mac. Вы меняете их на сервере.
- По умолчанию агенты сервера используют модель по умолчанию. При новой установке это Enconvo Cloud в учетной записи, под которой вошёл сервер, поэтому его чаты расходуют ваши баллы Cloud.
- Чтобы быстро сменить модель одного агента, воспользуйтесь выбором модели в чате сервера на вашем Mac. Он задаёт модель, уровень рассуждения и скорость для этого агента на сервере. Провайдеру, которому нужен ключ API, сначала нужен этот ключ на сервере.

## Откройте веб-интерфейс сервера

Сервер может отдавать Окно чата и Настройки как веб-сайт, так что вы можете пользоваться Настройками в браузере вашего Mac. Установка с вашего Mac его не включает. Включите его один раз по SSH.

<Steps>
  <Step title="Включите веб-интерфейс">
    Подключитесь к серверу через `ssh` и выполните:

    ```bash
    enconvo service install --web 127.0.0.1:54580
    ```

    Эта команда перезаписывает службу Enconvo с включённым веб-интерфейсом и перезапускает её. Он слушает только `127.0.0.1`, поэтому снаружи сервера до него не добраться. При повторном запуске `enconvo service install` служба работает только с параметрами последнего запуска.
  </Step>
  <Step title="Откройте туннель с вашего Mac">
    В Терминале на вашем Mac используйте то же имя хоста, что и с `ssh`:

    ```bash
    ssh -N -L 54580:127.0.0.1:54580 my-server
    ```

    Не закрывайте его, пока пользуетесь веб-интерфейсом. Нажмите Control-C, чтобы закрыть туннель.
  </Step>
  <Step title="Откройте веб-интерфейс">
    Откройте `http://127.0.0.1:54580` в браузере вашего Mac. Настройки работают так же, как на вашем Mac: выбирайте модели в **Настройки → AI-модель**, добавляйте плагины в **Настройки → Плагины** и вводите там же ключи API.
  </Step>
</Steps>

`enconvo service url` на сервере выводит адрес веб-интерфейса.

### Доступ без туннеля

Чтобы открывать веб-интерфейс с других компьютеров без SSH, привяжите его к сети:

```bash
enconvo service install --web 0.0.0.0:54580
```

Тогда веб-интерфейсу понадобится токен подключения. Выполните `enconvo service url`, чтобы вывести адрес с ним, оканчивающийся на `?tkn=`. Откройте эту ссылку один раз, и браузер сохранит токен. За обратным прокси добавьте `--web-url https://enconvo.example.com` с адресом, который отдаёт прокси, или `--web-host <name>` для другого имени, по которому доступен сервер. Для обоих тоже нужен токен.

<Warning>
  Токен даёт тому, у кого он есть, вашу учетную запись Enconvo на сервере и все файлы, которые может прочитать её пользователь. Держите ссылку в тайне, закройте порт межсетевым экраном или VPN и отдавайте предпочтение туннелю SSH. Чтобы заменить токен, удалите на сервере `~/.config/enconvo/.support/windows-shell/web-token` и выполните `systemctl --user restart enconvo`.
</Warning>

## Настройка из командной строки

Маршруты каждого установленного плагина — это команды `enconvo` на сервере: `enconvo <plugin> <route> --flags` или `--input-json` для всего запроса. Добавьте `-h` на любом уровне, чтобы увидеть, что там есть:

```bash
enconvo -h
enconvo config -h
enconvo config set -h
```

Заключайте в кавычки ключи, содержащие `|`, например `'agent|main'`. Без кавычек оболочка воспринимает `|` как конвейер.

### Модели

Выведите список провайдеров моделей сервера. `commandKey` каждого из них, например `llm|enconvo_ai`, — это значение, которое вы задаёте:

```bash
enconvo llm list_providers
```

Задайте модель по умолчанию, которую используют все агенты, настроенные на модель по умолчанию:

```bash
enconvo config get llm --includes selected
enconvo config set --preferenceKey llm --keys selected --value 'llm|<provider id>'
```

Задайте модель одного агента. Главный агент — `agent|main`; `enconvo agent list` показывает `command_key` остальных:

```bash
enconvo config get 'agent|main' --includes llm
enconvo config set --preferenceKey 'agent|main' --keys llm --value 'llm|<provider id>'
```

Задайте значение `default`, чтобы снова следовать модели по умолчанию. `enconvo config preferences 'agent|main'` перечисляет все настройки агента.

Чтобы отменить одну настройку, назовите её:

```bash
enconvo config reset 'agent|main' --keys llm
```

<Warning>
  `enconvo config reset` без `--keys` сбрасывает все настройки этого ключа, а для агента или команды ещё и удаляет данные его рабочего пространства. Это нельзя отменить.
</Warning>

`config get` показывает сохранённые ключи API и токены как `[hidden]`. Вводите ключи API в Настройках веб-интерфейса, а не через `config set`, чтобы они не попали в историю вашей оболочки.

### Плагины

```bash
enconvo plugin list
enconvo plugin install owner/repo
enconvo plugin uninstall <name>
```

`plugin install` принимает GitHub `owner/repo`, URL git, ссылку `https` на `.zip`, `npm:<package>`, папку или `<plugin>@<marketplace>`. Плагины, которым нужен экран, на сервере скрыты.

### Агенты

```bash
enconvo agent list
enconvo agent create -h
```

`enconvo agent -h` перечисляет остальное, например удаление или приостановку агента.

## Используйте настройки вашего Mac через синхронизацию

Синхронизация копирует настройки вашего Mac на сервер через вашу учетную запись Enconvo. Она входит в тарифы Enconvo Cloud и пожизненные лицензии.

1. На вашем Mac откройте **Настройки → Синхронизация**, включите **Синхронизация между компьютерами** и выберите **Учетная запись Enconvo** в разделе **Хранилище**. Сервер Linux не может обратиться к iCloud.
2. В веб-интерфейсе сервера откройте **Настройки → Синхронизация** и включите **Синхронизация между компьютерами**.
3. В разделе **Что синхронизируется** выберите, что переносить, на обоих компьютерах, например **Настройки**, **Плагины** и **Навыки**.
4. Чтобы перенести и ключи API, включите **Ключи API** на обоих. По умолчанию это выключено. Ваш Mac покажет код: проверьте, что сервер показывает такой же, затем нажмите **Разрешить**.

То, что относится к одному компьютеру, остаётся на нём: горячие клавиши, пути к папкам и рабочие папки, входы в аккаунты, Автоматизации и боты для обмена сообщениями. О том, что охватывает каждый вариант, см. [Синхронизация Mac](/ru/configuration/account).

## Устранение неполадок

| Проблема | Что делать |
| --- | --- |
| `enconvo: command not found` | Откройте новый сеанс SSH. Установка добавляет папку Enconvo в `PATH` в профиле вашей оболочки, а сеанс, открытый до установки, его не прочитал. |
| `enconvo service url` не выводит адрес | Enconvo не запущен или работает без веб-интерфейса. Снова выполните `enconvo service install --web 127.0.0.1:54580`. |
| Браузер не открывает `127.0.0.1:54580` | Проверьте, что туннель всё ещё открыт, затем проверьте службу командой `systemctl --user status enconvo` и её журнал командой `journalctl --user -u enconvo`. |
| Веб-интерфейс запрашивает токен подключения | Откройте полную ссылку, которую выводит `enconvo service url`, с `?tkn=` в конце. |
| `service install` сообщает, что Enconvo уже запущен для этого пользователя | Ваш Mac запустил Enconvo как фоновый процесс, что происходит, когда сервер не держит пользовательские службы запущенными после выхода из системы. Выполните `sudo loginctl enable-linger $USER`, снова выполните `enconvo service install --web 127.0.0.1:54580`, затем перезапустите сервер, чтобы службу взяла на себя система. |
| `service install` сообщает, что systemd недоступен | Вместо этого запустите `enconvo --headless --web 127.0.0.1:54580` под собственным менеджером процессов. |
| Чаты используют не ту модель, что на вашем Mac | У сервера свои модели. Проверьте `enconvo config get llm --includes selected` или включите синхронизацию. |
