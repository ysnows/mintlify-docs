Эта страница для вас, если Mac добавил сервер Linux в **Настройки → Connections** и установил там Enconvo. Сервер запускает Enconvo без экрана, и Mac открывает его чаты, но не настройки. Настроить сервер можно тремя способами: в его веб-интерфейсе, из командной строки или синхронизировав настройку Mac на него.

## Чем Mac делится с сервером

Сопряжение позволяет Mac пользоваться чатами, агентами и файлами сервера. Настройки оно не разделяет. Сервер хранит свои модели, агентов, плагины и API-ключи и не копирует их с Mac.

- Настройки и API-ключи с Mac не открываются. Их меняют на сервере.
- Сразу после установки агенты сервера используют модель по умолчанию. На новой установке это Enconvo Cloud, на учетной записи, в которую вошёл сервер, поэтому его чаты тратят ваши баллы Cloud.
- Чтобы быстро сменить модель одного агента, используйте выбор модели в чате сервера на Mac. Он задаёт модель, усилие рассуждения и скорость этого агента на сервере. Провайдеру, которому нужен API-ключ, сначала нужен этот ключ на сервере.

## Откройте веб-интерфейс сервера

Сервер может отдавать Окно чата и Настройки как сайт, чтобы пользоваться Настройками в браузере Mac. Установка с Mac этого не включает. Включите один раз по SSH.

<Steps>
  <Step title="Включите веб-интерфейс">
    Подключитесь к серверу через `ssh` и выполните:

    ```bash
    enconvo service install --web 127.0.0.1:54580
    ```

    Это переписывает службу Enconvo с включённым веб-интерфейсом и перезапускает её. Она слушает только `127.0.0.1`, поэтому снаружи сервера до неё не добраться. Когда вы снова запускаете `enconvo service install`, служба работает только с параметрами нового запуска.
  </Step>
  <Step title="Откройте туннель с Mac">
    В Terminal на Mac используйте то же имя хоста, что и с `ssh`:

    ```bash
    ssh -N -L 54580:127.0.0.1:54580 my-server
    ```

    Оставьте его запущенным, пока пользуетесь веб-интерфейсом. Нажмите Control-C, чтобы закрыть.
  </Step>
  <Step title="Откройте веб-интерфейс">
    Откройте `http://127.0.0.1:54580` в браузере Mac. Настройки работают как на Mac: выбирайте модели в **Настройки → AI-модель**, добавляйте плагины в **Настройки → Плагины** и вводите там же API-ключи.
  </Step>
</Steps>

`enconvo service url` на сервере печатает адрес веб-интерфейса.

### Доберитесь без туннеля

Чтобы открывать веб-интерфейс с других компьютеров без SSH, привяжите его к сети:

```bash
enconvo service install --web 0.0.0.0:54580
```

Тогда веб-интерфейсу нужен токен соединения. Выполните `enconvo service url`, чтобы напечатать адрес с ним, заканчивающийся на `?tkn=`. Откройте эту ссылку один раз, и браузер сохранит токен. За обратным прокси добавьте `--web-url https://enconvo.example.com` с адресом, который отдаёт прокси, или `--web-host <name>` для другого имени, по которому доступен сервер. Оба тоже требуют токен.

<Warning>
  Токен даёт тому, у кого он есть, вашу учетную запись Enconvo на сервере и каждый файл, который может прочитать её пользователь. Держите ссылку в тайне, держите порт за файрволом или VPN и предпочитайте туннель SSH. Чтобы заменить токен, удалите `~/.config/enconvo/.support/windows-shell/web-token` на сервере и выполните `systemctl --user restart enconvo`.
</Warning>

## Настройка из командной строки

Маршруты каждого установленного плагина — команды `enconvo` на сервере: `enconvo <plugin> <route> --flags` или `--input-json` для всего запроса. Добавьте `-h` на любом уровне, чтобы увидеть, что там есть:

```bash
enconvo -h
enconvo config -h
enconvo config set -h
```

Заключайте в кавычки ключи с `|`, например `'agent|main'`. Без кавычек оболочка читает `|` как канал.

### Модели

Перечислите провайдеров моделей сервера. `commandKey` каждого, например `llm|enconvo_ai`, — значение, которое вы задаёте:

```bash
enconvo llm list_providers
```

Задайте модель по умолчанию, которую использует каждый агент, настроенный на значение по умолчанию:

```bash
enconvo config get llm --includes selected
enconvo config set --preferenceKey llm --keys selected --value 'llm|<provider id>'
```

Задайте модель одного агента. Основной агент — `agent|main`; `enconvo agent list` показывает `command_key` остальных:

```bash
enconvo config get 'agent|main' --includes llm
enconvo config set --preferenceKey 'agent|main' --keys llm --value 'llm|<provider id>'
```

Задайте значение `default`, чтобы снова следовать модели по умолчанию. `enconvo config preferences 'agent|main'` перечисляет все настройки агента.

Чтобы отменить одну настройку, назовите её:

```bash
enconvo config reset 'agent|main' --keys llm
```

<Warning>
  `enconvo config reset` без `--keys` сбрасывает все настройки этого ключа, а для агента или команды также удаляет данные его рабочего пространства. Это нельзя отменить.
</Warning>

`config get` показывает сохранённые API-ключи и токены как `[hidden]`. Вводите API-ключи в Настройках веб-интерфейса, а не через `config set`, чтобы они не попали в историю оболочки.

### Плагины

```bash
enconvo plugin list
enconvo plugin install owner/repo
enconvo plugin uninstall <name>
```

`plugin install` принимает GitHub `owner/repo`, git URL, ссылку `https` на `.zip`, `npm:<package>`, папку или `<plugin>@<marketplace>`. Плагины, которым нужен экран, на сервере скрыты.

### Агенты

```bash
enconvo agent list
enconvo agent create -h
```

`enconvo agent -h` перечисляет остальное, например удаление или паузу агента.

## Используйте настройку Mac через Sync

Sync копирует настройки Mac на сервер через учетную запись Enconvo. Это часть тарифов Enconvo Cloud и пожизненных лицензий.

1. На Mac откройте **Настройки → Sync**, включите **Sync across computers** и выберите **Enconvo account** в **Storage**. Сервер Linux не может достучаться до iCloud.
2. В веб-интерфейсе сервера откройте **Настройки → Sync** и включите **Sync across computers**.
3. В **What syncs** выберите, что перенести на обоих компьютерах, например **Настройки**, **Плагины** и **Навыки**.
4. Чтобы перенести и API-ключи, включите **API Keys** на обоих. По умолчанию выключено. Mac тогда показывает код: проверьте, что сервер показывает тот же, затем нажмите **Allow**.

То, что принадлежит одному компьютеру, остаётся там: сочетания клавиш, пути папок и рабочие папки, входы, Автоматизации и боты мессенджеров. Что покрывает каждый выбор — в [Учетной записи и Sync](/ru/configuration/account).

## Устранение неполадок

| Проблема | Что сделать |
| --- | --- |
| `enconvo: command not found` | Откройте новую сессию SSH. Установка добавляет папку Enconvo в `PATH` профиля оболочки, который сессия, открытая до установки, не прочитала. |
| `enconvo service url` не печатает адрес | Enconvo не запущен или работает без веб-интерфейса. Снова выполните `enconvo service install --web 127.0.0.1:54580`. |
| Браузер не может открыть `127.0.0.1:54580` | Проверьте, что туннель ещё открыт, затем проверьте службу через `systemctl --user status enconvo` и её журнал через `journalctl --user -u enconvo`. |
| Веб-интерфейс спрашивает токен соединения | Откройте полную ссылку, которую печатает `enconvo service url`, с `?tkn=` в конце. |
| `service install` говорит, что Enconvo уже запущен для этого пользователя | Mac запустил Enconvo как фоновый процесс, что он делает, когда сервер не держит пользовательские службы после выхода. Выполните `sudo loginctl enable-linger $USER`, снова `enconvo service install --web 127.0.0.1:54580`, затем перезапустите сервер, чтобы служба взяла управление. |
| `service install` говорит, что systemd недоступен | Вместо этого выполните `enconvo --headless --web 127.0.0.1:54580` под своим менеджером процессов. |
| Чаты используют другую модель, чем на Mac | У сервера свои модели. Проверьте `enconvo config get llm --includes selected` или включите Sync. |
