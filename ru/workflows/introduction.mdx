Рабочий процесс — это повторяемый процесс, сохраненный как шаги: прочитать информацию, преобразовать ее, спросить модель, передать работу агенту или вызвать установленный инструмент. Используйте его, когда одну и ту же многошаговую работу делаете снова и снова и хотите видеть, что дал каждый шаг. Откройте **Настройки → Рабочие процессы → Управление**, чтобы смотреть рабочие процессы и историю запусков.

<Tip>
Только начинаете? Посмотрите видеоурок на 2½ минуты [Соберите первый рабочий процесс](/ru/workflows/build-your-first-workflow): создание, правка и запуск от начала до конца.
</Tip>

## Выберите подходящий инструмент

| Вам нужно | Используйте |
| --- | --- |
| Повторно использовать запрос на выделенном тексте | [AI Commands](/ru/features/ai-commands) |
| Позволить помощнику решать, какие инструменты использовать | [Агенты](/ru/ai/agents) |
| Задать повторяемую последовательность с проверяемыми результатами | Рабочий процесс |
| Запустить инструкцию агента, рабочий процесс или скрипт в заданное время | [Автоматизации](/ru/workflows/scheduled-jobs) |

## Как устроен рабочий процесс

У рабочего процесса три части:

- `inputs`: значения, которые нужны запуску, например тема или фрагмент текста.
- `jobs`: именованные группы шагов. Задания стартуют параллельно, если `needs` не заставляет одно ждать другое.
- `steps`: упорядоченный список внутри каждого задания. Шаги внутри задания идут один за другим.

Текущие рабочие процессы используют `version: agent-workflow/v1` с картой `jobs`, и у каждого задания есть список `steps`:

```yaml
version: agent-workflow/v1
title: Quick Summary
description: Summarize supplied text into three bullets.
inputs:
  text:
    type: string
    default: "A sample paragraph to summarize."
jobs:
  main:
    steps:
      - id: summarize
        prompt: "Summarize in three bullets: {{ inputs.text }}"
```

<Note>
Старый формат верхнего уровня `tasks` больше не принимается. Перенесите каждую последовательность в `jobs.<name>.steps`, дайте шагам явные ID и используйте `steps.<id>.output` внутри задания или `jobs.<job>.<step>.output` между заданиями.
</Note>

## Что может шаг

Каждый шаг делает ровно одно из этого:

| Шаг | Поля | Результат |
| --- | --- | --- |
| Оболочка | `command` или `run` | Вывод команды, включая `stdout`, `stderr` и `exitCode` |
| Запрос | `prompt` | Ответ модели; используйте схему вывода для структурированных данных |
| Агент | `agent` и `message` | Ответ выбранного агента |
| Инструмент | `tool` и `with` | Результат установленной конечной точки Local API |
| Преобразование | `uses: transform` и `value` | Значение по шаблону |
| Вложенный процесс | `uses: workflow` с `workflowId` или `workflow` | Результат запуска дочернего рабочего процесса |
| Одобрение | `uses: approval` и `message` | Ваш ответ: одобрено или отклонено, с необязательным отзывом |
| Судья | `uses: judge` и `question` | Да или нет от Jev, быстрой модели решений Enconvo Cloud, с вероятностью |
| Классификация | `uses: classify`, `question` и `options` | Вариант, который выбрал Jev, с уверенностью |

Шаг также может выполняться только при условии, повторяться по списку, повторять попытку или возвращать структурированные данные. См. [Продвинутые рабочие процессы](/ru/workflows/advanced-workflows).

## Запустить рабочий процесс

- Откройте его в **Рабочие процессы**, задайте **Inputs** и выберите **Run**.
- Найдите сохраненный рабочий процесс в SmartBar. Текст запуска доступен как `inputs.input_text`.
- Упомяните доступный рабочий процесс через `@` в чате, чтобы агент мог его использовать.
- Запускайте по расписанию через [автоматизацию](/ru/workflows/scheduled-jobs).

## Где сохраняются рабочие процессы

Каждый рабочий процесс — один файл в `~/.enconvo/workflows/<id>.yaml`. Имя файла — это ID рабочего процесса. Держите этот ID стабильным, чтобы сохранить связь с историей запусков.
