Рабочий процесс — это повторяемый процесс, сохранённый в виде шагов: прочитать информацию, преобразовать её, спросить модель, передать работу агенту или вызвать установленный инструмент. Используйте его, когда вы снова и снова выполняете одну и ту же многошаговую работу и хотите видеть, что дал каждый шаг. Откройте **Настройки → Рабочие процессы → Управление**, чтобы просмотреть свои рабочие процессы и историю их запусков.

<Tip>
Впервые знакомитесь с рабочими процессами? Посмотрите видеоурок на 2½ минуты [Создайте свой первый сценарий](/ru/workflows/build-your-first-workflow), чтобы создать, изменить и запустить рабочий процесс от начала до конца.
</Tip>

## Как устроен рабочий процесс

Рабочий процесс состоит из трёх частей:

- `inputs`: значения, которые нужны запуску, например тема или фрагмент текста.
- `jobs`: именованные группы шагов. Задания (jobs) начинаются параллельно, если только `needs` не заставляет одно ждать другое.
- `steps`: упорядоченный список внутри каждого задания. Шаги внутри задания выполняются один за другим.

Текущие рабочие процессы используют `version: agent-workflow/v1` с картой `jobs`, и каждое задание содержит список `steps`:

```yaml
version: agent-workflow/v1
title: Quick Summary
description: Summarize supplied text into three bullets.
inputs:
  text:
    type: string
    default: "A sample paragraph to summarize."
jobs:
  main:
    steps:
      - id: summarize
        prompt: "Summarize in three bullets: {{ inputs.text }}"
```

<Note>
Прежний формат `tasks` верхнего уровня больше не принимается. Перенесите каждую последовательность в `jobs.<name>.steps`, задайте шагам явные ID и используйте `steps.<id>.output` внутри задания или `jobs.<job>.<step>.output` между заданиями.
</Note>

## Что может делать шаг

Каждый шаг делает ровно одно из следующего:

| Шаг | Поля | Результат |
| --- | --- | --- |
| Shell | `command` или `run` | Вывод команды, включая `stdout`, `stderr` и `exitCode` |
| Prompt | `prompt` | Ответ модели; для структурированных данных используйте схему вывода |
| Agent | `agent` и `message` | Ответ выбранного агента |
| Tool | `tool` и `with` | Результат установленной конечной точки Local API |
| Transform | `uses: transform` и `value` | Значение, собранное по шаблону |
| Subworkflow | `uses: workflow` с `workflowId` или `workflow` | Результат запуска дочернего рабочего процесса |
| Approval | `uses: approval` и `message` | Ваш ответ: одобрено или отклонено с необязательным комментарием |
| Judge | `uses: judge` и `question` | Ответ «да» или «нет» от Jev, быстрой модели принятия решений Enconvo Cloud, с его вероятностью |
| Classify | `uses: classify`, `question` и `options` | Вариант, выбранный Jev, с его уверенностью |

Шаг также может выполняться только при выполнении условия, повторяться по списку, повторять попытки или возвращать структурированные данные. См. [Расширенные рабочие процессы](/ru/workflows/advanced-workflows).

## Запуск рабочего процесса

- Откройте его в **Рабочие процессы**, задайте **Входные данные** и выберите **Запустить**.
- Найдите сохранённый рабочий процесс в SmartBar. Текст из панели запуска доступен как `inputs.input_text`.
- Упомяните доступный рабочий процесс через `@` в чате, чтобы агент мог его использовать.
- Запускайте его по расписанию через [автоматизацию](/ru/workflows/scheduled-jobs).

## Где сохраняются рабочие процессы

Каждый рабочий процесс — это один файл `~/.enconvo/workflows/<id>.yaml`. Имя файла — это ID рабочего процесса. Сохраняйте этот ID неизменным, чтобы не потерять связь с историей его запусков.
