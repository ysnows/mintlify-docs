Большинство людей устанавливают плагины из магазина плагинов на странице **Плагины** в Enconvo. Enconvo также устанавливает плагины из других мест, включая плагины Codex и Claude Code, которые их разработчики публикуют на GitHub и в маркетплейсах плагинов. О пакетах, которые читает Enconvo, смотрите [Форматы плагинов](/extensions/plugin-formats).

Чтобы установить плагин из приложения, прочитайте разделы [Со страницы плагинов](#со-страницы-плагинов) и [Из чата](#из-чата). Остальная часть страницы предназначена для разработчиков и опытных пользователей: установка из Терминала, добавление маркетплейсов плагинов, обновление и удаление, а также публикация собственного плагина.

<Warning>
Только плагины из магазина Enconvo проходят проверку в Enconvo. Плагин из любого другого места может запускать программы на вашем Mac через свои серверы MCP, поэтому устанавливайте его только из источника, которому вы доверяете.
</Warning>

## Со страницы плагинов

Нажмите **Добавить** на странице **Плагины**:

| Вариант | Что делает |
|---|---|
| **Создать плагин** | Начинает чат, в котором агент Enconvo создаёт плагин вместе с вами. |
| **Загрузить архив плагина…** | Устанавливает файл: пакет `.enconvo` или `.zip` с плагином Claude Code или Codex. |
| **Добавить из GitHub…** | Устанавливает плагин или плагин из маркетплейса плагинов из GitHub, git, npm или папки (смотрите ниже). |
| **Добавить сервер MCP…** | Открывает настройки MCP, чтобы подключить один сервер без плагина вокруг него. |
| **Добавить расширение PopBar…** | Устанавливает расширение PopBar по ссылке, из файла или из фрагмента `#popclip` (смотрите [Расширения PopBar](/ru/features/popbar)). |
| **Новый навык…** | Открывает настройки навыков, чтобы написать собственный навык. |
| **Руководство разработчика** | Открывает [Разработка расширений](/ru/extensions/developing). |

То, что вы добавили, находится в разделе **Установлено** вверху вкладки **Enconvo**: подключённые вами Коннекторы и установленные или созданные вами плагины, по названию. Нажмите **Установлено**, чтобы увидеть их все. Плагины, которые поставляются с Enconvo, там не перечислены. У расширений PopBar есть собственная вкладка **PopBar** с проверенным каталогом Enconvo; смотрите [Расширения PopBar](/ru/features/popbar).

### Добавление из GitHub

Вставьте адрес плагина и нажмите **Предпросмотр**:

- `owner/repo` или ссылка на GitHub, в том числе на папку (`/tree/<branch>/<folder>`)
- `owner/repo/folder` для плагина внутри репозитория, с `@branch` или `@tag`, чтобы зафиксировать версию
- любой адрес git по https
- `npm:<package>`, с `@version`, чтобы зафиксировать версию
- ссылка https на `.zip` плагина
- папка на вашем Mac

Приватный репозиторий GitHub или git тоже подходит. Enconvo использует учётную запись GitHub, в которую вы уже вошли на этом Mac, или ваш ключ SSH, так что вводить пароль не нужно.

Прежде чем что-либо установить, Enconvo показывает плагин: его формат (Codex, Claude Code, переносимый или Enconvo), версию, разработчика, навыки, серверы MCP и хуки, а также приложения ChatGPT, которые он включает и которые Enconvo не загружает. Для каждого сервера MCP указано, запускается ли он на вашем Mac или подключается через интернет. Хуки плагина запускают команды на вашем Mac, поэтому они остаются выключенными, если вы не отметите **Разрешить запуск хуков**. Нажмите **Установить**, и Enconvo откроет страницу плагина. В её строке **Источник** указано, откуда пришёл плагин (для GitHub и git с коммитом), и есть ссылка на репозиторий или страницу npm, а примечание внизу называет разработчика плагина: только собственные плагины Enconvo и плагины из его магазина сообщают, что они созданы Enconvo. Плагины, установленные таким образом, перечислены в разделе **Личное**. Повторная установка из того же места обновляет плагин. Если плагин с таким же именем уже установлен из другого места, сначала удалите его.

Если адрес — маркетплейс плагинов, диалог перечисляет его плагины с кнопкой **Установить** у каждого. Установка одного из них добавляет маркетплейс, который при следующем открытии диалога показывается в разделе **Ваши маркетплейсы**.

Исходный код плагина Enconvo нужно собрать, прежде чем он заработает, поэтому диалог вместо этого даёт вам команду `enconvo plugin install` для запуска в Терминале.

## Из чата

Когда вы просите агента Enconvo о том, чего ваши плагины не умеют, он может поискать плагин в маркетплейсах плагинов на вашем Mac: в тех, что вы добавили в Enconvo, и в тех, что есть в Codex или Claude Code, но которых ещё нет в Enconvo, включая маркетплейс OpenAI Curated, который поставляется с Codex (смотрите [Маркетплейсы, добавленные в Codex или Claude Code](#маркетплейсы-добавленные-в-codex-или-claude-code)). Он читает уже имеющиеся на вашем Mac копии их каталогов и ничего не скачивает во время поиска. Он пропускает плагины, которые вы уже установили, и плагины с именем, как у установленного вами из другого места.

Когда он находит плагин, агент показывает в чате карточку, и ничего не устанавливается, пока вы не нажмёте **Установить**:

- Для маркетплейса, добавленного вами в Enconvo, на карточке указано, какие серверы MCP плагин запускает на вашем Mac или к каким подключается, его навыки и другие нужные ему плагины.
- Для маркетплейса, который есть только в Codex или Claude Code, на карточке сказано, что установка добавляет этот маркетплейс в Enconvo. До этого Enconvo не может прочитать содержимое плагина, поэтому карточка не может его перечислить.

В любом случае хуки плагина остаются выключенными, пока вы не включите их в разделе **Плагины**. Когда плагин нельзя установить, например потому что нельзя установить нужный ему плагин, агент сообщает об этом вместо показа карточки.

### Плагины из ChatGPT

Плагины из [каталога плагинов ChatGPT](https://chatgpt.com/plugins) нельзя установить в Enconvo. Большинство из них — приложения ChatGPT, которые работают только внутри ChatGPT, а остальные OpenAI предоставляет только ChatGPT и Codex. Если вы вошли в Codex на своём Mac, агент знает каталог по копии, которую хранит Codex. Когда вы называете один из его плагинов или вставляете ссылку chatgpt.com на него, агент объясняет, почему не может его установить, и предлагает то, что делает то же самое: Коннектор, сервер MCP, навык или плагин с тем же именем в одном из ваших маркетплейсов. У многих плагинов каталога, которые поставляются с файлами, есть плагин с тем же именем в OpenAI Curated — маркетплейсе, который поставляется с Codex (публичный репозиторий OpenAI `openai/plugins`). Агент предлагает этот плагин, а его установка добавляет OpenAI Curated в Enconvo. Enconvo не загружает приложения ChatGPT, которые входят в эти плагины, а только их навыки и серверы MCP.

Ссылка chatgpt.com не работает и в **Добавить из GitHub**; диалог сообщает то же самое.

## Из командной строки

`plugin install` берёт плагин из GitHub, git, npm, zip в интернете, папки или маркетплейса. Должен быть запущен Enconvo 2.5.6 или новее.

```sh
npx -p @enconvo/api enconvo plugin install <source>
```

| Источник | Пример |
|---|---|
| Репозиторий GitHub, при необходимости с папкой в нём и веткой, тегом или коммитом | `acme/notes`, `acme/plugins/notes@v1.2.0` |
| Адрес GitHub | `https://github.com/acme/plugins/tree/main/notes` |
| Любой другой репозиторий git по https (нужен git); адрес ssh работает только для GitHub | `https://git.example.com/notes.git`, `git@github.com:acme/notes.git` |
| Пакет npm | `npm:@acme/notes-plugin`, `npm:@acme/notes-plugin@1.2.0` |
| Zip плагина в интернете (только публичный https) | `https://downloads.acme.com/notes-1.2.0.zip` |
| Папка на вашем Mac | `./notes`, `~/code/notes`, `/Users/ada/notes` |
| Плагин из добавленного маркетплейса | `notes@acme-plugins` |

<Note>
Для `plugin install` и `plugin marketplace` нужен выпуск `@enconvo/api` новее 0.1.174. Внутри проекта, который зависит от `@enconvo/api`, достаточно `npx enconvo …`. Для `marketplace import` также нужен Enconvo 2.5.7 или новее.
</Note>

Добавьте `--preview`, чтобы увидеть, что и откуда было бы установлено, ничего не устанавливая.

Если источник — маркетплейс плагинов, а не плагин, `plugin install` перечисляет его плагины. Если в маркетплейсе больше 200 плагинов, перечисляются первые 200 и сообщается, сколько ещё осталось; `plugin marketplace add` перечисляет все. Выберите один через `--plugin`, что также добавляет маркетплейс:

```sh
npx -p @enconvo/api enconvo plugin install acme/plugins --plugin notes
```

### Что происходит при установке

- **Настройки**: плагин с обязательными настройками, например ключом API, устанавливается, а затем запрашивает их. `plugin install` называет их; заполните их на странице плагина.
- **Плагины Enconvo из исходного кода**: когда в репозитории GitHub или папке есть не собранный плагин Enconvo, `plugin install` сначала собирает его. Папка собирается на месте, после `npm install`.
- **Знакомство**: когда плагин называет навык знакомства, Enconvo предлагает запустить его после первой установки.
- **Вход**: когда серверам MCP плагина требуется ваш вход, как у Notion или Figma, страница плагинов показывает **Войти** сразу после установки. Enconvo открывает страницу входа сервера в вашем браузере и предлагает следующий сервер, когда этот подключён. `plugin install` вместо этого называет серверы. Пропущенный вход ждёт в **Настройки → Серверы MCP**.
- **Хуки**: [хуки](/extensions/plugin-formats#hooks) плагина устанавливаются выключенными, потому что они запускают команды. `--preview` перечисляет их; разрешите их переключателем **Разрешить хуки** на странице плагина. Разрешённые вами хуки остаются включёнными при обновлениях, которые их не меняют.
- **Зависимости**: когда плагину Claude Code из маркетплейса нужны другие плагины, Enconvo устанавливает их вместе с ним (смотрите [Маркетплейсы плагинов](#маркетплейсы-плагинов)). `--preview` перечисляет их и сообщает, какие уже установлены, какие были бы установлены и какие установить нельзя. Зависимость, которую запись маркетплейса объявляет из неразрешённого маркетплейса, останавливает установку; зависимость, объявленная в собственном `plugin.json` плагина, пропускается, и установка продолжается. Их хуки остаются выключенными, а удаление плагина сохраняет их, пока вы их не очистите (смотрите [Удаление](#удаление)).
- **Использование**: как в Codex, введите `@` в чате и выберите плагин или нажмите один из промптов в разделе **Попробуйте спросить** на его странице. В обоих случаях к чату прикрепляется плагин. Каждый установленный плагин есть в меню `@`, включая плагин Codex или Claude Code без категории.
- **Одно и то же имя**: повторная установка из того же источника обновляет плагин. Если плагин с таким именем уже установлен из другого места, например из магазина, Enconvo оставляет его и просит сначала его удалить.

Когда Enconvo не запущен, `plugin install` всё равно может установить плагин Enconvo из GitHub, собрав его. Для всего остального откройте Enconvo и повторите попытку.

## Маркетплейсы плагинов

Маркетплейс — это каталог плагинов в репозитории или папке. Enconvo читает оба вида: `.agents/plugins/marketplace.json` Codex и `.claude-plugin/marketplace.json` Claude Code.

```sh
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins   # GitHub, a git address or a folder
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins --ref v2   # at a branch, tag or commit
npx -p @enconvo/api enconvo plugin marketplace list               # added marketplaces and their plugins
npx -p @enconvo/api enconvo plugin install notes@acme-plugins     # install one of them
npx -p @enconvo/api enconvo plugin marketplace refresh            # fetch them again for new plugins
npx -p @enconvo/api enconvo plugin marketplace remove acme-plugins
```

`refresh` также откликается на `upgrade` (название в Codex) и `update` (название в Claude Code), а `--ref v2` — то же самое, что `acme/plugins@v2`.

На странице плагинов откройте **Добавить → Добавить из GitHub…** и вставьте адрес маркетплейса или выберите добавленный вами в разделе **Ваши маркетплейсы**.

Enconvo хранит копию маркетплейса из GitHub или git, а маркетплейс-папку читает там, где она лежит. Удаление маркетплейса сохраняет плагины, которые вы из него установили.

### Маркетплейсы, добавленные в Codex или Claude Code

Если вы добавляли маркетплейсы в Codex или Claude Code на этом Mac или Codex загрузил свой маркетплейс OpenAI Curated, `marketplace list` показывает те, которых в Enconvo ещё нет, а `import` добавляет их, так что вводить их адреса заново не нужно:

```sh
npx -p @enconvo/api enconvo plugin marketplace import                            # all of them
npx -p @enconvo/api enconvo plugin marketplace import claude-plugins-official    # only these
```

Enconvo находит их в `~/.codex/config.toml` Codex, в его копии OpenAI Curated и в личном `~/.agents/plugins/marketplace.json`, а также в списке известных маркетплейсов Claude Code. Он только читает эти файлы и ничего не меняет ни в одном из приложений. OpenAI Curated добавляется из `openai/plugins` на GitHub. Он пропускает другие маркетплейсы, которые поставляются с Codex и содержат плагины для собственных инструментов Codex, а также маркетплейсы Claude Code, добавленные по веб-адресу файла `marketplace.json`, которые Enconvo не добавляет. Если в обоих приложениях есть маркетплейс с одним именем, он предлагает вариант из Codex.

Маркетплейсы Codex, такие как OpenAI Curated, перечисляют только имя каждого плагина и откуда он берётся. Для плагина в собственной папке маркетплейса Enconvo показывает название, описание, категорию и разработчика из манифеста плагина, как и Codex, а агент находит его и по тому, что он делает, и по имени. То, что запись маркетплейса сообщает сама, имеет приоритет.

Некоторые плагины OpenAI Curated, такие как Gmail, Google Drive, Outlook и Teams, работают только при входе в Codex через ChatGPT, поэтому Codex не предлагает их тем, кто входит с ключом API. Enconvo тоже не выполняет вход в ChatGPT, поэтому показывает их как требующие входа в ChatGPT, не устанавливает их, и агент их не предлагает. Для этих сервисов добавьте собственный сервер MCP провайдера или Коннектор.

### Откуда берутся плагины маркетплейса

Плагины маркетплейса могут быть из папки в маркетплейсе, другого репозитория GitHub, адреса git, папки в репозитории git, npm или zip в интернете (источник `archive` в Claude Code). Плагин, который маркетплейс Codex помечает как `NOT_AVAILABLE`, установить нельзя.

Источник-папка, записанный как `./plugins/notes`, читается от корня маркетплейса. Простое имя, такое как `notes`, читается из папки, которую называет `metadata.pluginRoot`, как в Claude Code, и для этого нужно это поле.

Скачивание из GitHub, npm или интернета может занять до трёх минут; если оно длится дольше, Enconvo останавливает его и просит проверить подключение.

Zip, будь то вставленная вами ссылка или перечисленная маркетплейсом, скачивается только с публичного адреса https, не более чем через пять перенаправлений. Когда маркетплейс указывает `sha256`, скачивание, которое не совпадает, отклоняется. Плагин может лежать в корне zip или внутри одной папки.

### Записи маркетплейса Claude Code

Записи маркетплейса Claude Code работают с собственным `plugin.json` плагина так, как их читает Claude Code:

- Запись может добавить `commands`, `agents`, `skills`, `outputStyles` и `themes` к собственным элементам плагина, а её `hooks` заменяют хуки плагина для тех же событий.
- Запись с `"strict": false`, которая также перечисляет что-либо из этого, для плагина с `plugin.json` отклоняется как конфликтующие манифесты. Держите их в одном месте.
- Если у плагина нет `plugin.json`, манифестом служит запись.
- Показываются название, описание, автор и другие сведения записи для списка; версия берётся из плагина.
- `renames` маркетплейса учитываются. Плагин, установленный под старым именем, продолжает обновляться под новым, а установка по старому имени его находит. Имя, переименованное в `null`, удалено из маркетплейса, и Enconvo сообщает об этом. Если собственный манифест плагина тоже сменил имя, Enconvo просит удалить старый плагин и установить новый, потому что Enconvo называет плагин по его манифесту.
- `dependencies` плагина, в его записи или в его `plugin.json`, устанавливаются вместе с ним. Каждая зависимость — это имя (`"formatter"`), имя и маркетплейс (`"formatter@acme-tools"`), любое из них с диапазоном `^` (`"formatter@acme-tools@^2.1"`) или `{ "name", "marketplace", "version" }` с диапазоном semver. Зависимость берётся из маркетплейса самого плагина, если не названо другое, а другой маркетплейс должен быть указан в `allowCrossMarketplaceDependenciesOn` маркетплейса, из которого вы устанавливали. Зависимость с диапазоном `version` устанавливается по самому высокому тегу выпуска (`<plugin>--v<version>`) в этом диапазоне и в диапазонах, которые накладывают на неё другие установленные плагины, из собственного репозитория плагина или, для плагина внутри маркетплейса, из репозитория маркетплейса (папка маркетплейса считается, если она в репозитории git). Если такого тега нет, плагин внутри маркетплейса устанавливается таким, каким он есть в маркетплейсе, а плагин в собственном репозитории отклоняется. Диапазоны, которым не удовлетворяет ни одна версия, отклоняют установку, а обновления остаются внутри диапазонов. Уже установленная зависимость остаётся как есть, а зависимость вне своего диапазона `version` получает предупреждение.

### Проверьте маркетплейс, прежде чем делиться им

Прежде чем делиться маркетплейсом, проверьте его и каждый плагин в нём. Правила те же, что применяет `claude plugin validate`, плюс правила Codex для `.agents/plugins/marketplace.json`; смотрите [Коды проверки](/extensions/validation-codes#marketplaces). Ошибка означает, что Claude Code не может добавить маркетплейс или установить плагин, хотя может всё ещё его перечислять: поле неверного типа в записи, `renames`, которые не ведут к плагину, сигналы `relevance`, которые он отклоняет, или имя маркетплейса, похожее на собственное имя Anthropic, например `claude-plugins-hub`. Предупреждение касается того, что Claude Code игнорирует, например опечатки в поле, и имён, которые отклоняет Claude Desktop.

```sh
npx -p @enconvo/api enconvo plugin validate path/to/marketplace
```

## Обновления

Проверка обновлений плагинов Enconvo охватывает также плагины, установленные из GitHub, git, npm, папок и маркетплейсов, и перечисляет их обновления вместе с обновлениями из магазина. Она читает последний коммит репозитория, не скачивая его, спрашивает у npm последнюю версию, замечает изменение установленной папки, а для zip, который маркетплейс закрепляет по `sha256`, замечает изменение закрепления. Обновление устанавливает плагин заново из того же источника.

Чтобы проверить один плагин, откройте его страницу и выберите **Проверить обновления** в меню **⋯**. Если есть более новая версия, нажмите **Обновить** в появившемся сообщении.

Или обновите один плагин из Терминала, как это делает `claude plugin update` в Claude Code:

```bash
npx -p @enconvo/api enconvo plugin update notes                # from wherever it came from, or the store
npx -p @enconvo/api enconvo plugin update notes@acme-plugins   # only if it came from that marketplace
```

Сначала выполняется проверка. Если ничего более нового нет, сообщается, что плагин уже последней версии, и ничего не меняется; иначе плагин обновляется так же, как из списка обновлений.

## Удаление

Удалите плагин из его меню или со страницы плагинов, где сначала просят подтвердить, или из Терминала:

```bash
npx -p @enconvo/api enconvo plugin uninstall notes            # also: remove, rm
npx -p @enconvo/api enconvo plugin uninstall notes --prune    # and the dependencies nothing needs any more
npx -p @enconvo/api enconvo plugin prune --dry-run            # list them without removing anything
npx -p @enconvo/api enconvo plugin prune                      # remove them (also: autoremove)
```

Очистка удаляет только плагины, установленные потому, что их требовал другой плагин, когда ни одному установленному плагину они больше не нужны, как это делает `claude plugin prune` в Claude Code. Плагин, который вы установили сами, никогда не очищается, а повторная установка зависимости вручную делает её вашей. В Терминале Enconvo перечисляет, что он удалит, и сначала спрашивает; добавьте `-y`, чтобы пропустить вопрос, который нужен `--prune`, когда спросить нельзя. Удаление на странице плагинов пока не выполняет очистку.

## Опубликуйте свой плагин

Чтобы разместить плагин в магазине Enconvo, смотрите [Правила магазина плагинов](/ru/extensions/publishing-guidelines). Чтобы отправить ссылку, по которой любой может установить плагин, нажмите **Поделиться…** на странице плагина; смотрите раздел «Как поделиться плагином» на странице [Плагины](/ru/extensions/overview). Чтобы поделиться им без Enconvo, отправьте его на GitHub или в маркетплейс, и люди смогут установить его через **Добавить из GitHub…** или командами выше.

### Пометка релиза тегом

`plugin tag` помечает коммит, который вы выпускаете, тегом git с именем `<plugin>--v<version>`, как это делает `claude plugin tag`. Claude Code и Enconvo выбирают среди этих тегов, когда зависимость другого плагина запрашивает диапазон версий, и любой может установить этот выпуск через Enconvo, например `acme/plugins/notes@notes--v1.2.0`.

```sh
npx -p @enconvo/api enconvo plugin tag plugins/notes --dry-run   # check, and print the git commands
npx -p @enconvo/api enconvo plugin tag plugins/notes --push      # tag HEAD and push the tag to origin
```

Версия берётся из манифеста плагина или из его записи в маркетплейсе, если в манифесте её нет, и должна быть в формате semver (`1.2.0`). Перед пометкой тегом `plugin tag` проверяет плагин так же, как `plugin validate`, и останавливается, если запись маркетплейса называет другую версию, если файлы в папке плагина не закоммичены или если тег уже существует. Повышайте версию для нового выпуска; `--force` вместо этого переносит существующий тег. Он помечает плагины Codex, Claude Code, переносимые и Enconvo одинаково, поэтому каждый манифест, который несёт пакет, должен называть одну и ту же версию. `-m` задаёт сообщение тега (`%s` — версия), а `--remote` — удалённый репозиторий, в который отправляет `--push`. Как и для `plugin install`, нужен выпуск `@enconvo/api` новее 0.1.174.
