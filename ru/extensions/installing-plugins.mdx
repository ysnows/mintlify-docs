Большинство устанавливает плагины из магазина на странице **Плагины** Enconvo. Enconvo также устанавливает плагины из других мест, включая плагины Codex и Claude Code, которые их разработчики публикуют на GitHub и в маркетплейсах. Пакеты, которые читает Enconvo, — в [Форматах плагинов](/extensions/plugin-formats).

Чтобы установить из приложения, читайте разделы «Со страницы Плагины» и «Из чата». Остальное — для разработчиков и опытных пользователей: установка из Terminal, добавление маркетплейсов, обновление и удаление и публикация своего плагина.

<Warning>
Enconvo проверяет только плагины магазина Enconvo. Плагин откуда угодно ещё может запускать программы на Mac через свои MCP-серверы, поэтому устанавливайте его только из источника, которому доверяете.
</Warning>

## Со страницы Плагины

Нажмите **Add** на странице **Плагины**:

| Вариант | Что делает |
|---|---|
| **Create plugin** | Начинает чат, в котором агент Enconvo собирает плагин вместе с вами. |
| **Upload plugin archive…** | Устанавливает файл: пакет `.enconvo`, расширение рабочего стола `.dxt` или `.zip` плагина Claude Code или Codex. |
| **Add from GitHub…** | Устанавливает плагин или один из маркетплейса с GitHub, git, npm или из папки (см. ниже). |
| **Add MCP server…** | Открывает настройки MCP, чтобы подключить один сервер без плагина вокруг него. |
| **Add PopBar extension…** | Устанавливает расширение PopBar по ссылке, из файла или сниппета `#popclip` (см. [Расширения PopBar](/ru/features/popbar)). |
| **New skill…** | Открывает настройки Навыков, чтобы написать свой навык. |
| **Developer guide** | Открывает [Разработку расширений](/ru/extensions/developing). |

То, что вы добавили, — в **Installed** вверху вкладки **Enconvo**: Коннекторы, которые вы подключили, и плагины, которые установили или сделали, по имени. Нажмите **Installed**, чтобы увидеть все. Плагины, которые идут с Enconvo, там не перечислены. У расширений PopBar своя вкладка **PopBar**, с проверенным каталогом Enconvo; см. [Расширения PopBar](/ru/features/popbar).

### Добавьте с GitHub

Вставьте, где лежит плагин, и нажмите **Preview**:

- `owner/repo` или ссылка GitHub, включая ссылку на папку (`/tree/<branch>/<folder>`)
- `owner/repo/folder` для плагина внутри репозитория, с `@branch` или `@tag`, чтобы закрепить версию
- любой адрес git https
- `npm:<package>`, с `@version`, чтобы закрепить одну
- ссылка https на `.zip` плагина
- папка на Mac

Частный репозиторий GitHub или git тоже работает. Enconvo использует учетную запись GitHub, уже вошедшую на Mac, или ключ SSH, поэтому пароль вводить не нужно.

Enconvo показывает плагин до установки чего-либо: формат (Codex, Claude Code, portable, desktop extension или Enconvo), версию, разработчика, навыки, MCP-серверы и хуки и любые приложения ChatGPT, которые он включает и которые Enconvo не загружает. Для каждого MCP-сервера он говорит, запускается ли тот на Mac или подключается через интернет. Хуки плагина запускают команды на Mac, поэтому остаются выключенными, пока вы не отметите **Allow its hooks to run**. Нажмите **Install**, и Enconvo открывает страницу плагина. Строка **Source** говорит, откуда пришёл плагин (для GitHub и git — с коммитом) и ссылается на репозиторий или страницу npm, а заметка внизу называет разработчика, которого указывает плагин: только собственные плагины Enconvo и плагины его магазина говорят, что сделаны Enconvo. Плагины, установленные так, перечислены в **Personal**. Повторная установка из того же места обновляет плагин. Если плагин с тем же именем уже установлен откуда-то ещё, сначала удалите его.

Когда адрес — маркетплейс плагинов, диалог перечисляет его плагины с кнопкой **Install** у каждого. Установка одного добавляет маркетплейс, который затем показывается в **Your marketplaces** при следующем открытии диалога.

Исходный код плагина Enconvo нужно собрать, прежде чем он заработает, поэтому диалог даёт команду `enconvo plugin install`, которую нужно выполнить в Terminal.

## Из чата

Когда вы просите агента Enconvo о том, чего ваши плагины не умеют, он может искать плагин в маркетплейсах на Mac: тех, что вы добавили в Enconvo, и тех, что есть у Codex или Claude Code, а у Enconvo ещё нет, включая OpenAI Curated, который идёт с Codex (см. раздел «Маркетплейсы, добавленные в Codex или Claude Code»). Он читает копии их каталогов, уже лежащие на Mac, и ничего не скачивает, пока ищет. Он пропускает установленные плагины и плагины, названные как тот, что вы установили откуда-то ещё.

Когда находит, агент показывает карточку в чате, и ничего не устанавливается, пока вы не нажмёте **Install**:

- Из маркетплейса, добавленного в Enconvo, карточка говорит, какие MCP-серверы плагин запускает на Mac или к каким подключается, его навыки и другие нужные плагины.
- Из маркетплейса, который есть только у Codex или Claude Code, карточка говорит, что установка добавляет этот маркетплейс в Enconvo. До этого Enconvo не может прочитать содержимое плагина, поэтому карточка не может его перечислить.

В любом случае хуки плагина остаются выключенными, пока вы не включите их в **Плагины**. Когда плагин нельзя установить, например потому что нужный ему плагин нельзя, агент говорит об этом вместо карточки.

### Плагины из ChatGPT

Плагины из [каталога плагинов ChatGPT](https://chatgpt.com/plugins) нельзя установить в Enconvo. Большинство — приложения ChatGPT, которые работают только внутри ChatGPT, а остальные OpenAI отдаёт только ChatGPT и Codex. Если вы вошли в Codex на Mac, агент знает каталог по копии, которую хранит Codex. Когда вы называете один из его плагинов или вставляете ссылку chatgpt.com, агент объясняет, почему не может установить, и предлагает то, что делает то же: Коннектор, MCP-сервер, навык или плагин с тем же именем в одном из ваших маркетплейсов. У многих плагинов каталога, которые идут с файлами, есть плагин с тем же именем в OpenAI Curated, маркетплейсе, который идёт с Codex (публичный репозиторий OpenAI `openai/plugins`). Агент предлагает этот плагин, и его установка добавляет OpenAI Curated в Enconvo. Enconvo не загружает приложения ChatGPT, которые включают эти плагины, только их навыки и MCP-серверы.

Ссылка chatgpt.com не работает и в **Add from GitHub**; диалог говорит то же.

## Из командной строки

`plugin install` берёт плагин с GitHub, git, npm, zip в вебе, из папки или маркетплейса. Должен быть запущен Enconvo 2.5.6 или новее.

```sh
npx -p @enconvo/api enconvo plugin install <source>
```

| Источник | Пример |
|---|---|
| Репозиторий GitHub, по желанию папка в нём и ветка, тег или коммит | `acme/notes`, `acme/plugins/notes@v1.2.0` |
| Адрес GitHub | `https://github.com/acme/plugins/tree/main/notes` |
| Любой другой репозиторий git по https (нужен git); адрес ssh работает только для GitHub | `https://git.example.com/notes.git`, `git@github.com:acme/notes.git` |
| Пакет npm | `npm:@acme/notes-plugin`, `npm:@acme/notes-plugin@1.2.0` |
| Zip плагина в вебе (только публичный https) | `https://downloads.acme.com/notes-1.2.0.zip` |
| Папка на Mac | `./notes`, `~/code/notes`, `/Users/ada/notes` |
| Плагин в добавленном маркетплейсе | `notes@acme-plugins` |

<Note>
`plugin install` и `plugin marketplace` нужен выпуск `@enconvo/api` новее 0.1.174. Внутри проекта, который зависит от `@enconvo/api`, достаточно `npx enconvo …`. `marketplace import` также нужен Enconvo 2.5.7 или новее.
</Note>

Добавьте `--preview`, чтобы увидеть, что было бы установлено и откуда, без установки.

Когда источник — маркетплейс, а не плагин, `plugin install` перечисляет его плагины. Маркетплейс больше чем из 200 перечисляет первые 200 и говорит, сколько ещё; `plugin marketplace add` перечисляет все. Выберите один через `--plugin`, что также добавляет маркетплейс:

```sh
npx -p @enconvo/api enconvo plugin install acme/plugins --plugin notes
```

### Что происходит при установке

- **Настройки**: плагин с обязательными настройками, например API-ключом, устанавливается, а затем спрашивает их. `plugin install` называет их; заполните на странице плагина.
- **Плагины Enconvo из исходников**: когда репозиторий GitHub или папка держит плагин Enconvo, который не собран, `plugin install` сначала собирает его. Папка собирается на месте, после `npm install`.
- **Онбординг**: когда плагин называет навык онбординга, Enconvo предлагает запустить его после первой установки.
- **Вход**: когда MCP-серверам плагина нужно, чтобы вы вошли, как у Notion или Figma, страница Плагины показывает **Sign in**, как только он устанавливается. Enconvo открывает страницу входа сервера в браузере и предлагает следующий сервер, как только этот подключится. `plugin install` вместо этого называет серверы. Пропущенный вход ждёт в **Настройки → MCP Servers**.
- **Хуки**: [хуки](/extensions/plugin-formats#hooks) плагина устанавливаются выключенными, потому что запускают команды. `--preview` перечисляет их; разрешите переключателем **Allow hooks** на странице плагина. Разрешённые хуки остаются включёнными через обновления, которые их не меняют.
- **Зависимости**: когда плагину Claude Code из маркетплейса нужны другие плагины, Enconvo устанавливает их вместе с ним (см. раздел «Маркетплейсы плагинов»). `--preview` перечисляет их и говорит, какие уже установлены, какие установятся и какие нельзя. Зависимость, которую запись маркетплейса объявляет из неразрешённого маркетплейса, останавливает установку; та, что объявляет собственный `plugin.json` плагина, пропускается, и установка продолжается. Их хуки остаются выключенными, а удаление плагина держит их, пока вы их не подчистите (см. раздел «Удаление»).
- **Использование**: как в Codex, наберите `@` в чате и выберите плагин или нажмите одну из подсказок в **Try asking** на его странице. В любом случае чат получает прикреплённый плагин. Каждый установленный плагин есть в меню `@`, включая плагин Codex или Claude Code, который не называет категорию.
- **То же имя**: повторная установка из того же источника обновляет плагин. Если плагин с тем же именем уже установлен откуда-то ещё, например из магазина, Enconvo его не трогает и просит сначала удалить.

Когда Enconvo не запущен, `plugin install` всё ещё может установить плагин Enconvo с GitHub, собрав его. Для всего остального откройте Enconvo и попробуйте снова.

## Маркетплейсы плагинов

Маркетплейс — каталог плагинов в репозитории или папке. Enconvo читает оба вида: `.agents/plugins/marketplace.json` Codex и `.claude-plugin/marketplace.json` Claude Code.

```sh
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins   # GitHub, a git address or a folder
npx -p @enconvo/api enconvo plugin marketplace add acme/plugins --ref v2   # at a branch, tag or commit
npx -p @enconvo/api enconvo plugin marketplace list               # added marketplaces and their plugins
npx -p @enconvo/api enconvo plugin install notes@acme-plugins     # install one of them
npx -p @enconvo/api enconvo plugin marketplace refresh            # fetch them again for new plugins
npx -p @enconvo/api enconvo plugin marketplace remove acme-plugins
```

`refresh` также отвечает на `upgrade` (имя Codex) и `update` (имя Claude Code), а `--ref v2` — то же, что `acme/plugins@v2`.

На странице Плагины откройте **Add → Add from GitHub…** и вставьте адрес маркетплейса или выберите добавленный в **Your marketplaces**.

Enconvo хранит копию маркетплейса с GitHub или git и читает папочный маркетплейс там, где он лежит. Удаление маркетплейса сохраняет плагины, которые вы из него установили.

### Маркетплейсы, добавленные в Codex или Claude Code

Если вы добавили маркетплейсы в Codex или Claude Code на этом Mac или Codex уже получил свой OpenAI Curated, `marketplace list` показывает те, которых у Enconvo ещё нет, а `import` их добавляет, чтобы не набирать адреса снова:

```sh
npx -p @enconvo/api enconvo plugin marketplace import                            # all of them
npx -p @enconvo/api enconvo plugin marketplace import claude-plugins-official    # only these
```

Enconvo находит их в `~/.codex/config.toml` Codex, его копии OpenAI Curated и личном `~/.agents/plugins/marketplace.json`, а также в списке известных маркетплейсов Claude Code. Он только читает эти файлы и ничего не меняет ни в одном приложении. OpenAI Curated добавляется из `openai/plugins` на GitHub. Он пропускает другие маркетплейсы, которые идут с Codex и держат плагины для собственных инструментов Codex, и маркетплейсы Claude Code, добавленные с веб-адреса файла `marketplace.json`, которые Enconvo не добавляет. Когда у обоих приложений маркетплейс с одним именем, он предлагает Codex.

Маркетплейсы Codex, такие как OpenAI Curated, перечисляют только имя каждого плагина и откуда он. Для плагина в собственной папке маркетплейса Enconvo показывает заголовок, описание, категорию и разработчика из манифеста плагина, как Codex, и агент находит его и по тому, что он делает, и по имени. То, что говорит сама запись маркетплейса, идёт первым.

Некоторые плагины OpenAI Curated, такие как Gmail, Google Drive, Outlook и Teams, работают, только когда вы входите в Codex через ChatGPT, поэтому Codex не предлагает их тем, кто входит API-ключом. Enconvo тоже не входит в ChatGPT, поэтому показывает их как требующие входа ChatGPT, не устанавливает их, и агент их не предлагает. Для этих служб добавьте собственный MCP-сервер провайдера или Коннектор.

### Откуда берутся плагины маркетплейса

Плагины маркетплейса могут приходить из папки в маркетплейсе, другого репозитория GitHub, адреса git, папки в репозитории git, npm или zip в вебе (источник `archive` Claude Code). Плагин, который маркетплейс Codex помечает `NOT_AVAILABLE`, установить нельзя.

Источник папки, записанный как `./plugins/notes`, читается от верха маркетплейса. Голое имя вроде `notes` читается из папки, которую называет `metadata.pluginRoot`, как в Claude Code, и нуждается в этом поле.

Загрузка с GitHub, npm или веба может занять до трёх минут; если дольше, Enconvo останавливает её и просит проверить соединение.

Zip, вставляете ли вы ссылку или его перечисляет маркетплейс, скачивается только с публичного адреса https, не больше чем через пять перенаправлений. Когда маркетплейс даёт его `sha256`, загрузка, которая не совпадает, отклоняется. Плагин может лежать в корне zip или внутри одной папки.

### Записи маркетплейса Claude Code

Записи маркетплейса Claude Code работают с собственным `plugin.json` плагина так, как их читает Claude Code:

- Запись может добавить `commands`, `agents`, `skills`, `outputStyles` и `themes` к собственным плагина, а её `hooks` заменяют хуки плагина для тех же событий.
- Запись с `"strict": false`, которая также перечисляет любое из этого, над плагином с `plugin.json`, отклоняется как конфликтующие манифесты. Держите их в одном месте.
- Когда у плагина нет `plugin.json`, запись — его манифест.
- Показываются имя, описание, автор и другие данные записи; версия — плагина.
- Следуют `renames` маркетплейса. Плагин, установленный под старым именем, продолжает обновляться под новым, и установка по старому имени его находит. Имя, переименованное в `null`, удалено из маркетплейса, и Enconvo об этом говорит. Если собственный манифест плагина тоже сменил имя, Enconvo просит удалить старый плагин и установить новый, потому что Enconvo называет плагин по манифесту.
- `dependencies` плагина, в записи или в `plugin.json`, устанавливаются вместе с ним. Каждый — имя (`"formatter"`), имя и маркетплейс (`"formatter@acme-tools"`), любое из них с диапазоном `^` (`"formatter@acme-tools@^2.1"`) или `{ "name", "marketplace", "version" }` с диапазоном semver. Зависимость приходит из собственного маркетплейса плагина, если не называет другой, а другой маркетплейс должен быть перечислен в `allowCrossMarketplaceDependenciesOn` маркетплейса, из которого вы установили. Зависимость с диапазоном `version` устанавливается на высшем теге выпуска (`<plugin>--v<version>`) в этом диапазоне и в диапазонах, которые на неё ставят другие установленные плагины, из собственного репозитория плагина или, для плагина внутри маркетплейса, из репозитория маркетплейса (папка маркетплейса считается, когда она в репозитории git). Без такого тега плагин внутри маркетплейса устанавливается как есть у маркетплейса, а плагин в собственном репозитории отклоняется. Диапазоны, которым не удовлетворяет ни одна версия, отклоняют установку, и обновления остаются внутри диапазонов. Уже установленная зависимость остаётся как есть, а та, что вне диапазона `version`, получает предупреждение.

### Проверьте маркетплейс, прежде чем делиться

Прежде чем делиться маркетплейсом, проверьте его и каждый плагин в нём. Правила — те, что применяет `claude plugin validate`, плюс правила Codex для `.agents/plugins/marketplace.json`; см. [Коды проверки](/extensions/validation-codes#marketplaces). Ошибка значит, что Claude Code не может добавить маркетплейс или установить плагин, даже если всё ещё может его перечислить: поле неверного типа в записи, `renames`, которые не ведут к плагину, сигналы `relevance`, которые он отклоняет, или имя маркетплейса, похожее на одно из собственных Anthropic, например `claude-plugins-hub`. Предупреждение покрывает то, что Claude Code игнорирует, например поле с опечаткой, и имена, которые отклоняет Claude Desktop.

```sh
npx -p @enconvo/api enconvo plugin validate path/to/marketplace
```

## Обновления

Проверка обновлений плагинов Enconvo также покрывает плагины, установленные с GitHub, git, npm, из папок и маркетплейсов, и перечисляет их обновления вместе с магазинными. Она читает последний коммит репозитория, не скачивая его, спрашивает npm о последней версии, замечает, когда установленная папка изменилась, и для zip, который маркетплейс закрепляет по `sha256`, замечает, когда закрепление меняется. Обновление устанавливает плагин снова из того же источника.

Чтобы проверить один плагин, откройте его страницу и выберите **Check for updates** в меню **⋯**. Когда есть более новая версия, нажмите **Update** в появившемся сообщении.

Или обновите один из Terminal, как `claude plugin update` в Claude Code:

```bash
npx -p @enconvo/api enconvo plugin update notes                # from wherever it came from, or the store
npx -p @enconvo/api enconvo plugin update notes@acme-plugins   # only if it came from that marketplace
```

Сначала он проверяет. Когда ничего новее нет, говорит, что плагин уже на последней версии, и ничего не меняет; иначе обновляет плагин так же, как список обновлений.

## Удаление

Удалите плагин из его меню или со страницы на странице Плагины, которая сначала просит подтвердить, или из Terminal:

```bash
npx -p @enconvo/api enconvo plugin uninstall notes            # also: remove, rm
npx -p @enconvo/api enconvo plugin uninstall notes --prune    # and the dependencies nothing needs any more
npx -p @enconvo/api enconvo plugin prune --dry-run            # list them without removing anything
npx -p @enconvo/api enconvo plugin prune                      # remove them (also: autoremove)
```

Подчистка удаляет только плагины, установленные потому, что другой плагин в них нуждался, когда ни один установленный плагин в них больше не нуждается, как `claude plugin prune` в Claude Code. Плагин, который вы установили сами, никогда не подчищается, а повторная установка зависимости самими делает её вашей. В Terminal Enconvo перечисляет, что удалит, и сначала спрашивает; добавьте `-y`, чтобы пропустить вопрос, что нужно `--prune`, когда спросить нельзя. Удаление на странице Плагины пока не подчищает.

## Опубликуйте свой

Чтобы поместить плагин в магазин Enconvo, см. [Правила магазина плагинов](/ru/extensions/publishing-guidelines). Чтобы отправить ссылку, которую может установить кто угодно, нажмите **Share…** на странице плагина; см. [Поделиться плагином](/ru/extensions/overview). Чтобы поделиться без Enconvo, отправьте его на GitHub или в маркетплейс, и люди смогут установить его через **Add from GitHub…** или команды выше.

### Пометьте выпуск

`plugin tag` помечает коммит, который вы выпускаете, git-тегом `<plugin>--v<version>`, как `claude plugin tag`. Claude Code и Enconvo выбирают среди этих тегов, когда зависимость другого плагина просит диапазон версий, и кто угодно может установить этот выпуск через Enconvo, например `acme/plugins/notes@notes--v1.2.0`.

```sh
npx -p @enconvo/api enconvo plugin tag plugins/notes --dry-run   # check, and print the git commands
npx -p @enconvo/api enconvo plugin tag plugins/notes --push      # tag HEAD and push the tag to origin
```

Версия берётся из манифеста плагина или из записи маркетплейса, когда в манифесте её нет, и должна быть semver (`1.2.0`). Перед пометкой `plugin tag` проверяет плагин, как `plugin validate`, и останавливается, когда запись маркетплейса называет другую версию, когда файлы в папке плагина не зафиксированы или когда тег существует. Поднимите версию для нового выпуска; `--force` вместо этого двигает существующий тег. Он помечает плагины Codex, Claude Code, portable и Enconvo одинаково, поэтому каждый манифест, который несёт пакет, должен называть одну версию. `-m` задаёт сообщение тега (`%s` — версия), а `--remote` — удалённый, куда пушит `--push`. Как и `plugin install`, ему нужен выпуск `@enconvo/api` новее 0.1.174.
