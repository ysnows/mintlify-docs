Эта страница для разработчиков, которые собираются отправить плагин в магазин плагинов Enconvo. Здесь описано, что проверяют ревьюеры, какие материалы для проверки отправлять с каждой версией, чек-лист перед `plugin publish` и что происходит после отправки.

Enconvo проверяет каждую версию, отправленную в магазин плагинов, прежде чем её сможет установить кто-либо ещё. Эти правила действуют для всех видов плагинов, которые принимает магазин: плагинов Enconvo, Codex, Claude Code и переносимых плагинов, включая плагины, состоящие только из навыков. Они основаны на [правилах OpenAI для плагинов](https://developers.openai.com/apps-sdk/app-submission-guidelines), поэтому плагин, который им соответствует, почти готов и к порталу плагинов OpenAI.

## Сначала проверьте плагин

Перед отправкой выполните:

```sh
npx -p @enconvo/api enconvo plugin validate            # the store's rules
npx -p @enconvo/api enconvo plugin validate --openai   # also OpenAI's portal rules
npx -p @enconvo/api enconvo plugin scan                # starts the MCP server and checks its tools
```

`validate` находит то, что можно проверить автоматически, а `scan` проверяет инструменты плагина с сервером MCP; каждую найденную проблему объясняет страница [Коды проверки](/extensions/validation-codes). Всё остальное ревьюеры проверяют вручную, как описано ниже.

## Назначение и качество

- Плагин делает что-то полезное, чего Enconvo ещё не умеет, и делает это полностью. Заготовки, демонстрационные и пробные версии отклоняются.
- Он ведёт себя предсказуемо. Если что-то идёт не так, например ошибка сети, нехватка разрешения или неверный ввод, он сообщает, что произошло, а не молча завершается ошибкой.
- Он использует только тот код, названия, значки и содержимое, которыми вы владеете или на которые у вас есть лицензия. Он не выдаёт себя за другой продукт и не создаёт впечатления, что его одобряют Enconvo или кто-либо ещё.

## Название, описание и карточка

- **Название и заголовок**: понятные и конкретные. Не используйте общее слово из одного слова и не добавляйте «MCP», «MCP Server» или «Plugin» к названию компании.
- **Описание**: точно говорит, что делает плагин. Без сравнений с другими продуктами, утверждений, которые вы не можете подтвердить, а также цен, скидок и предложений бесплатного пробного периода.
- **Значок и скриншоты**: значок — файл PNG, JPEG, WebP или GIF размером до 5 МБ. До 8 скриншотов кладут в папку `metadata/`, они показываются в порядке имён файлов. На них плагин показан так, как он работает на самом деле.
- **Поддержка**: дайте людям способ связаться с вами: `interface.websiteURL` и `interface.supportURL`, а для сайта можно указать `homepage` или `repository`. Плагин Claude Code может использовать вместо них `supportUrl` и `documentationUrl`. Страница магазина показывает эти ссылки до установки плагина.
- **Версия**: повышайте её при каждом обновлении. Пока обновление на проверке, магазин продолжает предлагать предыдущую версию. `plugin publish` до сборки и загрузки спрашивает у магазина, какую версию он выпустил, и останавливается с подсказкой следующей версии, если ваша не выше.

## Инструменты MCP

Когда плагин содержит сервер MCP, ревьюеры читают его инструменты так, как их будет читать модель ИИ.

- **Имена** — простые глаголы, которые говорят, что делает инструмент, например `get_order_status`, и они уникальны в пределах сервера. Без жаргона и непонятных сокращений.
- **Описания** объясняют, что инструмент делает, что он изменяет и чего не может, и соответствуют его схеме ввода и реальному поведению. Они не велят модели отдавать предпочтение этому плагину, вызывать другие плагины или вызывать инструмент для всего подряд.
- **Одна операция на инструмент**, у каждой своя схема ввода.
- **Аннотации** явно задаются у каждого инструмента:

| Аннотация | `true`, когда инструмент | `false`, когда он |
|---|---|---|
| `readOnlyHint` | только читает, вычисляет или показывает предпросмотр | что-либо изменяет: записывает, сохраняет файл, отправляет, публикует, загружает, ставит работу в очередь или запускает задачу |
| `destructiveHint` | удаляет, перезаписывает, отменяет или отправляет то, что нельзя вернуть, даже если пользователь мог бы отменить действие | только добавляет |
| `openWorldHint` | обращается к публичному или неограниченному содержимому, например к веб-поиску, или отправляет на любой адрес | остаётся внутри ограниченной учётной записи, рабочего пространства или каталога, даже размещённого в другом месте |

Enconvo опирается на эти аннотации. Инструмент с `readOnlyHint: true` запускается без вопроса к пользователю и параллельно с другими операциями чтения. Инструмент с `destructiveHint: true` сначала спрашивает пользователя, если только он не дал агенту полный доступ. Инструмент, который что-то изменяет, но заявлен как только для чтения, отклоняется.

`enconvo plugin scan` запускает сервер MCP плагина, перечисляет его инструменты с аннотациями и называет каждый инструмент, у которого аннотации нет ([`annotations_required`](/extensions/validation-codes#mcp-server-scan)).

Инструмент со своим интерфейсом указывает своё представление, ресурс `ui://`, в `_meta.ui.resourceUri`, а представление объявляет домены, к которым обращается, в `_meta.ui.csp` (`connectDomains`, `resourceDomains`, `frameDomains`). Это ключи MCP Apps, которые читает любой хост. Enconvo также читает `_meta["openai/outputTemplate"]` и `_meta["openai/widgetCSP"]` из ChatGPT и для представления, написанного для ChatGPT (`text/html+skybridge` или инструмент, указанный только через `openai/outputTemplate`), предоставляет API `window.openai`, который оно вызывает, поэтому плагин, созданный для ChatGPT, показывает свой интерфейс в Enconvo без изменений. Задайте также ключи MCP Apps, чтобы интерфейс показывали и другие хосты. `scan` читает каждое представление так же, как Enconvo, и сообщает, если оно задано только способом OpenAI.

## Данные и конфиденциальность

- **Запрашивайте только то, что нужно для задачи.** Входные данные инструментов должны быть специфичны для задачи. Не запрашивайте всю беседу, прежние сообщения или обширные данные профиля «на всякий случай».
- **Возвращайте только то, что отвечает на запрос.** Не включайте в результаты инструментов внутренние идентификаторы, данные трассировки и отладочный вывод.
- **Никогда не собирайте** через входные данные инструментов данные платёжных карт, медицинские записи, государственные идентификаторы, например номера социального страхования, а также пароли, ключи API и одноразовые коды. Учётные данные хранятся в настройках плагина, где их держит Enconvo.
- **Политика конфиденциальности.** Плагину, который отправляет данные на сервер, нужна опубликованная политика конфиденциальности: что он собирает, зачем, кто получает данные, как долго они хранятся и как люди могут их удалить. Укажите её адрес в `interface.privacyPolicyURL`, а условия использования, если они есть, — в `interface.termsOfServiceURL`. Страница магазина ссылается на оба документа.
- **Никакого отслеживания** людей, их запросов и использования сверх того, что нужно плагину для работы и что раскрыто в его политике конфиденциальности.
- **Не оставляйте секреты в пакете.** Любой может его скачать. Файлы `.env` исключаются автоматически, но убедитесь, что в пакет не попали другие ключи или личные файлы.

## Вход в аккаунт и тестовые аккаунты

Если плагину нужна учётная запись, вход должен быть явным и запрашивать только необходимые разрешения. Ревьюерам нужно проверить его без создания учётной записи и без получения кода двухфакторной аутентификации, поэтому дайте им демо-аккаунт с примерами данных:

```sh
npx -p @enconvo/api enconvo plugin publish --review-notes "Sign in as review@example.com with the password …"
```

Заметки для ревьюеров получают только ревьюеры Enconvo. Они не входят в пакет и не попадают в карточку магазина.

## Платные функции

Плагин может работать с учётной записью, за которую люди уже платят, и может сообщать, что для функции нужен другой тариф. Если он что-то продаёт или принимает платежи, скажите об этом в материалах для проверки (`commerce` и `commerce_description`, ниже): что продаётся и где люди платят. Люди платят на вашем собственном сайте; плагин не скрывает списания и не берёт с пользователей Enconvo больше, чем со всех остальных.

Портал OpenAI строже. Он принимает только плагины, продающие физические товары, без подписок, кредитов и других цифровых продуктов. Прежде чем отправлять плагин туда, проверьте его [правила торговли](https://developers.openai.com/apps-sdk/app-submission-guidelines).

## Безопасность

- Плагин подходит для широкой аудитории, включая подростков, и не ориентирован на детей младше 13 лет.
- Он делает то, о чём попросил пользователь, и ничего больше: без постороннего содержимого, перенаправлений и рекламы.
- Его описания, промпты и навыки никогда не запрашивают секреты, не переводят деньги и не передают данные без ведома пользователя, не пытаются обойти защитные механизмы Enconvo и не скрывают, что делает плагин, в том числе с помощью закодированных инструкций.
- Он не собирает данные с сайтов и не оборачивает другие сервисы в нарушение их условий, а также не обходит их ограничения частоты запросов и контроль доступа.
- Он не продаёт и не делает возможным ничего из [списка запрещённых товаров и услуг](https://developers.openai.com/apps-sdk/app-submission-guidelines) OpenAI, например оружие, наркотики, азартные игры, контент для взрослых, вредоносное ПО или финансовое мошенничество.

## Материалы для проверки

Материалы для проверки сообщают ревьюерам, что пробовать: промпты, которые плагин должен обрабатывать, промпты, которые он должен оставлять без внимания, и короткое демо-видео. Они хранятся с каждой версией и показываются только ревьюерам.

В плагине Codex, Claude Code или переносимом плагине они лежат там, где их читает портал OpenAI: в `extensions["com.openai"]` одного файла `plugin.json`. OpenAI импортирует их из `.codex-plugin/plugin.json`, если он есть у плагина (как его создаёт `enconvo plugin create`); из корневого `plugin.json`, если в нём есть собственный `extensions["com.openai"]` или нет манифеста Codex; и из `.claude-plugin/plugin.json` в плагине, созданном только для Claude Code. Не добавляйте `extensions["com.openai"]` в корневой `plugin.json` только ради них: тогда Codex игнорирует карточку из `.codex-plugin/plugin.json`. `enconvo plugin validate --openai` называет манифест, в котором они должны находиться.

```json
{
  "name": "notes",
  "version": "1.2.0",
  "extensions": {
    "com.openai": {
      "review": {
        "test_cases": {
          "positive": [
            {
              "description": "Finds a note by topic",
              "prompt": "Find my notes about the Q3 launch",
              "tools_triggered": "search_notes, read_note",
              "expected_behavior": "Lists the matching notes and quotes the most relevant one"
            }
          ],
          "negative": [
            { "description": "Unrelated question", "prompt": "What's the weather in Paris?" }
          ]
        },
        "demo_recording_url": "https://example.com/notes-demo.mp4",
        "commerce": false
      },
      "publication": {
        "release_notes": "Search now matches note titles."
      }
    }
  }
}
```

В плагине Enconvo тот же объект `review` размещается на верхнем уровне `package.json`.

| Поле | Что в нём хранится |
|---|---|
| `test_cases.positive` | Промпты, которые плагин должен обрабатывать, у каждого есть `description`, `prompt`, `expected_behavior` и `tools_triggered`. Необязательно: `file_attachment_urls` и `expected_output_url`. |
| `test_cases.negative` | Промпты, которые плагин должен оставлять другим средствам, у каждого есть `description` и `prompt`. |
| `demo_recording_url` | Видео с основными промптами и инструментами. |
| `commerce`, `commerce_description` | Продаёт ли плагин что-либо, и что именно и где. |
| `publication.release_notes` | Что изменилось. `plugin publish` использует их как журнал изменений магазина, если вы не передали `-m`. |

В каждом списке до 20 случаев. Текстовые поля вмещают до 4000 символов, а каждый адрес — это адрес `https://`, который ревьюеры могут открыть. `validate` и `publish` отклоняют материалы, нарушающие эти ограничения.

Данные для входа никогда не кладут в пакет, потому что любой может его скачать. `validate` и `publish` отклоняют `review` с `test_credentials` или `reviewer_instructions`; передавайте их через `--review-notes` или в форме Review details в панели OpenAI.

В `plugin.json` блок `publication` может также содержать то, что портал OpenAI импортирует для карточки, а `validate --openai` проверяет это так же, как портал. Enconvo показывает `translations` на языке интерфейса для установленного плагина и перед установкой плагина из источника; страницы магазина Enconvo их пока не используют:

| Поле | Что в нём хранится |
|---|---|
| `countries` | Где доступен плагин, в виде кодов стран в верхнем регистре, например `["US", "GB"]`. `[]` делает его доступным везде. |
| `translations` | Текст карточки по локалям, например `{"fr-FR": {"subtitle": "…", "description": "…"}}`. Подзаголовок — одна строка до 30 символов, описание — до 4000. |

Поле со значением `null` сохраняет значение, уже записанное в панели OpenAI. Тестовые случаи уровня плагина предназначены для плагина ровно с одним сервером MCP.

Для окончательной отправки в OpenAI плагина с сервером MCP или приложением нужно ровно 5 положительных и 3 отрицательных случая, демо-запись и примечания к выпуску; плагину только с навыками нужны одни примечания к выпуску. `validate --openai` перечисляет недостающее как предупреждения, потому что загрузка на портал принимает плагин без них и требует их только при окончательной отправке.

## Чек-лист перед отправкой

Перед запуском `plugin publish`:

- `plugin validate` не сообщает об ошибках, и вы прочитали его предупреждения.
- `version` выше последней опубликованной вами версии, а каждый манифест в пакете указывает одно и то же имя и версию.
- Для обновления `plugin validate --previous` с архивом предыдущего выпуска не сообщает ничего неожиданного: обновление заменяет плагин целиком, поэтому пропущенный в нём навык или сервер MCP удаляется (`plugin_components_removed`).
- Заголовок, описание и значок говорят, что делает плагин, а скриншоты показывают его в работе.
- Указан адрес домашней страницы или поддержки, а если плагин куда-либо отправляет данные, дана ссылка на политику конфиденциальности.
- У каждого инструмента MCP понятные имя и описание, заданы `readOnlyHint`, `destructiveHint` и `openWorldHint`, а `plugin scan` перечисляет их без проблем.
- В `description` навыков сказано, когда их использовать.
- Обязательные параметры, например ключ API, объявлены как настройки, а не запрашиваются в чате.
- В папке нет ключей, токенов и личных файлов.
- Материалы для проверки перечисляют промпты, которые стоит попробовать, и промпты, которые нужно оставить без внимания, а если нужен вход в аккаунт, готов демо-аккаунт для `--review-notes`.
- Вы установили пакет из его папки (`plugin install .`) и попробовали тестовые случаи в Enconvo.

## Что происходит после отправки

1. `plugin publish` проверяет плагин и то, что его версия выше выпущенной в магазине, затем загружает его и отправляет версию на проверку. Пока новый плагин не одобрен, его видите только вы.
2. Ревьюер читает карточку, файлы пакета (с изменениями с момента выпущенной версии), материалы для проверки и ваши заметки и пробует тестовые случаи.
3. Одобренная версия появляется в магазине, а установленным копиям предлагается обновление. Если версия отклонена, вы получаете письмо с причиной. Исправьте, повысьте версию и опубликуйте снова.

Enconvo также разбирает жалобы на опубликованные плагины. Плагин, который нарушает эти правила, в том числе одобренный ранее, может быть удалён из магазина, а его разработчику по почте сообщается причина.

## Отправка и в OpenAI

Ту же папку можно отправить на портал плагинов OpenAI:

```sh
npx -p @enconvo/api enconvo plugin validate --openai
npx -p @enconvo/api enconvo plugin scan --openai
npx -p @enconvo/api enconvo plugin pack --openai
```

`pack --openai` создаёт архив, который принимает портал. Учётные данные для ревьюеров OpenAI вводятся в форме отправки на портале, но не кладутся в пакет. Не оставляйте в нём и свои ключи: `pack` и `publish` исключают файлы `.env`, а `validate` предупреждает о файле, похожем на закрытый ключ или данные для входа (`archive_member_secret`).

### Имя плагина

Портал принимает в `name` плагина только буквы, цифры, `-` и `_`, а OpenAI рекомендует строчные буквы, цифры и одиночные дефисы. Codex, Claude Code и Enconvo также устанавливают имя с точкой, например `acme.tools`, но `validate --openai` и `pack --openai` его отклоняют (`plugin_name_format`), поэтому плагин, который вы собираетесь отправлять, называйте `acme-tools`.

### Сервер MCP и домен

После загрузки портал подключается к серверу MCP плагина и сканирует его инструменты; когда сервер меняется, пересканируйте его там. Портал обращается к серверу только по публичному адресу `https://`, поэтому сервер, работающий на компьютере пользователя, сначала нужно развернуть; `scan --openai` предупреждает о таком (`mcp_server_not_remote`). При окончательной отправке портал требует все три аннотации у каждого инструмента. Он больше не просит их обосновывать; если автоматическая проверка отметит одну из них, вы можете обжаловать это с объяснением. Плагину, представления которого встраивают страницы, по-прежнему нужно обоснование для каждой встроенной страницы: что она делает, зачем плагин её встраивает и кто контролирует её домен. Страницы с зарегистрированного домена самого сервера MCP разрешены, а отдельные арендаторы на общем хосте считаются разными доменами. `scan --openai` перечисляет домены, которые встраивают ваши представления (`frame_domain_explanation_required`).

Прежде чем вы сможете отправить плагин, портал проверяет, что вы контролируете домен сервера MCP: он выдаёт токен, который нужно отдавать простым текстом по адресу `/.well-known/openai-apps-challenge` на хосте сервера или родительском домене. `scan --openai` сообщает, что отвечают эти адреса, а `scan --challenge-token <token>` проверяет, что один из них отдаёт ровно этот токен, прежде чем вы выберете **Verify Domain**; см. [Подтверждение домена](/extensions/validation-codes#domain-verification).

Портал OpenAI подключает для сканирования и проверки только один сервер MCP на плагин, поэтому `validate --openai` предупреждает о плагине с несколькими. Один и тот же сервер, объявленный для Codex в `mcp.json` и для Claude Code в `.mcp.json`, считается один раз.

### Обновление опубликованного плагина

Чтобы обновить плагин, опубликованный там, загрузите полный ZIP с более высокой версией и всем, что вы хотите сохранить. Если вы не сохранили архив опубликованной версии, портал выдаёт его через **Download release ZIP** в меню **…** этой версии; сверьте новую версию с ним через `validate --openai --previous <zip>`. Портал не может добавить сервер MCP в опубликованный плагин, у которого его не было, или изменить URL опубликованного сервера (для этого обратитесь в поддержку OpenAI), и `--previous` сообщает об обоих случаях; см. [Обновления](/extensions/validation-codes#updates).

### Окончательная отправка

Окончательная отправка в OpenAI требует от карточки больше, чем загрузка, и `validate --openai` предупреждает о каждом пробеле:

- `interface.longDescription` и `interface.category`; без категории каталог относит плагин к разделу Other.
- Для плагина с сервером MCP — `websiteURL`, `supportURL`, `privacyPolicyURL` и `termsOfServiceURL`, каждый — адрес `https://` длиной до 1024 символов.
- Собственная карточка. Плагину Claude Code только с `.claude-plugin/plugin.json` портал заполняет карточку значениями по умолчанию (`claude_format_normalized`), поэтому добавьте `.codex-plugin/plugin.json` с `interface`, чтобы написать её самостоятельно.
- Скриншоты только если у сервера MCP есть собственный интерфейс: по одному PNG или JPEG на каждый стартовый промпт, шириной ровно 706 пикселей и высотой от 400 до 860 пикселей. Портал решает это по результатам сканирования, поэтому `scan --openai` отклоняет скриншоты, когда ни один инструмент не показывает интерфейс (`screenshots_not_allowed`). Каталог OpenAI больше не показывает скриншоты и представляет плагин его стартовыми промптами, поэтому пишите их внимательно.

Каталог показывает имя разработчика из вашей подтверждённой личности OpenAI, независимо от того, что указано в `interface.developerName`. Коды см. в разделе [Окончательная отправка в OpenAI](/extensions/validation-codes#openai’s-final-submission).
