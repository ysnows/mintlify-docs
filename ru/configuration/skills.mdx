Навык объединяет инструкции, ресурсы и необязательные скрипты, чтобы Enconvo надёжно следовал рабочему процессу. Создайте его, если вам постоянно приходится объяснять одну и ту же процедуру, например как проверять код или как оформлять заметки о встречах. Навыками можно делиться с командой или сообществом.

<Note>
Навыки используют **постепенное раскрытие**, чтобы эффективно управлять контекстом: Enconvo начинает с метаданных каждого навыка (название, описание, путь к файлу). Полные инструкции загружаются только тогда, когда навык активирован.
</Note>

В этом видео рассказывается о навыках, затем о серверах MCP, плагинах и Extension Store.

## Управление навыками

Откройте **Настройки → Навыки**. Эти навыки общие для всех агентов, и каждый агент может добавить свои в своих настройках.

- Карточки вверху показывают число навыков: **Все навыки**, **Включено, ни разу не использовалось**, **В нескольких папках** и **Выкл.**. Нажмите на карточку, чтобы вывести только их.
- В каждой строке показано **Где находится** (встроенный, либо папка или приложение, откуда он взят) и когда он **Последнее использование**. Отключите навыки, которые не нужны вашим агентам, переключателем в конце строки или выберите несколько и отключите их вместе.
- **Добавить из GitHub** устанавливает навык из репозитория, а **Импортировать** добавляет навык из папки на вашем Mac. См. [Установка навыков](#установка-навыков).
- **Ваши навыки** перечисляет созданные вами навыки по происхождению: **Записано**, **Запомнено**, **Скрипт**, **Написан** или **Установлено**. Нажмите на навык, чтобы увидеть его **Шаги**, **Подводные камни** и **История**. См. [Навыки с сохранёнными шагами](#навыки-с-сохранёнными-шагами).

В Окне чата навыки можно также открыть прямо в окне из **Плагины** на панели значков.

## Как выглядит навык

Навык — это папка с файлом `SKILL.md` и необязательными скриптами и справочными материалами.

```
my-skill/
├── SKILL.md          # Required: instructions + metadata
├── scripts/          # Optional: executable code
├── references/       # Optional: documentation
└── assets/           # Optional: templates, resources
```

### Формат SKILL.md

`SKILL.md` должен начинаться с блока frontmatter, содержащего `name` и `description`:

```markdown
---
name: my-skill
description: Explain exactly when this skill should and should not trigger.
---

Step-by-step instructions for EnConvo to follow.
```

<Tip>
Enconvo выбирает навык по его `description`, поэтому чётко задайте его область и границы. Укажите, **когда** использовать навык и **когда нет**.
</Tip>

## Использование навыка

Вы можете вызвать навык по имени или позволить Enconvo выбрать подходящий под ваш запрос.

### Вызов навыка по имени

Введите `/` и название навыка в SmartBar или в чате:

```
/code-reviewer Review this function for security issues
/meeting-notes Format these raw notes into a structured summary
/api-checker Check the health of api.example.com
```

Это самый надёжный способ: вы получаете именно тот навык, который нужен. Чтобы вывести только навыки, введите `$`.

Навыки установленных вами плагинов тоже есть в меню `/` и `$` под названием `plugin:skill`, как в Claude Code.

### Пусть Enconvo выберет сам

Если вы не называете навык, Enconvo подбирает для вашего запроса наиболее подходящий навык по его `description`:

1. Вы вводите: «Сведи эти заметки о встрече в список действий»
2. Enconvo просматривает описания всех доступных навыков
3. Подходит навык `meeting-notes` («...оформляет необработанные расшифровки встреч в структурированные заметки с пунктами действий...»)
4. Навык активируется, и его инструкции направляют ответ

Подбор идёт по смыслу, а не только по совпадающим ключевым словам, поэтому запрос, сформулированный иначе, чем описание, или написанный на другом языке, всё равно находит навык. Чтобы агент всегда видел навык, закрепите его в настройках агента **Инструменты и навыки**; см. [Агенты](/ru/ai/agents).

### Пишите описания, которые хорошо подбираются

Хороший подбор зависит от грамотно написанного `description`:

| Качество | Пример |
|---------|---------|
| **Слишком расплывчато** | «Помогает с кодом» |
| **Слишком широко** | «Делает всё, что связано с программированием» |
| **Хорошо** | «Проверяет код на ошибки, проблемы безопасности и соответствие лучшим практикам. Используйте, когда пользователь просит проверить код или хочет улучшить его качество. Не используйте для генерации кода или написания нового кода.» |

Хорошее описание состоит из трёх частей:

- **Что делает**: «Проверяет код на ошибки, проблемы безопасности и соответствие лучшим практикам»
- **Когда срабатывать**: «Используйте, когда пользователь просит проверить код»
- **Когда не срабатывать**: «Не используйте для генерации кода или написания нового кода»

## Где хранятся навыки

Enconvo читает навыки из нескольких мест, у каждого своя область действия:

| Область | Расположение | Для чего использовать |
|-------|----------|------------|
| **Проект** | `$PROJECT/.agents/skills/` (также `.enconvo/skills/`, `.claude/skills/` и `.codex/skills/`) | Навыки для одного проекта или рабочей области |
| **Пользователь** | `~/.agents/skills/` (также `~/.enconvo/skills/`, `~/.claude/skills/` и `~/.codex/skills/`) | Личные навыки для всех ваших проектов |
| **Система** | Входят в состав Enconvo | Встроенные навыки, доступные всем |

Каждый агент может также иметь собственные навыки: добавьте их в разделе **Навыки** в настройках агента.

Если два навыка в разных местах имеют одинаковое название, оба остаются доступными; Enconvo их не объединяет. **Настройки → Навыки** перечисляет такие навыки в **В нескольких папках**.

### Навыки проекта

Навыки проекта находятся внутри папки проекта и доступны только тогда, когда этот проект активен:

```
my-project/
├── .agents/
│   └── skills/
│       ├── deploy-checklist/
│       │   └── SKILL.md
│       └── pr-template/
│           └── SKILL.md
├── src/
└── package.json
```

Используйте их для навыков, зависящих от соглашений, структуры файлов или инструментов проекта.

### Пользовательские навыки

Пользовательские навыки в `~/.agents/skills/` доступны в каждом проекте. Используйте их для личных навыков, не относящихся к одному проекту:

```
~/.agents/skills/
├── email-composer/
│   └── SKILL.md
├── meeting-notes/
│   └── SKILL.md
└── code-reviewer/
    └── SKILL.md
```

## Создание навыка

### С помощью создателя навыков

Самый быстрый способ создать навык — встроенный создатель:

```
/skill-creator
```

Создатель проведёт вас по шагам:

1. Что делает навык
2. Когда он должен срабатывать
3. Должен ли он состоять только из инструкций или включать скрипты

По умолчанию и рекомендуется вариант только с инструкциями. Добавляйте скрипты, только когда нужно детерминированное поведение или внешние инструменты.

### Вручную

Создайте папку с файлом `SKILL.md`:

<Steps>
  <Step title="Создайте папку навыка">
    ```bash
    mkdir -p ~/.agents/skills/my-skill
    ```
  </Step>
  <Step title="Напишите SKILL.md">
    ```bash
    cat > ~/.agents/skills/my-skill/SKILL.md << 'EOF'
    ---
    name: my-skill
    description: Summarize selected text into bullet points. Use when the user asks for a summary or key takeaways. Do not use for translation or rewriting tasks.
    ---

    ## Instructions

    1. Read the selected text from the user's input.
    2. Identify the 3-5 most important points.
    3. Return a bullet-point summary.
    4. Keep each bullet under 20 words.
    EOF
    ```
  </Step>
  <Step title="Проверьте, что он появился">
    Enconvo обнаруживает изменения навыков автоматически. Если новый навык не появился, перезапустите Enconvo.
  </Step>
</Steps>

### Напишите инструкции

Тело `SKILL.md` под frontmatter содержит инструкции, которым следует ИИ. Пишите их как чёткие шаги в повелительном наклонении:

````markdown
---
name: changelog-generator
description: Generate a changelog from git commits. Use when the user asks to create a changelog, release notes, or commit summary. Do not use for general git operations.
---

## Instructions

1. Read the git log for the specified date range or number of commits.
2. Group commits by category:
   - **Features**: New functionality (commits starting with "feat:")
   - **Fixes**: Bug fixes (commits starting with "fix:")
   - **Breaking Changes**: Changes that break backward compatibility
   - **Other**: Everything else
3. For each commit, write a user-facing description (not the raw commit message).
4. Format as markdown with version header, date, and categorized bullet points.
5. Highlight breaking changes with a warning callout.

## Output Format

```
## v1.2.0 (2024-01-15)

### Features
- Added dark mode support for all pages
- New export to PDF option in reports

### Fixes
- Fixed login timeout on slow connections
- Resolved duplicate notification issue

### Breaking Changes
⚠️ API endpoint `/v1/users` now requires authentication
```
````

### Советы для хороших навыков

- **Делайте каждый навык узким.** Один навык — одна задача. Навык, который делает слишком много, сложнее правильно запускать и поддерживать. Если вы пишете 10 или больше шагов, охватывающих несколько задач, разделите его на отдельные навыки.
- **Точно указывайте входные данные.** Скажите, откуда именно берётся ввод: «Прочитай выделенный текст», «Разбери прикреплённый файл», «Используй URL из сообщения пользователя».
- **Определите формат вывода.** Добавьте конкретный пример того, как должен выглядеть результат, чтобы результаты оставались единообразными.
- **Учитывайте крайние случаи.** Добавьте инструкции для типичных крайних случаев: «Если коммитов не найдено, сообщи, что диапазон пуст» или «Если ввод не является корректным JSON, попроси пользователя проверить формат».
- **Пишите шаги в повелительном наклонении.** Чётко указывайте входные данные, шаги и ожидаемые результаты. Расплывчатые инструкции приводят к нестабильным результатам.
- **Отдавайте предпочтение инструкциям, а не скриптам.** Инструкции простым языком проще писать, отлаживать и менять. Используйте скрипты, только когда нужно детерминированное поведение или внешние инструменты.
- **Задавайте чёткие границы.** В описании укажите и то, что навык должен обрабатывать, и то, что не должен.
- **Проверяйте описания срабатывания.** Пробуйте разные запросы, чтобы убедиться, что навык срабатывает, когда должен, и не срабатывает, когда не должен.
- **Ведите версии навыков.** Храните навыки, которыми делится команда, в системе контроля версий (git), чтобы отслеживать изменения, откатываться и работать вместе.

## Добавление скриптов

Для навыков, которым нужна исполняемая логика, добавьте папку `scripts/`:

```
my-skill/
├── SKILL.md
└── scripts/
    └── fetch_data.sh
```

Сошлитесь на скрипты в своём `SKILL.md`:

````markdown
---
name: api-checker
description: Check API endpoint health and response times.
---

## Instructions

1. Run the health check script:
   ```bash
   bash scripts/fetch_data.sh $URL
   ```
2. Parse the JSON output.
3. Report status, response time, and any errors.
````

### Когда использовать скрипты

| Используйте скрипты, когда | Используйте только инструкции, когда |
|-----------------|---------------------------|
| Нужен детерминированный результат (точные форматы, вычисления) | Задача в основном о рассуждении и языке |
| Вы взаимодействуете с внешними API или базами данных | Задача использует только встроенные возможности ИИ |
| Нужно программно обрабатывать или преобразовывать данные | Задача связана с написанием, резюмированием или анализом |
| Требуется аутентификация или работа с учётными данными | Инструкций самих по себе достаточно |

## Добавление справочных материалов

Добавьте файлы с документацией или контекстом, к которым навык может обращаться:

```
my-skill/
├── SKILL.md
├── references/
│   ├── api-docs.md
│   └── examples.md
└── scripts/
    └── run.sh
```

Сошлитесь на них в инструкциях:

```markdown
Consult `references/api-docs.md` for the API schema before making requests.
```

Справочные материалы полезны для:

- документации по API, которой навык должен следовать
- руководств по стилю или брендбуков
- примеров кода и шаблонов
- знаний из конкретной предметной области

## Установка навыков

Используйте `/skill-installer`, чтобы установить навык из магазина навыков Enconvo или из GitHub. Он также умеет устанавливать из Skills.sh, ClawHub и по прямым URL ZIP-файлов.

### Из магазина навыков Enconvo

Найдите навык по названию и установите его:

```
/skill-installer pdf
```

Эта команда ищет в магазине навыков Enconvo и устанавливает подходящий навык. Enconvo автоматически обнаруживает недавно установленные навыки.

### Из GitHub

Установите навык прямо по URL репозитория GitHub:

```
/skill-installer https://github.com/anthropics/skills/tree/main/skills/pptx
```

URL может указывать на подпапку, поэтому можно установить один навык из большого репозитория, не клонируя его целиком.

### Из папки на вашем Mac

1. Откройте **Настройки → Навыки** и нажмите **Импортировать**.
2. Выберите папку с подпапками навыков, в каждой из которых есть `SKILL.md`.

Enconvo добавляет папку в список мест, откуда читает навыки, и её навыки становятся общими для всех агентов. Чтобы перестать использовать папку, выберите её в меню источников, затем **Удалить папку**. Сама папка остаётся на диске.

## Навыки с сохранёнными шагами

Каждый сохранённый рабочий процесс — это тоже навык со своим `SKILL.md`, а навык может хранить шаги ранее выполненной задачи. Когда вы запускаете такой навык, его сохранённые шаги выполняются первыми, без основной модели, что быстрее и дешевле. Шаг, который больше не подходит, например сместившаяся кнопка, исправляется по собственным заметкам и скриншотам навыка. Только если это не удалось, агент выполняет задачу по `SKILL.md`.

В **Ваши навыки** навык с пометкой **Сначала выполняет сохранённые шаги** имеет шаги; с пометкой **Только инструкции** — не имеет. **История** каждого навыка показывает, как проходили его запуски и чему он научился, и позволяет восстановить более раннюю версию.

### Превратите запись в навык

Запись выполненной вами задачи можно превратить в навык. Каждое записанное действие становится проверяемым шагом, а его скриншот сохраняется для исправлений. Навык остаётся **Черновиком**, пока его запуск не пройдёт успешно.

### Выполните скрипт как шаг

Навык может хранить скрипт [Code Mode](/ru/configuration/code-mode) в собственной папке `scripts` и запускать его как один из своих шагов, так что задача с множеством вызовов инструментов выполняется как один шаг.

## Пусть навыки учатся тому, как вы работаете

Навыки могут учиться тому, как вы любите выполнять задачи, подобно тому как Воспоминания запоминают факты. Откройте **Настройки → Память** и включите **Запоминать способы**:

- Когда вы поправляете то, как была выполнена задача, или шаг пришлось исправить, навык запоминает это сразу. В чате появляется заметка **Запомнено** с кнопкой **Отменить**.
- Когда задача возникает во второй раз, она становится новым навыком.
- Проверка памяти и Уборка памяти ухаживают и за навыками.

В **При изменении шагов** выберите **Сразу применять** или **Сначала спросить**, чтобы изменение шагов навыка ждало, пока вы нажмёте **Применить** в его заметке. Подводные камни в любом случае добавляются сразу. Платежи, отправка и удаление всегда спрашивают вас первыми, а ключи и пароли никогда не запоминаются.

## Управление навыками

### Просмотр навыков

**Настройки → Навыки** перечисляет навыки, общие для всех агентов. Выберите представление вверху:

| Представление | Что показывает |
| --- | --- |
| **Все навыки** | Каждый навык один раз, даже если копия есть в нескольких папках |
| **Включено, ни разу не использовалось** | Навыки, которые предлагаются агентам в каждом чате, но ими не пользовались |
| **В нескольких папках** | Навыки с копией более чем в одной папке, например для Claude Code и Codex |
| **Выкл.** | Навыки, которые агенты не получают |

Ищите, фильтруйте по источнику (**Все источники**, **Встроенные**, **Из плагинов** или одна папка) или сортируйте по **По названию (А–Я)** или **Последнее использование**.

### Обновление навыков

- **Навыки из магазина**: снова запустите `/skill-installer`, чтобы проверить наличие более новой версии.
- **Навыки из GitHub**: снова запустите установщик с тем же URL.
- **Ваши собственные навыки**: редактируйте файл `SKILL.md` напрямую. Enconvo обнаружит изменение автоматически.

### Отключение навыка

Навык можно отключить, не удаляя его:

1. Откройте **Настройки → Навыки**.
2. Найдите навык.
3. Выключите его переключатель.

Агенты не могут использовать отключённый навык ни по имени, ни по подбору, пока вы не включите его обратно. Профиль приложения, закрепляющий навык, всё равно может его использовать.

## Примеры навыков

### Рецензент кода

```markdown
---
name: code-reviewer
description: Review code for bugs, security issues, and best practices. Use when the user asks for a code review or wants to improve code quality. Do not use for code generation or writing new code.
---
```

### Сообщение коммита git

````markdown
---
name: commit-message
description: Generate conventional commit messages from staged changes. Use when the user asks for a commit message or wants to commit changes. Do not use for general git operations like branching or merging.
---

## Instructions

1. Read the staged diff (use `git diff --staged`).
2. Identify the type of change:
   - feat: New feature
   - fix: Bug fix
   - docs: Documentation
   - refactor: Code restructuring
   - test: Adding tests
   - chore: Maintenance
3. Write a commit message following Conventional Commits format:
   ```
   type(scope): concise description

   - Detail 1
   - Detail 2
   ```
4. Keep the subject line under 72 characters.
5. Include a body only if the change needs explanation.
````
