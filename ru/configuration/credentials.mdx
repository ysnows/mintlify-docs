Каждому провайдеру нужны учётные данные: ключ API или вход в тариф, который вы уже оплачиваете. Вы добавляете их на странице Настроек самого провайдера, и Enconvo хранит их в профиле провайдера, общем для всех функций, которые им пользуются. **Настройки → Управление учётными данными** показывает все учётные данные в одном месте.

Это видео заканчивается в Управлении учётными данными, после Аватара и Каналов мессенджеров.

## Добавить провайдера

<Steps>
  <Step title="Открыть категорию">
    Откройте страницу Настроек того, чем хотите пользоваться, например **Настройки → AI-модель**, **Настройки → Генерация изображений** или **Настройки → Синтез речи**.
  </Step>
  <Step title="Выбрать провайдера">
    Выберите провайдера. Чтобы настроить вторую копию, для другого ключа или учётной записи, выберите **Добавить нового провайдера**.
  </Step>
  <Step title="Выбрать способ входа">
    В **Аутентификация** выберите **Ключ API** или **Подписка**, если провайдер позволяет пользоваться оплаченным тарифом.
  </Step>
  <Step title="Добавить учётные данные">
    Вставьте ключ API или завершите вход у провайдера.
  </Step>
  <Step title="Проверить">
    Нажмите **Проверить**, если кнопка есть на странице, выберите модель и попробуйте короткий запрос.
  </Step>
</Steps>

Ключ API списывается со счёта API провайдера. Подписка использует включённое в тариф использование и его лимиты. Текст под **Аутентификация** говорит, что именно использует страница.

## Общие профили

Профиль провайдера, например **OpenAI 2**, хранит ключ API провайдера и вход по подписке и появляется в каждой категории, которую провайдер поддерживает. Переименование или удаление профиля меняет его во всех этих категориях, а не только на открытой странице.

У каждой категории свои настройки модели, голоса и генерации. Новый ключ API, однако, доходит до каждой функции, которая использует профиль, поэтому после смены проверьте эти функции.

Что предлагает провайдер, зависит от категории. Вход, который работает для AI-чата, не значит, что голосовой API реального времени провайдера входит в тариф. Если категория принимает только ключ API, страница так и пишет и называет категории, где работает подписка.

## Проверить использование тарифа

Вход по подписке показывает учётную запись и сколько тарифа осталось. Значение вроде **% осталось** — это оставшийся лимит. Откройте меню карточки учётной записи и выберите **Обновить сведения об использовании**, чтобы обновить его, или **Переподключить**, чтобы войти снова.

Если Claude или Codex выдали вам бесплатные сбросы лимита, карточка подписки Claude или ChatGPT показывает **Сброс бесплатного лимита**: сколько их и до какого срока. Нажмите **Использовать сброс** и подтвердите, чтобы восполнить лимиты. Если их больше одного, карточка перечисляет их, и вы используете выбранный.

Если использование не показано, это не значит, что оно безлимитное.

## Управлять учётными данными

Откройте **Настройки → Управление учётными данными**. Список группирует учётные данные по профилю провайдера, затем показывает **Unused keys**: ключи, которые не использует ни один провайдер.

- Введите текст в **Поиск провайдеров...**, чтобы найти нужного.
- Нажмите **Добавить новые учетные данные**, чтобы создать ещё одни учётные данные для выбранной службы.
- Чтобы удалить учётные данные, наведите на них и нажмите значок корзины. Если ключ использует коннектор API, подтверждение называет его, а **Удалить и отключить** отключает его, пока вы не дадите другой ключ.
- Нажмите **Навести порядок** внизу списка, чтобы удалить все неиспользуемые ключи сразу. Кнопка показывает, сколько их, а подтверждение сначала перечисляет их. Enconvo сам неиспользуемые ключи не удаляет.

Нажмите учётные данные, чтобы добавить или сменить ключ. **Используется в** перечисляет функции, которые на них опираются, например **AI-модель** или **Синтез речи**; нажмите одну, чтобы открыть эту страницу Настроек.

У собственных учётных данных профиля здесь нет кнопки удаления. Они уходят, когда вы удаляете провайдера.

Ещё две группы появляются, когда они у вас есть: **Другие службы** — ключи к службам, для которых у Enconvo нет провайдера, и **Данные для входа** — сохранённые входы на сайты и в приложения.

## Когда агенту нужен ключ

Когда задаче нужен ключ API службы, агент показывает в чате карточку **Подключить**, а не просит вставить ключ. Ключ попадает в Управление учётными данными, а не в разговор, и следующие чаты используют его без повторного вопроса.

Для службы, у которой в Enconvo нет провайдера, карточка показывает хост, куда ключ будет отправлен. Ключ сохраняется в **Другие службы**, и агент может использовать его только в запросах к этому хосту.

Сам ключ агент не держит: он называет сохранённые учётные данные, а там, где запрос или команда показали бы ключ, читается `[redacted]`.

В чате на телефоне карточка **Подключить** показывается на iPhone, а ключ сохраняется в Управлении учётными данными на Mac. В чате мессенджера агент никогда не просит ключ: он отправляет ссылку, которая открывает чат в Enconvo.

Если вы всё же вставите ключ API в сообщение, Enconvo сохранит его в Управлении учётными данными и заменит на `[redacted]` в сохранённом чате, чтобы следующие запросы и другие устройства его не несли. Новый ключ, который вы вставляете для службы, у которой ключ уже есть, заменяет сохранённый.

## Входы на сайты и в приложения

Когда задача в браузере доходит до страницы входа, карточка один раз спрашивает имя пользователя и пароль. Enconvo заполняет их только на этом сайте, и агент пароль не видит. Сохранённые входы появляются в **Данные для входа**. Снимите **Запомнить эти данные для входа**, чтобы использовать их только для этого входа.

Когда входу в приложение Mac нужен пароль, карточка называет приложение. Enconvo вводит имя пользователя и пароль только в это приложение, а пароль — только в поле, которое скрывает вводимое.

## Свои адреса

У провайдеров **OpenAI Compatible** и **Anthropic Compatible** есть поле базового URL API для вашего сервера. У некоторых встроенных провайдеров настройка адреса остаётся в **Управление учётными данными**. Про сервер моделей на другом компьютере см. [Локальные модели](/ru/ai/local-llm).

Менять, куда отправляется сохранённый ключ, могут только собственные окна Enconvo: адрес провайдера или учётных данных, либо использование сохранённого ключа сервером MCP. Другие программы через Local API, телефон и агенты получают отказ.

## Как хранятся ключи

- Каждый сохранённый ключ и вход шифруется ключом, который остаётся в Связке ключей этого Mac, поэтому копию папки настроек Enconvo нельзя прочитать на другом компьютере. Если вы вернётесь к более старой версии Enconvo, ключи придётся ввести снова.
- Другая программа, которая запрашивает настройки через [Local API](/ru/advanced/cli-local-api) Enconvo, получает `[hidden]` вместо каждого ключа. Плагин из магазина может использовать только свои ключи и учётные данные, выбранные в его настройках.
- Открывать сохранённые ключи может только код, который установил Enconvo и который не изменён. Настройки по-прежнему показывают и проверяют ключи.

## Устранение неполадок

| Проблема | Что делать |
| --- | --- |
| Проверка не проходит | Проверьте выбранный профиль, способ аутентификации, адрес и что у учётной записи провайдера есть доступ. |
| Одна функция работает, другая нет | Проверьте, что учётная запись поддерживает эту функцию и модель. Страница говорит, когда категория принимает только ключ API. |
| После смены ключа что-то перестало работать | Профиль общий. Проверьте другие категории, которые его используют. |
| В области использования показано **Переподключить** | Вход истёк. Нажмите **Переподключить** и войдите снова. |
