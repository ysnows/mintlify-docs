---
title: "Хуки"
description: "Автоматически запускайте команду оболочки или отправляйте вебхук, когда агент запускается, использует инструмент или завершает работу."
---

Хуки запускают команду оболочки или отправляют HTTP-запрос, когда в Enconvo что-то происходит, например агент запускается, завершается, терпит неудачу или использует инструмент. Вы настраиваете их в файле JSON, так что можно добавлять уведомления, журналы, локальную автоматизацию или интеграции, не создавая расширение.

<Note>
Большинство хуков работают по принципу «запустил и забыл»: они выполняются в фоне и не блокируют Enconvo. Исключение во время запусков агента — `PreToolUse`, `Stop` и `SubagentStop`. Агент ждёт их, поэтому они могут заблокировать вызов инструмента или вернуть агента к работе. См. [Блокирующие хуки](#блокирующие-хуки).
</Note>

## Быстрый старт

<Steps>
  <Step title="Создайте папку для хуков">
    ```bash
    mkdir -p ~/.enconvo
    ```
  </Step>

  <Step title="Создайте ~/.enconvo/hooks.json">
    ```json
    {
      "hooks": {
        "UserPromptSubmit": [
          {
            "hooks": [
              {
                "type": "command",
                "command": "echo 'Agent status changed' >> /tmp/enconvo-hooks.log"
              }
            ]
          }
        ]
      }
    }
    ```
  </Step>

  <Step title="Запустите агента">
    Запустите любого агента или команду чата. Когда его статус изменится, Enconvo выполнит
    настроенную команду и добавит строку в `/tmp/enconvo-hooks.log`.
  </Step>
</Steps>

## Файл конфигурации

Хуки хранятся в:

```text
~/.enconvo/hooks.json
```

Enconvo также читает прежний файл `~/.config/enconvo/hooks.json`, если нового файла нет. Если существуют оба файла, приоритет у `~/.enconvo/hooks.json`.

Файл перечитывается при каждом срабатывании события, поэтому хуки можно редактировать, пока Enconvo работает. Перезапуск не нужен.

## Управление хуками в настройках

Откройте **Настройки → Хуки**, чтобы увидеть хуки из `~/.enconvo/hooks.json`, сгруппированные по событиям. Включайте или отключайте запись её переключателем или нажмите **Открыть hooks.json**, чтобы изменить файл. Отключение или включение записи добавляет в неё `enabled: false` или `enabled: true`, не меняя её команду или вебхук.

## Хуки из плагинов

Плагины Claude Code и Codex, например context-mode, могут приносить собственные хуки. Когда вы их разрешите, они работают так же, как в Claude Code: в начале чата, вокруг каждого сообщения, вызова инструмента и сжатия, а также когда ответ завершается ошибкой или агент заканчивает работу.

1. Установите плагин из **Плагины** или передайте агенту в чате репозиторий GitHub плагина, адрес Git, zip или пакет npm. Он предложит карточку установки плагина.
2. Перед установкой отметьте **Разрешить запуск хуков**. У плагина, установленного без этого, указано, что его хуки отключены; позже нажмите на нём **Разрешить хуки**, чтобы включить их.

Если обновление плагина меняет его хуки, они перестают запускаться, пока вы не проверите их и не разрешите снова. Хуки, которые Enconvo не может запустить, перечислены на карточке как не запускаемые в Enconvo.

## Как работают хуки

Когда срабатывает событие, Enconvo:

1. Загружает `~/.enconvo/hooks.json`.
2. Обращается к `~/.config/enconvo/hooks.json`, только если нового файла нет.
3. Находит записи внутри объекта верхнего уровня `hooks`, ключ которых совпадает с названием события.
4. Применяет необязательное регулярное выражение `matcher`.
5. Пропускает записи, у которых `enabled` равно `false`.
6. Запускает все настроенные хуки одновременно.

Названия событий хуков соответствуют набору жизненного цикла Claude Code и Codex: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `Stop` и `SubagentStop`. Старые названия событий Enconvo и старая плоская форма JSON по-прежнему работают для существующих установок, но новые записи используют обёрнутый формат в стиле Codex.

## Справочник по конфигурации

```json
{
  "hooks": {
    "event_name": [
      {
        "matcher": "optional_regex_filter",
        "enabled": true,
        "hooks": [
          { "type": "command", "command": "..." },
          { "type": "http", "url": "..." }
        ]
      }
    ]
  }
}
```

| Поле | Тип | Обязательно | Описание |
|-------|------|----------|-------------|
| `hooks` | object | Да | Карта событий с названиями событий в качестве ключей. |
| `event_name` | string | Да | Событие, которое нужно слушать. Используйте его как ключ внутри `hooks`. |
| `matcher` | string | Нет | Фильтр-регулярное выражение. Для событий инструментов сопоставляется с `toolName`, `toolTitle` или `path`; для остальных событий — с названием события хука. |
| `enabled` | boolean | Нет | Установите `false`, чтобы оставить запись в конфигурации, но не выполнять её. По умолчанию `true`. |
| `hooks` | array | Да | Хуки команд и HTTP, которые нужно выполнить. |

### Хук команды

Хук команды запускает команду оболочки. Enconvo записывает полезную нагрузку события в stdin команды в виде JSON.

```json
{
  "type": "command",
  "command": "bash ~/.enconvo/hooks/on-status-change.sh",
  "timeout": 30000
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `type` | `"command"` | - | Обязательный тип хука. |
| `command` | string | - | Команда оболочки для выполнения. |
| `timeout` | number | `30000` | Тайм-аут в миллисекундах. |

### HTTP-хук

HTTP-хук отправляет полезную нагрузку события как тело запроса JSON.

```json
{
  "type": "http",
  "url": "https://example.com/webhook",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer your-token"
  },
  "timeout": 30000
}
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `type` | `"http"` | - | Обязательный тип хука. |
| `url` | string | - | URL конечной точки HTTP. |
| `method` | string | `"POST"` | Метод HTTP. |
| `headers` | object | `{}` | Дополнительные заголовки запроса. |
| `timeout` | number | `30000` | Тайм-аут в миллисекундах. |

## Блокирующие хуки

Во время запуска агента или бота три события выполняются как блокирующие хуки. Агент ждёт каждый подходящий хук (они выполняются параллельно), прежде чем продолжить, и читает их результат так же, как Claude Code и Codex.

| Событие | Когда | Что может сделать хук |
|-------|------|----------------------|
| `PreToolUse` | Непосредственно перед выполнением вызова инструмента. `matcher` проверяется по названию инструмента, заголовку и пути маршрута. | Заблокировать вызов или переписать его ввод. |
| `Stop` | Непосредственно перед тем, как агент завершает ход ответом. | Вернуть агента к работе с инструкцией. |
| `SubagentStop` | Непосредственно перед завершением субагента. | Вернуть субагента к работе с инструкцией. |

Хук принимает решение одним из двух способов:

- **Код выхода 2** блокирует. Причиной служит текст, который команда пишет в stderr.
- **Код выхода 0 с JSON в stdout.** Любой другой вывод, код выхода, ошибка или тайм-аут ничего не решают, и запуск продолжается так, будто хука нет.

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Writing outside the project is not allowed."
  }
}
```

| Вывод JSON | Эффект |
|-------------|--------|
| `hookSpecificOutput.permissionDecision: "deny"` | `PreToolUse`: вызов не выполняется. Модель видит `permissionDecisionReason` как результат инструмента и может выбрать другой путь. |
| `hookSpecificOutput.permissionDecision: "ask"` | Обрабатывается как `deny`. В Enconvo пока нет запроса подтверждения для хуков. |
| `hookSpecificOutput.permissionDecision: "allow"` | `PreToolUse`: вызов выполняется. |
| `hookSpecificOutput.updatedInput` | `PreToolUse`: вызов выполняется с этим вводом вместо ввода модели. |
| `{ "decision": "block", "reason": "..." }` | `Stop` / `SubagentStop`: агент продолжает работать, а `reason` становится его следующей инструкцией. В `PreToolUse` блокирует вызов. |
| `{ "decision": "approve" }` | То же, что `allow`. |

HTTP-хуки решают ответом 2xx, тело которого — тот же JSON.

Когда подходит несколько хуков, запрет (deny) приоритетнее запроса (ask), а тот приоритетнее разрешения (allow). Причины объединяются, а используется последнее значение `updatedInput`.

Хук `Stop` может вернуть агента не более 5 раз за один ход. При второй и последующих проверках `stop_hook_active` равно `true`, поэтому хук может позволить агенту остановиться, когда его инструкция выполнена. Блокировка `Stop` применяется только тогда, когда агент завершает работу штатно; неудачный или остановленный запуск всё равно вызывает `Stop` в фоне.

<Tip>
Агент ждёт блокирующие хуки, поэтому медленный хук `PreToolUse` замедляет каждый вызов инструмента, а медленный хук `Stop` откладывает конец хода. Делайте их быстрыми, задавайте короткий `timeout` или выполняйте медленную работу в фоне (`command &`).
</Tip>

Блокирующие хуки получают обычную [полезную нагрузку события](#полезная-нагрузка-события) плюс поля Claude Code на верхнем уровне:

```json
{
  "hook_event_name": "PreToolUse",
  "session_id": "Qx2...",
  "cwd": "/Users/you/project",
  "tool_name": "bash",
  "tool_input": { "command": "rm -rf build" },
  "tool_use_id": "call_1",
  "event": "PreToolUse",
  "sourceEvent": "agent_tool_step_changed",
  "params": { "toolName": "bash", "status": "running", "sessionId": "Qx2..." },
  "timestamp": 1742313600000
}
```

`Stop` и `SubagentStop` вместо полей инструмента получают `stop_hook_active` и `last_assistant_message`. Хуки команд выполняются в рабочем каталоге агента.

### Блокировка опасной команды

```bash
#!/bin/bash
# ~/.enconvo/hooks/guard.sh
COMMAND=$(jq -r '.tool_input.command // empty')
if echo "$COMMAND" | grep -q 'rm -rf /'; then
  echo "Deleting from the filesystem root is not allowed." >&2
  exit 2
fi
```

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "bash",
        "hooks": [{ "type": "command", "command": "bash ~/.enconvo/hooks/guard.sh", "timeout": 5000 }]
      }
    ]
  }
}
```

### Заставьте агента запускать тесты перед завершением

```bash
#!/bin/bash
# ~/.enconvo/hooks/require-tests.sh
[ "$(jq -r '.stop_hook_active')" = "true" ] && exit 0
echo '{"decision":"block","reason":"Run the test suite and fix any failures before you finish."}'
```

## Полезная нагрузка события

Хуки команд получают этот JSON в stdin. HTTP-хуки получают тот же JSON как тело запроса.

```json
{
  "event": "UserPromptSubmit",
  "fullEvent": "event-UserPromptSubmit",
  "sourceEvent": "run_status_changed",
  "sourceFullEvent": "event-run_status_changed",
  "params": {
    "commandKey": "agent|main",
    "runStatus": "running"
  },
  "timestamp": 1742313600000
}
```

| Поле | Описание |
|-------|-------------|
| `event` | Короткое название события. |
| `fullEvent` | Внутреннее название события с префиксом `event-`. |
| `sourceEvent` | Исходное событие Enconvo, породившее это событие хука, когда событие сопоставлено для совместимости с Codex. |
| `sourceFullEvent` | Исходное внутреннее название события с префиксом `event-`. |
| `params` | Полезная нагрузка, специфичная для события. |
| `timestamp` | Метка времени Unix в миллисекундах. |

Фоновые хуки получают и поля Claude Code: `hook_event_name`, `session_id`, когда она есть у события, а для событий инструментов — `tool_name`, `tool_input` и `tool_use_id`.

## Доступные события

| Событие | Параметры | Когда |
|-------|--------|------|
| `SessionStart` | `{ command, commandKey }` | Создаётся новый сеанс чата. |
| `UserPromptSubmit` | `{ commandKey, runStatus, status?, sessionId? }` | Запуск агента, чата или бота начинается с ввода пользователя. |
| `PreToolUse` | `{ toolCallId, toolName, toolTitle?, status, sessionId?, commandKey? }` | Начинается вызов инструмента. Блокирующее во время запусков агента. |
| `PermissionRequest` | `{ toolCallId, toolName, toolTitle?, status, sessionId?, commandKey? }` | Вызов инструмента доходит до состояния разрешения или отказа. |
| `PostToolUse` | `{ toolCallId, toolName, toolTitle?, status, sessionId?, commandKey? }` | Вызов инструмента завершается успешно, с ошибкой, полностью или отклоняется. |
| `Stop` | `{ commandKey, runStatus, status?, sessionId? }` | Запуск агента, чата или бота достигает конечного статуса. Блокирующее, когда агент завершает работу штатно. |
| `SubagentStop` | `{ commandKey, runStatus, status?, sessionId? }` | Субагент вот-вот завершится. Блокирующее. Субагенты не вызывают `Stop`. |

Прежние названия Enconvo, такие как `run_status_changed` и `agent_tool_step_changed`, по-прежнему работают, поэтому существующие файлы хуков не нужно переносить сразу.

## Рецепты

### Уведомление macOS, когда агент терпит неудачу

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "STATUS=$(cat | jq -r '.params.runStatus // .params.status') && [ \"$STATUS\" = \"failed\" ] && osascript -e 'display notification \"An agent failed\" with title \"EnConvo\"'"
          }
        ]
      }
    ]
  }
}
```

### Журнал изменений статуса агента

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "jq -c '{time: (.timestamp / 1000 | strftime(\"%Y-%m-%d %H:%M:%S\")), agent: .params.commandKey, status: (.params.runStatus // .params.status)}' >> ~/.enconvo/agent-status.log"
          }
        ]
      }
    ]
  }
}
```

### Журнал вызовов инструментов агента

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.params | \"\\(.status) \\(.toolName) \\(.toolCallId)\"' >> ~/.enconvo/agent-tools.log"
          }
        ]
      }
    ]
  }
}
```

### Отправка в Slack

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "http",
            "url": "https://hooks.slack.com/services/YOUR/WEBHOOK/URL"
          }
        ]
      }
    ]
  }
}
```

### Собственный скрипт

Создайте скрипт, который читает полезную нагрузку события из stdin:

```bash
#!/bin/bash
# ~/.enconvo/hooks/on-status-change.sh
INPUT=$(cat)
STATUS=$(echo "$INPUT" | jq -r '.params.runStatus // .params.status')
AGENT=$(echo "$INPUT" | jq -r '.params.commandKey')

echo "[$(date)] $AGENT -> $STATUS" >> /tmp/enconvo-hooks.log

if [ "$STATUS" = "failed" ]; then
  osascript -e "display notification \"$AGENT failed\" with title \"EnConvo\""
fi
```

Сошлитесь на него в `~/.enconvo/hooks.json`:

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.enconvo/hooks/on-status-change.sh"
          }
        ]
      }
    ]
  }
}
```

Сделайте скрипт исполняемым:

```bash
chmod +x ~/.enconvo/hooks/on-status-change.sh
```

## Устранение неполадок

| Проблема | Что делать |
| --- | --- |
| Хук не запустился | Проверьте, что `~/.enconvo/hooks.json` — корректный JSON, что ключ верхнего уровня совпадает с названием события и что команда работает, когда вы запускаете её сами. Если у вас остался `~/.config/enconvo/hooks.json`, он игнорируется, пока существует новый файл. |
| Вы не уверены, блокируют ли хуки Enconvo | Блокируют только `PreToolUse`, `Stop` и `SubagentStop`, во время запусков агента. Все остальные хуки работают по принципу «запустил и забыл». Если какой-либо хук завершается ошибкой или превышает тайм-аут, Enconvo записывает сбой в журнал и продолжает так, будто хука нет. |
| Хуки плагина не запускаются | Откройте плагин и нажмите **Разрешить хуки**. После обновления, изменившего их, проверьте их и разрешите снова. |
| Команда не находит скрипт или исполняемый файл | Используйте абсолютные пути. Раскрытие `~` оболочкой работает, когда команда выполняется через оболочку, но с абсолютными путями проще отлаживать. |

### Проверьте скрипт вручную

Передайте в скрипт образец полезной нагрузки через конвейер:

```bash
echo '{"event":"Stop","params":{"commandKey":"agent|main","runStatus":"failed"},"timestamp":1742313600000}' | bash ~/.enconvo/hooks/on-status-change.sh
```
