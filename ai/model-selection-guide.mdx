Use the model picker in Enconvo as the current list of models your configured provider can use. Model availability, limits, and pricing change; a model name alone does not establish access or capabilities.

## Choose by task

| Task | Check before choosing |
| --- | --- |
| Quick rewrite or short answer | Latency, output quality, and cost |
| Multi-step Agent work | Reliable tool calling and suitable reasoning support |
| Screenshot or image question | Image input support |
| Long document | Supported context length and how the document is extracted |
| Private/offline work | Local inference plus local processing for any supporting tools |
| Voice conversation | [Realtime Voice](/features/live-voice) access, configured separately |
| Image or video creation | The appropriate generation provider, not merely a chat model |

## Defaults, projects, and conversations

In current builds, selecting a model in a top-level **New chat** sets the Agent’s default. Starting a new chat inside a project uses that project’s own model preference. Once created, a chat keeps its selected model and reasoning effort until you change them in that chat.

Existing chats without an explicit override, and IM channels, can continue to follow the Agent default. Check the model shown in the conversation before sending a request if you have just changed a default elsewhere.

## Reasoning and generation controls

Reasoning effort changes how a supported model approaches a task and can affect latency and usage. Temperature and other generation controls vary by model; use the controls available in your selected provider rather than assuming all providers share the same range or settings.

## Compare fairly

Try the same small, representative task on two candidate models. Check correctness, tool completion, latency, and usage. For important work, validate the result against the source material rather than judging only fluency.
