Chaque fournisseur que vous utilisez a besoin d’un identifiant : une clé API, ou une connexion à un forfait que vous payez déjà. Vous l’ajoutez sur la page Réglages propre au fournisseur, et Enconvo le conserve dans un profil de fournisseur que chaque fonction utilisant ce fournisseur partage. **Réglages → Gestion des identifiants** montre tous vos identifiants au même endroit.

## Ajouter un fournisseur

<Steps>
  <Step title="Ouvrir une catégorie">
    Ouvrez la page Réglages de ce que vous voulez utiliser, par exemple **Réglages → Modèle d’IA**, **Réglages → Génération d’images** ou **Réglages → Synthèse vocale**.
  </Step>
  <Step title="Choisir le fournisseur">
    Sélectionnez un fournisseur. Pour configurer une deuxième copie, pour une autre clé ou un autre compte, choisissez **Ajouter un nouveau fournisseur**.
  </Step>
  <Step title="Choisir comment se connecter">
    Sous **Authentification**, choisissez **Clé API**, ou **Abonnement** quand le fournisseur vous laisse utiliser un forfait que vous payez.
  </Step>
  <Step title="Ajouter l’identifiant">
    Collez votre clé API, ou terminez la connexion du fournisseur.
  </Step>
  <Step title="Le tester">
    Cliquez sur **Valider** si la page l’affiche, choisissez un modèle, et essayez une courte demande.
  </Step>
</Steps>

Une clé API est facturée sur le compte API du fournisseur. Un abonnement utilise l’usage inclus dans votre forfait et ses limites. Le texte sous **Authentification** indique lequel la page utilise.

## Profils partagés

Un profil de fournisseur, comme **OpenAI 2**, contient la clé API du fournisseur et sa connexion d’abonnement, et apparaît dans chaque catégorie que le fournisseur prend en charge. Renommer ou supprimer le profil le change dans toutes ces catégories, pas seulement sur la page où vous êtes.

Chaque catégorie garde ses propres réglages de modèle, de voix et de génération. Une nouvelle clé API, en revanche, atteint chaque fonction qui utilise le profil : testez ces fonctions après l’avoir changée.

Ce qu’un fournisseur propose varie selon la catégorie. Une connexion qui fonctionne pour le chat d’IA ne signifie pas que l’API vocale temps réel du fournisseur est incluse. Quand une catégorie n’accepte qu’une clé API, sa page le dit et nomme les catégories où l’abonnement fonctionne.

## Vérifier l’usage d’un forfait

Une connexion d’abonnement montre votre compte et ce qu’il reste de votre forfait. Une valeur comme **% restant** est l’allocation qu’il vous reste. Ouvrez le menu de la carte du compte et choisissez **Actualiser l’usage** pour le mettre à jour, ou **Reconnecter** pour vous connecter à nouveau.

Quand Claude ou Codex vous a accordé des réinitialisations de limite gratuites, une carte d’abonnement Claude ou ChatGPT affiche **Réinitialisations de limite gratuites** : combien vous en avez et jusqu’à quand. Cliquez sur **Utiliser une réinitialisation** et confirmez pour remplir à nouveau vos limites. S’il y en a plusieurs, la carte les liste, et vous utilisez celle que vous choisissez.

Quand aucun usage ne s’affiche, cela ne signifie pas que votre usage est illimité.

## Gérer vos identifiants

Ouvrez **Réglages → Gestion des identifiants**. La liste groupe les identifiants par profil de fournisseur, puis montre les **Clés inutilisées** : des clés qu’aucun fournisseur n’utilise.

- Tapez dans **Rechercher des fournisseurs...** pour en trouver un.
- Cliquez sur **Ajouter un nouvel identifiant** pour créer un autre identifiant pour un service que vous choisissez.
- Pour supprimer un identifiant, survolez-le et cliquez sur l’icône de corbeille. Si un connecteur de clé API utilise cette clé, la confirmation le nomme, et **Supprimer et déconnecter** le déconnecte jusqu’à ce que vous lui donniez une autre clé.
- Cliquez sur **Nettoyer** en bas de la liste pour supprimer d’un coup toutes les clés inutilisées. Le bouton indique combien il y en a, et la confirmation les liste d’abord. Enconvo ne supprime jamais les clés inutilisées de lui-même.

Cliquez sur un identifiant pour ajouter ou changer sa clé. **Utilisé par** liste les fonctions qui s’en servent, comme **Modèle d’IA** ou **Synthèse vocale** ; cliquez sur l’une pour ouvrir cette page Réglages.

Les identifiants propres à un profil n’ont pas de bouton de suppression ici. Ils partent quand vous supprimez le fournisseur.

Deux autres groupes apparaissent quand vous en avez : **Autres services**, pour les clés de services pour lesquels Enconvo n’a pas de fournisseur, et **Connexions**, pour les connexions de sites et d’apps que vous avez enregistrées.

## Quand un agent a besoin d’une clé

Quand une tâche a besoin de la clé API d’un service, l’agent affiche une carte **Connecter** dans le chat au lieu de vous demander de coller la clé. La clé va dans Gestion des identifiants, pas dans la conversation, et les chats suivants l’utilisent sans redemander.

Pour un service pour lequel Enconvo n’a pas de fournisseur, la carte montre l’hôte auquel la clé sera envoyée. La clé est enregistrée sous **Autres services**, et l’agent ne peut l’utiliser que dans des requêtes vers cet hôte.

L’agent ne détient jamais la clé lui-même : il nomme l’identifiant enregistré, et partout où une requête ou une commande afficherait la clé, on lit `[redacted]`.

Dans un chat Téléphone, la carte **Connecter** s’affiche sur votre iPhone, et la clé est enregistrée dans Gestion des identifiants sur votre Mac. Dans un chat de messagerie instantanée, l’agent ne demande jamais de clé ; il envoie un lien qui ouvre le chat dans Enconvo à la place.

Si vous collez quand même une clé API dans un message, Enconvo l’enregistre dans Gestion des identifiants et la remplace par `[redacted]` dans le chat enregistré, pour que les demandes suivantes et vos autres appareils ne la portent pas. Une nouvelle clé que vous collez pour un service qui en a déjà une remplace la clé enregistrée.

## Connexions de sites et d’apps

Quand une tâche de navigateur arrive sur une page de connexion, une carte demande une fois le nom d’utilisateur et le mot de passe. Enconvo les remplit uniquement sur ce site, et l’agent ne voit jamais le mot de passe. Les connexions enregistrées apparaissent sous **Connexions**. Décochez **Mémoriser cette connexion** pour ne l’utiliser que pour cette connexion.

Quand la connexion d’une app Mac a besoin d’un mot de passe, la carte nomme l’app. Enconvo tape le nom d’utilisateur et le mot de passe uniquement dans cette app, et le mot de passe uniquement dans un champ qui masque ce que vous tapez.

## Points d’accès personnalisés

Les fournisseurs **OpenAI Compatible** et **Anthropic Compatible** ont un champ d’URL de base d’API pour votre propre serveur. Certains fournisseurs intégrés gardent leur réglage de point d’accès dans **Gestion des identifiants**. Pour un serveur de modèles sur un autre ordinateur, voir [Modèles locaux](/fr/ai/local-llm).

Seules les fenêtres d’Enconvo peuvent changer où une clé enregistrée est envoyée : l’adresse d’un fournisseur ou d’un identifiant, ou l’usage d’une clé enregistrée par un serveur MCP. Les autres programmes qui utilisent l’API locale, le téléphone et les agents sont refusés.

## Comment les clés sont conservées

- Chaque clé et connexion enregistrée est chiffrée avec une clé qui reste dans le Trousseau de ce Mac, donc une copie du dossier de réglages d’Enconvo ne peut pas être lue sur un autre ordinateur. Si vous revenez à une version plus ancienne d’Enconvo, vous saisissez à nouveau vos clés.
- Un autre programme qui demande les réglages à l’[API locale](/fr/advanced/cli-local-api) d’Enconvo reçoit `[hidden]` à la place de chaque clé. Un plugin du store ne peut utiliser que ses propres clés et l’identifiant choisi dans ses réglages.
- Seul le code qu’Enconvo a installé et qui n’a pas été modifié peut ouvrir les clés enregistrées. Les Réglages affichent et vérifient les clés comme avant.

## Dépannage

| Problème | Que faire |
| --- | --- |
| La validation échoue | Vérifiez le profil sélectionné, la méthode d’authentification, le point d’accès, et que votre compte fournisseur a bien l’accès. |
| Une fonction marche et une autre échoue | Vérifiez que le compte prend en charge cette fonction et ce modèle. La page le dit quand une catégorie n’accepte qu’une clé API. |
| Quelque chose a cessé de fonctionner après un changement de clé | Le profil est partagé. Testez les autres catégories qui l’utilisent. |
| La zone d’usage affiche **Reconnecter** | La connexion a expiré. Cliquez sur **Reconnecter** et connectez-vous à nouveau. |
