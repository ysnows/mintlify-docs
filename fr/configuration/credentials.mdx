Chaque fournisseur que vous utilisez a besoin d’un identifiant : une clé API, ou une connexion à un abonnement que vous payez déjà. Vous l’ajoutez sur la page Réglages du fournisseur, et Enconvo le conserve dans un profil de fournisseur que toutes les fonctionnalités utilisant ce fournisseur partagent. **Réglages → Gestion des identifiants** affiche tous vos identifiants au même endroit.

## Ajouter un fournisseur

<Steps>
  <Step title="Ouvrir une catégorie">
    Ouvrez la page Réglages de ce que vous voulez utiliser, par exemple **Réglages → Modèle d’IA**, **Réglages → Génération d’images** ou **Réglages → Synthèse vocale**.
  </Step>
  <Step title="Choisir le fournisseur">
    Sélectionnez un fournisseur. Pour en configurer une seconde copie, avec une autre clé ou un autre compte, choisissez **Ajouter un nouveau fournisseur**.
  </Step>
  <Step title="Choisir la méthode de connexion">
    Sous **Authentification**, choisissez **Clé API**, ou **Abonnement** lorsque le fournisseur permet d’utiliser un abonnement que vous payez.
  </Step>
  <Step title="Ajouter l’identifiant">
    Collez votre clé API, ou terminez la connexion du fournisseur.
  </Step>
  <Step title="Le tester">
    Cliquez sur **Valider** si la page l’affiche, choisissez un modèle et essayez une courte requête.
  </Step>
</Steps>

Une clé API est facturée sur le compte API du fournisseur. Un abonnement utilise la consommation incluse dans votre offre, avec ses limites. Le texte sous **Authentification** indique laquelle des deux la page utilise.

## Profils partagés

Un profil de fournisseur, tel que **OpenAI 2**, contient la clé API du fournisseur et sa connexion d’abonnement, et apparaît dans toutes les catégories que le fournisseur prend en charge. Renommer ou supprimer le profil le modifie dans toutes ces catégories, pas seulement sur la page où vous vous trouvez.

Chaque catégorie conserve son propre modèle, sa propre voix et ses propres réglages de génération. En revanche, une nouvelle clé API atteint toutes les fonctionnalités qui utilisent le profil : testez-les après l’avoir changée.

Ce qu’un fournisseur propose varie selon la catégorie. Une connexion qui fonctionne pour le chat IA ne signifie pas que l’API vocale en temps réel du fournisseur est incluse. Lorsqu’une catégorie n’accepte qu’une clé API, sa page le dit et nomme les catégories où l’abonnement fonctionne.

## Vérifier la consommation d’un abonnement

Une connexion d’abonnement affiche votre compte et ce qu’il reste de votre offre. Une valeur telle que **% restant** correspond à la part qu’il vous reste. Ouvrez le menu de la carte du compte et choisissez **Actualiser l’utilisation** pour la mettre à jour, ou **Reconnecter** pour vous connecter de nouveau.

Lorsque Claude ou Codex vous a accordé des réinitialisations de limite gratuites, la carte d’un abonnement Claude ou ChatGPT affiche **Réinitialisations de limite gratuites** : combien vous en avez et jusqu’à quand. Cliquez sur **Utiliser** et confirmez pour recharger vos limites. Si vous en avez plusieurs, la carte les liste et vous utilisez celle que vous choisissez.

Lorsqu’aucune consommation ne s’affiche, cela ne signifie pas que votre consommation est illimitée.

## Gérer vos identifiants

Ouvrez **Réglages → Gestion des identifiants**. La liste regroupe les identifiants par profil de fournisseur, puis affiche **Clés inutilisées** : les clés qu’aucun fournisseur n’utilise.

- Saisissez dans **Rechercher des fournisseurs…** pour en trouver un.
- Cliquez sur **Ajouter un nouvel identifiant** pour créer un autre identifiant pour un service que vous choisissez.
- Pour supprimer un identifiant, survolez-le et cliquez sur l’icône de corbeille. Si un Connector à clé API utilise cette clé, la confirmation le nomme, et **Supprimer et déconnecter** le déconnecte jusqu’à ce que vous lui donniez une autre clé.
- Cliquez sur **Nettoyer** en bas de la liste pour supprimer d’un coup toutes les clés inutilisées. Le bouton indique combien il y en a, et la confirmation les énumère d’abord. Enconvo ne supprime jamais de lui-même les clés inutilisées.

Cliquez sur un identifiant pour ajouter ou modifier sa clé. **Utilisé par** énumère les fonctionnalités qui en dépendent, telles que **Modèle d’IA** ou **Synthèse vocale** ; cliquez sur l’une d’elles pour ouvrir cette page des Réglages.

Les identifiants propres à un profil n’ont pas de bouton de suppression ici. Ils disparaissent lorsque vous supprimez le fournisseur.

Deux autres groupes apparaissent lorsque vous en avez : **Autres services**, pour les clés de services pour lesquels Enconvo n’a pas de fournisseur, et **Identifiants de sites**, pour les connexions aux sites web et aux apps que vous avez enregistrées.

## Quand un agent a besoin d’une clé

Lorsqu’une tâche a besoin de la clé API d’un service, l’agent affiche une carte **Connecter** dans le chat au lieu de vous demander de coller la clé. La clé va dans la Gestion des identifiants, pas dans la conversation, et les chats suivants l’utilisent sans redemander.

Pour un service pour lequel Enconvo n’a pas de fournisseur, la carte affiche l’hôte auquel la clé sera envoyée. La clé est enregistrée sous **Autres services**, et l’agent ne peut l’utiliser que dans les requêtes vers cet hôte.

L’agent ne détient jamais la clé lui-même : il désigne l’identifiant enregistré, et partout où une requête ou une commande afficherait la clé, on lit `[redacted]`.

Dans un chat Phone, la carte **Connecter** s’affiche sur votre iPhone, et la clé est enregistrée dans la Gestion des identifiants sur votre Mac. Dans un chat de messagerie instantanée, l’agent ne demande jamais de clé ; il envoie à la place un lien qui ouvre le chat dans Enconvo.

Si vous collez tout de même une clé API dans un message, Enconvo l’enregistre dans la Gestion des identifiants et la remplace par `[redacted]` dans le chat enregistré, afin que les requêtes suivantes et vos autres appareils ne la contiennent pas. Une nouvelle clé que vous collez pour un service qui en a déjà une remplace la clé enregistrée.

## Connexions aux sites web et aux apps

Lorsqu’une tâche de navigateur arrive sur une page de connexion, une carte demande une seule fois le nom d’utilisateur et le mot de passe. Enconvo les saisit sur ce site uniquement, et l’agent ne voit jamais le mot de passe. Les connexions enregistrées apparaissent sous **Identifiants de sites**. Décochez **Mémoriser cet identifiant** pour ne l’utiliser que pour cette connexion.

Lorsque la connexion d’une app Mac demande un mot de passe, la carte nomme l’app. Enconvo saisit le nom d’utilisateur et le mot de passe dans cette app uniquement, et le mot de passe seulement dans un champ qui masque ce que vous tapez.

## Points de terminaison personnalisés

Les fournisseurs **Compatible OpenAI** et **Compatible Anthropic** ont un champ d’URL de base de l’API pour votre propre serveur. Certains fournisseurs intégrés conservent leur réglage de point de terminaison dans **Gestion des identifiants**. Pour un serveur de modèles sur un autre ordinateur, voir [Modèles locaux](/fr/ai/local-llm).

Seules les fenêtres d’Enconvo peuvent changer l’endroit où une clé enregistrée est envoyée : l’adresse d’un fournisseur ou d’un identifiant, ou l’utilisation d’une clé enregistrée par un serveur MCP. Les autres programmes qui utilisent l’API locale, le téléphone et les agents sont refusés.

## Comment les clés sont conservées

- Chaque clé et chaque connexion enregistrée est chiffrée avec une clé qui reste dans le trousseau de ce Mac, si bien qu’une copie du dossier de réglages d’Enconvo ne peut pas être lue sur un autre ordinateur. Si vous revenez à une version plus ancienne d’Enconvo, vous saisissez de nouveau vos clés.
- Un autre programme qui demande les réglages à l’[API locale](/fr/advanced/cli-local-api) d’Enconvo reçoit `[hidden]` à la place de chaque clé. Un plugin du store ne peut utiliser que ses propres clés et l’identifiant choisi dans ses réglages.
- Seul le code qu’Enconvo a installé et qui n’a pas été modifié peut ouvrir les clés enregistrées. Les Réglages affichent et vérifient les clés comme auparavant.

## Dépannage

| Problème | Que faire |
| --- | --- |
| La validation échoue | Vérifiez le profil sélectionné, la méthode d’authentification, le point de terminaison, et que votre compte chez le fournisseur y a accès. |
| Une fonctionnalité marche et une autre échoue | Vérifiez que le compte prend en charge cette fonctionnalité et ce modèle. La page indique quand une catégorie n’accepte qu’une clé API. |
| Quelque chose a cessé de fonctionner après un changement de clé | Le profil est partagé. Testez les autres catégories qui l’utilisent. |
| La zone de consommation affiche **Reconnecter** | La connexion a expiré. Cliquez sur **Reconnecter** et connectez-vous de nouveau. |
