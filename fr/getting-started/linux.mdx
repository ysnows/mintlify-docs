<Note>
Enconvo pour Linux est en bêta et sort sur le canal de mise à jour **Bêta**. Il est fait pour un usage quotidien, mais des choses peuvent encore changer d’une version à l’autre. Si quelque chose casse, dites-le-nous sur le [site de retours](https://feedback.enconvo.com).
</Note>

**Bêta actuelle : 2.5.13 Beta 3** (`2.5.13-beta-3`). Pour voir votre version, ouvrez **Réglages → Général → Mises à jour**. Sur un serveur, `enconvo update --check` l’affiche.

## Choisissez comment vous l’exécutez

| Vous avez | Ce que vous obtenez | Commencez ici |
| --- | --- | --- |
| Un bureau Linux (GNOME, KDE et d’autres) | L’app Enconvo avec sa Fenêtre de chat et ses fenêtres de Réglages | Installer sur un bureau |
| Un serveur ou un ordinateur cloud sans bureau | Enconvo en arrière-plan, utilisé depuis un navigateur sur votre propre ordinateur | Installer sur un serveur |

## Configuration requise

- **Intel/AMD 64 bits (x86-64).** Il n’y a pas encore de version ARM.
- **Ubuntu 22.04, Debian 12, RHEL 9, Amazon Linux 2023, ou plus récent.** Rocky Linux et AlmaLinux 9 comptent comme RHEL 9. Les systèmes plus anciens ne peuvent pas exécuter Enconvo : leur bibliothèque C est trop ancienne.
- **Mémoire :** nous recommandons au moins 2 Go libres, et 4 Go si l’agent utilise un navigateur.
- **Un compte utilisateur normal.** Exécutez Enconvo en tant que vous-même, pas en root, parce que son agent lance des commandes avec les droits de cet utilisateur. Sur un serveur, créez un utilisateur juste pour Enconvo.

## Télécharger la Bêta

La Bêta existe sous trois formes : un `.deb` pour Debian et Ubuntu, un `.rpm` pour Fedora, RHEL, Rocky, AlmaLinux et openSUSE, et un `.tar.gz` portable pour le reste. Chaque nom de fichier porte le numéro de version de la Bêta. Pour 2.5.13 Beta 3, ce sont :

- `enconvo_2.5.13~beta~3_amd64.deb`
- `enconvo-2.5.13~beta~3-1.x86_64.rpm`
- `Enconvo-2.5.13-beta-3-linux-x64.tar.gz`

Ces commandes trouvent la Bêta la plus récente et la téléchargent.

<Tabs>
  <Tab title="Debian, Ubuntu">
    ```bash
    FEED=https://file.enconvo.com/linux-x64/beta
    FILE=$(curl -fsSL $FEED/latest.json | grep -o 'enconvo_[^"]*\.deb')
    curl -fLO "$FEED/$FILE"
    ```
  </Tab>
  <Tab title="Fedora, RHEL, Rocky, AlmaLinux, openSUSE">
    ```bash
    FEED=https://file.enconvo.com/linux-x64/beta
    FILE=$(curl -fsSL $FEED/latest.json | grep -o 'enconvo-[^"]*\.rpm')
    curl -fLO "$FEED/$FILE"
    ```
  </Tab>
  <Tab title="Portable .tar.gz">
    ```bash
    FEED=https://file.enconvo.com/linux-x64/beta
    FILE=$(curl -fsSL $FEED/latest.json | grep -o 'Enconvo-[^"]*\.tar\.gz')
    curl -fLO "$FEED/$FILE"
    tar xzf "$FILE"
    ```

    Cela décompresse un dossier nommé `Enconvo`. Lancez-le depuis là, et utilisez `./Enconvo/enconvo` partout où cette page dit `enconvo`.
  </Tab>
</Tabs>

## Installer sur un bureau

Le gestionnaire de paquets installe aussi ce dont les fenêtres de l’app ont besoin, GTK et WebKitGTK.

<Tabs>
  <Tab title="Debian, Ubuntu">
    ```bash
    sudo apt install ./enconvo_*.deb
    ```
  </Tab>
  <Tab title="Fedora, openSUSE">
    ```bash
    sudo dnf install ./enconvo-*.rpm      # Fedora
    sudo zypper install ./enconvo-*.rpm   # openSUSE
    ```
  </Tab>
  <Tab title="Portable .tar.gz">
    Installez GTK 3 et WebKitGTK 4.1 depuis votre distribution, puis démarrez Enconvo depuis son dossier :


    ```bash
    ./Enconvo/enconvo
    ```
  </Tab>
</Tabs>

RHEL 9, Rocky Linux 9 et AlmaLinux 9 ne fournissent pas WebKitGTK 4.1, dont les fenêtres de l’app ont besoin, donc sur ces systèmes exécutez Enconvo comme sur un serveur.

Ouvrez **Enconvo** depuis le menu des applications, connectez-vous et continuez avec le [Démarrage rapide](/fr/quickstart). L’icône d’Enconvo apparaît dans la zone de notification là où le bureau en affiche une.

## Installer sur un serveur

Un serveur n’a pas besoin des bibliothèques de bureau, donc laissez-les de côté.

<Steps>
  <Step title="Installer le paquet">
    <Tabs>
      <Tab title="Debian, Ubuntu">
        ```bash
        sudo apt install --no-install-recommends ./enconvo_*.deb
        ```
      </Tab>
      <Tab title="Fedora, RHEL, Rocky, AlmaLinux">
        ```bash
        sudo dnf install --setopt=install_weak_deps=False ./enconvo-*.rpm
        ```
      </Tab>
      <Tab title="openSUSE">
        ```bash
        sudo zypper install --no-recommends ./enconvo-*.rpm
        ```
      </Tab>
      <Tab title="Portable .tar.gz">
        Rien à installer : utilisez le dossier `Enconvo` que vous avez décompressé.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Démarrer Enconvo comme service">
    ```bash
    enconvo service install --web
    ```

    Enconvo tourne maintenant en arrière-plan et sert sa Fenêtre de chat et ses Réglages comme un site web sur cette machine seulement, à `127.0.0.1:54580`. Il redémarre au démarrage du serveur. Si la commande dit qu’il ne tourne que tant que vous êtes connecté, lancez la commande `sudo loginctl enable-linger` qu’elle affiche.
  </Step>
  <Step title="Se connecter">
    ```bash
    enconvo login
    ```

    Enconvo affiche un code court. Ouvrez `enconvo.com/device` sur votre téléphone ou votre ordinateur, vérifiez que la page nomme votre compte, et approuvez le code dans les 10 minutes.
  </Step>
  <Step title="Ouvrir Enconvo depuis votre ordinateur">
    Lancez ceci sur votre propre ordinateur, puis laissez-le tourner :


    ```bash
    ssh -N -L 54580:127.0.0.1:54580 you@your-server
    ```

    Ouvrez [http://localhost:54580](http://localhost:54580) dans votre navigateur. Vous obtenez la même Fenêtre de chat et les mêmes Réglages que dans l’app de bureau.
  </Step>
</Steps>

Pour utiliser ce serveur depuis l’app Enconvo sur votre téléphone, lancez `enconvo companion pair --phone` et scannez le code affiché. Voir [Associer votre téléphone](/fr/integrations/pair-your-phone).

### Y accéder sans tunnel SSH

Le tunnel est le moyen le plus sûr d’entrer, parce que rien sur le serveur n’est ouvert au réseau. Le site a tous les droits de votre compte et peut atteindre les fichiers du serveur, donc quiconque peut l’ouvrir peut utiliser les deux.

Pour l’ouvrir directement depuis d’autres ordinateurs, par exemple sur un réseau privé ou un VPN :


```bash
enconvo service install --web 0.0.0.0:54580
enconvo service url
```

`enconvo service url` affiche l’adresse avec son jeton de connexion. Gardez cette adresse privée, et n’exposez pas ce port à Internet.

Pour une adresse publique, placez un proxy inverse avec HTTPS devant Enconvo et indiquez à Enconvo l’adresse qu’il sert :


```bash
enconvo service install --web --web-url https://enconvo.example.com
```

Avec HTTPS, le site peut aussi être installé comme une app sur votre téléphone ou votre ordinateur.

## Utiliser Contrôle du navigateur sur un serveur

L’agent peut naviguer sur un serveur sans écran : Enconvo démarre son propre navigateur sans interface, appelé Enconvo Browser, la première fois que l’agent en a besoin. Installez d’abord Chromium.

<Tabs>
  <Tab title="Debian">
    ```bash
    sudo apt install chromium
    ```
  </Tab>
  <Tab title="Ubuntu">
    ```bash
    sudo snap install chromium
    ```
  </Tab>
  <Tab title="Fedora">
    ```bash
    sudo dnf install chromium
    ```
  </Tab>
  <Tab title="RHEL, Rocky, AlmaLinux">
    Chromium vient d’[EPEL](https://docs.fedoraproject.org/en-US/epel/) :


    ```bash
    sudo dnf install epel-release
    sudo dnf install chromium
    ```
  </Tab>
</Tabs>

Demandez ensuite à l’agent, par exemple : « Ouvre news.ycombinator.com et dis-moi la première histoire. »

Enconvo Browser garde ses propres connexions. Quand un site a besoin de vous, pour une connexion ou une vérification, l’agent vous donne une vue en direct de la page dans votre navigateur, où vous pouvez cliquer et taper vous-même. Elle se ferme après 30 minutes d’inactivité, et ramène ses onglets la fois suivante.

Une page que seul le serveur peut atteindre, comme un serveur de développement que l’agent a démarré sur `localhost`, s’ouvre aussi à côté de la discussion comme vue en direct, donc cela fonctionne à travers le tunnel SSH.

## Ce qui fonctionne où

| Fonction | Bureau Linux | Serveur |
| --- | --- | --- |
| Fenêtre de chat, Réglages | Oui | Oui, dans votre navigateur |
| Agents, outils, fichiers, documents, artefacts | Oui | Oui |
| Contrôle du navigateur | Oui | Oui, avec Chromium |
| Base de connaissances, Mémoire, Automatisations, Workflows | Oui | Oui |
| Modèles Enconvo Cloud, recherche web, OCR, création d’images, parole | Oui | Oui |
| Contrôle de l’ordinateur | Oui | Non : il n’y a pas d’écran à contrôler |
| Raccourcis globaux, Dictée, Notes vocales, Enregistrements, Gribouillage à l’écran, Captures d’apps, notifications | Oui | Non : ils ont besoin d’un bureau |

Sous Wayland, les raccourcis globaux ont besoin d’un bureau qui les propose aux apps.

Ces fonctions ne sont pas sur Linux : SmartBar, PopBar, Dynamic Island, Commande vocale, Avatar, Mascotte de bureau, Barre latérale de l’app, Conversation en direct et Sous-titrage. SmartBar, PopBar, Dynamic Island, Commande vocale, Avatar et Mascotte de bureau sont dans la [Bêta Windows](/fr/getting-started/windows).

Les modèles de discussion locaux tournent à partir de fichiers GGUF, sur les systèmes avec glibc 2.38 ou plus récent. Les modèles MLX ont besoin d’un Mac.

## Votre compte sur Linux

Si votre compte utilise aussi l’[app iPhone](/fr/integrations/iphone-app), vos choix par défaut de discussion, de parole et d’image suivent votre compte sur cet ordinateur. Un fournisseur qui tourne sur votre propre clé API ne suit pas, parce que les clés ne sont pas copiées. Ajoutez la clé dans **Réglages** sur cet ordinateur si vous voulez le même fournisseur ici.

Si l’horloge de votre serveur est dans un autre fuseau horaire que votre navigateur, Enconvo propose d’utiliser le vôtre pour les heures et les [Automatisations](/fr/workflows/scheduled-jobs).

## Mettre à jour

Une version Bêta reste sur le canal Bêta. Pour le changer, ouvrez **Réglages → Général** et réglez **Canal de mise à jour**. Voir [Mises à jour](/fr/configuration/updates).

Sur un bureau, utilisez **Mettre à jour** dans la Fenêtre de chat quand il apparaît. La version portable se remplace elle-même. Pour un `.deb` ou un `.rpm`, Enconvo télécharge le nouveau paquet dans votre dossier Téléchargements, et vous l’installez comme dans Installer sur un bureau.

Sur un serveur :


```bash
enconvo update --check   # is there a newer version?
enconvo update           # download and check it
```

Si vous avez installé le `.deb` ou le `.rpm`, `enconvo update` télécharge le nouveau paquet et affiche la commande pour l’installer en root. Lancez cette commande, puis redémarrez le service :


```bash
systemctl --user restart enconvo
```

Si vous lancez le `.tar.gz` portable, `enconvo update` remplace le dossier et redémarre son service pour vous. Si la nouvelle version ne démarre pas, il remet l’ancienne.

## Dépannage

| Ce que vous voyez | Que faire |
| --- | --- |
| `enconvo` dit que l’app de bureau a besoin de GTK 3 et de WebKitGTK 4.1 | Sur un bureau, installez les paquets qu’il nomme. Sur un serveur, ou sur RHEL 9, utilisez `enconvo service install --web` |
| `GLIBC_2.34 not found`, ou un message listant les systèmes pris en charge | Le système est trop ancien : utilisez-en un de la configuration requise |
| `dnf` dit `nothing provides libwebkit2gtk-4.1.so.0` | Vous avez un paquet plus ancien. Installez la Bêta actuelle avec la commande serveur |
| Enconvo s’arrête quand vous vous déconnectez du serveur, ou ne démarre pas après un redémarrage | Lancez `sudo loginctl enable-linger "$USER"` |
| `localhost:54580` ne s’ouvre pas | Vérifiez que la commande `ssh -L` tourne encore, et que `systemctl --user status enconvo` dit active |
| Le site demande un jeton | Lancez `enconvo service url` sur le serveur et ouvrez l’adresse affichée |
| L’agent dit qu’il ne peut pas démarrer Enconvo Browser | Installez Chromium. Google Chrome 137 et les versions suivantes ne peuvent pas charger l’extension dont Enconvo Browser a besoin |
| Le code a expiré | Relancez `enconvo login` pour en obtenir un nouveau |

Pour lire le journal d’Enconvo sur un serveur :


```bash
journalctl --user -u enconvo -n 100
```

## Retirer Enconvo


```bash
enconvo service uninstall
sudo apt remove enconvo     # Debian, Ubuntu
sudo dnf remove enconvo     # Fedora, RHEL, Rocky, AlmaLinux
sudo zypper remove enconvo  # openSUSE
```

Vos réglages et vos discussions restent dans `~/.config/enconvo`. Supprimez ce dossier pour les retirer aussi.
