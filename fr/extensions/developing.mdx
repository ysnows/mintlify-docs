---
title: "Développer des extensions"
description: "Créez un plugin Enconvo avec une commande TypeScript et une route Local API, essayez-le dans l’app et publiez-le dans la boutique de plugins."
---

Ce guide s’adresse aux développeurs qui veulent ajouter leurs propres commandes à Enconvo. Vous créez un plugin avec une commande et une route Local API, vous l’intégrez à Enconvo par une compilation, vous le testez, puis vous le publiez dans la boutique de plugins.

Un plugin Enconvo est un paquet ESM dont les métadonnées sont dans `package.json`, les commandes sous `src/` et les routes d’API facultatives sous `src/api/`. Les commandes s’exécutent via l’environnement d’exécution des extensions d’Enconvo ; une commande de plugin est une fonction exportée par défaut, et non une classe qui implémente une interface `Command`.

## Avant de commencer

Il vous faut Node.js 18 ou version ultérieure, npm ou un autre gestionnaire de paquets, et Enconvo en cours d’exécution sur votre Mac.

## Démarrage rapide

Créez un projet de plugin dans un nouveau dossier :

```sh
npx -p @enconvo/api enconvo plugin create hello-enconvo
cd hello-enconvo
npm install
npm run dev
```

Le projet contient une commande (**Say Hello**), une route Local API, une icône provisoire et un README. `npm run dev` compile le plugin dans Enconvo et le recompile à chaque enregistrement. Cherchez **Say Hello** dans Enconvo pour l’exécuter.

Le nom du plugin vient du nom du dossier. Passez `--name`, `--title`, `--description` ou `--author` pour les définir vous-même. Choisissez un nom qu’aucun plugin installé dans Enconvo n’utilise déjà, car la compilation remplace les fichiers du plugin installé ; `plugin create` refuse de tels noms.

Pour créer un plugin qui s’installe aussi dans Codex et Claude Code, partez plutôt de `--template skills` (une compétence) ou de `--template mcp` (un serveur MCP). Voir [Plugin Formats](/extensions/plugin-formats) pour ces paquets, et [Installer des plugins](/fr/extensions/installing-plugins) pour essayer n’importe quel plugin depuis un dossier, GitHub ou une place de marché.

<Note>
`plugin create`, `plugin validate` et la publication pour examen nécessitent une version de `@enconvo/api` plus récente que 0.1.173. Si votre version ne les a pas, configurez le projet à la main comme décrit ci-dessous.
</Note>

## Configurer un projet à la main

```text
hello-enconvo/
├── package.json
├── tsconfig.json
├── src/
│   ├── hello.ts
│   └── api/
│       └── echo.ts
└── assets/
    └── icon.png
```

Créez `package.json` :

```json
{
  "$schema": "https://enconvo.com/schemas/extension.json",
  "name": "hello_enconvo",
  "version": "0.1.0",
  "title": "Hello Enconvo",
  "description": "A small example command and API.",
  "author": "Your Name",
  "icon": "icon.png",
  "type": "module",
  "categories": ["Productivity"],
  "commands": [
    {
      "name": "hello",
      "title": "Say Hello",
      "description": "Return a greeting for the input text.",
      "commandType": "command",
      "mode": "no-view"
    }
  ],
  "scripts": {
    "build": "enconvo plugin build",
    "dev": "enconvo plugin build --dev",
    "validate": "enconvo plugin validate"
  }
}
```

La première entrée de `categories` détermine la section où le plugin apparaît dans la page Plugins et dans la boutique : Productivity, Communication, Developer Tools, Data & Analytics, Finance, Creativity, Business & Operations, Education & Research ou Security.

Installez le SDK, puis les outils de compilation comme dépendances de développement :

```sh
npm install @enconvo/api
npm install --save-dev tsup typescript @types/node
```

`enconvo plugin build` compile votre code avec le `tsup` propre au plugin. Sans lui, la compilation n’a rien pour compiler ; les SDK récents s’arrêtent avec une erreur, et les anciens se terminent sans compiler vos commandes.

Créez `tsconfig.json` :

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["ES2023", "DOM"],
    "types": ["node"],
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true
  },
  "include": ["src"]
}
```

Placez une icône carrée PNG, JPEG, WebP ou GIF de 5 Mo au plus dans `assets/icon.png`.

## Ajouter une commande

`commands[].name` correspond au nom du fichier source. Placez ceci dans `src/hello.ts` :

```typescript
import { EnconvoResponse, type RequestOptions } from "@enconvo/api";

export default async function main(request: Request) {
  const options = await request.json() as RequestOptions;
  const name = String(options.input_text || "").trim() || "World";
  return EnconvoResponse.text(`Hello, ${name}!`);
}
```

La clé de la commande est `hello_enconvo|hello`. Les préférences d’exécution et les paramètres de la requête sont fusionnés dans le corps de la requête.

## Ajouter une route Local API

Les fichiers de `src/api/` sont découverts pendant la compilation et n’ont besoin d’aucune entrée dans `commands[]`. Placez ceci dans `src/api/echo.ts` :

```typescript
interface EchoParams {
  /** Text to return. @required */
  text: string;
}

/** Return the supplied text. */
export default async function main(request: Request) {
  const params = await request.json() as EchoParams;
  if (typeof params.text !== "string") {
    return Response.json({ error: "text must be a string" }, { status: 400 });
  }
  return Response.json({ text: params.text });
}
```

Cela devient `hello_enconvo/echo`. Un répertoire tel que `src/api/items/list.ts` devient `hello_enconvo/items/list`. Utilisez les [schémas de la Local API](/fr/advanced/cli-local-api) installés pour connaître la forme exacte des requêtes.

## Compiler et tester

```sh
npm run build
npm run dev
npx enconvo plugin generate-schema
```

Compilez depuis le répertoire du plugin. Une bonne compilation se termine par `ready - built extension successfully`. Si elle affiche une ligne `error`, corrigez ce qu’elle nomme et recompilez. Le mode développement surveille les fichiers pour les recompiler. Les schémas d’API sont générés dans le répertoire `skills/` du plugin.

Appelez la route pendant qu’Enconvo s’exécute :

```sh
curl -X POST http://localhost:54535/api/hello_enconvo/echo \
  -H "Content-Type: application/json" -d '{"text":"hi"}'
```

Testez un message d’accueil et une entrée d’API invalide avant de partager le plugin. Une compilation réussie ne teste ni les opérations natives ni tous les appels aux fournisseurs.

## Publier dans la boutique de plugins

```sh
npm run validate
npx enconvo plugin publish
```

### Vérifier le plugin

`plugin validate` vérifie le plugin selon les règles de la boutique sans rien envoyer ; [Validation Codes](/extensions/validation-codes) explique chaque problème signalé. Après une compilation, il indique aussi combien de fichiers contiendra le paquet et quels fichiers sont exclus. Il vérifie que :

- le nom n’utilise que des lettres, des chiffres, des points, des tirets et des tirets bas
- `version` ressemble à `1.2.3`
- le plugin a un titre
- l’icône est un PNG, JPEG, WebP ou GIF de 5 Mo au plus

Vous pouvez ajouter jusqu’à 8 captures d’écran dans un dossier `metadata/` ; la page du plugin dans la boutique les affiche sous sa description, dans l’ordre des noms de fichiers.

### L’envoyer pour examen

`plugin publish` compile le plugin et l’envoie avec le compte Enconvo auquel vous êtes connecté ; Enconvo doit donc être lancé et connecté. Enconvo examine chaque version avant qu’elle apparaisse dans la boutique. Tant qu’un nouveau plugin n’est pas approuvé, vous seul pouvez le voir ; pendant l’examen d’une mise à jour, la boutique continue de proposer la version précédente.

Augmentez `version` dans `package.json` à chaque mise à jour. Avant de compiler quoi que ce soit, `plugin publish` demande à la boutique quelle version elle a publiée, et s’arrête en indiquant la prochaine version à utiliser si la vôtre n’est pas supérieure. Une version en cours d’examen, ou refusée, peut être soumise de nouveau telle quelle ; le nouvel envoi la remplace.

Le paquet est fabriqué à partir du plugin compilé. Les fichiers `.env`, `node_modules`, les dossiers de gestion de versions et les archives `.zip` sont exclus, mais vérifiez qu’aucun autre identifiant ni fichier privé ne s’y retrouve.

Les relecteurs suivent les [Plugin Store Guidelines](/fr/extensions/publishing-guidelines). Ajoutez à `package.json` un objet `review` contenant les prompts qu’ils doivent essayer, et transmettez les informations de connexion d’un compte de démonstration avec `--review-notes` ; seuls les relecteurs les voient.
