Les plugins ajoutent à Enconvo des commandes, des fournisseurs, des outils et des routes d'API. Ouvrez **Réglages → Plugins** pour parcourir le catalogue, installer ce dont vous avez besoin et gérer ce que vous avez déjà.

## Trouver et installer un plugin

<Steps>
  <Step title="Ouvrir les plugins">
    Ouvrez **Réglages → Plugins**. Appuyez sur **⌘K** pour accéder directement à la zone de recherche.
  </Step>
  <Step title="Rechercher">
    Recherchez par tâche ou par nom de plugin. Quand rien ne correspond dans l'onglet actuel, la page propose les résultats d'un autre onglet.
  </Step>
  <Step title="Ouvrir sa page">
    Cliquez sur le plugin pour lire sa description, ce qu'il contient et ce dont il a besoin.
  </Step>
  <Step title="Installer et configurer">
    Cliquez sur **Installer** s'il n'est pas encore installé. Ajoutez ensuite les identifiants de fournisseur ou les réglages de commande qu'il demande.
  </Step>
  <Step title="L'utiliser">
    Cliquez sur **Essayer maintenant**, lancez l'une de ses commandes depuis SmartBar, ou activez ses outils pour l'Agent qui doit l'utiliser.
  </Step>
</Steps>

La page d'un plugin liste ses commandes et leurs réglages. Quand vous ouvrez les réglages d'une commande depuis un autre endroit d'Enconvo, vous arrivez sur cette commande à l'intérieur de son plugin.

Quand un plugin a une vue dans la Fenêtre de chat, comme [Email](/fr/integrations/email), sa page comporte un bouton **Ouvrir** qui ouvre cette vue à cet endroit : ce qu'elle contient, par exemple l'ajout d'une boîte mail, est à un clic. Un plugin avec plusieurs vues a plutôt un menu **Ouvrir**.

## La page Plugins

| Onglet | Ce qu'il affiche |
| --- | --- |
| **Enconvo** | Le catalogue par catégorie. **Installé** en haut liste les Connecteurs que vous avez connectés et les plugins que vous avez installés ou créés. **Ajouts récents** présente les nouvelles entrées. |
| **Intégré** | Les plugins fournis avec Enconvo : **Rechercher** contient les listes dans lesquelles vous cherchez depuis SmartBar, et **Contrôle** contient Utilisation de l’ordinateur et Utilisation du navigateur. |
| **Apps Mac** | Les apps de ce Mac que les agents peuvent utiliser, comme Calendrier, Mail et Notes. Pour en connecter une, macOS demande une autorisation, pas un compte. Voir [Apps Apple](/fr/integrations/apple-ecosystem). |
| **PopBar** | Les extensions compatibles PopClip qui ajoutent des boutons à [PopBar](/fr/features/popbar). |
| **Personnel** | Les plugins que vous avez créés ou importés, et ceux que vous avez publiés dans la boutique Enconvo. |

Pour ajouter un plugin extérieur au catalogue, utilisez **Créer un plugin** ou le menu **Ajouter** :

| Option | Ce qu'elle fait |
| --- | --- |
| **Créer un plugin** | Décrivez ce dont vous avez besoin, et l'agent écrit, teste et installe le plugin. |
| **Importer l’archive du plugin…** | Installe un fichier `.enconvo`, ou un plugin Claude Code ou Codex au format `.zip`. |
| **Ajouter depuis GitHub…** | Installe depuis un dépôt de plugin, ou depuis une place de marché Claude Code ou Codex. |
| **Ajouter un serveur MCP…** | Ouvre [Serveurs MCP](/fr/features/mcp). |
| **Ajouter une extension PopBar…** et **Importer depuis PopClip…** | Ajoutent des extensions PopClip à PopBar. |
| **Nouvelle compétence…** | Ouvre [Compétences](/fr/configuration/skills). |

Certains plugins de la boutique apportent les outils et les consignes d'un service entier :

- **Shopify** permet à l'agent de gérer votre boutique Shopify avec la CLI officielle de Shopify, en vous montrant chaque modification avant de l'appliquer. Il fonctionne avec plusieurs boutiques. L'agent demande de quelle boutique il s'agit quand vous ne la nommez pas, nomme la boutique dans chaque modification qu'il présente, et exécute une fois par boutique une modification destinée à plusieurs boutiques.
- **Expo** apporte les compétences officielles de l'équipe Expo et le serveur MCP Expo, à la place de l'ancien Connecteur Expo en lecture seule. L'agent crée, met à niveau et publie des apps Expo et React Native, lit vos builds EAS, vos journaux, vos plantages et vos avis, et ne lance des builds et des soumissions qu'après votre approbation de chacun. Une connexion Expo que vous avez déjà faite est conservée.

**Obsidian**, **Tailscale** et **Cloudflare** sont aussi des plugins de la boutique de plugins : installez-les depuis la page Plugins. Une copie que vous aviez déjà continue de fonctionner et se met à jour toute seule. Les agents savent dès le départ lesquels des plugins Obsidian, Tailscale, Cloudflare et Shopify vous avez installés.

Le [Catalogue des commandes intégrées](/fr/extensions/built-in-extensions) liste les familles de commandes documentées. Les entrées de la boutique et les plugins installés dans votre version peuvent différer de ce catalogue.

## Commandes, fournisseurs et outils

- Une **commande** est une action que vous lancez.
- Un **fournisseur** apporte une capacité, comme un modèle ou une voix.
- Un **outil** est une action qu'un Agent peut appeler.

Installer un plugin ne fait pas toujours de son fournisseur celui par défaut, et n'active pas forcément tous les outils pour tous les Agents.

Dans SmartBar, utilisez le sélecteur de commandes (`@` par défaut) ou cherchez le titre d'une commande. Le menu d'actions `/` sert à autre chose : ce n'est pas un préfixe pour les noms de plugins.

## Utiliser plusieurs comptes dans un Connecteur

Les Connecteurs qui se connectent depuis votre Mac, comme Notion, Webflow et Linear, peuvent gérer plusieurs comptes.

- Sur la page du Connecteur, sélectionnez **Connecter un autre compte** pour en ajouter un. **Comptes connectés** les liste tous.
- Sélectionnez **Définir par défaut** sur le compte avec lequel les agents doivent envoyer ou créer. Les agents lisent depuis tous les comptes.
- Nommez un compte dans une demande, par exemple « envoie-le depuis mon adresse professionnelle », et l'agent utilise celui-là.
- **Déconnecter** retire un compte ; **Déconnecter tous les comptes** les retire tous.

Dans l'Espace de travail d'un client, chaque Connecteur garde son propre compte par défaut, indiqué par **Par défaut dans** suivi du nom de l'Espace de travail. L'agent y utilise le compte de ce client, sauf si vous en nommez un autre.

## Désactiver, mettre à jour ou supprimer

Sur la page d'un plugin :

- L'interrupteur active ou désactive le plugin. Tant qu'il est désactivé, les agents ne peuvent ni le trouver ni l'utiliser, et SmartBar ne le liste pas et ne vous permet pas de le mentionner avec `@`. Ses réglages sont conservés.
- Le menu **⋯** contient **Réglages**, **Rechercher des mises à jour** et **Désinstaller**. Les plugins fournis avec Enconvo ne peuvent pas être désinstallés.

Avant de désinstaller un plugin, vérifiez les Agents, les flux de travail et les commandes personnalisées qui l'utilisent. Réinitialiser une commande restaure ses réglages. Réinitialiser un fournisseur partagé peut aussi modifier des identifiants que d'autres fonctionnalités utilisent ; voir [Identifiants](/fr/configuration/credentials).

## Partager un plugin

Vous pouvez partager un plugin que vous avez créé, ou dont le dossier se trouve sur ce Mac, avec un lien que toute personne à qui vous le donnez peut installer.

1. Sur la page du plugin, cliquez sur **Partager…**. Connectez-vous à votre compte Enconvo si Enconvo vous le demande.
2. Sous **Qui peut l’installer**, choisissez **Toute personne disposant du lien** ou **Boutique de plugins**.
3. Cliquez sur **Publier**, puis sur **Copier le lien** et envoyez le lien.

Enconvo vérifie et examine chaque version avant que le lien ne l'installe, et le lien ouvre la page du plugin sur enconvo.com. Chaque personne qui l'installe obtient sa propre copie ; ses données, vos clés et vos connexions restent sur votre Mac.

Pour modifier un plugin partagé, cliquez de nouveau sur **Partager…** : envoyez une version plus récente, changez **Qui peut l’installer**, ou cliquez sur **Arrêter le partage**. Le lien cesse alors de fonctionner, et les personnes qui avaient installé le plugin gardent leur copie. Si l'examen refuse une version, **Partager…** en indique la raison et propose **Corriger dans le chat**. Pour partager un [Espace](/fr/features/spaces), voir [Partager un Espace](/fr/features/spaces).

## Créer le vôtre

Utilisez le SDK TypeScript et la CLI décrits dans [Développer des extensions](/fr/extensions/developing). La CLI regroupe la compilation, l'installation, la génération de schémas et la publication sous `enconvo plugin`. Publier rend un plugin disponible en dehors de votre propre environnement de développement.

Enconvo installe aussi les plugins Codex, Claude Code et portables. Voir [Formats de plugin](/extensions/plugin-formats) et [Installer des plugins](/fr/extensions/installing-plugins).
