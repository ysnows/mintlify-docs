Les plugins ajoutent des commandes, des fournisseurs, des outils et des routes API à Enconvo. Ouvrez **Réglages → Plugins** pour chercher dans le catalogue, installer ce qu’il vous faut et gérer ce que vous avez déjà.

## Trouver et installer un plugin

<Steps>
  <Step title="Ouvrir Plugins">
    Ouvrez **Réglages → Plugins**. Appuyez sur **⌘K** pour aller à la zone de recherche.
  </Step>
  <Step title="Rechercher">
    Cherchez par la tâche ou le nom du plugin. Quand rien sur l’onglet actuel ne correspond, la page propose les résultats d’un autre onglet.
  </Step>
  <Step title="Ouvrir sa page">
    Cliquez sur le plugin pour lire sa description, ce qu’il contient et ce dont il a besoin.
  </Step>
  <Step title="Installer et le configurer">
    Cliquez sur **Installer** s’il n’est pas encore installé. Ajoutez ensuite les identifiants de fournisseur ou les réglages de commande qu’il demande.
  </Step>
  <Step title="L’utiliser">
    Cliquez sur **Essayer maintenant**, lancez une de ses commandes depuis SmartBar, ou activez ses outils pour l’Agent qui doit l’utiliser.
  </Step>
</Steps>

La page d’un plugin liste ses commandes et leurs réglages. Quand vous ouvrez les réglages d’une commande depuis ailleurs dans Enconvo, vous arrivez sur cette commande dans son plugin.

Quand un plugin a une vue dans la Fenêtre de chat, comme [E-mail](/fr/integrations/email), sa page a un bouton **Ouvrir** qui ouvre cette vue là, donc ce qui s’y trouve, comme ajouter une boîte, est à un clic. Un plugin avec plusieurs vues a un menu **Ouvrir** à la place.

## La page Plugins

| Onglet | Ce qu’il affiche |
| --- | --- |
| **Enconvo** | Le catalogue par catégorie. **Installé** en haut liste les Connecteurs que vous avez connectés et les plugins que vous avez installés ou créés. **Ajoutés récemment** montre les nouvelles entrées. |
| **Intégré** | Plugins fournis avec Enconvo : **Recherche** contient les listes que vous cherchez depuis SmartBar, et **Contrôle** contient Contrôle de l’ordinateur et Contrôle du navigateur. |
| **Apps Mac** | Apps de ce Mac que les agents peuvent utiliser, comme Calendrier, Mail et Notes. En connecter une demande une autorisation à macOS, pas un compte. Voir [Apps Apple](/fr/integrations/apple-ecosystem). |
| **PopBar** | Extensions compatibles PopClip qui ajoutent des boutons à [PopBar](/fr/features/popbar). |
| **Personnel** | Plugins que vous avez construits ou importés, et ceux que vous avez publiés dans la boutique Enconvo. |

Pour amener un plugin de l’extérieur du catalogue, utilisez **Créer un plugin** ou le menu **Ajouter** :

| Option | Ce qu’elle fait |
| --- | --- |
| **Créer un plugin** | Décrivez ce qu’il vous faut, et l’agent écrit, teste et installe le plugin. |
| **Téléverser l’archive du plugin…** | Installe un fichier `.enconvo`, ou un plugin Claude Code ou Codex `.zip`. |
| **Ajouter depuis GitHub…** | Installe depuis un dépôt de plugin, ou une marketplace Claude Code ou Codex. |
| **Ajouter un serveur MCP…** | Ouvre [Serveurs MCP](/fr/features/mcp). |
| **Ajouter une extension PopBar…** et **Importer depuis PopClip…** | Ajoute des extensions PopClip à PopBar. |
| **Nouvelle compétence…** | Ouvre [Compétences](/fr/configuration/skills). |

Certains plugins de la boutique apportent les outils et le guide de tout un service :

- **Shopify** laisse l’agent gérer votre boutique Shopify avec le CLI officiel de Shopify, en vous montrant chaque changement avant de le faire. Il fonctionne sur plusieurs boutiques. L’agent demande quelle boutique quand vous n’en nommez pas, nomme la boutique dans chaque changement qu’il montre, et lance un changement destiné à plusieurs boutiques une fois par boutique.
- **Expo** apporte les compétences officielles de l’équipe Expo et le serveur MCP Expo, à la place de l’ancien Connector Expo en lecture seule. L’agent construit, met à niveau et publie des apps Expo et React Native, lit vos builds EAS, journaux, plantages et avis, et ne démarre les builds et les soumissions qu’après votre approbation. Une connexion Expo déjà faite est conservée.

**Obsidian**, **Tailscale** et **Cloudflare** sont aussi des plugins de la boutique de plugins : installez-les depuis la page Plugins. Une copie que vous aviez déjà continue de fonctionner et se met à jour toute seule. Les agents savent dès le départ lesquels des plugins Obsidian, Tailscale, Cloudflare et Shopify vous avez installés.

Le [Catalogue des commandes intégrées](/fr/extensions/built-in-extensions) liste les familles de commandes documentées. Les entrées de la boutique et les plugins installés dans votre version peuvent en différer.

## Commandes, fournisseurs et outils

- Une **commande** est une action que vous lancez.
- Un **fournisseur** fournit une capacité, comme un modèle ou une voix.
- Un **outil** est une action qu’un Agent peut appeler.

Installer un plugin n’en fait pas toujours le fournisseur par défaut, et n’active pas chaque outil pour chaque Agent.

Dans SmartBar, utilisez le sélecteur de commandes (`@` par défaut) ou cherchez le titre d’une commande. Le menu d’actions `/` fait autre chose ; ce n’est pas un préfixe pour les noms de plugins.

## Utiliser plusieurs comptes dans un Connector

Les Connecteurs qui se connectent sur votre Mac, comme Notion, Webflow et Linear, peuvent garder plus d’un compte.

- Sur la page du Connector, sélectionnez **Connecter un autre compte** pour en ajouter un. **Comptes connectés** les liste tous.
- Sélectionnez **Définir par défaut** sur le compte avec lequel les agents doivent envoyer ou créer. Les agents lisent depuis chaque compte.
- Nommez un compte dans une demande, comme « envoie-le depuis mon adresse professionnelle », et l’agent utilise celui-là.
- **Déconnecter** retire un compte ; **Déconnecter tous les comptes** les retire tous.

Dans l’espace de travail d’un client, chaque Connector garde son propre compte par défaut, affiché comme **Par défaut dans** et le nom de l’espace de travail. L’agent utilise le compte de ce client là, sauf si vous en nommez un autre.

## Désactiver, mettre à jour ou retirer

Sur la page d’un plugin :

- L’interrupteur active ou désactive le plugin. Tant qu’il est désactivé, les agents ne peuvent ni le trouver ni l’utiliser, et SmartBar ne le liste pas et ne vous laisse pas le mentionner avec `@`. Ses réglages sont conservés.
- Le menu **⋯** a **Réglages**, **Vérifier les mises à jour** et **Désinstaller**. Les plugins fournis avec Enconvo ne peuvent pas être désinstallés.

Avant de désinstaller un plugin, vérifiez les Agents, workflows et commandes personnalisées qui l’utilisent. Réinitialiser une commande restaure ses réglages. Réinitialiser un fournisseur partagé peut aussi changer des identifiants que d’autres fonctions utilisent ; voir [Identifiants](/fr/configuration/credentials).

## Partager un plugin

Vous pouvez partager un plugin que vous avez créé, ou dont le dossier est sur ce Mac, avec un lien que toute personne à qui vous le donnez peut installer.

1. Sur la page du plugin, cliquez sur **Partager…**. Connectez-vous à votre compte Enconvo si Enconvo le demande.
2. Sous **Qui peut l’installer**, choisissez **Toute personne disposant du lien** ou **Boutique de plugins**.
3. Cliquez sur **Publier**, puis sur **Copier le lien** et envoyez le lien.

Enconvo vérifie et relit chaque version avant que le lien ne l’installe, et le lien ouvre la page du plugin sur enconvo.com. Chaque personne qui l’installe en reçoit une copie à elle ; ses données, vos clés et vos connexions restent sur votre Mac.

Pour changer un plugin partagé, cliquez de nouveau sur **Partager…** : envoyez une version plus récente, changez **Qui peut l’installer**, ou cliquez sur **Arrêter le partage**. Le lien cesse de fonctionner, et les personnes qui ont installé le plugin gardent leur copie. Si la relecture refuse une version, **Partager…** montre pourquoi et propose **Corriger dans le chat**. Pour partager un [Espace](/fr/features/spaces), voir Partager un Espace.

## Créer le vôtre

Utilisez le SDK TypeScript et le CLI dans [Développer des extensions](/fr/extensions/developing). Le CLI regroupe la construction, l’installation, la génération de schéma et la publication sous `enconvo plugin`. Publier rend un plugin disponible en dehors de votre propre configuration de développement.

Enconvo installe aussi des plugins Codex, Claude Code et portables. Voir [Formats de plugins](/extensions/plugin-formats) et [Installer des plugins](/fr/extensions/installing-plugins).
