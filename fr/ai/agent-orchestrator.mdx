Certains travaux demandent plus d’un Agent : un chercheur pour trouver les faits, un rédacteur pour en faire un article, un développeur et un relecteur pour une modification. Nommez les Agents dans un chat, et celui à qui vous parlez devient le responsable. Il rédige un plan de travail, confie à chaque membre sa tâche et vérifie le résultat par rapport à l’objectif. Pour un travail qui dure, un Projet rassemble les plans, les chats et les fichiers d’un même dossier.

La vidéo ci-dessous montre tout le flux en moins de 2 minutes : inviter des Agents avec @, le plan de travail, le Tableau et les Projets.

## Confier un travail à plusieurs Agents

1. Dans n’importe quel chat, tapez `@` puis le début du nom d’un Agent, puis appuyez sur Retour pour le choisir dans la liste. Ajoutez autant d’Agents que le travail l’exige.
2. Décrivez ce que chacun doit faire, puis envoyez. Par exemple : « @Researcher trouve trois faits sur la bambouseraie de Kyoto, puis @Writer transforme-les en un court article. »
3. Le responsable répond par un plan de travail : l’**Objectif**, ce qui doit être vrai pour qu’il soit terminé (**Terminé quand**), ce qu’il laisse de côté, et une tâche pour chaque membre. Chaque tâche reçoit l’objectif et ces lignes mot pour mot. Une tâche qui a besoin du résultat d’une autre attend, et commence avec le travail non fusionné de cette tâche déjà intégré.
4. Si le plan vous attend, vérifiez-le, puis cliquez sur **Démarrer**, **Modifier le plan** ou **Abandonner**. Les membres démarrent lorsque vous démarrez le plan.
5. Quand les tâches se terminent, la carte du plan montre chaque résultat, et le responsable dit si l’objectif est atteint.

Une tâche peut aller à n’importe lequel de vos Agents ou agents de code, comme coéquipier, même s’il n’est pas membre d’un Projet. Nommez-le dans votre demande, et choisissez son effort de raisonnement si vous voulez qu’il réfléchisse davantage ou réponde plus vite.

Quand un plan avec Codex démarre, Enconvo demande d’abord l’accès au dossier, pour que l’exécution ne s’arrête pas pour cela après votre départ.

## Suivre un plan en cours

Pendant qu’un plan s’exécute, une ligne au-dessus du chat montre son objectif, sa progression, son coût et sa durée. Cliquez dessus pour ouvrir la vue d’exécution : les étapes de chaque tâche, ce qu’elle a trouvé, la preuve qu’elle donne, le coût par membre, et pourquoi une tâche n’est pas allée au bout.

Certains résultats vous attendent avant que le plan continue. Cliquez sur **Transmettre** pour accepter un résultat retenu ou une remarque de relecture, ou sur **Renvoyer** pour que le membre le corrige.

## Lire le résultat

Quand un plan se termine, la carte de résultat commence par ce qu’il a conclu et votre prochaine étape. En dessous figurent les résultats complets de chaque tâche. Les tâches de code ont un bouton **Fusionner**, et une ligne indique les tâches encore à fusionner.

Le responsable vérifie chaque ligne **Terminé quand** et dit quelles tâches montrent que c’est atteint. Une vérification indépendante signale toute affirmation que les tâches ne montrent pas clairement. Si l’objectif n’est pas encore atteint, le responsable peut enchaîner avec d’autres plans pour le même objectif, jusqu’à cinq, sous un même budget.

Le responsable peut aussi proposer jusqu’à trois leçons pour les exécutions suivantes. Conservez ou abandonnez chacune : seules celles que vous conservez arrivent dans la [Mémoire](/fr/ai/memory).

## Suivre le Tableau

Cliquez sur **Tableau** en haut du chat pour voir ses tâches sous forme de cartes. Chaque tâche a un numéro, comme T-1, et passe de **À démarrer** à **En cours d’exécution** puis à **Terminé**. **Attend votre réponse** retient tout ce qui attend votre réponse ou votre approbation.

| Contrôle | Rôle |
| --- | --- |
| **Tous** / **Attend votre réponse** | Afficher toutes les tâches, ou seulement celles qui vous attendent. |
| **Grouper par** | Grouper les cartes, par exemple par idée ou par **Chat**. |
| **Affichage** | Changer ce que chaque carte montre. |
| **Rechercher des tâches ou T-12** | Trouver une tâche par ses mots ou son numéro. |

**Tableau**, dans le menu **···** du rail d’icônes de la barre latérale, montre les tâches de tous vos chats. Un chat qui a des tâches les liste aussi sous sa ligne dans la barre latérale.

Si les tours de vérification et de correction d’une tâche retrouvent toujours le même problème, les tours s’arrêtent au lieu de réessayer. Une vérification qui ne peut pas s’exécuter le dit, au lieu de renvoyer du code qui fonctionne.

## Projets

Un Projet regroupe des chats liés autour d’un dossier, et le fichier `AGENTS.md` du dossier devient les instructions du Projet. Cliquez sur **+** à côté de **Projets** dans la barre latérale pour ouvrir **Créer un projet** :

- Saisissez un **Nom du projet** pour créer un nouveau dossier dans Documents, ou cliquez sur **Utiliser un dossier existant** ou **Cloner un dépôt**.
- Sous **Partir de**, choisissez **Vide** ou une équipe : **Bureau de recherche**, **Studio de contenu**, **Développeurs d'apps** ou **Planificateur de voyage**.

### Cloner un dépôt

1. Dans **Créer un projet**, cliquez sur **Cloner un dépôt**.
2. Collez une URL GitHub, `owner/name`, ou n’importe quelle adresse Git. Si vous êtes connecté à GitHub, vous pouvez aussi choisir l’un de vos dépôts dans la liste.
3. Cliquez sur **Cloner**. Le dépôt est copié dans un nouveau dossier, et il s’ouvre comme Projet.

### Qui fait le travail

Dans un Projet avec des membres, le responsable planifie chaque objectif, les membres le réalisent, et une relecture ou un test le vérifie. Les membres peuvent inclure des agents de code comme Claude Code et Codex. Chaque tâche de code travaille dans sa propre copie du code, et la carte de résultat du plan a un bouton **Fusionner** pour quand vous êtes prêt.

Claude Code, Codex, Grok Build ou Antigravity peuvent diriger un Projet. Avec des membres, un agent de code responsable planifie leur travail dans un plan de travail et lit leurs résultats, comme n’importe quel autre responsable. Dans un Projet sans membres, il fait le travail lui-même dans le chat, sans plan de travail ni tâches de Tableau, jusqu’à ce que vous ajoutiez des membres.

Dans le chat Responsable d’un Projet, vous pouvez confier une partie d’une demande à un modèle par son nom, comme Opus 5.5, ou nommer un Agent et un modèle ensemble, comme Claude Code sur Opus 5.5. Le responsable peut aussi lancer des Sous-agents pour son propre travail. Un Projet peut faire passer ses objectifs et ses tâches par ses propres flux de travail : voir [Utiliser vos propres flux de travail](/fr/ai/projects).

Les membres ne peuvent pas démarrer de plans, approuver, changer les réglages, installer des logiciels ni utiliser vos connexions. Les membres agents de code ne peuvent pas pousser, déplacer d’autres branches ni supprimer des worktrees : seul Enconvo fusionne et pousse. L’accès complet dans le chat Responsable d’un Projet et ses tâches fonctionne comme dans n’importe quel autre chat. Pour le Tableau, les Idées et les réglages d’un Projet, voir [Projets et le Tableau](/fr/ai/projects).

## Dépannage

| Problème | Que faire |
| --- | --- |
| Appuyer sur Retour a envoyé le message au lieu de choisir l’Agent | Attendez que la liste des Agents apparaisse sous le champ avant d’appuyer sur Retour. |
| Une tâche reste dans **Attend votre réponse** | Ouvrez la tâche, ou le chat, et répondez à la question ou à l’approbation qu’elle attend. |
| Un agent de code ne peut pas démarrer | Installez-le et connectez-vous d’abord. Voir [Agents de code](/fr/ai/coding-agents). |
| Un plan Codex s’arrête pour demander l’accès au dossier | Répondez à la question d’accès au dossier au démarrage du plan, pour que l’exécution puisse continuer sans vous. |
