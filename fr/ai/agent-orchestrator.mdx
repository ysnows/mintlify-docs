Certains travaux demandent plus d’un Agent : un chercheur pour trouver les faits, un rédacteur pour en faire un article, un codeur et un relecteur pour une modification. Nommez les Agents dans un chat, et l’Agent à qui vous parlez devient le responsable. Il rédige un Plan de travail, donne à chaque membre sa tâche et vérifie le résultat par rapport à l’objectif. Pour un travail de longue durée, un [Projet](#projets) rassemble les plans, les chats et les fichiers d’un même dossier.

La vidéo ci-dessous présente tout le déroulement en moins de 2 minutes : faire appel à des Agents avec @, le Plan de travail, le Tableau et les Projets.

## Confier une tâche à plusieurs Agents

1. Dans n’importe quel chat, saisissez `@` et le début du nom d’un Agent, puis appuyez sur Retour pour le choisir dans la liste. Ajoutez autant d’Agents que nécessaire.
2. Décrivez ce que chacun doit faire, puis envoyez. Par exemple : « @Chercheur trouve trois faits sur la forêt de bambous de Kyoto, puis @Rédacteur en fait un court article. »
3. Le responsable répond avec un Plan de travail : l’**Objectif**, ce qui doit être vrai pour que ce soit terminé (**Terminé quand**), ce qu’il laisse de côté, et une tâche pour chaque membre. Chaque tâche reçoit l’objectif et ces lignes mot pour mot. Une tâche qui a besoin du résultat d’une autre l’attend, et démarre avec le travail non fusionné de cette tâche déjà fusionné.
4. Si le plan attend votre validation, vérifiez-le, puis cliquez sur **Démarrer**, **Modifier le plan** ou **Abandonner**. Les membres démarrent quand vous démarrez le plan.
5. Quand les tâches sont terminées, la carte du plan affiche chaque résultat, et le responsable indique si l’objectif est atteint.

Une tâche peut être confiée à n’importe lequel de vos Agents ou Agents de code comme coéquipier, même s’il n’est pas membre d’un Projet. Nommez-le dans votre demande, et choisissez son effort de raisonnement si vous voulez qu’il réfléchisse davantage ou réponde plus vite.

Quand un plan avec Codex démarre, Enconvo demande d’abord l’accès aux dossiers, afin que l’exécution ne s’arrête pas pour cela une fois que vous vous êtes éloigné.

## Suivre un plan en cours

Pendant l’exécution d’un plan, une ligne au-dessus du chat affiche son objectif, sa progression, son coût et sa durée. Cliquez dessus pour ouvrir la vue d’exécution : les étapes de chaque tâche, ce qu’elle a trouvé, la preuve qu’elle fournit, le coût par membre et la raison pour laquelle une tâche n’a pas abouti.

Certains résultats attendent votre réponse avant que le plan continue. Cliquez sur **Transmettre** pour accepter un résultat retenu ou une remarque de relecture, ou sur **Renvoyer** pour que le membre la corrige.

## Lire le résultat

Quand un plan se termine, la carte de résultat commence par ce qu’il a donné et par votre prochaine étape. En dessous figurent les résultats complets de chaque tâche. Les tâches de code ont un bouton **Fusionner**, et une ligne nomme les tâches qu’il reste à fusionner.

Le responsable vérifie chaque ligne **Terminé quand** et indique quelles tâches montrent qu’elle est satisfaite. Un contrôle indépendant signale toute affirmation que les tâches ne démontrent pas clairement. Si l’objectif n’est pas encore atteint, le responsable peut poursuivre avec d’autres plans pour le même objectif, jusqu’à cinq, dans le cadre d’un seul budget.

Le responsable peut aussi proposer jusqu’à trois enseignements que les exécutions suivantes devront prendre en compte. Conservez ou abandonnez chacun d’eux : seuls ceux que vous conservez parviennent dans la [Mémoire](/fr/ai/memory).

## Suivre le Tableau

Cliquez sur **Tableau** en haut du chat pour voir ses tâches sous forme de cartes. Chaque tâche porte un numéro, par exemple T-1, et passe de **À démarrer** à **En cours d’exécution** puis à **Terminé**. **Attend votre réponse** regroupe tout ce qui attend votre réponse ou votre approbation.

| Contrôle | Ce qu’il fait |
| --- | --- |
| **Tous** / **Attend votre réponse** | Affiche toutes les tâches, ou seulement celles qui vous attendent. |
| **Grouper par** | Regroupe les cartes, par exemple par idée ou par **Chat**. |
| **Affichage** | Modifie ce que montre chaque carte. |
| **Rechercher des tâches ou T-12** | Trouve une tâche par ses mots ou par son numéro. |

**Tableau**, dans le menu **···** de la barre d’icônes de la barre latérale, affiche les tâches de tous vos chats. Un chat qui a des tâches les liste aussi sous sa ligne dans la barre latérale.

Si les tours de vérification et de correction d’une tâche retrouvent sans cesse le même problème, les tours s’arrêtent au lieu de réessayer. Une vérification qui ne peut pas s’exécuter le dit, au lieu de renvoyer du code qui fonctionne.

## Projets

Un Projet regroupe des chats liés autour d’un même dossier, et le fichier `AGENTS.md` du dossier devient les instructions du Projet. Cliquez sur **+** à côté de **Projets** dans la barre latérale pour ouvrir **Créer un projet** :

- Saisissez un **Nom du projet** pour créer un nouveau dossier dans Documents, ou cliquez sur **Utiliser un dossier existant** ou **Cloner un dépôt**.
- Sous **Partir de**, choisissez **Vide** ou une équipe : **Bureau de recherche**, **Studio de contenu**, **Développeurs d'apps** ou **Planificateur de voyage**.

### Cloner un dépôt

1. Dans **Créer un projet**, cliquez sur **Cloner un dépôt**.
2. Collez une URL GitHub, `owner/name` ou n’importe quelle adresse Git. Si vous êtes connecté à GitHub, vous pouvez aussi choisir l’un de vos dépôts dans la liste.
3. Cliquez sur **Cloner**. Le dépôt est copié dans un nouveau dossier et s’ouvre comme un Projet.

### Qui fait le travail

Dans un Projet avec des membres, le responsable planifie chaque objectif, les membres le réalisent, et une relecture ou un test le vérifie. Les membres peuvent inclure des Agents de code comme Claude Code et Codex. Chaque tâche de code travaille dans sa propre copie du code, et la carte de résultat du plan a un bouton **Fusionner** pour quand vous êtes prêt.

Claude Code, Codex, Grok Build ou Antigravity peuvent diriger un Projet. Avec des membres, un responsable de type Agent de code planifie leur travail dans un Plan de travail et lit leurs résultats, comme n’importe quel autre responsable. Dans un Projet sans membres, il fait lui-même le travail dans le chat, sans Plan de travail ni tâches du Tableau, jusqu’à ce que vous ajoutiez des membres.

Dans le chat Responsable d’un Projet, vous pouvez confier une partie d’une demande à un modèle par son nom, comme Opus 5.5, ou nommer ensemble un Agent et un modèle, comme Claude Code sur Opus 5.5. Le responsable peut aussi démarrer des Sous-agents pour son propre travail. Un Projet peut exécuter ses objectifs et ses tâches via des workflows qui lui sont propres : consultez [Utiliser vos propres workflows](/fr/ai/projects).

Les membres ne peuvent pas démarrer de plans, approuver des actions, modifier des réglages, installer des logiciels ni utiliser vos connexions. Les membres de type Agent de code ne peuvent pas pousser, déplacer d’autres branches ni supprimer des worktrees : seul Enconvo fusionne et pousse. L’Accès complet dans le chat Responsable d’un Projet et dans ses tâches fonctionne comme dans n’importe quel autre chat. Pour le Tableau, les Idées et les réglages d’un Projet, consultez [Projets et Tableau](/fr/ai/projects).

## Dépannage

| Problème | Que faire |
| --- | --- |
| Appuyer sur Retour a envoyé le message au lieu de choisir l’Agent | Attendez que la liste des Agents apparaisse sous la zone de saisie avant d’appuyer sur Retour. |
| Une tâche est bloquée sur **Attend votre réponse** | Ouvrez la tâche, ou le chat, et répondez à la question ou à l’approbation qu’elle attend. |
| Un agent de code ne démarre pas | Installez-le et connectez-vous d’abord. Consultez [Agents de code](/fr/ai/coding-agents). |
| Un plan Codex s’arrête pour demander l’accès aux dossiers | Répondez à la question d’accès aux dossiers au démarrage du plan, pour que l’exécution puisse se poursuivre sans vous. |
