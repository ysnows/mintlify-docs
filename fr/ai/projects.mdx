Un Projet réunit les chats, les idées et l’équipe d’un même dossier. Vous notez ce que vous voulez sous forme d’idée, le responsable du Projet la planifie avec l’équipe, et chaque tâche avance sur le Tableau jusqu’à son achèvement. Utilisez un Projet pour un travail de longue durée, comme un site web ou une app, quand vous voulez voir d’un coup d’œil ce qui tourne et ce qui vous attend.

La vidéo ci-dessous ouvre un Projet, ajoute une idée qui confie une partie du travail à Claude Code, la suit sur le Tableau, puis archive et restaure le Projet.

## Avant de commencer

Vous avez besoin d’un Projet. Cliquez sur **+** à côté de **Projets** dans la barre latérale de la Fenêtre de chat et choisissez un dossier : consultez [Créer un Projet](/fr/ai/agent-orchestrator). Pour confier des tâches à un Agent de code comme Claude Code ou Codex, installez-le et connectez-vous d’abord : consultez [Agents de code](/fr/ai/coding-agents).

## Ouvrir un Projet

Cliquez sur le Projet dans la barre latérale. Sa page comporte trois onglets :

| Onglet | Ce qu’il affiche |
| --- | --- |
| **Chat** | Le chat du Projet avec son responsable, et un panneau de ce qui [vous attend](#voir-ce-qui-attend-votre-réponse). |
| **Tableau** | Les idées du Projet, de **Pas commencé** à **Terminé** en passant par **En planification** et **En cours**. |
| **Équipe et réglages** | Qui fait partie de l’équipe, et quand l’équipe [vous consulte](#choisir-quand-l’équipe-vous-consulte). |

Les visages de l’équipe, le responsable en premier, s’affichent en haut à gauche. Les tâches d’un chat de Projet s’affichent aussi sous sa ligne dans la barre latérale.

## Ajouter une idée

Une idée est quelque chose que vous voulez que le Projet fasse.

1. Ouvrez l’onglet **Tableau** et cliquez sur **Nouvelle idée**.
2. Écrivez ce que vous voulez, comme vous le diriez. Vous pouvez joindre des captures d’écran ou des fichiers, ou cliquer sur le micro et parler.
3. Définissez une **Priorité** si vous le souhaitez. Enconvo devine le **Type** à partir de vos mots : **Fonction**, **Bug**, **Amélioration**, **Documents** ou **Recherche**. Modifiez-le si la déduction est fausse.
4. Cliquez sur **Ajouter l’idée**.

L’idée apparaît sous forme de carte sous **Pas commencé**, avec un titre court rédigé à partir de vos mots et un drapeau rouge, orange ou bleu selon sa priorité. Le responsable commence aussitôt à la planifier et la déplace vers **En planification**. Les fichiers que vous avez joints parviennent au responsable au démarrage de l’idée. Pour ne voir qu’un seul type d’idées, utilisez **Filtrer par type**.

Des idées peuvent aussi arriver d’elles-mêmes. Donnez à une [Tâche planifiée](/fr/workflows/scheduled-jobs) l’action **Ajouter à Ideas**, et chaque ticket GitHub, message Discord ou Telegram, e-mail ou webhook qu’elle reçoit devient une idée sur le tableau du Projet. Le responsable reproduit un bug et planifie la correction, ou étudie une demande et la clôt avec un motif ou la planifie, et vous demande avant que quoi que ce soit change.

Quand le plan est prêt, il montre chaque tâche, qui la réalise et avec quel modèle. Vérifiez-le, puis cliquez sur **Démarrer**. L’idée passe à **En cours**. Le responsable planifie à partir de l’**Objectif** et de la ligne **Terminé quand** de l’idée, et l’idée passe à **Terminé** seulement quand le responsable juge cet objectif atteint.

## Suivre une idée

Cliquez sur une idée pour ouvrir sa page. Votre chat avec le responsable se trouve d’un côté, et le plan, les tâches, les mots, les fichiers et l’objectif de l’idée de l’autre. **Où en est-elle** affiche **Planifier le travail**, **Faire le travail** et **Revue et tests**, avec l’avancement de chacun et la personne qui s’en charge.

Pour retravailler une idée terminée, cliquez sur **Rouvrir**.

Une idée qui a des tâches propose deux vues en haut : **Tâches** n’affiche que ses tâches sous forme de tableau, et **Chat avec** suivi du nom du responsable, comme **Chat avec Mavis**, ouvre le chat où elle a été planifiée.

## Confier une tâche à un Agent de code

Nommez l’Agent, et le modèle si vous en voulez un, dans l’idée ou dans le chat du Projet. Vous pouvez aussi ne nommer qu’un modèle, comme Opus 5.5, et le responsable réalise cette tâche avec lui. Cela fonctionne aussi dans un Projet sans membres. Par exemple :

```text
Add a dark mode switch to the settings page. Have Claude Code on Opus 5.5 write the dark styles.
```

Le responsable planifie la partie nommée comme une tâche pour cet Agent sur ce modèle, même si l’Agent n’est pas l’un des membres du Projet, et peut faire le reste lui-même. Le plan et le Tableau affichent le modèle à côté de la personne qui réalise la tâche. Si le nom peut désigner plusieurs modèles, ou aucun, le responsable pose la question.

Quand l’Agent de code a terminé, sa tâche attend votre relecture sous **À relire** sur le tableau **Tâches** de l’idée. Dans un Projet dont le dossier n’est pas un dépôt git, elle passe directement à **Terminé**. Chaque tâche de code travaille dans sa propre copie du code, et la carte de résultat du plan a **Fusionner** pour quand vous êtes prêt. Les membres ne peuvent pas pousser ni fusionner eux-mêmes.

Chaque tâche que vous confiez au responsable, dans l’onglet Chat ou dans les Idées, s’affiche sur le Tableau, regroupée par idée ou par chat. Choisissez un chat dans le filtre de chats du Tableau, ou **Grouper par** **Chat**, pour suivre une seule conversation.

Le travail que vous faites dans les chats du Projet s’affiche aussi sur le Tableau : quand un chat modifie des fichiers ou exécute une commande, une carte l’accompagne jusqu’à **Terminé** avec un court résumé et les fichiers modifiés. Cliquez sur la carte pour ouvrir le chat. Le responsable voit ces cartes et tient ses propres tâches à l’écart des mêmes fichiers.

## Fusionner le travail terminé

Cliquez sur **Fusionner** sur une tâche, ou sur la carte de résultat du plan, pour la fusionner dans la **Branche de base** du Projet. Des modifications non validées sur d’autres lignes du même fichier n’empêchent pas une fusion. Si git est occupé, Fusionner patiente un instant et nomme le fichier de verrou quand il en reste un.

Pour fusionner sans cliquer, activez **Fusionner le travail validé** dans **Réglages du projet → Tableau**. Cela demande une **Branche de base**, définie dans **Worktrees**. Chaque tâche fusionne alors d’elle-même une fois que sa vérification et une relecture par l’Agent d’un autre éditeur ont réussi. Sous **Réussit quand**, choisissez **Aucune remarque bloquante**, **Le réviseur approuve** ou **Vérification seule**. Une tâche en conflit retourne à son membre. Quand le réviseur ne peut pas s’exécuter, toutes les fusions se mettent en pause au lieu d’être ignorées.

### Projets hors de git

Dans un Projet dont le dossier n’est pas un dépôt git, chaque chat Responsable enregistre ses Plans de travail dans son propre dossier de chat, de sorte que deux chats Responsable peuvent exécuter des plans en même temps. La carte du plan affiche **Enregistré dans** et le dossier, et **A aussi changé** liste les fichiers qu’une tâche a modifiés en dehors de celui-ci.

## Interroger le responsable autrement

Dans le chat Responsable d’un Projet :

- **Comparer les réponses** pose la même question à deux à six agents, et le responsable compare ce qu’ils disent.
- **Utiliser un style** choisit la façon dont le responsable rédige ses réponses.

Pour que Codex, Claude Code ou un autre de vos Agents relise ou teste le travail en cours, demandez-le simplement. Dans un Projet, le responsable démarre cet Agent comme Sous-agent et rapporte le résultat dans le même chat. Le responsable peut aussi démarrer des Sous-agents pour son propre travail, en plus des tâches qu’il donne aux membres du Projet.

Pour exécuter une tâche via l’un des workflows du Projet, saisissez `@` et choisissez le workflow, ou cliquez sur **Utiliser dans le chat** à côté de lui dans l’onglet **Équipe et réglages**. Consultez [Utiliser vos propres workflows](#utiliser-vos-propres-workflows).

## Voir ce qui attend votre réponse

Ouvrez l’onglet **Chat**. Le panneau au-dessus de la zone de message comporte trois colonnes :

| Colonne | Ce qu’elle liste |
| --- | --- |
| **Attend votre réponse** | Les tâches qui attendent votre réponse, votre approbation ou votre relecture. |
| **En cours** | Les tâches en cours d’exécution. |
| **Nouveaux résultats** | Les tâches terminées que vous n’avez pas encore ouvertes. |

Cliquez sur une ligne pour ouvrir son idée.

## Utiliser le Tableau pour tout

**Tableau**, dans le menu **···** de la barre d’icônes de la barre latérale de la Fenêtre de chat, affiche au même endroit les tâches de chaque chat, Projet et équipe. Pour le garder dans la barre, choisissez **Personnaliser la barre latérale…** dans ce menu. Consultez [Fenêtre de chat](/fr/ai/chat).

Pour ne voir que certains Projets, cliquez sur le filtre en haut à gauche (**Tous les tableaux**) et choisissez ceux que vous voulez. Les autres commandes du Tableau sont décrites dans [Suivre le Tableau](/fr/ai/agent-orchestrator).

## Constituer l’équipe

Ouvrez l’onglet **Équipe et réglages**. Le haut montre le responsable et chaque membre, avec **Ajouter un membre** pour faire venir un autre Agent. Cliquez sur les visages de l’équipe en haut à gauche pour voir toute l’équipe d’un coup : le responsable avec **Modifier**, et chaque membre avec un rôle que vous pouvez modifier sur place.

Le responsable peut être l’un de vos Agents ou un Agent de code : Claude Code, Codex, Grok Build ou Antigravity. Un responsable de type Agent de code planifie le travail des membres dans un Plan de travail et lit leurs résultats, comme n’importe quel autre responsable.

Les membres peuvent être des Agents sur vos [autres ordinateurs associés](/fr/integrations/other-computers). Le responsable leur confie les tâches qui exigent cet ordinateur, et la réponse revient comme résultat de la tâche. Si cet ordinateur n’a pas d’accès d’appareil sur votre compte, la tâche l’indique et renvoie vers **Gérer les appareils**.

### Comment fonctionne l’équipe

Chaque objectif que vous donnez au responsable, depuis le Chat ou les Idées, passe par **Standard** : **Planifier le travail**, **Faire le travail**, puis **Revue et tests**. Choisissez qui réalise chaque étape. Confiez la planification à un membre, et ce membre rédige le plan quand vous le demandez ; le responsable propose ensuite ses tâches sous forme de Plan de travail qui attend votre **Démarrer**. Vous pouvez aussi activer ou désactiver la vérification et définir les **Tours de correction**, c’est-à-dire le nombre de fois qu’une tâche retourne pour être corrigée.

### Utiliser vos propres workflows

**Flux de travail personnalisés**, dans l’onglet **Équipe et réglages**, est désactivé tant que vous ne l’activez pas. Quand il est désactivé, chaque objectif passe par **Standard**. Activez-le pour exécuter des objectifs ou des tâches isolées via des [Flux de travail](/fr/workflows/introduction) :

- **Ou exécutez chaque objectif avec un flux de travail** liste les flux de travail d’équipe. Pointez-en un et cliquez sur **Utiliser pour chaque objectif**, ou cliquez sur **Nouveau flux de travail d’équipe** pour créer le vôtre.
- **Flux de travail de tâche** liste les flux de travail que le responsable peut donner à une tâche isolée, comme corriger un bug. Cliquez sur **Utiliser dans le chat** pour en nommer un dans le chat Responsable, ou sur **Nouveau workflow** pour en créer un.

Les flux de travail intégrés :

| Flux de travail | Ce qu’il fait |
| --- | --- |
| **Ship** | Transforme une idée en spécification, conception et plan que vous approuvez, réalise chaque tâche avec tests, vérifications, relecture et validation, puis relit toute la branche. |
| **Planificateur** | Transforme une idée en spécification, conception et tâches que vous approuvez, et remet les tâches au responsable sous forme de Plan de travail. |
| **Sprint** | Réalise une tâche planifiée avec tests, vérifications, relecture et validation. |
| **Compound** | Applique les enseignements que vous avez conservés aux documents et aux règles du dépôt. |
| **Verify setup** | Détermine comment vérifier et exécuter le Projet, rédige un guide de vérification que vous approuvez, et le prouve en l’exécutant. |

Chaque ligne montre l’icône du flux de travail, les visages des membres qui le réalisent, ainsi que son nombre d’exécutions et d’échecs. Quand il manque un membre à un flux de travail, cliquez sur **Choisir un agent…** dans sa ligne. Cliquez sur une ligne pour ouvrir le flux de travail et modifier ses étapes ou les personnes qui les réalisent.

Les modifications que vous enregistrez dans un flux de travail d’un Projet restent un **Brouillon** : les nouveaux plans continuent d’utiliser la version publiée jusqu’à ce que vous cliquiez sur **Publier**. **Revenir à la version précédente** rétablit la version d’avant. Le flux de travail d’une tâche affiche les tokens et le coût de chaque étape, avec un total aux tarifs de l’API.

### Définir la commande de vérification

La commande de vérification s’exécute dans la copie du code d’une tâche terminée avant son passage en relecture. Une vérification qui échoue retourne au membre de la tâche pour correction.

1. Dans l’onglet **Équipe et réglages**, cliquez sur **Réglages du projet**, puis sur **Tableau**.
2. À côté de **Commande de vérification**, cliquez sur **Trouver**. Enconvo lit la commande dans les fichiers du Projet et ne la renseigne que si elle réussit.
3. S’il n’en trouve aucune, cliquez sur **Demander à Mavis de la configurer** (le bouton porte le nom de votre responsable). Le responsable trouve ou ajoute la commande dans son chat.

Un Projet sans commande de vérification affiche son étape de vérification comme **Non vérifié**.

### Nettoyer les worktrees

Chaque chat et chaque tâche d’un Projet git travaille dans son propre worktree. Pour libérer de l’espace disque, Enconvo archive les worktrees dont vous avez terminé et supprime leurs dossiers. Dans **Réglages du projet → Worktrees** :

| Réglage | Ce qu’il fait |
| --- | --- |
| **Archiver les worktrees fusionnés** | Archive un worktree une fois son travail dans la branche de base et rien n’étant resté non validé ni non poussé. |
| **Archiver les worktrees sans discussions** | Archive un worktree une fois qu’aucun de ses chats ne reste dans la liste des chats. |
| **Archiver les worktrees inactifs** | Archive un worktree, avec ses chats, après qu’ils n’ont vu aucune activité pendant le nombre de jours choisi sous **Archiver après une inactivité de** : 3, 7, 14 ou 30. |

Un worktree avec des modifications non validées reste toujours. **Restaurer** ramène un worktree archivé.

## Choisir quand l’équipe vous consulte

Ouvrez l’onglet **Équipe et réglages**.

Sous **Quand vous consulter** :

| Réglage | Ce qu’il fait |
| --- | --- |
| **Quand un plan est prêt** | **Intelligent**, la valeur par défaut, démarre le plan aussitôt quand il fait ce que vous avez déjà demandé, et attend votre **Démarrer** quand il va plus loin ou présente un risque. **Toujours me demander** attend **Démarrer** à chaque fois. **Toujours démarrer** démarre chaque plan dès qu’il est prêt. |
| **Commencer la planification dès qu’une tâche est ajoutée** | Activé : le responsable planifie chaque nouvelle idée aussitôt. Désactivé : les nouvelles idées attendent sous **Pas commencé** jusqu’à ce que vous les démarriez. |

Les actions qui suppriment, envoient, publient, paient ou poussent demandent toujours, quel que soit votre choix. Le dossier, les worktrees, les autorisations, le budget et le périmètre se trouvent dans **Réglages du projet**.

## Laisser le responsable agir en votre absence

Dans un Projet en **Accès complet**, le responsable peut faire avancer le travail quand une tâche rend compte et que personne n’est dans le chat. Activez **Le responsable agit en votre absence** dans **Réglages du projet → Tableau**.

Le responsable corrige, relance et fusionne alors de lui-même, dans la limite de 6 tours par heure et de 100 000 points par jour. Il n’envoie, ne pousse, ne publie, ne paie et ne supprime jamais rien en dehors de la copie du code propre à une tâche.

À votre retour, une carte **Pendant votre absence** en haut du chat Responsable liste ce que le responsable a fait et les étapes qu’il vous a laissées. Après deux tours échoués d’affilée, ou à une limite, le responsable se met en pause et **Attend votre réponse** demande s’il faut **Reprendre** ou **Laisser en pause**.

## Archiver un Projet

Quand un Projet est terminé, archivez-le pour le retirer de la barre latérale sans rien supprimer.

1. Pointez le Projet dans la barre latérale et cliquez sur **⋯**.
2. Choisissez **Archiver le projet**.

Le Projet et ses chats quittent la barre latérale, et ses tâches planifiées sont mises en pause. Un chat d’un Projet archivé ne peut plus recevoir de messages tant que vous ne l’avez pas restauré.

Pour le ramener :

1. Ouvrez **Réglages → Archivé**.
2. Cliquez sur **Projets**.
3. Cliquez sur **Restaurer** à côté du Projet.

Le Projet revient dans la barre latérale avec ses chats, et ses tâches planifiées sont de nouveau activées.

## Les Projets sur votre téléphone

L’app iPhone ouvre aussi vos Projets : les Idées, le Tableau, les Réglages du projet, **Nouveau projet** et la carte du Plan de travail, où vous répondez, fusionnez, démarrez ou relancez une tâche. Le menu `@` y liste les membres et les workflows du Projet. Consultez [App iPhone](/fr/integrations/iphone-app).

## Dépannage

| Problème | Que faire |
| --- | --- |
| Une nouvelle idée reste sous **Pas commencé** | Activez **Commencer la planification dès qu’une tâche est ajoutée** dans **Équipe et réglages**, ou ouvrez l’idée et démarrez-la vous-même. |
| Un plan attend alors que vous avez choisi **Intelligent** | Le plan va plus loin que ce que vous avez demandé, ou comporte une étape risquée. Vérifiez-le et cliquez sur **Démarrer**. |
| La tâche d’un Agent de code ne démarre pas | Installez l’Agent de code et connectez-vous. |
| Une tâche attend avec l’état **En attente** et un avertissement de connexion | L’Agent de code est déconnecté, ou sa connexion expire bientôt. Cliquez sur **Se reconnecter**. Les tâches en attente reprennent dès que vous vous reconnectez. |
| Une carte du Tableau signale un problème en orange | C’est un problème de configuration. Suivez la solution proposée par la carte ; le responsable ne réessaie pas. Une erreur d’Enconvo indique qu’il est sans risque de réessayer. |
| Une tâche échoue dans un Projet conservé dans iCloud | Avec Optimiser le stockage du Mac activé, il se peut que les fichiers ne soient pas sur votre Mac. Dans le Finder, choisissez **Garder téléchargé** pour le dossier du Projet. |
| Une tâche indique que le dossier du Projet a disparu | Le dossier a été déplacé ou supprimé. Remettez-le en place, ou créez un nouveau Projet pour son nouvel emplacement. |
| Une tâche s’arrête au **Périmètre** du Projet | Cliquez sur **Modifier le Périmètre** sur la tâche pour autoriser ce dont elle a besoin. Vous seul modifiez un Périmètre. |
| Une tâche signale une fusion ou un rebase laissé à moitié fait | Son agent s’est arrêté en cours de route. Terminez ou annulez la fusion ou le rebase avant de fusionner la tâche. |
| Chaque plan attend **Démarrer** | Les plans attendent tant que vous êtes déconnecté d’Enconvo. Connectez-vous dans **Réglages → Compte**. |
| Un Projet est absent de la barre latérale | Il est peut-être archivé. Regardez dans **Réglages → Archivé** sous **Projets**. |
| Une tâche de Flux de travail a échoué | Ouvrez la tâche. Elle indique ce que sa commande a écrit en dernier et l’étape de quel membre a échoué. |
| Un objectif n’utilise pas le flux de travail d’équipe que vous avez choisi | Activez **Flux de travail personnalisés** dans l’onglet **Équipe et réglages**. Quand il est désactivé, chaque objectif passe par **Standard**. |
