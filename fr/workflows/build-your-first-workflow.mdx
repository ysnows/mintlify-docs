Les flux de travail enchaînent invites, agents et outils en une exécution répétable. Ce tutoriel en construit un du début à la fin : créez-le à partir du modèle **Visite des types d’étapes**, ajoutez une étape à la main, laissez l’assistant de flux de travail en ajouter une autre, puis exécutez-le et lisez la sortie de chaque étape.

<YouTubePlayer videoId="g02LJwso1yk" title="Comment créer un flux de travail dans Enconvo" />

La vidéo dure 2 minutes 24 secondes. Les étapes écrites ci-dessous suivent le même ordre, avec l’horodatage correspondant à chaque étape.

## Ce que vous allez construire

Le modèle **Visite des types d’étapes** tourne déjà tel quel. Au fil du tutoriel, il devient un petit pipeline de contenu :

| Étape | Type | Effet |
| --- | --- | --- |
| Date du jour | Shell | Imprime la date du jour |
| Lister les flux enregistrés | Outil | Liste vos flux existants (s’exécute en parallèle de la date) |
| Demander une idée au modèle | Invite | Suggère une nouvelle automatisation sur l’entrée `topic` |
| Laisser l’agent la développer | Agent | Transforme l’idée en un plan en trois étapes |
| Écrire un tweet | Invite | Ajoutée à la main : transforme le plan en un tweet percutant |
| Traduire le tweet en japonais | Invite | Ajoutée par l’assistant : traduit le tweet |

## Suivre le parcours

<Steps>
  <Step title="Créer un flux de travail (0:07)">
    Ouvrez **Réglages → Flux de travail → Gérer** et sélectionnez **Nouveau workflow**. Sous **Ou partir d’un modèle**, choisissez **Visite des types d’étapes**. Le flux est créé et l’éditeur s’ouvre en mode **Visuel**. La vidéo a été enregistrée avant l’existence du dialogue **Nouveau workflow**, donc le point de départ s’y appelle *Starter Workflow*.
  </Step>
  <Step title="Lire le graphe (0:18)">
    Lisez le graphe depuis le haut. Le nœud **Entrées** déclare ce dont une exécution a besoin ; ici, c’est un seul `topic`. Les deux premières étapes sont côte à côte parce qu’elles appartiennent à des jobs distincts, donc elles s’exécutent en parallèle. Chaque résultat descend ensuite vers les étapes en dessous, qui s’exécutent dans l’ordre.
  </Step>
  <Step title="Modifier une étape (0:28)">
    Sélectionnez une étape pour l’ouvrir dans l’inspecteur, où vous pouvez changer son ID, son titre et son invite. Les doubles accolades tirent des valeurs dans une étape : `{{ inputs.topic }}` lit une entrée d’exécution, et `{{ steps.idea.output }}` lit le résultat d’une étape précédente. C’est ainsi que les étapes se parlent.
  </Step>
  <Step title="Ajouter une étape (0:37)">
    Sélectionnez le **+** sous la dernière étape et choisissez un type d’étape, comme Invite, Agent, Shell ou Outil. Donnez à la nouvelle étape Invite l’ID `tweet`, le titre « Write a tweet », et cette invite :

    ```text wrap
    Turn this plan into one punchy tweet: {{ steps.plan.output }}
    ```

    <Tip>
    Après avoir renommé un ID d’étape, appuyez sur Retour avant de passer au champ suivant.
    </Tip>
  </Step>
  <Step title="Ou demander à l’assistant de flux (0:57)">
    Au lieu de modifier à la main, sélectionnez **Assistant** dans la barre d’outils et décrivez le changement dans le panneau qui s’ouvre à côté du canevas :

    ```text wrap
    Add a final step that translates the tweet into Japanese
    ```

    L’assistant modifie le graphe et liste les étapes qu’il a changées. Sélectionnez **Rétablir la version précédente** sur sa réponse si le résultat ne vous convient pas. Dans la vidéo, il ajoute une étape `translate_ja` dont l’invite lit `{{ steps.tweet.output }}`. Relisez la nouvelle étape avant d’enregistrer : les modifications de l’assistant restent non enregistrées tant que vous ne sélectionnez pas **Enregistrer**.
  </Step>
  <Step title="Voir le YAML (1:16)">
    Sélectionnez **YAML** dans la barre d’outils pour voir le même flux comme source. Chaque flux est un fichier simple, enregistré dans `~/.enconvo/workflows/<id>.yaml`, donc il est facile à lire, comparer et partager. Sélectionnez **Visuel** pour revenir au graphe. Le fichier complet est dans [Le flux terminé](/fr/workflows/build-your-first-workflow) ci-dessous.
  </Step>
  <Step title="L’exécuter et vérifier la sortie (1:28)">
    Sélectionnez **Entrées**, réglez les valeurs d’exécution (la vidéo utilise `{"topic": "matcha"}`), et choisissez **Exécuter**. Les étapes en cours brillent en bleu et les étapes terminées passent au vert. L’étape Agent prend plus de temps que les autres.

    Quand l’exécution se termine, sélectionnez n’importe quelle étape et ouvrez son onglet **Sortie** pour voir exactement ce qu’elle a produit. La dernière étape a repris le tweet et l’a traduit, sans copier-coller.
  </Step>
  <Step title="Retrouver les exécutions passées (2:05)">
    Chaque exécution est conservée sous **Exécutions** dans la barre d’outils, pour que vous puissiez revenir plus tard à n’importe quel résultat.
  </Step>
</Steps>

<Note>
Exécuter un flux de travail appelle de vrais modèles et outils. Cela peut utiliser des crédits de fournisseur, et les étapes Shell ou Outil agissent avec les autorisations du compte de votre Mac. Relisez les étapes d’un flux avant de l’exécuter.
</Note>

## Le flux terminé

Voici le flux construit dans la vidéo, écrit en YAML. La vue **YAML** peut le formater un peu différemment.

```yaml
version: agent-workflow/v1
title: Starter Workflow
description: "Starter workflow showing parallel jobs and the four executors: command (shell), prompt (LLM), agent, and tool (Local API)."
tags:
  - demo
inputs:
  topic:
    type: string
    description: Topic to brainstorm an automation for
    default: coffee
jobs:
  date:
    steps:
      - id: today
        name: Get today's date
        command: 'date "+%Y-%m-%d"'
  catalog:
    steps:
      - id: my_workflows
        name: List saved workflows (tool)
        tool: workflow/list
        with:
          limit: 5
  ideate:
    needs: [date, catalog]
    steps:
      - id: idea
        name: Ask the model for an idea
        prompt: "Today is {{ jobs.date.today.output.stdout | trim }}. Existing workflows: {{ jobs.catalog.my_workflows.output.summaries | dump }}. Suggest ONE new automation about {{ inputs.topic }} that is not in the list, in one sentence."
      - id: plan
        name: Let the agent expand it
        agent: agent/main
        message: "Expand this automation idea into a three-step execution plan: {{ steps.idea.output }}"
      - id: tweet
        name: Write a tweet
        prompt: "Turn this plan into one punchy tweet: {{ steps.plan.output }}"
      - id: translate_ja
        name: Translate the tweet into Japanese
        prompt: "Translate this tweet into natural, fluent Japanese. Keep hashtags, emojis, and links intact. Reply with only the translated tweet: {{ steps.tweet.output }}"
```

Le job `ideate` attend `date` et `catalog` via `needs`, donc il peut lire leurs résultats avec `jobs.<job>.<step>.output`. Dans un job, les étapes suivantes lisent les précédentes avec `steps.<id>.output`.
